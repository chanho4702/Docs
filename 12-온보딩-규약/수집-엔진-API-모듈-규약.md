## 🔴 반드시 지킬 것

### 1. 구역을 섞지 마라

| 넣을 곳 | 기준 |
|---|---|
| `engine/` | **다른 소스에도 같은 질문이 있는가?** 있으면 중립 계약 |
| `zabbix/` | Zabbix API 모양 그대로여도 되는 것(관리 CRUD·아이덴티티). 추상화 시도하지 말 것 |

**판정 기준은 "값이 어디서 오는가"가 아니라 "그 값이 답하는 질문"이다**(ADR D11).
같은 `trigger.get` 응답에서 와도 `manual_close`(→ 중립 `AlertRule.manualCloseAllowed`)와
`expression`(→ Zabbix 전용)은 갈린다. 항목마다 **개별로** 물을 것 — 한 문장에 같이 등장한다고 묶지 말 것.

### 2. §D5 계약 시그니처 규칙 (proto 호환 선지불)

- `Map<String,Object>` **금지** · 제네릭 **금지** · enum은 명시 · 페이지네이션은 opaque token
- 예외는 `EngineException` 단일 계층
- **소스 원시 값을 그대로 싣지 마라** — Zabbix의 `"0"`(없음), 비트합, HTTP 코드 같은 마법값은
  어댑터에서 정규화한다. 계약에 새면 다른 소스가 `0`을 유효 식별자로 쓸 때 충돌한다.
  - 예외: **소스 표기를 응답에 복원해야 하는 경우**는 표현 계층(app)이 되돌린다(모델은 null 유지).

### 3. proto 동기화는 스텝 종료 체크리스트다

`src/main/proto/engine.proto`를 Java와 함께 고친다. 과거 6스텝 밀려 한꺼번에 갚은 적이 있다.

⚠️ **선재 이슈(미해결)**: enum 값 `SYSTEM`이 `MetricDomain`(=8)과 `CallerRole`(=1) 양쪽에 있다.
proto3는 enum 값이 **패키지 스코프**라 codegen 시 충돌한다. 지금은 codegen을 안 해 무해하지만
**물리 분리(스텝 6) 전에 한쪽에 접두어를 붙여야 한다.**

### 4. 필드는 실소비자가 생길 때 증분 추가 (§D2 스코프 절제)

"나중에 쓸 것 같아서" 넣지 말 것. `InventoryHost`는 4a에 ref/name/interfaces로 시작해
groups·lastCheck(4c-2) → tags(4c-4a) → enabled(4c-5e) → osName(4c-4f) 순으로 자랐다.

**비용이 드는 서브조회는 옵트인으로 둔다** — `HostQuery.include`, `AlertQuery.includeActions`,
`AlertHistoryQuery.includeEntities`. 원본이 성능 때문에 조회를 나눠 놨다면 **그 결정을 계약이 표현해야
한다**. 안 그러면 전환하면서 조용히 사라진다.

### 5. 제약을 풀 때는 그 제약이 **겸하던 역할**을 먼저 찾아라

`AlertHistoryQuery.ruleNativeId`는 필수였고, 그게 "무제한 이력 스캔 방지"를 겸하고 있었다.
nullable로 풀면서 **"규칙 또는 시간창 중 하나는 필수"** 를 생성자에서 강제해 방어를 대체했다.

## 🟡 알아둘 것

### 정렬·순서도 계약이다

`AlertHistoryQuery`는 정렬을 옵션으로 열지 않고 **최신순 고정**이다(열면 소스별 지원 차이가 샌다).
⚠️ 다만 **고정된 정렬이 소비자의 동점 처리를 바꿀 수 있다** — 실제로 Top 호스트 동점 순서가 뒤집혀
소비자가 역순 순회로 발생 순서를 복원했다. **중립 모델을 써도 순서는 위임 못 한다.**

### 두 해석을 나란히 두는 패턴

같은 값을 다르게 묻는 계약은 **중복이 아니라 다른 질문**이다. 셋 다 실재한다:

| 체인/넓은 쪽 | 정확/좁은 쪽 | 구분 이유 |
|---|---|---|
| `MEMORY:pused`(폴백 체인) | `MEMORY:size.pused`(정확 키) | 체인을 쓰면 값이 0→11로 바뀐다 |
| `NETWORK:if.in.family`(`net.if.in`) | `if.in.perif.family`(`net.if.in[`) | `[` 유무가 인터페이스 개수를 바꾼다 |
| `DISK:fs.root.pused`(체인) | `fs.root.size.pused`(정확) | dependent 계열 호스트에서 0→실값 |

(카탈로그 자체는 `engine-zabbix`에 있지만, **왜 나뉘는지**는 계약 설계 판단이다.)

### 쓰기 계약 원칙 (ADR D10)

1. 대상은 **식별자 목록으로만** — 필터로 쓰기 금지(소스가 필터를 다르게 해석하면 의도치 않은 대상이 바뀐다)
2. 명령은 서술적, 인코딩(비트합 등)은 어댑터
3. capability 게이팅
4. 읽기 포트와 쪼개지 않음(같은 화면이면 `CallerContext` 2벌 방지)
5. 부분 성공 계약 없음(반환값 없음)

### 레거시 예외 커널은 엔진 계약이 아니다

`common/exception/`의 4개는 **app 레거시**다. `engine/` 구역은 쓰지 않는다.
스텝 5에서 app→engine-zabbix 컴파일 차단을 위해 여기로 옮겨 왔을 뿐이다
(§D8의 "engine-api로 못 올라감" 판정을 뒤집은 것 — 원칙이 목표를 막아서).

⚠️ `ErrorCode`를 건드릴 때: **403은 HTTP 200 + body `code:403`으로 나간다**(원본 버그 보존).
"정상화"하지 말 것 — FE가 깨진다.

## 🟢 작업 방식

1. **실소비자를 먼저 읽어라.** 이 모듈의 계약은 전부 "naive하게 설계했다가 실소비자 shape 보고 고친" 결과다.
2. **원본 필터를 정독하라.** search(부분일치)로 후보를 받아 놓고 정확 일치로 거르는 코드가 흔하다 —
   그러면 그건 계열이 아니라 **정확 키 여러 개**다.
3. 계약을 바꿨으면 **소비자 전환 → 전 테스트 → 런타임 전/후 비교**까지가 한 스텝이다.
   ⚠️ 캐시·스냅샷이 낀 경로(리포트 스냅샷, Redis 60초 캐시)는 비교 전에 비워야 한다 —
   안 그러면 **전환 경로를 타지 않은 채 identical이 나온다**.
