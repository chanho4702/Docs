## 4. 발견

### F-1 — 🔴 첫 손계산 공식이 틀렸다 (QA 방법 결함 · **해소**)

첫 시도에서 **6건 전부 불일치**가 났다. 원인은 BE가 아니라 **내 공식**이었다.

| | 내가 세운 것 | 실제 사양 |
|---|---|---|
| 상각대상액 | 취득가액 − **비망가액 1,000** | 취득가액 − **잔존가액(오버라이드 없으면 0)** |
| 나눗셈 | `floor()` | `round()` |
| 비망가액 | 매달 반영 | **마지막 달 정산에만** 등장 |

**교훈:** 손계산이 어긋나면 먼저 의심할 것은 구현이 아니라 **공식을 어디서 가져왔는가**다.
이 건은 `DepreciationCalculator.straightLineMonths`를 직접 읽고서야 갈렸다 —
설계서 문장("잔존가 0 + 비망가액 1,000")만 보고 세운 공식이 원인이었다.
(2차 시도에서도 상세 EP의 필드 경로를 `data.residualValue`로 잘못 읽어 하한이 1,000으로 폴백돼 또 틀렸다.
 실제 경로는 `data.params.residualValue`다.)

### F-2 — 🔴 dev 데이터가 비망가액 경로를 전혀 실행하지 않았다 (환경 결함 · **✅ 해소**)

```sql
select count(*) total,
       count(*) filter (where cost_data ? 'residual_value') has_residual,
       count(*) filter (where cost_data->>'residual_value' = '0') is_zero
  from asset where cost_data is not null;
--  79 | 68 | 68
```

**79건 중 68건에 `residual_value = "0"`이 명시돼 있다**(2026-08-03 목업 생성분).
코드는 정상이다 — 필드가 **없을 때만** 비망가액 1,000을 적용하고, 있으면 수동 오버라이드로 존중한다
(`CostParamResolver:230`). 있으니 하한이 0이 된 것이다.

**영향:**
- 상각 완료 22건의 장부가액이 전부 **0**이다(1,000이 아니라).
- 즉 **설계검토 지적 #2**("상각 완료를 장부가 0으로 판정하면 비망가액 때문에 0건이 된다")가
  **dev에서는 재현되지 않는다.** 실제로 이 데이터에서는 `bookValue === 0` 판정도 22건을 맞힌다.
- 구현은 `depreciationStatus === 'completed'`로 판정하므로 **어느 쪽이든 옳다**(코드 변경 불필요).
- 🔴 **위험은 회귀 탐지력이다.** 비망가액 로직이 깨져도 dev 데이터로는 드러나지 않는다.
  (계산기 단위 테스트 `DepreciationCalculatorTest`가 그 경로를 덮고 있어 최후 방어선은 있다.)

**✅ 조치 완료(2026-08-05):** F-3이 *잔존가액 0*으로 결정돼 **기본값 자체가 0**이 됐다.
목업의 명시적 `residual_value`도 제거해 dev가 기본값 경로를 타게 했다 — 수치는 그대로다(0 → 0).
이제 비망가액이 필요한 자산은 `residual_value`로 **명시**하며, 그 경로는 단위 테스트가 덮는다.

### F-3 — ✅ 잔존가액 0으로 결정 (2026-08-05)

2026-08-04 사용자 의견: *"비망가액은 … 우리 취지랑 조금 안 맞는 것 같음. 설정하게 할 수 있으면 하고 아님 말자"*

→ **사용자 결정: 잔존가액 0.** 목업의 부작용이던 상태가 이제 명시적 정책이 됐다.

| 반영 | 내용 |
|---|---|
| 코드 | `MEMO_VALUE(1,000)` → **`DEFAULT_RESIDUAL_VALUE(0)`** 로 상수 교체·개명 |
| 테스트 | 하한 1,000을 기대하던 11건 갱신. "장부가 0 판정 금지" 근거를 **수동 잔존가액**으로 교체(실제 계산기 호출로 강화) |
| 문서 | 설계·계약·E2E·메모리의 "비망가액 1,000원" 문구 일괄 정정 |
| FE | `residual_value_hint` 문구(kr·en), 타입 주석 |
| 데이터 | dev 목업의 명시적 `residual_value` 제거 |

회계 목적으로 비망가액이 필요하면 **자산별 `residual_value`로 명시**한다 — 기능은 남아 있다.
