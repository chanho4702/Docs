# 데이터 소스 관리

> **사이드바** 설정 > 데이터 소스 관리
> **경로** `/setting/integrations` → 소스별 워크스페이스 `/setting/integrations/:provider`

## 무엇을 하는 화면인가

관측 데이터를 제공하는 외부 시스템을 **한곳에서 구성**하는 화면이다. MovesEye가 다중 데이터소스 제품으로 가는 관문이다.

## 화면 구성

### 소스 목록

네 개 소스가 카드로 표시된다.

| 소스 | 상태 |
|---|---|
| **Zabbix** | **런타임 어댑터 설치됨 — 실제 설정 가능** |
| Prometheus | 어댑터 미설치 |
| Elasticsearch | 어댑터 미설치 |
| Datadog | 어댑터 미설치 |

각 카드에 상태 배지가 붙는다: `런타임 준비됨` / `런타임 미설치`, `설정됨` / `설정 가능` / `어댑터 미설치`.

### Zabbix 연결 설정

| 항목 | 설명 |
|---|---|
| **API Endpoint** | 비워 두면 서버에 설정된 기본 URL 사용 |
| **API 사용자** | 전용 계정 |
| **API 비밀번호** | 비워 두면 **현재 저장된 값 유지** |

### 연동 상태

설정 상태, 자격증명 만료, 비밀값 정책(응답 비노출 · 입력 시에만 교체)을 표시한다.

### 소스별 워크스페이스

카드에서 들어가면 소스 고유의 관리 영역이 나온다.

| 소스 | 워크스페이스 모듈 |
|---|---|
| Zabbix | 호스트 · 템플릿 · 아이템 · 트리거 |
| Prometheus | 타깃 · 서비스 디스커버리 · 규칙 · 레이블 |
| Elasticsearch | 인덱스 · 파이프라인 · 스트림 · 질의 |
| Datadog | 통합 · 모니터 · 호스트 · 태그 |

## 🔴 화면에 보이는 것 ≠ 사용할 수 있는 것

**가장 중요한 안내다.** 네 소스가 모두 화면에 나오지만, **실제로 연결되는 것은 Zabbix 하나**다.

나머지 셋의 워크스페이스에 들어가면 화면이 직접 이렇게 알린다.

> "{공급자} 관리 화면은 **UI 미리보기**입니다. 공급자 고유 운영 개념과 화면 구조만 먼저 확인할 수 있습니다. 실제 조회·저장·연결 성공 처리는 **백엔드 어댑터가 준비될 때** 활성화됩니다."

목록 화면에도 명시돼 있다 — "**런타임 어댑터가 설치된 소스만 실제 저장할 수 있습니다.**"

고객 시연에서 오해가 생기기 쉬운 지점이므로, 담당자는 이 차이를 먼저 설명한다.

## 왜 억지로 통합하지 않는가

워크스페이스 화면의 설명이 설계 의도를 그대로 담고 있다.

> "공급자마다 다른 운영 모델을 억지로 통합하지 않고, MovesEye 안에서 일관된 진입 경험만 제공합니다."

메트릭·인벤토리·알람 같은 **공통 도메인은 정규화**하지만, 소스 고유의 관리 개념(Zabbix 템플릿, Prometheus 서비스 디스커버리)은 각자의 모습으로 둔다. 억지로 하나로 만들면 어느 쪽에서도 정확하지 않은 화면이 된다.

## 주의할 점

### 비밀번호는 화면에 다시 나오지 않는다

저장된 비밀값은 응답에 실리지 않는다. 수정 시 **비워 두면 기존 값이 유지**되고, 입력했을 때만 교체된다. 다른 항목만 고치려고 비밀번호 칸을 비워도 기존 연결이 끊기지 않는다.

### 전용 계정을 쓴다

사람이 함께 쓰는 계정을 넣지 않는다. 비밀번호가 바뀌면 제품 전체가 멈추고, 감사 로그에서 행위자를 구분할 수 없다.

### 연결이 끊기면 전 화면이 영향받는다

이 설정이 잘못되면 모니터링·이벤트·자산 화면이 **동시에** 비게 된다. 특정 화면만 비는 것과 구분되는 증상이다.
