## 3. 배포 전 점검

> **ZM-157(권한·세션 변경)을 포함하는 배포는** 전원 1회 재로그인 공지, AI 서버 V7의 정지 후 교체 배포, 단일 Redis 전제 확인이 추가로 필요하다. 항목은 [로컬·검증 Runbook §11](%EC%9A%B4%EC%98%81%EC%9E%90-%EB%9F%B0%EB%B6%81.md)을 따른다. 이 문서가 draft라 절차는 확정되지 않았다.

- [ ] 현재 배포 version·commit·Flyway를 기록했다.
- [ ] PostgreSQL backup을 생성하고 별도 환경에서 restore test했다.
- [ ] Redis 손실 시 영향과 재생성 가능 상태를 확인했다.
- [ ] Zabbix·AWS·SMTP·secret 의존성의 변경 여부를 확인했다.
- [ ] 새 environment variable과 secret을 배포 전에 주입했다.
- [ ] Flyway가 backward compatible인지, 장시간 lock을 유발하는지 검토했다.
- [ ] rollback과 DB forward-fix 중 어떤 전략을 쓸지 결정했다.
- [ ] 변경 시간과 사용자 영향·우회책을 공지했다.

## 5. 배포 후 검증

- 로그인·refresh·logout
- 권한이 다른 계정의 Host Group 범위
- 실제 Zabbix Host·metric·Problem
- 자산/비용/맵 중 release 영향 기능
- scheduler 실행·run log
- error rate, latency, DB connection, Redis session
- secret·개인정보 log 노출 없음

결과와 timestamp, 실행자, evidence 경로를 release 문서에 연결한다.

## 6. Rollback / Forward-fix 결정

| 조건 | 기본 판단 |
|---|---|
| code-only, schema backward compatible | 이전 artifact rollback 검토 |
| destructive/irreversible migration | code rollback 금지, forward-fix와 restore 시점 결정 |
| credential·권한 사고 | key 폐기·회전 우선, 접근 차단 후 복구 |
| Zabbix write 영향 | 변경 감사 로그와 원천 현재값 비교 후 수동 복원 승인 |

실제 명령, 허용 RTO/RPO, restore 지점은 owner 승인 뒤 추가한다.
