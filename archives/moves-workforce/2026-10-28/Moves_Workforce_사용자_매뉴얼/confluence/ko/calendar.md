# 프로젝트 캘린더

[가이드 홈](./index.md) · [English](../en/calendar.md)

> 검토 초안: 지정된 staging 환경의 실제 화면·배포 버전 확인 전입니다.

프로젝트 캘린더에서는 참여자의 워크로그와 연결된 이슈의 일정을 날짜별로 확인합니다. 개인 업무만 볼 때는 My Work를 사용합니다.

## 확인 절차

1. 프로젝트 상세에서 **캘린더**를 엽니다. 프로젝트 관리 읽기와 해당 프로젝트 조회 범위가 필요합니다.
2. 확인할 월 또는 주로 이동합니다.
3. 작업자·작업 필터로 대상을 좁힙니다.
4. **워크로그** 또는 **이슈** 표시 모드를 선택합니다.

| 모드 | 확인하는 것 |
|---|---|
| 워크로그 | 실제 기록된 시간과 일별 합계 |
| 이슈 | 시작일~기한으로 표시한 일정 |

공휴일과 프로젝트 이벤트도 함께 확인할 수 있습니다. 시작일·기한이 없는 작업은 **기간 미설정**에서 확인하고 [작업 관리](./project-work.md)에서 일정을 지정합니다.

## 결과가 예상과 다를 때

- 워크로그가 없으면 기간·작성자·이슈 연결을 확인합니다.
- 이슈 막대가 없으면 이슈 표시 모드와 일정 유무를 확인합니다.
- 워크로그를 고칠 때는 작성자 본인의 수정 권한이 필요합니다.
- 여러 날의 일정은 시작일과 마지막 표시 날짜를 확인합니다.

이 화면의 워크로그는 Jira 및 My Work와 같은 기록입니다. 개인별 투입 추세는 [인력 분석](./analytics.md)에서 보는 편이 좋습니다. 모드 전환은 본문 표로 설명하고 별도 캡처는 필수로 요구하지 않습니다.

## 버튼·입력 항목과 처리 결과 상세

프로젝트 캘린더는 프로젝트 범위의 일정과 기록을 확인합니다. 개인 My Work 캘린더와 표시 대상이 다릅니다.

| 버튼·입력 항목 | 기능·사용 조건·변경 대상 | 결과 확인과 문제 대응 |
|---|---|---|
| 오늘·이전/다음·월/주 | 표시하는 날짜와 시간 축을 바꿉니다. 프로젝트 기간이나 이슈 날짜를 수정하지 않습니다. | 화면 제목의 기간과 해당 프로젝트를 확인합니다. |
| 워크로그·이슈 표시 | 워크로그는 실제 투입 날짜·시간, 이슈 일정은 시작·기한 기준입니다. 같은 이슈도 모드에 따라 보이는 날짜가 다릅니다. | 기간 밖 기록과 날짜 없는 이슈가 보이지 않는 이유를 구분합니다. |
| 이슈·기록 상세·일정 미지정 목록 | 대상을 선택해 키·이름·기간·시간을 확인합니다. 시작일 또는 기한이 없는 작업은 일정 미지정 목록에서 확인합니다. | 계획 날짜 변경은 권한 있는 사용자가 작업 관리의 간트에서 수행합니다. 캘린더 조회와 워크로그 등록을 혼동하지 않습니다. |
