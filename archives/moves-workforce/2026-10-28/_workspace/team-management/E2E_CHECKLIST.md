# 팀 기능 P0+P1 — 실기동 확인 체크리스트

> 2026-07-28 / 로컬 테스트 906건(백엔드 562 + 프론트 344)이 전부 통과했지만,
> **아래는 원리적으로 로컬에서 증명할 수 없는 항목**이다.
> P0에서 KVS 빈 문자열 건이 449개 통과 후 첫 실행에서 터진 전례가 있다.

---

## ⛔ 0순위 — 이게 안 되면 나머지가 무의미하다

### E-1. 배포 순서 (KVS 엔티티 선언 선행)
- **왜**: `manifest.yml`에 KVS `team` 엔티티를 선언했다. 미배포 상태에서 `addTeam`을 호출하면 **422 semantic error**
- **확인**: `forge deploy` 완료 후 `/backoffice/team` 진입 → 팀 생성
- **실패 징후**: `422` 또는 `semantic error` → 배포가 안 된 것

### E-2. 마이그레이션 v013 (`users.team_key` 컬럼)
- **확인**: `forge logs`에서 `v013_alter_users_add_team_key` 확인. 또는 `/backoffice/users`에서 팀 컬럼이 보이는지
- **왜 로컬 불가**: `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`의 TiDB 실동작 (v012 선례는 있음)
- **실패 징후**: 사용자 목록에서 팀 컬럼이 빈칸 고정, 팀 배치가 저장 안 됨

### E-3. ⚠️ 권한 세트에 `TEAM_MANAGEMENT` 수동 부여
- **왜**: `migrateFrom`을 **의도적으로 지정하지 않았다.** 기존 커스텀 권한 세트 보유자는 재시드 후에도 팀 메뉴가 **안 보인다**
- **확인**: `/backoffice/permission`에서 세트별로 `TEAM_MANAGEMENT` read/write를 켠다
- **참고**: Jira ADMINISTER 보유자는 카탈로그 파생이라 **즉시 접근 가능**. 그래서 관리자 본인은 문제를 못 느낀다

## 🔴 1순위 — 기본 동작

### E-4. 루트 팀 생성 (KVS 빈 문자열 — 이미 한 번 터진 지점)
- **확인**: **상위 팀 없이** 팀 생성. 이어서 **팀장·설명 없이** 생성
- **왜**: `parentTeamKey`뿐 아니라 `leaderAccountId`·`permissionKey`·`description`도 같은 함정이었다
- **실패 징후**: `Value for attribute "..." cannot be empty`

### E-5. `sortOrder: 0` 저장 (U-2, 미확인)
- **왜**: integer attribute에 `0`을 저장할 때 KVS가 "empty"로 볼 가능성이 남아 있다. 빈 문자열과 별개 사안
- **확인**: 첫 팀 생성이 곧 이 케이스다(E-4와 동시 확인됨)

### E-6. 팀 CRUD 직후 즉시 반영 (F3)
- **확인**: 팀 생성 → **목록에 바로 보이는가** → 그 팀을 상위로 하는 하위 팀 생성
- **왜**: 60초 캐시 때문에 "만든 적 없는데 중복" 상황이 났었다. fresh 로드로 고쳤다
- **실패 징후**: 생성 후 목록에 없음 → 재생성 시 `TEAM_NAME_DUPLICATED`

### E-7. 사용자 수정 시 다른 필드 보존 (C1 read-merge)
- **확인**: 사용자 편집에서 **직무만** 바꿔 저장 → 팀·등급·권한이 **그대로인지**
- **왜**: read-merge 전환의 핵심. 실패하면 저장 한 번에 팀 소속이 날아간다
- **함께**: 직무 Select를 **비우고** 저장 → 실제로 해제되는지 (`?? null` 동작)

### E-8. 팀 삭제 시 하위 팀 승격
- **확인**: 하위 팀이 있는 팀을 삭제 → 하위가 **조부모로 올라가는지** (같이 삭제되면 안 됨)
- **함께**: 삭제 후 토스트의 영향 카운트(해제 인원·승격 팀 수)가 맞는지

## 🟠 2순위 — 권한 (P1, 실패 시 보안 문제)

### E-9. `TEAM_ONLY` 스코프
- **확인**: 권한 세트를 `TEAM_ONLY`로 바꾼 계정으로 로그인 → 프로젝트 목록에 **내 팀이 참여한 것만** 보이는지
- **⚠️ 핵심**: **팀 미소속 계정**을 `TEAM_ONLY`로 두면 → **아무것도 안 보여야 한다**(fail-close)
- **실패 징후**: 전사 프로젝트가 다 보임 = fail-open (검증에서 3중으로 막았지만 실기동 확인 필요)

### E-10. 팀 상속 권한
- **확인**: 사용자 권한을 **"팀 상속"** 으로 저장 → 그 사람이 팀 권한세트를 따르는지
- **함께**: 조상 팀 어디에도 세트가 없는 상태에서 "팀 상속" 선택 → **미리보기가 "모든 권한을 잃습니다"로 경고**하는지
- **⚠️ 반대 확인**: 팀 목록 조회가 실패한 상태에서는 "권한 없음"이 아니라 **"확인 불가"** 로 표시돼야 한다(거짓 경고 방지)

### E-11. 개인 권한 우선 (R2)
- **확인**: 개인 권한세트 有 + 팀 권한세트 有 인 사용자 → **개인 것이 적용**되는지 (합집합 아님)

### E-12. 팀장 역할 (`/my-page` → 내 팀)
- **확인**: 팀장 계정으로 `/my-page` 진입 → "내 팀" 섹션에 팀원 목록 + **스킬 편집**이 되는지
- **왜**: 팀장 진입점이 백오피스가 아니라 `/my-page`다(H1 재설계). 백오피스는 팀장이 도달할 수 없다
- **실패 징후**: 섹션이 안 보이거나, 스킬 저장이 거부됨 → 선행 read 권한이 막힌 것

### E-13. 팀장 권한 경계 (D4 — 권한 상승 방지)
- **확인**: 팀장이 **자기 팀 동료(리더가 아닌 같은 팀원)** 의 스킬을 편집하려 할 때 **거부**되는지
- **왜**: 설계서 자기모순으로 여기가 열릴 뻔했다. 로컬 52건 실행으로는 통과

### E-14. 사용자 삭제 시 팀장 참조 정리
- **확인**: 팀장으로 지정된 사용자를 백오피스에서 삭제 → 그 팀의 팀장이 **비워지는지**
- **왜**: 남으면 "계정을 지웠는데 팀장 권한이 남는" fail-open

## 🟡 3순위 — 이상 상태 (인위적 재현 필요, 로컬은 순수 함수 테스트로만 고정)

### E-15. 강등 노드 복구 경로 (U-7)
- **재현**: 사이클(A→B→A)을 만들어야 한다. 정상 UI로는 서버가 거부하므로 **KVS 직접 조작이나 동시 편집**이 필요
- **확인**: 사이클 팀들이 **트리 최상위에 나타나고**, 선택해서 상위 팀을 다시 지정할 수 있는지
- **왜**: F1이 막던 경로다. 예전엔 서브트리가 통째로 사라져 **고칠 방법이 없었다**

### E-16. 경고 표시 (U-8)
- **확인**: 사이클 상태에서 배너 + 노드 경고 아이콘이 뜨는지, 사이클/기타 강등이 구분되는지

### E-17. 팀 100개 초과 (U-1, U-9)
- **확인**: 팀이 100개를 넘을 때 전량 수집되는지(`truncated: false`), 트리 렌더 체감 속도
- **왜**: KVS 커서 페이징의 런타임 동작은 타입 정의로만 확인했다

### E-18. `leaderEmail` 폴백 (U-10)
- **확인**: Jira 개인정보 설정으로 이메일이 비공개인 사용자를 팀장 지정 → 에러 없이 이메일 줄만 안 보이는지

## 알려진 한계 (버그 아님 — 의도적 수용)

1. **팀 생성 후 60초 내에 그 팀에 인원을 배치하면, 사용자 목록의 팀 이름 컬럼이 잠시 빌 수 있다.** 소속 자체는 정확하고 필터·집계도 맞다(표시만의 문제). 권한 판정 캐시와 공유하는 구조라 수용했다.
2. **팀장의 프로젝트 배정 취소는 제공되지 않는다.** P1에서 의도적으로 닫았다(P2에서 `project_team`과 함께 열 예정).
3. **권한 세트 로드가 실패하면 공휴일 조회 1건이 열린다.** 노출면이 그것뿐이라 현행 유지했다.
4. **삭제 영향은 사전 경고가 아니라 삭제 후 토스트다.** P0에 미리보기 resolver가 없다.
