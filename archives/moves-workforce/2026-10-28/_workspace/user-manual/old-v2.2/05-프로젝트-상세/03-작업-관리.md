# 5.3 프로젝트 상세 — 작업 관리

## 🔐 접근 권한

| 구분 | 필요 권한 |
|---|---|
| 목록·트리·간트 조회 | `PROJECT` 읽기 |
| 작업 추가(편입)·연결 해제 | `PROJECT` 쓰기 |
| 인라인 편집(담당자·동료·일정·계획 작업량) | `PROJECT` 쓰기 **+ Jira 이슈 편집 권한** |
| 트리·간트 편집(일정·선후행·상위 지정·폴더) | `PROJECT` 쓰기 **+ Jira 권한**(아래) |
| 자동 편입(구독) 설정 | `PROJECT` 쓰기 |

**함께 필요한 Jira 권한**

| 작업 | Jira 권한 |
|---|---|
| 일정 변경 | 이슈 편집 · 일정 관리 |
| 담당자 지정 | 담당자 지정 |
| 선후행 연결 | 이슈 연결 |
| 계획 작업량(MD) | 이슈 편집 + 프로젝트의 **시간 추적 활성화** |

- 트리·간트는 `PROJECT` 읽기만 있으면 **조회 전용**으로 열립니다(간트 툴바에 "조회 전용" 배지).
- 권한이 없으면 뷰 전환 버튼에서 트리·간트가 빠지고, 남는 보기가 하나뿐이면 전환 버튼 자체가 사라집니다.
- 앱 권한이 있어도 Jira 권한이 없으면 **저장 시점에 거부**되고 사유가 안내됩니다.

---

**언제 쓰나** — 프로젝트의 모든 작업(이슈)을 **찾고, 담당을 정하고, 구조와 일정을 잡을** 때.

같은 작업 묶음을 **목록 / 트리 / 간트** 세 가지 방식으로 봅니다(우측 위 전환 버튼).

| 보기 | 무엇에 쓰나 | 잘하는 일 |
|---|---|---|
| **목록** (기본) | 작업을 찾고 추가·수정 | 검색·필터, 작업 추가/연결 해제, 셀 인라인 편집 |
| **트리** | 작업의 **구조**를 보고 정리 | 상위-하위·폴더 계층 정리(드래그), 한 작업의 모든 정보 확인 |
| **간트** | 작업의 **일정**을 보고 조정 | 기간 조정, 선후행 연결, 전체 일정 조망 |

- 트리와 간트는 **같은 데이터**를 봅니다. 한쪽에서 바꾸면 다른 쪽에도 그대로 반영됩니다.
- 트리와 간트는 **담당자·상태·스페이스 필터를 공유**합니다. 보기를 바꿔도 "이 담당자 작업만" 보던 상태가 유지됩니다. (목록 보기는 검색 조건 체계가 달라 따로 동작합니다.)

## 5.3.1 목록 보기

- 상단 필터: **업무 검색**, **스페이스**, **담당자**, **상태**
- 우측 위 **+ 작업 추가**

| 컬럼 | 설명 |
|---|---|
| 프로젝트 | 소속 프로젝트 |
| 키 | 이슈 키 |
| 업무 | 이슈 제목 |
| 상태 | 해야 할 일 / 진행 중 / 완료 |
| 담당자 | 이슈 담당자 |
| 동료 | 협업자(여러 명 지정 가능) |
| 시작일 | 작업 시작일 (셀에서 수정 가능) |
| 기한 | 작업 기한 (셀에서 수정 가능) |
| 계획 작업량 | 계획 공수. 단위 **MD = Man-Day(인일)** (예: 5.1 MD). Jira의 Original Estimate 기반 |
| 처리율 | 진행률 (예: 0% / 5% / 100%) |
| 추가 작업 | **삭제**(프로젝트 연결 해제) |

> **인라인 편집:** **담당자·동료·시작일·기한** 셀을 클릭하면 그 자리에서 수정됩니다. 변경은 해당 Jira 이슈에 즉시 반영됩니다.

> ⚠️ **"작업 추가"는 새 이슈를 만들지 않습니다.** **이미 존재하는 Jira 이슈를 검색해 이 프로젝트에 편입**하는 방식입니다. 목록의 **삭제**도 이슈 삭제가 아니라 **프로젝트 연결 해제**입니다.

## 5.3.2 담당자·동료 관리

작업에 **누가 매달려 있는지**를 정하는 기능입니다. 여기서 지정한 값이 My Work·마이페이지·인력 분석·가동률 계산의 기준이 됩니다.

### 담당자와 동료의 차이

| 구분 | 인원 | 성격 | 저장 위치 |
|---|---|---|---|
| **담당자**(Assignee) | **1명** | Jira 기본 기능. 이슈를 **책임지는** 사람 | Jira 이슈의 담당자 필드 |
| **동료**(협업자) | **여러 명** | 이 앱이 추가한 개념. 함께 **수행하는** 사람 | Jira 이슈에 앱이 저장하는 협업자 목록 |

한 이슈에 담당자는 한 명뿐이지만 실제로는 여러 명이 함께 일하는 경우가 많습니다. **동료**는 그 현실을 담기 위한 항목입니다. 담당자와 동료는 **별개 축**이라, 담당자를 바꿔도 동료 목록은 그대로 유지됩니다.

> 동료로 지정되면 그 사람의 **My Work에 "협업 이슈"로 집계**되고, 마이페이지·인력 분석의 작업량에도 반영됩니다. 즉 동료 지정은 단순 표시가 아니라 **집계에 실제로 들어갑니다.**

### 지정하는 세 가지 경로

| 경로 | 위치 | 쓰임 |
|---|---|---|
| **표 인라인 편집** | 작업 관리 > 목록 | 이슈 하나씩 담당자·동료를 바로 수정 |
| **트리 보기** | 작업 관리 > 트리 | 상위/하위 구조를 보면서 동료 지정 |
| **작업 배정** | [인력 관리 > 작업 배정](./02-인력-관리.md#524-작업-배정) | **스킬 적합도와 현재 부하를 비교해** 배정. 여러 건을 한 번에 처리할 때 |

앞의 두 경로는 "이 이슈에 누구를 넣을까", **작업 배정**은 "이 사람에게 무엇을 맡길까" 관점입니다.

### 등록일·등록자는 자동으로 기록됩니다

작업을 프로젝트에 편입할 때 **누가 언제 등록했는지**가 이슈에 함께 저장되며, [작업 이력](./05-분석-및-리포트.md#556-작업-이력) 화면에서 확인할 수 있습니다.

- **최초 등록 시점만 유지됩니다.** 이미 등록일이 있는 이슈는 다시 편입해도 덮어써지지 않습니다.
- 직접 수정할 수 없는 읽기 전용 값입니다.

### 지정 결과가 반영되는 곳

| 화면 | 반영 내용 |
|---|---|
| [My Work](../02-my-work.md) | 담당자·동료인 이슈가 내 작업으로 표시 |
| [마이페이지](../03-마이페이지.md) | 내 작업·처리율·남은 작업 집계 |
| 작업 관리(목록/트리/간트) | 담당자 필터, 트리·간트의 담당자 표시 |
| [분석 및 리포트 > 인력](./05-분석-및-리포트.md#552-인력-분석--누가-과부하이고-누가-여유인가) | 인력별 공수(MD)·가동률 산정 대상 |
| [자원 관리](../06-자원-관리/README.md) | 인력별 부하(작업량)·배정 현황 |
| [프로젝트 대시보드](./01-대시보드.md) | 담당자 분포 차트 |

### 주의사항

- **동료 지정 직후 목록 필터 결과가 잠깐 예전 상태로 보일 수 있습니다.** Jira 검색 색인 갱신에 시간이 걸리기 때문이며, 값 자체는 이미 저장돼 있습니다.
- **프로젝트 인력과 담당자는 별개입니다.** 이슈 담당자로 지정해도 프로젝트 인력 명단에 자동 추가되지 않습니다. 인건비·가동률 집계에 포함하려면 [인력 관리](./02-인력-관리.md)에서 별도로 추가해야 합니다.
- 담당자·동료 변경은 **해당 Jira 이슈에 즉시 반영**됩니다.

## 5.3.3 자동 편입(프로젝트 구독)

작업 추가 모달의 **구독 설정** 탭에서 Jira **스페이스** 또는 **보드**를 구독하면 조건에 맞는 이슈가 이 프로젝트로 자동 편입됩니다.

| 소스 유형 | 기준 |
|---|---|
| **스페이스** | Jira 프로젝트 전체. 이슈 타입·하위 작업·추가 JQL로 좁힐 수 있습니다 |
| **보드** | 보드의 저장 필터와 sub-query에 실제로 포함되는 이슈만. 보드 필터가 바뀌면 다음 동기화부터 대상도 바뀝니다 |

### 설정 절차

1. 소스 유형과 소스를 선택합니다. **이미 다른 RMS 프로젝트가 소유한 소스는 선택할 수 없습니다.**
2. 필요하면 하위 작업 포함 여부와 추가 JQL을 지정합니다. `currentUser()` 같은 사용자 의존 함수와 `ORDER BY`는 사용할 수 없습니다.
3. 미리보기에서 편입 대상·다른 프로젝트와의 충돌·이미 편입된 건수를 확인합니다.
4. **기존 이슈도 가져오기**를 선택하면 기존분을 백필 큐로 가져오고, 끄면 구독 시점 이후 생성분만 대상으로 합니다.

### 운영 규칙

- 프로젝트당 구독은 **최대 10개**, 한 스페이스/보드는 전체에서 **한 프로젝트만** 구독할 수 있습니다.
- 스페이스 신규 이슈는 생성 이벤트로 빠르게 처리하고, 보드·이벤트 누락·이슈 이동은 **1시간마다** 정합성을 확인합니다.
- 작업 목록의 **자동 편입** 요약에서 구독 스페이스 필터와 **지금 동기화**를 사용할 수 있습니다. **지금 동기화는 대기 중인 정합성 검사를 즉시 실행할 뿐, 생성 시 선택한 백필 하한을 우회하지 않습니다.**
- 구독을 해제해도 **이미 편입된 이슈는 남습니다.**

## 5.3.4 트리·간트 공통 — 먼저 알아야 할 것

### 권한

| 권한 | 가능한 일 |
|---|---|
| 프로젝트 **읽기** | 트리·간트 조회, 펼침/접기, 줌, 필터, 상세 확인 |
| 프로젝트 **쓰기** | 일정·상위·선후행·폴더·담당자·동료·계획 작업량 편집 |

읽기 권한만 있으면 간트 툴바에 **"조회 전용"** 배지가 뜨고 드래그·연결·편집이 잠깁니다. 트리에서는 편집 버튼과 드래그가 나타나지 않습니다.

> Jira 자체 권한도 함께 확인합니다. 앱에서 쓰기 권한이 있어도 Jira에서 **이슈 편집·일정 변경·담당자 지정·이슈 연결** 권한이 없으면 저장이 거부되고 사유가 안내됩니다.

### 세 가지 계층 개념 — 구분해서 쓰세요

| 개념 | 만드는 곳 | 저장 위치 | 특징 |
|---|---|---|---|
| **Jira 하위 이슈** | Jira | Jira 표준 | Jira가 정한 3단계(에픽>스토리>하위작업) 제약을 받습니다 |
| **상위 지정(WBS)** | 이 앱(트리·간트) | 앱이 이슈에 저장 | **단계 제한 없이 자유롭게 중첩**. Jira 상위가 있어도 이 지정이 **우선 적용**됩니다 |
| **폴더** | 이 앱(트리·간트) | 앱 내부 | Jira에 없는 앱 전용 묶음. 이슈가 아니므로 Jira에서는 보이지 않습니다 |

> **왜 상위 지정이 따로 있나요?** Jira는 3단계와 인접 단계만 허용해 4단계 이상 WBS를 만들 수 없습니다. 앱의 상위 지정은 이 제약을 벗어나기 위한 것입니다. 대신 **Jira 화면에는 이 계층이 나타나지 않습니다.**

### 필터

담당자 · 상태 · 스페이스(여러 스페이스가 섞여 있을 때만 표시) 필터를 두 보기가 공유합니다. 폴더는 필터로 직접 걸러지지 않고, **남은 작업을 기준으로 폴더의 기간·수행율이 다시 계산**됩니다.

## 5.3.5 트리 보기 — 작업 구조 정리

화면은 좌우로 나뉩니다. **왼쪽은 계층 구조, 오른쪽은 선택한 항목의 상세**입니다.

### 왼쪽 — 계층 구조

- **검색**: 작업 키·이름으로 걸러냅니다
- **모두 펼치기 / 모두 접기**
- **폴더 추가** (쓰기 권한)
- 폴더는 항상 같은 단계의 작업보다 위에 표시됩니다
- 항목을 클릭하면 오른쪽에 상세가 열립니다

### 드래그로 구조 바꾸기 (쓰기 권한)

| 무엇을 | 어디에 놓으면 | 결과 |
|---|---|---|
| 작업 | 다른 작업 위 | 그 작업의 **하위로 지정**(상위 지정) |
| 작업 | 폴더 위 | 그 **폴더에 소속** |
| 작업 | 목록 아래 **"여기에 놓으면 최상위로 이동"** 영역 | **상위 지정 해제** |
| 폴더 | 다른 폴더 위 | 그 폴더의 **하위 폴더로 이동** |
| 폴더 | 최상위 영역 | **최상위 폴더로 이동** |
| 폴더 | 작업 위 | 아무 일도 일어나지 않습니다(작업은 폴더의 상위가 될 수 없습니다) |

- 자기 자신이나 자기 하위로는 옮길 수 없습니다(순환 방지).
- 상위가 지정된 작업을 폴더에 넣으면 **상위 지정이 먼저 해제**됩니다. 한 작업은 "다른 작업의 하위"이면서 동시에 "폴더 소속"일 수 없습니다.
- 같은 규칙이 간트의 행 드래그에도 그대로 적용됩니다.

### 오른쪽 — 선택한 작업의 상세

| 구역 | 내용 |
|---|---|
| 헤더 | 작업 이름, 상태, 이슈 키 |
| 처리율 | 진행률 막대 |
| 속성 | 담당자 / 시작일 / 기한 / 협업자 / 계획 작업량 / Jira 프로젝트 |
| 연관 관계 | 상위 작업 · 하위 이슈 · 선행/후행 작업 · 소속 폴더 · Jira 연결 |
| 쌓인 워크로그 | 이 작업에 기록된 워크로그 목록과 **합계 시간** |

속성의 **연필 아이콘**을 누르면 편집합니다(쓰기 권한). 계획 작업량은 그 자리에서 숫자를 입력하고 Enter로 저장하며, 일정·협업자·상위·폴더는 모달이 열립니다. 여기서 저장한 값은 간트에도 즉시 반영됩니다.

### 상위 작업의 "출처" 표시 — 트리 보기에만 있는 정보

상위는 **Jira가 정한 것**과 **이 앱에서 지정한 것** 두 가지가 있어, 지금 적용 중인 상위가 어디서 왔는지 배지로 구분합니다.

| 표시 | 의미 |
|---|---|
| **워크포스에서 지정** | 앱에서 지정한 상위가 적용 중 |
| **Jira에서 정의** | Jira 표준 상위가 적용 중 |
| *워크포스 지정으로 가려진 Jira 상위* | 앱 지정이 Jira 상위를 대신하는 중. 가려진 Jira 상위를 함께 표시하며, 상위 지정을 해제하면 Jira 상위로 돌아갑니다 |
| *현재 트리 화면에 없습니다* | 상위 작업이 필터에 걸렸거나 조회 범위 밖입니다 |
| *조회 범위에 없어 적용되지 않았습니다* | 앱에서 지정한 상위 작업이 이 프로젝트에 편입돼 있지 않아 계층이 그려지지 않았습니다 |

### 선후행(선행 작업 / 후행 작업)

- **연결 추가** 버튼으로 상대 작업을 골라 연결하고, 각 항목의 **×** 로 해제합니다.
- 선후행은 **Jira 이슈 링크(Blocks)로 저장**됩니다. 그래서 간트에서 그렸는지 Jira에서 만들었는지는 **구분되지 않습니다.**
- 상대가 다른 프로젝트에 있거나 조회 범위 밖이면 **읽기 전용**으로 따로 표시됩니다(연결이 사라진 것이 아닙니다).
- 선후행이 아닌 Jira 링크(관련됨, 중복 등)는 아래 **Jira 연결**에 따로 모입니다.

## 5.3.6 간트 보기 — 일정 조정

왼쪽 표와 오른쪽 타임라인으로 구성됩니다. 경계선을 끌어 좌우 폭을, 컬럼 경계를 끌어 컬럼 폭을 조절할 수 있습니다.

### 왼쪽 표의 컬럼

| 컬럼 | 내용 | 편집 |
|---|---|---|
| 이슈 | 이슈 키·이름 (펼침/접기 화살표 포함) | — |
| 상태 | 해야 할 일 / 진행 중 / 완료 | — |
| 담당자 | 이슈 담당자 | ✅ 셀 클릭 |
| 협업자 | 함께 수행하는 인원(여러 명) | ✅ 셀 클릭 |
| 시작일 | 시작일. 미설정이면 **일정 설정** 버튼 | ✅ |
| 기간 | 시작~종료 일수 | — |
| 계획 작업량 | 계획 공수(MD) | ✅ 셀 클릭 후 입력 |
| 처리율 | 진행률(%) | — |
| 상위 지정 | 상위 작업 선택 (쓰기 권한일 때만 컬럼 표시) | ✅ |

### 타임라인

- 줌: **일 / 주 / 월**
- 세로 기준선: **오늘**, **프로젝트 시작**, **프로젝트 종료**

| 막대 | 의미 |
|---|---|
| 파란 막대 | 일반 작업 |
| 초록 막대 | **Jira 하위 이슈를 가진 상위 작업** — 하위 기간을 감싸는 요약 막대 |
| 보라 마름모 | 마일스톤(시작일 = 종료일) |
| 회색 점선 막대 | **일정이 없는 작업** — 프로젝트 시작일 위치에 임시 표시 |
| 틸(청록) 막대 | 폴더 — 깊이가 깊을수록 연해집니다 |

> **앱에서 상위 지정한 작업은 초록 요약 막대가 되지 않습니다.** 각자 자기 일정을 가진 **독립 작업**으로 남고, 왼쪽 표에서 펼침/접기만 생깁니다. 초록 요약 막대는 Jira 하위 이슈를 가진 경우에만 나타납니다.

### 편집 조작 (쓰기 권한)

| 하고 싶은 일 | 조작 |
|---|---|
| 일정 변경 | 막대를 **드래그**(이동) 또는 **끝을 끌어** 기간 조정 |
| 일정 없는 작업에 일정 주기 | 회색 점선 막대를 드래그하거나, 시작일 컬럼의 **일정 설정** 버튼으로 날짜 입력 |
| 선후행 연결 | 한 막대의 **끝점**을 다른 막대로 드래그 |
| 선후행 해제 | 연결선을 선택해 삭제 |
| 계층 만들기 | 왼쪽 표에서 행을 **드래그**하거나 **상위 지정** 컬럼에서 선택 |
| 폴더 만들기·정리 | 툴바 **폴더 추가**, 행 메뉴에서 이름 변경/하위 폴더 추가/이동/삭제 |

- 진행률 막대는 드래그로 바꿀 수 없습니다. **처리율은 Jira가 시간 추적(기록 시간과 잔여 추정, 하위 이슈 포함)으로 계산한 값**이라 직접 입력하는 항목이 아닙니다.
- 순환이 생기는 연결(A→B→A), 자기 자신 연결, 다른 프로젝트 작업과의 연결은 거부되고 사유가 안내됩니다. 거부되면 화면도 원래대로 되돌아갑니다.

### 폴더

- 폴더로 이슈를 묶어 **WBS(작업 분류)** 를 구성합니다. 중첩할 수 있고 **깊이에 따라 색 농도**가 달라집니다.
- 폴더 막대의 **기간·처리율·계획 작업량은 하위 항목에서 자동 집계**됩니다. 처리율은 계획 작업량(MD)으로 가중 평균합니다.
- 이슈가 없는 **빈 폴더도 이름만 표시**됩니다.
- **폴더를 삭제해도 이슈는 삭제되지 않습니다.** 내용물(이슈·하위 폴더)은 **상위 폴더로 옮겨지고**, 상위가 없으면 최상위로 올라갑니다. 다만 그 폴더가 끝점이던 선후행 연결은 함께 사라집니다.

### 선후행 연결의 두 가지 저장 방식

- **이슈 ↔ 이슈** 연결은 Jira의 **이슈 링크(Blocks)** 로 저장되어 Jira 이슈 화면에서도 보입니다.
- **폴더가 포함된 연결**(폴더↔이슈, 폴더↔폴더)도 같은 방식으로 만들 수 있지만, 폴더는 Jira에 없는 앱 전용 개념이라 **앱 내부에만 저장**됩니다.

> **Jira 이슈 화면의 표기 방향:** 간트에서 만든 선후행은 Jira 이슈 화면에서 "blocks / is blocked by" 방향이 **간트와 반대로** 보일 수 있습니다. 간트 화면의 방향(왼쪽이 선행)이 기준이며, 일정 계산과 표시는 정상입니다.

> **성공 알림 묶음:** 드래그로 여러 항목을 연달아 편집하면 알림이 건건이 뜨지 않고 잠시 모아져 **"변경 N건이 저장되었습니다"** (일정 / 연결 / 상위 지정 / 폴더 소속 / 폴더 이동 분류) 한 건으로 표시됩니다. 오류 알림은 즉시 표시됩니다.

## 5.3.7 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| 트리·간트 버튼이 안 보입니다 | 프로젝트 읽기 권한이 없습니다 |
| 드래그·편집이 안 됩니다 | 프로젝트 쓰기 권한이 없거나("조회 전용" 배지), Jira에서 그 이슈 편집 권한이 없습니다 |
| 상위로 지정했는데 하위로 안 들어갑니다 | 상위로 지정한 작업이 **이 프로젝트에 편입돼 있지 않거나** 필터에 걸렸습니다. 트리 상세의 상위 항목에 사유가 표시됩니다 |
| 계획 작업량 저장이 실패합니다 | 그 Jira 프로젝트에서 **시간 추적(Time Tracking)이 꺼져** 있습니다. Jira 관리자에게 활성화를 요청하세요 |
| 폴더에 넣었더니 상위 지정이 풀렸습니다 | 정상 동작입니다. 상위 지정과 폴더 소속은 동시에 유지되지 않습니다 |
| 작업이 트리 최상위에 떠 있습니다 | 상위 작업이 필터로 걸러졌을 때 하위가 사라지지 않도록 최상위로 올려 보여줍니다. 필터를 해제하면 제자리로 돌아갑니다 |
| Jira에서 상위를 바꿨는데 반영되지 않습니다 | 앱에서 지정한 상위가 **우선 적용** 중입니다. 트리 상세에서 상위 지정을 해제하세요 |
| 간트에서 만든 계층이 Jira에 없습니다 | 앱의 상위 지정·폴더는 Jira에 없는 개념입니다(선후행 연결은 Jira에도 저장됩니다) |
