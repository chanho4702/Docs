프로젝트 데이터 범위 변경 「권한 관리」 쓰기
  • 이 화면의 쓰기 권한은 다른 모든 권한을 부여할 수 있는 권한입니다. 최소 인원에게만 주세요.
  • 기본 시스템 세트(Admin / Member)는 페이지 권한을 수정할 수 없고, 프로젝트 조회 범위만 바꿀 수 있습니다.
  • Jira 관리자 권한 세트의 프로젝트 범위는 변경할 수 없습니다.
  • 세트를 사용자·팀에 배정할 때는 배정자 자신의 권한을 넘는 세트를 줄 수 없습니다(Jira 관리자·「권한 관리」 쓰기 보유자는 제한 없음). 자기 승격을 막기 위한 규칙입니다.

언제 쓰나 — 권한 세트를 만들고 각 기능의 읽기/쓰기와 프로젝트 조회 범위를 정할 때.

그림 7-10 권한 세트 편집

그림 7-10. 권한 세트 편집 — ① 세트 목록(시스템 세트·프리셋·커스텀) ② 항목별 읽기/쓰기 체크(워크포스 영역·설정 영역) ③ 항목 설명 ④ 프로젝트 데이터 범위(전체/소속 프로젝트만/내 팀만)와 경고.

권한-세트-만들기권한 세트 만들기

  1. 권한 추가 → 권한 이름을 입력합니다 (예: super admin).
  2. 항목별로 읽기 / 쓰기 를 체크합니다. 최소 하나 이상 선택해야 합니다.
  3. 프로젝트 데이터 범위를 지정합니다.

읽기(Read) 는 화면 조회, 쓰기(Write) 는 생성·수정·삭제 권한입니다. 각 항목 아래에 그 권한이 제어하는 페이지·탭·기능 설명이 표시됩니다.

기본-제공-세트와-프리셋기본 제공 세트와 프리셋

  • 기본 시스템 세트: Admin / Member — 페이지 권한은 수정할 수 없지만 프로젝트 조회 범위는 설정할 수 있습니다.
  • 편집 가능한 프리셋: PM / PMO / Team Lead / Team Member
  • 앱 업그레이드로 새 항목(예: 워크로그 추출)이 생기면 기존 세트에는 꺼진 채로 추가됩니다. Admin 세트만 켜져 있으므로 필요한 세트에 직접 켜 주세요.

주의사항

  • Jira 관리자 세트는 항상 전체를 조회하며 이 설정을 변경할 수 없습니다.
  • 내 팀만 선택 시 팀 미지정 사용자는 아무 프로젝트도 볼 수 없게 된다는 경고가 해당 인원 수와 함께 표시됩니다.
  • 내 팀만은 프로젝트 범위만 제한합니다. 같은 세트에 자원 관리·인력 관리 조회 권한을 함께 주면 전사 인원 목록은 그대로 보입니다.
  • 워크로그 추출과 Jira 이슈 패널의 워크로그 기록은 이 범위와 무관합니다(Jira 권한 기준).

팀-권한-상속팀 권한 상속

개인 권한 세트를 지정하는 대신 팀 권한 상속을 선택하면 소속 팀(없으면 상위 팀)의 세트를 따릅니다.

  • 선택 시 "현재 상속받게 될 권한: {이름} ({팀})" 이 미리 표시됩니다.
  • 상속받을 권한이 없거나 팀에 소속되지 않았으면 "이 사용자는 모든 권한을 잃게 됩니다" 경고가 나옵니다.
  • 팀에 권한 세트를 거는 방법은 를 참고하세요.

알아두기알아두기

  • 권한 검사는 화면 노출과 별개로 서버에서도 수행됩니다. 권한 없는 작업을 시도하면 "이 작업을 수행할 권한이 없습니다"가 표시됩니다.
  • 권한별로 무엇이 되고 안 되는지는 를 참고하세요.
  • 사용자가 자신의 현재 권한을 확인하려면 을 보면 됩니다.
