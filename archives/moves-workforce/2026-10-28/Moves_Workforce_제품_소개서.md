## 한 줄 요약

**Jira의 업무 기록을 인력·공수·진척·비용의 판단 근거로.**

**Moves Workforce**는 Atlassian Jira Cloud용 Forge 앱입니다. Jira 이슈와 워크로그에 인력·팀·근무 기준·급여 정책을 연결해 프로젝트 운영에 필요한 정보를 한곳에서 확인합니다.

핵심은 **완성·공수·일정을 하나의 진척률로 합치지 않는다**는 것입니다. 공수를 81% 썼다고 일이 81% 끝난 것은 아니며, 세 숫자를 평균 내는 순간 그 차이가 사라집니다.

```
일정 진척  68.0%   ███████████████████░░░░░░░░░   시간이 얼마나 흘렀나
완성 진척  55.6%   ████████████████░░░░░░░░░░░░   상태와 계획 공수로 본 완성 정도
공수 진척  81.2%   ███████████████████████░░░░░   얼마나 일했나

완성 − 일정 = −12.4%p  →  지연
```

> 설명용 예시이며 실제 고객 데이터가 아닙니다. 완성 진척은 일정 진척보다 12.4%p 낮고 공수 소진은 더 큽니다. 이 차이를 근거로 작업 범위·추정 공수·병목을 점검할 수 있습니다. 완성 진척에는 진행 중 이슈의 공수 비율에 따른 근사가 포함됩니다.

> 📷 *캡처 삽입: 프로젝트 상세 > 분석 및 리포트 > 진척률 — 종합 헤더 + 진척 비교 막대*

## 1. 왜 필요한가

**Jira의 이슈·시간 추적 정보를 조직의 인력 배치와 프로젝트 운영 판단으로 연결합니다.**

이슈는 Jira에, 인력 배치는 엑셀에, 비용은 별도 시트에 관리하는 조직에서는 보고할 때마다 자료를 모으고 기준을 맞춰야 합니다. Moves Workforce는 이 정보를 연결해 반복 집계와 대조 작업을 줄이는 데 도움을 줍니다.

| 지금 벌어지는 일 | Moves Workforce가 하는 일 |
|---|---|
| 투입 공수(MM)를 월말에 손으로 집계한다 | Jira 워크로그와 등록된 근무 기준으로 MD·MM을 환산한다 |
| "이번 달 1MM이 며칠이죠?"를 매번 다시 정한다 | 1MM은 그 달의 실제 근무일(평일 − 공휴일)로 자동 계산된다 |
| 휴가·참여 기간을 고려하지 않아 부하 판단이 왜곡된다 | 조회 범위의 참여 기간·연차·공휴일을 반영한 **실효 가용 공수**와 비교한다 |
| 진척률은 담당자의 감(感)이거나, 소진한 공수를 그대로 옮겨 적은 숫자다 | 완성·공수·일정을 분리해 계측하고, 그 차이를 지연 신호로 쓴다 |
| 인건비는 별도 시트에 있고 프로젝트 실적과 연결되지 않는다 | 급여 정책에 따른 계획 인건비와 일정 기준 소진 추정, 워크로그 비중에 따른 이슈별 배분을 확인한다 |

### 어떤 역할에 유용한가

| 역할 | 확인할 질문 | 주요 화면 |
|---|---|---|
| PM | 계획보다 늦거나 공수가 집중되는 작업은 무엇인가? | 진척률 · 작업 분석 · 간트 |
| 팀장 | 팀의 부하가 어떻게 분포하고 누구를 배정할 수 있는가? | 인력 현황 · 팀 분석 · 프로젝트 배정 |
| PMO·의사결정자 | 여러 프로젝트 중 어디를 먼저 살펴봐야 하는가? | 통합 대시보드 · 비용 분석 |
| 구성원 | 어떤 업무에 시간을 기록했고 일정은 어떻게 되는가? | 내 업무 · 워크로그 · 마이페이지 |

## 2. 무엇을 답하나

회의와 운영 과정에서 나오는 **질문을 중심으로** 주요 화면을 소개합니다.

### 2.1 "계획대로 가고 있습니까?" — 진척률

완성·공수·일정 3층 진척과 **차이(%p)** 로 한 줄 결론을 냅니다.

- 누적 S-curve로 계획선 대비 처짐을 확인합니다.
- **확정 지연**(완료 이슈의 실적일 − 기한 평균, 회고)과 **예측 지연**(남은 공수 추세로 본 예보)을 나눠 제시합니다.
- 완성 진척과 일정 진척의 차이로 뒤처짐·선행 정도를 확인합니다. 상태 판정에는 설정된 임계치가 적용됩니다.

### 2.2 "왜 이 작업만 오래 걸립니까?" — 작업 분석

계획 공수(Original Estimate) 대비 실투입 MD를 이슈별로 비교합니다.

- 초과율을 🟢 계획 이내(≤100%) / 🟠 초과(100~130%) / 🔴 심한 초과(130% 이상)로 끊어 **공수 블랙홀**과 범위 누락 후보를 먼저 띄웁니다.
- 남은 공수 추세로 **예상 완료일**을 계산해 기한 초과 이슈를 미리 발견합니다.
- 완료 이슈는 **편차** 컬럼으로 계획 정확도를 사후 검증합니다.

> 📷 *캡처 삽입: 작업 분석 테이블 — 초과율 배지가 섞인 행 + 계획/실투입/예상 완료일 컬럼*

### 2.3 "누가 과부하이고 누가 여유입니까?" — 인력 분석 · 인력 현황

가동률을 **총 MD ÷ 실효 가용 MD**로 계산합니다.

- 분모에 **참여 기간·연차·공휴일**을 반영해 일할 수 있었던 시간과 기록된 시간을 비교합니다.
- 화면의 가동률 구간과 부하 신호로 인력 배분을 점검합니다. 인력 현황 구간과 통합 대시보드 경고 임계치는 구분해서 읽습니다.
- 인별·팀별 보기를 전환하며, 팀 가동률은 개인 비율의 단순 평균이 아니라 `Σ투입MD ÷ Σ가용MD`입니다.

가동률은 기록된 업무 부하를 보여주는 지표입니다. 개인의 성과·역량 점수가 아니며 미기록 업무와 조회 범위를 함께 확인해야 합니다.

> 📷 *캡처 삽입: 자원관리 > 인력 현황 — 상단 요약(여유·적정·과부하) + 가동률 바가 보이는 행*

### 2.4 "이 프로젝트에 누구를 넣습니까?" — 프로젝트 배정

프로젝트의 미배정·임박·지연 작업 수를 왼쪽에, 전사 인력 후보를 오른쪽에 두고 **스킬 적합도**와 **부하 신호**를 나란히 비교합니다. 한 명씩 또는 팀 전체를 그 자리에서 배정합니다.

> 📷 *캡처 삽입: 자원관리 > 프로젝트 배정 — 좌 프로젝트 카드 + 우 후보 목록의 적합도·신호*

### 2.5 "일정과 순서를 어떻게 잡습니까?" — 작업 관리

같은 데이터를 **목록 · 트리 · 간트** 세 뷰로 전환해 봅니다. WBS 계층, 선후행 관계, 폴더로 구조를 잡고 막대를 끌어 일정을 조정합니다.

> 📷 *캡처 삽입: 간트 뷰 — 폴더 계층 + 선후행 선이 보이는 구간(가로로 긴 크롭)*

### 2.6 "여기에 돈이 얼마나 들어갔습니까?" — 비용

급여 정책(**인원별** 또는 **등급 밴드**)을 바탕으로 계획 인건비와 비용 배분을 확인합니다. **미산정 인원** 표시로 설정 누락을 점검할 수 있습니다.

- **계획 인건비**: 프로젝트에 적용되는 유효 투입급여를 합산합니다.
- **소진 비용(AC)**: 계획 인건비를 일정 진척률로 안분한 추정값입니다. 실제 지급액이나 회계 지출 원장이 아닙니다.
- **이슈별 비용**: 인원별 소진 추정액을 워크로그 비중으로 배분해 공수가 집중된 작업을 살펴봅니다.

> 외부 소개 자료에는 가상 인물·가상 급여로 구성한 데모 화면을 사용합니다. 실제 고객 화면을 사용한다면 이름·금액 등 민감정보를 제거합니다.

### 2.7 그 밖에

| 이슈를 매번 손으로 옮기지 않습니다 | 프로젝트 하나가 아니라 전사를 봅니다 |
|---|---|
| Jira 스페이스·보드를 **구독**하면 조건에 맞는 이슈가 자동 편입됩니다 | 통합 대시보드에서 전 프로젝트를 시간·범위·자원 축으로 비교합니다 |
| 생성 이벤트로 즉시 편입하고, 누락은 시간별 정합성 검사가 보완합니다 | 계층형 팀 트리, 팀별 가동률·구성·투입, 담당 팀 대비 실제 기여 |
| 구독을 해제해도 이미 편입된 이슈와 과거 집계는 그대로 유지됩니다 | 목록형 화면은 **현재 필터가 적용된 결과**를 그대로 엑셀로 내보냅니다 |

## 3. 숫자를 해석하는 기준

보고에 쓰이는 숫자는 계산 방식이 공개돼야 신뢰됩니다. 각 화면은 자기가 쓴 분모와 근사 여부를 화면 안에서 밝힙니다.

### MD·MM — 등록된 근무 기준으로 환산합니다

```
MD = 기록 시간 ÷ 설정된 1일 근무 시간
월별 MM = 해당 월 투입 MD ÷ 해당 월 기준 근무 MD
```

월별 기준 근무 MD는 평일과 등록된 공휴일·부분 근무일을 반영합니다. 여러 달을 조회할 때는 화면이 사용하는 기간 기준 분모를 함께 확인합니다. 1일 근무 시간과 공휴일을 먼저 설정해야 조직 기준에 맞는 수치가 나옵니다.

### 가동률 — 분모가 공정합니다

```
가동률(%) = 투입 MD ÷ 실효 가용 MD × 100
```

"일할 수 있었던 시간" 대비 "기록된 업무 시간"입니다. 해당 조회 범위의 경과 기간과 연차·공휴일을 반영하며, 전사 집계에서는 같은 사람의 중복 참여 기간을 합집합으로 계산합니다. 팀 가동률은 개인 비율의 단순 평균이 아니라 `Σ투입MD ÷ Σ가용MD`로 계산합니다. 화면별 대상 프로젝트와 기간이 다르면 값도 달라질 수 있습니다.

### 완성 진척 — 공수 소진과 다릅니다

```
완성 진척 = Σ(이슈 진행률 × 계획공수) ÷ Σ(계획공수)
```

완료는 100%, 할 일은 0%로 계산합니다. 진행 중 이슈는 실투입/계획 공수 비율을 최대 100%로 제한해 근사합니다. 계획 공수가 없거나 0인 이슈는 가중 계산에서 제외되므로 계획 공수 입력 상태를 함께 점검해야 합니다. 이 지표는 산출물 품질이나 고객 검수 완료를 독립적으로 측정하는 값이 아닙니다.

## 4. 데이터와 권한

인력·공수 데이터는 곧 인사 정보입니다. 화면을 숨기는 것으로는 부족하다고 보고, 권한 판정을 **서버**에 두고 응답 자체에서 민감 필드를 제거합니다.

| 항목 | 동작 방식 |
|---|---|
| **데이터 위치** | Jira 이슈·워크로그를 원본으로 사용하고 앱 데이터·집계 스냅샷·일부 조회 캐시를 Forge SQL/KVS에 저장합니다. 고객이 별도 앱 서버나 외부 DB를 구축할 필요가 없습니다 |
| **기능 권한** | 권한 세트 × 리소스 키의 **읽기 / 쓰기 분리**. 서버는 매핑되지 않은 호출을 기본 거부(deny-by-default)합니다. 화면 숨김은 UX이고 실제 경계는 서버입니다 |
| **조회 범위** | 권한 세트마다 프로젝트 범위를 지정합니다 — `ALL` 전체 / `MEMBER_ONLY` 내가 참여한 프로젝트 / `TEAM_ONLY` 내 팀·하위 팀. 팀장은 자신이 이끄는 팀 인원만 조회합니다 |
| **인건비 분리** | 비용·급여는 일반 권한과 분리된 `PROJECT_COST` 키로만 열립니다. 권한이 없으면 0원이 아니라 **카드 자체가 나타나지 않습니다** |
| **등급 밴드 정책** | 등급 기반 급여 정책을 켜면 개인 연봉·투입 급여는 서버 응답에서 **키 자체가 제거**됩니다. 저장 값은 정책을 되돌릴 수 있도록 보존만 합니다 |
| **Jira 조회** | 일반 Jira 조회는 사용자 권한을 기본으로 합니다. 자동 집계 등 시스템 경로와 저장된 집계 정보는 별도의 앱 권한·조회 범위 규칙을 적용합니다 |
| **외부 통신** | 오류 모니터링을 위한 Sentry 연동이 있습니다. Forge 기반이라는 사실을 외부 전송 없음이나 특정 보안 인증 취득으로 표현하지 않습니다 |

**요구 권한(scope)**: `storage:app`, `read:jira-user`, `read:jira-work`, `write:app-data:jira`, `write:jira-work`, `manage:jira-configuration`

## 5. 도입

Jira Cloud 사이트에 설치하면 기본 데이터와 스키마가 자동으로 초기화됩니다. 역할·등급·스킬 프리셋이 함께 제공되며, 관리자가 수정한 값을 이후 시드가 덮어쓰지 않습니다.

### 5.1 설치 후 채울 네 가지

| 단계 | 내용 |
|---|---|
| **1. 근무 기준 정하기** | 1일 근무 시간(기본 8h)과 공휴일을 등록합니다. 모든 근무일 기반 계산의 분모가 됩니다 |
| **2. 인력 등록** | Jira 사용자를 불러오거나 엑셀로 일괄 등록합니다. 대용량은 백그라운드로 처리되고 진행률이 표시됩니다 |
| **3. 팀·권한 구성** | 계층형 팀과 팀장을 지정하고 권한 세트를 배정합니다. PM·PMO·팀장·팀원 프리셋이 기본 제공됩니다 |
| **4. 프로젝트 연결** | 프로젝트를 만들고 Jira 스페이스·보드를 구독하면 이슈가 자동으로 편입되기 시작합니다 |

### 5.2 별도 앱 인프라 구축 부담을 줄이는 구조

- Atlassian Forge 위에서 실행 — 고객의 별도 앱 서버 구축이 필요하지 않습니다. 앱 업데이트와 설정 관리는 필요합니다
- Jira 테마(라이트/다크)를 자동으로 따릅니다
- 한국어·영어 인터페이스를 제공합니다
- 저장 공간 사용량과 임계치(80/90%) 경고를 관리자 화면에서 확인합니다

### 5.3 도입 전 확인할 점

- **Jira Cloud 전용**입니다 — Server / Data Center에는 설치되지 않습니다
- 투입 공수는 워크로그를 기준으로 합니다. **기록이 없으면 투입 공수·가동률을 실제 업무량으로 해석할 수 없습니다**
- 진척률은 이슈에 **계획 공수(Original Estimate)** 가 입력돼 있어야 계산됩니다
- 전사 통합 집계는 일 단위 배치 스냅샷이며, 권한이 있으면 재집계를 요청할 수 있습니다. 비동기 완료와 기준 시각을 확인해야 하며 모든 화면이 실시간 갱신되는 것은 아닙니다
- 등급 기반 급여 정책을 쓰려면 대상 전원의 등급과 각 등급의 대표값(또는 하한·상한)을 먼저 채워야 합니다

## 7. 소개 PPT 구성과 이미지 전략

**대상·분량**: PM·PMO·팀장·도입 의사결정자 대상, 10~15분 발표용 12장. 고객의 문제 → 차별점 → 실제 화면 → 도입 흐름 순으로 구성합니다.

### 7.1 슬라이드별 메시지와 시각 자료

| 장 | 메시지 | 이미지·도식 계획 |
|---|---|---|
| 1. 표지 | Jira 데이터를 프로젝트 운영의 판단 근거로 | 통합 대시보드 핵심 영역을 크게 배치하고 제품명·한 줄 가치 표시 |
| 2. 고객의 문제 | 보고할 때마다 흩어진 숫자를 맞추는 부담 | Jira 이슈·인력 시트·보고서가 분산된 상황을 편집 가능한 도식으로 표현 |
| 3. 핵심 차별점 | 공수 소진과 업무 완성은 다르다 | §한 줄 요약의 일정·완성·공수 비교 막대. ‘설명용 예시’ 표시 |
| 4. 제품 전체상 | 인력·공수·진척·비용을 연결한다 | Jira 이슈·워크로그와 근무 기준·급여 정책을 각 분석 영역에 연결하는 도식 |
| 5. 진척 관리 | 계획과 실적의 차이로 점검 대상을 찾는다 | 진척 분석의 비교 막대·S-curve 확대. 근사 지표임을 짧게 표시 |
| 6. 인력 현황 | 가용 시간과 기록 시간을 비교한다 | 인력 현황 요약과 가동률 행. 색상과 상태 문자를 함께 표시 |
| 7. 인력 배정 | 스킬과 부하를 함께 보고 배정한다 | 프로젝트 배정 화면에서 후보의 적합도·부하 영역 확대 |
| 8. 작업·일정 | 계층과 선후행 관계로 작업 순서를 파악한다 | 6~10개 작업과 연결선이 읽히는 간트 구간을 가로로 배치 |
| 9. 비용 | 계획 인건비와 소진 추정·배분을 확인한다 | 가상 급여의 데모 비용 화면. ‘일정 기준 소진 추정’ 설명을 화면 옆에 표시 |
| 10. 전사 관점 | 여러 프로젝트에서 먼저 볼 대상을 고른다 | 통합 대시보드 전체상과 핵심 비교 영역. 집계 기준 시각 유지 |
| 11. 도입·권한 | 운영 기준과 접근 범위를 설정한다 | 근무 기준 → 인력 등록 → 팀·권한 → 프로젝트 연결의 4단계 도식 |
| 12. 다음 단계 | 우리 프로젝트 데이터로 확인한다 | 제품 화면 한 장, 데모·적용 상담 안내와 확인된 연락처 |

개인 종합 분석·기간 리포트는 대상 환경의 배포 확인 후 청중의 관심에 따라 6장·10장을 대체하거나 부록에 넣습니다. 실제 제공 기능처럼 보이는 가상 UI를 제작하지 않습니다.

### 7.2 캡처 준비와 디자인 원칙

- **구성 비중**: 실제 제품 화면 약 60%, 설명용 도식·차트 약 30%, 분위기 이미지 10% 이하를 권장합니다. 기능의 근거는 실제 화면으로 보여줍니다.
- **데모 데이터**: 같은 프로젝트·같은 조회 기간·같은 테마를 사용합니다. 인력명·고객명·이슈 내용·급여는 가상 데이터로 준비합니다.
- **가독성**: 한 장에 핵심 화면 하나와 확대 영역 하나를 기본으로 합니다. 콜아웃은 2~3개 이내로 제한하고 필터·단위·기준 시각을 남깁니다.
- **일관성**: 로고·브랜드 가이드가 있으면 우선 적용합니다. 없으면 네이비·화이트·청록 포인트를 임시 디자인으로 사용합니다. 공식 브랜드 색상으로 간주하지 않습니다.
- **편집성**: 도식과 예시 그래프는 PowerPoint 도형·차트로 만듭니다. 예시 숫자는 실제 고객 실적과 명확히 구분합니다.
- **AI 이미지**: 필요한 경우 표지의 추상 배경에만 사용합니다. 제품 UI·로고·숫자·한글을 이미지 생성으로 대체하지 않습니다.
- **자료 누락**: 캡처가 없으면 ‘제품 화면 삽입 예정’과 화면명·강조 영역을 적습니다. 연락처·가격·도입 실적·절감률·인증·Marketplace 링크를 임의로 만들지 않습니다.

### 7.3 외부 공유 전 확인할 항목

1. 소개할 기능이 대상 환경에 배포되어 있고 데모 계정에서 동작하는지 확인합니다.
2. 캡처의 민감정보와 예시 데이터 표시를 확인합니다.
3. 완성 진척의 근사, 비용의 추정·안분, 대시보드의 집계 시점을 설명에 반영합니다.
4. 제품 문의·설치 링크를 실제 주소로 채우고, 확보되지 않은 항목은 제거합니다.
