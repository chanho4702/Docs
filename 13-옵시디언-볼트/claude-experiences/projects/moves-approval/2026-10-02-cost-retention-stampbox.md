# 비용 점검에서 출시 준비까지 — 스윕 축소, 보관 정책, 결재란·증명서

날짜: 2026-10-02 ~ 10-04 · 프로젝트: [[moves-approval]] · 관련: [[2026-08-31-kvs-concurrency-tunnel-trap]], [[forge-migration-lifecycle]]

"컴퓨팅 비용이 많이 드는 것 같다"에서 시작해 출시 전 정리까지 이어진 사흘. 결정과 함정만 남긴다.

## 1. 비용의 정체는 승인 처리가 아니라 주기 작업이었다

- 5분 스윕(하루 288회)이 할 일이 없어도 SQL ~10·KVS 15 를 썼고, 마감 임박·독촉 후보를 **이미 알림을 보냈어도 매번 load(쿼리 3회)** 했다. 결재가 쌓일수록 커지는 구조.
- 5분 → 시간 → **하루 한 번**(사용자 결정). 할 일 대부분이 일 단위였다.
- 주기를 늘리기 전에 "주기가 정밀도를 정하던 곳"을 전부 다른 경로로 옮겼다: 결정 경로가 지난 마감을 즉시 만료(도메인에도 가드 — CAS 재시도도 같은 now 로 같은 판정), 재요청은 `expireOpenRequest` 가 이미 처리, byline 은 `expiresAt` 으로 "기한 초과" 표시, 마감 임박 창은 최소 24시간.
- 이미 보낸 알림은 `event_key IN (...)` 한 번으로 걸러 load 를 생략. 키에 단계를 넣지 않으면 임박 구간 중 단계가 넘어간 새 결재자가 누락된다(Codex 지적).

## 2. 보관 정책 — "내보낸 것만 지운다"를 성립시키는 근거

- 끝난 요청은 다시 바뀌지 않으므로 **같은 cutoff 의 대상 집합이 고정**된다. 그래서 cutoff 를 기록해 두면 "내보낸 범위만 삭제"가 성립한다.
- 처음엔 마지막 페이지를 내줄 때 기록했다 → 화면이 파일 생성에 실패해도 삭제 범위가 열린다. **파일을 실제로 내려받은 뒤 별도 호출로 확정**하게 바꿨다.
- 넘겨받은 cutoff 는 정책보다 미래로 못 늘린다(최근 기록 삭제 경로 차단).

## 3. 함정

- **매크로 높이는 `<html>` 이 아니라 #root 를 재야 한다.** iframe 안의 `<html>` 은 뷰포트에 묶여 내용이 자라도 안 변한다 → 이름·서명 이미지가 늦게 오면 아래가 잘림. body 기본 여백 8px 도 빠져 있었다.
- **REST 로 심는 Forge 매크로는 ARI extensionKey**(`ari:cloud:ecosystem::extension/{appId}/{envId}/static/{key}`). app/env 는 `getAppContext()`. 스파이크(S2)에서 확인해 둔 게 그대로 쓰였다 — 지운 코드도 `git show` 로 다시 꺼내 읽을 가치가 있다.
- 결재란 자동 삽입은 **검증을 다 통과한 뒤** 넣고, 오른 버전으로 요청을 건다. 원래 버전으로 걸면 곧바로 "요청 이후 수정됨".
- 스파이크 resolver 9개가 전부 PUBLIC 이었다(페이지 생성 포함). 검증 모듈은 "나중에 지운다"가 아니라 출시 체크리스트에 넣어야 한다.
- CRA 는 CI=true 에서 Atlaskit CSS Minimizer 경고를 에러로 올린다 → 파이프라인 빌드 단계만 `CI=false`. 워크포스 파이프라인을 그대로 복사하면 locales 병합(`npm run merge`)이 빠져 백엔드가 import 에서 죽는다.
- Codex 의 Windows 읽기 전용 샌드박스가 UAC 취소(1223)로 셸을 못 띄우고, 저장소에 `%SystemDrive%/` 캐시 폴더를 남겼다. `codex review --commit` 은 프롬프트와 같이 못 쓴다 → `codex exec -s read-only` 로 우회.
- 증명서 PDF: 한글 글꼴을 심으면 수 MB → 본문은 html2canvas 이미지, 검증값(요청 ID·SHA-256)만 ASCII 텍스트·키워드로. 흰 종이·고정색으로 그려야 다크 테마에서 검은 PDF 가 안 된다.

## 4. 남은 것

- 화면 실측을 한 번도 못 했다(브라우저 확장 미연결). 결재란 자동 삽입이 최대 위험.
- 데이터 관리·결재란·증명서·표 교체는 Codex 검수 전.
