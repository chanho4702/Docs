## ① 프로젝트 핵심 요약 (PPT 소스팩)

### 한 줄 정의
**Moves Workforce (Moves RMS)** — Jira Cloud 안에 설치되는 Forge 앱. 워크로그(작업 시간 기록)를 원천 데이터로 프로젝트의 **인력·공수(MD/MM)·가동률·진척도·인건비**를 관리·분석하는 워크포스 관리 도구.

### 문제 인식 (Why)
- Jira는 "이슈가 어떤 상태인가"는 보여주지만 **"사람과 공수 관점에서 프로젝트가 어떤 상태인가"** 는 보여주지 않는다.
- 누가 얼마나 투입됐나(가동률), 계획 대비 실제 공수는(추정 정확도), 일정 대비 진짜 얼마나 끝났나(진척), 인건비는 얼마인가 — 전부 별도 엑셀로 하던 일.
- Moves Workforce는 이를 **Jira 안에서**(별도 시스템·데이터 반출 없이) 해결.

### 사용자별 가치
| 사용자 | 얻는 것 |
|---|---|
| 실무자 | 워크로그 기록(캘린더/테이블, 기간 일괄 입력), 내 업무·목표시간 현황 |
| PM | 프로젝트별 인력·작업·진척·리스크 이슈 관리, 계획 대비 실투입 분석 |
| 경영진/PMO | 전사 통합 대시보드 — 프로젝트별 T/S/R 신호등, 가동률·인건비 비교 |

### 핵심 도메인 개념 (차별화 포인트이기도 함)
- **MD/MM**: 1MD = 1Day 근무시간(기본 8h, 설정 가능). **1MM = 그 달 실제 근무일(평일−공휴일)** — 달력 비례식이 아닌 실근무일 기반 자동 산출.
- **가동률** = 투입MD ÷ 실효 가용MD(근무일에서 **연차·공휴일 차감**) → 휴가자가 "일 안 한 사람"으로 과소평가되지 않는 공정한 분모. MM(절대 투입량)과 분리된 상대 지표.
- **진척도 3층 분리**: 공수(얼마나 일했나) ≠ 완성(얼마나 끝났나) ≠ 일정(시간이 얼마나 흘렀나) — 한 숫자로 합치지 않음. "공수 80% 썼으니 80% 끝났다"는 함정 차단. 핵심 신호 = **완성률 − 일정률**(음수면 지연).
- **T/S/R 신호등**: 전사 대시보드에서 프로젝트별 일정(Time)/범위(Scope)/자원(Resource)을 정상/주의/위험으로 요약.

### 기능맵 (화면 기준)
1. **My Work** (`/myWork`, 기본 진입) — 요약지표 5카드(월/주/일 누적 vs 목표시간), My 프로젝트, 캘린더/테이블 뷰, 워크로그 추가(단건 + **기간 일괄 생성, 실패 시 전체 롤백**), 마크다운 편집기(ADF 저장), 협업자(coworker) 개념.
2. **프로젝트 관리** (`/project`) — 목록(기간·예산·상태) + **칸반 보드**(드래그 상태 변경, 컬럼=커스텀 상태, 인라인 편집).
3. **프로젝트 상세** (`/project/:id`) 탭:
   - **대시보드** — 요약 카드(인력/기간/총 인건비) + 위젯(역할·등급·담당자·작업·급여 분포, 히트맵, 라인차트) + **react-grid-layout 드래그 배치·커스텀 차트 추가**(레이아웃 프로젝트별 저장).
   - **인력 관리** — 멤버별 역할/등급/급여 인라인 편집 (인건비 산정 기준).
   - **작업 관리** — Jira 이슈 편입 방식(`projectId` 커스텀 필드), 담당자·동료·일정 인라인 편집 → Jira 즉시 반영, 계획 작업량(MD)·처리율.
   - **간트** — 이슈 연결 간트(SVAR): 일정 편집 + **계층(임의 깊이 WBS) + 선후행(네이티브 이슈 링크)** 편집, 폴더·드래그앤드롭.
   - **프로젝트 캘린더** — 프로젝트 전체 워크로그·이벤트 (작업자/작업 필터).
   - **분석 및 리포트**:
     - **이슈 분석** — 계획(Original Estimate) vs 실투입(워크로그) MD 비교, 예상 완료일, 초과율 신호색(🟢≤100% / 🟠~130% / 🔴130%+), 이슈별 S-curve, 엑셀 내보내기. → 추정 정확도·공수 블랙홀·일정 리스크.
     - **인력 분석(MM)** — 멤버별 총MM·실효 가용MD·가동률(⚪<50% 저활용 / 🟢 / 🔵 적정 / 🔴>100% 과부하), 일/주/월 투입 추이 + 1MM 기준선. → 부하 균형·투입량 정산.
   - **진척도** — 3층(완성/공수/일정) 비교 막대, S-curve(계획 vs 실적 누적 + 예상 완료 마커), 상태별 분포(개수/공수), 지연·위험 이슈 테이블, 확정 지연(회고) vs 예측 지연(예보).
4. **통합 대시보드** (`/dashboard`, 전사) — 종합 개요 T/S/R 신호등 + 비교 서브탭 4종(일정=간트·공수추이·계획대비실적 / 범위=완성률vs일정률·리스크TOP·문제이슈 버블 / 자원=롤·레벨 분포·가동률 / 비용=인건비·급여 히스토그램). 배치 스냅샷 기반 + 온디맨드 재집계 버튼. 위젯마다 계산식 안내(ⓘ).
5. **Settings** (`/backoffice/*`) — 일반 설정(1Day 근무시간·가동률 band), 사용자 관리(**엑셀 대량 업로드, 큐 기반 비동기+진행률 폴링**), 역할/등급/프로젝트 상태(**상태 전이 파이프라인 시각 편집**)/공휴일(월별 MM 요약), **권한 관리**.

### 권한/보안 (엔터프라이즈 어필 포인트)
- 권한 세트(Admin/Member + 커스텀) × 리소스 14키 × 읽기/쓰기.
- **서버 측 가드**: 모든 resolver(109개)가 요청마다 서버에서 권한 검증, **deny-by-default**(미매핑=자동 거부), fail-close. 버튼 숨김 수준이 아님.
- **프로젝트 스코프**: 권한 세트별 "소속 프로젝트만 조회"(ALL/MEMBER_ONLY) — 외주·파트너 차등 운영 가능.
- 데이터는 Atlassian 인프라(Forge SQL/KVS) 안에만 존재 — 외부 서버 없음.

### 기술 아키텍처 (기술 청중용 1장)
```
Jira (이슈·워크로그·사용자·커스텀 필드 projectId/coworker)
   ↓ REST API
Forge 백엔드 (Node.js resolver: 집계·MM/가동률/진척 계산, 서버 권한 가드)
   ↓ Forge SQL(MySQL: 프로젝트/사용자/워크로그) + KVS(설정·캐시·스냅샷)
React 18 UI (Atlaskit 디자인시스템 — Jira와 동일한 룩앤필, ECharts/FullCalendar/간트/칸반)
```
- **Atlassian Forge 플랫폼**: 설치형 앱, 별도 서버·인프라 불필요, Atlassian 보안 경계 내 실행.
- 성능 설계: 전사 집계는 스케줄 배치 스냅샷, 분석은 프로젝트 단위 1회 페치 + KVS 캐시, 대량 업로드는 이벤트 큐.
- i18n 한/영 지원. Sentry 모니터링.

### 수치·상태 (2026-07-06 기준, 지어내기 방지용 사실 목록)
- 백엔드 resolver 109개 전수 권한 가드, 권한 리소스 카탈로그 14키.
- 테스트: 백엔드 165개(12 suites), 프론트 58개(6 suites).
- 화면: 글로벌 페이지 4메뉴 + 프로젝트 상세 7탭 + 백오피스 7페이지.
- 진행 중(발표 시 언급 주의): 간트·권한 고도화 배포 전 최종 확인 단계.

## ② Genspark 프롬프트 작성 요령 (조언)

1. **소스를 반드시 프롬프트에 동봉하라.** Genspark는 이 앱을 모른다 — 프롬프트만 주면 일반적인 RMS 얘기를 지어낸다. 위 ①소스팩을 프롬프트 뒤에 `[참고 자료]`로 붙이는 게 핵심. (사용자 매뉴얼 530줄 원문은 과함 — 소스팩 수준의 증류본이 적당.)
2. **슬라이드별 4요소를 지정하라**: 제목 / 핵심 메시지 1문장 / 불릿 3~4개 / 시각 요소(다이어그램·표·차트·스크린샷 자리). 아웃라인을 통째로 맡기면 구조가 평범해진다.
3. **"자료에 없는 수치·기능을 지어내지 마라"를 명시하라.** AI 슬라이드 도구의 최다 사고 지점. 수치는 위 ①의 "수치·상태" 목록만 쓰게 한다.
4. **스크린샷은 자리표시자로.** Genspark는 실제 앱 화면을 못 만든다. "여기는 실제 화면 캡처 자리(placeholder + 캡션)"로 지시하고, 생성 후 직접 캡처로 교체하는 게 결과물이 훨씬 신뢰감 있다. AI 이미지로 가짜 UI를 그리게 하면 오히려 역효과.
5. **2단계 플로우 활용**: Genspark는 아웃라인 확인 → 생성 순서로 진행된다. 아웃라인 단계에서 장수·순서를 손보고 나서 생성 승인할 것. 생성 후엔 슬라이드 단위로 "이 장만 수정" 지시가 잘 먹힌다.
6. **디자인 지시는 짧고 명확하게**: 톤(예: 밝고 신뢰감 있는 SaaS 제품 소개), 주 색상, 언어(한국어, 기술 용어는 영문 유지), 텍스트 밀도(불릿 최대 4개).
7. **청중에 따라 프롬프트를 갈아끼워라** (아래 ③은 기본형=제품 소개):
   - **경영진/고객**: 기능 나열 축소, 문제→가치→차별점→신뢰(보안) 중심 10~12장.
   - **개발팀/기술**: 아키텍처·성능 설계·권한 가드 장을 확대, [[2026-07-06-permission-hardening]] §8의 기술 발표 프롬프트와 병합.

## ③ 복붙용 Genspark 프롬프트 (기본형: 제품 전체 소개, 16장)

```
Jira Cloud용 워크포스 관리 앱 "Moves Workforce"의 제품 소개 프레젠테이션을 만들어줘.

[청중] 이 제품을 처음 보는 사내 관계자·잠재 고객 (Jira는 알지만 이 앱은 모름)
[분량] 슬라이드 16장, 한국어 (기술 용어·제품명은 영문 유지)
[디자인] 밝고 신뢰감 있는 SaaS 제품 소개 스타일. 파란색 계열 포인트 컬러. 슬라이드당 불릿 최대 4개, 텍스트 과밀 금지.
[절대 규칙] 아래 [참고 자료]에 없는 기능·수치를 지어내지 마라. 앱 화면이 필요한 곳은 AI 이미지를 그리지 말고 "화면 캡처 자리" placeholder + 캡션으로 남겨라.

슬라이드 구성:
1. 표지 — "Moves Workforce: Jira 안에서 끝내는 인력·공수·진척 관리" + 한 줄 소개
2. 문제 — Jira는 이슈 상태는 보여주지만 "사람과 공수"는 못 보여준다. 가동률·계획 대비 공수·진척·인건비는 전부 엑셀로 하던 일 (Before 시나리오)
3. 솔루션 개요 — Jira에 설치되는 Forge 앱. 워크로그를 원천 데이터로 인력·공수·진척·비용을 한곳에서. 데이터는 Atlassian 밖으로 나가지 않음 (3개 아이콘 카드: 기록→분석→의사결정)
4. 사용자별 가치 — 실무자/PM/경영진 3열 표
5. 핵심 개념 — MD·MM(실근무일 기반)·가동률(연차 차감 분모)·진척 3층 분리. "공수 80% 썼다 ≠ 80% 끝났다" 메시지 강조
6. 기능맵 — My Work / 프로젝트 관리 / 프로젝트 상세(7탭) / 통합 대시보드 / Settings 한 장 지도 (다이어그램)
7. My Work — 개인 워크로그: 캘린더·테이블 뷰, 기간 일괄 입력(실패 시 전체 롤백), 월/주/일 목표시간 대비 현황 [화면 캡처 자리]
8. 프로젝트 관리 — 목록 + 칸반 보드(드래그 상태 변경, 커스텀 상태 컬럼) [화면 캡처 자리]
9. 프로젝트 상세 ①: 대시보드·인력·작업 관리 — 위젯 대시보드(드래그 배치·커스텀 차트), 멤버별 역할/등급/급여 인라인 편집, Jira 이슈 편입·즉시 반영 [화면 캡처 자리]
10. 프로젝트 상세 ②: 간트 — 일정·계층(임의 깊이 WBS)·선후행(Jira 네이티브 이슈 링크) 편집 [화면 캡처 자리]
11. 분석 리포트 ①: 이슈 분석 — 계획 vs 실투입 MD, 초과율 신호색(초록/주황/빨강), 이슈별 S-curve, 엑셀 내보내기 → "추정 정확도와 공수 블랙홀을 찾는다" [화면 캡처 자리]

13. 진척도 — 완성/공수/일정 3층 비교, 핵심 신호 = 완성률−일정률(음수면 지연), S-curve, 지연·위험 이슈 테이블, 확정 지연(회고) vs 예측 지연(예보) [화면 캡처 자리]
```
