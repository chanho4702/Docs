# 팀 분석 확충 — 설계 5차 검토와 배치 전환

> 프로젝트: [[moves-workforce]]
> 선행: [[2026-07-06-permission-hardening]] · [[2026-06-11-analysis-review]]
> 커밋: `165bd21`(RFC-172) · `f9be032`(174) · `3e42d80`(175) · `e3d8e5c`(176)
> 작업 디렉토리: `_workspace/team-analytics/`

## 결론

RFC-147 팀 개념 도입의 잔여(N3-1·InfoTip·P3-B)를 끝내고, 그 위에 **팀 분석 화면**을 새로 만들었다.
설계는 외부 모델(codex `gpt-5.6-sol`) 검토를 **5회** 거쳤고 지적 30여 건이 **전부 실제 결함**이었다(설계자 반박 0건).

- 프론트 60 suites / 1028 tests, 백엔드 56 suites / 860 tests, build PASS
- 신규 resolver **1개**, 신규 권한 키 **0개**, 신규 차트 옵션 빌더 **0개**
- **배포·E2E 미수행.** 배포 전 권한 감사 필수(아래 §열린 항목)

---

## 1. 가장 큰 배움 — "화면이 안 맞는다"는 신호는 예외 처리로 드러난다

설계 초안은 팀 분석을 **통합 대시보드에 위젯으로 확충**하는 것이었다. 4차 검토까지 통과한 뒤
사용자가 *"뭔가 통합 대시보드랑 안 맞는 것 같다"* 며 자원관리로 옮기자고 했다.

그 직관이 옳았다는 근거가 설계서 안에 이미 있었다:

> 가동률은 분모(`availMd`)가 **전 프로젝트 참여 구간의 union** 이라 프로젝트 필터에 반응하지 못한다(M-1).
> → 그래서 "이 축을 고르면 필터가 안 먹습니다"라는 **예외 안내**를 띄우도록 설계돼 있었다.

통합 대시보드의 핵심 조작이 "프로젝트 선택"인데 주력 지표가 거기 반응하지 못한다는 것은
**지표가 그 화면에 속하지 않는다는 신호**였다. 옮기고 나니 예외 처리 자체가 사라졌다.

부수 효과로 **검토 지적 6건이 통째로 소멸**했다 — B3/B4 집계 계약 부재(중대 2건),
위젯 간 스코프 비일관, 배지 상호 안내, 탭 조립 `ReferenceError`, 원자 배포 제약.

> 💡 **예외 처리가 늘어나는 축은 배치를 의심하라.** 안내 문구로 덮는 것은 증상 처리다.
> 축이 다르면(대시보드=프로젝트 / 자원관리=사람) 화면을 옮기는 편이 싸다.

## 2. 검토 5회에서 나온 결함 (설계 단계에서 잡은 것)

| 차 | 결과 |
|---|---|
| 1차 | 12건(치명 1·중대 7) → **착수 불가** |
| 2차 | 해소 9·부분해소 3 + **새 결함 5** → 착수 불가 |
| 3차 | 해소 5·부분해소 3 + **새 결함 8**(중대 3) → "수정 후 착수 가능" |
| 4차 | **조건부 2건** → P1-a만 착수 승인 |
| 5차 | 배치 전환분 3건 → 구현 병행 |

### 치명 — 비가시 팀이 "알 수 없는 팀"으로 되살아난다

```js
// rollupTeamTree.js:148-150
for (const key of groupByKey.keys()) {
    if (!metaByKey.has(key)) metaByKey.set(key, { id: key, name: null, parentTeamKey: null });
}
```

팀 메타(이름 사전)에만 필터를 걸면 이 세 줄이 **필터로 제거한 팀을 루트 노드로 복원**한다.
이름만 `(알 수 없는 팀)` 으로 가려지고 **MD·인건비 수치는 그대로 노출**된다.

→ 집계 함수가 `scope`(`allowedTeamKeys`+`includeUnassigned`)를 **필수 인자로 받고 미전달 시 throw**.
복원 루프에도 검사를 넣어 이중 방어.

> 💡 **필터는 "결과"가 아니라 "집계 진입 전"에 건다.** 결과만 거르면 (a) 복원 루프 같은 경로로 되살아나고
> (b) 비율의 분모가 전체로 남아 값이 틀어진다.

### "알려진 0"을 `null` 로 만들면 분모까지 잃는다

이 리포는 오래 **`?? 0` 금지**(모름을 0으로 만들지 마라)를 지켜 왔는데, 이번엔 **정반대 실수**가 나왔다.

지연율(`delayedShare`) 설계에서 **정상 프로젝트의 지연 공수를 `null`** 로 뒀다.
`aggregateByTeam` 은 **분자·분모가 둘 다 숫자인 행만** 누적하므로, 정상 행이 분모에서도 빠진다.

```
지연 5MD + 정상 5MD 인 팀 → 5/5 = 100%   (실제 50%)
```

→ 정상 행은 **알려진 `0`** 이다. §8-2 에 "모르는 값(null) vs 알려진 0" 판단 기준표를 신설했다.

> 💡 **비율 필드는 분자와 분모가 같은 행 집합을 봐야 한다.** 분자만 `null` 로 만들면 분모까지 잃는다.

### 응답 래핑 — 같은 앱에서 두 형태가 공존한다

`responseWrapper` 는 `{success:true, ...result}` 로 **스프레드**한다.
- 서비스가 `{content:{...}}` 를 반환 → 소비는 `res.content.*`
- 서비스가 평면 객체 반환 → 소비는 `res.*`

설계서가 `content.team.teamAnalyticsScope` 로 적었는데 실제는 **루트 `res.team`** 이었다.
그대로 구현했으면 **메뉴가 전면 미노출**된다. 이 리포에서 같은 계열 사고가 이미 한 번 났다(프로젝트 목록 상태 간헐 미표시).

### 프리셋 판정표를 계약으로 쓸 수 없다

권한 프리셋(PM/PMO/Team Lead/Team Member)은 `edit:true` 이고 **최초 1회만 생성**된다.
시드 `Member.projectScope` 도 기존 저장값을 보존한다.
→ "프리셋 이름 기준" 테스트는 **운영 설치값을 보장하지 못한다.**
`resourceMap × projectScope × isTeamLead` **조합표**로 고정하고, 배포 전 KVS 감사 절차를 넣었다.

### 정적 검사가 0개 파일을 검사하고 있었다

`teamScopeLeak.test.js` 가 존재하지 않는 경로(`pages/teamAnalytics/**`, 설계 변경으로 폐기된 경로)를
가리켜 **대상 0개에 대해 통과**하고 있었다. → 경로 수정 + `targets.length > 0` 단언 추가.

> 💡 **경로 기반 정적 검사에는 "검사 대상이 1개 이상"을 반드시 단언하라.** 오타 하나로 조용히 무력화된다.

## 3. 구현에서 나온 것

### characterization test 가 실제로 값을 했다

기존 화면(`ResourceAnalysisPage`)에서 어댑터를 추출하기 전에 현행 동작을 10항목으로 고정했는데,
**설계서 표에 없던 동작 1건**이 발견됐다:

> 500명 초과 시 팀 뷰뿐 아니라 **팀 필터도 함께 무력화**된다

놓쳤으면 추출 과정에서 조용히 사라졌을 동작이다.

실행 순서도 정석이었다 — 어댑터 작성 → **페이지를 바꾸기 전에** 32 테스트 PASS →
추출·교체 → **같은 파일 무수정** 재실행 PASS. 테스트를 고쳐가며 맞춘 게 아니라는 기계적 증거다.

### 테스트가 버그를 정답으로 고정하고 있던 사례 2건

**① 기간 계산 (실제 버그였다)**

```js
// 기대값을 검증 대상 함수로 만들면 무엇을 바꿔도 통과한다
expect(getQuickRange('lastMonth', NOW)).toEqual({
    start: fmt(new Date(2026, 6, 1)),   // ← 같은 fmt
    end:   fmt(new Date(2026, 7, 0)),
});
```

`fmt` 가 `toISOString()`(UTC)이라 KST(UTC+9)에서 **로컬 자정이 전날 15:00 UTC** 가 되어
`지난 달` 이 **6/30 ~ 7/30** 으로 나왔다(정답 7/1~7/31). **말일 워크로그가 통째로 빠진다.**
자정 직후(KST 00:00~08:59)에는 `오늘`·`이번 주`도 하루씩 밀렸다.

→ `fmt` 를 로컬 달력 기준으로 바꾸고, 기대값을 **리터럴 날짜**로 교체. 경계 케이스(30일 달·연도 경계·자정 직후) 추가.

**② DnD 손상 부모 정리 (내가 짠 테스트가 오동작을 고정)**

강등된 팀(손상 부모)을 최상위로 놓는 것은 서버 입장에서 **손상 정리**인데,
프론트가 유효 부모로 비교해 "이미 루트"라며 막고 있었다. 그 오동작을 테스트가 정답으로 굳혀 두었다.
→ 무변화 판정만 `rawParentTeamKey`(KVS 원본) 기준으로. 순환·깊이는 유효 부모 기준 유지.

> 💡 **기대값을 검증 대상 함수로 만들지 마라.** 동어반복이 되어 버그까지 함께 고정된다.
> 날짜·금액처럼 사람이 검산할 수 있는 값은 **리터럴**로 쓴다.

### 단일 소속 검증은 맵으로 바꾸기 **전** 원본에서

`assertSingleMembership(memberTeamMap)` 을 프론트에 두려던 계획이 **검출력 0** 이었다.
`Object.fromEntries` 가 중복을 이미 덮은 뒤라 그 시점엔 중복을 볼 수 없다.
→ 백엔드 `findAllMemberTeamPairs()` **원본 배열**에서 검증. 검출력 증명 테스트도 함께 남겼다
(같은 입력에서 맵이 3행→2키로 줄고 마지막 값이 이기는 것을 코드로 고정).

## 4. 만든 것

### RFC-172 — RFC-147 잔여

- **N3-1** 인력 분석 리포트 인별↔팀별 토글. `issueCount` 는 사람 간 중복 계상이라 **소계 컬럼 자체를 제외**하고 이유를 표에 밝힘
- **P3-B** 팀 트리 드래그앤드롭(백오피스 전용). `Boolean(canWrite && onDrop)` 옵트인 — 같은 패널을 `/resource` 가 재사용하므로
- **N3-2 보류 확정** — 인력 탭에 MM·인건비가 **없다**(salary 는 U10 회귀 가드가 SELECT 를 막고, MM 은 워크로그 조회가 필요). 인계서 스펙이 낡았던 것

### RFC-174/175 — 팀 분석 기반 + 화면

- `resolveTeamAnalyticsScope(principal)` → `ALL|LEADING|NONE` **단일 함수**를 두 소비처가 호출 → 메뉴/데이터 드리프트 구조적 불가
- 🔴 `projectScope === 'ALL'` 조건이 핵심 — **`Team Lead` 프리셋이 `RESOURCE_MANAGEMENT read` 를 보유**해서 이게 없으면 팀장이 전 팀으로 승격
- 🔴 `REPORT read` 로 열면 안 됨 — 시드 `Member` 가 `REPORT read`+`projectScope ALL`
- LEADING 은 `leadingScopeTeamKeys` 사용(`scopeTeamKeys` 를 쓰면 팀장 아닌 동료에게 열린다 — 과거 D4 사고 계열)

### RFC-176 — 필터·차트·관계도

- 팀 **다중 선택** + 프로젝트 **다중 선택(검색)** + 진행중/전체 프리셋
- **프로젝트별 팀 투입 차트** — 기존 5종이 전부 팀을 행으로 둬서 "이 프로젝트에 누가 얼마나"를 볼 수 없었다
- **배정 관계도 3레이어**(프로젝트→팀→담당자) — 인력 현황에서 프로젝트 배정 탭으로 이관
- **팀 전체 배정** — `insertProjectusers` 가 이미 배열을 받아 백엔드 변경 0

## 5. 재사용 가능한 규칙

- **프리셋과 개별 선택을 곱하지 마라** — 실제 필터는 선택 집합 하나, 프리셋은 그것을 채우는 단축키.
  두 조건을 곱하면 "진행중인데 왜 이게 빠졌지"를 사용자가 예측할 수 없다
- **프로젝트 종료 판정은 목적에 따라 다르다** — `isTerminalStatus`(상태만) vs `isProjectClosed`(+종료일 경과).
  **지연 분석에는 상태 기준만** 써야 한다. 기한 초과를 닫힘으로 보면 **지연 프로젝트가 사라져 지연 축이 0 으로 수렴**한다
- **프론트가 백엔드 규칙을 이식할 때는 테스트가 원본 파일을 읽어 대조**하게 하라(정규식 문자열까지).
  백엔드가 바뀌면 프론트 테스트가 먼저 깨진다
- **`getTeamList` 대신 `getTeamOptions`** — grant 가 `OR[TEAM_MANAGEMENT r, USER_MANAGEMENT r]` 라
  `RESOURCE_MANAGEMENT` 만 가진 사용자에게 **항상 거부**된다
- **`canRender` 는 탭을 숨기지 않는다** — 선택 시 `NoPermissionPage` 를 보여줄 뿐. 리포 관례이며 의도된 것
  (사라진 이유를 알 수 없는 것보다 낫다)
- **차트에서 `null` 을 0 막대로 그리지 마라** — 높이 0 은 "값이 0"이라는 주장이다
- **기존 옵션 빌더는 additive 확장** — `orientation`·`valueFormatter` 를 옵션으로 추가하되 미전달 시 현행 동작.
  신규 빌더 파일 0 을 유지했다

## 6. 열린 항목

- 🔴 **배포 전 권한 감사** — `REPORT.read && !RESOURCE_MANAGEMENT.read` 인 **모든 세트**가 통합 대시보드에서
  보던 팀 비교를 잃는다. 시드 `Member`·`Team Member` 외에 **커스텀 세트**와 **팀 권한 상속자**
  (`permission_key IS NULL` + `team.permissionKey` + `nearestAncestorWith`)까지 산출해야 한다. 담당자 승인 없이 배포 금지
- **화면 수동 확인** — 이 리포에 `@testing-library/react` 가 없어 자동 렌더 테스트가 아니다.
  JSX 무변경 diff + 순수 함수 테스트 + 정적 단언의 조합으로 검증했다
- **P2 기간별 추이** — 배치 `monthly_effort_json` 이 **프로젝트 단위**(`monthSecMap[month] += sec`)라 팀 분해 불가.
  워크로그 DDL 은 주석 상태. 배치에 `members[].monthlyEffort` 추가 필요
- **레이더(#6 팀 프로필)** — 완수 규모 산식·4축 정규화·리스크 역변환·null 축 계약이 미정이라 P1 제외
- **배정 ≠ 투입** — 관계도는 배정 기준(`projectusers ⋈ project`), 프로젝트별 투입 차트는 공수 기준.
  전사 `project_team`(담당 팀) 을 한 번에 읽는 resolver 가 없어 "배정만 되고 아직 투입 없는 팀"은 보이지 않는다
- RFC-172 부터 **배포·E2E 미수행** 누적
