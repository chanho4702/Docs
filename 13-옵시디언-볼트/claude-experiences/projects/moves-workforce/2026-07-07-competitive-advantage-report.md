# Moves Workforce 경쟁 우위 분석 보고서

> **작성일**: 2026-07-07 · **목적**: 타사(마켓플레이스 경쟁 앱·Jira 기본 기능) 대비 Moves Workforce의 경쟁 우위를 정리하고, 세일즈·소개 자료에서 앞세울 메시지 우선순위를 제언.
> **근거 자료**: [[moves-workforce-overview]] · [[2026-07-06-ppt-genspark-sourcepack]] · [[2026-07-06-permission-hardening]]
> **주의**: 경쟁사(Tempo·BigPicture 등) 서술은 일반 지식 기준이며 최신 스펙 재검증 필요.

---

## 1. 요약 (Executive Summary)

Moves Workforce의 경쟁 우위는 5가지로 정리되며, 앞세울 순서는 다음과 같다.

1. **보안 — Forge 네이티브, 데이터가 Atlassian 밖으로 나가지 않음** (1순위 영업 카드, 단 시간 한정 우위)
2. **지표 설계의 정합성** — 실근무일 MM·연차 차감 가동률·진척 3층 분리 (가장 저평가된 차별점)
3. **엔드투엔드 커버리지** — 실무자 기록 → PM 분석 → 경영진 대시보드를 한 앱으로
4. **비용(인건비) 분석** — 권한 격리와 한 세트로 제시할 때 강점
5. **간트** — "더 깊은 간트"가 아니라 "공수·진척이 붙은, 데이터 락인 없는 간트"로 프레이밍

한 문장 포지셔닝: **"급여·공수 같은 민감 데이터를 Atlassian 밖으로 내보내지 않으면서, 한국 관행에 맞는 제대로 된 지표로, 기록부터 경영 판단까지 한 앱에서."**

---

## 2. 경쟁 구도

| 경쟁 상대 | 커버 영역 | 비고 |
|---|---|---|
| Jira 기본 (타임라인·Advanced Roadmaps) | 이슈 상태·간단 일정 | 인력·공수·비용 관점 부재 |
| Tempo 계열 (Timesheets + Cost Tracker) | 타임시트 수집·비용(별도 앱) | Connect 기반 — 데이터가 벤더 서버로 나감. 해석(MM·가동률·진척)은 미제공 |
| BigPicture / Structure.Gantt | 간트·포트폴리오 | 간트 뎁스는 최상위, 그러나 공수·비용과 미연결·앱 전용 데이터 |
| 엑셀 (현실의 최다 경쟁자) | 전부 수동 | 데이터 이중 입력·지표 drift |

경쟁 앱은 대부분 **한 조각**(타임시트 or 간트 or 비용)만 커버 → 고객은 2~3개 앱 조합 + 엑셀로 메꾸는 구조.

## 3. 경쟁 우위 상세

### 3.1 보안 — Forge 네이티브 (1순위)
- 데이터 저장소가 Forge SQL/KVS → **워크로그·급여 데이터가 Atlassian 보안 경계를 벗어나지 않음**. Connect 기반 경쟁 앱(Tempo 등)은 벤더 서버에 데이터 저장.
- 앱 자체 권한도 엔터프라이즈급: 서버 측 가드(resolver 109개 전수, deny-by-default, fail-close), projectScope(소속 프로젝트만 조회 — 외주·파트너 차등 운영). → [[2026-07-06-permission-hardening]]
- 별도 서버·인프라 불필요 → 도입·보안 심사·구매 결재 통과가 다른 차원.
- **리스크**: 경쟁사들도 Forge 마이그레이션 진행 중 → 영원한 해자가 아닌 **시간 한정 우위**. 지금 세게 밀어야 함.

### 3.2 지표 설계의 정합성 (가장 저평가된 차별점)
- **1MM = 그 달 실제 근무일(평일−공휴일)** 자동 산출 — 달력 비례식 아님. → [[2026-05-27-mm-redesign]]
- **가동률 분모에서 연차·공휴일 차감** → 휴가자가 "일 안 한 사람"으로 과소평가되지 않는 공정한 분모. MM(절대량)과 분리된 상대 지표.
- **진척 3층 분리**: 공수 ≠ 완성 ≠ 일정. "공수 80% 썼으니 80% 끝났다"는 함정 차단. 핵심 신호 = 완성률−일정률. → [[2026-05-29-progress-page]]
- 타임시트 앱은 시간 "수집"까지만 하고 해석은 엑셀로 넘김 — Moves Workforce는 **해석까지 제품 안에** 있음.
- MD/MM·공휴일 관리는 **한국 SI/PMO 관행 정합** — 해외 앱이 흉내 내기 어려운 국내 시장 적합성.

### 3.3 엔드투엔드 커버리지
- 실무자(워크로그 기록) → PM(프로젝트 분석·간트·진척) → 경영진(전사 T/S/R 신호등·비용 비교)을 **한 앱**으로.
- 경쟁 구도상 "앱 3개 살 것을 1개로" + **데이터 원천이 하나라 지표끼리 어긋나지 않음**(계산식 SSOT).

### 3.4 비용(인건비) 분석
- 멤버별 역할/등급/급여 → 프로젝트 인건비 → 전사 비용 비교·급여 히스토그램까지 연결. Tempo는 Cost Tracker 별도 유료 앱.
- 급여는 민감 데이터라 단독으로는 도입 장벽이 될 수 있음 → **`PROJECT_COST` 권한 키 분리·deny-by-default와 한 세트**로 "안전하게 격리된 비용 분석"으로 제시해야 강점이 됨.

### 3.5 간트
- vs Jira 기본: 임의 깊이 WBS·선후행·폴더 — 명백히 깊음.
- vs BigPicture/Structure.Gantt: 뎁스 싸움은 불리. 차별점은 ① **선후행=네이티브 이슈 링크, 계층=커스텀 필드** — 앱을 제거해도 Jira 데이터 온전(락인 없음), ② **같은 앱의 공수·진척 데이터와 연결**. → [[2026-07-02-issue-link-gantt]]
- 권장 프레이밍: "더 깊은 간트" ❌ → **"공수·진척이 붙은, 데이터 락인 없는 간트"** ⭕

## 4. 메시지 제언

- **순서**: 보안(3.1) → 지표 정합성(3.2) → 엔드투엔드(3.3)를 주장으로, 비용(3.4)·간트(3.5)는 그 안의 기능 증거로 배치.
- **청중별**: 경영진/구매 → 3.1+3.4(안전한 비용 가시성) / PMO·PM → 3.2+3.3 / 기술 검토자 → 3.1(Forge 아키텍처·서버 가드).
- PPT 반영 시 [[2026-07-06-ppt-genspark-sourcepack]]의 슬라이드 2(문제)·15(운영·보안)에 본 보고서 3.1·3.2 논지 보강.

## 5. 복붙용 Genspark 보강 프롬프트 (기존 16장 덱에 경쟁 우위 반영)

> 사용법: 기존 [[2026-07-06-ppt-genspark-sourcepack]] §③ 기본형으로 생성한 덱에 아래 프롬프트를 그대로 투입. 처음부터 재생성할 경우엔 기본형 프롬프트의 슬라이드 3과 4 사이에 아래 "새 슬라이드"를 끼워 17장으로 요청.

```
기존 "Moves Workforce 제품 소개" 슬라이드를 아래 [경쟁 우위 자료] 기준으로 보강해줘. 전체 구조와 디자인 톤은 유지하고, 지정한 슬라이드만 수정·추가한다.

[절대 규칙]
- [경쟁 우위 자료]에 없는 경쟁사 기능·수치를 지어내지 마라.
- 특정 경쟁사 이름을 슬라이드에 쓰지 마라 — "일반적인 타임시트 앱 / 간트 전문 앱 / 외부 서버형(Connect) 앱"처럼 유형으로만 표현. 비방 톤 금지, 사실 대비만.

수정 사항:

1. [새 슬라이드 추가] 슬라이드 3(솔루션 개요) 바로 뒤에 "왜 Moves Workforce인가 — 3가지 차별점" 추가:
   - 핵심 메시지: "민감 데이터는 Jira 밖으로 나가지 않고, 지표는 제대로 계산되며, 기록부터 경영 판단까지 한 앱에서 끝난다"
   - 3열 카드: ① 보안 — Forge 네이티브, 데이터가 Atlassian 보안 경계 안에만 존재(외부 서버 없음) ② 제대로 된 지표 — 실근무일 기반 MM, 연차를 분모에서 빼는 가동률, 진척 3층 분리 ③ 올인원 — 실무자 기록→PM 분석→경영진 대시보드, 앱 여러 개+엑셀 조합 불필요·지표 원천 단일화

2. [슬라이드 2 보강] 문제 슬라이드에 불릿 1개 추가: "타임시트 앱은 시간을 '수집'까지만 — 해석(MM·가동률·진척)은 결국 엑셀. 간트·비용은 또 다른 앱 → 앱 2~3개 + 엑셀 조합, 지표는 서로 어긋남"

3. [슬라이드 10 교체] 간트 슬라이드의 핵심 메시지를 "더 깊은 간트"가 아니라 "공수·진척과 연결된, 데이터 락인 없는 간트"로 교체:
   - 선후행은 Jira 네이티브 이슈 링크, 계층은 커스텀 필드로 저장 → 앱을 제거해도 Jira 데이터는 온전 (앱 전용 데이터에 갇히지 않음)
   - 같은 앱의 공수·진척 데이터와 연결된 일정 관리 (Jira 기본 타임라인 대비: 임의 깊이 WBS·폴더·선후행)

4. [슬라이드 15 승격] 운영·보안 슬라이드의 핵심 메시지를 "데이터가 Atlassian 보안 경계를 벗어나지 않는다"로 승격:
   - 상단에 데이터 위치 비교 도식: 외부 서버형(Connect) 앱 = 데이터가 벤더 서버로 나감 vs Moves Workforce(Forge) = Jira 인프라 안에만 존재
   - 기존 불릿 유지: 서버가 모든 요청 검증(deny-by-default, resolver 109개 전수), 소속 프로젝트만 보기 스코프(외주 차등 운영)
   - 불릿 추가: "급여·비용 데이터는 별도 권한 키(PROJECT_COST)로 격리 — 볼 사람만 본다"

5. [슬라이드 14 보강] 통합 대시보드 슬라이드에 문구 추가: 비용 비교는 "권한으로 격리된 인건비 가시성" — 경영진에겐 보이고, 권한 없는 사용자에겐 숨겨진다

6. [슬라이드 16 정합] 마무리의 핵심 가치 3줄을 새 차별점 슬라이드의 3개 카드(보안/지표/올인원)와 동일한 순서·표현으로 맞춰라
```
