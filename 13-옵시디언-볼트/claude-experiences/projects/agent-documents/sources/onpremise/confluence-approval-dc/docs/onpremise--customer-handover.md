# DMOVE Approvals for Confluence Data Center

## 고객 전달 안내서

이 문서는 DMOVE Approvals 앱을 도입하는 고객의 Confluence 관리자, 결재 운영 담당자,
일반 사용자가 처음 확인할 안내서입니다. 설치·초기 설정·사용 방법은 아래 역할별 문서를
함께 제공하십시오.

| 대상 | 먼저 읽을 문서 | 용도 |
|---|---|---|
| Confluence 관리자·운영 담당자 | `guide-admin.md` | 설치, 권한, 정책, Flow·그룹, 운영 및 문제 해결 |
| 결재 요청자·결재자 | `guide-user.md` | 승인 요청, 승인·반려, 업무함, 알림, 서명 및 위임 |
| 설치를 수행하는 기술 담당자 | 이 문서의 설치 전 확인 및 설치 후 확인 | 배포 전제와 인수 확인 |

## 1. 제공 범위

DMOVE Approvals는 Confluence 페이지 전체 또는 페이지 안의 특정 콘텐츠 영역에 순차 결재를
적용합니다. 요청자는 결재선을 정해 요청하고, 결재자는 자기 차례에 승인 또는 반려합니다.
처리 결과와 감사 이력은 Confluence 안에 남습니다.

현재 고객 제공 대상은 다음과 같습니다.

| 항목 | 지원 범위 |
|---|---|
| Confluence | Data Center 9.2.x |
| Java runtime | 고객 Confluence 9.2.x 환경에서 지원하는 Java 17 또는 Java 21 |
| 설치 파일 | 공급사가 제공한 `approval-confluence9-<version>.jar` |
| Confluence 10.x | 현재 제공하지 않음 |

> Confluence 10.x로 업그레이드할 계획이 있으면 설치 또는 업그레이드 전에 DMOVE에 문의하십시오.
> 9.2.x용 설치 파일은 10.x에서 사용할 수 없습니다.

Java runtime은 고객이 사용하는 Confluence 9.2.x patch 버전의 Atlassian 지원 기준을 먼저
확인한 뒤 결정하십시오. 이 앱은 Java 17과 Java 21 runtime을 지원하지만, Confluence 자체가
지원하지 않는 runtime 조합은 사용하면 안 됩니다.

## 2. 설치 전 확인

설치를 시작하기 전에 다음을 확인하십시오.

- 대상 Confluence가 **Data Center 9.2.x**인지 확인합니다.
- 설치 작업을 수행할 계정이 Confluence 관리자 권한을 가졌는지 확인합니다.
- 공급사가 제공한 release 승인 완료 JAR인지 확인합니다. 로컬 개발 build 산출물은 설치하지 마십시오.
- 운영 환경에 먼저 설치하지 말고, 고객의 스테이징 환경에서 권한·메일·다중 node 동작을 확인합니다.
- 기존 승인 데이터가 있다면 DB 백업과 현재 앱 목록을 확보한 뒤 변경 작업을 진행합니다.
  기존 앱에서의 데이터 이전 또는 이전 버전으로의 복구는, 호환성·백업/복구 가능 여부·rollback
  기준을 공급사가 서면으로 확인한 절차가 있을 때만 진행합니다.
- Data Center 변경 절차(작업 창, node별 적용 방식, 재기동 여부, 롤백 담당자)를 고객 운영 표준에
  따라 사전에 확정합니다. 모든 node에서 앱이 활성 상태인지 인수 단계에서 확인합니다.

## 3. 설치와 첫 화면 확인

1. Confluence에 관리자 계정으로 로그인합니다.
2. **일반 설정 → 앱 관리(Universal Plugin Manager)** 에서 제공받은 JAR을 업로드합니다.
3. 앱이 활성화됐는지 확인합니다.
4. 적용한 스페이스의 일반 페이지를 열어 제목 위에 **승인** 상태 표시가 보이는지 확인합니다.
5. 페이지 편집 권한이 있는 계정으로 페이지 상단의 **승인 요청** 버튼이 보이는지 확인합니다.

설치 뒤 데이터 저장소와 cluster 작업은 앱이 자동으로 준비합니다. DB table이나 scheduler를
수동으로 만들 필요는 없습니다.

## 4. 운영 시작 전 결정할 항목

관리자는 **승인 설정** 화면에서 아래 항목을 고객 정책에 맞춰 정합니다. 설정 화면 접근은
Confluence 관리자 또는 설정 관리자에게만 허용됩니다.

| 항목 | 고객이 결정할 내용 |
|---|---|
| 적용 스페이스 | 전체 스페이스에서 사용할지, 지정한 스페이스에서만 사용할지 |
| 승인 Flow와 그룹 | 반복 결재선, 그룹 승인 규칙(1명 또는 전원), 담당자 |
| 기본 마감일 | 마감일을 둘지와 기본 일수 |
| 알림 | Confluence 알림, 이메일 알림, 마감 임박·독촉 알림 사용 여부 |
| 전자서명·PIN | 전자서명 표시와 PIN 검증을 의무화할지 |
| 결재 위임 | 부재 시 대리 결재를 허용할지 |
| 일괄 승인 | 여러 요청을 한 번에 처리하도록 허용할지 |
| 상태 표시명 | 조직에서 사용할 상태 명칭 |
| 설정 관리자 | Confluence 관리자 외에 승인 설정을 관리할 사용자 |

처음 설치했을 때 적용 스페이스를 지정하지 않으면 모든 스페이스에 승인 기능이 보입니다.
운영 시작 전에는 반드시 **전체 사용** 또는 **지정 스페이스 사용** 중 하나를 명시적으로 선택하고,
선택한 범위에서만 상태 표시와 요청 버튼이 보이는지 확인하십시오.

## 5. 필수 인수 확인

아래 시나리오는 고객의 실제 계정과 권한으로 확인하십시오.

- 페이지 편집자가 승인 요청을 만들 수 있다.
- 2명 이상 결재선에서 앞 단계가 끝난 뒤 다음 단계만 처리할 수 있다.
- 반려 시 요청이 종료되고, **진행 중인 요청만** 요청자가 회수할 수 있다.
- 진행 중인 페이지를 편집하면 해당 요청이 만료되며, 완료된 승인 이력은 유지된다.
- 승인 업무함에서 내 차례와 내 요청을 확인할 수 있다.
- 적용 스페이스 밖에서는 승인 UI가 노출되지 않는다.
- 권한 없는 사용자가 승인 설정에 직접 접근하면 거부된다.
- 이메일 알림을 사용할 경우 실제 고객 메일 서버에서 수신을 확인한다.
- 위임·전자서명·PIN·일괄 승인을 켠 경우에는 각 기능을 별도로 확인한다.

## 6. 사용 중 알아둘 점

- 한 대상에는 진행 중인 승인 요청을 하나만 둘 수 있습니다. 대상은 페이지 전체 결재의 경우 해당
  페이지이고, 콘텐츠 영역 결재의 경우 해당 `approval-region` 영역입니다.
- 순차 결재이므로 앞 단계가 끝나기 전에는 다음 단계 결재자가 결정할 수 없습니다.
- 진행 중인 요청은 요청자가 회수할 수 있고, 결재자가 반려하면 즉시 종료됩니다. 회수와 반려가
  완료된 요청은 되돌릴 수 없습니다.
- 진행 중인 페이지 결재는 페이지 내용이 변경되면 만료됩니다. 완료된 승인은 지워지지 않지만,
  새 페이지 버전은 재승인을 받아야 합니다.
- 결재 위임을 사용하면 결정은 원 결재자 이름으로 기록되고, 실제 처리한 대리인은 감사 이력에 남습니다.

## 7. 지원 요청 시 전달할 정보

문제가 발생하면 아래 정보를 함께 전달해 주십시오.

1. Confluence 버전과 Java runtime 버전
2. 앱 버전 및 설치 파일 이름
3. 발생 시각, 대상 페이지 주소, 영향을 받은 사용자
4. 재현 절차와 화면 메시지 또는 화면 캡처
5. Confluence application log에서 `kr.dmove.confluence.approval`로 검색한 관련 로그

상세 설정과 문제 해결 표는 `guide-admin.md`를, 일반 사용 방법은 `guide-user.md`를 참고하십시오.

## 8. Data Center 동시 처리 안내

승인 요청의 승인·반려·회수·만료 처리는 모든 node에서 공유하는 cluster lock으로 보호됩니다.
같은 요청을 여러 사용자가 동시에 처리하면 한 요청만 먼저 처리되며, 다른 요청은 잠시 후 다시 시도해야 할 수 있습니다.

- 잠시 후 재시도 안내가 표시되면 화면을 새로고침한 뒤 요청의 최신 상태를 확인합니다.
- cluster lock 서비스를 사용할 수 없는 비정상 상태에서는 승인 상태를 변경하지 않습니다. 이 경우 데이터가 불완전하게 저장되지는 않습니다. Confluence 재기동을 먼저 수행할 필요는 없으며, 관리자 또는 지원 담당자가 앱 상태를 확인한 뒤 필요하면 앱을 다시 활성화합니다.
- 재시도해도 계속 실패하면 발생 시각, 요청 URL, 화면 메시지와 `kr.dmove.confluence.approval` 로그를 함께 지원 담당자에게 전달합니다.

운영 인수 전에는 서로 다른 두 node에서 같은 승인 요청을 동시에 승인 또는 반려해 하나만 처리되고 나머지는 최신 상태를 표시하는지 확인하십시오.
