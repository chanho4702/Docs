# 데이터·보안·개인정보

> 대상: 사이트 관리자, 보안·개인정보 검토 담당자

## 요약

- Moves Approval은 **Atlassian Forge** 앱으로, Atlassian 인프라 안에서만 실행됩니다.
- 앱 데이터는 Atlassian이 호스팅하는 **Forge 저장소**(Forge SQL·Forge Key-Value Store)에만 저장됩니다. 결재 데이터는 외부 서버로 보내지 않습니다. 예외는 **오류 진단** 하나로, 화면에서 처리되지 않은 오류가 나면 오류 종류·스택·브라우저 정보만 Sentry(미국)로 보냅니다([오류 진단 정보](#오류-진단-정보)).
- 사용자를 대신해 Confluence에 접근할 때는 **그 사용자의 권한으로** 호출합니다. 사용자는 자신이 볼 수 없는 페이지의 정보를 앱을 통해 볼 수 없습니다.
- 앱은 **페이지 본문을 저장하지 않습니다.** 승인 판단에 필요한 버전 번호와 영역 내용의 해시값만 저장합니다. 결재 증명서의 문서 지문도 그때그때 계산할 뿐 본문을 남기지 않습니다.
- 앱이 페이지 본문을 **고치는** 경우는 요청자가 선택한 **결재란 자동 추가** 하나뿐이며, 요청자의 권한으로만 고칩니다.

## 저장하는 데이터

| 데이터 | 내용 | 목적 |
| --- | --- | --- |
| 승인 요청 | 페이지 ID·제목·버전, 스페이스 키, 영역 식별자와 내용 해시, 상태, 마감일, 요청 메모(최대 500자), 요청자 계정 ID | 승인 진행과 이력 |
| 결재선과 결정 | 단계, 승인자 계정 ID, 결정(승인·반려), 결정 시각, 반려·회수 사유, 대리 결재자 | 결정 기록 |
| 감사 이벤트 | 요청·승인·반려·회수·만료가 일어난 순서와 사유 | 감사 타임라인 |
| 업무함 색인 | 계정 ID별 역할(승인자·요청자·참조자)과 차례 여부 | 승인 업무함 목록 |
| 앱 내 알림 | 수신자 계정 ID, 알림 종류와 변수(문서 제목 등), 읽음 여부 | 알림함 |
| 서명 | 사용자가 그리거나 올린 서명 이미지(480×160 이하로 축소) | 결정 옆 도장, 결재란 |
| 서명 PIN | PIN의 **솔트 처리된 PBKDF2 해시**와 실패 횟수. PIN 원문은 저장하지 않습니다. | 결정 확인 |
| 결재 위임 | 위임자·대리인 계정 ID, 기간, 메모 | 대리 결재 |
| 설정 | 정책, 적용 스페이스, 결재선, 승인 그룹, 승인자 명부, 설정 관리자 | 앱 동작 |
| 결재 기록 보관 설정 | 보관 기간, 마지막 내보내기의 날짜·건수·실행한 관리자 계정 ID | 보관 기간 관리 |
| 설정 변경 이력 | 변경한 사용자 계정 ID, 시각, 영역, 내용 | 감사 |

사용자는 Atlassian **계정 ID**로만 저장됩니다. 이름·이메일·프로필 사진은 저장하지 않고, 화면을 표시할 때마다 Confluence에서 그 시점의 정보를 읽어 옵니다.

결재 증명서 PDF는 요청할 때마다 브라우저에서 만들어 내려받으며, 앱이 사본을 보관하지 않습니다.

## 보관 기간

| 데이터 | 보관 |
| --- | --- |
| 끝난 결재 기록(승인·반려·만료·회수된 요청과 그 결재선·감사 이벤트) | 관리자가 정한 보관 기간(무기한·1·3·5·10년, **기본 3년**) 동안 보관합니다. 기간이 지나도 자동으로 지우지 않으며, 관리자가 **엑셀로 내보낸 뒤** 직접 삭제할 때만 지워집니다. |
| 진행 중인 요청 | 보관 기간 대상이 아닙니다. |
| 앱 내 알림 | 180일 후 자동 삭제 |
| 설정 변경 이력 | 1년 후 자동 삭제 |
| 서명·PIN·위임 | 사용자가 삭제하거나 바꿀 때까지. Atlassian 계정이 폐쇄되면 자동 삭제 |

- 보관 기간은 설정 → **데이터 관리** → **결재 기록 보관**에서 정합니다. 앱 관리자(Confluence 관리자·설정 관리자)만 이 화면을 쓸 수 있습니다.
- 삭제는 **마지막으로 내보낸 범위**만 할 수 있고, 한 번 더 확인한 뒤 실행됩니다. 요청을 삭제하면 그 요청의 결재선·감사 이력·업무함 항목·관련 알림이 함께 지워집니다. **삭제는 되돌릴 수 없습니다.**
- 관리자가 볼 수 없는 페이지의 기록은 내보내기·삭제에서 빠집니다. 다만 Confluence 에서 **완전히 삭제된 페이지**(휴지통 비움·스페이스 삭제)의 기록은 포함하되, 페이지 제목·요청 메모·반려/회수 사유를 비우고 내보냅니다. Confluence 는 삭제된 페이지와 앱까지 막는 제한이 걸린 페이지를 구분해 주지 않으므로, 그런 제한 페이지의 기록도 같은 방식으로 처리됩니다.
- 보관 기간 변경·내보내기·삭제는 설정 변경 이력에 남습니다(영역 "보관 기간", 동작 "내보내기"·"정리").
- 사용자는 결재 기록을 수정할 수 없습니다. 결재 기록은 위의 보관 기간·정리 정책에 따라서만 지워집니다.

앱을 제거한 뒤의 데이터 처리는 Atlassian Forge 플랫폼의 데이터 보관 정책을 따릅니다.

### 내보낸 파일

**엑셀로 내보내기**로 받은 .xlsx 파일(시트: 결재 요청 / 결재선 / 이력)에는 문서 제목, 요청 메모, 반려·회수 사유, 그리고 내보낸 시점에 Confluence에서 읽은 **사용자 이름**이 들어 있습니다. 파일은 관리자의 컴퓨터로 내려받아지며 그 뒤의 보관·접근 통제·폐기는 **고객의 책임**입니다. 조직의 기록 보존 정책에 맞는 곳에 보관하세요.

### 저장 공간 한도

앱 데이터는 Forge SQL의 설치당 저장 한도(1 GiB 기준) 안에 저장됩니다. 한도를 넘으면 새 결재를 저장할 수 없습니다. 설정 → **데이터 관리** → **저장 공간**에서 사용량을 확인할 수 있으며, 80% 이상이면 **주의**, 90% 이상이면 **위험**으로 표시됩니다. 테이블별 크기·행 수는 데이터베이스 통계 기반 추정치입니다.

## Confluence에 쓰는 데이터

앱이 Confluence에 쓰는 것은 아래 두 가지뿐입니다.

| 무엇 | 언제 | 누구의 권한으로 |
| --- | --- | --- |
| **결재란 매크로**를 페이지 맨 위에 추가 | 페이지 결재를 요청할 때 요청자가 **문서 맨 위에 결재란 추가**를 선택한 경우(기본값은 정책 **승인 요청 시 문서 맨 위에 결재란 자동 추가**, 기본 켬) | **요청자** — 앱 권한으로 쓰지 않습니다 |
| 관련자를 @멘션하는 **댓글** | **Confluence 알림으로도 보내기**가 켜진 경우(기본 켬) | 해당 작업을 실행한 사용자(`asUser`) |

- **결재란 자동 추가**는 앱이 페이지 본문을 고치는 유일한 경우입니다. 요청자 권한으로 고치므로 페이지 버전이 하나 오르고 페이지 이력에 요청자가 "Moves Approval" 메시지로 남습니다. 문서에 결재란이 이미 있으면 넣지 않고, 요청자에게 편집 권한이 없거나 그 사이 다른 저장이 있으면 넣지 않은 채 요청만 진행합니다. 결재란은 결재 상태를 표시하는 매크로일 뿐 결재 데이터를 본문에 적지 않습니다.
- 댓글은 Confluence 콘텐츠이므로 페이지를 볼 수 있는 사람 모두에게 보이고, 앱을 제거해도 남습니다. 결재란 매크로도 페이지 본문에 남지만, 앱을 제거하면 더 이상 동작하지 않습니다.

## 결재 증명서

- 결재 증명서 PDF는 **끝난 결재**에 대해서만, 그 페이지를 **볼 수 있는 사용자**에게만 발급됩니다. 요청이 그 페이지의 것인지 서버에서 다시 확인합니다.
- 문서 지문을 계산하려고 결재 대상 버전의 본문을 **증명서를 여는 사용자의 권한으로** 읽고, SHA-256 값만 계산해 돌려줍니다. 본문은 저장하지 않습니다. 그 버전을 읽을 수 없으면 지문을 생략합니다.
- 증명서에는 요청자·결재자·처리자 이름, 요청 메모, 반려·회수 사유가 들어갑니다. 내려받은 PDF의 보관과 공유는 고객의 책임입니다.

## 오류 진단 정보

앱 화면에서 처리되지 않은 오류가 나면 원인을 찾기 위해 오류 정보를 **Sentry**(Functional Software, Inc., 미국 리전)로 보냅니다. 이 송신은 manifest에 Atlassian이 허용한 분석 도구(`analytics`)로 선언되어 있고, 고객 데이터가 아닌 것(`inScopeEUD: false`)으로 표시되어 있습니다.

| 보내는 것 | 보내지 않는 것 |
| --- | --- |
| 오류 종류·메시지·스택 추적, 앱 환경, 브라우저·OS 종류 | 계정 ID·이름·이메일, 페이지 주소·제목·본문, 결재 내용·사유·메모, 쿠키·요청 헤더, 콘솔 로그, 클릭·이동 기록 |

오류 메시지에는 앱이 만든 오류 코드가 들어가며 결재 내용이 들어가지 않도록 설계했습니다. 서버 오류의 원문(데이터베이스 메시지 등)은 화면으로 내려보내지 않으므로 Sentry로도 가지 않습니다.

## 요청하는 권한과 용도

| 권한 | 용도 |
| --- | --- |
| `read:page:confluence`, `read:content-details:confluence`, `read:confluence-content.summary` | 승인 대상 페이지의 제목·버전 확인, 페이지 수정 이벤트 수신, 영역 내용 해시와 결재 증명서의 문서 지문 계산 |
| `write:page:confluence` | 요청자가 선택한 경우 요청자 권한으로 페이지 맨 위에 결재란 매크로 추가 |
| `read:space:confluence` | 적용 스페이스 선택과 스페이스 이름 표시 |
| `read:content.permission:confluence` | 사용자와 승인자의 페이지 보기·편집 권한 확인 |
| `read:user:confluence` | 승인자·참조자 검색과 이름 표시 |
| `read:group:confluence` | 승인 그룹으로 쓸 Confluence 그룹과 구성원 조회 |
| `read:comment:confluence`, `write:comment:confluence` | 대상 페이지에 @멘션 알림 댓글 작성 |
| `storage:app` | 앱 데이터 저장(Forge 저장소) |
| `report:personal-data` | 저장한 계정 ID를 Atlassian 개인정보 보고 API로 보고하고, 폐쇄된 계정의 개인정보 삭제 |

## 접근 통제

- **모든 요청은 서버에서 권한을 다시 확인합니다.** 화면에 버튼이 보이는지와 관계없이, 앱의 모든 기능은 서버의 권한 표에 선언된 조건(본인 데이터, 페이지 보기·편집 권한, 관리자 권한)을 통과해야 실행됩니다. 선언되지 않은 기능은 실행되지 않습니다.
- **목록은 건별로 다시 걸러냅니다.** 승인 업무함은 결과를 돌려주기 전에 사용자가 실제로 볼 수 있는 페이지만 남깁니다.
- **페이지 권한을 우회하는 읽기는 사용자에게 돌려주지 않습니다.** 마감 만료·페이지 수정 감지처럼 사용자 없이 도는 작업만 앱 권한으로 페이지를 읽으며, 그 결과는 버전 비교와 해시 계산에만 씁니다. 보관 기간 정리는 관리자에게 보이지 않는 페이지가 Confluence 에 아직 있는지만 앱 권한으로 확인합니다.
- **앱 권한으로 페이지 본문을 고치지 않습니다.** 결재란 자동 추가는 요청자 권한으로만 실행됩니다.
- **동시 결정에 안전합니다.** 같은 순간 여러 결정이 들어와도 한 대상에는 진행 중 요청이 하나만 존재하며, 다른 사람의 결정을 덮어쓸 수 없습니다.
- **마감 이후 결정은 서버가 거절합니다.** 정기 정리가 돌기 전이라도 마감이 지난 요청에 대한 승인·반려는 기록되지 않습니다.
- **데이터 관리**(저장 공간·결재 기록 보관·삭제)는 앱 관리자만 쓸 수 있습니다.
- **서명 PIN**은 5회 실패 시 15분 동안 잠깁니다.
- **라이선스**가 비활성이면 서버가 모든 기능 호출을 거절하고, 모든 화면(설정 포함)과 문서 속 매크로에 구매 안내가 표시됩니다. 영역 승인 매크로 안의 본문과 페이지 제목 아래 결재 상태 표시는 그대로 보입니다. 진행 중인 요청의 마감 만료 처리는 데이터 정합을 위해 계속 돌지만 알림은 만들지 않습니다.

## 개인정보 주체 요청

사용자는 **내 서명**에서 서명과 PIN을, **내 위임**에서 위임을 직접 삭제할 수 있습니다. 승인 결정 기록은 조직의 감사 기록이므로 사용자가 수정하거나 삭제할 수 없으며, 보관 기간이 지난 기록을 관리자가 내보낸 뒤 삭제할 때만 지워집니다. 앱은 이름·이메일을 자체 보관하지 않으므로, Atlassian 계정이 삭제되면 화면에는 Confluence가 그 계정에 대해 돌려주는 정보가 그대로 표시됩니다. 다만 이미 내보낸 엑셀 파일이나 내려받은 증명서 PDF에 들어간 이름은 고객이 관리하는 사본이므로 앱이 바꿀 수 없습니다. 그 밖의 요청은 사이트 관리자를 통해 지원 채널로 문의해 주세요.

### 계정 폐쇄

앱은 저장한 계정 ID를 Atlassian **개인정보 보고 API**(Personal data reporting API)로 7일마다 보고합니다. 계정이 폐쇄된 것으로 확인되면 그 사용자의 **서명·PIN·위임·받은 알림**을 지우고 **승인자 명부·설정 관리자**에서 뺍니다. 결재·감사 기록 속 계정 ID는 조직의 감사 기록이므로 위의 보관 기간 정책을 따르며, 화면에는 Atlassian이 폐쇄 계정에 대해 돌려주는 정보가 표시됩니다.
