# 제품 시나리오 목록

가이드를 쓸 때 빠뜨리지 않도록 Moves Approval 이 **실제로 지원하는** 흐름을 모았습니다. 편집자용 문서이며 고객 본문에 넣지 않습니다.
기준: 소스 `develop` (2026-10-22). 상태 규칙은 `src/domain/approval`, 데모 데이터는 [demo-data.md](cloudjira--demo-data.md).

데모 열: ✔ 데모 데이터에 있음 · △ 일부만(직접 조작 필요) · ✖ 데모에 없음

## 상태와 전이 한눈에

| 상태 | 뜻 | 들어오는 길 | 나가는 길 |
| --- | --- | --- | --- |
| 대기(PENDING) | 결재 진행 중 | 요청 | 승인·반려·만료·회수·재상신(이전 요청 닫힘) |
| 승인(APPROVED) | 모든 단계 통과 | 마지막 단계 승인 | 없음(종료) — 다시 결재하려면 새 요청 |
| 반려(REJECTED) | 한 명이라도 반려 | 반려 | 없음(종료) — 새 요청으로 다시 시작 |
| 만료(EXPIRED) | 마감이 지남 | 하루 한 번 점검 · 결정 시점 즉시 판정 | 없음(종료) |
| 회수(CANCELLED) | 요청자·관리자가 거둬들임, 또는 시스템이 닫음 | 회수 · 영역 매크로 삭제(REGION_REMOVED) · 새 버전 재상신(SUPERSEDED) | 없음(종료) |

- 열린 요청은 **대상(페이지 또는 영역)마다 하나**뿐입니다. 진행 중에 또 요청할 수 없습니다.
- 문서를 고쳐도 요청은 닫히지 않습니다. "요청 이후 수정됨" 안내와 **새 버전으로 다시 상신**이 나타납니다.
