# 작성자·요청자 가이드

## 작업 기록과 승인 요청

1. 대상 이슈에서 **Log work**를 열고 작업 날짜·소요 시간·설명을 입력합니다.
2. 저장 결과를 확인합니다. 자동 요청 정책이면 저장 후 승인 요청을 접수합니다. 수동 정책이면 기록 상세에서 승인 요청을 진행합니다.
3. 승인자가 필요하면 서버가 제공하는 후보에서 선택합니다. 기본 팀장·활성 계정·이슈 열람 권한 등에 따라 후보가 달라집니다.
4. **Work log → 상세**에서 승인 상태와 잠금 이유를 확인합니다. 앱 업무함에서도 본인 요청과 이력을 확인할 수 있습니다.

| 표시 결과 | 다음 행동 |
| --- | --- |
| 저장됨·승인 대기 | 추가 저장 없이 결정 대기 |
| 승인자 선택 필요 | 원래 기록에서 후보 선택 |
| 저장됨·승인 요청 실패 | 원래 기록에서 요청만 재시도 |
| 반려됨 | 사유 확인 후 현재 정책이 허용하는 수정·재요청 |
| 마감됨·승인됨 | 잠금 이유 확인, 제공되는 경우 소명 요청 |

아직 아무도 결정하지 않은 대기 요청에서만 승인자 변경이 제공될 수 있습니다. 변경은 이전 결정을 덮어쓰지 않고 새 요청 회차로 남습니다. 후보가 없으면 팀과 이슈 권한을 관리자에게 확인하세요.

규칙 위반으로 표시된 미승인 기록도 소명 사유를 요구할 수 있습니다. 승인된 기록의 재검토와는 별개입니다. 연동 모드에서는 연결 이슈의 Workforce 팀장에게 자기 승인이 허용되며, 상위 팀장이 있으면 기본 후보는 상위 팀장입니다.

## 소명과 변경 이력

확정된 기록의 재검토가 필요하고 상세에 소명 동작이 제공되면 사유를 입력해 요청하세요. 소명 중에도 기존 잠금과 확정 시간이 유지됩니다. 소명은 자유 편집 허가가 아닙니다.

상세의 승인 이력과 변경 이력은 서로 다릅니다. 승인 이력은 누가 언제 결정했는지, 변경 이력은 앱이 관찰한 생성·수정·삭제를 보여 줍니다. 열람 권한이나 이력 수집 설정에 따라 보이는 범위가 달라집니다.

상태 변경 승인은 [현재 제공 상태](cloudjira--07-transition-approval.md)를 확인하세요.
