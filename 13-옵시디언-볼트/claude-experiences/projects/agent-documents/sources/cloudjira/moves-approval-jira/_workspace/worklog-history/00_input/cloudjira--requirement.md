# worklog-history — 워크로그 변경 이력 감사

> 로드맵 6번(2026-10-04 추가). 근거: 고객 미팅(스트라드비전) 5장 "이력 감사" — "언제, 누가, 무엇을, 몇 번 수정했는지".
> 워크포스는 Forge 저장소 한계로 이 기능을 권장하지 않았다 → **승인 앱 DB(별도 1 GiB)에 쌓는다. 워크포스 리포는 건드리지 않는다.**

## 목표

워크로그 생성·수정·삭제마다 **누가 / 언제 / 무엇이 어떻게(이전 값 → 이후 값)** 바뀌었는지 남기고, 워크로그별 수정 횟수를 보여 준다.
감사 대응용이므로 기록은 append-only 이고, 사용자가 고칠 수 없다.

## 수집 경로 (이미 있는 것을 재사용)

- 이벤트: `src/trigger/onWorklogChanged.js`(created/updated/deleted) — 지금은 `TimesheetDriftService` 만 부른다. 이력 기록을 같은 어댑터에서 함께 부른다(throw 금지 규칙 유지, 한쪽 실패가 다른 쪽을 막지 않게).
- 누락 보정: `runTimesheetSweep` 의 `worklog/updated`·`deleted` since 스윕. 보정으로 잡힌 변경은 **"보정 감지(중간 변경 누락 가능)"** 로 표시한다 — 이벤트 사이의 중간 수정은 복구 불가하다는 걸 숨기지 않는다.
- 우리 화면 쓰기(`src/resolver/worklog/WorklogGateway.js`, period-lock 의 대체 Log work): 실제 사용자와 이전 값을 확실히 안다 → 그 경로는 **출처 APP** 으로 정확히 기록. Jira 화면·REST·자동화 경로는 **출처 JIRA** 로, 행위자는 워크로그의 `updateAuthor`(삭제는 이벤트 페이로드의 사용자 — 미검증, 없으면 "알 수 없음").

## 이전 값

이벤트에는 변경 후 값만 온다. 이전 값은 **우리가 마지막으로 본 상태(미러)** 에서 가져온다.
- 워크로그 미러 테이블(워크로그 id·이슈·작성자·시작 시각·초·설명 지문·최종 관측 시각)이 필요하다. 타임시트 스냅샷과 중복되면 통합을 검토하라.
- 미러에 없던 워크로그(설치 전 생성)를 처음 보면 "기준선 관측" 기록을 남기고 이전 값은 비운다.

## 용량 (제약)

- 200명 기준(연 24만 워크로그, 수정 포함 이력 약 36만 행) **이력+미러 연 150MB 이하** 목표. 설계서에 행 크기 근거를 적는다.
- 설명(comment) 원문 보관 여부가 용량을 좌우한다. 기본 가정: 설명은 **지문 + 앞부분 일부**만 남기고 원문은 Jira 에 둔다 — 고객이 원문 보존을 요구하면 정책으로 켠다. (QUESTIONS 에 기록)
- 보관 기간 정책 `worklogHistoryRetentionMonths` 기본 **12개월**, 기존 보관/내보내기(엑셀 → 확정 후 삭제) 흐름 재사용.
- 수집 범위: 앱이 켜진 프로젝트(프로젝트 설정)만. 기본값은 설계에서 정하되 근거를 적는다.

## 화면

1. 워크로그 단위: 우리 작업 로그 탭(period-lock 의 `worklog-activity-tab`)에서 워크로그별 "이력 N회" → 펼치면 변경 목록
2. 타임시트 상세: 해당 기간의 변경 이력(특히 승인 후 변경)을 함께 표시
3. 관리자 감사 화면: 사용자·프로젝트·기간·변경 종류로 검색, 엑셀 내보내기(`utils/excel.js`)

## 권한

- 본인 워크로그 이력: 본인
- 팀원 이력: 그 팀의 팀장(타임시트 범위와 같은 공용 함수)
- 전체: 관리자
- 모든 경로에서 이슈 열람 권한으로 다시 좁힌다(불변식 7). 형제 resolver(목록·상세·내보내기·카운트) 모두 같은 범위.

## 완료 기준

- 백엔드·UI 테스트·빌드 통과(현재 866/203 기준선 유지 + 신규)
- 같은 이벤트가 두 번 와도 이력이 한 번만 쌓인다(결정적 id) — 테스트로 증명
- 이벤트 경로와 스윕 경로가 같은 변경을 두 번 기록하지 않는다 — 테스트로 증명
- append-only: 이력 수정·삭제 resolver 가 없다(보관 기간 정리 배치만 예외)

## 범위 밖

워크포스 리포 변경, 외부 저장소, 실시간 알림 채널(6-2), 배포.
