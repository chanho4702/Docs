# workforce-input-reopen — 요구서 (2026-10-14)

## 사용자 결정
- "워크로그 진입점이 하나였으면"(10-13)의 뜻은 **"Jira 패널에서만 하지 말자"** 였다. 승인 앱 하나로 창구를 묶은 linked-mode-ux ① 은 오해였다.
- **워크포스 앱 내부에서도 연동 이슈 워크로그 작성·수정·삭제를 다시 연다.** CLAUDE.md "워크로그 중심 개선 요구(10-13)" 의
  "정상 입력 창구는 Jira 이슈 패널 또는 Workforce 앱 내부" 를 그대로 구현한다.
- 워크포스의 Jira 이슈 패널은 제거한다(linked-mode-fix R4, 별도 진행 중). 따라서 창구는 ① 승인 앱 이슈 화면(Work log 탭·Log work 액션) ② 워크포스 앱 내부 화면 둘.

## 전제·배경
- linked-mode-ux ① 이 워크포스 입력을 넘김으로 막은 이유: 워크포스 입력 경로가 승인 앱의 검사(작성 기간·사전 승인·승인분/마감 잠금)를 **우회**했다(코덱스 검토 `_workspace/linked-mode-ux/codex-review.md`).
  다시 열 때 이 우회를 그대로 되살리면 안 된다.
- 승인 앱은 워크포스 서명 출처(`movesRms.origin`, cap `wlorigin`)를 이미 정상 입력으로 인정한다(`PROVEN_ORIGINS` 에 WORKFORCE). 워크포스 입력 화면 코드는 넘김 뒤에 남아 있다.
- 앱 간 직접 호출은 없다. 교환은 **Jira 엔티티 프로퍼티 + 서명**(CLAUDE.md 확정)뿐이다. 워크포스 DB 무증가.
- ctl 문서(`movesApproval.ctl`)의 `ch` 는 지금 항상 `'APP'`(linked-mode-ux ①). 워크포스 신판은 `ch` 를 보지 않고 무조건 넘긴다.

## 요구
### R1 워크포스 저장 전 판정 (우회 금지)
- 워크포스가 연동 이슈 워크로그를 작성·수정·삭제하기 **직전**에 승인 앱 규칙을 판정하고, 거부면 저장하지 않는다. 판정 불가(문서 없음·서명 실패·만료)도 **거부**(저장 실패 시 거부 원칙, linked-issue-schedule).
- 판정 항목: 작성 기간(rms.issue s/e — 워크포스 자기 문서), 사전 승인(pa=REQUIRED 이면 승인 앱의 사전 승인 상태), 승인분 잠금(승인·마감된 워크로그 수정·삭제 차단), 기간 마감(사용자×기간 `movesApproval` 문서 `cl`/`lk`), 사이트 기록 규칙 7키(create/edit/deleteWindowDays·하루/주 상한 등 — 승인 앱 사이트 관리자 설정).
- 설계가 정할 것: 이 판정에 필요한 승인 앱 상태를 워크포스가 **어느 서명 문서에서** 읽는지(기존 계약 재사용 우선: ctl·approval.worklog.v1·movesApproval 사용자×기간·rms.issue), 모자라면 승인 앱이 게시할 최소 추가 항목. 새 테이블 금지.
- 판정 로직은 두 앱이 **같은 결과**를 내야 한다 — 승인 앱의 순수 도메인 판정 함수를 워크포스로 복사(B안, 계약 테스트로 양쪽 대조)하거나 계약 문서에 판정 결과를 싣는 방식 중 설계가 고른다.

### R2 창구 전환
- ctl `ch` 를 `'ANY'`(또는 설계가 정하는 값)로 바꾸고, 워크포스는 `ch` 가 `'ANY'` 이고 R1 판정이 통과하면 자기 화면에서 저장한다. `'APP'` 이면 지금처럼 넘김(구판 호환).
- 워크포스 4화면의 넘김 버튼 → 입력 폼 복귀. 넘김 경로(`approvalHandoff`)는 거부 사유 안내에만 남긴다("승인 앱에서 사유 확인").
- 승인 앱 이슈 화면은 그대로. 두 창구 모두 저장 직후 자동 접수(autoRequest)·기본 승인자(팀장) 동일 — 승인 앱 워크로그 트리거가 출처 WORKFORCE 를 같은 흐름으로 태운다.

### R3 사후 검증 유지
- 승인 앱 트리거·스윕의 "다른 경로 입력 감지·재승인·통제"는 그대로. 워크포스가 R1 을 통과해 쓴 워크로그는 출처 서명으로 정상 입력이 된다.

## 완료 기준
- 워크포스 내부 화면에서 연동 이슈 워크로그 작성 → 승인 앱에 '승인 요청 전/요청됨' 으로 표시되고 승인 흐름이 돈다(개발 사이트 실측, Tom Kim).
- 승인 앱이 거부해야 할 조건(작성 기간 밖·승인분·마감)에서 워크포스 저장이 거부된다(테스트 + 실측 1건).
- 두 리포 테스트·빌드 녹색. 새 SQL 없음. 워크포스 locales·미추적 파일 불변.
