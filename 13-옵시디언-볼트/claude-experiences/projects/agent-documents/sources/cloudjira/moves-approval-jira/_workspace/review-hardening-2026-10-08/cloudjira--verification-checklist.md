# 후속 개선 검증 기준

## 보관

- 클라이언트 count/cutoff 위조, 페이지 건너뛰기, 미완료 confirm, 다른 사용자 세션, 만료 세션은 삭제를 허용하지 않는다.
- 같은 cutoff에 나중에 들어온 ID와 이미 내보낸 뒤 부속자료가 바뀐 ID는 삭제하지 않는다.
- TIMESHEET는 참여자 조회라는 목록 전제를 내보내기에 재사용하지 않는다. 현재 TimesheetAccess를 검사한다.
- worklog history 형제 내보내기도 서버 ID 집합을 고정한다. 이력의 Q73 마스킹 정책은 유지한다.
- 승인자의 원문 접근과 제한 공개 워크로그 설명의 작성자 제한을 분리한다.
- 부분 삭제 실패 후 재호출은 부모·자식 일관성과 허가 처리 상태를 확인한다.
- 과거 cutoff-only 완료 기록은 새 삭제 허가로 인정하지 않는다.
- 새로 추가한 상세 metadata는 실제 Excel 파일에 보존된다.

## PIN

- 동일 초기 record를 읽은 병렬 실패 5회가 5회로 누적된다.
- 동시 실패가 잠금을 만든 후 오래된 성공 결과가 잠금을 지우지 않는다.
- PIN을 바꾼 뒤 이전 세대의 성공/실패/삭제가 새 PIN을 변경하지 않는다.
- 최초 등록 경합은 하나만 성공하며 기존 PIN을 upsert로 덮지 않는다.
- CAS 실패 재시도는 상한이 있고 SET에는 rev 증가가 있다.

## 외부 쓰기·스윕

- 필드 PUT 전송 직전 불명확 상태를 영속 기록한다. timeout/5xx/프로세스 종료 뒤 재PUT하지 않는다.
- 현재 값이 다시 from이 되어도 불명확 시도를 확정 실패로 해석하지 않는다.
- 적용 대기·적용 중·결과 불명확인 승인은 보관 삭제에서 제외한다.
- 실패 25회 이후에도 worklog cursor/watermark를 건너뛰지 않는다.
- 알림 첫 100개가 발송 완료/정책 비활성이어도 뒤 후보를 스캔한다.
- 예산 소진 시 원본 마지막 후보 cursor를 저장하고 실패한 페이지는 다시 처리한다.
- 가시성 판정 실패 시 집계도 fail-close, 불완전 집계는 정확한 0으로 표시하지 않는다.

## 실행·커밋

- 모든 코드 작성 에이전트 완료 후 backend → UI tests → UI build → Forge lint.
- UI 실제 응답 shape, enum 및 kr/en 번역 대조.
- 마이그레이션 이름/순서, 신규 테이블·컬럼 readiness, resolver 등록 계약 확인.
- 검증된 변경을 경로별 staging. 빌드 산출물·생성 번역은 제외하고 한국어 이유 중심 커밋.
# 재개 후 확인 (2026-10-10)

- 2026-10-08 백엔드 결과: 107 suites / 1,463 tests PASS. 재개 후 변경에 대한 최종 재실행은 별도로 필요하다.
- 승인 내보내기: 현재 열람 가능한 행만 서버 허가 집합에 포함한다. 워크로그 이력은 기존 Q73에 따라 가린 행도 포함한다. 두 정책을 혼동하지 않는다.
- 삭제 허가: `session.cutoff`와 현재 정책의 교집합, 서버 ID 집합, 현재 자료 지문을 사용한다. 조회 후 자식 변경까지 원자적으로 봉쇄했다고 주장하지 않는다.
- 작업 단위 커밋: 스키마 준비, PIN, 필드 UNKNOWN, 내보내기·보관, 배치·집계. 모든 구현 에이전트가 완료한 뒤 경로를 지정해 스테이징한다.
- 최종 검증 순서: 백엔드 → UI → UI build → Forge lint. 빌드·생성 번역은 커밋하지 않는다.
