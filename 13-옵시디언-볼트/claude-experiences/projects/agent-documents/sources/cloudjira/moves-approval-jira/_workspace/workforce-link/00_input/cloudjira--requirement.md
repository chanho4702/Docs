## 목표

워크포스(`C:\CloudJira\moves-workforce`)와 같은 사이트에 설치되면 두 앱이 **Jira 엔티티 프로퍼티 + Ed25519 서명**으로만 대화한다.
이 리포에서 할 일은 **승인 앱 쪽 절반**이다: (A) 승인 상태를 서명해 게시, (B) 워크포스 게시물을 서명 검증 후 라우팅·제한선에 사용, (C) 둘 다 없거나 검증 실패면 조용히 단독 경로.
워크포스 리포 쪽 변경(공개키 내장·검증·표시)은 **이 회차에서 하지 않는다** — 설계서에 "워크포스 측 작업 명세"로 적고 QUESTIONS 에 승인 요청만 남긴다.

## 해야 할 것

1. **서명 계약 (순수)** — `src/integration/workforce/` 에 정규화(canonical JSON) → 서명 대상 바이트 → 서명/검증. 서명 대상에 `cloudId` + 엔티티 종류·id(+ 사용자×기간이면 accountId·periodKey)와 계약 버전 `v` 를 넣어 다른 사이트·다른 엔티티로의 복사 재사용을 막는다(DESIGN §4.1). 알고리즘 Ed25519(`node:crypto`), 개인키는 `forge variables set --encrypt`(환경 변수), 상대 앱 공개키는 빌드 내장. 키 회전(`kid`)·재생 방지(`rev`/발행 시각) 범위는 설계에서. **Forge 런타임 Ed25519 지원은 미검증** — 대체안(예: HMAC 불가 사유, 실패 시 동작)을 설계에 적는다.
2. **승인 → 워크포스 게시 (asApp)** — DESIGN §4.3 기본: 사용자 프로퍼티 `movesApproval.{yyyy}` 에 `{periodKey: {status, worklogSetHash, decidedAt, sig, ...}}`. 상태 원천은 우리 DB(타임시트 요청 상태 + `timesheet_submission` 스냅샷 + CHANGED_AFTER_APPROVAL 부속 행 + period-lock 마감). 상태 값 집합(미제출·제출·승인·반려·승인 후 변경, 마감 여부)과 `worklogSetHash` 정의(워크포스가 같은 기간 워크로그로 **재계산 가능**해야 함 — 기존 `ts1z` 지문과의 관계 확정)는 설계에서.
   - 게시 시점: 결정·제출·회수·만료·변경 감지·마감/재개방. 핫패스는 throw 금지 → 실패는 아웃박스/리컨실 스윕이 멱등 재게시(AGENTS.md 트리거 규칙, watermark·커서·예산).
   - 32KB 한도(DESIGN §4.4) — 연 단위 키 분할, 크기 초과 시 동작.
   - 사용자 프로퍼티 쓰기 불가(미검증) 시 후퇴안: 워크로그 단위 프로퍼티 + 큐 (설계에 적고 구현은 플래그로 선택 가능하게 할지 결정).
   - 이슈 프로퍼티 `movesApproval`(전환 승인 요약)은 `transition-approval` 범위 — 이번엔 계약 자리만.
3. **워크포스 → 승인 검증·사용** — `movesRms.org`(사용자: `{teamKey, leaderKeys, rev, sig}`), `movesRms.check`(워크로그: 제한선 위반 코드), `movesRms.pm`(프로젝트: PM). 서명 검증 통과분만 사용, 실패·부재 = 없음(단독 경로) + 감사 기록. 판정 결과(팀장 해석·예외 승인 단계)는 우리 DB 에 남긴다.
   - 결재선: 연동 시 팀장 원천을 워크포스 `movesRms.org` 로(단독 모드는 `timesheet_team_member` 유지). `TeamScope`·`TimesheetAccess` 두 곳에서만 범위 판정한다는 규칙 유지 — 원천 전환을 이 두 곳에 꽂는 방식을 설계.
   - 제한선: 워크포스 위반 코드(`OVER_PLAN`·`OUT_OF_PERIOD`·`NOT_MEMBER` 등)를 받아 DESIGN §5 "예외 승인 단계(PM)"를 결재선에 끼운다(`normalizeSteps` 단계 추가, 상태 머신 무변경). 승인 앱이 워크포스 데이터를 재계산하지 않는다.
   - 모드 판정은 설치 감지가 아니라 "서명이 맞는 게시물이 있는가"(DESIGN §3) — 기능 단위로 부분 폴백.
4. **관리 화면** — adminPage 에 연동 상태(공개키 지문·마지막 게시/검증 결과·실패 건수·재게시 버튼), 연동 on/off 정책. 사람이 읽는 문구는 프론트 i18n.
5. **i18n** — kr/en 동시, `npm run merge`. 서버는 문구를 만들지 않는다.
6. **워크포스 측 작업 명세(문서만)** — 워크포스가 해야 할 것: 공개키 내장, `expand=properties` 로 사용자/워크로그 프로퍼티 읽기, hash 재계산·일치 판정, 상태 배지·원가 "승인분만", `movesRms.*` 서명 게시. 워크포스 DB 무증가 준수. 설계서 별도 절로 + QUESTIONS 에 승인 요청.
