설계 기준으로 검토했으며, 코드 수정·테스트는 하지 않았다.

| 4회차 지적 | 판정 | 근거 |
|---|---|---|
| P1 연속 재생 | **부분 해소** | §5.3.1의 누적 병합과 A48′·A48″는 정상 저장 시 반례를 닫는다. 그러나 누적값 저장 실패를 허용하는 §5.3.3 예외에서는 다음 호출까지 제한을 보존할 수 없다. |
| P1 감사 실패 시 이전 허용값 사용 | **해소** | §5.3.3은 실패 시 거부하거나 이번 호출에 새 제한을 적용한다. 이전 허용값으로 통과시키던 경로는 닫혔다. |
| P2 설명 불일치 | **해소** | §4.2는 직속, §17.1④와 A42는 명시적 `ch:'WORKFORCE'`로 정리됐다. |

남은 P1 반례: 저장본 `rev=300, NOT_REQUIRED` → `rev=200, REQUIRED` 수신 → 감사/CAS 실패 → 이번 호출에는 REQUIRED 적용하지만 `conflictLimit`은 미저장 → 다음 호출에 `rev=100, NOT_REQUIRED` 재생 → 저장본과 재생본 모두 NOT_REQUIRED이므로 앞서 적용한 REQUIRED가 사라진다.

이는 §5.3.3·A51이 명시적으로 허용한 실패 경로다. **누적 저장 실패 이후에도 제한이 다음 호출에 유지되거나, 미해결 상태로 거부되는 계약**이 필요하다. 단순 구현 테스트 항목으로 넘길 수 없다.

새 P0는 발견하지 않았다. 별개 새 P1보다는 기존 연속 재생 P1이 실패 경로에서 남는다. §11.2와 A5′의 “CAS 실패 후 저장본으로 판정”도 새 실패 계약에 맞춰 정리해야 한다.

착수 불가: 충돌 제한 저장 실패 후 다음 호출에서 기존 제한이 풀리는 경로가 남아 있다.
