# 전체 검수 후속 개선

사용자 요청: 남은 문제 개선 진행, 적당한 작업 단위로 나누어 커밋.

기준: `_workspace/full-review-2026-10-07/REVIEW.md`의 잔존 설계 문제와 현재 코드. 시작 작업 트리는 깨끗하며 이전 검수 수정은 이미 기존 커밋에 포함되어 있다.

완료 기준:
- 내보내기 확인과 삭제 범위를 서버가 받은 요청 집합 및 변경 시점으로 제한한다.
- PIN 실패 누적·잠금·성공·등록/변경·삭제가 동시 요청과 PIN 세대 변경에 안전하다.
- 승인 보관 내보내기에 현재 대상 가시성과 부속 자료 보존 계약을 적용한다.
- 외부 쓰기 결과 불명확의 자동 재전송을 막고 미적용 승인 삭제를 보호한다.
- 스윕 실패 페이지를 영구 누락시키지 않고 알림 후보의 첫 배치 이후도 예산과 커서로 처리한다.
- 집계의 가시성 범위와 기존 UI 계약을 확인한다.
- 회귀 테스트·전체 백엔드/UI 테스트·UI 빌드·Forge lint를 수행한다.
- 검증된 변경만 기능 단위로 한국어 커밋, 푸시·배포는 하지 않는다.

변경된 응답은 프론트 단계에서 실제 백엔드 계약에 맞춘다. 기존 배포 마이그레이션 이름과 보안 불변식을 보존한다.

추가 확인: `WorklogHistoryRetentionService`도 클라이언트 cutoff/count를 삭제 허가로 사용했다. 이 경로 역시 서버 내보내기 ID 집합으로 제한한다. Q73의 권한 없는 이력 마스킹·보관 정리 정책은 유지한다.

운영 한계는 숨기지 않는다: Jira read–PUT 사이 외부 편집을 원자적으로 잠그지는 않는다. 실패 페이지를 버리지 않도록 바꾸지만 poison page 이후의 독립 진행에는 별도 영속 재처리 큐가 필요하다. 집계가 조회 예산에 걸리면 불완전함을 응답과 UI에 표시한다.
