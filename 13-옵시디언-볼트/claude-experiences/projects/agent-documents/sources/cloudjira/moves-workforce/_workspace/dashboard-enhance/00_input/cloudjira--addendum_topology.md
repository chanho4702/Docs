**노드 크기 규칙 (T1·T2 공통, 사용자 확정)**:
- symbolSize = **MM(공수) 비례** — 산정 큰 노드 = 큰 원

- 범례/툴팁에 "크기 = 산정 공수, 미산정 = 기본 크기" 안내 1줄

## 보강 4 (2026-08-13, 사용자 T1 구조 정정 — 이전 T1 서술을 대체)

> "무브스아이 -> 프로젝트 -> 프로젝트에 연결된 이슈들 이런 구조여야 해. 각 이슈들도 연관관계가 있으니 잘 표시해줘야 하고, 연관관계는 하위이슈/연결이슈/워크포스 연결이슈가 있고, 각 이슈 노드의 크기는 투입된 시간이어야 해. 그래야 어떤 노드가 비용이 큰 노드인지 확인할 수 있으니까"

**T1 계층 (확정)**:
1. **루트 = 무브스(RMS) 프로젝트** 노드 1개 (현재 상세 화면의 프로젝트)
2. **중간 = Jira 프로젝트(스페이스)** 노드 — 이슈들이 소속된 Jira 프로젝트별 (구독 스페이스 복수 가능)
3. **리프 = 이슈** 노드

루트→스페이스, 스페이스→이슈는 소속 엣지. 여기에 **이슈 간 연관관계 엣지 3분류**:
- **하위이슈** — Jira parent/subtask 관계
- **연결이슈** — Jira issue links (Blocks 포함 전 타입, 타입명 툴팁)
- **워크포스 연결이슈** — 앱 정의 상위(wbsParent)
- 3분류가 범례·색/선 스타일로 구분. (폴더 소속은 이슈 간 관계가 아니므로 엣지 3분류에 넣지 않음 — 표시 여부는 프론트 설계 재량, 과설계 금지)

**이슈 노드 크기 = 투입 시간(timeSpentSeconds → actualMd) 비례** (이전 "plannedMd 비례"를 대체).
목적 = 비용이 큰 노드 식별. 투입 0/없음 = 디폴트 크기 고정. sqrt+클램프 규칙 유지.
루트/스페이스 노드 크기 = 산하 투입 시간 합 비례 권장.
