- 로고: `static/images/app.logo.png` 를 표지와 마무리에 사용(있으면). 없으면 텍스트 로고.

[슬라이드 구성] — 각 장: 제목 / 핵심 메시지 1문장 / 불릿 / 시각 요소 / 발표자 노트(2~4문장, 원고 문장 재사용)

1. 표지 — "Moves Workforce" + 한 줄 가치 "Jira의 업무 기록을 인력·공수·진척·비용의 판단 근거로". 다크 배경, 우측에 통합 대시보드 캡처 placeholder(📷 /dashboard 종합 개요 핵심 영역). 부제: Atlassian Jira Cloud용 Forge 앱.

2. 고객의 문제 — 메시지 "보고할 때마다 흩어진 숫자를 다시 맞춘다". 좌측: Jira 이슈 / 인력 배치 엑셀 / 비용 시트 / 월간 보고서가 따로 노는 도식(도형으로 편집 가능하게). 우측 표 「지금 벌어지는 일 → Moves Workforce가 하는 일」 원고 §1 표의 5행을 그대로.

3. 핵심 차별점 — 메시지 "공수 소진과 업무 완성은 다르다". 원고 「한 줄 요약」의 일정/완성/공수 3막대를 pptxgenjs 도형 막대로 그리고 "완성 − 일정 = −12.4%p → 지연" 콜아웃. 캡션 "설명용 예시 데이터". 하단에 3카드: ① 별도 인프라 없이 Jira 안에서 ② 근무일·연차를 반영한 지표 ③ 기록→분석→경영 판단을 한 앱에서.

4. 제품 전체상 — 메시지 "인력·공수·진척·비용을 하나로 연결한다". 좌측 입력(Jira 이슈·워크로그 / 근무 기준·공휴일 / 인력·팀 / 급여 정책) → 중앙 Moves Workforce → 우측 출력(진척률 / 작업 분석 / 인력 현황·배정 / 비용 / 통합 대시보드 / 기간 리포트) 흐름 도식. 하단 한 줄: 역할별 화면 — PM·팀장·PMO·구성원(원고 §1 「어떤 역할에 유용한가」 표를 4열 아이콘 행으로).

5. 진척 관리 — 메시지 "계획과 실적의 차이로 점검 대상을 찾는다". 📷 프로젝트 상세 > 분석 및 리포트 > 진척률 — 종합 헤더 + 진척 비교 막대. 불릿: 완성·공수·일정 3층 + 차이(%p) / 누적 S-curve로 계획선 대비 처짐 / 확정 지연(회고) vs 예측 지연(예보) / 상태 판정은 설정 임계치. 캡션 "완성 진척은 진행 중 이슈의 공수 비율 근사 포함".

6. 작업 분석 — 메시지 "왜 이 작업만 오래 걸리는가". 📷 작업 분석 테이블 — 초과율 배지가 섞인 행 + 계획/실투입/예상 완료일 컬럼. 불릿: 계획 공수(Original Estimate) 대비 실투입 MD / 초과율 🟢≤100% · 🟠100~130% · 🔴130%↑ 로 공수 블랙홀 우선 표시 / 남은 공수 추세로 예상 완료일 / 완료 이슈는 편차 컬럼으로 추정 정확도 사후 검증.

7. 인력 현황 — 메시지 "일할 수 있었던 시간과 기록된 시간을 비교한다". 📷 자원관리 > 인력 현황 — 상단 요약(여유·적정·과부하) + 가동률 바 행. 산식 카드(Consolas): 가동률(%) = 투입 MD ÷ 실효 가용 MD × 100. 불릿: 분모에 참여 기간·연차·공휴일 반영 / 팀 가동률은 Σ투입MD ÷ Σ가용MD(단순 평균 아님) / 가동률은 부하 지표이지 성과 점수가 아님(원고 문장 그대로).

8. 인력 배정 — 메시지 "스킬과 부하를 함께 보고 배정한다". 📷 자원관리 > 프로젝트 배정 — 좌 프로젝트 카드 + 우 후보 목록의 적합도·신호. 불릿: 미배정·임박·지연 작업 수를 왼쪽에 / 전사 후보의 스킬 적합도·부하 신호를 오른쪽에 / 한 명씩 또는 팀 전체를 그 자리에서 배정.

9. 작업·일정 — 메시지 "계층과 선후행으로 작업 순서를 잡는다". 📷 간트 뷰 — 폴더 계층 + 선후행 선이 보이는 구간(가로로 긴 크롭, 6~10개 작업). 불릿: 같은 데이터를 목록·트리·간트 3뷰로 전환 / WBS 계층·선후행·폴더 / 막대를 끌어 일정 조정 / 선후행은 Jira 네이티브 이슈 링크로 저장돼 앱 전용 데이터에 갇히지 않음.

10. 비용 — 메시지 "계획 인건비와 소진 추정을 확인한다". 📷 프로젝트 상세 > 비용 — 데모(가상 인물·가상 급여) 화면. 3카드: 계획 인건비(유효 투입급여 합산) / 소진 비용 AC(계획 인건비를 일정 진척률로 안분한 추정, 회계 지출 아님) / 이슈별 비용(워크로그 비중 배분). 하단 한 줄: 급여 정책 인원별 또는 등급 밴드, 미산정 인원 표시. 우측 작은 자물쇠 콜아웃: "비용·급여는 별도 권한 키(PROJECT_COST)로만 열림 — 권한 없으면 카드 자체가 없음".

11. 전사 관점 — 메시지 "여러 프로젝트 중 먼저 볼 곳을 고른다". 📷 통합 대시보드(/dashboard) 전체상 + 핵심 비교 영역. 불릿: 전 프로젝트를 시간·범위·자원 축으로 비교 / 스페이스 구독으로 이슈 자동 편입, 시간별 정합성 검사 / 계층형 팀 트리·팀별 가동률 / 목록 화면은 현재 필터 결과 그대로 엑셀 내보내기. 캡션 "일 단위 배치 스냅샷 + 요청 시 재집계, 기준 시각 표시".

12. 도입·권한 — 메시지 "운영 기준과 접근 범위를 설정하면 시작된다". 좌측 4단계 프로세스 도식: ① 근무 기준(1일 근무시간 기본 8h·공휴일) → ② 인력 등록(Jira 사용자·엑셀 일괄, 대용량 백그라운드) → ③ 팀·권한(프리셋 PM·PMO·팀장·팀원) → ④ 프로젝트 연결(스페이스 구독). 우측 권한 표 4행: 읽기/쓰기 분리·서버 deny-by-default / 조회 범위 ALL·MEMBER_ONLY·TEAM_ONLY / 인건비 PROJECT_COST 분리 / 등급 밴드 정책 시 개인 급여 키 제거. 하단 한 줄: Jira Cloud 전용(Server/DC 불가), 라이트·다크 테마, 한국어·영어.

13. 마무리(다크) — 메시지 "우리 프로젝트 데이터로 확인해 보십시오". 3줄 가치 요약을 3번 슬라이드의 3카드와 같은 순서·표현으로. 다음 단계 한 줄: "대표 프로젝트 하나로 근무 기준·계획 공수를 설정하고 워크로그를 누적하며 기존 보고와 대조". 문의·설치 링크는 "(연락처 기입)"·"(Marketplace 링크 기입)" 그대로 두고 지어내지 마라.

부록 A. 숫자를 해석하는 기준 — 원고 §3의 산식 3개(MD·MM / 가동률 / 완성 진척)를 Consolas 카드 3개로, 각 카드 아래 "먼저 설정해야 할 것" 한 줄(1일 근무시간·공휴일 / 참여 기간·연차 / 계획 공수 입력).
