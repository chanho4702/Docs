## 1. 목적·범위

앱 버전별 변경 내용을 사용자 관점에서 기록한다. **최신 버전이 맨 위**로 오도록 누적한다. 각 항목은 사용자에게 의미 있는 변화 위주로 적고, 내부 리팩터링은 생략하거나 한 줄로만 적는다.

## 2. 버전 표기 규칙

- 앱 버전은 매니페스트/패키지 버전과 동기화한다.
  - 백엔드 함수: `package.json`(루트) `version`
  - 프론트엔드: `static/ui/package.json` `version`
- 릴리스 항목은 아래 분류를 사용한다: **신규 · 개선 · 수정 · 주의(마이그레이션/설정 필요)**.

### [개발 기준: 백엔드 v1.1.17 / 프론트 v0.1.62] — 2026-08-10

> 이 항목은 개발 소스 기준이며, package version은 변경되지 않았습니다. 실배포 전 감사에서 확인된 권한·라이선스 결함을 우선 정리한 릴리스입니다.

- **보안(중요)**: 프로젝트 대시보드의 **총 인건비**는 이제 `PROJECT_COST` 읽기 권한이 있는 사용자에게만 표시됩니다. 이전에는 급여 정책이 *등급 밴드* 방식일 때만 숨겨졌는데, 기본값이 *인원별* 방식이라 일반 구성원에게도 프로젝트 인건비가 보였습니다.
- **보안(중요)**: 등급 목록의 **급여 밴드 금액**은 비용 열람 또는 등급 관리 권한이 없으면 응답에서 제외됩니다. 등급과 밴드를 조합하면 개인 급여를 역산할 수 있었습니다. 급여 정책 화면의 "밴드 미설정" 안내는 그대로 동작합니다.
- **보안(중요)**: **인력 현황·인력 상세·스킬 매칭·부하 요약·배정 관계도**가 모두 같은 가시 범위를 따릅니다. 팀장은 자신이 이끄는 팀 인원만 보이며, 이전에는 화면만 제한되고 데이터는 전사 범위로 나갔습니다. 관리자·PMO·PM은 종전대로 전사를 봅니다.
- **보안**: 프로젝트에 **팀 전체 추가** 시 담당 팀 범위 검증이 추가됐습니다. 후보 목록 조회는 거부하던 팀을 실제 추가 동작은 통과시키고 있었습니다.
- **보안**: 프로젝트 구독의 **추가 JQL 조건**에 괄호·따옴표 검증이 추가됐습니다. 조건을 조작해 구독하지 않은 스페이스의 이슈를 편입시킬 수 있었습니다. 이미 저장된 조건도 실행 시점에 검증합니다.
- **운영 안정화**: 라이선스 상태를 **확인하지 못한 경우**에는 앱을 차단하지 않습니다. 아틀라시안 라이선스 조회가 일시적으로 실패해도 앱 전체가 멈추지 않습니다. 단, 조회에 성공했는데 활성 라이선스가 없으면 종전대로 차단합니다.
- **수정**: 스킬이 100건을 넘으면 목록·필터·스킬 매핑에서 초과분이 보이지 않고, 같은 이름이 중복 등록되던 문제를 고쳤습니다(기본 프리셋만 133건이라 전체 등록 시 발생).
- **수정**: 전사 대시보드의 **지금 재집계**가 권한 없는 사용자에게도 보이고 눌러도 아무 반응이 없던 문제, 다른 집계가 끝난 직후 눌렀을 때 즉시 완료로 처리되던 문제를 고쳤습니다. 집계 중에도 기준 시각이 함께 표시됩니다.
- **수정**: 프로젝트 캘린더에서 기간 워크로그 등록이 실패했을 때 남은 항목이 목록에 보이지 않아 중복 등록으로 이어지던 문제를 고쳤습니다. 종료 시각이 시작보다 빠르면 등록 전에 안내합니다.

### [개발 기준: 백엔드 v1.1.17 / 프론트 v0.1.62] — 2026-08-06

> 이 항목은 개발 소스 기준이며, package version은 변경되지 않았습니다. 운영 릴리스로 확정하기 전 대상 환경의 배포·설치 상태를 확인해야 합니다.

- **개선**: 전사 대시보드의 **지금 재집계**는 큐 등록 직후 끝난 것으로 처리하지 않습니다. 집계 시작 전의 기준 시각이 바뀔 때까지 15초 간격으로 완료를 확인하고, 완료되면 화면을 자동 갱신합니다. 대기 상한은 10분입니다.
- **수정**: 기간 워크로그 등록이 일부 실패한 경우 취소 결과를 확인해 실제로 남은 항목이 목록에 보이도록 했습니다. 사용자 조회의 빈 결과, 단일 급여 구간 계산, 구독 화면 query key 계약도 보완했습니다.
- **운영 안정화**: 큐 consumer·scheduled trigger에서도 Forge 실행 환경을 판별해 development/staging에서 라이선스 확인이 불필요하게 차단되는 경로를 보완했습니다.
- **내부 정리**: 카탈로그 일괄 추가와 프로젝트 전체 이슈 수집의 중복 구현을 통합하고, frontend/backend 근무일 계산 동기화 테스트를 추가했습니다.

### [개발 기준: 백엔드 v1.1.17 / 프론트 v0.1.62] — 2026-08-04

> 아래 항목은 `develop` 브랜치와 2026-08-04 작업 트리 기준이다. 최근 프로젝트 구독 커밋은 **배포/E2E 미수행**으로 기록되어 있으므로, 운영 배포 노트로 확정하기 전에 대상 환경의 배포·설치 상태를 확인해야 한다. 패키지 버전은 아직 이전 값과 동일하다.

- **신규 — 팀·자원관리**
  - 계층형 팀 관리, 사용자 단일 소속 팀, 팀장 관계, 프로젝트 담당 팀과 주 담당 팀을 추가했다.
  - `TEAM_ONLY` 프로젝트 범위와 PM/PMO/Team Lead/Team Member 권한 프리셋을 제공한다.
  - `/resource`에 인력 현황·조직 현황·팀 분석·프로젝트 배정 탭을 구성했다. 팀/프로젝트 필터, 팀별 가동률·구성·투입·진척·계층 롤업, 3레이어 배정 관계도, 팀 전체 배정을 지원한다.
  - 프로젝트 인력 분석에 인별/팀별 보기, 프로젝트 분석에 **담당 팀 대비 실제 기여** 화면을 추가했다.
  - 마이페이지에 내 권한·스킬과 팀장 전용 팀원 업무 분석을 추가했다.
- **신규 — 프로젝트 구독**
  - 프로젝트가 Jira 스페이스 또는 보드를 구독하면 조건에 맞는 이슈를 자동 편입한다.
  - 생성 이벤트의 빠른 편입, 시간별 정합성 리컨실, 기존 이슈 백필 큐, 미리보기·수동 동기화·해제를 지원한다.
  - 한 소스는 전사에서 한 RMS 프로젝트만 구독할 수 있고, 프로젝트당 최대 10개다. 해제해도 이미 편입된 이슈는 유지된다.
- **신규 — 급여 정책**
  - 전사 급여 정책 `INDIVIDUAL`(인원별) / `LEVEL_BAND`(등급 기반)를 추가했다.
  - 등급별 급여 하한·상한·대표값과 프로젝트 급여 관리의 유효 인건비 계산을 제공한다.
  - 등급 기반 정책에서는 개인 연봉·투입 급여를 서버 응답에서 제거하고, 저장된 개인 값은 정책 복귀를 위해 보존한다.
- **개선**
  - 작업 관리 상단에 구독 소스 요약·즉시 동기화·구독 스페이스 필터 연결을 추가하고, 소스 아이콘/선택 상태 표시를 개선했다.
  - 등급 밴드 변경 시 사용자·프로젝트 급여·비용·대시보드 관련 TanStack Query 캐시를 함께 무효화한다.
  - 팀 분석의 종료 프로젝트 혼입을 막기 위해 기본값을 진행 중 프로젝트로 하고, 알 수 없는 값은 0 대신 `N/A`로 구분한다.
- **수정·하드닝**
  - 권한 매핑 deny-by-default, 팀장 allowlist, project scope, SQL DML 영향 행 수, license fail-close, job polling 응답 계약을 보강했다.
  - 전사 가동률의 인원별 참여 기간 합집합 분모, 일정 겹침 최소 `workRatio`, 미래/0 분모 처리 등 지표 불변식을 정리했다.
- **주의**
  - 자동 마이그레이션 v015는 `portfolio_project_snapshot.salary_policy`, v016은 `project_subscription`을 추가한다.
  - `manifest.yml`의 KVS `level`/`settings` 속성과 이슈 생성 trigger·consumer·scheduled trigger가 변경되므로 **배포가 필요**하다. scope 변경은 없으며 보드 Agile API는 현 scope에서 실호출 검증이 필요하다.
  - 등급 기반 정책을 켜기 전에 비용 산정 대상 전원의 등급을 지정하고, 각 사용 등급에 대표값 또는 하한·상한 쌍을 채워야 한다. 그렇지 않으면 해당 인원의 인건비는 0으로 계산된다.
  - 대규모 구독이 `PARTIAL`로 끝난 뒤 cursor로 재개할 때, 이미 태깅된 이슈로 후보 집합이 줄어 이전 cursor가 미조회 이슈를 건너뛸 위험이 있다. 이 경로는 수정·회귀 테스트·사이트 E2E가 완료되기 전 운영 정확성을 보장하지 않는다.
  - 공휴일 Sidebar 메뉴는 현재 `PERMISSION_MANAGEMENT`로 노출을 판정하지만 편집 API는 `PUBLIC_HOLIDAY_MANAGEMENT`를 사용한다. 전용 공휴일 권한만 가진 사용자는 직접 URL로 접근해야 하는 UI 불일치가 남아 있다.
