# 워크로그 사전 승인과 기간 잠금

**기간 잠금은 Moves Approval을 Jira 시간 추적 제공자로 선택한 사이트의 앱 입력 화면에 적용됩니다. REST·자동화·모바일 등 다른 경로의 변경을 전부 사전 차단하지 않습니다.** 다른 경로의 변경은 감지·이력·재승인으로 관리합니다.

## 제공자 선택

사이트 관리자가 Jira **설정 → 시스템 → 시간 추적**에서 제공자를 **Moves Approval**로 선택합니다. 사이트의 활성 제공자는 하나이므로 Tempo 등 다른 제공자와 동시에 선택할 수 없습니다. 기존 입력 흐름을 점검한 뒤 전환하세요.

선택하면 Jira 기본 **Log work**·**Work log** 화면 대신 앱의 입력·목록 모듈을 사용합니다. 이 모듈은 Atlassian Preview 기능이며 설치 환경에서 동작을 확인해야 합니다. [Atlassian 시간 추적 제공자 문서](https://developer.atlassian.com/platform/forge/manifest-reference/modules/jira-time-tracking-provider/)

## 입력·수정·삭제

이슈의 **••• → Log work**에서 작업 날짜·시간·설명을 입력하고, **Work log** 탭에서 목록을 확인합니다. 수정·삭제는 본인 여부와 Jira 워크로그 권한에 따라 허용됩니다. 앱은 사용자의 Jira 권한으로 실행하므로 권한이 없으면 처리되지 않습니다.

기본 정책은 제출 중·승인된 본인 기간의 앱 입력을 잠급니다. 기간 기준 날짜를 바꾸는 편집도 잠금 조건을 확인합니다. 기간이 마감되어 있으면 마감 잠금도 적용됩니다.

## 건별 사전 승인 설정

프로젝트 관리자는 프로젝트의 Moves Approval 설정에서 **워크로그 생성 사전승인** 필수 여부, 허용 결재선과 기본 결재선을 정합니다. 기존 결재선을 재사용하며 요청자가 매번 단계를 구성할 필요가 없습니다. 기본값은 사전 승인 필수 아님입니다.

필수 정책을 사용하려면 사이트 관리자가 Moves Approval을 Jira 시간 추적 제공자로 선택하고, 전역 **적용 프로젝트** 설정에서 해당 프로젝트를 사용 상태로 두어야 합니다. 제공자를 선택하지 않으면 앱 입력 화면이 표시되지 않고 Jira 기본 입력 경로가 남습니다. 프로젝트가 비활성화되어 있으면 프로젝트 관리자가 정책을 저장했더라도 앱은 새 승인 요청과 등록을 차단합니다. 사이트 관리자와 두 전제를 먼저 확인하세요.

앱 접근 제한을 켠 사이트에서는 요청자도 앱 명부 또는 허용된 활성 팀에 등록해야 승인 상세 확인·등록을 완료할 수 있습니다. 일반 입력 화면을 열 수 있다는 것만으로 승인 후 등록 권한을 갖는 것은 아닙니다. 프로젝트에서 필수 조건을 켜기 전에 요청자 계정으로 전체 절차를 시험하세요.

이슈의 Moves Approval 패널에서 **워크로그 승인 결재선**을 선택하면 다음 입력안에 적용합니다. 기본 결재선이 있으면 재선택 없이 사용할 수 있습니다. 이는 앱 패널 안의 선택 항목이며 Jira의 기본 custom field는 아닙니다. 사용자는 허용된 결재선만 바꿀 수 있고, 프로젝트의 승인 필수 조건을 해제할 수 없습니다. 다른 사용자가 이 이슈의 다음 결재선을 바꾸더라도 이미 상신한 입력안과 승인 단계는 바뀌지 않습니다. 현재 Flow가 허용 목록에서 빠지거나 승인 단계 구조가 바뀌거나 프로젝트 정책이 비활성화되면 기존 입력안은 등록되지 않을 수 있습니다. 전환 승인은 별도의 프로젝트·유형·목적 상태 규칙으로 결재선이 자동 결정됩니다.

1. 승인 필수 프로젝트에서 날짜·시간·설명을 작성하고 승인 요청을 보냅니다. 이 시점에는 Jira 워크로그가 생성되지 않습니다.
2. 결재자가 입력안을 검토하고 승인하거나 반려합니다. 입력안은 고정되며, 내용 변경은 새 승인 요청이 필요합니다.
3. **내 워크로그 승인 요청 · 등록 현황**에서 상세를 열고 요청자 본인이 **승인된 기록 등록**을 누릅니다. 요청자 권한으로 실행하므로 Jira 작성자는 요청자입니다. 승인 결정과 실제 등록 상태를 구분해서 확인하세요.
4. 실제 Jira에 등록된 기록은 기존 타임시트 기간 승인 대상이 됩니다. 건별 사전 승인이 기간 승인을 대신하지 않습니다.

등록 직전에 권한·잠금·현재 결재선 정책을 다시 검사합니다. 정책이나 결재선이 바뀌면 새 승인이 필요할 수 있습니다. 사전 승인을 해제한 뒤에도 이전 승인 입력안이 자동 등록되는 것은 아닙니다. 스토리지가 준비되지 않았거나 정책을 확인할 수 없으면 앱의 신규 등록을 잠시 거부합니다.

**등록 결과 불명**은 실패를 뜻하지 않습니다. Jira에는 이미 등록됐지만 응답을 받지 못했을 수 있습니다. 같은 승인 요청을 자동 재전송하지 않습니다. 결과 대조에서 후보를 찾거나 검색을 완료해도 자동으로 등록 완료를 확정하지 않으며, 지원 담당자가 실제 Jira 기록을 확인해야 합니다. 확인 전에 같은 내용을 새 요청으로 등록하면 중복 기록이 생길 수 있습니다.

사전 승인 관문은 앱의 신규 워크로그 등록에 적용합니다. 기존 기록의 수정·삭제에는 현재 권한·기간 잠금이 적용되며 신규 등록 승인과 동일한 관문이 아닙니다. REST·자동화·다른 앱의 직접 등록은 이 관문을 통과하지 않습니다. Jira 권한 운영을 함께 설계해야 하며, 요청자의 작업 권한을 회수하면 앱에서 승인된 기록을 등록하는 것도 막힙니다.

## 마감·다시 열기

관리자는 타임시트 설정에서 기간을 마감하거나 다시 열 수 있습니다. 자동 마감은 기본 꺼짐이며 기간 종료 후 일수를 설정해 켭니다. 다시 열기는 마감 잠금만 해제하며 제출·승인 잠금은 별도로 유지됩니다. 다시 열어도 과거 결정 이력을 수정하지 않습니다. 재제출이 필요한 경우 내 타임시트에서 진행하세요.

미소속자의 입력을 Jira 전체에서 제한하려면 고객 Jira 관리자가 **Work on work items** 등 권한과 프로젝트 역할을 별도로 설계해야 합니다. 권한에는 월·주별 시간 조건이 없습니다.

## 원본 우선 사후 인증과 고통제 모드

일반 워크로그는 Jira에 먼저 저장합니다. 작업 로그 행의 **워크로그 사후 인증**을 선택하면 해당 원본만 조회하고, 작성자에게 제공된 결재선을 선택하여 **기록 인증 요청**을 제출합니다. 다른 작성자의 원본은 인증을 요청할 수 없습니다. 인증 목록을 모든 행마다 자동 조회하지 않으며 선택한 기록만 확인합니다.

상태는 미인증(UNVERIFIED), 인증 결재 중(PENDING), 원본 인증됨(VERIFIED), 인증 반려(REJECTED), 인증 후 변경(CHANGED_AFTER_VERIFICATION)입니다. 인증 당시 시간·설명·공개 범위를 포함한 지문을 고정하고 최종 승인 직전 원본을 다시 확인합니다. 수정·삭제가 관찰되면 인증이 무효화되며 이전 값으로 복원해도 자동 복구되지 않습니다. 삭제된 원본은 사용자 조회에서 오류가 날 수 있습니다. 과거 전체 기록의 일괄 인증이나 이슈 전체 인증 목록은 제공하지 않습니다.

기존 WORKLOG_CREATE는 선택적인 **고통제 승인 후 등록** 모드입니다. 승인 전에 원본을 쓰지 않고 승인 후 본인이 등록합니다. 자동 워크로그 생성은 하지 않습니다. 사후 인증, 이 모드, 기간 단위 타임시트 승인은 각각 독립적인 절차입니다. Jira native·REST·자동화·다른 앱 입력을 전부 사전 차단하는 기능은 아닙니다. provider 선택과 앱 화면의 기간 잠금 범위는 위 안내를 따르세요.

## 워크로그 정책 계층 안내

기존 프로젝트의 사전승인 필수 설정도 유지됩니다. 계층 정책을 CERTIFICATION으로 바꾸는 것만으로 기존 필수 사전승인이 해제되지는 않습니다. 실제 등록 방식은 작성 화면의 승인 안내를 확인하세요.

정책은 사이트 → Workforce 프로젝트(해당 이슈 제약 포함) → Jira 프로젝트 → Jira 이슈 순서로 항목별 상속합니다. 이슈 작업 로그의 **이슈 워크로그 정책·상속**에서 실제 값·출처·리비전·잠금·무시된 설정을 확인하세요. 관리자는 체크한 항목만 재정의하고 체크를 해제하면 상속으로 되돌립니다. Workforce 잠금은 완화할 수 없고 비교 가능한 키만 최소 제한보다 강화할 수 있습니다.

작성·수정·삭제 전에 날짜/원래 작성일 기준 작업 허용 기간, 제출·마감 잠금, WARN/BLOCK, 승인 모델을 확인합니다. BLOCK 시간 상한은 실행 직전 현재 합계를 검사해 Jira 쓰기 전에 거부합니다. WARN과 기존 EXTRA_STEP 시간 상한은 기록을 지연시키지 않고 타임시트 미리보기·제출에서 안내합니다. PREAPPROVAL은 기존 결재선과 승인 후 본인 등록을 요구하며 직접 생성하지 않습니다. CERTIFICATION은 Jira 원본을 먼저 저장한 뒤 인증합니다. 이슈가 이동하면 이전 프로젝트 override는 적용되지 않으며 새 프로젝트 관리자가 기존 리비전과 이전 프로젝트를 함께 확인하는 CAS로 명시 설정을 재귀속할 수 있습니다.

Workforce 캐시는 유효 기간 뒤 24시간 유예 동안 마지막 검증본을 사용합니다. 유예 종료 후 잠금 없는 키는 사이트/로컬 fallback, 잠금 키는 관련 작업 차단입니다. 설명 이력 보관은 기본 비활성입니다. 수집 on/off는 이슈 실제 적용값을 따르지만 과거 이력 열람은 수집이 꺼져도 가능할 수 있습니다. 보존 기간은 사이트 전용이며 0은 무기한입니다. 정책 확인과 Jira 쓰기 사이의 외부 변경을 단일 transaction으로 묶거나 native/REST/자동화를 모두 사전 차단하는 보장은 없습니다.
