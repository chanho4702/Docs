# 필드 변경 승인

앱을 통한 변경 요청은 승인 후 적용합니다. **Jira 직접 편집·REST·자동화 변경은 사전 차단하지 않고 감지·기록합니다.**

## 규칙 설정

프로젝트 관리자는 **프로젝트 설정 → Moves Approval → 필드 변경 승인 규칙**에서 이슈 유형·필드·결재선을 지정합니다. 현재 지원 유형은 날짜, 사용자, 우선순위, 숫자, 단일 선택입니다. 다중 값·텍스트·서식 있는 본문·날짜와 시간·계단식 선택 등은 지원 대상이 아닙니다. 상태·해결 값은 전환 승인으로 관리합니다.

## 요청·적용

1. 이슈의 **필드 변경 승인** 영역에서 대상 필드의 **변경 요청**을 엽니다.
2. 현재 값과 새 값 또는 값 지우기를 확인하고 사유·마감·참조자를 입력합니다.
3. 규칙의 결재선으로 제출합니다.
4. 최종 승인 뒤 **승인 상태와 적용 상태**를 함께 확인합니다.

| 적용 상태 | 의미·대응 |
| --- | --- |
| 적용됨 | Jira 값 적용 완료 |
| 승인됨 · 미적용 | 편집 권한·편집 화면·Jira 응답을 확인하고 상세에서 다시 적용 |
| 값 충돌 · 미적용 | 요청 이후 현재 값이 달라짐. 덮어쓰지 않으므로 현재 값을 기준으로 새 요청 |
| 적용 중·적용 대기 | 잠시 후 상세를 다시 확인. 일괄 승인에서 적용이 뒤로 미뤄질 수 있음 |

최종 결정 시에는 승인자 이름과 권한으로 적용합니다. 다시 적용하면 실제 적용한 사용자가 Jira 수정자로 남습니다. 승인 성공이 필드 적용 성공을 보장하지 않습니다. 다시 적용은 요청자·해당 요청의 결재자(대리 처리자 포함)·Jira 관리자가 할 수 있으며 실행자에게 Jira 편집 권한이 필요합니다.

## Jira 권한과 직접 변경

직접 편집을 조직 차원에서 제한하려면 관리자가 요청자 역할의 **Edit work items** 권한을 조정하고 승인자에게 필요한 권한을 유지합니다. 다른 편집 업무에도 영향을 주므로 시험 프로젝트에서 먼저 검증하세요. 필드를 편집 화면에서 제거하면 앱의 적용도 실패합니다.

규칙 삭제는 이후 감지·승인 적용 범위에 영향을 주며 진행 중 요청은 남습니다. 우회 변경 이력에서 요청 만료·승인 값 덮어쓰기 등을 확인하세요.
