# 소개와 핵심 개념

Moves Approval for Jira는 Jira Cloud용 승인 앱입니다. Jira의 이슈 권한을 유지하면서 요청·결정·변경 이력을 업무함에서 확인합니다. Confluence 페이지 승인 앱과는 별도 앱입니다.

## 여섯 가지 승인 대상

| 대상 | 승인하는 것 | 승인 이후 |
| --- | --- | --- |
| 이슈 일반 승인 | 이슈의 검토 결과 | 이슈를 자동 전환하거나 편집을 잠그지 않습니다. 수정 표시를 확인하고 필요하면 재상신합니다. |
| 워크로그 사후 인증 | Jira에 이미 저장된 워크로그의 시간·설명·공개 범위 지문 | 승인 후 `VERIFIED`가 되며 원본 수정·삭제를 관찰하면 `CHANGED_AFTER_VERIFICATION`으로 바뀝니다. |
| 워크로그 입력안 사전 승인 | 앱에서 새로 등록할 미저장 워크로그 입력안 | 선택적인 고통제 모드입니다. 승인 후에도 요청자 본인이 Jira에 등록하며 REST·자동화의 직접 입력을 대신 막지 않습니다. |
| 타임시트 | 사용자 한 명의 월 또는 주 기간에 대한 제출본 | 이후 워크로그 변경을 감지하면 재제출이 필요합니다. |
| 상태 전환 승인 | 이슈를 특정 목적 상태로 이동할 권한 | 신규 요청은 승인 후 요청자 권한으로 자동 적용합니다. 기존 LEGACY_MANUAL은 수동 전환합니다. 해당 전환에 validator를 붙여야 강제됩니다. |
| 필드 변경 승인 | 규칙 대상 필드의 현재 값 → 새 값 | 최종 승인자의 Jira 권한으로 적용합니다. 승인과 적용 결과를 따로 확인합니다. |

일반 승인·전환 승인·필드 변경 승인은 별도 요청입니다. 일반 승인을 완료해도 전환 승인 조건을 대신 충족하지 않습니다.

## 결재선과 상태

결재선은 순서가 있는 단계들입니다. 각 단계는 지정된 승인자와 완료 조건에 따라 진행하고, 앞 단계가 끝나야 다음 단계의 차례가 옵니다. 참조자는 내용을 확인하지만 참조자 역할만으로 결정할 수는 없습니다.

완료 조건의 필요 승인 수가 1이면 단계 내 한 명의 승인으로 진행하고, 인원 수와 같으면 전원 승인이 필요합니다. 예를 들어 3명 중 2명으로 설정하면 2명의 승인이 필요합니다. 단계 내 반려는 요청 반려로 이어집니다.

승인 대기 → 승인 완료·반려·만료·회수로 진행합니다. 끝난 요청의 결정을 고치는 대신 새 요청을 만듭니다. 조직에서 상태 표시명을 바꿔도 승인 규칙은 바뀌지 않습니다.

## 역할

요청자는 내용을 제출하고 진행을 확인합니다. 승인자는 자신의 차례에 결정합니다. 팀장은 자신이 이끄는 팀의 타임시트를 확인합니다. Jira 관리자·앱 설정 관리자는 전역 설정을, 프로젝트 관리자는 해당 프로젝트의 승인 규칙을 관리합니다. 어떤 역할도 Jira 이슈 열람 권한을 대신하지 않습니다.
