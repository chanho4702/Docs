Required access

Project read permission and project visibility scope are required to enter project details. Tabs have additional permissions. An unavailable financial field is hidden; it should not be interpreted as a zero amount.

Tab Read Write
Dashboard Dashboard read Dashboard write for widgets, layout, and filters
User Management → Members Project read Project or Resource management write
Salary management Cost read Cost write
Work assignment Project or Resource management read Project or Resource management write
Work management: List, Tree, Gantt, Map Project read Project write; Map is read-only
Project calendar Project read Calendar viewing does not itself grant editing rights
Work and people analysis Report read Read-only analysis
Team analysis Report and Project read Read-only analysis
Progress Report read Read-only analysis
Cost analysis Cost read Read-only analysis
Work history Project write controls tab availability Read-only history
Document management Project read Project write; linking to issues also requires Jira Edit Issues

Editing Jira issues additionally requires the relevant Jira permissions: issue editing, scheduling, assignment, or linking. Salary policy also controls which individual amounts are available.

Header and navigation

Select a project from the project list, Kanban, or My Work. Breadcrumbs show the project, tab, and subtab. Copy link includes the selected screen and view so another authorized user can open the same context. Changing tabs updates the navigation context used by refresh and Back.

Where to start

  • New project: add people, then link existing Jira issues manually or through a subscription.
  • Scheduling: use Tree and Gantt. Bulk updates can apply dates or planned effort to selected work items.
  • Weekly reporting: review progress, then the dashboard.
  • Design documents and meeting notes: link them in Document Management.
  • Cost review: check salary management, then cost analysis.
