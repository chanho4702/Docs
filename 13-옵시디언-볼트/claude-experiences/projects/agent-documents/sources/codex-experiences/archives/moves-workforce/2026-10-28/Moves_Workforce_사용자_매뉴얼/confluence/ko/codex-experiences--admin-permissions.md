# 권한과 데이터 조회 범위

[가이드 홈](codex-experiences--index.md) · [English](../en/codex-experiences--admin-permissions.md)

> 검토 초안: 2026-10-04 지정된 staging의 영어 화면을 촬영했습니다. 화면 이미지는 한·영 가이드가 공통으로 사용합니다. 배포 버전과 역할별 접근·저장 동작은 아직 검증 중입니다.

권한은 **할 수 있는 작업**, 조회 범위는 **그 작업을 적용할 데이터**를 정합니다. Jira 권한은 별도로 적용됩니다. 이 세 가지를 함께 확인해야 메뉴가 없거나 저장이 거부되는 이유를 찾을 수 있습니다.

## 권한 세트 만들기

권한 관리 읽기로 설정을 확인하고, 쓰기로 세트를 생성·수정합니다.

1. **Settings → 권한 관리**에서 권한 세트를 추가합니다.
2. 필요한 기능의 읽기·쓰기를 선택합니다.
3. 프로젝트 데이터 범위를 지정합니다.
4. 사용자 또는 팀에 배정합니다.
5. 대상 사용자의 **마이페이지 → 내 권한**과 실제 접근 결과를 확인합니다.

권한 관리 쓰기는 다른 권한을 부여할 수 있으므로 권한 운영 담당자에게 배정합니다. 일반 배정자는 자신의 권한을 넘는 세트를 지정하지 못할 수 있습니다.

## 프로젝트 범위

| 범위 | 의미 |
|---|---|
| 전체 프로젝트 | 앱의 전체 프로젝트 범위 |
| 소속 프로젝트만 | 본인이 프로젝트 인력으로 등록된 프로젝트 |
| 내 팀만 | 본인 소속·리딩 팀 및 하위 팀 관계를 기준으로 허용된 프로젝트 |

내 팀만을 쓸 때는 사용자 팀·팀장 관계와 프로젝트 담당 팀·실제 인력 배정을 함께 확인합니다. 유효한 팀 관계가 없으면 프로젝트가 비어 보일 수 있습니다.

## 비용과 조직 정보

- 비용 읽기는 급여·인건비 조회를 별도로 제어합니다. 프로젝트나 리포트 읽기만으로 비용이 열리지 않습니다.
- 개인 금액은 급여 정책의 영향도 받습니다. 등급 기반 정책에서는 개인 연봉을 숨길 수 있습니다.
- 팀·인력 범위는 별도의 조직 열람 판정을 따릅니다. 프로젝트 범위만 바꾸고 명부 전체가 숨겨진다고 가정하지 마세요.
- 자원관리 인력 명부와 팀 분석은 아래 조직 범위 규칙을 함께 확인합니다.

| 우선순위 | 조건 | 조직 데이터 범위 |
|---|---|---|
| 1 | Jira 전역 관리 권한 보유 | 전체 |
| 2 | 팀 관리·인력 관리·자원관리 중 **하나 이상의 읽기** 권한 **그리고 전체 프로젝트 범위** | 전체 |
| 3 | 위 조건을 충족하지 않지만 실제 팀장으로 등록됨 | 본인이 이끄는 팀과 하위 팀 |
| 4 | 위 조건에 모두 해당하지 않음 | 이 조직 조회 경로에서 열람할 데이터 없음 |

이 표는 화면 자체의 접근 권한을 대신하지 않습니다. 자원관리 화면에는 자원관리 읽기가 따로 필요합니다. **리포트 읽기만으로 전사 명부가 열리지 않습니다.** 표의 규칙은 로컬 구현에서 확인했으며 staging 적용 여부는 실화면 검증 대기입니다.

Admin·PM·PMO 같은 이름만으로 실제 권한을 단정하지 않습니다. 시스템 세트의 편집 가능 항목과 Jira 관리자 예외도 화면에서 확인합니다.

## 팀 권한 상속

개인에게 명시적으로 배정된 권한과 팀 상속을 구분합니다. 팀 상속을 선택하면 소속 팀 또는 상위 팀의 세트를 따릅니다. 상속할 세트가 없다는 경고가 나오면 배정을 완료하기 전에 권한 구성을 보완합니다.

팀장 변경·팀 이동·팀 삭제는 상속 결과를 바꿀 수 있습니다. 변경 후 대상 계정으로 다시 확인하세요.

## Jira 권한과 별도인 기능

앱 쓰기 권한이 있어도 이슈 편집·담당자 지정·워크로그 기록은 Jira가 거부할 수 있습니다. 필요한 Jira 권한은 [작업 관리](codex-experiences--project-work.md)와 [My Work](codex-experiences--my-work.md)를 참고하세요. 워크로그 추출의 데이터 범위도 본인 Jira 권한을 따릅니다.

## 버튼·입력 항목과 처리 결과 상세

권한 관리에서 화면 접근(Read/Write)과 데이터 범위를 함께 정합니다. 메뉴가 보인다는 사실만으로 모든 인력·비용 데이터를 조회할 수 있는 것은 아닙니다.

| 버튼·입력 항목 | 기능·사용 조건·변경 대상 | 결과 확인과 문제 대응 |
|---|---|---|
| 권한 추가·이름 | 이름을 붙이고 사용할 기능의 읽기·쓰기를 선택해 세트를 저장합니다. 이름 중복 또는 아무 기능도 선택하지 않은 상태는 오류가 될 수 있습니다. | 추가만으로 사용자에게 적용되지 않습니다. 사용자 개인 세트 또는 팀 세트에 연결해야 합니다. |
| 읽기·쓰기·전체 선택 | 읽기는 조회, 쓰기는 해당 기능의 생성·변경·삭제 접근을 제공합니다. 전체 선택은 편집 중 체크박스를 넓히는 동작입니다. | 최소 업무 범위만 선택하고 저장합니다. 앱 쓰기로 Jira Edit/Assign/Schedule/Link 권한이 자동 부여되지는 않습니다. |
| 전체·내 프로젝트·내 팀 프로젝트 범위 | 프로젝트 조회 범위를 정합니다. 관리자의 전체 범위는 별도 규칙을 따릅니다. 조직 인력 명부는 추가 조직 범위 판정을 받습니다. | 내 팀 범위와 Resource/User 읽기만으로 전사 후보가 보인다고 가정하지 않습니다. 실제 팀장은 담당 팀·하위 팀 범위로 제한될 수 있습니다. |
| 비용·급여 권한 | 비용 접근과 급여 정책을 함께 만족해야 관련 금액을 조회합니다. 일반 명부 권한과 비용 권한은 별개입니다. | 비용 권한 없는 계정과 등급 기반 정책의 개인 금액 표시를 각각 확인합니다. |
| 권한 수정·삭제 | 수정은 연결된 사용자·팀의 실효 접근에 영향을 줍니다. 사용 중인 세트의 삭제는 거부될 수 있습니다. | 변경 후 대상 사용자가 본인 계정으로 확인합니다. 삭제하려면 먼저 세트 참조를 확인·정리합니다. |
| 사용자 개인 권한·팀 상속 | 개인 세트가 있으면 이를 사용하고, 팀 상속은 소속 팀 또는 가까운 상위 팀의 세트를 따릅니다. 등록 기본값과 편집의 팀 상속 선택은 구분합니다. | 팀 이동·팀 세트 변경 전 실효 권한을 확인합니다. 상속할 세트가 없는 상태를 자동 Member 부여로 단정하지 않습니다. |
