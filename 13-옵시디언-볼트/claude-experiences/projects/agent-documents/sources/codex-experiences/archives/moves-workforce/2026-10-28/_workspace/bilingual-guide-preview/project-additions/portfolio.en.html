Compare schedule, scope, resources, and cost across projects to decide where to investigate. The portfolio dashboard shows aggregated results rather than live data entry.

Required access

Report read allows viewing; Report write allows reaggregation. Cost information additionally requires Cost read. Projects remain limited to your visibility scope.

Recommended review sequence

  1. Check the aggregation timestamp and status.

  2. Select projects to compare.

  3. Use the schedule, scope, and resource signals to choose projects for review.

  4. Narrow the cause using the relevant comparison tab.

  5. Open project progress, work, or people analysis to inspect the underlying issues.

Perspective

Question to investigate

Schedule

Is completion keeping pace with elapsed schedule?

Scope

Is a large amount of work still unstarted?

Resources

Are overloaded and underused people appearing together?

Cost

What needs investigation when budget, estimated labor cost, and completion are compared?

Traffic lights help select investigation targets. Green does not prove that no problem exists, and red does not establish its cause.

Aggregation and filter considerations

  • Recent worklog or staffing changes may not appear until the next aggregation. If permitted, request reaggregation and check completion.

  • If a project retains its previous result after an aggregation failure, do not report it as current.

  • Some organization-wide widgets use a different scope from the top-level project filter. Read each widget's explanation.

  • Following a salary-policy change, cost display may be restricted until results are aggregated under the new policy.

  • Organization-wide and project utilization may handle overlapping periods and denominators differently.

When topology is available, expand project, space, status, and issue relationships to investigate individual issues. Do not treat a capped or partially displayed graph as the complete dataset.

Common controls and aggregation

Portfolio compares multiple projects at an aggregation timestamp. A new worklog can be saved while displayed values still reflect an earlier aggregation.

Aggregate now / As of / partial failure

Request aggregation when authorized and refresh after completion. Failed projects can retain previous values.

Distinguish accepted/running/completed states and inspect As of/failure notices. Do not treat mixed-time values as all current.

Project selection / Select all / Clear

Select projects to compare; Clear does not delete stored data. Some company-wide metrics are independent of this filter.

Check each widget's company-wide/selected-project basis. Zero selections can show a prompt.

Time / Scope / Resource / Cost

Switch time/scope/resource/cost axes. Cost visibility follows financial access.

If Cost is absent, check ordinary view access and financial access separately.

Signals / table / chart / expand / row drilldown

Change presentation or drill into a project. Read signals with their calculation explanations.

Closing/view switching does not mutate data. Check the same filters/timestamp in expanded views.

Overview

Overview — T/S/R Signals by Project

What it shows: Time / Scope / Resource status per project at a glance (click a row to drill in)

Calculation basis

T diagnoses completion against elapsed schedule; S uses the to-do issue share; R uses project average utilization. Utilization/to-do color boundaries follow current site settings and aggregation values.

How to read it

The Resource (R) signal uses the project's internal average load, which differs from the company-wide utilization distribution (filter-independent). The completion behind Time (T) and Cost (CPI) approximates in-progress issues by effort consumption, so it may differ from actual deliverable completeness. The more red signals, the higher the overall risk.

Filters, access, and notes: Uses the projects selected at the top, within your authorized visibility. Recheck aggregation time after changing the selection.

Time — Schedule

Project Schedule

What it shows: Start–end span with schedule elapsed (blue bar) and completion (green bar) compared in one row, per project

Calculation basis

Top bar = schedule elapsed (start–today, calendar-based; fill edge aligns with the today line). Bottom bar = completion (green, progress from start). Both bars fill relative to the full start–end span.

How to read it

When the green (completion) end is left of the blue (elapsed) end / today line, progress trails the schedule — a delay signal. To the right means ahead of schedule. This is now compared directly on the chart.

Issue Completion vs Progress

What it shows: Completion counted in finished issues next to progress measured in effort, so you can see the difference

Calculation basis

Issue completion = finished issues ÷ all issues. Progress = completion weighted by planned effort, the same number the progress tab shows. Projects with no issues are left out.

How to read it

The wider the gap, the more 'how many are done' and 'how far along are we' say different things. Use it to find the projects where a healthy issue count is misleading.

Problem Issues at a Glance (TOP 50)

What it shows: x=delay days, y=effort diff, bubble=severity

Calculation basis

Severity = delay days × 1 + max(effort diff, 0) × 2 — effort overrun is weighted 2× more than schedule delay (under-spend counts as 0). Shows the top 50 issues across all projects as bubbles.

How to read it

Top-right (high delay and overrun) is riskier; bubble size is severity and grows more with effort overrun. Identify what to address first.

Filters, access, and notes: Uses the global top 50 problem issues from portfolio aggregation; neither the top project selection nor project-scope filtering applies. This cap is not the total problem count.

Calculation basis

Counts members per role (or level) for each project, shown as a stacked bar (y-axis = people).

Utilization

What it shows: Overall (company distribution & overload list) / By project (member utilization)

Calculation basis

Utilization = actual work ÷ available capacity. Numerator (actual) = worklog hours converted to days (MD; 1 MD = one workday's hours). Denominator (available) = workdays in the period (excluding weekends/holidays) minus leave/vacation. 1.0 = 100% (full load). Overall sums each person's project spans without overlap (a shared period counts once — no double counting) for the denominator; by project uses only that project's span.

How to read it

Above 1.0 (100%) means overload; below means slack. Leave is subtracted from the denominator so people on vacation aren't underrated. Overall = 'is this person overloaded company-wide' (sums multiple projects, filter-independent); by project = 'who is overloaded in this project'. Different denominators, different meanings.

Filters, access, and notes: Overall is independent of the top selection; By project uses selected projects. Interpret their different periods and denominators explicitly.

Effort Concentration

What it shows: Effort per person from most to least, so you can see how few people carry the work

Calculation basis

Adds up each person's effort (MD) across the selected projects, sorts from most to least, and builds the cumulative share over everyone. The line above is the share held by the top 20% of people.

How to read it

The sooner the cumulative line reaches 80%, the more the work sits with a few people. If any of them drop out, the schedule feels it right away.

Filters, access, and notes: Uses the projects selected at the top, within your authorized visibility. Recheck aggregation time after changing the selection.

Utilization and Effort

What it shows: Effort carried in the selected projects together with company-wide utilization. Look at the people in the top right first

Calculation basis

The horizontal axis adds up each person's effort (MD) in the selected projects. The vertical axis is company-wide utilization. Band colors follow the same rule as Resource Management and My Page.

How to read it

Top right is someone carrying a lot of work who is also busy everywhere else, so relieve them first. Bottom right carries a lot but still has room, and top left is loaded by other projects.

Filters, access, and notes: Horizontal effort sums selected projects; vertical utilization comes from the overall aggregation. The two axes have different scopes.

Portfolio Cost Summary

What it shows: Total planned labor cost / actual cost / burn rate for selected projects

Calculation basis

Sum planned labor for selected projects; incurred cost sums each project’s planned labor multiplied by elapsed schedule. Burn rate = incurred divided by planned labor. Distinguish these from entered business budgets and actual accounting payments.

How to read it

Read cost progression within the selected scope; do not compare it directly with completion for a different project scope.

Filters, access, and notes: Uses the projects selected at the top, within your authorized visibility. Recheck aggregation time after changing the selection. Unavailable financial data is different from a zero cost.

Cost at Completion

What it shows: What the labor cost adds up to at the end if the current pace holds

Calculation basis

CPI = completion divided by elapsed schedule; when CPI is positive, estimated cost at completion = planned labor divided by CPI. With no elapsed schedule or zero CPI, the current view retains planned labor as a fallback. Equal bars do not establish absence of risk: also check CPI and progress.

How to read it

An at-completion bar above its budget bar means the budget is exceeded if nothing changes. The line on top tells you how much more it costs if you do not act now.

Cost per MD

What it shows: Labor cost divided by the effort actually spent, compared across projects

Calculation basis

Cost per MD = labor cost ÷ effort spent. The reference line divides total labor cost by total effort, which is not the same as averaging the per-project rates. Projects with no effort spent cannot be divided and are left out.

How to read it

Projects above the line are senior-heavy or cost a lot for the effort spent. A high rate is not bad by itself. The question is whether it matches how hard the work is.
