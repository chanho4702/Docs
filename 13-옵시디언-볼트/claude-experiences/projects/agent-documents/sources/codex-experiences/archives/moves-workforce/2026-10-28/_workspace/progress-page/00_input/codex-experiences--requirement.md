- 탭 등록: `static/ui/src/constants/tabs.js`의 `projectDetailTabs` 배열에 최상위 항목 추가

1. 데이터 모델/기존 API 조사 결과 + 추가 필요 엔드포인트 목록

## 핵심 개념 — 진척도 3층 분리 (합치지 말 것)

### 층 1. 공수 진척 — "얼마나 일했나"
- 계획 누적 공수: 일별 예상 진척의 누적
  - 일별 예상 진척 = 전체 계획공수 / (전체 WorkDay × 인원수)
  - 개인 연차·휴일 반영해 일별 보정(가용률)
- 실제 누적 공수: 워크로그 일별 합산 누적
- 의미: 공수 소진 상태(효율/리스크 신호). 완성도 아님.

### 층 2. 완성 진척 — "얼마나 끝났나" (진짜 진척도)
- 완성 진척률 = Σ(이슈 진행률 × 이슈 계획공수) / Σ(이슈 계획공수)
- 이슈 진행률:
  - 완료(Done 카테고리) → 100% 고정 (워크로그가 계획 초과해도 100% 캡, 절대 초과 금지)
  - 진행 중 → 이슈 처리율(%) 그대로
  - 해야 할 일 → 0%
- 의도: 계획공수로 가중. 큰/작은 이슈 동일 취급 금지.

### 층 3. 일정 진척 — "시간이 얼마나 흘렀나" (순수 달력)
- 일정 진척률 = 경과 WorkDay / 전체 WorkDay
- 휴일·주말 제외 근무일 기준. 이슈/공수 무관.
- 층2와 비교해 지연/정상 기준선 역할.

## 진단 규칙
1) 완성(층2) vs 일정(층3): 완성<일정−threshold→지연, ≈→정상, >일정+threshold→앞섬. threshold 기본 5%p, 설정 가능.
2) 공수(층1) vs 완성(층2) 보조: 공수≫완성→비효율/리스크, ≈→효율적, ≪→효율 좋음/과다추정.

## 지연도 처리 (duedate)
- 확정 지연(완료 이슈, 회고): 실제 완료일 = Done AND 마지막 워크로그 작성일. 지연일 = 완료일−duedate. 집계: 평균 지연일/지연 비율/최대 지연.
- 예측 지연(미완료, 추세): 완성 진척 추세 연장 → 예상 완료일. 예측 지연 = 예상 완료일−종료일.
- 한 카드에 "확정/예측" 병기.

## 화면 구성
- A. 진척 종합 헤더: 상태 배지(정상/주의/지연), 완성%/일정%/차이(%p, 양수 초록·음수 빨강), 확정/예측 지연 카드.
- B. 진척 비교 막대: 0~100% 축에 일정/완성(강조)/공수 3개. MD 환산 병기(전체 계획MD, 계획누적MD, 실적기성MD=전체계획×완성률, 실투입MD=워크로그누적).
- C. 진척 추이 S-curve: 계획누적(점선) vs 실제누적(실선), 토글로 완성진척 추이. **작업/인력 분석의 누적 추이 그래프 컴포넌트 재사용**. 오늘 세로선 + 예상완료일 주석.
- D. 상태별 이슈 분포: 가로 누적막대(완료/진행/할일). 개수 기준 / 공수 기준 토글(공수 기준 권장 기본).
- E. 지연·위험 이슈 목록: 기한초과 미완료/처리율 정체/공수편차 큰 이슈. 컬럼: 키/담당자/기한/처리율/지연일수/공수편차. 행 클릭→작업 상세.

## 작업 전 필수 확인
1. 기존 '작업 분석'·'인력 분석' 소스 먼저 읽고 컴포넌트·상태관리·차트·계산로직·스타일 패턴 그대로 따름. 새 패턴 금지.
   - 참조: `static/ui/src/pages/projectDetail/analysisReport/issue/`, `.../resource/`
2. 데이터 모델·기존 API 조사:
   - 이슈별 계획공수(MD)/처리율/상태(Done 카테고리 매핑)
   - 워크로그(이슈 연결/작성일/공수)
   - 프로젝트 시작·종료일/WorkDay 정의/인원수
   - 휴일·개인 연차/가용률
   - 일반 설정의 MM 기준, 1Day 시간
3. 모호/불가 질문 정리:
   - '진행 중' 처리율 데이터 신뢰성/입력 여부
   - 'Done 카테고리' 판정 기준 매핑 명확성
   - 인원수/가용 인원 시점별 변동 반영 방법
   - 처리율 누락 이슈 fallback

## 비기능 요구
- 기간 필터: 인력 분석과 동일 빠른선택(오늘/이번주/이번달/지난주/지난달)+날짜 직접지정 컴포넌트 재사용
- 권한: '권한 관리' 리포트 항목 Read/Write 준수
- 로딩/빈데이터/에러 상태 각각 처리
- 기존 디자인 토큰·컴포넌트·차트만. 새 의존성 금지.
- i18n 체계 준수 (locales/script + merge)
- 계산 기준값(1Day 시간, 1MM 일수)은 일반 설정에서 읽기. 하드코딩 금지.
- 베이스라인 확장 대비: 계획 기준 데이터를 교체 가능 형태로 분리(향후 베이스라인 스냅샷 대비 모드 추가 대비).
