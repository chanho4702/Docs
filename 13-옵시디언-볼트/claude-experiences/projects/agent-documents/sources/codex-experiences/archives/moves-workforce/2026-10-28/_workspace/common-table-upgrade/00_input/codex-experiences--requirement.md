# 요구사항: 공용 테이블 컴포넌트 기능 개선

> 2026-08-12. 사용자 요청 원문 요지: "테이블이 울룩불룩 왔다갔다 한다 / 호버하면 화살표가 뜨는데 정렬이 안 되는데 왜 있냐 / 정렬 기능과 컬럼 너비 조절을 모든 테이블 공통으로 개선해 달라"

## 확인된 사실 (사전 조사)

- 공용 테이블: `static/ui/src/components/table/` — `CommonTable`(Atlaskit DynamicTable 래퍼), `PagingTable`, `CursorPagingTable`, `TreeTable` + `table.css`
- **정렬 무동작 원인**: DynamicTable은 **행 셀의 `key`를 정렬 값**으로 사용한다. 그러나 호출부 대부분이 셀 `key`에 컬럼 식별자('check','project' 등 행마다 동일한 값)를 넣는다 → `isSortable` 컬럼은 화살표만 뜨고 클릭해도 순서 불변.
  - `isSortable: true` 사용처: myPage(MyWorklogPanel, MyIssuesPanel), resource/teamAnalytics/charts 5개 등. 이들 중 실제로 동작하는 곳/안 하는 곳을 설계 단계에서 전수 판별할 것.
- **폭 출렁임 원인**: `table-layout: auto` + 컬럼 width 미지정이 대부분 → 페이지 전환·데이터 갱신 때마다 내용 기준 재계산. `isFixedSize` prop은 있으나 기본 false에 사용처 드묾. head `width` 지정도 일부 테이블뿐.
- **컬럼 리사이즈**: DynamicTable 미지원 — 커스텀 필요.

## 요구사항

1. **폭 안정화 (울룩불룩 제거)**: 페이지 전환·데이터 갱신·호버 시 컬럼 폭이 출렁이지 않게 한다. 공용 레벨에서 해결(호출부 전수 수정 최소화).
2. **정렬 실동작**:
   - 정렬 가능한 컬럼은 클릭 시 실제로 정렬된다.
   - **정렬이 동작하지 않는 컬럼에는 화살표(정렬 어포던스)가 뜨지 않는다** — "기능 없는 화살표" 제거가 사용자 불만의 핵심.
   - 호출부가 셀에 정렬 값을 주는 계약(예: `sortValue`)을 정의하되, **하위 호환**: 기존 호출부는 무수정으로 최소한 현행 표시 유지(화살표만 정리돼도 됨). 대표 화면 몇 곳은 새 계약으로 마이그레이션해 실동작을 보여준다.
3. **컬럼 너비 드래그 조절**: 헤더 경계 드래그로 사용자 폭 조절. 공용 레벨 1회 구현으로 4종 테이블 전체 적용. (영속화(localStorage)는 설계 판단 — 필수 아님, 과잉 금지)
4. **공통 적용 범위**: CommonTable을 직접/간접(P/C/Tree) 쓰는 모든 화면. 개별 화면 커스텀 코드 없이 공용에서 처리.

## 제약 (프로젝트 규약)

- Atlaskit DynamicTable 유지가 기본. 교체(자체 table 구현)는 비용·회귀 위험 평가 후 명확한 이득이 있을 때만 설계로 제안.
- 신규 외부 의존성 지양(번들 예산 gzip 950KB, 현재 895KB). react-table 등 도입은 금지 수준으로 신중히.
- 스피너 금지·스켈레톤 유지, RFC-178 공용 지점 원칙(수정은 components/table 안에서).
- 폰트 굵기 수렴(2026-08-11) 직후이므로 th 600 등 기존 스타일 계약 유지.
- 백엔드 변경 없음(프론트 전용). i18n 신규 키 필요 시 kr/en + merge 규약.
- 다크 테마: table.css는 전부 `--ds-*` 토큰 — 신규 스타일도 동일 원칙.

## 검증 포인트

- 정렬: 정렬값 있는 컬럼 클릭 → 오름/내림 토글 실동작, 정렬값 없는 컬럼 → 화살표 미노출
- 폭: 페이지 전환 시 컬럼 폭 불변(대표 화면 2~3곳), 리사이즈 후 페이지 전환에도 유지
- 리사이즈: 드래그로 폭 변경 가능, 최소 폭 보호, TreeTable·CursorPagingTable에서도 동작
- 기존 호출부 무수정 화면들이 깨지지 않음(스냅샷/렌더 테스트 + 빌드)
- 번들 예산 통과
