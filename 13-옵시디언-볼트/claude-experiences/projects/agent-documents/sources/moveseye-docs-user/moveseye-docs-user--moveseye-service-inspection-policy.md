# 무브스아이(MovesEye/DMOVE) 서비스 점검 정책 (초안 v0.1)

> 작성일: 2026-06-18 · 상태: 초안(Draft) · 검토 필요
> 대상 서비스: Zabbix 기반 인프라 모니터링 대시보드 (NestJS BE + React19/Vite FE)

---

## 1. 목적과 범위

본 정책은 무브스아이 서비스의 가용성·안정성·보안을 유지하기 위한 **정기·비정기 점검 기준과 절차**를 정의한다.
무브스아이는 일반 웹서비스와 달리 **외부 Zabbix 서버에 종속된 프록시형 모니터링 솔루션**이며, 운영 환경이 비표준적(프로덕션 watch 모드, 부팅 시 자동 마이그레이션, 외주 인프라 호스팅)이라는 특성을 전제로 점검 항목을 설계한다.

### 점검 대상 구성요소
| 계층 | 구성요소 | 비고 |
|------|----------|------|
| 프론트엔드 | React19/Vite 정적 빌드(dist) | 웹서버 서빙 |
| 백엔드 | NestJS 10 (포트 3000) | **프로덕션도 `start:dev`(watch) 구동** |
| 데이터 | PostgreSQL(노출 3410), Redis(노출 3411) | 부팅 시 TypeORM 마이그레이션 자동 실행 |
| 외부 의존 | **Zabbix 서버(JSON-RPC)**, AWS(EC2/CloudWatch), Firebase/Twilio/Novu/Mail | Zabbix는 핵심 SPOF |

---

## 2. 서비스 특성에 따른 핵심 리스크

점검 항목은 아래 구조적 리스크에서 도출한다.

1. **Zabbix 단일 장애점(SPOF)** — 메트릭 원천이 외부 Zabbix. Zabbix 연결/인증 실패 시 무브스아이 전 기능 마비.
2. **프로덕션 watch 모드 운영** — dist 빌드 파이프라인 부재. 메모리 누수·watch 프로세스 다운 위험 상존.
3. **부팅 시 자동 마이그레이션** — 재시작이 곧 스키마 변경. 마이그레이션 실패 시 기동 불가.
4. **외주 인프라(savvycom.xyz)·prod 정의 부재** — 운영 책임 경계 모호, dev/qa만 CI 자동 배포.
5. **시크릿 평문 커밋(.env.*)** — 자격증명 노출 상태 상시.
6. **그룹 기반 접근제어(user-group ↔ host-group)** — 권한 오설정 시 모니터링 데이터 부적절 노출.

## 3. 점검 정책: 3계층 + 주기 분리

### L1 — 일상 점검 (매일 / 가급적 자동화)
| 항목 | 기준 | 비고 |
|------|------|------|
| BE 프로세스 생존 | 포트 3000 응답, `/api`(Swagger) 도달 | watch 프로세스 다운 감지 |
| BE 메모리/CPU | 임계치 초과 알림 | watch 모드 누수 대비 |
| PostgreSQL / Redis | 연결 정상(3410/3411), 복제·메모리 | |
| **Zabbix 연결성·인증** | JSON-RPC 응답, sessionid(authToken) 유효 | **독립 항목 필수** |
| 디스크 사용량 | 임계치 경보 | 로그·DB 증가 대비 |
| 에러로그 급증 | 비정상 패턴 알림 | |
| 자기 모니터링 | 무브스아이 호스트를 Zabbix에 등록해 self-monitoring | 권장 |

### L2 — 주간 점검 (수동)
| 항목 | 기준 |
|------|------|
| 배포 정합성 | dev/qa 브랜치-서버 버전 일치, 의도치 않은 재시작 여부 |
| 자동 마이그레이션 이력 | 최근 적용 마이그레이션·실패 여부 점검 |
| 시크릿/인증서 만료 | JWT·외부 API 키·도메인 인증서 |
| 백업 복구 테스트 | DB 백업 존재 및 복구 가능성 |
| 권한 이상치 | user-group↔host-group 부여 적정성 |

### L3 — 분기 점검
| 항목 | 기준 |
|------|------|
| 의존성 버전·EOL | Zabbix·AWS SDK·Node·주요 패키지 |
| 용량/부하 산정 | 호스트 수 증가 대비 |
| 보안 점검 | 시크릿 분리·키 로테이션 진행도(아래 4항) |

---

## 4. 배포·재시작 시 강제 절차 (자동 마이그레이션 대응)

무브스아이는 **재시작 = 스키마 변경 가능**이므로 다음을 절차로 강제한다.
1. 재시작/배포 전 **DB 백업** 확보.
2. 추가된 마이그레이션 파일 **사전 리뷰**.
3. 재시작 후 **마이그레이션 적용 결과 + 기동 성공** 확인.
4. 실패 시 **백업 복구 + 롤백** 경로 명시.

---

## 5. 보안 점검 (시크릿 노출 대응)

`.env.example`/`.env.dev`/`.env.qa`에 운영 자격증명(JWT·Zabbix·AWS·Firebase·Twilio·Novu·AES/RSA 키)이 평문 커밋되어 있음.
- 점검 항목: **키 로테이션 주기, 시크릿 분리(.env → 비밀관리도구) 진행 현황**.
- 우선순위: Zabbix 운영 계정·JWT secret·클라우드 키.

---

## 6. 선결 과제 (정책 확정 전 채워야 할 빈칸)

1. **운영 책임 RACI** — 무브스아이 팀 vs 외주(Savvycom)의 점검·장애대응 책임 경계.
2. **prod 환경 정의** — 현재 레포에 dev/qa만 존재. 운영 환경의 배포·점검 기준 부재.
3. **알림 채널** — 점검 이상 시 통보 경로(Jandi/메일 등) 확정.
