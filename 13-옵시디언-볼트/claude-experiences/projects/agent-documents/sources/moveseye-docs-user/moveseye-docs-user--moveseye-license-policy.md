# 본문 — OSS 컴플라이언스 정책

## 1. 배경: 무브스아이의 라이선스 종속 구조

무브스아이는 자체 코드(BE/FE)와 다수의 오픈소스 의존성으로 구성되며, **핵심 메트릭 원천인 Zabbix가 7.0부터 AGPLv3로 전환**되었다는 점이 라이선스 정책의 결정적 변수다. (Zabbix 6.4까지는 GPLv2 / 7.0부터 AGPLv3)

AGPLv3는 *네트워크를 통해 서비스를 제공*하는 경우에도 **수정본 소스코드 공개 의무**가 발생하는 강한 카피레프트 라이선스다.

## 2. 컴포넌트별 라이선스 현황

| 컴포넌트 | 라이선스 | 영향 / 조치 |
|----------|----------|-------------|
| **Zabbix 7.0** | **AGPLv3** | 최대 리스크. 무브스아이는 **수정 없이 JSON-RPC API로 호출만** 함 → 통상 "별개 저작물(aggregation)"로 해석되어 무브스아이 소스 공개 의무는 발생하지 않을 가능성이 높음. **단, Zabbix를 패치·번들·재배포 시 의무 발생** |
| **Mapbox GL JS v2+** | **독점(Mapbox TOS)** | v2부터 BSD → 독점 전환. 유효한 Mapbox 토큰·계정 필수. 오픈소스 아님 |
| MapLibre GL | BSD-3-Clause | Mapbox 대체용 오픈소스. 이미 의존 중 → 일원화 후보 |
| React / Ant Design | MIT | 관대, 문제없음 |
| ECharts | Apache-2.0 | 관대(특허조항 포함) |
| 기타 npm/yarn 의존성 다수 | 혼재 | SBOM·자동 스캔으로 관리(아래 3항) |

## 3. 컴플라이언스 3원칙 (정책 본문)

### 원칙 1 — Zabbix 격리
- Zabbix는 **수정·번들 금지**, **외부 서비스로 분리 운영**하고 JSON-RPC API로만 소비한다.
- Zabbix 소스에 패치가 필요하면 사전 법무 검토 필수(AGPL 전이 위험).

### 원칙 2 — 지도 라이브러리 일원화
- Mapbox GL JS(독점, 토큰·과금·TOS 관리 필요)와 MapLibre(오픈소스) 중 **택1을 명문화**한다.
- 라이선스 리스크 제거를 우선한다면 **MapLibre로 일원화** 권장.

### 원칙 3 — SBOM·자동 스캔
- `yarn licenses` / `license-checker` 등으로 의존성 라이선스 목록(SBOM)을 산출·관리한다.
- CI에 **copyleft(GPL/AGPL/LGPL) 신규 도입 자동 차단(또는 경고)** 규칙을 추가한다.

## 4. 운영 룰

1. 신규 의존성 추가 시 라이선스 확인을 PR 체크리스트에 포함.
2. 분기 1회 SBOM 갱신 및 copyleft 유입 점검.
3. 고객 납품/배포 형태 변경 시 본 정책 재검토(특히 Zabbix 동봉 여부).

# 부록 — 제품 라이선싱 모델 (사업 선택)

무브스아이 자체(우리 코드)를 고객에게 어떤 형태로 제공할지는 **본문의 Zabbix 격리 원칙에 묶인다.**

| 모델 | 적합성 / 주의 |
|------|---------------|
| **SaaS 구독** (우리가 호스팅) | Zabbix를 우리가 미수정·분리 운영하면 깔끔. 현재 외주 인프라 구조와 정합. **권장 기본형** |
| **온프레미스 납품(상용 클로즈드)** | 가능하나 **Zabbix를 함께 패키징하면 AGPL 전이 위험** → Zabbix는 "고객이 별도 설치" 또는 미수정 분리 배포 |
| 오픈소스 공개 | 우리 코드는 자유롭게 가능하나 사업 모델상 비권장 |

> **요지:** 어떤 모델을 택하든 **무브스아이 자체 코드는 상용/클로즈드로 보유 가능**하나, **Zabbix를 동봉·수정하지 않는 한**에서만 성립한다.
