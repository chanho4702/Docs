## 1. APM으로 무엇을 보나 — 봐야 하는 것 · 볼 수 있는 것 · 우리가 해결한 것

> 이 장을 읽으면: ① 운영자가 상황별로 **어느 메뉴·탭·지표를 먼저 봐야 하는지**, ② 우리 APM이 **볼 수 있는 것 전부와 못 보는 것**, ③ 고객 관점에서 "전에는 못 했는데 지금은 되는 것"이 무엇이고 **화면에서 어떻게 확인하는지** 알게 된다. 메뉴·탭의 뜻 자체는 [4.5절](solutions--05-menus-and-tabs.md) 사전에 있다.

### 1.1 봐야 하는 것 — 상황별 체크리스트

### 1.2 볼 수 있는 것 — 전체 목록

**핵심 지표 6종 커버리지**(설계 §14 — 사용자 필수 요건) + 같은 급으로 다루는 지표:

| 지표 | 어디서 오나 | 어떻게 보이나 | 단계 | 한계 |
|---|---|---|---|---|
| **응답 시간**(p50/p95/p99) | `http.server.request.duration` 히스토그램 | 서비스 개요 3선+밴드·분포 히트맵·엔드포인트 표·산점도 | P1(산점도 P2) | 버킷 보간값. `mixedBounds`면 `—`. route 없는 프레임워크는 `__other__` |
| **처리량(TPS)** | 같은 히스토그램 `count`/Δt | 개요 StatCard·서비스 area·엔드포인트 rps·실시간 rps | P1 | 배치·메시징 처리량은 P3 메시징 화면 |
| **에러율** | `status_class=5xx` 비율(+스팬 ERROR) | 오류율 line+임계선·상태코드 stacked·예외 그룹 | P1(그룹 P2) | 4xx 제외(설계상 의도) |
| **트랜잭션 추적** | OTLP traces(tail 샘플링) | 워터폴·크리티컬 패스·플레임·비교(BE만) | P2 | 프레임워크 경계까지. 메서드 스팬은 Java `methods.include`. 정상 2% 표본 |
| **액티브 트랜잭션** | `http.server.active_requests` | 개요 area·실시간·`ACTIVE_REQUESTS_SPIKE` 알람 | P1 | Java만 실측 ✅, Node·Python은 "계측 미제공" |
| **DB 연결·쿼리** | 풀 메트릭(HikariCP) + `db.client.operation.duration` + 스팬 `db.query.text` | 런타임 탭 풀 stacked+대기 p95 · DB 호출 분석(정규화 SQL·총 소요·흐름도) | 풀 P1·쿼리 P2 | 파라미터 값은 기본 마스킹(`?`). 앱이 잰 시간(커넥션 대기 포함) |
| **가용성** | 5분 칸 판정(UP+DEGRADED ÷ 판정 칸) | 24h 띠·목록 %·리포트 | P1 | UNKNOWN·보존 밖은 분모 제외. DOWN은 합성 감시만 |
| **Apdex** | 히스토그램 보간, T=0.5s 기본 | 개요 게이지 | P1 | T는 초 단위(다른 건 ms) |
| **포화도** | active_requests·풀 pending·JVM 힙/GC/스레드·process CPU | 런타임 탭·실시간 액티브 | P1 | 비-JVM 런타임 슬롯은 표만 |

**그 위에 볼 수 있는 것**: 서비스 맵(서비스/DB/외부/큐 토폴로지, P2) · 에러 그룹(지문·첫/마지막·스택, P2) · 외부 호출(대상별 지연·오류·타임아웃, P2) · 배포 마커·전후 비교·신규 예외(자동 감지+웹훅, P2) · SLO(가용성/지연 SLI·에러 버짓·번 레이트 4창·캘린더·번 알람, P3) · 합성 감시(Zabbix 웹 시나리오 CRUD·24h 가용성·단계별 응답·30일 캘린더, P3) · 메시징(큐/토픽 처리량·소비 지연)·배치(실행 이력·간트, P3) · 주간/월간 리포트(P3) · 홈 위젯 3(P3) · AI 원인 브리핑·툴 11·'/' 명령 5(P3) · RUM(페이지별 PV·세션·LCP/INP/CLS/TTFB/FCP·timing 평균·JS 오류·브라우저→백엔드 트레이스, P4) · K8s(파드/노드/네임스페이스·재시작·OOM 배지, P4) · 수집기 상태·폐기 통계·설치 가이드·알람 규칙 5종+Zabbix 진단(P1) · **실시간 관제**(요청 관제 — TPS·p95·오류율 속도계 3종·서비스 이퀄라이저·동시 요청 타일·관제실 벽 모드 / X-View — 완료 스팬 스트리밍 산점도·상시 "표시 n / 관측 m" 배지·브러시→표·패턴 라벨 / 비동기 워터폴 확장 — 링크 팝오버·부모 종료 이후 마커, **P5** — 요청 관제·X-View는 기본 전부 꺼짐·출시 게이트 다수 잔여, 비동기는 ✅ 출시 게이트 PASS, [18-p5-realtime.md](solutions--18-p5-realtime.md)).

**볼 수 없는 것**(비범위 — 소개서에 그대로 쓰는 문장): 세션 리플레이·입력값 수집 · 코드 프로파일링(메서드 단위 CPU/메모리) · 로그 상관("이 요청의 로그" — 로그 도메인 설계 선행, 미착수) · 상용 APM 에이전트(Datadog·New Relic 등) 호환·외부 APM 읽기 연동 · 모바일 RUM · Go 등 자동계측 없는 스택의 코드 수정 0 · SaaS · 인프라 메트릭 대체(Prometheus/hostmetrics — 수집 엔진 몫) · 통계적 이상 탐지 엔진(AI 툴은 대화형 좁히기) · Collector 운영 대행 · 트레이스 전량·무기한 보존(7일, 정상 2%) · 🔴 **진행 중인 요청 목록·초당 유입 곡선**(P5 — 스팬은 끝나야 export되어 원리적으로 안 됨. 시작 이벤트가 있어야 되는 P5.3b는 제품 지원 결정 대기, [18-p5-realtime.md](solutions--18-p5-realtime.md) §10.5) · 다중 BE 노드 합산 실시간 관제(라이브 상태가 한 프로세스 인메모리라 첫 배포는 BE 1대 전제).

### 1.3 우리가 해결해 준 문제 — "전에는 못 했던 것 → 지금은"

| 고객의 질문(전에는) | 지금은 | 어떻게 확인하나(클릭 경로) |
|---|---|---|
| "코드 안 고치고 붙일 수 있나" — 상용 APM은 에이전트·계정·비용, Zabbix는 호스트만 | **OTel 자동계측 한 줄 + Collector 1바이너리**(우리 yaml 생성) → 60초 안에 서비스가 목록에 자동 등록 | 수집기 › 토큰·설정 › 발급(+yaml) → 설치 가이드(OS×스택) → 앱에 `-javaagent` 한 줄 → 상태 탭 "최근 60초 수신" → 서비스 목록에 나타남 |
| "사내 Jira가 지금 느린가" — 호스트 CPU로는 모른다 | **서비스 단위** 상태 5종·RED·Apdex·가용성, 5분 판정 근거 툴팁 | 서비스 목록 상태 칩 → 배지 툴팁("p95 2400ms > 2000ms") → 상세 개요 탭 |
| "느린 API가 **어느 SQL** 때문인가" | 트레이스 워터폴 크리티컬 패스 + DB 쿼리 그룹(총 소요 정렬·정규화 SQL·예시 트레이스) | 서비스 상세 트랜잭션 탭에서 느린 route 클릭 → 트레이스 탭 산점도 위쪽 점 → 워터폴 굵은 행(자기 시간 최대) / 또는 DB 호출 분석 '총 소요' 1위 → 쿼리 상세 → 예시 트레이스 |
