## 구현 순서 권고

1. 먼저 설계 v2에서 logical run 상태를 확정한다: full/incremental 분리, `runId`, high-water, next cursor, query fingerprint, checkpoint 원자성, head scan 정책.
2. `AlertPort`/`AlertScanOutcome`에 opaque continuation과 consumer 예외 계약을 추가하고, `ZabbixQueryExecutor`가 초기 cursor·고정 upper bound·다음 cursor를 반환하도록 만든다.
3. problem/trigger/user 보강이 공유하는 호출·시간 budget을 구현한 뒤 adapter의 경량 `scanActive`부터 완성한다.
4. `event_sync_run`과 run marker, 후보 cursor, 정렬에 맞는 partial composite index를 additive migration으로 추가한다. 첫 NULL bootstrap 및 online index 배포 방식을 함께 확정한다.
5. 페이지 단위 트랜잭션으로 사건 반영·읽음 반영·checkpoint 전진을 묶는다. 먼저 full consumer를 구현하고, 이후 기존 의미를 보존한 incremental consumer를 연결한다.
6. full mark&sweep과 incremental new-head 경로를 분리한다. sweep·좀비 정리·건강 카운터는 logical full 완료에서만 실행한다.
7. broadcast는 UI-visible 변경과 marker/checkpoint 변경을 분리해 회차당 최대 1회로 고정한다.
8. 마지막으로 동적 Zabbix 결과, 첫 NULL 수백만 건, 중간 실패/재시작, 두 인스턴스·lease 만료, 실제 규모의 SQL 실행계획과 WAL 부하를 검증한 뒤 feature flag로 단계 배포한다.
