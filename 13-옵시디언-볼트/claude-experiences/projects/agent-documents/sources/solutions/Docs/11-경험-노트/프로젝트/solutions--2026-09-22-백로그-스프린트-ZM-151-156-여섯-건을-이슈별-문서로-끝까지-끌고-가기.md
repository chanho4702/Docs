## 핵심 결정 (Decisions)
- **BE는 이슈마다 격리 워크트리** — IntelliJ BE(:3000)가 master `build/classes`를 공유해 돌아서 master에서 빌드하면 실행 중 JVM이 깨진다. 병합은 master ff.
- **인스턴스 스냅샷은 중복 제거 금지** — 회차당 한 행이 추정 비용 가동시간·플릿 추이의 근거. VPC만 구간 적재로 바꿨다.
- **내보내기 상한 초과는 파일 시작 전 거절**(계획 EP `allowed=false`) — 조용히 잘린 감사 파일은 "그 뒤론 아무 일도 없었다"로 읽힌다. 경합 절단은 파일 끝 표지.
- **내보내기 원문은 항상 마스킹 기본** — 화면 규칙(`keep_raw_sql=false`면 저장값 그대로)에 "켰다 끈 설치본" 틈이 있어 파일에는 안 씀. 틈 자체는 별도 이슈 권고.
- **실패 응답은 파일이 아니라 기존 JSON envelope(HTTP 200)** — FE는 blob `Content-Type`으로 판정. 09-22 curl 실측으로 확인.

## 겪은 문제 & 해결 (Troubleshooting)
- **마이그레이션 번호 충돌**: 151의 V60이 master의 V60~V63과 겹침 → 어느 DB에도 V60 미적용 확인 후 **V64로 재번호**. 보고서 본문의 "V60"은 V64로 읽는다고 머리에 명시.
- **다른 커밋이 내 파일을 먼저 가져감**: ZM-122 커밋이 152의 파일 일부·번역 줄을 먼저 담아 master가 **미추적 모듈을 import** → 새 체크아웃 빌드 실패. 152 커밋이 그 모듈까지 담아 해소.
- **공유 IT DB 충돌**: 다른 워크트리가 같은 시각에 IT를 돌려 `moveseye_it`이 겹치면 중복 키·컬럼 없음으로 **가짜 실패 9건**. 단독 재실행에서 통과. 워크트리별 IT DB 분리가 근본 해결(미착수).
- **Docker 꺼지면 IT가 조용히 skip**(시간 0) → `IT_DB_URL` 명시 + `:cleanTest`.
- **FE master에 원래 있던 테스트 실패**: v2가 지운 함수를 옛 테스트가 참조. 테스트 폴더는 tsc 대상이 아니라 타입체크로는 안 걸린다.
- **세션 장애 후 인수**: 보고서가 "master 병합 `39ece8e`"라고 적혀 있어도 **git 실물·파일 존재·테스트 재실행**으로 다시 확인했다(전부 일치).
- **코덱스 승격 샌드박스 오류**: 모든 셸 호출이 `setup refresh had errors`로 거부되어 검수가 "판정 불가"만 냄 → `-c windows.sandbox='"unelevated"'`로 우회(설정 파일 무수정). "판정 불가"는 검수가 아니라 환경 오류다.

## 교훈 (Lessons)
- **상태 보호(dirty guard) 기능은 이탈 경로를 먼저 표로 열거하라** — 클릭·브라우저 POP·강제 전환(라이선스)·언마운트·재조회·원격 변경. FE 검수 5회 왕복이 전부 "같은 R2의 다른 경로"였다.
- **런타임 실측은 재기동 없이도 가능할 수 있다** — 실행 중 프로세스의 기동 시각·`build/classes` 타임스탬프를 병합 시각과 대조하면 "이미 병합본이 떠 있다"를 알 수 있다. 154 BE는 그렇게 재기동 없이 curl로 확인했다.
- **실측이 통과해도 검수는 경계 조건을 잡는다** — curl 실측은 전부 정상이었지만 코덱스는 미래 `to`의 요청별 재절단(계획↔파일 불일치), 10분 다운로드 중 계정 전환, 취소가 요청을 중단하지 않는 것을 잡았다. 정상 경로 실측과 경계 조건 검수는 대체 관계가 아니다.
- **인덱스 문서는 갱신 날짜를 머리에** — 세션이 끊기면 다음 사람이 어느 문서가 낡았는지 그 한 줄로 가른다. 계약서·설계서 머리의 "미커밋·FE 미착수"가 그대로 남아 있던 것이 이번 인수의 첫 정리 대상이었다.
