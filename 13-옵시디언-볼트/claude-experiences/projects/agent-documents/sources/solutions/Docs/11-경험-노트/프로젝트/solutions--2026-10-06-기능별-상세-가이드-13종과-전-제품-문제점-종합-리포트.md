## 결과

- 문서 13종 약 12,200행, 기능 절 197개, 문제점 309건(높음 28·중간 161·낮음 120, 영역 간 중복 포함).
- 높음 28건은 핵심 근거 코드를 다시 열어 확인했다. 런타임 재현은 0건이다.
- 눈에 띈 것: 홈 위젯 서비스의 트랜잭션 우회(`new`로 본체 생성), 스왑 차트 단위 뒤바뀜, 호스트·그룹 수정의 Zabbix 전체 교체 위험, OAuth redirect 스킴 대소문자, `spring.mail.*` 매핑 소실, 알람 이름 255자, 비용 내보내기 100행 절단.
- 기존 `guides/pages/` 화면별 가이드 대부분이 08-11 기준이라 메뉴·주소·탭이 현재와 다르다는 것도 함께 드러났다.

## 교훈

- **영역을 나눠 병렬로 읽히면 깊이가 나온다.** 한 에이전트가 영역 하나의 화면→API→서비스→배치를 끝까지 따라가게 하고, 문서 형식·증거 수준 표기·금지 사항을 공통 지침 파일 하나로 주면 13개 결과물의 구조가 맞는다.
- **"높음"은 받은 그대로 믿지 않고 근거 행을 다시 연다.** 28건 모두 서술과 코드가 맞았지만, 그 확인이 있어야 종합 리포트에 올릴 수 있다. 중간·낮음까지는 못 했으므로 그 사실을 문서에 적었다.
- **코드 경로는 기계로 검사한다.** 링크·경로·행 번호 실존 검사와 생략 경로 펼치기를 스크립트로 돌리니 사람이 못 보는 깨짐(대괄호+괄호가 링크로 해석되는 표기, 잘못된 패키지 경로)이 잡혔다.
- **리팩터링이 어댑터를 남길 때 프록시 경계를 본다.** "기존 단위 테스트를 살리려고 본체를 직접 생성"한 선택이 트랜잭션을 조용히 벗겼다. 리포지토리를 대역으로 바꾼 단위 테스트는 이 종류를 못 잡는다.
- **설정 파일의 무관한 줄 삭제는 주제가 다른 커밋에 묻힌다.** 메일·Zabbix 매핑이 AWS 커밋에서 빠졌다. 설정 파일 diff는 커밋 주제와 따로 본다.
- **의도된 설계와 결함을 구분해 적는다.** 서비스 계정 토큰 실행, 권한 축 없는 조회는 결함으로 단정하지 않고 "결정 필요"로 분류했다.

## 코덱스 의견과 재개 지점 (같은 날 추가)

리포트에 대한 독립 의견을 코덱스에 요청했다(읽기 전용, 약 13분). 높음 28건 중 동의 20·부분 동의 7·반대 1, 중간 표본 26건 중 틀림 0.

- 반대 1건(APV-01)은 작성 중에 BE가 움직여 이미 해소된 것이었다 — 문서는 `e55948c` 기준인데 끝날 때 HEAD는 `22eeff8`.
- "결정 필요"로 적은 8개 중 5개는 계약서·설계서·ADR에 이미 결정이 있었다. 영역 문서에는 "의도된 예외"로 적혀 있었는데 종합 단계에서 뭉뚱그렸다.
- 수정 묶음은 DB 마이그레이션·보안 핫픽스·API 설계가 섞여 있어 나눠야 한다.
- 사용자 결정: **지금은 착수하지 않고 기록만.** 재개 지점은 `C:/solutions/_workspace/planning/backlog_product-gap-2026-10-06.md`, 코덱스 의견 전문은 `_workspace/reviews/review_feature-guides-2026-10-06_codex.md`.

추가 교훈

- **종합 전에 결정 기록을 검색한다.** "의도인지 모르겠다"는 대개 계약서에 답이 있다. 결함·승인된 위험 설계·조건부 한계·미확인 추론을 중요도 표에서 섞지 않는다.
- **긴 작업은 끝날 때 기준 커밋을 다시 본다.** 병렬 조사 40분 사이에 다른 세션이 두 번 커밋했다.
- **"한 번에 수정" 목록은 변경 종류로 다시 나눈다.** 화면 표시 수정, DB 마이그레이션, 보안 핫픽스, API 계약 변경은 배포·검수 단위가 다르다.
