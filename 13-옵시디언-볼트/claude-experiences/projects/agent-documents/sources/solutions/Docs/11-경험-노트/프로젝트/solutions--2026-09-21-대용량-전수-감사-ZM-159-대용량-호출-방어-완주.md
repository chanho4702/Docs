## 결정과 이유

- **호출 예산은 전역 정책 하나**(`zabbix.call.policy.{method}.*`, 요청별 확대 금지). 사용자 방향 "과하게 하지 말 것"과 일치 — 대용량 방어의 목적은 1회 호출 크기 통제이지 전량 수집 지원이 아니다.
- **C5 핵심 4개(전부 코덱스가 차단으로 잡음)**: ① **1콜 행 상한 < 보유 상한**이어야 쪼개 완주 가능(같으면 "한 조각이 넘쳤다 = 이미 상한 초과") → history.get 10만→**1만**, 기동 시 검증 ② **정책 창과 행 상한은 짝** — `200개 × 3,000초 ÷ 1분 = 1만 행` ③ 실행기의 **확정 전 창 버퍼도 예산에**(`maxWindowRows`를 `IntSupplier`로, 전달한 페이지는 즉시 `set(i,null)`) → [[topics/backend/moveseye-history-scan-held-budget|moveseye-history-scan-held-budget]] ④ **분할은 기존 소비자를 깨뜨린다** — `ItemsService`는 "응답이 정확히 10만이면 잘림"으로 판정, `HostService`는 DESC로 최신 구간 유지 → 레거시 API는 1콜 그대로, 분할은 새 API에만.
- 응답 상한 16MiB로의 축소는 대규모 힙 실측 전이라 **64MiB 유지**(보류).
- 🔴 배포 주의: 외부 설정에 `history.get.max-rows=100000`을 고정한 환경은 `max-history-rows`와 함께 조정해야 기동 — 09-21 사용자 확인 결과 **그 설정 자체가 어디에도 없음**(전부 기본값) → 배포 위험 없음.

## 함정·교훈

- 🔴 **기계 변환 정규식이 변이를 "생존"으로 오판** — ① 대입문 연속 줄을 exec로 ② `\s*$`가 뒤 빈 줄을 삼킴 ③ sed가 한글·이모지 패턴을 못 맞춤 → python 치환 + `cmp`로 변경 확인. 변이 검사 "실패"가 컴파일 오류일 수도 있다 — 결과 XML로 사유 확인.
- 🔴 교착 테스트는 `@Timeout(threadMode=SEPARATE_THREAD)`+기한 있는 get(안 그러면 워커가 영구 정지). `timeout N ./gradlew test`로 끊으면 클라이언트만 죽고 데몬이 계속 돌며 **빈 결과 XML**을 남긴다 — 전체 테스트는 시간 제한 없이 백그라운드, 집계 전 `build/test-results` 비우기.
- 🔴 `MetricPort` default 메서드에 람다 금지(합성 private static을 `LicenseGuardedPortTest`가 리플렉션 호출해 깨짐) · ArrayDeque null 원소 NPE · lenient 스텁 재스텁은 `doThrow().when()` · `expectedRows` 곱셈 오버플로 → `multiplyExact` 포화 · python 문자열 `\u0000`이 실제 NUL로 · `cat > 파일`을 heredoc 앞에 두면 stdin 대기.
- 🔴 **다중 세션**: master가 분 단위로 앞선다 → **커밋 전 리베이스 + ff 병합**이 기본. 마이그레이션 번호는 선점당한다(V62 충돌 → V63). 공유 IT DB는 다른 세션 미커밋 마이그레이션·연결 고갈로 깨진다 → [[topics/backend/shared-it-db-worktree-collision|shared-it-db-worktree-collision]]. `codex exec`는 git 저장소 안에서만(`C:/worktrees`는 거부).
- FE 워크트리 `git worktree remove`가 "Invalid argument" → PowerShell `Remove-Item -Recurse -Force` 후 `worktree prune`.
