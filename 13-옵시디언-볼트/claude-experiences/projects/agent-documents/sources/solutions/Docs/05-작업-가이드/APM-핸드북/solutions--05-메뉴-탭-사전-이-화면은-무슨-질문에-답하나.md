### 4.5 메뉴·탭 사전 — 이 화면은 무슨 질문에 답하나

> 화면마다 **어떤 질문에 답하나 / 무엇이 보이나 / 데이터는 어디서 오나 / 언제 여나 / 함정** 다섯 칸. 문구 근거는 FE 도움말 원문 `kr.json` `page_guide.apm_*`(화면 제목 옆 `?`에 뜨는 그 글)과 `guides/apm-screen-chart-guide.md` §2, 라우트는 `constants/routes.ts` `PATH_APPLICATION_MONITORING`, 탭 정의는 `constants/apm.ts`. 전부 `/application-monitoring` 아래에 있고 `FeatureGate("APM")` + `permissionKey apm`(view)이 지킨다.

#### 4.5.1 사이드바 메뉴 9개

> 🔴 **개수 정정(2026-09-16~17)**: 이 절이 처음 쓰일 때는 7개였다. ① 09-16 **SLO가 사이드바에 노출**되면서(FE `3a09b33` — 화면과 라우트는 있는데 메뉴에 없어 주소를 직접 쳐야 열리던 것) 8개가 됐다(`SideNav.tsx:331~409` 실사 — 계약서 `contract_apm-p5-live.md` §6-J·§7.3이 잡아낸 오계수). SLO는 **헤더 ⚙ 설정에서도 그대로 열린다**(두 곳에서 열림 — 사용자 결정)이므로 화면 사전은 [4.5.4](#454-설정--메뉴에서-여는-화면-2개)에 그대로 두고 여기서는 개수만 정정한다. ② 2026-09-17 P5.2가 더하는 **실시간 관제**가 FE `master`에 병합되며(`4e4062f`) **현행 9개**가 됐다 → [4.5.1b](#451b-실시간-관제--p52p53). 🔴 다만 기본값이 전부 꺼져 있어(§10.9) 메뉴는 보여도 데이터는 흐르지 않는다.

- **관측 없음 ≠ 0** — 데이터가 안 온 것과 값이 0인 것은 다른 상태다. 문구로만이 아니라 **타입으로** 가른다(`tps: number | null`). 3초 유예를 넣었다가 이 규칙을 스스로 깬 적이 있다([부록 B](solutions--15-%EB%B6%80%EB%A1%9D-B.-%EC%9D%B4-%ED%94%84%EB%A1%9C%EC%A0%9D%ED%8A%B8%EA%B0%80-%EB%92%A4%EC%A7%91%EC%9D%80-%EA%B0%80%EC%A0%95-%EC%8B%A4%EC%B8%A1-%EA%B2%80%EC%88%98%EA%B0%80-%EC%84%A4%EA%B3%84%EB%A5%BC-%EB%B0%94%EA%BE%BC-36%EA%B0%80%EC%A7%80.md) #35).
- **표시 n / 관측 m** — 어느 숫자가 어느 층(관측/보관/표시)의 것인지 항상 붙인다. 통계는 **전체 관측**에서만 내고 **표시 표본에서 계산하지 않는다**(표본에서 오류율을 내면 강조 계층 때문에 올라간다).
- **완료 처리량이지 유입이 아니다** — 1초 막대가 움직이는 것은 "방금 끝난 요청"이다.
- **"초 단위"·"실시간(1초)"라고 쓰지 않는다** — 갱신 리듬은 부품 제목 옆 작은 글씨("1초"·"약 1분 이내")로만 적고, 헤더의 종단 지연 문구는 반드시 **"권장 설정 시"**를 단다(빼면 거짓이 된다 — BSP 기본값의 저트래픽 서비스는 캡처 단계에서만 p95 5.7초다).

**이 메뉴가 보여주지 않는 것**: 확장 없는 서비스(자바 외 언어 포함)의 진행 중 요청 목록·유입 곡선(스팬은 끝나야 export — 확장 설치 서비스만 예외, [18](solutions--18-P5-%EC%8B%A4%EC%8B%9C%EA%B0%84-%EA%B4%80%EC%A0%9C-%EC%A7%80%EA%B8%88-%EC%9D%B4-%EC%88%9C%EA%B0%84%EC%9D%84-%EB%B3%B4%EB%8A%94-%EA%B8%B8%28%EB%9D%BC%EC%9D%B4%EB%B8%8C-%EC%8A%A4%ED%8C%AC-X-View-%EC%9A%94%EC%B2%AD-%EA%B4%80%EC%A0%9C-%EB%B9%84%EB%8F%99%EA%B8%B0%29.md) §10.10) · 메서드 프로파일링 · 비-HTTP SERVER 점(RPC·메시징은 P5.5) · 과거 조회(15분 지나면 없다 — 트레이스 탐색으로; 진행 중 요청은 90초) · 다중 BE 합산. 이유는 [18-p5-realtime.md](solutions--18-P5-%EC%8B%A4%EC%8B%9C%EA%B0%84-%EA%B4%80%EC%A0%9C-%EC%A7%80%EA%B8%88-%EC%9D%B4-%EC%88%9C%EA%B0%84%EC%9D%84-%EB%B3%B4%EB%8A%94-%EA%B8%B8%28%EB%9D%BC%EC%9D%B4%EB%B8%8C-%EC%8A%A4%ED%8C%AC-X-View-%EC%9A%94%EC%B2%AD-%EA%B4%80%EC%A0%9C-%EB%B9%84%EB%8F%99%EA%B8%B0%29.md) §10.5.

- **진행 중 작업**: 스팬은 끝나야 export되므로 "미완 비동기 N개" 같은 것은 만들 수 없다.
- **병렬 실행·스레드 수**: `thread.*`는 스팬을 *시작한* 스레드 정보이고 스팬에 프로세스/인스턴스 식별자가 없어 같은 이름의 두 JVM을 가르지 못한다 → "병렬 실행"·"스레드 N개" 문구는 화면 어디에도 없다(✅ 문구 게이트 0건). 스레드 레인은 BE 필드(F1) 뒤 P5.6b.
- **완전한 링크 그래프**: 적재 32/스팬·절단 플래그 없음 → 요약은 항상 "응답에 포함된 링크".
- **X-View의 점**: X-View는 HTTP SERVER만이며 자식 INTERNAL·CLIENT·CONSUMER는 점이 되지 않는다.
- **메시징 롤업과의 일치**: 메시징 화면의 `lagCount`는 "첫 링크 우선·없으면 부모·같은 시스템·1시간 lookback" 조건으로 센 값이라 여기의 링크 수와 같다고 설명하지 않는다.

🔴 **출시 문구(R-P5.6 §11)**: `@Async`·CompletableFuture 구성에서는 링크가 자동 생성되지 않습니다(javaagent 2.31.1 실측, 14구성 1,400요청 전건 0). 부모-자식 연결은 100% 유지되므로 워터폴의 부모 종료 이후 종료 표시로 추적합니다. Kafka·RabbitMQ 환경은 이번 실측 범위 밖입니다.
