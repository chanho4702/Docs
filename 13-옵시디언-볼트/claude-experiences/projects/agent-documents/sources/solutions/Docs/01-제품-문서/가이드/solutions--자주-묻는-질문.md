# MovesEye 자주 묻는 질문(FAQ)

> 도입 검토·사용·운영 단계에서 **실제로 반복해서 받은 질문**과, 지원 과정에서 **고장으로 오인하기 쉬운 동작**을 한 곳에 모았다. 절차가 필요하면 각 답의 링크를 따라간다.
>
> 표기: **[제공]** 구현 완료 · **[개발 중]** 일부 반영 · **[예정]** 설계만 확정. 실제 제공 범위는 도입 환경의 릴리스와 라이선스에 따른다.

## 1. 제품 일반

**Q. MovesEye(DMOVE)는 무엇인가요?**
여러 모니터링 데이터소스(Zabbix·Prometheus·Datadog·Elasticsearch)의 상태·장애·자산·비용을 **하나의 운영 화면**으로 통합하는 설치형 종합 모니터링 제품입니다. 수집은 각 도구에 맡기고, 그 위에 완성된 운영 화면·권한·자산 맥락을 얹습니다. → [제품 소개서](../%EC%A0%9C%ED%92%88/solutions--%EC%A0%9C%ED%92%88-%EC%86%8C%EA%B0%9C%EC%84%9C.md)

**Q. Zabbix를 대체하나요?**
아니요. Zabbix Server·Agent·트리거·알림 규칙은 그대로 두고 API로 연동합니다. 기존 감시 체계에 영향을 주지 않으며, 추가로 필요한 것은 애플리케이션 서버·PostgreSQL·Redis뿐입니다.

**Q. 지금 연결할 수 있는 데이터소스는 무엇인가요?**
**Zabbix 하나**입니다(7.0 계열에서 실측). 데이터 소스 화면에 Prometheus·Datadog·Elasticsearch가 보이더라도 화면 골격과 내부 계약만 준비된 상태이고 어댑터는 아직 없습니다. → [제품 개요 §3.1](../%EC%A0%9C%ED%92%88/solutions--%EC%A0%9C%ED%92%88-%EA%B0%9C%EC%9A%94.md)

**Q. Grafana를 이미 쓰는데 왜 필요한가요?**
Grafana는 패널마다 소스별 쿼리를 직접 짜는 **범용 시각화 도구**이고, MovesEye는 운영 화면·권한·대상 관리·자산·비용·맵이 **이미 완성된 제품**입니다. 쿼리 언어를 몰라도 쓸 수 있고, 뒤의 소스가 바뀌어도 화면은 그대로입니다. 두 도구를 함께 쓰는 구성도 가능합니다.

**Q. 조회 전용 대시보드인가요?**
아니요. 호스트 등록·템플릿 연결·아이템·트리거·액션·미디어·매크로·점검 기간까지 화면에서 관리하며, **여기서 한 변경은 실제 Zabbix에 기록**됩니다. 별도 사본이 아닙니다.

**Q. 몇 대까지 관리할 수 있나요?**
제품 자체에 대수 제한은 없습니다. 성능은 연결된 Zabbix 규모와 서버 사양에 따르므로 도입 전 규모를 공유해 주시면 검토합니다.

**Q. 폐쇄망에서 쓸 수 있나요?**
제품 자체는 외부 통신 없이 동작합니다. 예외는 **지리 맵의 지도 타일**(OpenFreeMap), **AWS 클라우드 연동**, **AI 어시스턴트의 외부 LLM 호출**(사내 Ollama 등 로컬 프로바이더를 쓰면 폐쇄망 가능)입니다. Zabbix 에이전트 설치 가이드는 폐쇄망용 반입 절차를 따로 제공합니다.

**Q. 데이터는 어디에 저장되나요?**
고객사 인프라에 설치되는 온프레미스 제품이며 데이터는 외부로 나가지 않습니다. 단, AI 어시스턴트에 외부 LLM(Anthropic·OpenAI 등)을 연결하면 **대화와 툴 결과가 해당 프로바이더로 전송**됩니다(§9).

**Q. 한국어를 지원하나요? 다크 모드는요?**
전 화면 한국어·영어를 지원하고 사용자별로 설정합니다. 다크 모드도 지원합니다.

**Q. 화면마다 도움말이 있나요?**
주요 화면 상단의 도움말(ⓘ)에서 그 화면의 목적·읽는 법·주의점을 볼 수 있습니다. 더 자세한 절차는 [화면별 가이드](%ED%99%94%EB%A9%B4%EB%B3%84/solutions--MovesEye-%ED%99%94%EB%A9%B4%EB%B3%84-%EA%B0%80%EC%9D%B4%EB%93%9C.md)를 봅니다.

## 2. 설치·요건

**Q. 필수 구성요소는 무엇인가요?**
JDK 17, PostgreSQL 13+, Redis 6+, 연동할 Zabbix(JSON-RPC), 그리고 FE를 서빙할 웹서버(Nginx·Apache 등)입니다. 선택은 SMTP(메일·비밀번호 재설정), AWS 자격증명(클라우드), AI 어시스턴트 서버(별도 프로세스)입니다. → [설치·배포 가이드](../%EC%9A%B4%EC%98%81/solutions--%EC%84%A4%EC%B9%98-%EB%B0%B0%ED%8F%AC-%EA%B0%80%EC%9D%B4%EB%93%9C.md)

**Q. DB 스키마를 미리 만들어야 하나요?**
아니요. 빈 데이터베이스와 계정만 만들면 기동 시 Flyway가 `V1`부터 최신까지 자동 적용합니다. 수동으로 테이블을 만들거나 `ddl-auto`를 켜지 않습니다.

**Q. `.env` 파일에 값을 넣었는데 적용이 안 됩니다.**
Spring은 `.env`를 자동으로 읽지 않습니다. OS 환경변수 또는 컨테이너 환경변수로 주입해야 합니다. `JWT_SECRET`은 예제값을 그대로 쓰지 않습니다.

**Q. 빌드가 알 수 없는 이유로 실패합니다.**
전역 `JAVA_HOME`이 JDK 8 등 다른 버전을 가리키는 경우가 가장 흔합니다. `java -version`을 먼저 확인하고 JDK 17을 명시합니다.

**Q. HTTP로 배포했더니 로그인 직후 전부 401이 납니다.**
`COOKIE_SECURE` 기본값이 `true`라 HTTP에서는 리프레시 쿠키가 저장되지 않습니다. HTTP 환경이면 `false`, HTTPS면 `true`로 둡니다. FE와 BE가 다른 도메인이면 `COOKIE_SAME_SITE`도 조정합니다. `localhost`는 예외라 로컬에서는 재현되지 않습니다.

**Q. FE와 BE를 다른 서버에 둘 수 있나요?**
가능합니다. FE는 정적 번들이라 빌드 시 BE URL을 주입하고, BE의 `CORS_ALLOWED_ORIGINS`에 FE origin을 등록합니다(와일드카드 금지).

**Q. 운영에서 Swagger(API 문서)를 켜도 되나요?**
켜지 않습니다. `SPRINGDOC_ENABLED`는 운영 기본 `false`이며, dev 프로필에서만 `/v3/api-docs`로 확인합니다.

**Q. Zabbix 에이전트는 어떻게 설치하나요?**
`Zabbix 관리 > 호스트 관리`의 **에이전트 설치 가이드**에서 OS·배포판·아키텍처·온라인/폐쇄망을 고르면, 우리 Zabbix 서버 주소와 버전에 맞는 **복붙 가능한 명령**이 생성됩니다. 폐쇄망은 다운로드 URL과 반입 절차를 줍니다. 설치 후 같은 화면에서 호스트 등록으로 이어집니다. **[제공]**

## 3. 로그인·계정·권한

**Q. 로그인은 되는데 새로고침하면 로그아웃됩니다.**
리프레시 토큰이 HttpOnly 쿠키로 오가는데 쿠키가 저장·전송되지 않는 상황입니다. HTTPS 여부와 `COOKIE_SECURE`, 크로스 도메인 여부와 `COOKIE_SAME_SITE`, 브라우저의 서드파티 쿠키 차단을 순서대로 확인합니다. → [문제 해결 §1](solutions--%EB%AC%B8%EC%A0%9C-%ED%95%B4%EA%B2%B0.md)

**Q. 세션은 얼마나 유지되나요?**
액세스 토큰 30분, 리프레시 8시간이 기본입니다(`JWT_ACCESS_EXPIRATION_SECONDS` / `JWT_REFRESH_EXPIRATION_SECONDS`). 사용 중에는 자동 갱신되고, 8시간 넘게 방치하면 재로그인합니다. 세션은 **계정당 1개**라 다른 곳에서 로그인하면 기존 세션이 끊깁니다.

**Q. 비밀번호를 잊었습니다.**
로그인 화면의 비밀번호 재설정에서 이메일로 받은 인증 코드로 재설정합니다. SMTP가 설정돼 있어야 하며, 미설정 환경에서는 관리자가 사용자 관리에서 초기화합니다.

**Q. LDAP·SSO·2차 인증(OTP)을 지원하나요?**
현재는 **제품 자체 계정(ID/비밀번호)만** 지원합니다. 이메일 인증 코드는 가입 확인·비밀번호 재설정용이지 2차 인증이 아닙니다. LDAP·SSO·OTP 2차 인증은 요구사항 접수 단계입니다. **[예정]**

**Q. 메뉴는 보이는데 목록이 텅 비어 있습니다.**
권한이 **두 축**입니다. 역할(Role)의 **기능 권한**은 메뉴를, 사용자 그룹↔호스트 그룹의 **데이터 범위**는 보이는 데이터를 통제합니다. 기능 권한만 주면 정확히 이 증상이 납니다. 관리자가 사용자 그룹에 호스트 그룹을 연결합니다. → [관리자 가이드 §3-1](solutions--%EA%B4%80%EB%A6%AC%EC%9E%90-%EA%B0%80%EC%9D%B4%EB%93%9C.md)

**Q. 메뉴 자체가 안 보입니다.**
역할에 해당 기능 권한 키가 없거나, **연결된 소스가 그 능력을 제공하지 않는** 경우입니다(예: Zabbix 미연결 시 Zabbix 관리 메뉴). AWS 미설정이면 클라우드 메뉴는 비활성으로 표시됩니다.

**Q. 퇴사자 계정은 삭제하나요?**
**비활성화**가 기본입니다. 삭제하면 감사 로그·자산 변경 이력의 행위자 추적이 끊깁니다. 비활성화는 로그인만 막고 이력을 보존합니다.

**Q. Zabbix 사용자와 MovesEye 사용자는 같은 건가요?**
다릅니다. MovesEye 사용자는 제품 DB에 있고, `user_sync` 배치로 Zabbix 사용자를 가져올 수 있습니다. 단 `SYNC_ENABLED`는 기본 `false`입니다 — 켜면 **Zabbix에 없는 로컬 계정을 제거**할 수 있으므로 켜기 전 반드시 백업합니다.

**Q. 역할은 몇 개로 시작하는 게 좋나요?**
3~4개(시스템 관리자·운영자·자산 담당자·조회 전용)로 시작하고 불편한 지점만 나중에 나눕니다. 역할을 먼저 만들고 사용자에 붙이는 순서를 지킵니다.

> 아래 여섯 문항은 ZM-157(2026-09-17) 변경입니다. 소스에 반영됐고 배포 전입니다. **[개발 중]**

**Q. 메뉴가 안 보이거나 "이 작업을 수행할 권한이 없습니다"가 뜹니다.**
역할에서 허락되지 않은 기능은 메뉴에서 숨겨지고, 주소를 직접 입력하거나 AI 어시스턴트로 요청해도 서버가 거부합니다. 조회는 역할 칸의 **보기**, 저장·삭제는 **편집** 권한이 필요합니다. Zabbix와 연결되지 않은 일반 계정은 Zabbix 데이터 화면에서 이 안내를 받습니다. 역할에서 체크해도 효과가 없는 칸도 있으니 [관리자 가이드 §3-6](solutions--%EA%B4%80%EB%A6%AC%EC%9E%90-%EA%B0%80%EC%9D%B4%EB%93%9C.md)의 표를 확인합니다. 새로고침 직후에는 서버에서 권한을 받을 때까지 메뉴가 잠시 비어 보일 수 있습니다. → [문제 해결 §2-2A](solutions--%EB%AC%B8%EC%A0%9C-%ED%95%B4%EA%B2%B0.md)

**Q. 업데이트 후 다시 로그인하라고 나옵니다.**
정상입니다. 로그인 유지 방식이 바뀌어 업데이트 전의 로그인 정보는 연장되지 않습니다. 모든 사용자가 최대 30분 안에 한 번 다시 로그인하면 이후에는 이전처럼 유지됩니다. 또 비밀번호를 바꾸거나 관리자가 계정을 비활성화하면 **다른 기기의 로그인은 곧바로 끝납니다.**

**Q. 로그인하면 곧바로 로그인 화면으로 돌아옵니다.**
같은 계정의 비밀번호 변경이나 계정 수정이 동시에 처리되는 중이면 로그인이 잠시 기다린 뒤 처리되지 못할 수 있습니다(`FAILED_TO_ACQUIRE_LOCK`). 잠시 후 다시 로그인합니다. 반복되면 관리자에게 확인을 요청합니다. → [문제 해결 §1-C](solutions--%EB%AC%B8%EC%A0%9C-%ED%95%B4%EA%B2%B0.md)

**Q. "권한 정보를 불러오지 못했습니다" 화면이 뜹니다.**
내 계정 정보나 권한을 서버에서 받지 못해 화면을 열지 않은 상태입니다. [다시 시도] → 새로고침 → 로그아웃 후 재로그인 순으로 해 봅니다. 여러 사용자에게 동시에 나타나면 관리자가 서버 상태를 확인합니다.

**Q. 관리자 계정의 비밀번호 찾기가 안 됩니다.**
계정에 이메일이 없으면 인증 코드를 보낼 수 없습니다. 업데이트 때 기본 관리자 계정의 **초기 설치 이메일은 비워집니다.** 다른 관리자에게 비밀번호 초기화를 요청하고, 로그인 후 실제로 받을 수 있는 이메일을 마이 페이지에서 등록합니다. → [관리자 가이드 §3-11](solutions--%EA%B4%80%EB%A6%AC%EC%9E%90-%EA%B0%80%EC%9D%B4%EB%93%9C.md)

**Q. 비밀번호를 바꿨더니 다른 PC에서 로그아웃됐습니다.**
의도된 동작입니다. 비밀번호 변경·재설정 시 그 계정의 다른 기기 로그인은 모두 끝납니다. 연결된 앱(MCP) 연결은 비밀번호 변경으로 끊기지 않으므로, 유출이 의심되면 `설정(⚙) > 연결된 앱`에서 연결도 해제합니다.

## 4. 모니터링·데이터 읽기

**Q. 차트가 비어 있으면 장애인가요?**
아닙니다. `-`, `N/A`, 빈 차트는 대개 **관측값 없음**이며 실제 0과 다릅니다. 같은 호스트의 다른 메트릭이 나오는지 → 해당 아이템이 존재하고 활성인지(아이템 관리) → 조회 기간이 수집 이력 안인지 순으로 봅니다. 메트릭 하나가 비었다고 호스트 전체 장애로 단정하지 않습니다.

**Q. 전 화면에서 호스트가 하나도 안 보입니다.**
Zabbix 연동이 끊긴 것입니다. `설정(⚙) > 데이터 소스 관리`의 URL과 전용 계정을 확인합니다. 계정 비밀번호 변경·잠금이 가장 흔한 원인입니다. 관리자 계정은 **매 요청 Zabbix에 로그인**하므로, 연동이 깨지면 사이드바까지 비어 보일 수 있습니다.

**Q. 데이터가 얼마나 최신인가요?**
화면의 기준 시각(`syncTime`)을 봅니다. 이벤트는 `event_sync` 배치 주기(권장 1분 수준)로, 메트릭은 조회 시점에 Zabbix에서 가져옵니다. 모든 메트릭이 같은 순간에 측정됐다고 보장하지 않습니다.

**Q. 트래픽 수치가 터무니없이 큽니다.**
네트워크 트래픽(`net.if.in/out`)은 **bps** 원값입니다. 화면은 비트레이트(SI 1000) 포매터를 씁니다. 바이트 포매터가 적용된 곳이 있으면 약 940만 배로 부풀려지므로 결함으로 보고합니다.

**Q. 시각이 9시간 어긋납니다.**
서버는 UTC로 실행되고 화면은 브라우저 시간대로 표시합니다. 로그·DB 값이 화면과 9시간 차이 나는 것은 정상입니다.

**Q. 정렬 순서가 이상합니다(대문자가 먼저 옵니다).**
Zabbix 정렬은 **대소문자를 구분하는 코드포인트 순**입니다. 사람이 기대하는 사전순과 달라도 원천 동작입니다.

**Q. 라이브 헬스체크는 무엇을 확인하나요?**
호스트 목록의 헬스체크 버튼은 BE가 직접 OS ping을 보내고, Agent 상태는 Zabbix 인터페이스 가용성을 읽습니다. 지금 이 순간의 도달 여부만 확인하며, 장기 상태나 모든 메트릭의 정상 여부를 보장하지 않습니다.

**Q. 디스크 차트는 나오는데 상세 표가 비어 있습니다.**
디스크 아이템 계열이 둘(`vfs.fs.size` / `vfs.fs.dependent`)이고 호스트마다 다릅니다. 상세 조회에 계열 폴백이 있으나 두 계열 모두 없는 호스트는 표가 빕니다.

**Q. 홈 화면은 커스터마이즈할 수 있나요?**
네. 홈은 **사용자별 위젯 대시보드**입니다. 위젯 14종을 추가·배치·크기 조정할 수 있고, 시스템 위젯 3종은 고정입니다. 위젯의 이상 수치에서 해당 화면으로 바로 내려갑니다. **[제공]**

**Q. 호스트 상세에 차트 편집(추가·삭제) 버튼이 없습니다.**
호스트 상세의 사용자 정의 차트는 그 호스트를 보는 모든 사용자가 함께 쓰는 화면이라, 편집에 **서버 또는 네트워크 모니터링의 편집 권한**이 필요합니다. 기본 역할의 일반 사용자는 차트를 볼 수만 있습니다. 필요하면 관리자가 역할에서 편집을 체크합니다. **[개발 중 — ZM-157, 배포 전]** → [관리자 가이드 §3-7](solutions--%EA%B4%80%EB%A6%AC%EC%9E%90-%EA%B0%80%EC%9D%B4%EB%93%9C.md)

**Q. 차트를 클릭하면 어디로 가나요?**
차트 조각·툴팁 링크·표 행은 같은 항목 집합으로 연결됩니다. 자산 대시보드에서는 자산 목록으로, 이벤트·Zabbix 화면에서는 해당 목록으로 필터가 걸린 채 이동합니다. 차트↔표 전환 버튼도 있습니다.

**Q. 리포트는 어떻게 뽑나요?**
`모니터링 > 호스트 그룹` 상세의 리포트 탭에서 주간·월간 자원·알람 리포트를 보고 Excel로 내려받습니다. 배치(`report_weekly`·`report_monthly`)가 스냅샷을 만들고, 없는 구간은 조회 시 백필합니다. 자산 비용 화면도 Excel 내보내기를 제공합니다.

## 5. 이벤트·알림

**Q. Problem과 Event는 같은 말인가요?**
아닙니다. **Problem**은 트리거가 문제 상태가 되어 열린 활성 장애이고, **Event**는 발생·복구·상태 변화의 시점 기록입니다. → [용어집](../%EC%B0%B8%EA%B3%A0/solutions--%EC%9A%A9%EC%96%B4%EC%A7%91.md)

**Q. 인지(acknowledge)하면 해결된 건가요?**
아니요. 운영자가 **인지하고 조치 중임을 팀에 기록**하는 행위입니다. 해소는 Zabbix 트리거가 복구 조건을 만족할 때 일어납니다.

**Q. 이벤트 통계(차트)는 어디서 보나요?**
`이벤트·알림` 화면의 통계 탭에서 심각도·호스트·시간대별 발생 추이와 해소 시간(MTTR)을 봅니다. 집계는 제품 DB에 동기화된 이벤트 기준입니다. **[제공]**

**Q. 알림(메일·Slack·Teams)은 어디서 설정하나요?**
두 경로가 있습니다.
- **Zabbix 액션·미디어 타입**: `Zabbix 관리 > 알림 관리`에서 액션 5종(장애·디스커버리·자동등록·내부·서비스)과 미디어 타입을 관리합니다. Slack·Teams·Jandi 등은 전부 Zabbix 미디어 타입입니다.
- **제품 자체 알림**: 화면 상단 알림 벨과 이메일(SMTP)입니다. 제품이 직접 Slack·Teams로 푸시하지는 않습니다.

**Q. 알림이 안 옵니다.**
AI 어시스턴트의 알림 진단 툴 또는 알림 관리 화면에서 **배달 경로 3단**(액션 활성 → 오퍼레이션에 미디어 지정 → 사용자 미디어 활성)을 확인합니다. 액션 조건을 전부 해제하면 **전역 액션으로 승격**되므로 제품이 거부합니다(`ACTION_UNLINK_MAKES_GLOBAL`).

**Q. 해소된 문제의 이력을 오래 보관하나요?**
`event_cleanup` 배치가 보존 기간이 지난 이벤트를 정리합니다. 주기와 활성 여부는 `설정 > 스케줄러`에서 조정합니다. 이 배치는 라이선스가 만료돼도 계속 돕니다(§10).

## 6. Zabbix 관리(대상 관리)

**Q. 제품에서 바꾼 설정이 Zabbix에도 반영되나요?**
네, 즉시 원천에 기록됩니다. 연습용이 아니므로 운영 대상은 변경 승인·영향 범위·롤백 계획을 먼저 확인합니다.

**Q. 태그를 하나 추가했더니 나머지가 사라졌습니다.**
Zabbix `update`는 태그·템플릿 링크 같은 배열을 **통째로 교체**합니다. 제품 화면은 현재 값을 읽어 전체를 다시 보내는 방식으로 이를 막으므로, **폼에 채워진 기존 값을 임의로 비우지 않습니다**. 이미 사라졌다면 변경 이력에서 이전 값을 확인해 복구합니다.

**Q. 트리거 수정 시 대상 호스트는 어디서 정하나요?**
트리거는 대상 호스트를 따로 갖지 않습니다. **expression 안의 `/host/key`가 곧 대상**입니다. expression을 고치면 다른 호스트를 보게 될 수 있습니다.

**Q. 아이템 관리·트리거 관리의 "정의처"는 무엇인가요?**
그 정의가 템플릿에서 상속된 것인지 호스트에 직접 만든 것인지, 몇 개 호스트에 전파됐는지를 보여 줍니다. 템플릿 쪽을 고치면 연결된 호스트 전체가 함께 바뀝니다. 기본 뷰는 디스커버리 자동 생성 항목을 숨깁니다.

**Q. 우리 Zabbix가 제대로 구성돼 있는지 한눈에 볼 수 있나요?**
`Zabbix 관리 > 구성 현황`에서 호스트·템플릿·아이템·트리거·미디어의 실제 사용 현황(예: 정의된 템플릿 중 실제 쓰이는 것)을 봅니다. `모니터링 커버리지`는 호스트별로 에이전트·템플릿·핵심 아이템이 갖춰졌는지 진단합니다. **[제공]**

**Q. 호스트 분류(서버·네트워크·스토리지 등)는 어떻게 관리하나요?**
분류는 **Zabbix 호스트 태그**로 붙고, `설정 > 기기분류 관리`는 표시명·순서·비용 정책 등 메타만 갖습니다. 분류를 지워도 호스트 데이터는 파괴되지 않으며, 모르는 코드는 "미분류"로 폴백합니다.

**Q. 수정 요청이 "인증 오류"로 표시됩니다.**
Zabbix 파라미터 검증 실패(`-32602`)가 과거 401로 보이던 회귀가 있었고 현재는 400으로 매핑됩니다. 여전히 401이면 실제 요청 파라미터를 확인하고 결함으로 보고합니다.

**Q. 필드를 비웠는데 지워지지 않습니다.**
부분 수정에서 **필드 미포함(변경 없음)** 과 **빈 문자열(값 지우기)** 은 다릅니다. 지우려면 빈 값을 명시적으로 저장해야 합니다.

**Q. 네트워크 디스커버리·매크로·점검 기간도 관리할 수 있나요?**
네. 디스커버리 규칙, 전역/호스트/템플릿 매크로, 점검 기간(Maintenance)을 `Zabbix 관리` 메뉴에서 관리합니다. 비밀 매크로 값은 마스킹됩니다. 그래프·스크립트·Web 시나리오·프록시·SLA 관리는 **[예정]** 입니다.

## 7. 자산·비용·맵

**Q. 자산은 어디서 오나요?**
`source=zabbix`(Zabbix 호스트에서 동기화), `source=cloud`(AWS EC2에서 자동 등록), `source=custom`(제품에서 직접 등록한 비품·회선 등) 세 출처입니다. 삭제는 물리 삭제가 아니라 `excluded` soft delete입니다.

**Q. 자산을 고쳤는데 원복됐습니다.**
Zabbix가 원천인 필드를 고쳤고 다음 동기화가 덮어쓴 것입니다. 영구히 유지할 값은 제품 소유의 보강 필드에 넣습니다. 수정 화면이 두 종류 필드를 구분해 안내합니다.

**Q. 지리 맵에 호스트 후보가 0건입니다.**
**자산 최초 동기화**를 하지 않은 상태입니다. 동기화 전에는 자산의 `linked_hostid`가 비어 후보가 잡히지 않습니다. `자산 관리 > 목록`에서 동기화를 한 번 실행합니다. 고장으로 오인하기 가장 쉬운 사례입니다.

**Q. 좌표는 어디에 저장되나요?**
호스트 좌표의 원천은 **Zabbix 인벤토리**입니다. 지리 맵에서 편집하면 Zabbix에 기록되며, 제품 DB에 좌표를 중복 저장하지 않습니다. 클러스터(사업장·데이터센터 묶음)만 제품 DB에 있습니다.

**Q. 지리 맵에서 호스트 핀을 옮길 수 없습니다.**
호스트 좌표 편집은 **관리자 전용**입니다. 좌표가 Zabbix 인벤토리에 기록되기 때문입니다. 일반 사용자는 지도와 클러스터를 볼 수 있고, 좌표 입력은 관리자에게 요청합니다. **[개발 중 — ZM-157, 배포 전]** → [지리 맵](%ED%99%94%EB%A9%B4%EB%B3%84/%EC%9E%90%EC%82%B0-%EA%B4%80%EB%A6%AC/solutions--%EC%A7%80%EB%A6%AC-%EB%A7%B5.md)

**Q. 네트워크 맵은 누가 편집할 수 있나요?**
모든 사용자가 편집할 수 있습니다(예외적으로 권한을 두지 않았습니다). 메인 맵은 하나만 유지하고, 라이브 뷰는 저장된 구성도에 현재 호스트 상태를 결합해 보여 줍니다. 노드에 실제 호스트를 연결해야 상태가 반영됩니다.

**Q. 감가상각은 어떻게 계산되나요?**
취득가액·취득일을 넣으면 정액법·정률법으로 계산합니다. 한국 세무 기준(월할, 잔존가액 0)이며 기기 유형별 기본 내용연수에 자산별 예외를 줄 수 있습니다. 파라미터를 바꾸면 **현재 파라미터로 소급 재계산**되고 과거 스냅샷은 보존하지 않습니다(의도된 설계). **[개발 중]**

**Q. CSV 업로드가 성공했는데 반영이 안 됐습니다.**
비동기 처리입니다. 업로드 성공은 "접수됨"이지 "처리 완료"가 아닙니다. 진행 중 작업 상태를 확인하고, 끝나기 전에 새 업로드를 제출하지 않습니다(활성 작업은 1개만 허용). 파일 상한은 10MB, 작업 이력은 24시간 보관됩니다.

**Q. 클라우드 비용은 어디서 보나요?**
`자산 관리 > 비용`의 **Cloud 탭**입니다. HW 비용 모집단은 `source≠cloud`이며, KRW(HW)와 USD(클라우드)는 합산하지 않습니다.

**Q. 자산 현황 대시보드의 "미분류"가 너무 많습니다.**
데이터 품질 문제입니다. Zabbix 호스트에 분류 태그가 없거나 인벤토리 모드가 꺼진 호스트가 많으면 그렇게 보입니다. `호스트 관리`의 일괄 분류 지정으로 채웁니다.

## 8. 클라우드(AWS)

**Q. AWS 연동은 어떻게 켜나요?**
`설정(⚙)`의 클라우드 인프라 항목에서 Access Key·Secret을 등록하고 연결 테스트를 합니다. 미설정이면 클라우드 메뉴가 비활성으로 표시됩니다. 자격증명은 DB에 **AES-256-GCM으로 암호화** 저장되며, 미설정 시 `.env`/IAM 표준 자격증명 체인을 자동 인식합니다. "기본 리전" 설정은 없습니다 — 전 리전을 자동으로 조회합니다.

**Q. AWS 요금이 발생하나요?**
기본 상태에서는 **과금 0**입니다. EC2·VPC 상태는 5분 배치 스냅샷(무료 API)으로 수집하고, 상태 타임라인·추정 비용은 그 스냅샷으로 만듭니다. 다음은 **관리자가 명시적으로 켠 경우에만** 유료 API를 호출합니다.
- CloudWatch 지표(플릿 CPU·네트워크·EBS 등): 설정의 CloudWatch 스위치. 끄면 목록·상세 시계열까지 차단되고 `cloudwatch-off` 배지가 보입니다. 월 예산 가드가 있습니다.
- Cost Explorer 실청구액: 유료 옵트인 고지 후 활성화. 일 1회 배치, 요청당 $0.01.

**Q. EC2 인스턴스의 CPU는 어디서 오나요?**
Zabbix 에이전트가 설치된 인스턴스는 **에이전트 값**이 우선이고, 없거나 품질이 낮으면 CloudWatch로 폴백합니다. 인스턴스↔호스트 매칭은 인스턴스 ID 태그 > IP 순이며 유일할 때만 연결합니다. 상세 화면에 출처 배지가 표시됩니다.

**Q. Nitro(EBS 전용) 인스턴스의 디스크 지표가 없습니다.**
EBS 전용 인스턴스는 `DiskRead/WriteBytes`가 없고 `EBSRead/WriteBytes`를 씁니다. 제품은 이를 자동으로 교체하며, 두 지표 모두 없으면 빈 값으로 표시합니다.

**Q. Azure·GCP는요?**
현재 AWS만 지원합니다. **[예정]**

## 9. AI 어시스턴트

**Q. AI 어시스턴트는 무엇을 하나요?**
화면 어디서든 우하단의 플로팅 챗을 열거나 `AI 어시스턴트` 메뉴로 들어가, 운영 중 필요한 일을 **자연어로 요청**하는 기능입니다. "지금 CPU가 높은 호스트 알려 줘", "이번 주 알람을 엑셀로 정리해 줘", "web-01 호스트에 태그 붙여 줘"처럼 말하면 어시스턴트가 제품 API를 대신 호출해 결과를 대화 안에서 보여 줍니다. 할 수 있는 일은 크게 네 가지입니다.
- **조회·진단** — 호스트·알람·자산·비용·Zabbix 구성(호스트·템플릿·아이템·트리거·액션)을 묻고, 알림이 왜 안 오는지 배달 경로까지 진단합니다.
- **리포트** — 조회 결과를 Excel 파일로 만들어 내려받게 합니다(파일은 24시간 보관).
- **변경** — 호스트 등록·수정, 장애 인지 처리, 자산·비용 입력 같은 쓰기 작업도 대화로 요청할 수 있습니다. 실행 전에 확인 카드를 띄워 승인을 받습니다.
- **화면 안내** — "이 화면은 뭘 보는 곳이야?", "비용 탭은 어디 있어?"처럼 물으면 지금 보고 있는 화면·탭을 설명하고 해당 화면으로 안내합니다.

자주 쓰는 요청은 입력창에 `/`를 치면 나오는 명령 목록(26개)에서 골라 바로 실행합니다. 이 밖에 홈 화면의 **AI 알림 분석 위젯**이 최근 알람을 요약해 주고, `AI 어시스턴트 > 알람 인텔리전스` 화면에서는 서버가 집계한 알람 통계 위에 LLM이 쓴 운영 브리핑을 버튼 클릭으로 받아볼 수 있습니다. **[제공]**

**Q. 어떤 LLM을 쓰나요? API 키는 어디에 넣나요?**
프로바이더 중립입니다 — Anthropic, OpenAI 호환, Azure OpenAI, Ollama(로컬). `설정(⚙) > AI 어시스턴트 설정`에서 관리자가 입력하며 암호화 저장·핫리로드됩니다. 코드나 환경변수에 키를 넣지 않습니다.

**Q. 누가 쓸 수 있나요?**
**관리자 전용**입니다. AI 서버는 자체 권한이 없고 사용자의 세션을 그대로 BE에 전달하므로, 사용자가 화면에서 못 하는 일은 AI로도 할 수 없습니다.

**Q. AI가 설정을 마음대로 바꿀 수 있나요?**
아니요. 읽기 툴만 즉시 실행되고, 쓰기·삭제 툴은 **확인 카드**를 띄워 사용자가 승인해야 실행됩니다. 삭제는 대상 10건 이하로 제한되며 카드에 대상 이름이 표시됩니다. 실행 결과는 화면 캐시에 즉시 반영됩니다.

**Q. 별도 서버인가요?**
네. `moveseye-ai`가 :3100에서 별도 프로세스(Spring Boot 4)로 돌며, BE `.env`를 공유하지 않으므로 환경변수를 따로 줍니다. AI 서버가 없어도 제품 나머지는 정상 동작합니다(`/ai/health`로 진입점 판정).

**Q. 대화 내용이 외부로 나가나요?**
외부 LLM 프로바이더를 선택하면 대화와 툴 결과(호스트명·알람 등)가 그 프로바이더로 전송됩니다. 폐쇄망·보안 요건이 있으면 Ollama 등 로컬 프로바이더를 씁니다. 대화 기록은 제품 DB에 저장됩니다.

**Q. "연결된 앱"은 무엇인가요?**
Claude Desktop·Claude Code 같은 외부 AI 클라이언트가 **MCP**로 MovesEye에 접속하는 기능입니다. OAuth 동의 화면을 거치고, 계정별 읽기/쓰기 권한(`mcp_permission`)으로 통제합니다.

**Q. Claude·Cursor 같은 외부 AI 앱을 MovesEye에 어떻게 연결하나요?**
`설정(⚙) > 연결된 앱`에서 커넥터 주소(`https://<도메인>/mcp` 형태)를 복사해 앱의 MCP 설정에 넣고, 브라우저에 뜨는 MovesEye 동의 화면에서 허용합니다. 앱별 절차(Claude Desktop·claude.ai·Claude Code·Cursor·VS Code)는 [MCP 연결 가이드 §3](solutions--MCP-%EC%97%B0%EA%B2%B0-%EA%B0%80%EC%9D%B4%EB%93%9C.md)에 있습니다. 먼저 관리자가 설치본에서 MCP 연동을 켜고 내 계정에 MCP 권한(조회만 또는 조회+변경)을 주어야 합니다.

**Q. 사내망에서만 열리는 주소를 claude.ai에 넣었더니 연결이 안 됩니다.**
claude.ai·Claude Desktop 커넥터는 Anthropic 클라우드가 MovesEye 서버에 직접 접속하므로, 인터넷에서 접근 가능한 https 주소가 필요합니다. 사내망 전용 설치본이면 내 PC에서 접속하는 Claude Code·Cursor·VS Code를 씁니다. → [MCP 연결 가이드 §9](solutions--MCP-%EC%97%B0%EA%B2%B0-%EA%B0%80%EC%9D%B4%EB%93%9C.md)

**Q. 관리자는 MCP 연동을 어떻게 켜나요?**
AI 서버에 `AI_MCP_ENABLED=true`를 주고, https 공개 주소에서 `/mcp`·`/oauth/`·`/.well-known/`·`/ai/` 경로를 AI 서버로 보내도록 프록시를 설정한 뒤, 사용자 관리에서 사용자별 MCP 권한을 줍니다. 기본은 꺼져 있습니다(데이터가 외부 AI 서비스로 나가기 때문). → [MCP 연결 가이드 2부](solutions--MCP-%EC%97%B0%EA%B2%B0-%EA%B0%80%EC%9D%B4%EB%93%9C.md)

**Q. AI 어시스턴트나 연결된 앱에서 삭제가 안 됩니다.**
**[개발 중 — ZM-157, 배포 전]**
- **연결된 앱(MCP)**: 호스트·아이템·트리거 삭제, 자산 제외, 데이터까지 지우는 템플릿 연결 해제는 **기본으로 막혀 있습니다.** 연결된 앱에는 MovesEye의 확인 카드가 없기 때문입니다. 삭제는 MovesEye 화면이나 화면 안의 AI 어시스턴트에서 합니다. 설치본 운영자가 설정으로 허용할 수 있지만, 허용해도 한 번에 대상 1개만 처리합니다.
- **화면 안의 AI 어시스턴트**: 확인 카드에서 대상 표(ID·이름)를 확인하고 [실행]을 눌러야 삭제됩니다. 한 요청에서 확인 카드는 5장까지입니다.
- **공통**: 역할에 해당 권한이 없으면 AI로도 할 수 없습니다.

**Q. 연결된 앱의 권한을 회수하면 언제 반영되나요?**
**다음 요청부터 바로** 반영됩니다. 권한을 없애면 모든 요청이, 쓰기를 읽기로 낮추면 변경 요청만 거부됩니다. 계정을 비활성화하거나 사용자 유형을 바꾸면 연결이 끊겨 다시 연결해야 합니다. **[개발 중 — ZM-157, 배포 전]**

**Q. 알람 인텔리전스 요약이 초기화됐습니다.**
업데이트 때 요약 캐시가 사용자별로 분리되면서 기존 요약이 지워집니다. [지금 분석]을 누르면 다시 만들어집니다. **[개발 중 — ZM-157, 배포 전]**

**Q. 답변에 화면이 안 맞거나 옛 경로를 가리킵니다.**
화면 카탈로그(`screens.json`) 갱신 누락입니다. 결함으로 보고합니다.

## 10. 리포트·스케줄러·배치

**Q. 어떤 배치가 있나요?**
`asset_sync`(호스트→자산), `event_sync`(이벤트, 짧은 주기), `event_cleanup`, `report_weekly`, `report_monthly`, `report_cleanup`, `user_sync`(기본 비활성) 등이 `설정 > 스케줄러`에 있습니다. 주기는 DB 설정이라 **재기동 없이** 바꿉니다. 클라우드 스냅샷·정리(기본 30일 보존), CE 청구액 배치도 같은 곳에서 봅니다.

**Q. 배치가 성공인데 데이터가 일부만 반영됐습니다.**
부분 실패는 예외가 아니라 요약 문자열(`ok=38 fail=2`)로만 남습니다. 실행 이력의 요약을 읽습니다. 전건 실패도 다음 실행은 취소되지 않으며 원인을 고치면 다음 주기에 복구됩니다.

**Q. 배치가 안 도는 것 같습니다.**
활성 여부·cron 표현식 → 마지막 실행 시각 → 다른 무거운 배치와 겹쳐 대기 중인지(`SCHEDULER_POOL_SIZE` 기본 4) 순으로 봅니다. **수동 실행을 연타하지 않습니다.**

**Q. 리포트가 무한히 쌓입니다.**
`설정 > 리포트 관리`에서 자동 삭제 보존 기간을 정합니다. 정하지 않으면 누적됩니다.

**Q. 라이선스가 만료됐는데 정리 배치가 계속 돕니다.**
의도된 동작입니다. 정리 배치가 멈추면 만료된 설치본의 디스크가 무한정 찹니다. 정리 배치는 외부 수집 없이 자기 DB만 만집니다.

## 11. 라이선스·에디션

**Q. 라이선스가 꼭 필요한가요?**
네, 필수입니다. 설치 후 **7일 안에** `설정(⚙) > 라이선스`에 키를 등록합니다. 기간제와 영구 라이선스를 모두 지원하며, 호스트 대수 제한은 없습니다.

**Q. 에디션 차이는 무엇인가요?**
STANDARD는 통합 모니터링·이벤트·자산·비용·맵·클라우드·대상 관리·리포트·권한을 모두 포함합니다. PREMIUM은 여기에 **GPU 모니터링·DB 모니터링·APM**을 더합니다. STANDARD에 특정 기능만 추가 부여하는 구성도 가능합니다(판정 = 에디션 기본값 ∪ 개별 부여 기능). **[개발 중]**

**Q. 발급받고 며칠 뒤 등록하면 손해인가요?**
아니요. 유효 기간은 **등록일부터** 계산됩니다. 갱신도 등록일 기준입니다.

**Q. 만료되면 바로 잠기나요?**
단계적으로 좁힙니다. 만료 후 약 30일은 **읽기 전용**(실시간 모니터링 유지, 설정·편집 차단), 그 이후는 DB에 쌓인 데이터만 조회하고 외부 수집을 멈춥니다. 갱신 전에 진행 중인 편집을 마무리합니다.

**Q. 키를 등록했는데 거부됩니다.**
키 복사 시 줄바꿈·공백 혼입, 다른 설치본에서 이미 사용한 키(`jti` 재사용 방지), 발급 도구와 제품의 클레임 정의 버전 불일치 순으로 확인합니다. 한글이 포함된 발급 정보는 인코딩 문제로 깨질 수 있으니 발급 시 확인합니다.

## 12. 로드맵·계획 기능

**Q. Prometheus는 언제 붙나요?**
다중 소스를 위한 내부 구조(중립 포트·소스 레지스트리·능력 기반 메뉴)는 완성됐고 Prometheus 어댑터가 다음 단계(Phase 2)입니다. 일정은 협의가 필요합니다. **[예정]**

**Q. 여러 소스를 붙이면 같은 서버가 중복으로 보이나요?**
Phase 2에서는 소스별로 구분돼 보입니다. 같은 실물을 하나로 묶는 크로스 소스 식별은 그 다음 단계이며 초기에는 수동 매핑으로 시작할 계획입니다.

**Q. APM·DB·GPU 모니터링 메뉴가 보이는데 잠겨 있습니다.**
PREMIUM 기능입니다. APM은 OpenTelemetry Collector 기반으로 개요·서비스·수집기·알람 규칙, 트레이스 탐색·서비스 맵·에러·DB·외부 호출·배포, 합성 감시·SLO·메시징/배치·리포트, 브라우저 사용자 경험(RUM), 실시간 관제(선택 기능)까지 **[제공]** 됩니다. 로그 탭은 **[예정]** 입니다. DB·GPU 모니터링은 **[예정]** 입니다. 잠긴 메뉴는 라이선스에 해당 기능이 없다는 뜻이지 고장이 아닙니다. → [어플리케이션 모니터링](%ED%99%94%EB%A9%B4%EB%B3%84/%EB%AA%A8%EB%8B%88%ED%84%B0%EB%A7%81/solutions--%EC%95%A0%ED%94%8C%EB%A6%AC%EC%BC%80%EC%9D%B4%EC%85%98-%EB%AA%A8%EB%8B%88%ED%84%B0%EB%A7%81.md), [수집기 설치](%ED%99%94%EB%A9%B4%EB%B3%84/%EB%AA%A8%EB%8B%88%ED%84%B0%EB%A7%81/solutions--%EC%88%98%EC%A7%91%EA%B8%B0-%EC%84%A4%EC%B9%98.md)

**Q. 로그 검색은요?**
Elasticsearch 기반 로그 도메인으로 **[예정]** 입니다. 메트릭 소스가 아니라 별도 도메인으로 설계됩니다.

**Q. 수집기를 별도 서버로 분리할 수 있나요?**
현재는 애플리케이션과 같은 프로세스입니다. 망 구조·수집 부하·다른 언어 구현이 필요해지면 분리할 수 있도록 계약을 호환 가능하게 설계해 두었습니다.

## 13. 지원 요청 시 알려 주실 것

**비밀번호·토큰·라이선스 키는 절대 포함하지 않습니다.**

- 발생 시각(시간대 명시)과 환경(운영/검증)
