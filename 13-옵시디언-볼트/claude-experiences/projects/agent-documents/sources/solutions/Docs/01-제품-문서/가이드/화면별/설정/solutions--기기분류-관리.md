# 기기분류 관리

> **사이드바** 설정 > 기기분류 관리
> **경로** `/setting/device-classification`

## 무엇을 하는 화면인가

호스트·자산 화면에서 쓰는 **기기 분류 체계**를 관리한다. 서버·네트워크·스토리지처럼 조직이 장비를 구분하는 기준을 정의하는 곳이다.

분류는 단순한 라벨이 아니다. **감가상각 기본값**이 여기에 붙는다.

## 화면 구성

| 요소 | 내용 |
|---|---|
| 목록 | 분류 코드, 표시명, 색, 순서, 상태(활성/비활성), 시스템 여부 |
| 순서 조정 | 위로 이동 / 아래로 이동 |
| 동작 | 분류 추가 · 수정 · 삭제 |

각 분류에 **상각 기본값**(내용연수 등)을 지정할 수 있다.

## 분류가 저장되는 방식

🔴 **분류의 진실은 호스트 태그다.** 이 테이블은 표시명·색·순서·상각 기본값 같은 **메타 정보만** 갖는다.

그래서:

- 분류를 삭제해도 **호스트 데이터는 파괴되지 않는다**
- 삭제하면 그 분류를 쓰던 호스트는 **'분류되지 않음'** 으로 표시된다
- **같은 코드를 다시 등록하면 복구된다** (태그가 보존돼 있기 때문)

삭제 확인창에도 이 내용이 안내된다.

## 사용 흐름

1. 조직이 쓰는 분류 체계를 정의한다.
2. 순서를 조정한다 — 화면 표시 순서에 반영된다.
3. 분류별 상각 기본값을 지정한다.
4. 쓰지 않는 분류는 비활성화하거나 삭제한다.

## 주의할 점

### 상각 기본값 변경은 소급 적용된다

🔴 저장 전에 이런 확인창이 뜬다.

> "전체 N건 중 M건이 이 기본값을 사용합니다. **과거 기간의 비용 수치도 소급 반영됩니다.** 저장할까요?"

결산이 끝난 기간의 비용 수치까지 바뀐다. 재무 담당자와 협의 후 변경한다.

### 시스템 분류

시스템 분류는 **삭제하거나 비활성화할 수 없다.** 라벨·색·순서만 바꿀 수 있다.

### 코드 규칙

- 코드는 **대소문자를 무시하고 중복 검사**한다 (`SERVER`와 `server`는 같은 것으로 본다)
- 형식 규칙이 있으며 위반 시 안내가 뜬다

### 삭제 전 사용 현황 확인

삭제 확인창이 **이 분류를 쓰는 호스트 수**를 보여준다. 0대가 아니면 그 호스트들이 '분류되지 않음'이 된다는 뜻이므로, 대체 분류를 먼저 지정하는 편이 낫다.
