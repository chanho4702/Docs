# 서버 모니터링

> **사이드바** 모니터링 > 서버 모니터링
> **경로** `/monitoring/server-monitoring` → 상세·그래프 하위 경로

## 무엇을 하는 화면인가

서버 장비를 목록으로 보고, 개별 서버의 자원 사용 상태를 상세히 확인하는 화면이다.

## 화면 구성

### 목록

서버별 현재 상태와 주요 사용률을 표로 본다.

- **호스트 그룹 필터** — 담당 그룹만 좁혀 본다
- **조회 기간** — 집계 구간을 바꾼다
- **상태 표시** — 가용성과 이상 여부

### 상세

호스트 하나의 자원별 화면으로 들어간다.

| 영역 | 내용 |
|---|---|
| CPU | 사용률 추이 |
| 메모리 | 사용률, swap |
| 디스크 | 파일시스템별 사용률과 용량, 상세 표 |
| 네트워크 | 인터페이스별 트래픽 |
| 인터페이스 | 접점 정보와 상태 |
| 응답 시간 | 반응 지연 |
| 라이브 체크 | ping·에이전트 즉시 확인 |

## 사용 흐름

1. 호스트 그룹으로 범위를 좁힌다.
2. 사용률이 높은 순으로 정렬해 이상 후보를 찾는다.
3. 해당 서버 상세로 들어가 **어느 자원이 문제인지** 확인한다.
4. 조회 기간을 넓혀 일시적 스파이크인지 지속 추세인지 판단한다.

## 주의할 점

- **메트릭 하나가 비었다고 서버 장애로 단정하지 않는다.** 그 항목만 수집되지 않을 수 있다. 같은 서버의 다른 자원이 나오면 서버는 살아 있는 것이다.
- **디스크 상세가 비어 보일 수 있다.** 디스크 아이템 계열이 둘(`vfs.fs.size` / `vfs.fs.dependent`)이고 호스트마다 존재하는 계열이 달라서다. 차트에는 값이 있는데 상세 표가 비는 조합이 실제로 존재한다.
- **트래픽 단위는 bps다.** 바이트로 착각하면 수치를 약 800만 배 크게 읽게 된다.
- **라이브 체크의 두 축은 성격이 다르다.** `ping`은 서버가 직접 보낸 ICMP 결과이고, `agent`는 수집 시스템이 보고한 인터페이스 가용성이다. 둘이 어긋날 수 있으며, 그 자체가 정보다(네트워크는 되는데 에이전트가 죽은 상태 등).

## 권한 (ZM-157, 소스 반영·배포 전)

- **메뉴와 상세** — 역할에 서버 모니터링 보기 권한이 있어야 메뉴가 보인다. 호스트 상세는 서버 또는 네트워크 모니터링 중 하나의 보기 권한으로 열린다.
- **사용자 정의 차트** — 호스트 상세의 차트는 그 호스트를 보는 모든 사용자가 함께 쓴다. 그래서 **차트 추가·편집·삭제·배치 변경 버튼은 서버 또는 네트워크 모니터링 편집 권한이 있을 때만 보인다.** 기본 역할의 일반 사용자는 차트를 볼 수만 있다. 편집이 필요하면 관리자에게 역할 변경을 요청한다.
- **저장 중 권한이 바뀐 경우** — 편집하는 동안 권한이 회수되면 저장이 "권한이 없습니다"로 실패하고, 입력한 내용은 창에 그대로 남는다. 여러 차트를 한 번에 추가하다 일부만 저장됐다면 다시 시도할 때 남은 차트만 추가된다.
- **볼 수 없는 호스트** — 데이터 범위 밖의 호스트는 차트도 열리지 않는다.

자세한 기준은 [사용자 가이드 §7.1](../../solutions--%EC%82%AC%EC%9A%A9%EC%9E%90-%EA%B0%80%EC%9D%B4%EB%93%9C.md)과 [관리자 가이드 §3-7](../../solutions--%EA%B4%80%EB%A6%AC%EC%9E%90-%EA%B0%80%EC%9D%B4%EB%93%9C.md)을 본다.
