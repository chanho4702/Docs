🔴 화면에 보이는 것 ≠ 사용할 수 있는 것

가장 중요한 안내다. 네 소스가 모두 화면에 나오지만, 실제로 연결되는 것은 Zabbix 하나다.

나머지 셋의 워크스페이스에 들어가면 화면이 직접 이렇게 알린다.

"{공급자} 관리 화면은 UI 미리보기입니다. 공급자 고유 운영 개념과 화면 구조만 먼저 확인할 수 있습니다. 실제 조회·저장·연결 성공 처리는 백엔드 어댑터가 준비될 때 활성화됩니다."

목록 화면에도 명시돼 있다 — "런타임 어댑터가 설치된 소스만 실제 저장할 수 있습니다."

고객 시연에서 오해가 생기기 쉬운 지점이므로, 담당자는 이 차이를 먼저 설명한다.

왜 억지로 통합하지 않는가

워크스페이스 화면의 설명이 설계 의도를 그대로 담고 있다.

"공급자마다 다른 운영 모델을 억지로 통합하지 않고, MovesEye 안에서 일관된 진입 경험만 제공합니다."

메트릭·인벤토리·알람 같은 공통 도메인은 정규화하지만, 소스 고유의 관리 개념(Zabbix 템플릿, Prometheus 서비스 디스커버리)은 각자의 모습으로 둔다. 억지로 하나로 만들면 어느 쪽에서도 정확하지 않은 화면이 된다.

주의할 점

비밀번호는 화면에 다시 나오지 않는다

저장된 비밀값은 응답에 실리지 않는다. 수정 시 비워 두면 기존 값이 유지되고, 입력했을 때만 교체된다. 다른 항목만 고치려고 비밀번호 칸을 비워도 기존 연결이 끊기지 않는다.

전용 계정을 쓴다

사람이 함께 쓰는 계정을 넣지 않는다. 비밀번호가 바뀌면 제품 전체가 멈추고, 감사 로그에서 행위자를 구분할 수 없다.

연결이 끊기면 전 화면이 영향받는다

이 설정이 잘못되면 모니터링·이벤트·자산 화면이 동시에 비게 된다. 특정 화면만 비는 것과 구분되는 증상이다.
