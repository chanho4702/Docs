# 사용자 관리

> **사이드바** Zabbix 관리 > 사용자 관리
> **경로** `/zabbix-management/users-roles`

## 무엇을 하는 화면인가

사용자 계정과 권한을 관리하는 화면이다. **제품에서 가장 신중하게 다뤄야 할 설정**이다 — 누가 무엇을 볼 수 있는지가 여기서 정해진다.

## 화면 구성

### 탭 3개

| 탭 | 내용 |
|---|---|
| **사용자** | 계정 등록·수정·활성 상태 |
| **사용자 역할** | 기능 권한 묶음 정의 |
| **사용자 그룹** | 사용자 묶음과 **호스트 그룹 데이터 범위** 연결 |

## 권한의 두 축

🔴 **이 구조를 이해하지 못하면 반드시 문제가 생긴다.**

| 축 | 통제 대상 | 설정 위치 |
|---|---|---|
| **기능 권한** | 어떤 메뉴·기능을 쓸 수 있나 | **사용자 역할** 탭 |
| **데이터 범위** | 어떤 호스트 그룹을 볼 수 있나 | **사용자 그룹** 탭 |

두 축은 **곱해진다.**

- 기능 권한만 주면 → **메뉴는 보이는데 목록이 텅 빈다** (가장 흔한 신고)
- 데이터 범위만 주면 → 메뉴 자체가 안 보인다

## 사용 흐름 — 새 사용자 추가

**순서가 중요하다.**

1. **역할을 먼저 만든다** (또는 기존 역할을 고른다).
2. **사용자 그룹**을 확인한다 — 어떤 호스트 그룹을 볼지.
3. 사용자를 만들면서 역할과 그룹을 붙인다.

역할 없이 사용자부터 만들면 계정마다 권한을 개별 조정하게 되어 곧 관리가 무너진다.

## 역할 설계 권고

처음부터 세밀하게 쪼개지 말고 3~4개로 시작한다.

| 역할 | 기능 권한 | 데이터 범위 |
|---|---|---|
| 시스템 관리자 | 전체 | 전체 |
| 운영자 | 모니터링·이벤트 조회 + acknowledge | 담당 그룹 |
| 자산 담당자 | 자산·비용 편집 | 전체 또는 담당 사업장 |
| 조회 전용 | 전 영역 조회만 | 담당 그룹 |

## 주의할 점

### 삭제보다 비활성화

퇴사·전배는 **비활성화**가 기본이다. 삭제하면 그 사용자가 남긴 감사 로그와 자산 변경 이력의 행위자 추적이 끊긴다. 비활성화는 로그인만 막고 이력을 보존한다.

### Zabbix 계정 동기화

이 화면은 Zabbix 사용자와 제품 사용자를 연결한다. **계정 동기화와 제품 내 권한은 별개**다 — Zabbix에서 계정을 가져와도 제품의 역할·데이터 범위는 따로 지정해야 한다.

🔴 **자동 동기화 배치(`user_sync`)는 기본적으로 꺼져 있다.** 켜면 Zabbix에 없는 로컬 계정이 **삭제될 수 있다.** 제품에서만 만든 계정을 쓰고 있다면 켜기 전에 반드시 백업한다.

### 권한은 화면 숨김이 아니다

메뉴를 숨기는 것은 편의일 뿐이며, 서버가 다시 검증한다. 우회 접근은 막힌다.
