# MovesEye 문제 해결 가이드

> 증상에서 출발해 원인을 좁히는 문서다. 서버가 아예 안 뜨는 상황은 **설치·배포 가이드 §10**과 **로컬·검증 Runbook §7**을 본다.

## 0. 진단의 대원칙

문의를 받으면 이 세 가지를 먼저 가른다. 여기서 방향이 갈리고, 건너뛰면 엉뚱한 곳을 판다.

1. **한 사람만 그런가, 전원이 그런가** — 한 사람이면 권한, 전원이면 연동·서버
2. **한 화면만 그런가, 전 화면이 그런가** — 한 화면이면 해당 데이터, 전 화면이면 인증·Zabbix 연결
3. **빈 값인가, 오류인가** — 빈 값은 대개 권한이나 미수집, 오류는 연동이나 계약 문제

> 🔴 **"성공 메시지"를 근거로 삼지 않는다.** 이 제품에서 실패는 HTTP 200으로 내려올 수 있고, 배치의 부분 실패는 성공으로 기록되며, 비동기 업로드는 접수만 해도 성공 응답을 준다. **실제 반영된 데이터를 눈으로 확인**하는 것이 유일하게 믿을 만한 판정이다.

## 1. 로그인·세션

### 로그인은 되는데 새로고침하면 로그아웃된다

리프레시 토큰이 **HttpOnly 쿠키**로 오가는데 쿠키가 저장·전송되지 않는 상황이다.

| 확인 | 조치 |
|---|---|
| HTTPS인데 `COOKIE_SECURE=false`인가 | `true`로 |
| FE와 BE가 다른 도메인인가 | `COOKIE_SAME_SITE` 조정 |
| 브라우저가 서드파티 쿠키를 차단하는가 | 동일 도메인 배포 또는 프록시 경유 |

### 401이 반복되고 화면이 무한 로딩된다

세션 만료 상태에서 **알림 벨 폴링**이 계속 401을 받는 알려진 이슈다. 사용자에게는 로그아웃 후 재로그인을 안내한다. 반복 재시도는 상황을 악화시킬 뿐이다.

확인 순서: 액세스 토큰 만료 → 리프레시 쿠키 존재 → Redis 세션 → **서버 시간**. 서버 시간이 어긋나면 발급 즉시 만료된 토큰이 나온다.

### 특정 사용자만 로그인이 안 된다

계정이 비활성화(`INACTIVE`)됐을 가능성이 높다. 관리자 화면에서 상태를 확인한다.

## 2. 화면이 비어 보인다

이 제품에서 가장 흔한 문의다. **"비었다"는 최소 네 가지 원인**을 가진다.

### 2-1. 메뉴는 보이는데 목록이 텅 비었다

**호스트 그룹 데이터 범위 권한이 없다.** 기능 권한(메뉴 접근)과 데이터 범위(볼 수 있는 호스트 그룹)는 별개 축이고, 기능 권한만 주면 정확히 이 증상이 난다.

관리자에게: 사용자 그룹 ↔ 호스트 그룹 권한을 확인한다(**관리자 가이드 §3-1**).

### 2-2. 메뉴 자체가 안 보인다

역할의 기능 권한에 해당 키가 없다.

### 2-3. 차트만 비었다

**관측값 없음**일 가능성이 높다. 실제 0과 구분해야 한다.

확인 순서:
1. 같은 호스트의 다른 메트릭은 나오는가 → 나오면 호스트는 살아 있다
2. 해당 아이템이 그 호스트에 존재하는가 (아이템 렌즈에서 확인)
3. 아이템이 활성 상태이고 최근 수집됐는가
4. 조회 기간이 수집 이력 범위 안인가

**메트릭 하나가 비었다고 호스트 전체 장애로 단정하지 않는다.**

### 2-4. 전 화면에서 호스트가 안 보인다

Zabbix 연동 자체가 끊겼다. 설정 > 연동 정보의 URL과 전용 계정을 확인한다. 계정 비밀번호가 바뀌었거나 계정이 잠긴 경우가 많다.

### 2-5. 지리 맵에 호스트 후보가 0건이다

**자산 최초 동기화를 하지 않았다.** 동기화 전에는 자산의 `linked_hostid`가 비어 있어 후보가 잡히지 않는다. 자산 관리 > 목록에서 동기화를 한 번 실행한다.

기능 고장으로 오인하기 쉬운 대표 사례다.

## 3. 데이터가 이상하다

### 트래픽 수치가 터무니없이 크다

**`net.if.in/out`은 bps 원값**이다. 바이트 단위 포매터를 적용하면 약 940만 배로 부풀려진다. 화면에서 이런 수치가 보이면 해당 위치의 포매터가 잘못된 것이다(비트레이트 포매터, SI 1000 단위를 써야 한다).

### 디스크 차트에는 나오는데 상세 표가 비었다

디스크 아이템 계열이 둘(`vfs.fs.size` / `vfs.fs.dependent`)이고 호스트마다 존재하는 계열이 다르다. 상세 조회에 계열 폴백이 들어가 있으나, 두 계열 모두 없는 호스트라면 표는 빈다.

### 값이 갑자기 달라졌다

메트릭 조회에 **폴백 체인**이 끼면 값이 바뀔 수 있다. 실제로 메모리 사용률이 폴백 때문에 0에서 11로 바뀐 사례가 있다. 최근 릴리스에서 해당 메트릭의 아이템 키가 바뀌지 않았는지 확인한다.

### 정렬 순서가 이상하다

Zabbix의 정렬은 **대소문자를 구분하는 코드포인트 순**이다. 사람이 기대하는 사전순과 다르다. 대문자로 시작하는 이름이 소문자보다 앞에 온다.

### 시각이 9시간 어긋난다

서버는 **UTC로 고정 실행**된다. 날짜 처리가 UTC 전제이므로 정상 동작이다.

## 4. 저장·수정이 안 된다

### 저장했다는데 값이 원복됐다

**Zabbix가 원천인 필드를 고쳤고, 다음 동기화가 덮어썼다.** 제품이 소유하는 보강 필드와 Zabbix 원천 필드는 편집 결과의 수명이 다르다. 수정 화면의 안내를 따른다.

영구히 유지해야 하는 값이라면 MovesEye 소유 필드에 넣어야 한다.

### 태그를 하나 추가했더니 나머지가 사라졌다

Zabbix `update`의 **배열 전체 교체** 때문이다. 제품 화면은 현재 값을 읽어 전체를 다시 보내는 방식으로 이를 막는다. 폼에 채워진 기존 값을 임의로 지우지 않는다.

이미 사라졌다면 Zabbix 감사 로그나 제품의 변경 이력에서 이전 값을 확인해 복구한다.

### 수정 요청이 "인증 오류"로 표시된다

Zabbix의 파라미터 검증 실패(`-32602`)가 과거 401로 매핑돼 인증 오류처럼 보인 회귀가 있었다. 현재는 `create`/`update`에서 400으로 매핑된다. 여전히 401로 보인다면 회귀를 의심하고 실제 요청 파라미터를 확인한다.

### 필드를 비웠는데 지워지지 않는다

부분 수정에서 **필드 미포함**(변경 없음)과 **빈 문자열**(값 지우기)은 다르다. 지우려면 빈 문자열을 명시적으로 보내야 한다.

## 5. 비용·업로드

### CSV 업로드가 성공했는데 반영이 안 됐다

**비동기 처리다.** 업로드 성공은 "접수됨"이지 "처리 완료"가 아니다. 진행 중 작업 상태를 확인한다.

### 정확히 10MB인 파일이 거부된다

파일 상한 10MB, 요청 상한 11MB로 여유를 두었으므로 정상적으로는 통과해야 한다. 거부된다면 multipart 설정이 변경됐는지 확인한다. 두 값을 같게 맞추면 이 증상이 재발한다.

### 업로드가 끝나지 않는다

새 업로드를 제출하지 않는다(활성 작업 유니크 제약에 걸린다). 작업의 heartbeat를 확인해 실제로 진행 중인지 멈춘 것인지 판정한다. 멈춘 작업 정리는 승인된 절차로만 한다.

### 감가상각 값이 과거와 다르다

파라미터를 바꾸면 **현재 파라미터 기준으로 소급 재계산**된다. 과거 시점 스냅샷을 보존하지 않는 설계다. 의도된 동작이다.

## 6. 배치·동기화

### 배치가 성공인데 데이터가 일부만 반영됐다

**부분 실패는 성공으로 기록되고 요약 문자열에만 남는다** (`ok=38 fail=2`). 실행 이력의 요약을 읽는다.

### 배치가 안 도는 것 같다

1. 설정에서 활성화돼 있는가, cron 표현식이 의도대로인가
2. 마지막 실행 시각이 주기 안인가
3. 다른 무거운 배치와 겹쳐 스레드 풀에서 대기 중인가 (`SCHEDULER_POOL_SIZE` 기본 4, 등록 배치 7개)

**수동 실행을 연타하지 않는다.** 이전 실행이 아직 도는 중일 수 있다.

### 로컬 사용자 계정이 사라졌다

`SYNC_ENABLED=true` 상태에서 `user_sync`가 돌면 **Zabbix에 없는 로컬 사용자를 제거**할 수 있다. 기본값이 `false`인 이유다. 백업에서 복구하고 설정을 되돌린다.

### 라이선스가 만료됐는데 정리 배치는 계속 돈다

의도된 동작이다. 정리 배치가 멈추면 만료된 설치본의 디스크가 무한정 찬다. 정리 배치는 외부 수집을 하지 않고 자기 DB만 만진다.

## 7. 라이선스

### 등록했는데 거부된다

- 키를 복사할 때 줄바꿈·공백이 섞이지 않았는지
- 이미 다른 설치본에서 사용된 키가 아닌지 (`jti` 재사용 방지)
- 발급 도구와 제품의 클레임 정의 버전이 맞는지 — 저장소가 분리돼 있어 한쪽만 갱신되면 "발급은 되는데 제품이 거부"하는 상태가 된다

### 갱신했는데 기간이 손해 본 것 같다

유효 기간은 **등록일부터** 계산된다. 발급받고 며칠 뒤 등록해도 손해가 없다.

### 만료 후 쓰기가 막혔다

정책대로다. 만료 후 약 30일은 읽기 전용(EXPIRED)이고 그 이후는 저장된 데이터만 조회(ARCHIVED)한다. 갱신 전에 진행 중인 편집을 마무리해야 한다.

## 8. 개발·검증 환경 특유의 함정

지원 담당자가 재현을 시도할 때 겪는 것들이다. **제품 결함으로 오진하기 쉽다.**

| 함정 | 실체 |
|---|---|
| Git Bash `curl -d`에 한글을 인라인으로 넣으면 500 | cp949로 인코딩돼 나간다. **제품 결함이 아니다.** 파일이나 `\uXXXX`, Node fetch로 재확인 |
| PowerShell에서 한글 인자·BOM 없는 스크립트 | 같은 계열의 인코딩 함정 |
| 브라우저 자동화 탭에서 도넛 차트가 멈춰 보임 | 자동화 탭은 `visibilityState=hidden`이라 `requestAnimationFrame`이 안 돈다. **렌더 버그가 아니다.** 정적 레이아웃 검증은 신뢰 가능 |
| 테스트가 갑자기 줄어듦 | 대량 파일 이동 후 증분 빌드 착시. `clean test`로 재확인 |
| 빌드가 이유 없이 실패 | 전역 `JAVA_HOME`이 JDK 8을 가리킴. JDK 17 명시 |
| 화면 이동 시 선택 상태가 초기화됨 | 라우트 전환마다 페이지가 리마운트된다. 페이지의 데이터 결정 상태는 URL 쿼리로 유지해야 한다(설계 제약) |

## 9. 지원 요청 시 포함할 정보

문의를 올릴 때 다음이 있으면 진단이 빨라진다. **비밀번호·토큰·키는 절대 포함하지 않는다.**

- 발생 시각(타임존 명시)과 환경
- 사용자 계정의 **역할과 호스트 그룹 권한 범위**
- 영향 범위: 나만 / 특정 그룹 / 전원
- 화면 경로와 조회 조건(기간·필터)
- 실패한 요청의 `errorCode`와 `message` (HTTP 상태만으로는 부족하다)
- 최근 변경 사항(배포·설정 변경·Zabbix 변경)
- 재현 절차
