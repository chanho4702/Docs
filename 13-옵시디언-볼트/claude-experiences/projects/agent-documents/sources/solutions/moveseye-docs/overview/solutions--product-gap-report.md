# 전 제품 문제점·보완점 종합 리포트

[기능별 상세 가이드 색인](../guides/features/solutions--README.md) · [APM 부족점 리포트(10-05)](solutions--apm-gap-report.md) · [문서 허브](../solutions--README.md)

> **2026-10-06 후속(정정 대기):** 이 문서는 BE `e55948c` 기준 본문을 그대로 보존하고 있습니다. 작성 이후 확인된 사항은 아직 본문에 반영하지 않았습니다. ① APV-01(원문 노출)은 BE `aab73fc`에서 해소됐습니다. ② 독립 검수에서 높음 28건 중 5건은 중간으로 내리고(MON-01·MON-02·AST-03·ZOP-01·APC-02) MAP-11은 높음으로 올리자는 의견이 나왔습니다. ③ 5.2절 "결정이 먼저 필요한 것" 중 다수는 설계서·계약서·ADR에 이미 결정 기록이 있습니다. ④ 5.1절의 수정 묶음은 한 번에 넣지 말고 나누라는 의견이 있습니다. 정정 목록과 재분류한 작업 계획은 [후속 백로그](../../_workspace/features/product-docs/product-docs/solutions--backlog_product-gap-2026-10-06.md)와 [검수 의견](../../_workspace/_archive/features/product-docs/product-docs/solutions--review_feature-guides-2026-10-06_codex.md)을 먼저 확인하세요.

**판정: 기능의 폭은 충분하지만, "화면에 보이는 숫자가 맞는가"와 "저장한 것이 그대로 남는가"를 먼저 손봐야 한다.** 13개 영역에서 문제점 309건(높음 28 · 중간 161 · 낮음 120)을 찾았다. 높음 28건 중 절반 가까이는 수정 범위가 작고 원인이 분명하다. 나머지는 제품 정책 결정이나 실제 Zabbix·AWS 환경 확인이 먼저 필요하다.

이 리포트는 영역별 문서의 4절을 한곳에서 볼 수 있게 묶은 것이다. 항목의 현상·영향·보완 제안·완료 조건·근거 코드 위치는 각 문서에 있고, 여기서는 **우선순위와 영역을 가로지르는 공통 원인**만 다룬다. 아래 순서는 분석 제안이며, 착수 결정을 대신하지 않는다.

## 1. 범위와 증거 수준

| 항목 | 내용 |
|---|---|
| 기준 | 2026-10-06 작업 디렉터리. BE `moveseye-be-spring` master `e55948c`, FE `moveseyee_fe` master `9dfcbe8`, AI `moveseye-ai` main `6eef23c`, Flyway V69 |
| 방법 | 화면 → 훅 → API 클라이언트 → Controller → Service → 저장소·외부 호출·배치를 따라가는 정적 코드 대조. 기존 가이드·계약·설계·감사·백로그와 교차 확인 |
| 하지 않은 것 | 서비스 기동, API 호출, 테스트 실행, 부하 시험, 실제 Zabbix·AWS·LLM 연동, 브라우저 렌더 확인 |
| 재확인 | 높음 28건은 작성자와 별도로 핵심 근거 코드를 다시 열어 서술과 일치함을 확인했다. 중간·낮음 항목은 작성 시 확인에 의존한다 |

증거 수준은 세 가지로 구분한다. **코드 확인**은 이번에 소스를 열어 본 사실이다. **기존 기록**은 과거 감사·검수 문서의 내용이다. **추론**은 확인한 구조에서 예상되는 영향이며 발생 빈도와 크기는 재지 않았다. 따라서 아래 항목은 "코드가 이렇게 되어 있다"는 사실이지 "운영에서 장애가 났다"는 사실이 아니다.

## 3. 높음 28건

성격에 따라 넷으로 나눴다. "다음 행동"은 **수정**(원인과 고칠 곳이 분명함), **결정**(의도된 설계인지 정책 판단이 먼저), **실측**(외부 시스템의 실제 반응 확인이 먼저), **구조**(설계 변경이 필요한 규모 과제) 중 하나다.

### 3.1 화면의 숫자가 틀리거나 빠진다

| ID | 현상 | 발생 조건 | 다음 행동 |

## 4. 영역을 가로지르는 공통 원인

개별 수정으로 닫을 수 있지만, 같은 원인이 여러 영역에서 반복된다. 공통 규칙을 한 번 정하면 재발을 줄일 수 있다.

### 4.1 Zabbix의 "전체 교체" 의미를 부분 전송으로 호출한다

`host.update`의 `interfaces`·`tags`, `hostgroup.massupdate`, `user.medias`는 보낸 목록으로 통째 교체된다. 화면이 일부만 알고 일부만 되돌려 보내면 나머지가 사라진다. ZCF-01·02가 대표이고, 비활성 분류 태그가 저장 때 사라지는 ZCF-04, 동시 편집 감지가 없는 ZCF-03, 액션 오퍼레이션 왕복 검증 기록이 없는 ZOP-09가 같은 계열이다. LLD 검수(R1~R7) 때 정리한 "받은 그대로 되돌리되 바꾼 필드만 덮는다"는 규칙을 호스트·그룹 수정에도 적용하는 것이 방향이다.

### 4.2 Zabbix 아이템 키·단위 가정이 화면마다 다르다

같은 지표를 목록과 상세가 다른 키로 읽거나(MON-08·09), 단위 변환을 한쪽에서만 한다(MON-01·02·05, CLD-12). 기기분류 판정도 변종이 넷이다(MAP-02의 근거 주석). 지표 정의(키 폴백 순서·단위·변환)를 `ZabbixMetricCatalog` 한곳에서 답하게 하고, 화면은 단위를 응답에서 받는 구조가 필요하다.

### 4.3 조회 실패와 "없음"·"0"을 구분하지 않는다

리전 조회 실패가 "자원 없음"으로(CLD-04), 권한 없음이 "정상"과 같은 회색 핀으로(MAP-07), 조회 실패가 0으로 그려진다(AST-13, HOME-03, MON-07). 사본이 멈춰도 화면 표시가 없다(EVT-19). 응답에 부분 실패·잘림·기준 시각을 싣고 화면이 그것을 표시하는 공통 규약이 필요하다. APM 화면 자기설명에서 이미 만든 "빈 값 이유" 방식을 다른 영역으로 넓히는 것이 가장 가깝다.

### 4.4 서비스 계정 토큰과 사용자 권한의 경계

쓰기·실행 기능 여러 곳이 MovesEye 관리자 판정 뒤에 Zabbix 슈퍼 관리자 토큰으로 동작한다(ZOP-01, APC-03, SEC-02). 반대로 사용자 토큰으로 계산한 결과를 공용으로 저장하는 곳도 있다(MON-03). "누구의 권한으로 읽고 쓰는가"와 "그 결과를 누구에게 보여 주는가"를 기능마다 명시해야 한다. 자산·비용·맵처럼 권한 축이 아예 없는 조회(AST-01, SEC-08·09, MAP-11)는 의도된 예외인지 결정이 먼저다.

### 4.5 전량 조회 후 메모리 필터

호스트 5천·아이템 1천만 가정에서, 요청마다 전 호스트나 기간 내 전량을 받아 앱에서 거르는 경로가 여러 영역에 남아 있다. EVT-04·05, MON-12, HOME-06·07, ZCF-06·07·12·13, ZOP-03·06, AST-14, CLD-02·03, APV-06·08, MAP-12·13이다. 2026-09-16 대용량 감사에서 지적된 항목 다수가 아직 유효하다. 영역별 문서가 "기존-유효"로 표시해 두었으므로, 감사 문서의 티켓과 묶어 관리하면 된다.

### 4.6 노드 로컬 상태 — BE를 2대 이상 띄우면 갈린다

SSE 허브(EVT-15), APM 라이브·예산·누적형 직전값(APC-02, APV-04), AI 대화 캐시(AI-07), 클라우드 짝짓기 색인·플릿 캐시(CLD-08), 기기분류 레지스트리(ZCF-21), 스케줄 변경 반영과 30분 고정 잠금(OPS-09)이 프로세스 메모리에 있다. 현재 단일 인스턴스 배포에서는 드러나지 않는다. 전체 목록은 [설정과 운영 기반](../guides/features/solutions--%EC%84%A4%EC%A0%95%EA%B3%BC-%EC%9A%B4%EC%98%81-%EA%B8%B0%EB%B0%98.md) 3절에 있다. 다중화 계획이 생기면 이 목록이 선행 작업 범위다.

### 4.7 시간대 전제가 흩어져 있다

배치 실행 시각을 서버 시간대로 해석하는데 화면에 표시가 없고(OPS-05), UTC 전제가 Dockerfile 진입점 옵션에만 있다(OPS-06). 리포트 경계는 UTC 고정(MON-13, APV-21), 통계 날짜 구분은 DB 세션 시간대(EVT-18), 점검 기간은 화면마다 다르다(ZOP-07). 클라우드(CLD-23)·AI(AI-15)·자산(AST-23)도 같다. 설치형 제품이므로 "저장은 UTC, 표시는 사용자 시간대, 일 단위 경계는 설치본 설정 시간대" 같은 한 줄 규칙과 그 설정 위치가 필요하다.

### 4.8 변경 감사 기록이 영역마다 다르거나 없다

Zabbix 구성 변경은 `zabbix_change_log`에 남지만 조회 화면과 보존 규칙이 없다(ZOP-05, ZCF-10). 로그인·계정·역할·라이선스(SEC-11), 설정 변경·배치 수동 실행(OPS-14), 클라우드 자격증명·유료 스위치(CLD-17), APM 알람 규칙·SLO(APC-10), 맵 삭제(MAP-11)는 기록이 없다. AI 질문 원문은 반대로 무기한 보존된다(AI-11). 공통 감사 표 하나와 조회 화면이 여러 항목을 함께 닫는다.

### 4.9 메뉴·주소 정의가 여러 곳의 사본이다

사이드바·모바일·전역 검색·AI 화면 목록이 각각 메뉴를 정의해 서로 어긋난다(HOME-08·13, MAP-20, AST-25, APV-20). 화면 도움말의 주소 매칭 누락(HOME-10)과 AI 화면 카탈로그의 옛 주소 잔존도 같은 원인이다. 메뉴 정의의 단일 원천을 두고 나머지가 그것을 읽게 하면 문서 drift도 함께 줄어든다.

### 4.10 설치형 운영 준비

메일 설정 매핑 소실(OPS-01)과 Zabbix 환경 변수 매핑 소실(OPS-02)은 설치 가이드가 안내하는 값이 코드에서 읽히지 않는 상태다. 무인증 헬스 엔드포인트가 없고(OPS-11), 배포 스크립트의 정지 대기 시간이 graceful 종료 시간보다 짧으며(OPS-12), 설치 번들과 운영 프로필이 없다(OPS-13). 배치 실패를 알리는 수단도 없다(OPS-08). 고객사 설치가 늘기 전에 설치·배포 가이드와 코드를 한 번 맞춰야 한다.

## 7. 이 리포트의 한계

- 정적 대조만 했다. "영향"은 구조에서 미루어 본 것이며, 운영에서 실제로 발생했다는 뜻이 아니다.
- 문제점 수는 영역 간에 일부 겹친다. 예를 들어 스케줄러 주기 소실은 EVT-10과 OPS-04에, 자산 조회 권한은 AST-01과 SEC-09에, 구 지도 화면의 토큰은 MAP-15·AST-16·SEC-26에 각각 적혀 있다. 합계 309건은 중복을 빼지 않은 수다.
- 중간·낮음 항목은 높음 항목과 같은 수준으로 재확인하지 않았다. 착수 전에 해당 문서의 근거 코드를 다시 여는 것을 전제로 한다.
- 전체 코드를 한 줄씩 본 감사가 아니다. 각 문서 6절에 읽지 않은 클래스와 확인하지 못한 동작을 적었다.
- 실제 배포 환경의 설정값(환경 변수, 프록시, 시간대)은 보지 않았다.
