🔴 핵심 사실: **Zabbix 공식 DB 템플릿 7종 전부 집계치만**. **PG `EXPLAIN`(ANALYZE 없이)도 `ExecCheckPermissions`로 테이블 권한 검사**, MySQL `EXPLAIN`도 실행 권한 동일 → 모니터링 계정으로 재계획 불가 → **GA 플랜 = Oracle `V$SQL_PLAN`·MSSQL `dm_exec_query_plan` 캐시만(D13)**. Datadog은 SECURITY DEFINER 함수·`dd_session` 뷰·XE 세션으로 풀지만 **우리는 전용 객체를 만들지 않는다(D14)**. **PG `pg_stat_statements`는 한 DB 접속으로 서버 전체**(D15). **Datadog RAC는 노드별 V$ + 필요 시 GV$**. OTel은 DB 모니터링에 **필수 아님**(J1 환경, 보조 경로 O1은 R7 뒤). Redis는 `INFO`에 `commandstats·latencystats` 포함, Zabbix 템플릿은 slowlog 건수만; MongoDB `locks/globalLock`는 L(blocker 관계) 보증 아님.

결정: 심층 = **BE 내장 JDBC 폴러** · Zabbix = 호스트 상관·발견·`history.push` 배달 · 세션 5s · Oracle V$ 허용목록(프로필별)·ASH/AWR 금지 · D13·D14·D15·D16(`maxDbTargets`, Q22) · 만료(EXPIRED)부터 폴러 정지 · Flyway **V90부터**(착수 시 재확인) · 패키지 `premium/dbm/` · **Redis·MongoDB·ClickHouse 비범위 유지, 재개는 Q31 신규 제안(순서·Phase·공수 미정)**.
