# 설계 — APM 서비스 맵 v2 (FE 재설계, ZM-122)

작성 2026-09-16. 대상은 **FE만**이다 — 계약(`GET /apm/service-map`)은 그대로 쓰고 BE 변경은 없다.
현행 구현: `pages/application-monitoring/service-map/*`(v1, WBS 6.6·7.15, 설계 §3.14).

## 1. 무엇이 문제인가 (실측 2026-09-16, dev)

| 관측 | 수치 |
|---|---|
| 노드 | 25개 — SERVICE 3 · DB 1 · **HTTP 21** |
| HTTP 21개의 정체 | 대부분 `ec2.<region>.amazonaws.com` — **같은 대상의 리전 변형** |
| 엣지 | 45개, `requests` 2,374 ~ 51 |
| 캔버스 | 높이 560px 고정. 같은 랭크에 21개가 쌓여 필요 높이 ≈ 1,760px |
| 결과 | fitView가 3배 이상 축소 → **라벨이 하나도 안 읽힌다** |

즉 "서비스가 많아서"가 아니다. **외부 의존이 노드 수를 지배**하고, 세로로 쌓인 한 열이 배율을
끌어내린다. 서비스가 10개가 되면 외부 노드는 100개를 넘는다.

두 번째 문제는 **엣지 굵기**다. 1.2~8px 제곱근 스케일이라 상위 경로 하나가 굵은 다발이 되어
화면을 덮고, 정작 굵기 차이로 값을 읽지는 못한다.

## 3. 노드 축소

### 3.1 외부 도메인 묶기

HTTP 노드의 라벨(호스트명)에서 **등록 도메인**을 뽑아 같은 도메인끼리 한 노드로 접는다.

- 규칙: 마지막 두 레이블. 단 `co.kr`·`com.au`·`co.jp`·`com.br` 같은 2차 도메인이면 세 레이블.
- IP·`localhost`·포트만 있는 호스트는 **묶지 않는다**(도메인이 아니다).
- 같은 도메인이 **2개 이상일 때만** 묶는다. 하나뿐이면 접어도 이득이 없고 이름만 뭉개진다.
- 그룹 노드: 라벨 `amazonaws.com`, 배지에 하위 개수. `incoming`·`outgoing`은 합.
- 🔴 **합쳐진 엣지의 p95는 비운다.** 서로 다른 대상의 백분위를 합칠 방법이 없다 — 호출 수와
  오류율(합/합)만 정확하다. 화면은 그 자리에 `—`와 "여러 대상의 합" 안내를 둔다.
- 펼치기: 그룹 노드를 누르면 그 그룹만 개별 노드로 전개. 상태는 **URL**(`?mapOpen=a,b`) —
  이 앱은 navigate마다 페이지를 리마운트하고([[fe-page-remount-on-navigate]]), 무엇보다
  "이 화면 그대로"를 링크로 건넬 수 있어야 한다(엣지 선택이 이미 URL에 있다).

### 3.2 종류별 구역

서비스 / 데이터베이스 / 외부 / 큐를 **배경 구역**으로 가르고 구역마다 접을 수 있게 한다.

- dagre는 그대로 쓴다(호출 방향이 랭크를 만든다). 구역은 dagre 결과 위에 **배경과 라벨**로 얹는다.
- 접기는 필터 바의 종류 토글과 같은 상태다 — 구역을 접으면 그 종류의 노드와 엣지가 빠진다.
- 🔴 접힌 종류 때문에 **끊긴 엣지는 그리지 않는다**. 한쪽 끝이 없는 화살표는 "어디론가 나간다"로
  읽히는데 그건 사실이 아니다(v1의 `droppedEdges` 안내를 같은 방식으로 재사용).

## 4. 호출량 표현 — 굵기에서 흐름으로

| 무엇 | 어떻게 |
|---|---|
| 굵기 | **전부 1.6px 고정**. 선택·호버일 때만 2.6px |
| 호출량 | **흐름 속도 + 점선 간격**. 많을수록 빠르고 촘촘하다 |
| 오류율 | 색(기존 `APM_ERROR_RATE_BANDS` 유지) |
| p95 | 엣지 라벨(기존) — 필터 바에서 라벨 축을 rps로 바꿀 수 있다 |

- 속도는 5단계로 접는다(제곱근 비율 → `0.5s ~ 2.4s`). 연속값을 쓰면 옆 엣지와 구분이 안 되고
  CSS 애니메이션 수만 늘어난다.
- 🔴 `prefers-reduced-motion`이면 애니메이션을 끄고 **점선 간격만** 남긴다. 움직임에 민감한
  사용자에게 맵 전체가 떨리는 화면이 된다.
- 🔴 엣지가 120개를 넘으면 **상위 40개만** 흐르게 한다. 전부 움직이면 어디를 봐야 할지 알 수 없고
  저사양 기기에서 프레임이 떨어진다.

## 5. 검색과 필터

필터 바(캔버스 위 한 줄). **전부 URL 쿼리**에 산다.

| 컨트롤 | 파라미터 | 동작 |
|---|---|---|
| 노드 검색 | `mapQ` | 이름 부분일치. 맞는 노드는 강조, 나머지는 흐리게(**감추지 않는다** — 맥락이 사라진다) |
| 종류 | `mapKinds` | 서비스·DB·외부·큐 토글(구역 접기와 같은 상태) |
| 오류만 | `mapErrors` | 오류율 > 0인 엣지와 그 끝점만 남긴다 |
| 최소 호출 | `mapMinReq` | 그 값 미만의 엣지를 감춘다(꼬리 잘라내기) |
| 엣지 라벨 | `mapLabel` | p95 / 호출수 / 없음 |
| 서비스·env | 기존 툴바 | 그대로(서비스는 1홉 이웃) |

- 필터가 하나라도 켜져 있으면 **해제 버튼**을 띄운다(트레이스 필터 바와 같은 규칙).
- 🔴 필터로 0건이 되면 빈 캔버스가 아니라 "필터에 걸린 것이 없다"를 말한다 — "데이터가 없다"와
  다른 상태다.

## 6. 캔버스

- 기본 높이 560 → **720**.
- **전체화면 버튼** — 차트 카드(`ApmChartCard`)와 같은 모달 패턴을 쓴다. 맵은 크게 볼수록 읽힌다.
- 범례를 고쳐 쓴다: 굵기 설명을 빼고 **흐름 속도 = 호출량 · 색 = 오류율**을 적는다.

## 8. 하지 않는 것

- **레이아웃 저장**: 저장 EP가 없다(계약 §10.1). v1의 각주를 그대로 둔다.
- **BE 변경**: 도메인 묶기는 화면의 판단이라 FE에서 한다. 서버가 묶으면 "원래 호스트가 무엇이었나"를
  화면이 되돌릴 수 없다.
- **노드 자동 숨김**: 임계는 사용자가 정한다. 화면이 조용히 지우면 "없는 것"과 구분되지 않는다.
