# 디자인 시스템 정비 — 진단과 개선안

작성 2026-08-18. 대상 `moveseyee_fe`. 트리거: "모니터링 시스템에 맞게 디자인을 손보자 / 차트가 중요하니 색상 팔레트를 두고 쓰자".

색은 **팔레트 파일 하나(`src/constants/palette.ts`)** 에서만 정의하고, 화면과 차트는 그 상수를 참조한다는 것이 이 문서의 결론이다.

---

## 1. 진단

측정이 가능한 항목은 색차 검증기(OKLab ΔE, 색각이상 시뮬레이션, 대비비)로 실측했다. 아래 수치는 추정이 아니라 실행 결과다.

### D1. 🔴 브랜드 색 스케일이 깨져 있다 — 호버하면 색상축이 바뀐다

`constants/colors.ts`의 `COLOR` 50~900은 **파란색 램프**인데 `500`만 브랜드 teal(`#379e9f`)이 들어가 있다.

```
50 #e0f1ff · 100 #b0d2ff · 200 #7fb0ff · 300 #4d8bff · 400 #1e79fe
500 #379e9f  ← teal (혼자 다른 색)
600 #0062b3 · 700 #004f81 · 800 #003650 · 900 #001620
```

`colorPrimary=500`, `colorLinkHover=300`, `colorLinkActive=700`으로 묶여 있으므로 **버튼·링크가 기본은 teal, 호버는 파랑, 누르면 진한 파랑**이 된다. 의도된 배색이 아니라 스케일 오염이다.

### D2. 🔴 색이 66개 파일에 하드코딩되어 같은 의미의 색이 화면마다 다르다

`#[0-9a-f]{6}` 직접 사용 파일 66개. 실제로 같은 뜻인데 값이 갈린 예:

| 의미 | 실사용 값 |
|---|---|
| 브랜드 teal | `#379e9f` · `#5fa6a1` · `#56dbc3` |
| 강조 파랑 | `#1677ff` · `#1e79fe` · `#0062b3` |
| 위험 빨강 | `#ff4d4f` · `#f5222d` · `#cf1322` · `#9e0911` · `#A20025` · `#E45959` |
| 보조 회색 | `#8c8c8c` · `#bfbfbf` · `#94a3b8` · `#a6a6a6` |

### D3. 🔴 차트 시리즈 색에 규칙이 없다 (제품 핵심 결함)

시계열 차트는 `useHandelChartAction`에서 옵션을 만드는데 **series에 색을 지정하지 않는다** → ECharts 기본 팔레트가 그대로 나온다. 결과:

- 같은 CPU 지표가 화면·차트마다 다른 색으로 그려진다.
- 시리즈가 늘거나 필터로 줄면 **살아남은 시리즈의 색이 이동한다**(색이 대상이 아니라 순번을 따라간다).
- 비용 화면만 자체 팔레트(`COST_CHART_COLORS`)를 따로 갖고 있어 제품 안에 팔레트가 두 개다.

### D4. 🔴 심각도 색이 색만으로는 구분되지 않는다

현재 Zabbix 표준 6색(`#97AAB3 #7499FF #FFC859 #FFA059 #E97659 #E45959`)을 흰 배경에서 측정한 결과:

```
[FAIL] 명도 대역      #FFC859, #FFA059 가 대역 밖(너무 밝음)
[FAIL] 인접 색차      재해 #E45959 ↔ 높음 #E97659 : ΔE 6.3 (기준 15)
[FAIL] 색각이상 분리  같은 쌍 ΔE 4.8 (deutan)
[WARN] 배경 대비      경고 #FFC859 = 1.54:1, 보통 #FFA059 = 2.01:1
```

**관제에서 가장 중요한 "재해 vs 높음"이 정상 시야에서도 구분되지 않는다.** 노랑·주황은 흰 배경 위 얇은 선·작은 점으로 쓰면 사실상 보이지 않는다.

대안 색을 여러 조합으로 재탐색했지만, 경고~재해 4단계가 노랑→주황→빨강 한 축에 몰려 있어 **어떤 값을 골라도 기준을 통과하지 못했다**(최선 ΔE 10.1). 따라서 결론은 색 교체가 아니라 **이중 인코딩(색 + 라벨/아이콘) 강제**다.

### D5. 다크 모드가 토글만 있고 실질 지원이 아니다

`themeSlice` + antd `darkAlgorithm`은 붙어 있으나, D2의 하드코딩 색들이 그대로 나오므로 다크에서 대비가 깨진다. 게다가 토글 스위치는 `checked = (theme === light)`에 `checkedChildren=🌙`이라 **라이트 모드일 때 달 아이콘**이 켜진다(의미 반전).

### D6. 한국어 UI인데 한글 폰트를 지정하지 않았다

`fontFamily: "Lato, sans-serif"` — Lato에는 한글 글리프가 없다. 따라서 한글은 전부 브라우저 기본 폴백(Windows: 맑은 고딕)으로 렌더되고, 굵기·자간이 통제되지 않는다. 화면 대부분이 한글인 제품에서 타이포그래피가 사실상 미설계 상태다.

### D7. 배경/카드의 계층 표현이 약하다

라이트 배경은 antd 기본 `#f5f5f5`, 카드는 흰색이었는데 카드 테두리가 `#E7EAF3B2`(반투명) — 흰 배경 위 대비 **약 1.1:1**로 사실상 보이지 않는다. 배경을 흰색으로 바꾸면 면으로도 선으로도 카드가 구분되지 않게 된다.

### D8. 유틸리티 CSS에 규칙이 없다

`App.css` 882줄에 `!important`가 반복되고, 타이포 스케일(`--text-xs`~`--text-9xl`)은 정의만 있고 어디에 무엇을 쓰는지 규칙이 없다. `.text-high`, `.text-average` 같은 의미 색이 팔레트가 아니라 CSS에 따로 박혀 있다.

## 2. 팔레트 정본 (`src/constants/palette.ts`)

검증기를 통과한 값만 채택했다.

| 그룹 | 용도 | 비고 |
|---|---|---|
| `BRAND` | 강조(버튼·링크·선택) | `primary #379e9f`. 차트용은 `primaryChart #0f9b9b` — 원 브랜드색은 채도(OKLCH C 0.093)가 낮아 선·점으로 그리면 회색으로 읽혀 검증 실패 |
| `SURFACE` | 페이지·카드·경계 | 페이지 `#ffffff`, 경계 `#E5E7EB` |
| `INK` | 텍스트 | 값·라벨·범례는 **시리즈 색을 입지 않는다** |
| `NAV` | 사이드바 | 딥 slate-teal `#0F2E33` |
| `CHART_SERIES` | 차트 카테고리 8슬롯 | 흰 배경 전 항목 PASS (최악 인접 CVD ΔE 13.6) |
| `METRIC_COLOR` | CPU/메모리/디스크/네트워크 고정색 | 화면이 달라도 같은 지표는 같은 색 |
| `CHART_SEQUENTIAL` | 연속량(히트맵 등) | 단일 색조 7단계 |
| `CHART_AXIS` | 격자·축·툴팁 | 데이터보다 뒤로 물러남 |
| `SEVERITY` | 심각도 — 면(태그·칩) | Zabbix 표준색 유지(관제자가 Zabbix 콘솔과 같은 색으로 읽어야 함) |
| `SEVERITY_STRONG` | 심각도 — 선·점·텍스트 | 대비 확보 변형. **라벨 동반 필수** |
| `HEALTH` | 가용성 정상/주의/장애/미상 | 심각도와 분리 |

### 규칙

1. 컴포넌트에 hex를 직접 쓰지 않는다. 팔레트에 역할 이름으로 추가하고 참조한다.
2. 차트 시리즈는 `CHART_SERIES` 순서대로 **고정 배정**한다. 9번째 시리즈는 새 색을 만들지 말고 "기타"로 묶거나 차트를 나눈다.
3. 색은 **대상**을 따라가고 순번을 따라가지 않는다. 필터로 시리즈가 줄어도 살아남은 시리즈의 색은 그대로다.
4. 상태색은 시리즈 색으로 재사용하지 않는다.
5. 심각도는 **색 단독 사용 금지** — 항상 라벨 또는 아이콘과 함께 쓴다.
6. 축은 하나만 쓴다(이중 Y축 금지). 단위가 다른 지표는 차트를 나눈다.

### P1·P2에서 실제로 바뀐 것

- **브랜드 축 통일** — 버튼·링크의 hover/active가 파랑으로 튀지 않는다. `Segmented` 선택색(팔레트 밖 `#5fa6a1`)도 브랜드로 회수.
- **차트 시리즈 색 배정** — `assignSeriesColors()`가 (1) 의미 고정 지표는 항상 같은 슬롯, (2) 나머지는 남은 슬롯 순서대로(한 차트 안 색 중복 없음), (3) 인터페이스별 반복 시리즈는 순서 배정. CPU/메모리/디스크/네트워크가 화면이 달라도 같은 색이 된다.
- **방향 규칙** — `BPS_IN/PPS_IN`=파랑, `BPS_OUT/PPS_OUT`=주황으로 통일.
- **차트 크롬 정리** — 격자 `#ccc`(선보다 눈에 띄었다) → 옅은 회색, 축선·축라벨·범례 글자를 잉크 색으로, 툴팁에 테두리·그림자, 면적 채움 `opacity 0.15`, 선 두께 2px.
- **심각도 색 표 3중 중복 제거** — geoMap·networkMap·zabbix-trigger가 각자 갖고 있던 같은 표를 `SEVERITY_BY_CODE` 하나로.
- **DSpin 버그** — `background-color: "#379e9f"`처럼 따옴표가 붙어 있어 CSS로는 무효였다(스피너가 브랜드색이 아니라 antd 기본색으로 돌고 있었다). CSS 변수로 교체하며 해결.
- 검증: 타입체크 통과, 린트 통과(기존 테스트 파일 3건의 룰 정의 오류는 선재 이슈), Jest 109 스위트 / 896 테스트 전부 통과.

### P3에서 실제로 바뀐 것

심각도는 색만으로 구분할 수 없다는 진단(D4)에 맞춰, **색을 보조로 내리고 라벨을 본체로** 만들었다.

- **공용 `SeverityTag`** (`components/StatusBadge/SeverityTag.tsx`) — 코드("0"~"5")든 이름(`DISASTER`)이든 받아 색+라벨을 항상 함께 낸다. 라벨 없는 심각도 표시는 더 이상 만들지 않는다.
- **색 표가 4벌이었다** — Zabbix 원색(트리거·지도), antd 프리셋 2종(그룹 알림추이는 재해=분홍, 공용 StatusBadge는 재해=`#A20025`), 리포트 셀 배경. 전부 하나로 합쳤다.
- **글자 대비** — antd `<Tag color="#hex">`는 글자를 무조건 흰색으로 칠한다. 경고(밝은 앰버) 위 흰 글자는 **2.15:1**이었다. `readableTextOn()`이 배경 밝기를 재서 고르게 했고, 이제 전 등급이 **4.4:1 이상**이다.
- **리포트 표 셀** — 재해 셀은 `#A20025` 배경에 어두운 글자라 대비 **1.79:1**(읽을 수 없음), 높음도 3.98:1이었다. `SEVERITY_SOFT`(옅은 면 전용, 등급이 오를수록 진해짐)로 교체해 전부 **8.8:1 이상**.
- **라벨을 달 수 없는 자리** — 지도 핀·네트워크맵 노드 뱃지는 핀 안에 호스트 수가 들어가 라벨 자리가 없다. 여기는 명도 차가 큰 `SEVERITY_STRONG`을 쓰고, 색↔등급 대응은 지도의 severity 필터가 범례 역할을 한다.
- **심각도 스택 차트** — 알림추이 막대는 시리즈가 곧 심각도인데 일반 카테고리 색(파랑/주황)이 나오고 있었다. `TMonitorChart.color`를 추가해 심각도 색으로 그린다.
- **지도 핀 상세** — 심각도 컬럼이 라벨 없이 원값 `"0"~"5"`를 그대로 노출하고 있었다. 라벨로 교체.
- **한국어 라벨 통일**(사용자 승인) — 공용 배지는 "분류되지 않음/평균/위험", 알람 화면은 "미분류/보통/재해"로 갈려 있었다. Zabbix의 Average는 심각도 등급이지 평균이 아니므로 **"평균"은 오역**이었다. 최상위 i18n 키를 `alert_severity.*`와 일치시켜 어느 키를 쓰든 같은 문구가 나온다(영어는 원래 동일).
- 검증: 타입체크·린트 통과, Jest 109 스위트 / 896 테스트 통과(라벨 키가 바뀐 테스트 기대값 2건 갱신).

### P4에서 실제로 바뀐 것

- **Pretendard를 번들로 싣는다** — CDN이 아니라 npm 패키지(`pretendard@1.3.9`, OFL). 이 제품은 고객사 설치형이라 폐쇄망에서도 떠야 한다. 기존 Lato는 Google Fonts CDN 링크였고, 폐쇄망에서는 그 요청이 실패해 렌더만 지연시켰다.
- **dynamic subset** — `unicode-range`로 92조각으로 쪼개져 있어, 화면에 실제로 뜬 글자의 조각만 내려받는다(조각당 30~44KB). 빌드 산출물에는 3.1MB가 들어가지만 런타임 전송량은 그 일부다.
- **폰트 스택 정본은 `TYPOGRAPHY.fontSans` 하나** — `--font-sans` CSS 변수로 주입되고, antd `ConfigProvider`와 `index.css`가 그 변수를 참조한다.
- **한글용 타이포 보정** — 자간 `-0.01em`(한글은 기본 자간이면 성기게 보인다), 행간 1.6(antd 기본 1.5714는 라틴 기준이라 받침이 눌린다).
- **고정폭 숫자** — 표·통계·페이지네이션에 `tabular-nums`. 값이 주기적으로 갱신되는 모니터링 화면에서 비례폭 숫자를 쓰면 같은 자리 숫자가 바뀔 때마다 폭이 변해 표가 떨린다.
- **ECharts 테마 등록**(`lib/echarts/theme.ts`) — 차트는 canvas라 CSS 폰트가 상속되지 않아, 지정하지 않으면 축·범례만 다른 글꼴로 그려진다. 테마에 폰트와 팔레트·축·툴팁 기본값을 넣어 8개 차트 인스턴스에 걸었다.
  - 이 과정에서 기존 `theme={mytheme}`(값이 `"light"`/`"dark"`)가 **ECharts에 등록되지 않은 이름이라 무시되고 있던 무효 코드**임을 확인하고 교체했다.
- **타이포 스케일 사용 규칙**을 `index.css`에 명문화 — 어느 단계를 어디에 쓰는지, 한 화면에서 4단계를 넘기지 않는다.
- 검증: 타입체크·린트 통과, Jest 896 테스트 통과, 프로덕션 빌드 성공.

### P5에서 실제로 바뀐 것

다크는 계속 지원하기로 결정. 토글만 있고 실질 지원이 아니던 상태를 정리했다.

- **팔레트가 모드별 두 벌**(`LIGHT`/`DARK`) — 다크는 라이트를 자동 반전한 값이 아니라 어두운 바탕에 맞춰 따로 고른 값이다(자동 반전은 채도가 튀고 대비가 무너진다). 다크 차트 8색은 어두운 바탕(#141414) 기준으로 명도대역·채도·색각이상 분리·대비 **전 항목 검증 통과**.
- **팔레트를 구독형 스토어로** — `usePalette()`가 `useSyncExternalStore`로 팔레트 모듈을 직접 구독한다. 리덕스에 묶지 않은 이유: 색은 스토어 없이도 읽혀야 하고, `useSelector`를 쓰면 Provider로 감싸지 않은 컴포넌트(단위 테스트 다수)가 전부 터진다(실제로 66개 테스트가 깨져서 알았다).
  - 훅을 쓸 수 없는 자리(순수 함수·모듈 상수)는 `getPalette()`, 스타일시트는 CSS 변수 — 모드가 바뀌면 `setPaletteMode`가 변수를 다시 주입한다.
- **다크에서 깨지던 것들** — 심각도/상태 태그의 옅은 파스텔이 어두운 바탕에서 흰 덩어리가 되던 것을 같은 색상의 어두운 면으로 뒤집었다(글자 대비 5.56~7.92). 스크롤 헤더의 흰 반투명 막, 알림 읽지 않음 배경, 구분선, 강제 검정 글자도 CSS 변수로 회수.
- **ECharts 테마 2벌 등록** — 모드에 따라 테마 이름이 바뀌고, 이름이 바뀌면 인스턴스가 다시 만들어져 축·격자·툴팁까지 새 색으로 그려진다.
- **토글 의미 반전 수정** — `checked`가 "라이트인가"였는데 켜짐 아이콘은 달이라, **라이트 모드에서 달이 켜진 것처럼** 보였다. 이제 켜짐이 곧 다크다.
- `colorScheme`을 문서 루트에 지정해 스크롤바·폼 컨트롤 등 브라우저 기본 UI도 모드를 따라간다.
- 검증: 타입체크 통과, 린트 경고 0(기존 테스트 파일 룰 정의 오류 3건은 선재), Jest 896 테스트 통과, 프로덕션 빌드 성공.

### P6에서 실제로 바뀐 것

- **사이드바 하위 메뉴 계층 표시**(사용자 요청) — 부모와 자식이 같은 바닥색이라 펼쳤을 때 어디까지가 자식인지 읽히지 않았다. 하위 묶음을 한 단 눌러 어둡게 깔고(3단 깊이는 두 단), 왼쪽에 안내선을 세우고, 펼쳐진 부모 항목에 옅은 배경을 줬다. 셀렉터는 `.side-nav`가 아니라 메뉴 자체(`.nav-menu`)에 건다 — 모바일 메뉴는 Drawer(portal)라 레이아웃 하위가 아니다.
- **맵 편집기 색 17개 파일 회수** — 인라인 style에는 CSS 변수를 그대로 쓸 수 있어(`color: "var(--ink-muted)"`) 훅 없이도 모드 전환이 자동 반영된다. 편집기 전용 역할은 팔레트에 `EDITOR`(선택 표시·노드 기본색·노드 테두리·틴트 바탕·안내선)로 정의했다. 선택 표시는 브랜드 teal, 노드 기본색은 파랑 — 겹치지 않아 선택 상태가 구분된다.
- 🔴 **CSS 변수가 통하지 않는 두 자리**를 찾아 되돌렸다:
  - `LinkLayer`의 링크 기본색 → MapLibre 레이어의 paint 속성으로 들어간다. 지도 렌더러는 CSS를 해석하지 않아 색이 통째로 빠진다.
  - `pinElement`의 핀 테두리 → SVG **속성**(attribute)이라 `var()`가 해석되지 않는다(인라인 style이었다면 됐다).
  - 둘 다 `getPalette()`로 실제 값을 읽게 했다.
- **App.css 의미 색 회수** — `.text-secondary`/`.text-average`/`.text-high` 등이 팔레트 밖 hex를 들고 있던 것을 CSS 변수로. 상태색(`--health-*`)도 변수로 노출했다.
- 검증: 타입체크 통과, 린트 경고 0, Jest 901 테스트 통과.

### 화면 도움말 — AI와 합치지 않는다 (2026-08-20 결정)

같은 화면 설명이 두 벌 있다: FE 도움말(`page_guide` 10개, 한/영)과 AI 서버의 화면 카탈로그
(`screens.json` 30개, `summary`+`howto`, 영어만). 한쪽만 고치면 AI와 도움말이 다른 말을 하게 되므로
합치자는 제안이 나올 수 있다 — **합치지 않기로 했다.**

**Why:** 도움말의 대상이 **AI를 쓰지 않는 고객**이다. 그 환경에는 AI 서버(:3100)가 아예 없다.
한 벌로 묶으면 어떤 형태로든 의존이 생기고, 그때 손해 보는 쪽이 정확히 이 도움말이 필요한 고객이다.
정본은 FE에 두고, 두 벌이 어긋나는 비용은 감수한다.

**How to apply:** 화면 설명을 고칠 때 두 곳을 함께 본다. 도움말에 "AI에게 물어보기" 같은 출구를
두지 않는다(그 고객에겐 눌러도 아무 데도 가지 않는 버튼이 된다).
