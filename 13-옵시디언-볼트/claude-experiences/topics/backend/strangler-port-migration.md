# 레거시 결합 해체 — 포트/어댑터 스트랭글러 실전 노트

한 외부 시스템(여기선 Zabbix)에 도메인 전체가 물려 있는 코드베이스를 **동작을 바꾸지 않으면서** 포트 뒤로 밀어 넣는 방법. moveseye 수집 엔진 Phase 1(6일·25+ 커밋·Java 504파일 중 45%가 결합)에서 검증됐다. → [[2026-07-28-collector-engine-phase1]]

## 착수 전

1. **결합도를 실측하라.** "몇 % 파일이 벤더를 참조하나 / 벤더 ID(`hostid` 등)가 도메인 밖 몇 파일에 누수됐나". 이 숫자가 논의를 전송 계층(gRPC 쓸까)에서 **도메인 모델 추상화**로 옮긴다.
2. **군집을 나눠라.** 추상화 가능한 것(읽기 메트릭·인벤토리·알람)과 **불가능한 것**(벤더 DSL이 UI까지 노출되는 관리 CRUD, IdP 역할)을 먼저 분리하고, 후자는 "전용 계약"으로 당당히 남긴다. 전부 추상화하려다 아무것도 못 옮기는 게 최악.
3. **불변식을 하나 정하라.** 여기선 "REST 응답 불변" — 이게 있으면 기존 E2E가 안전망이 되고 FE 작업이 0이 된다.

## 진행 중

- **스텝 하나 = 커밋 하나.** 되돌릴 단위가 곧 판단 단위다. 각 스텝의 완료 기록(무엇을 옮겼고 무엇을 보류했고 왜)을 설계서에 누적하면, 며칠 뒤 재개할 때 "왜 이건 안 옮겼지"를 다시 논쟁하지 않는다.
- 🔴 **런타임 전/후 응답 diff가 진짜 그물이다.** 컴파일·단위 테스트를 전부 통과하고도 값이 바뀐 사례가 반복해서 나온다: 폴백 체인이 만든 값 변화, 벤더의 대소문자 구분 정렬, 중첩 삼항의 `int`/`Integer` 언박싱 NPE, `Map.of().get(null)` NPE. 응답 채집 스크립트를 초반에 만들어 두면 매 스텝 재사용된다.
- **불변식은 응답에만 적용되는 게 아니다** — 배치가 DB에 쓰는 값(문자열 `"0"` 표기 등)도 같은 기준으로 봐야 한다.
- **경계 판단 기준: "이 값이 답하는 질문이 무엇인가."** 벤더 개념이면 전용, 어느 소스에서도 물을 수 있는 질문이면 중립. 이 기준을 잡으니 "트리거 상세는 전용, 조치 가능 여부는 중립"처럼 한 객체 안에서도 선이 그어졌다.
- **쓰기 계약은 서술적 명령 + 명시적 대상**으로. 대상을 필터로 고르게 하면(예: "조건에 맞는 알람 전부 ack") 포트가 벤더 쿼리 언어를 다시 빨아들인다.
- **원칙이 목표를 막으면 원칙의 비용을 재라.** "계약 층에 웹 의존을 두지 않는다"는 원칙 때문에 의존 차단이 불가능해졌을 때, enum 하나 때문에 `spring-web`을 계약 모듈에 넣는 쪽을 택했다(계약 변화 0). 순수성보다 차단이 값졌다.

## 마무리 — 경계를 "증명"하기

- **컴파일 의존을 끊어라**(Gradle `runtimeOnly` 등). 규약·리뷰가 아니라 **빌드가 강제**해야 유지된다.
- 🔴 **차단됐다는 증거는 "빌드가 성공했다"가 아니라 "의도한 것이 깨진다"이다.** 구현 타입을 참조하는 프로브 클래스를 넣어 `package does not exist`로 빌드가 실패하는 것을 확인하고 지웠다.
- 🟢 **패키지명을 유지하고 모듈만 옮기면 이동은 사실상 공짜다** — git이 `rename (100%)`로 인식하고 소비자 import가 한 줄도 안 바뀐다. "어디에 두느냐"와 "뭐라 부르느냐"는 다른 결정이고, 후자를 같이 건드리면 diff에서 이동과 실제 변경이 섞여 리뷰가 불가능해진다. (단, 모듈 간 split package가 남으므로 정리 스텝을 따로 잡을 것.)
- ⚠️ **대량 이동 뒤에는 `clean test`** — 증분 빌드는 안 돈 테스트를 사라진 것처럼 보여준다(586→552 착시).
- ⚠️ **모듈화는 배포 파이프라인을 조용히 깨뜨린다** — Dockerfile·CI가 단일 모듈을 가정하고 있다.

## 다음 소스를 붙일 때 (검증 단계)

두 번째 소스 연결은 "기능 추가"가 아니라 **"정규화 모델이 첫 소스에 오염됐는지 검증"** 이다. 계약이 깨지면 실패가 아니라 발견이며, **모델 수정 예산을 미리 잡아 둘 것**. 검증 방식도 달라진다 — 기존 소스는 무회귀 비교, 새 소스는 "화면이 성립하는가"라는 신규 검증이라 둘을 분리해서 봐야 한다.
