# 북 스터디는 어떻게 이루어지는가

## 기본 구조

대부분의 북 스터디는 아래 사이클을 반복한다.

1. **분량 지정** — 매주(격주) 읽어올 챕터/페이지를 미리 합의
2. **각자 읽기 + 정리** — 모임 전까지 전원이 해당 분량을 읽고 요약·질문거리 준비
3. **발제(발표)** — 담당자가 핵심 내용을 요약 발표
4. **토론** — 질문·코멘트·적용 아이디어 공유
5. **기록** — 논의 내용을 공개된 곳(노션, 위키, GitHub 등)에 남김

## 발제자 선정 방식

| 방식        | 특징                                                        |
| ----------- | ----------------------------------------------------------- |
| 순번제      | 부담이 예측 가능. 자기 차례가 아니면 느슨해질 수 있음       |
| 당일 랜덤   | 전원이 발표 준비를 해오고 당일 룰렛으로 선정 → 집중도 상승  |
| 자유 발제   | 읽으며 인상 깊었던 부분을 각자 자유롭게 공유. 진입장벽 낮음 |

## 토론을 살리는 장치

- 발표 후 **전원이 최소 3개**(질문 / 새로 배운 것 / 중요하다고 느낀 부분)를 공유하는 규칙
- 책과 연결된 **실습 세션** 추가 (개발서라면 코드로 직접 확인)
- 매 모임 끝에 **짧은 회고** — 오늘 얻은 인사이트 한 줄씩
- 스터디 중간 지점에 **운영 방식 자체를 회고**하고 규칙 조정

## 운영 팁

- **인원**: 8명 이하 (피자 2판 법칙). 많으면 발언 기회가 줄어 참여도 하락
- **규칙은 명료하게**: 지각·결석·미준비 페널티(벌금, 커피 등)를 시작 전에 합의. 규칙이 명료할수록 책임감·참여도가 올라감
- **모임 형태**: 주 1회 온라인 화상 기본 + 2~3주에 한 번 오프라인을 섞는 하이브리드가 흔함
- **산출물 남기기**: 매 모임마다 눈에 보이는 결과물(정리 문서, 체크리스트, 액션 아이템)이 있으면 만족도와 지속률이 올라감
- **성공 기준 명시**: "완독"인지 "업무 적용"인지 목표를 시작 전에 정해야 중도 이탈이 줄어듦
