버그 하나를 고칠 때 **주석 블록·부가 UI·테스트를 리포 관례에 맞춘다며 필요 이상으로 늘리지 않는다.**

**Why:** 팀장 후보 목록 결함 수정에서 사용자가 "뭔가 과하게 코드 짜는거 같은데"라고 지적했다.
이 리포는 기존 파일들의 주석 밀도가 매우 높아 그대로 따라가면 수정량이 실제 변경보다 커진다 —
관례를 따르는 것과 부풀리는 것은 다르다.

**How to apply:**
- 결함 수정의 본체는 **원인을 없애는 최소 변경**이다. 배경 설명은 "왜 이렇게 됐는지"가
  코드만 봐선 복원 불가능할 때만 남기고, 3~4줄로 끝낸다.
- 테스트는 **회귀 가드가 되는 불변식**만 — 케이스를 채우려고 늘리지 않는다.
- 자료구조 순회는 리포에 이미 있는 패턴을 쓴다(`flatMap` 평탄화 등).
  중첩 루프가 3단이 되면 대개 중간 단계가 헛도는 것이다 — 사용자가 이것도 짚었다.
- 부가 UI(경고 배너·카운터)는 요청에 없으면 넣기 전에 값어치를 따진다.
