# 이슈 맵 — 2차 요구사항 (2026-09-02, dev 실화면 확인 후 사용자 피드백)

사용자 원문 요지: "세로 배치 말고 가로 배치. 하위 항목은 연결 선. 간트에서 정의한 연결 관계도 표시하되 하위 이슈는 실선, 연결 이슈는 점선. 간트에서 디렉토리(폴더) 정의했으면 폴더도 표시. 최상단 루트는 항상 프로젝트 이름 카드."

## 1. 배치 방향: 위→아래 트리(조직도형)
- 루트가 **맨 위**, 자식은 **아래 행**, 형제는 **옆으로 나란히**(가로). 현재 구현(좌→우, 형제 세로 쌓기)을 뒤집는다.
- 부모 Bottom(source) → 자식 Top(target). 부모 x = 자식 블록의 수평 중앙. 행 y = depth × (issueHeight + gapY). 폴더(56px)는 행 상단 정렬.
- 형제 순서·접힘 규칙(접힌 서브트리는 노드/엣지 미생성)은 그대로.

## 2. 프로젝트 루트 카드 (항상 존재)
- 합성 노드 `project:<project_id>`, 타입 `projectRoot`, depth 0. `buildWorkTree` 루트 배열 전체가 이 노드의 자식.
- 표시: 프로젝트 이름(`findProjectById` → `rows[0].project_name`, 쿼리키 `findProjectByIdQueryKeys(project_id)` — 상세 페이지와 같은 키라 캐시 공유), 전체 이슈 수·폴더 수. 틸 강조의 뚜렷한 카드(이슈 카드와 구분).
- 접을 수 없음(항상 펼침). 클릭해도 드로어 없음.
- 이름 로딩 전/실패 시 폴백 라벨(i18n).

## 3. 엣지 2종
- **계층(부모→하위)**: 실선. 기존 그대로.
- **의존(간트 연결 관계)**: **점선** + 화살표. 출처는 `useGanttData`의 `links`(이슈 Blocks 링크)와 `folderLinks`(폴더 링크). 가시성 규칙은 `GanttPage.jsx`와 동일 — 이슈 링크는 양 끝점이 필터 통과 이슈, 폴더 링크는 양 끝점이 실제 SVAR 노드. 여기에 더해 **양 끝점이 현재 레이아웃에 존재(펼쳐져 보이는) 노드**일 때만 그린다.
- 순수 함수 `buildDependencyEdges(links, folderLinks, visibleNodeIds)` → jest.
- 핸들: 계층은 상/하, 의존은 좌/우(`dep-in`/`dep-out`)로 분리해 선이 겹치지 않게. 의존 엣지 색은 계층보다 약하게(`color.border.bold` 계열), 선택 노드에 닿은 엣지는 틸 강조(기존 규칙 유지).
- 캔버스 구석 범례: 실선=하위, 점선=선후행.

## 4. 폴더 노드
- 폴더는 이미 `folderGroup` 노드로 존재. **초기 펼침 규칙 변경**: 프로젝트 루트 + 모든 폴더 노드는 펼침, 자식이 있는 이슈 노드만 접힘. (사용자가 "폴더가 안 보인다"고 느낀 원인 = 루트만 펼침이라 상위 이슈 아래 폴더가 숨어 있었음)
