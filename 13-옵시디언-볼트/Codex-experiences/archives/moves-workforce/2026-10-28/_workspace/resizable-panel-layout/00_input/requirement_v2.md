# 요구사항 v2: 패널 레이아웃 — 접기 버튼 상단 이동 + 3개 화면 확산

> 2026-08-12. v1(배정 화면 적용, RFC-185 커밋 완료) 사용 피드백 기반 보완.
> 사용자 원문 요지: "선 위에 버튼 있는 거 킹받는다, 상단에 버튼 만들자. My Work랑 작업 배정 페이지, 작업 관리 트리에도 적용해줘."

## 1. 접기 버튼 위치 변경 (v1 UX 수정)

- 현재: 핸들(경계선) 위에 ◀/▶ 버튼 — 사용자가 명확히 불호.
- 요구: **접기/펼치기 버튼을 패널 상단으로** 이동. 형태는 설계 판단(각 패널 우상단 아이콘 버튼, 또는 패널 그룹 상단 툴바 등)이되:
  - 배정 화면 패널들은 Card 헤더(`headerRight`에 SearchInput 등)가 이미 있음 — 충돌 없이 얹힐 것
  - 접힌 레일 상태에서도 펼치기 버튼이 명확할 것 (레일 자체 클릭으로 펼침도 고려)
  - 핸들은 순수 리사이즈 전용으로 단순화
- 공개 API 변화가 생기면 하위 호환 유지 또는 v1 적용처(배정 화면) 동시 갱신.

## 2. 확산 적용 3개 화면

| 화면 | 위치 | 현재 구조 (설계 시 실코드 확인) |
|------|------|------|
| My Work | `pages/myWork/` (WorklogPage, `/myWork`) | 좌 MyProjectList / 우 워크로그 영역 분할 |
| 작업 배정 탭 | `pages/projectDetail/assignment/` (프로젝트 상세 > 인력 > 작업 배정) | 작업 큐 / 후보 패널 등 다분할 (WorkQueuePanel·CandidatePanel) |
| 작업 관리 트리 뷰 | `pages/projectDetail/work/` 트리 뷰 (WORK_VIEWS.md 참조) | 좌 트리 구조 / 우 상세(TreeDetailPanel) |

- 각 화면의 기존 데이터 흐름·훅 무변경 원칙은 v1과 동일 (레이아웃만 감싸기).
- storageKey는 화면별 고유 키.
- 각 화면의 접기 대상·최소폭·기본 가중치는 설계에서 실코드 기반으로 정한다.
- 화면 구조가 ResizablePanels에 안 맞는 곳(예: 이미 다른 분할 메커니즘)이 있으면 설계에서 사유와 함께 제외 가능 — 억지 적용 금지.

## 3. 비목표

- 간트 하단 잘림은 별도 트랙에서 처리(이 요구사항 범위 아님).
- 세로 분할, 패널 재정렬, 그 외 화면 확산.

## 검증 포인트

- v1 화면(배정) 회귀 없음 + 버튼 위치 변경 반영
- 신규 3개 화면: 접기/펼치기·드래그·상태 유지 동작, 데이터 흐름 무회귀
- 전체 테스트·CI 빌드·번들 예산
