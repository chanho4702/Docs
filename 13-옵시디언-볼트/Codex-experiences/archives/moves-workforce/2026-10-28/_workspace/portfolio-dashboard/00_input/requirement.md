# 전사 통합 대시보드 (Portfolio Dashboard) — 요구사항

> 작성: 2026-06-01 · 슬러그 `portfolio-dashboard` · 초기 실행
> 관련 기존 자산: [[2026-05-29-progress-page]] 진척도 3층, ProgressCalculator, 워크로그 전용 병렬 페처, MM 재설계, KVS 캐시 패턴

## 1. 목적

기존 분석/진척 화면은 모두 **프로젝트 1개 범위**(`/project/:id` 내부)다.
PMO/경영진이 **모든 프로젝트를 한 화면에서** 인력·공수·진척·리스크 관점으로 조망할 상위 뷰가 없다.
→ 전 프로젝트를 가로지르는(across) **전사 통합 대시보드**를 신규 최상위 화면으로 신설.

## 2. 확정 결정 (사용자, 2026-06-01)

| 항목 | 결정 | 근거 |
|------|------|------|
| **범위** | 전사 통합 — 모든 프로젝트 across. 신규 최상위 라우트(예: `/dashboard` 또는 `/project` 랜딩 상위). 기존 프로젝트 단위 대시보드(`projectDetail/dashboard`)와 별개 층위. | 기존 대시보드는 단일 프로젝트 전용 |
| **데이터 전략** | **사전 집계(배치) + 스냅샷 조회.** Scheduled Trigger로 주기적으로 전 프로젝트 지표를 미리 계산해 SQL/KVS에 스냅샷 적재. 대시보드는 적재된 스냅샷만 조회. | Forge 256MB·타임아웃 제약. 전 프로젝트 across 온디맨드 집계는 워크로그 N+1로 위험 → [[forge-worklog-performance]] |
| **권한** | `canRead('REPORT')` 게이트. 진척도 탭과 동일 패턴. | 기존 권한 패턴 재사용, PMO/관리자 한정 |

## 3. 지표/위젯 후보 (설계에서 확정·우선순위化)

레이아웃 컨셉(사용자 확인한 mockup):
```
┌──────────────────────────────────────────┐
│ 전사 KPI: 프로젝트 N · 총 투입MM · 평균 진척 · 리스크 건수 │
│ [프로젝트별 진척 히트맵/테이블]   [리스크 TOP 프로젝트]    │
│ [인력 가동률 분포]               [전사 공수 추이 추세]    │
└──────────────────────────────────────────┘
```
- **전사 KPI 카드**: 활성 프로젝트 수, 총 투입 MM, 평균 완성 진척률, 지연/리스크 프로젝트 수
- **프로젝트별 현황 테이블/히트맵**: 프로젝트명·상태·완성%·일정%·차이(%p)·투입MM·가동률·리스크 배지. 행 클릭 → 해당 프로젝트 상세로 드릴다운
- **리스크 TOP**: 진척 지연(완성<일정−threshold) 또는 공수 초과 프로젝트 정렬
- **인력 가동률 분포**: 전사 인력의 가동률 분포(과소/적정/과부하)
- **공수 추이**: 전사 누적 투입 MM/MD 추세

> 진척/완성/일정/MM/가동률 산식은 **기존 정의를 재사용**(진척도 3층, MM 재설계, 가동률 분리). 신규 계산식은 최소화.

## 4. 데이터 전략 상세 (설계 핵심 — architect가 구체화)

- **사전 집계 대상**: 프로젝트별 스냅샷 1행(완성%·일정%·투입MM·가동률·리스크상태·이슈 분포 요약) + 전사 롤업.
- **배치**: Scheduled Trigger(manifest 등록). 주기 후보(매일 새벽). 전 프로젝트 순회하며 기존 서비스(진척/워크로그/MM)로 지표 계산 후 적재. p-limit 동시성 제한.
- **적재 저장소**: 프로젝트별 스냅샷 행 = SQL 후보, 전사 롤업/메타 = KVS 후보. (architect가 SQL vs KVS 경계 확정)
- **조회 resolver**: 대시보드는 적재된 스냅샷만 읽어 즉시 응답(무거운 계산 없음).
- **신선도 표기**: 스냅샷 생성 시각(lastAggregatedAt)을 응답에 포함해 화면에 "기준 시각" 노출. 수동 새로고침(즉시 재집계 트리거) 여부는 설계에서 판단.

## 6. 영향 범위

- **백엔드**: 신규 도메인 `src/resolver/portfolioDashboard/`(Controller/Service/Repository) + 집계 배치(Scheduled Trigger handler) + 스냅샷 스키마(SQL ddl/migrate 또는 KVS 엔티티) + `src/index.js` 등록 + manifest 트리거.

## 6-A. 2차 추가 요구 (2026-06-01, 사용자)

설계 리뷰 중 추가된 요구. 데이터 가용성 확인 완료(`projectusers` 테이블에 `role_key`/`level_key`/`salary`가 **프로젝트 단위로** 저장 — SQL 한 방 조회, 워크로그 페치 무관).

확정 요구:
1. **프로젝트별 롤/레벨 분포 비교** — `projectusers` GROUP BY. 차트: **100% 정규화 누적막대**(ECharts bar-stack-normalization, `stackChartOption` 정규화). 롤/레벨 **토글**.
2. **급여 분석** (확정 2종): (a) **프로젝트별 총 인건비**(Σ salary, 막대), (b) **급여 구간 분포**(히스토그램). ※ 급여는 민감 데이터 → 노출 범위 후속 검토.
3. **작업 분포** — **확정(2026-06-01, 보류 해제)**: **프로젝트별 작업 분포 = 투입 인력 대비 작업 공수**. 차트 = **ECharts scatter-aggregate-bar**(산점↔집계막대 토글). 점=투입 인원 1명, y=그 인원의 작업 공수(MD), x=프로젝트(카테고리), 집계막대=프로젝트별 공수 합/평균. 효과: 인력 간 공수 편중 + 프로젝트 간 공수 차이 동시 파악. 데이터: 인당 공수 MD는 가동률 계산 중간값 재사용(추가 페치 없음). 위젯은 **신규 추가**(공수 추이·가동률 분포 유지) → 위젯 총 10종.
4. **프로젝트 가로 비교 핵심 지표**: 프로젝트별 **투입 공수·비용(인건비)·인원·작업량 진척**을 한눈에. → 프로젝트 현황 테이블 컬럼으로 통합(프로젝트/상태/인원/투입MM/인건비/완성%/일정%/가동률/리스크).
5. **문제 이슈 한눈에 차트** (확정): **버블/산점도**(x=지연일수, y=공수편차, 버블=개별 이슈, 우상단=위험). 전사 **TOP N 이슈만** 스냅샷 적재. "문제 이슈" 정의는 진척도 재사용(기한초과 미완료/공수편차/지연). 개별 상세는 프로젝트 드릴다운.

정보구조(3섹션):

- 섹션2 프로젝트 비교(현황 테이블 중심 + 롤/레벨 분포·인건비·급여분포·공수추이)

## 6-B. 3차 추가 요구 (2026-06-01, 사용자) — ★ 정체성 전환

목업 v2 리뷰 중 확정. **이 대시보드의 정체성은 "전사 합산"이 아니라 "프로젝트별 비교"다.**

확정 요구:
1. **상단 프로젝트 멀티셀렉트 필터** — 모든 위젯이 선택된 프로젝트에만 반응. **기본값 = 전체 선택**.
2. **문제 이슈 버블만 필터 예외** — 항상 전 프로젝트 대상(필터 무관). 화면에 "필터 무관" 배지.
3. **전사 합산 KPI 카드 제거** — 프로젝트별 비교로 완전 전환. (선택분 요약 라인은 *선택된 프로젝트 합계* 컨텍스트로만, 전사 고정 합산 아님 — 유지/제거 자유)
4. **★ 데이터 모델 전환**: 프론트가 필터로 **즉시 재집계**하려면 백엔드 스냅샷이 **프로젝트별 raw 데이터**를 보유해야 함. 전사 롤업(KVS) 의존 축소 → **프로젝트별 스냅샷이 중심**. 프로젝트별로 담을 raw: 인원별 급여(급여 히스토그램 재계산용), 인원별 가동률(가동률 분포 재계산용), 월별 공수(공수 추이 라인용), 인원별 공수(작업 분포용), 롤/레벨 분포. 프론트가 선택분을 합산/분포 재구성. 전사 KPI 합산은 프론트가 선택분으로 계산(or 제거).
5. **공수 추이** = 전사 합산 → **프로젝트별 라인 비교**(프로젝트당 월별 MD 라인).
6. **급여·가동률 분포** = 선택 프로젝트 인원 기준 재집계.
7. **레이아웃** = 섹션2 서브탭(개요 / 인력·비용 / 공수·작업).

목업: `_workspace/portfolio-dashboard/mockup_v2.html` · `mockup_v2.png` (이 방향 확정본).

### 6-B 추가 확정 (2026-06-01)
- **급여 노출 = 현행(REPORT 게이트로 충분)** 확정. 개별 salary가 응답에 raw 포함되나 REPORT 권한자만 접근, 화면엔 합계·구간만. 서버 마스킹/별도 권한은 후속.
- **가동률 분모·payload = 기본값 진행**(Σ/Σ, 통상 단일 호출). 후속 보정 여지만 기록.
- **공수 추이 = 월별 ⇄ 누적 토글** 추가. `monthlyEffort[]` 프론트 cumsum → 프로젝트별 누적 공수 곡선(미니 S-curve) 비교. 추가 페치 없음. 누적 MM 환산 병기.

> **여기까지가 설계 범위(사용자 지시: "일단 여기까지만 설계").** 구현 파이프라인(백엔드/프론트/검증)은 착수하지 않음.

> 데이터 전략 영향: "사전 집계 배치 → 스냅샷"은 유지하되, 스냅샷 단위가 **프로젝트별 raw(인원 배열 포함)** 로 바뀜. 배치는 여전히 전 프로젝트 1회 집계. 조회 resolver는 프로젝트별 스냅샷 배열을 반환하고, **필터·분포 재집계·KPI 합산은 프론트에서** 수행(스냅샷이 가벼우므로 가능). KVS 롤업은 lastAggregatedAt/aggregateStatus 등 메타 위주로 축소, 또는 전사 폴백용.
