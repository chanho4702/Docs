# 검증 시나리오

1. 인력 현황의 행 클릭 → 선택한 accountId 패널 → 상세보기 → 동일 accountId 종합 분석. 자원관리 별도 탭 없음.
2. 직접 URL 및 새로고침에서도 동일 인원 조회. 목록으로 복귀 경로 존재.
3. 권한 없는 페이지에서 데이터 요청하지 않음. 서버는 principal 누락/팀 범위 밖 인원 직접 invoke 거부.
4. 프로젝트 범위 밖 SQL 이력/워크로그가 결과에 포함되지 않음. 이름/시간/건수 등 파생 값도 동일 범위.
5. 선택한 기간의 해당 인원 워크로그만 합산. 프로젝트별 합과 기간 총합 일치. Jira project와 RMS project 식별자를 혼동하지 않음.
6. 기간 필터 변경 시 query key 분리. 응답 역전 시 다른 인원/기간 데이터 표시하지 않음. 호출자 권한 범위 반영.
7. 빈 결과와 조회 실패를 구분. 초과 데이터나 API 실패를 정상적인 0시간으로 표시하지 않음.
8. 날짜 순서/잘못된 날짜/상한 초과 검증. 부분 인라인 워크로그와 검색 페이지네이션 확인.
9. 현재 상태와 기간별 실적을 구분. 프로젝트 일정이 개인 배정 일정이나 미래 가용성으로 표시되지 않음.
10. 한국어/영어 키 존재, 공용 레이아웃 사용, lazy route Suspense 유지, 이슈 링크 동작.

필수 명령: backend jest, frontend jest, CI=true frontend build, app root pwd 후 forge lint. 실제 Jira 설치 브라우저 검증은 별도 증거로 기록한다.
