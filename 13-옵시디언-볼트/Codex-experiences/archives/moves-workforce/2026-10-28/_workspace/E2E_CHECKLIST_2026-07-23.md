## ⛔ 1순위 — 설계 전제를 검증하는 항목 (실패하면 재설계)

### C-1. 팀 관리형 프로젝트에서 작업 배정 큐가 채워지는가
- **왜**: 이 기능 전체가 "JQL 술어 `moves_RMS_projectId = "<uuid>"` 로 프로젝트를 확정할 수 있다"는 전제 위에 있다. 팀 관리형은 앱 필드가 `fields` 응답에서 빠지지만 **JQL 인덱스는 동작한다**고 보고 설계했다.
- **확인**: 팀 관리형 프로젝트 상세 > 인력 > 작업 배정 진입
- **정상**: 좌측 큐에 작업이 뜬다
- **실패 징후**: 큐가 비어 있고 `meta.issueScanned === 0` → JQL 인덱스 문제. 회사 관리형에서는 되는지 대조해볼 것

### C-2. 배정 직후 화면이 재조회 없이 즉시 갱신되는가
- **왜**: Jira 검색 인덱스 지연 때문에 write 후 `search/jql` 재조회를 금지하고, **서버 응답만으로 캐시를 패치**하도록 설계했다. 이 설계의 유일한 실증 지점이다.
- **확인**: 후보 행에서 [담당자 지정] → 좌측 큐 항목과 우측 후보 수치 관찰
- **정상**: 즉시 갱신되고 값이 유지된다
- **실패 징후**: 값이 잠깐 바뀌었다가 **원래대로 돌아온다** → 어딘가에서 재조회가 일어나는 것

### C-3. 담당자 지정이 실제로 Jira에 반영되는가
- **확인**: [담당자 지정] 후 Jira 이슈 화면에서 담당자 확인
- **정상**: 반영됨
- **실패 징후**: 403 → `Jira 배정 권한이 없습니다` 토스트. 계정의 Jira **ASSIGN_ISSUES** 권한 확인
- 협업자 지정은 이슈 프로퍼티 write라 이 권한과 무관 — 따로 확인

### C-4. 연관 관계 중복이 사라졌는가 + 교차 프로젝트 Blocks가 살아있는가
- **확인**: 작업 관리 > 트리 > 이슈 선택 > 연관 관계 섹션
- **정상**: `Blocks` 링크가 **선후행에만** 나온다(Jira 연결 목록에 중복 없음)
- **함께 확인**: 다른 프로젝트 이슈와 Blocks로 엮인 이슈를 골라, 그 관계가 **"조회 범위 밖 선후행"으로 표시**되는지. 아예 안 보이면 회귀다

## ⚠️ 2순위 — 동작·성능 확인

### C-5. 목록 뷰 조회 횟수 (브라우저 Network 탭)
- **확인**: 작업 관리 > 목록 진입 시 `searchIssueWithJQL` 호출 수
- **정상**: 그룹 요약 1회 + 펼친 그룹당 1회 (수정 전엔 각각 2배)
- **뷰 전환 왕복**: 목록 → 간트 → 목록, 60초 이내면 **추가 호출 0회**
- 칸반 보드의 이슈 모달에서도 동일하게 1회인지 확인

### C-6. 작업 배정 좌우 카드 높이
- **왜**: `78vh`가 Forge iframe에서 실제로 같은 높이로 떨어지는지가 로컬에서 확인 불가
- **정상**: 좌우 카드 높이가 같고, 각 카드 **본문만** 스크롤(헤더·필터 바는 고정)
- 작은 화면(노트북)에서 `minHeight 480`이 먹는지도 함께

### C-7. 관계 편집이 간트에 반영되는가
- **확인**: 트리에서 선후행 추가/삭제 → 간트 뷰로 전환
- **정상**: 간트 화살표에 즉시 반영(같은 쿼리키 캐시 공유)
- 상위 지정도 동일하게 확인. 사이클을 만들려 시도하면 서버가 거부하고 롤백되는지도

### C-8. 상위 출처 표기가 맞는가
- **확인**: Jira에서 부모가 지정된 이슈 / 워크포스(간트)에서 상위를 지정한 이슈 각각
- **정상**: "워크포스 지정" / "Jira 정의" 배지가 정확히 갈리고, 워크포스가 override 중이면 **가려진 Jira 상위**가 함께 보인다
- 상위 해제 시 Jira 상위로 폴백되는지

### C-9. 전사 인력 풀 토글 응답 속도
- **확인**: 작업 배정 > 전사 풀 토글
- 최대 300명 × Jira 배치(50청크 × 동시성 3 = 6청크)
- 체감 지연이 크면 `MAX_POOL_ACCOUNTS` 하향 검토

## 🔍 3순위 — 권한·표시 확인

### C-10. 권한 조합별 화면 (작업 배정)
| 권한 | 기대 화면 |
|---|---|
| `PROJECT` read만 | 전사 컬럼 잠금(자물쇠 아이콘), 풀 토글 미노출, 후보 행 클릭 불가 |
| + `RESOURCE_MANAGEMENT` read | 전사 컬럼·괴리 신호·풀 토글 노출 |
| `PROJECT` write 없음 | 배정 버튼 비활성 |
| MEMBER_ONLY로 비소속 프로젝트 | 접근 거부 |

### C-11. 관계 편집 권한
- 편집 UI는 **`PROJECT_GANTT` write** 기준(`PROJECT` 아님). 이 권한이 없으면 편집 버튼이 안 보여야 하고, 보이는데 서버가 거부하면 불일치다

### C-12. 집계 시각 표기
- 작업 배정의 프로젝트 가동률 옆 집계 시각이 `Invalid Date`로 뜨지 않는지
- 이 값은 일 배치 스냅샷 유래라 **대부분 `-`로 표시되는 게 정상**이다

## 알려진 한계 (버그 아님 — 설계 시 수용한 사항)

1. **60초 후 탭 재진입 시 배정 결과가 잠깐 옛 값으로 보일 수 있다.** staleTime 만료 후 자연 재조회가 Jira 인덱스 지연 값을 받을 수 있다.
2. **추정치 없는 이슈는 담당자를 지정해도 큐에 남는다.** `NO_ESTIMATE` 플래그가 살아 있어 "열린 작업"으로 계속 분류된다.
3. **전사 풀에서 데려온 후보의 괴리 신호는 프로젝트 수치와 어긋나 보일 수 있다.** 신호는 서버가 계산한 값을 그대로 쓰고 프론트가 재계산하지 않는다(규칙 이원화 방지).
4. **프로젝트 내 가동률은 일 배치 스냅샷 값**이라 실시간이 아니다. 집계 시각을 함께 표기한다.
