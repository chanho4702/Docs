# 스킬 입력 UX 협의안

## 현재
- ProjectModal은 editId가 있어야 RequiredSkillEditor를 표시한다. 신규 생성 때 입력 불가.
- 프로젝트 저장과 스킬 저장 버튼/요청이 분리되어 있다.
- SkillMultiSelect는 직군 필터와 다중 선택창을 세로 배치하고 선택값을 창 내부에 표시한다.

## 제안
- 생성·수정 화면 모두 동일한 요구 스킬 영역을 제공한다.
- 직군 필터와 검색창에서 후보를 찾고 추가한다. 선택된 스킬은 별도 영역에 이름, 개수, 제거 버튼으로 표시한다.
- 입력창을 닫아도 선택 결과는 계속 보이며 중복 선택은 막는다.
- 프로젝트의 저장 버튼 한 곳으로 입력을 제출한다. 저장 중 중복 제출을 막고 실패 시 입력을 보존한다.
- 조회 실패를 빈 스킬로 취급하거나 불완전한 로드 상태에서 기존 값을 덮어쓰지 않는다.

## 구현 전 확정할 범위
1. 생성 지원 + 통합 저장 + 선택 UI 개선
2. 현행 저장 방식 유지 + 선택 UI 개선
3. 화면 시안 먼저 검토

1안을 선택하면 insertProject/updateProject와 setProjectSkills의 별도 저장 계약을 설계해야 한다. 단순 연속 호출을 원자적 저장처럼 표시하지 않는다. 프로젝트 생성만 성공했을 때 중복 생성 없이 스킬 저장을 재시도할 수 있어야 한다. 공용 SkillMultiSelect 변경은 개인 스킬/인력 필터 소비자 영향도 확인한다.

사용자의 사전 협의 요청에 따라 아직 구현하지 않았다.
