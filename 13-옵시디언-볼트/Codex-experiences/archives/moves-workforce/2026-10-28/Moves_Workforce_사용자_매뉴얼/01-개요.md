# 1. 개요

## 접근 권한


| 구분        | 필요 권한                               |
| --------- | ----------------------------------- |
| 이 페이지의 내용 | **권한 불필요** — 앱에 접속할 수 있으면 누구나 해당됩니다 |


이 매뉴얼의 모든 페이지 상단에는 **접근 권한** 표가 있습니다. 권한 이름은 [설정 &gt; 권한 관리](./07-설정/08-권한-관리.md) 화면의 항목명을 「 」 안에 그대로 씁니다.


| 표기           | 의미                                       |
| ------------ | ---------------------------------------- |
| 「프로젝트 관리」 읽기 | 그 항목의 **읽기(Read)** 체크가 있어야 화면이 보입니다      |
| 「프로젝트 관리」 쓰기 | **쓰기(Write)** 체크가 있어야 추가·수정·삭제 버튼이 나타납니다 |
| A 또는 B       | 둘 중 **하나만** 있어도 됩니다                      |
| A + B        | **둘 다** 있어야 합니다                          |
| 권한 불필요       | 본인 데이터이거나 전역 공개 정보입니다                    |
| Jira 권한      | 앱 권한과 **별개로** Jira 자체 권한이 필요합니다          |


> 권한이 없으면 대부분 **버튼·탭·메뉴가 아예 보이지 않습니다.** 서버에서도 같은 검사를 하므로 화면을 우회해도 거부됩니다.

## 1.2 접속 방법

Jira 상단 **앱** 메뉴에서 **Moves Workforce**를 선택합니다. 화면 왼쪽에 공통 사이드바가 있으며 **접기/펴기 토글(`‹` / `›`)** 로 폭을 줄일 수 있습니다.

![그림 1-1 Jira 앱 메뉴에서 Moves Workforce 진입](./images/01-entry-jira-apps-menu.png)
*그림 1-1. Jira 상단 앱 메뉴 → Moves Workforce. 처음 열면 My Work가 표시됩니다.*

> **Jira에서 사용하는 앱입니다.** Moves Workforce는 Jira에 설치하고 Jira에서 엽니다. Confluence는 **선택 사항**이며 Confluence 안에는 앱 화면이 없습니다. 같은 사이트에 Confluence가 있으면 프로젝트 상세의 [문서 관리](./05-프로젝트-상세/06-문서-관리.md) 탭에서 Confluence 문서를 검색해 작업에 연결할 수 있고, Confluence가 없어도 나머지 기능은 모두 동작합니다.

> **다크 모드:** 별도 설정 없이 **Jira의 테마(라이트/다크)를 자동으로 따라갑니다.** 사이드바 로고와 대비도 다크 전용으로 바뀌며, 차트·표·간트를 포함한 모든 화면이 다크 모드에서 동일하게 동작합니다.

> **Jira 이슈 화면에서도 보입니다.** 앱 프로젝트에 편입된 이슈를 Jira에서 열면 이슈 화면의 활동 탭과 오른쪽 패널에 Moves Workforce가 나타나 공수 확인과 워크로그 기록을 할 수 있습니다. [10장](./10-jira-이슈-패널.md)을 참고하세요.

## 1.4 권한의 기본 개념

### ① 읽기와 쓰기가 분리됩니다

기능 영역마다 **읽기(Read)** / **쓰기(Write)** 가 따로 있습니다. 읽기만 있으면 조회는 되지만 추가·수정·삭제 버튼이 **아예 보이지 않습니다.**

### ② 화면에서 숨긴다고 끝이 아닙니다

권한 검사는 **서버에서도 수행**됩니다. 권한 없는 작업을 시도하면 "이 작업을 수행할 권한이 없습니다"가 표시됩니다.

### ③ 프로젝트 조회 범위가 따로 있습니다

권한 세트마다 볼 수 있는 프로젝트 범위가 설정됩니다.


| 범위           | 보이는 프로젝트                                                                            |
| ------------ | ----------------------------------------------------------------------------------- |
| **전체 프로젝트**  | 모든 프로젝트                                                                             |
| **소속 프로젝트만** | 본인이 **인력으로 등록된** 프로젝트만                                                              |
| **내 팀만**     | 내 소속 팀·하위 팀, 내가 이끄는 팀·하위 팀의 인원이 참여했거나 담당 팀으로 지정된 프로젝트. **유효한 팀이 없으면 아무것도 보이지 않습니다** |


> Jira 관리자와 Admin 권한 세트는 이 설정과 무관하게 항상 전체 프로젝트를 봅니다.
> **참여 중인 프로젝트가 보이지 않는다면** 프로젝트 관리자에게 [인력 등록](./05-프로젝트-상세/02-인력-관리.md)을 요청하세요.

권한 설정 방법은 [7.8 권한 관리](./07-설정/08-권한-관리.md), 권한별로 무엇이 되는지는 [부록 B](./부록/B-권한별-사용-범위.md)를 참고하세요.

### ④ Jira 자체 권한도 따로 있습니다

앱은 Jira 호출을 **본인 계정으로** 실행합니다. 앱에서 쓰기 권한이 있어도 Jira에서 그 작업이 막혀 있으면 저장이 거부되고 사유가 안내됩니다.


| 하려는 일         | 필요한 Jira 권한                                              |
| ------------- | -------------------------------------------------------- |
| 이슈 조회         | Browse Projects                                          |
| 워크로그 작성·수정·삭제 | Work On Issues (남의 워크로그 수정·삭제는 Edit/Delete All Worklogs) |
| 일정 변경         | Edit Issues + Schedule Issues                            |
| 담당자 지정        | Assign Issues                                            |
| 선후행 연결        | Link Issues                                              |
| 계획 작업량(MD)    | Edit Issues + 프로젝트의 시간 추적 활성화                            |


> 설치·최초 접근에 필요한 Jira 계정 권한(누가 처음 관리자로 들어갈 수 있는지)은 [관리자 매뉴얼 2.0](../Moves_Workforce_관리자_매뉴얼.md#20-시작하기-전에--필요한-jira-계정-권한)에 정리돼 있습니다.

## 1.5 공통 UI 규칙


| 규칙               | 설명                                                                                                                           |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| **화면 주소가 유지됩니다** | 현재 페이지·탭·보기 방식이 브라우저 주소에 실립니다. **새로고침해도 같은 화면**이 열리고, 브라우저 **뒤로 가기**가 동작하며, 주소를 복사해 보내면 상대도 같은 화면(예: 특정 프로젝트의 간트 보기)으로 들어옵니다 |
| **링크 복사**        | 프로젝트 상세 등 페이지 헤더의 **링크 복사** 버튼으로 현재 화면 주소를 클립보드에 복사합니다                                                                       |
| **브레드크럼**        | 프로젝트 상세 상단에 `프로젝트 관리 / 프로젝트명 / 탭 / 하위 탭` 경로가 표시되며 각 항목을 눌러 이동합니다                                                             |
| **셀 인라인 편집**     | 표의 일부 셀은 클릭하면 그 자리에서 바로 수정됩니다. Enter 저장 / Esc 취소                                                                             |
| **차트·표 전환**      | 대부분의 차트 위젯은 표 보기 토글, 펼치기(전체 화면), 새로고침, 계산식 안내(ⓘ)를 제공합니다                                                                      |
| **패널 접기·너비 조절**  | 좌우로 나뉜 화면(작업 배정, 분석 상세 등)은 카드 헤더의 **접기** 버튼과 경계선 드래그로 폭을 조절합니다. 마지막 남은 패널은 접을 수 없고, 상태는 브라우저에 화면별로 기억됩니다                     |
| **표 컬럼 너비 조절**   | 표 헤더 경계를 끌어 컬럼 폭을 바꿉니다. 정렬 가능한 컬럼에만 정렬 화살표가 표시됩니다                                                                            |
| **상태 표시**        | 이슈·프로젝트 상태는 색 있는 라벨(할 일 = 회색, 진행 중 = 파랑, 완료 = 초록)로 모든 화면에서 같은 모양으로 표시됩니다                                                     |
| **엑셀 내보내기**      | 목록형 화면은 **현재 필터가 적용된 결과**를 내려받습니다                                                                                            |
| **알림(토스트)**      | 저장 성공/실패가 우측 상단에 잠깐 표시됩니다. 연속 편집 시 성공 알림은 묶여서 한 건으로 나옵니다                                                                     |
| **로딩 표현**        | 데이터를 불러오는 동안 화면 골격(스켈레톤)이 먼저 나타납니다                                                                                           |
