# 자주 묻는 질문

[가이드 홈](./index.md) · [English](../en/faq.md)

> 검토 초안: 지정된 staging 환경의 실제 화면·배포 버전 확인 전입니다.

문제가 생기면 아래 순서로 조건을 확인하세요. 같은 증상에도 여러 원인이 있을 수 있으므로 한 가지 설정만 보고 결론을 내리지 않습니다.

## 메뉴가 보이지 않습니다

마이페이지의 내 권한에서 해당 기능의 읽기 권한을 확인합니다. 사용자 등록·권한 세트·팀 상속이 올바른지 관리자에게 확인받고 새로고침합니다. 내 팀은 실제 팀장 관계도 필요합니다.

## 동료에게 보이는 프로젝트나 인력이 없습니다

계정마다 조회 범위가 다를 수 있습니다. 프로젝트 인력 등록, 소속·리딩 팀, 프로젝트 담당 팀, 조직 열람 권한을 비교합니다. 특정 Jira 이슈만 안 보이면 Jira에서 직접 열 수 있는지도 확인합니다.

## 작업 추가로 새 Jira 이슈를 만들 수 있나요?

기존 이슈 편입은 Jira 이슈를 앱 프로젝트에 연결합니다. 작업 관리의 이슈 생성은 새 Jira 이슈를 생성하며, Jira의 Create Issues 권한과 필수 입력이 필요합니다. 프로젝트에서 제외하는 동작은 Jira 이슈를 삭제하지 않습니다.

## 담당 팀을 지정했는데 인력이 없습니다

담당 팀은 책임 조직을 지정한 것입니다. 실제 참여자는 사용자 추가 또는 담당 팀의 구성원 선택(Pick members)로 등록합니다. 이슈 담당자 지정도 프로젝트 인력 등록과 별개입니다.

## 워크로그를 저장하거나 수정할 수 없습니다

이슈 접근, 시간 추적, 작성자의 Jira 권한을 확인합니다. 작성은 Work On Issues, 본인 수정은 Edit Own Worklogs, 본인 삭제는 Delete Own Worklogs가 필요합니다. 저장 실패 시 같은 기록이 이미 저장됐는지 확인한 뒤 재시도합니다.

## 프로젝트 인건비가 0이거나 항목이 없습니다

항목이 없으면 비용 권한·급여 정책부터 확인합니다. 실제 0이면 투입 유형, 개인 또는 등급 금액, 프로젝트 기간을 확인합니다. 의도한 0원 프로젝트 투입인지도 구분합니다. [인건비 안내](./project-people.md)를 참고하세요.

## 워크로그를 기록했는데 대시보드 숫자가 그대로입니다

마지막 집계 시각과 부분 실패 안내를 확인합니다. 필요하면 권한 있는 사용자가 재집계합니다. 프로젝트별 분석과 전사 분석을 비교할 때는 기간·인력·이슈 범위도 맞춥니다.

## Excel에는 모든 워크로그가 들어 있나요?

성공적으로 수집한 기록이 들어 있습니다. 검색 상한, 취소, 일부 실패, Jira 권한 때문에 수집하지 못한 기록은 포함되지 않습니다. 파일의 요약과 화면의 수집 상태를 함께 확인하세요.

## Confluence 문서가 끊김으로 보입니다

페이지가 삭제됐을 수도 있지만 본인 권한이 없을 수도 있습니다. 원문 주소로 직접 열어 보고, 같은 사이트의 Confluence 연결 상태도 확인합니다. 확인 불가 상태는 삭제 확정이 아닙니다.

## 팀원을 다른 팀으로 옮길 수 없습니다

해당 사용자가 현재 팀장인지 확인합니다. 팀장을 먼저 변경하거나 해제한 뒤 이동하고, 이동 후 팀 권한 상속도 확인합니다.

## 앱 프로젝트를 삭제하면 Jira 이슈도 없어지나요?

Jira 이슈 자체는 남고 앱 프로젝트 관련 데이터와 연결이 정리됩니다. 중간 실패는 삭제 진행 창에서 사유를 확인해 재시도합니다. 앱 프로젝트의 삭제된 데이터는 복구할 수 없으므로 대상부터 확인합니다.

## 문의할 때 무엇을 전달하나요?

사이트, 발생 시각과 시간대, 화면 경로, 수행한 단계, 예상 결과와 실제 결과, 오류 문구를 전달합니다. 필요한 경우 예시 이슈 키와 개인정보를 가린 화면을 포함합니다. 비밀번호·API 토큰은 전달하지 않습니다.
