## 접근 권한

| 구분 | 필요 권한 |
|---|---|
| 화면 조회 | 「인력 관리」 읽기 |
| 인력 추가·수정·삭제 | 「인력 관리」 쓰기 |
| 엑셀 일괄 업로드 | 「인력 관리」 쓰기 |
| Excel 다운로드 | 「인력 관리」 읽기 |
| 연봉 입력·표시 | 「인력 관리」 쓰기 **+** 급여 정책이 **인원별** |
| 권한 세트 지정 | 「인력 관리」 쓰기. 단, **자기 권한을 넘는 세트는 줄 수 없습니다**(Jira 관리자·「권한 관리」 쓰기 보유자는 제한 없음) |

- 역할·등급·팀·권한 **선택지**는 이 화면에서 함께 조회됩니다(「인력 관리」 읽기로 열립니다). 값 자체를 만들려면 각 기준정보 화면의 권한이 필요합니다.
- 급여 정책이 등급 기반이면 연봉 칸이 사라집니다([7.1](https://dmove-addons.atlassian.net/wiki/spaces/MW/pages/173342802)).


**언제 쓰나** — 워크포스 사용자(인력)를 등록·수정할 때. **여기 등록된 사람만** 팀 배치·프로젝트 인력·팀장 지정의 대상이 됩니다.

> **[이미지 삽입 위치 · 추가 캡처 필요]** 인력 관리 — ① 권한/역할/등급/팀별 인원 통계 카드 ② 필터와 Excel 다운로드 ③ 인력 추가·일괄 업로드 ④ 인력 표(팀장 배지·권한·연봉).


## 화면 구성

- 상단에 **권한 / 역할 / 등급 / 팀별 인원 통계** 카드
- 필터: 사용자 검색 · 역할 · 등급 · 권한 · 팀
- **Excel 다운로드**: 설정한 필터 조건 그대로 내려받습니다

| 컬럼 | 설명 |
|---|---|
| 사용자 | 이름·아바타. 소속 팀의 팀장이면 **팀장** 배지 |
| 직무 역할 | [7.4](https://dmove-addons.atlassian.net/wiki/spaces/MW/pages/173146154)에서 정의한 값 |
| 직무 등급 | [7.5](https://dmove-addons.atlassian.net/wiki/spaces/MW/pages/173178927)에서 정의한 값 |
| 팀 | 소속 팀 |
| 권한 | 권한 세트 또는 **팀 권한 상속** |
| 연봉 | **급여 정책이 인원별일 때만** 입력·표시 (단위: 만원) |
| 등록일 / 작업 | 등록 시각, 수정·삭제 |

## 인력 한 명 추가하기

1. **인력 추가**를 누릅니다.
2. **Jira 사용자**를 이름 또는 이메일로 검색해 선택합니다.
3. 직무 역할·등급·권한을 지정합니다.
   - **권한을 선택하지 않으면 Member 권한으로 자동 등록**됩니다.
   - 팀 권한을 따르게 하려면 **팀 권한 상속**을 선택합니다([7.8 참고](https://dmove-addons.atlassian.net/wiki/spaces/MW/pages/173244476)).
4. 정책이 인원별이면 연봉을 입력할 수 있습니다.

## 팀장의 팀 이동 제한

수정 창에서 **팀**을 바꿀 수 있지만, 그 사람이 **어떤 팀의 팀장이면 그 팀 밖으로 옮길 수 없습니다.** "팀장은 이끄는 팀 밖으로 옮길 수 없습니다. 팀장 지정을 먼저 해제하세요"가 표시됩니다. [7.3 팀 관리](https://dmove-addons.atlassian.net/wiki/spaces/MW/pages/172916876)에서 팀장을 바꾼 뒤 이동하세요.

## 여러 명 한 번에 등록하기 (일괄 업로드)

> **[이미지 삽입 위치 · 추가 캡처 필요]** 일괄 업로드 — ① 템플릿 다운로드 ② 파일 드롭 영역 ③ 진행률 ④ 결과 요약(전체/등록/중복/미존재/실패) ⑤ 실패 목록 버튼.


1. **일괄 업로드** → **템플릿 다운로드**로 양식을 받습니다.
2. 양식을 채워 xlsx로 저장합니다. **최대 5MB, xlsx만 가능**합니다.
3. 파일을 드래그하거나 **파일 선택**으로 올립니다.
4. 처리는 백그라운드로 진행되며 진행률이 표시됩니다.
5. 결과가 **전체 / 등록 / 중복 / 미존재 / 실패**로 요약됩니다.
6. 실패 건이 있으면 **일괄 업로드 실패 목록** 버튼으로 사유를 확인합니다.

| 결과 항목 | 의미 |
|---|---|
| 등록 | 정상 등록됨 |
| 중복 | 이미 워크포스에 있는 사용자 |
| **미존재** | 입력 이메일로 Jira 계정을 찾지 못함 — 초대 여부·Email 값·계정 검색 가능 여부를 확인합니다 |
| 실패 | 그 밖의 오류(실패 목록에서 사유 확인) |

## 알아두기

- 급여 정책이 등급 기반이면 **"개인 연봉은 입력·표시되지 않습니다"** 안내가 표시됩니다([7.1](https://dmove-addons.atlassian.net/wiki/spaces/MW/pages/173342802)).
- 사용자를 삭제하면 복구할 수 없습니다. 삭제 전 확인 창이 표시됩니다. 삭제된 사람이 팀장이던 팀은 **팀장이 비워집니다.**
- 여기서 등록한 연봉은 프로젝트 인건비 계산 중 **연봉 투입 유형**에서 사용됩니다([5.2 급여 관리](https://dmove-addons.atlassian.net/wiki/spaces/MW/pages/172851256)).

## 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| 업로드 결과가 전부 "미존재"입니다 | 초대 여부·템플릿의 정확한 Email 값·계정 검색 가능 여부를 함께 확인합니다 |
| 연봉 칸이 보이지 않습니다 | 급여 정책이 등급 기반입니다 |
| 권한 세트를 고를 수 없습니다 | 내 권한보다 넓은 세트는 배정할 수 없습니다. 「권한 관리」 쓰기 보유자에게 요청하세요 |
| 팀을 바꾸려는데 거부됩니다 | 그 사람이 팀장입니다. [7.3](https://dmove-addons.atlassian.net/wiki/spaces/MW/pages/172916876)에서 팀장을 먼저 해제하세요 |
| 팀장으로 지정하려는데 목록에 없습니다 | 그 사람을 먼저 여기서 인력으로 등록해야 합니다 |
| 프로젝트 배정 화면에서 "백오피스에 등록되지 않은 사용자"라고 나옵니다 | 같은 이유입니다. 인력으로 먼저 등록하세요 |

## 버튼·입력 항목과 처리 결과 상세

설정의 인력 관리는 앱 사용자 등록입니다. Jira 계정 생성·초대와 프로젝트 구성원 추가는 별도입니다.

| 버튼·입력 항목 | 기능·사용 조건·변경 대상 | 결과 확인과 문제 대응 |
|---|---|---|
| 사용자 추가·Jira 사용자 | 접근 가능한 Jira 계정을 선택하고 역할·레벨·권한·팀 등 조직 정보를 지정합니다. 같은 계정 중복 등록은 거부됩니다. | 저장 후 계정·이름을 확인합니다. 검색 실패는 초대 여부뿐 아니라 계정 식별·Jira 검색 접근도 확인합니다. |
| 권한·팀·급여 입력 | 개인 권한 또는 팀 관계를 설정합니다. 급여 필드는 정책과 금액 접근 권한에 따라 달라집니다. 팀장은 다른 팀으로 옮기기 전에 리더 지정을 해제해야 할 수 있습니다. | 미지정·팀 상속·기본 Member를 같은 의미로 사용하지 않습니다. 저장 후 실효 권한을 대상 계정으로 확인합니다. |
| 템플릿 다운로드·Excel 선택·업로드 | 다운로드한 템플릿의 정확한 Email 헤더에 Jira 계정 이메일을 입력합니다. 최대 파일 크기는 5MB입니다. 역할·레벨·팀·Salary 열을 추가해도 이 업로드는 반영하지 않습니다. | 등록은 비동기 작업입니다. 창 닫힘·접수 성공을 전원 등록 완료로 해석하지 말고 작업 상태와 실제 목록을 확인합니다. |
| 일괄 업로드 실패 목록 | 실패한 이메일과 사유를 확인합니다. 성공 사용자와 실패 사용자를 나누어 후속 처리합니다. | Email 헤더·빈 행·계정 조회 가능 여부·중복을 수정하고 실패 대상만 재등록합니다. 상세 조직 정보는 등록 후 수정합니다. |
| 사용자 삭제 | 앱 사용자와 프로젝트 배정·개인 일정·보유 스킬 및 팀장 참조 등을 정리합니다. Jira 계정·원본 워크로그·프로젝트 과거 실적을 삭제하는 동작은 아닙니다. | 복구 불가 안내를 확인하고 소속·배정을 검토합니다. 삭제 후 Jira 접근이 사라진 것으로 가정하지 않습니다. |
