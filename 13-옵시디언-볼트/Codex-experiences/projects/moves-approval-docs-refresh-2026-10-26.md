# Moves Approval 문서 최신 캡처 갱신 (2026-10-26)

## 결과

- staging 최신 배포본에서 승인 업무함을 다시 캡처했다: `ma-05-inbox-2026-10-26.jpg`.
- 한국어·영어 `승인 업무함` 문서의 기존 이미지를 교체했다.
- Marketplace 심사 안내 한·영 문서에도 같은 실제 화면을 추가해 앱 진입점, 개인 기능 탭, Excel 내보내기를 한눈에 확인하게 했다.
- 공개 Confluence 문서 40개를 REST로 다시 게시했고, 첨부 파일은 40개가 됐다.
- 게시 검증 결과: 가이드 48/48 통과, 한·영 24쌍, 내부 링크 300개, 누락 첨부·깨진 링크·미해결 링크 0개.

## 확인 중 발견한 점

- staging의 기존 `2027 사업 계획 초안` 페이지에 저장된 영역 승인 매크로 두 개는 2026-10-26 배포 뒤에도 무한 로딩 표시가 남았다.
- 페이지 ADF에는 staging app/environment/module key와 `bodiedExtension` 본문이 존재하지만 Forge invocation 로그가 생기지 않았다. 앱 코드가 실행되기 전 Confluence가 저장된 확장을 해석하지 못하는 경로로 보인다.
- 이 화면은 정상 기능 증거로 사용할 수 없으므로 공개 문서의 MA-04 자리표시자를 실제 이미지로 교체하지 않았다.

## 교훈

- 문서용 화면은 캡처 직후 렌더링 상태를 직접 확인하고, 로딩 표시나 계정 ID가 보이는 화면은 첨부하지 않는다.
- 같은 파일명을 덮어쓰면 Confluence 첨부 업로드가 생략될 수 있다. 최신 화면은 날짜가 포함된 새 파일명으로 올려 문서 본문도 함께 갱신한다.
- Marketplace 심사 안내에는 대표 앱 화면을 넣되, 기대 결과를 실제 실행 증거처럼 표현하지 않는다.
