# 2026-08-26 APM(애플리케이션 모니터링) 설계 v1 초안

> 상위: [[moveseye]] · 정본: `C:\solutions\_workspace\designs\devdesign_apm.md` · 관련: [[2026-08-24-ai-account-monitoring-design]](OTLP 수신기 재사용)

## 무엇을 했나

프리미엄 3단계로 예약만 돼 있던 APM(`Feature.APM`, FE `/application-monitoring` 스텁, 문서 "준비 중")의 내용물을 정의했다. 결론은 **"서비스"를 1급 엔티티로 세우고 3마일스톤**:

| M | 내용 | 수집 | 새 인프라 |
|---|---|---|---|
| M1 | Zabbix 웹 시나리오·프로세스/포트·미들웨어 템플릿을 서비스 단위로 래핑 + 제품 안에서 시나리오 CRUD | Zabbix | 0 |
| M2 | OTel 자동계측 메트릭 수신 → 엔드포인트별 RED + JVM 런타임 | 앱 → BE push | PG 롤업 테이블 |
| M3 | 샘플링 트레이스 + 서비스 맵 | 앱 → BE push | PG 일 파티션(ClickHouse 승격 조건부) |

미결 Q1~Q10(에디션 경계·protobuf·저장소·착수 순서 등)을 사용자에게 넘긴 상태.

## 실측이 뒤집은 것

- 고객 문서는 "Prometheus·Datadog 어댑터가 붙어야 APM 가능"이라 했는데, 데모 Zabbix(7.0.6·76대)에 **웹 시나리오 22건이 15s~1m로 실사용 중**이고 DMOVE 자체 템플릿 "IDC Web Service by Dmove"(포트·프로세스)까지 있었다. M1은 외부 소스 없이 가능하고 수요도 이미 검증된 셈.
- **JMX 66아이템은 한 번도 수집되지 않았다**(lastclock 0, unsupported 6) — Java Gateway 미구성. "JVM 모니터링 = JMX 템플릿 링크"로 팔면 빈 화면이 나온다. 진단 배지·가이드가 선결이고, M2(OTel)는 Gateway 없이 JVM 메트릭을 준다.
- 프리미엄 설계서 §7.4 "Zabbix로는 수집 불가"는 트레이스에 한해 참. "OTel Collector → Tempo/ClickHouse → TracePort"는 설치형(무도커·Windows Redis 미지원) 제약과 충돌해 **PG 우선 + 승격 조건**으로 바꿨고, TracePort는 엔진 포트가 아니라 `premium/apm/trace/TraceStore`로 재해석(우리가 저장소 주인이라 소스 중립 포트가 아님).

## 교훈

- **"설계서에 적힌 방향"도 실측 대상이다.** §7.4는 2026-07-29에 APM을 범위 밖으로 밀며 한 줄로 적은 가설이었고, 그 한 줄이 고객 문서까지 번져 "외부 소스 필요"로 굳어 있었다. 데모 Zabbix API 두 번 호출로 뒤집혔다.
- **재사용 자산의 "거의 맞음"을 조심.** AI 모니터링 OTLP 수신기는 json 전용(Claude Code가 Node라서)이고 히스토그램은 sum만 취한다. OTel Java agent는 http/protobuf가 기본(SDK에 json 익스포터 없음)이고 p95엔 버킷이 필요하다 — 같은 OTLP인데 두 군데가 안 맞는다. 착수 시 R1 실험으로 재확인.
- 카디널리티는 화면이 고정된 제품에서 **허용목록**으로 막는 게 맞다(수집 엔진의 "Grafana가 아니라 오피니언 대시보드" 철학과 동일). `http.route` 500 상한 + `__other__`.
- 샘플링된 트레이스로 오류율을 세면 안 된다 — 오류율은 전량 메트릭에서, 트레이스는 예시로만(R5).

## v2 — 같은 날 "수집기는 오픈텔레메트리" 결정으로 재편

- Zabbix 래핑 M1 삭제. 파이프라인 = 앱(OTel 자동계측) → **OTel Collector 게이트웨이**(우리는 yaml 생성기·설치 가이드) → BE(json) → PG. Collector가 protobuf→json 변환·tail 샘플링·큐잉을 맡아 v1의 protobuf·오류 유실 문제가 함께 사라졌다. 서비스는 `service.name` 첫 수신 시 자동 등록.
- 사용자가 준 **시장 체크리스트 7항목**(WhaTap)과 AWS·Elastic 정의로 채점했더니 진짜 갭이 나왔다: **제품 자체 푸시 알림이 이메일뿐**(Slack/Teams/Jandi는 Zabbix 미디어 타입 관리 화면일 뿐, AI 모니터링 알람도 화면 표시용). Zabbix 밖 데이터인 APM 알람은 배달 경로가 없다 → Zabbix 7.0 `history.push`로 트래퍼 아이템에 밀어 Zabbix 액션·미디어를 공짜로 쓰는 안(래핑 원칙).
- 교훈: **"기존 알림 채널로"라고 쓰기 전에 그 채널이 실재하는지 grep 한 번.** 설계서 두 편(AI 모니터링·APM v1)이 같은 가정을 그대로 썼다.
- 교훈: 경쟁 정의 3곳이 공통으로 꼽는 항목(합성 감시·액티브 트랜잭션·DB 호출 지연·SLA)은 우리 정의에 없어도 **고객 채점표에는 있다** — 비범위로 밀기 전에 표에 올려 대조.

## v3 — "주력으로 간다" → 범위 확대·차트 조사·WBS

- 동반 문서 `designs/devdesign_apm-screens-wbs.md`: 메뉴 13개(개요·서비스(탭 12)·맵·트레이스 탐색·에러·DB·외부·메시징/배치·합성·SLO·RUM·알람·수집기), 차트 프리미티브 18종을 우리 스택으로 판정 — **ECharts 5.6 내장 17종**(heatmap·scatter large+brush·custom flame·calendar·sankey·treemap·gantt은 신규 개방), **직접 구현은 트레이스 워터폴 1건**(Grafana TraceView는 AGPL, Jaeger UI는 앱이라 발췌 불가), 신규 의존 `@dagrejs/dagre`·`sql-formatter`(MIT). WBS 80여 태스크, Phase 4개 ~210 사람-일.
- 핵심 지표 6종(WhaTap 표) 대조에서 정직하게 적은 것: **"코드 수준 추적"은 자동계측 기본이 아니다**(프레임워크 경계까지) → `otel.instrumentation.methods.include` 한 줄을 가이드에. `db.query.text`는 기본 마스킹이라 파라미터 값이 안 보인다.
- 검수는 `codex exec --sandbox read-only -`(stdin 프롬프트 파일)로 직접 실행 — 결과는 `reviews/review_apm-design.md` 하단에 붙인다.

## 코덱스 검수(🔴13·🟡10) → v3.1 반영

`codex exec`는 `C:\solutions`가 git 저장소가 아니라 처음 거부됨 → `--skip-git-repo-check` 필요. 검수가 잡아낸 진짜 결함들:
- **403을 "Collector가 30분 재시도로 버틴다"고 쓴 전제가 틀렸다** — OTLP exporter는 4xx를 영구 실패로 즉시 폐기. 라이선스 만료 = 그 순간부터 손실. 설계 문장 하나가 만료 UX 전체를 바꿨다.
- yaml에 Collector 자기 메트릭을 보내는 receiver/파이프라인이 없어 "수집기 상태 화면"에 데이터가 올 수 없었다(허용목록도 `otelcol_*`를 막고 있었음). **설정 파일과 화면 요구를 같이 놓고 대조**해야 잡히는 종류.
- 용량 산식에서 인스턴스 축 누락(6,000→1만 행/분), 서비스 UNIQUE가 env를 빼먹음, `GET ?token=`으로 토큰이 URL에 남는 API, 히스토그램 경계가 다른 버킷을 그냥 합산하려던 롤업.
- 교훈: **"기존 알림 채널로"·"재시도로 버틴다"처럼 편한 전제는 설계서 간에 복사된다** — AI 모니터링·APM v1·v2가 같은 문장을 물려받았다. 전제는 grep 한 번·문서 한 번으로 끊는다.
