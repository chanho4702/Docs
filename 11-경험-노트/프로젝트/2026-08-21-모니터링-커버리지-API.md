# 모니터링 커버리지 API

[[moveseye]]의 AI tool `check_monitoring_coverage`에서 쓰던 판정 기준을 Spring read-only API `GET /hosts/manage/coverage`로 승격했다.

- `host.get` 한 번에서 `selectParentTemplates`, `selectItems=count`, `selectTriggers=count`, agent interface 상태를 함께 받아 Host별 상세 조회(N+1)를 피한다.
- 분류명은 AI tool과 호환되게 `noTemplate`, `collectingNothing`, `noTrigger`, `agentUnreachable`로 유지한다. 화면은 AI 없이도 이 목록과 `coverageScore`를 표시할 수 있다.
- `agentUnreachable`는 agent interface(type `1`)가 존재할 때만 `available=2`를 문제로 본다. SNMP/ICMP 전용 장비를 agent 장애로 오탐하지 않는다.
- `findings`는 카테고리 건수 합이 아니라 사각지대가 하나 이상 있는 **고유 Host 수**다. 커버리지 점수도 이 고유 수를 기준으로 계산한다.
- AI 분석 UI는 API 결과를 근거로 전달하고, LLM은 우선순위와 조치 설명만 맡긴다.

관련 계약: `C:\solutions\_workspace\contract_monitoring-coverage.md`.

## 후속 백로그 (2026-08-24)

기능 구현·런타임 검증·AI 분석 연동은 완료됐다. 다음은 필수 결함이 아닌 제품 고도화 후보로 보류한다.

- 실제 브라우저에서 사이드바와 페이지 헤더 안내 문구의 줄바꿈·밀도를 최종 확인한다.
- 커버리지 발견 유형에서 Host 관리의 해당 설정 화면으로 바로 이동하는 조치 링크를 제공한다.
- AI 분석 결과를 바탕으로 권장 조치 순서를 화면 내에서 더 구조화한다.
- `데이터 소스 관리`에 Prometheus 등 추가 provider가 연결될 때 동일한 IA로 확장한다.
