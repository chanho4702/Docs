# 2026-07-20~22 — Zabbix 관리 기능 제품화 (ZM-86 묶음)

## 설계 판단

- **트리거 단독 메뉴 → 폐기**: 스코프 토글(B안)까지 만들었다가 **완전 컨테이너 드릴다운(A안)** 으로 대체했다. "무엇을 관리하나"가 아니라 "어디에 속한 것을 보나"가 사용자의 실제 탐색 순서였다. 아이템은 호스트 다이렉트 진입도 부활.
- **기기분류: 호스트 태그가 진실, 테이블은 메타만**. `device_classification` 행을 지워도 파괴가 0이다(호스트 태그는 그대로). 쓰기는 화이트리스트, 읽기에서 미지 코드가 오면 미분류로 폴백하는 3중 폴백 레지스트리.
- **목록 필터는 FE 클라이언트 사이드**로 두었다 — 전역 필터 정책은 미결로 남김.

## 교훈 — Zabbix API (→ [[zabbix-api-quirks]])

- `host.update`의 `tags`는 **전체 교체**다. 폼에서 태그를 건드리면 다른 태그가 증발하므로 round-trip(읽고→합쳐서→쓰기)이 필수.
- link/unlink는 전부 **host-side**로 해야 한다 (`host.massadd`/`host.massremove`). `template.massadd/massremove`는 거부하거나 200 no-op.
- `trigger.create`는 `hostid`를 받지 않는다 — expression의 `/host/key`가 대상 지정이다.
- `-32602`(Invalid params)는 create/update일 때만 400으로 매핑. 조회에서 같은 코드를 400으로 만들면 인증 실패(401) 경로와 섞인다.
- 부분 수정에서 clearable 필드는 **빈 문자열 = 클리어**로 취급해야 해서 `putIfProvided` 류의 분기가 필요하다.
- 🔴 **Zabbix에는 offset이 없다** → ID만 조회 → 슬라이스 → 그 페이지만 하이드레이트하는 **ID-슬라이스 페이징**으로 전체 임의 페이징이 가능하다(페이지당 0.4~1.3초). 처음엔 CAP+truncated로 짰다가 "미련하다"는 지적을 받고 재작성했다.

## 교훈 — FE

- `DmoveTable`에 `loading`을 안 넘기면 `spinning: undefined`를 antd Spin이 true로 취급해 **무한 스피너**가 된다. 별도 쿼리 없이 prop 데이터만 쓰는 표에서 터진다 → 기본값 `false`. → [[2026-06-18-monitoring-tabs-perf-review]]와 같은 함정의 재발.
- 라우트 페이지는 navigate(쿼리 변경 포함)마다 **통째 리마운트**된다(`CSSTransition key=location.key`). 스코프·선택 대상 같은 데이터-결정 상태는 로컬 `useState` 금지, URL query state로.
