# 2026-09-22 ZM-161 설정 메뉴를 "관리 콘솔"로 분리(같은 SPA)

프로젝트: [[moveseye]] · 브랜치 `ZM-161`(FE 전용, 워크트리 `C:/worktrees/zm-161-fe`)

## 문제
헤더 ⚙ 드롭다운에 설정 화면 12개가 한 줄로 쌓여 있었다. 실제 원인은 "설정이 많다"가 아니라 **관리자 기능이 개인 설정 메뉴에 얹혀 있다**는 것 — 일반 사용자는 2개만 보이고 관리자에게만 12개가 다 뜬다.

## 결정
- **별도 백오피스 앱은 안 한다.** 설치형이라 고객사마다 배포 산출물이 하나 더 늘고 쿠키·권한·라이선스 게이트·i18n을 두 벌 유지해야 한다.
- **같은 SPA 안의 라우트 트리 + 자체 좌측 내비 레이아웃.** 기존 `AppLayout`/`DashboardLayout`/`GuestLayout` 패턴에 `SettingsLayout`을 얹었다(`AppLayout nav="settings"`).
- **자빅스 관리는 콘솔에 넣지 않는다.** 운영자가 관제 중에 드나드는 화면이라 사이드바 잔류(사용자 결정).
- **URL은 그대로 `/setting/**`.** `/admin/**`으로 갈면 모델은 깨끗하지만 AI 서버 `screens.json`(10경로)·사용자 문서 5편·FE 테스트 10파일이 문자열로 물고 있어 세 저장소가 동시에 낡는다. 분리는 레이아웃·내비 층에서만.
- **항목 정본 하나**(`constants/adminConsole.tsx`, 5그룹 12항목)를 ⚙·콘솔 내비(데스크톱/모바일 같은 훅)·콘솔 홈 카드·전역 검색이 전부 읽는다. 기존 `SETTINGS_ENTRIES` export는 평탄본으로 남겨 정적 테스트 3개가 무수정 통과.

## 검증
tsc·eslint 0 · jest 7 suites 141 통과(신규 14) · 헤드리스 Chrome 실측(콘솔 홈·관리 화면 선택 표시·⚙ 드롭다운 4항목·모바일 서랍 14항목). 커밋 `d47c0a5` → master fast-forward 병합(미푸시), 워크트리·브랜치 정리.

## 교훈
- **"메뉴가 많다"는 그룹 문제가 아니라 노출 축 문제일 수 있다.** 개인/관리자 항목이 같은 축에 섞였는지 먼저 본다.
- **URL 변경 비용은 FE 밖에서 결정된다.** 경로를 문자열로 갖고 있는 곳(AI 화면 카탈로그·문서·테스트)을 세 곳 grep한 뒤에 "깨끗한 모델"을 고를지 정한다.
- **데스크톱·모바일 내비가 트리를 따로 적으면 반드시 어긋난다.** 메인 사이드바가 그 병을 앓고 있어 콘솔은 처음부터 훅 하나를 공유하게 했다.
- 워크트리 실측: `.env`는 untracked라 복사 필요 · BE dev CORS가 5173~5175뿐이라 `--port 5174 --strictPort` · headless-shot은 `FE_ROOT`로 `ws` 해석 경로 지정.
