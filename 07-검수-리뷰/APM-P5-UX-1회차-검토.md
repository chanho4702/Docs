#### v2와 맞춰야 할 계약 정리

1. **snapshot 이벤트는 세 개다.** `snapshot.begin → snapshot.chunk → snapshot.end` 검증 완료 뒤에만 화면을 확정한다. 중간 chunks를 차트에 그리지 않는다.
2. **재생 커서는 `(epoch, viewKey, seq)`다.** 수동 EventSource 재생성에도 `viewKey`를 전달한다. `pointsRev`와 `statsRev`는 별도로 적용한다.
3. **`dictVersion` 증가는 세대 초기화가 아니다.** 정상적인 사전 추가마다 필터를 해제하지 않는다. 삭제·누락·불연속을 구분한다.
4. **버킷 키는 `(serviceId, b)`다.** 다서비스 화면에서 문서의 `Map<b, TypedArray>`만 구현하면 같은 초의 서비스가 충돌한다.
5. **강조 보존 문구를 낮춘다.** “오류·느림은 유지”는 서버에서도 전량 보관한다는 인상을 준다. “브라우저 추가 축소에서 강조 계층 우선 유지”가 정확하다. 기본 계층에도 오류·느림이 있으므로 ‘정상 표본만 솎음’도 부정확하다.
6. **재접속 종료 조건을 빠짐없이 옮긴다.** 429 지연·jitter, 연속 실패 5회 후 수동 재시도, 일반 네트워크 재접속, 401 세션 확인, `epochChanged` 시 연결 유지 후 snapshot 대기를 구분한다.
7. **솎음 비율 하나로 창 전체를 설명하지 않는다.** 과거 버킷의 전달률이 다를 수 있다. 상시 배지는 실제 표시 수를 기준으로 하고 단계별 비율은 보조 정보로 둔다.

`replaceMerge`는 `notMerge:true`와 함께 기존 상태를 보존하는 기능이 아니다. `notMerge:true`가 전체 컴포넌트를 새로 만들며, `replaceMerge`에서 기존 계열을 유지하려면 안정적인 `id`가 필요하다. [ECharts 공식 API 설명](https://github.com/apache/echarts-doc/blob/master/en/api/echarts-instance.md)

#### 계산·탐색에서 추가로 고칠 사항

- **부모 종료 이후 구간 길이**는 `max(0, childEnd - max(childStart, parentEnd))`다. `childEnd-parentEnd`는 부모 종료와 자식 시작 사이의 공백까지 포함할 수 있다.
- 겹침 계산은 `[start,end)`로 정의한다. 같은 시각의 종료와 시작을 중복으로 세지 않고, 0ms 스팬을 실행 구간으로 늘리지 않는다.
- 2,000칸으로 줄일 때 값이 **평균/최대/시점 값 중 무엇인지** 결정한다. 칸 수 제한만으로 의미가 정해지지 않는다.
- `truncated`뿐 아니라 `rootMissing`, `cycleBroken`, 고아·적재 진행 상태도 프로파일의 해석 범위에 반영한다.
- 링크 5,000×32개를 모두 SVG로 그리지 않는다. 전체 개수는 계산하되 관계선은 선택한 링크 중심으로 제한한다.
- **발행 trace에서 자신을 참조하는 소비 trace들을 찾는 역방향 조회는 현 detail 응답으로 불가능하다.** 따라서 “비동기 트랜잭션 전체 묶어 보기”는 FE 단독 범위가 아니다.
- 메시징 롤업은 첫 링크 우선, 링크가 없을 때 부모를 사용한다. 같은 시스템·식별 가능한 목적지, 발행 시각 1시간 lookback 등 조건도 있다. 모든 링크를 탐색하는 화면과 `lagCount`가 일치한다고 설명하지 않는다.

## 3. v2 필수 8건 반영 간이 확인

**문서 반영 여부만 확인한 결과이며, 성능·정합성의 최종 판정은 실측 뒤 3회차에서 합니다.**

1. **✅ 반영 — 수신·보관·표시 분리:** §0에서 표시 전량 보장을 철회하고 층별 약속을 분리했다.
2. **🟡 부족 — 실제 allocation 제한:** §2.4의 슬롯 arena 전환은 반영됐지만, 고정 할당과 §5의 정상 부하 힙 설명 및 사전 예산이 일치하지 않는다.
3. **✅ 반영 — 메타 캐시:** soft/hard expiry, single-flight, generation, commit 이후 무효화, 라이선스 freshness 분리가 명시됐다.
4. **✅ 반영 — snapshot·커서·revision:** 발행 경계, `sinceSeq/viewKey`, revision 분리, 사전 참조 수명 규칙이 문서에 들어갔다. 절차의 정합성 본판정은 유보한다.
5. **🟡 부족 — 바이트 상한:** frame·로그·큐·chunk 상한은 들어갔지만, 전체 retained bytes와 admission 예산의 증명이 아직 닫히지 않았다.
6. **✅ 반영 — control·재접속:** 명시적 close, retryable 분기, 실패 상한, 거절 변환 위치가 들어갔다. UX 문서의 누락은 별도 보완 대상이다.
7. **✅ 반영 — partialSuccess 수량:** 중복·표시 축소를 실제 거절 수에서 제외하는 보존식이 반영됐다.
8. **✅ 반영 — HTTP·오류·단일 노드:** HTTP SERVER 모집단, 오류 두 축, BE 전체 1대와 같은 프로세스의 메트릭 공급이 명시됐다. §8-2b의 질문 3건도 이 결정과 일치한다.

### 반영 과정에서 새로 드러난 모순

| 위치 | 문제 | 필요한 정리 |
|---|---|---|

## 4. P5.6 선출시 선언과 R-P5.6

### 선언

**P5.6은 지금 독립적으로 구현 착수할 수 있습니다. R1·R2를 기다릴 필요는 없습니다.**

다만 첫 출시 범위는 다음처럼 한정하는 것을 권합니다.

- 응답에 포함된 링크 목록과 같은/다른 trace 이동
- 부모 종료 이후 완료 마커·해칭
- 관련 스팬 필터와 원래 선택으로 돌아가기
- 저장·응답 범위와 누락 가능성을 설명하는 빈 상태
- 선택적으로 kind별 자기 시간 비율

**정확한 스레드 레인, 실제 병렬성 판정, 발행→모든 소비 역탐색은 이 FE 단독 선출시 선언에 포함하지 않습니다.**

### 착수 전 반드시 고칠 항목

1. ‘비동기 정의’에서 **관계·시간상 특징·실제 실행 방식**을 구분한다.
2. 링크 대상 kind 미확인 상태, 부모 관계, 같은 trace 메시징을 처리한다.
3. 링크 32개 상한과 누락 메타데이터 부재를 반영해 완전성 문구를 낮춘다.
4. 스레드 식별 범위를 축소하거나 필요한 BE 필드를 별도 범위로 확정한다.
5. 겹침 수를 병렬 실행 수로 부르는 문구를 삭제한다.
6. `msgDest` 등 실제 경로·query·탭 키, 선택 복귀, 404 문구를 수정한다.
7. R-P5.6을 출시 게이트에 넣고 공수 포함 여부를 통일한다.

### R-P5.6의 구체 절차

**목적을 두 개로 나눠야 합니다.**

- **생성 검증:** 해당 javaagent·라이브러리 설정에서 링크나 자식 스팬이 실제 생성되는가.
- **보존 검증:** 생성된 관계가 Collector→BE→DB→API→화면까지 계약대로 유지되는가.

`@Async`나 CompletableFuture의 컨텍스트 전파 지원은 작업마다 스팬이나 링크가 생성된다는 뜻이 아닙니다. 자동 생성 결과와 `@WithSpan`/수동 스팬으로 관측 지점을 추가한 결과를 분리해야 합니다. [Java 자동계측 공식 지원 목록](https://github.com/open-telemetry/opentelemetry-java-instrumentation/blob/main/docs/supported-libraries.md)

#### A. 환경 고정

다음을 결과 문서에 기록합니다.

- JDK·javaagent·Spring·Kafka/RabbitMQ 클라이언트 버전
- SDK 샘플러·BSP 설정, Collector 버전·저장 파이프라인 설정
- semconv opt-in과 활성 계측 옵션
- fixture별 예상 작업 수·메시지 수·trace/span/message 식별자
- 프로세스/인스턴스 및 스레드 이름·ID를 기록한 앱 측 기준 로그

먼저 **fixture가 전부 저장되는 격리된 조건**으로 전달 정합성을 확인하고, 그다음 실제 tail 샘플링 조건으로 미저장·늦은 도착을 확인합니다. P5 live 파이프라인은 필요하지 않습니다.

#### B. fixture 행렬

| fixture | 실행 조건 | 확인할 것 |
|---|---|---|
| 동기 호출 음성 대조군 | 부모 안에서 자식 DB/HTTP 호출이 끝나는 요청 | 겹치는 스팬이 2개 이상이어도 비동기/병렬로 확정하지 않는가 |
| `@Async` | fire-and-forget / 호출자가 완료를 기다리는 경우 각각 | 순수 자동계측에서 자식·링크가 생기는지, 없으면 관측 스팬을 추가했을 때 부모 전파가 유지되는지 |
| CompletableFuture | 기본 실행기·사용자 Executor, `thenApply`·`thenApplyAsync`, `allOf` 각각 | 컨텍스트 전파, 부모 선택, fan-out/fan-in 링크의 실제 생성 여부 |
| Kafka | 단건·배치 소비, 두 생산 trace의 메시지 묶음, 처리 지연 | 실제 `kind/operation`, 부모 또는 링크 경로, 메시지별 링크 속성 |
| RabbitMQ | 단건 listener·여러 소비자·배치 가능 구성 | 동일 trace/다른 trace, 생산자 참조, fan-out 관계 보존 |
| 수동 Link 대조군 | 같은 trace의 비부모 링크·부모와 같은 링크·다른 trace 링크 | UI 관계 처리를 결정적으로 검증. **자동계측 지원의 증거로 사용하지 않음** |
| 경계·누락 | 링크 31/32/33개, 대상 미저장, 늦은 자식, 동일 스레드 이름의 두 JVM | 상한·빈 상태·잘못된 스레드 합치기·재조회 동작 |

배치 링크 128/129 경계는 SDK 자체 상한과 BE reader 상한을 구분할 수 있는 입력으로 추가합니다. 최신 메시징 규약의 kind와 기존 agent 출력이 다를 수 있으므로 **실제 출력 버전별 결과**를 남깁니다.

#### C. 측정 지점

| 지점 | 남길 자료 |
|---|---|
| **M0 앱 기준 로그** | 실제 작업·메시지 수, 시작/종료, trace/span ID, 실행 스레드 |
| **M1 Collector 수신 직후·tail 이전** | 원본 OTLP의 `kind`, parent, links, 링크 속성, `thread.*` |
| **M2 저장 exporter 출력 / BE 파서 입력** | Collector 처리 뒤 동일 필드가 남는지 |
| **M3 `linksJson`·허용목록 적용 뒤** | 유효 링크 순서, 32개 절단, 허용·별칭·차단 속성 |
| **M4 `apm_span`** | `parent_span_id`, kind, 시작·지속시간, attrs, links jsonb |
| **M5 trace detail API** | 동일 링크 ID·순서, 조회 마스킹, offset/duration, 부분 응답 플래그 |
| **M6 화면** | 마커·개수·점프 대상·선택 복귀·누락 안내·키보드 동작 |

#### D. 합격식

**1. 링크 전달 정합성**

스팬 `s`마다 다음을 정의합니다.

- `L(s)`: M2에서 유효한 ID를 가진 링크 목록
- `E(s)`: `L(s)`의 앞 32개에 현 허용목록·별칭·정책을 적용한 기대 목록

전부 저장하는 대조 조건에서는:

```text
DB.links(s) = E(s)
API.links(s) = 조회 마스킹 정책을 적용한 E(s)
```

ID·순서·허용 속성 보존 일치율 **100%**, 허용되지 않은 속성 잔존 **0건**을 합격 조건으로 둡니다. 33번째 링크의 제거는 계약대로면 합격이지만, UI가 ‘전체 링크’라고 말하면 UX 불합격입니다.

**2. 자동계측 생성 여부**

각 시나리오를 예를 들어 100회씩 반복하고 다음을 별도로 기록합니다.

```text
작업 스팬 생성률
부모 컨텍스트 연결률
링크 생성률
같은 trace / 다른 trace 비율
```

링크 0건이면 **‘해당 구성에서는 자동 생성되지 않음’**입니다. 수동 Link fixture 성공으로 이를 덮지 않습니다. 자동 메시징 연결을 제품에서 지원한다고 표시할 구성은 반복 수행에서 예상 관계 누락·오연결이 없어야 합니다.

**3. 시간·관계 계산**

동일 JVM의 결정적인 fixture에서:

```text
부모 종료 이후 표시 = childEnd > parentEnd + 허용 오차
해칭 길이 = max(0, childEnd - max(childStart, parentEnd))
겹침 수 C(t) = Σ 1[start ≤ t < end]
```

기대 마커와 계산 결과가 일치하고, 동기 대조군을 ‘병렬 실행’이라고 표현하는 사례는 **0건**이어야 합니다. 다른 호스트의 시계 차이는 별도 불확실성으로 취급합니다.

**4. 조회·탐색**

- 저장된 대상 이동: 정확한 trace·span 선택 성공 **100%**
- 같은 trace 대상이 접혀 있거나 화면 밖에 있어도 이동 가능
- 대상 미저장·대상 스팬 누락·403·일시 오류를 서로 구분
- 돌아가기 시 원래 선택·탭·필터 복원
- 늦게 저장된 자식·대상은 명시적 재조회로 확인 가능

**5. 표시 성능**

5,000스팬, 최대 링크 수, 많은 스레드 속성 값, 접기·필터·점프를 포함합니다. **잠정 기준**으로 입력 반응 200ms 이내, 최장 UI 정지 500ms 미만을 실행 전에 고정할 수 있습니다. 2,000칸 제한이나 sweep line의 복잡도만으로 합격시키지 않습니다.
