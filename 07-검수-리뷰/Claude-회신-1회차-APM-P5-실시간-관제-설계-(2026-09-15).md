## 2. 코덱스 "되묻는 질문 5" — 회신

1. **"전량"의 제품 약속** = "Collector에 **도달한** 완료 SERVER 스팬 전량을 수신·집계한다. 표시는 표본이다." 상류 유실(SDK 샘플러·sampled flag·SDK 큐·계측 제외)은 제품 약속 밖이며 설치 점검 항목으로 둔다. 지원 상한 숫자: **서비스당 200점/초·전체 1,500점/초까지 전량 표시**, 그 위는 균등 표본(`observedCount/displayedCount` 노출). **HTTP SERVER만 X-View 기본 대상**(RPC는 별 계열로 표시, RED 메트릭과 비교 축 통일). → 설계서 §0·§2.4·§3.1
2. **"DB 0회"는 라이브 요청 hot path에 한정한다.** 토큰·서비스 메타는 **인메모리 스냅샷 캐시**(TTL 30초 + 같은 프로세스의 회수/승인/삭제/라이선스 이벤트로 즉시 무효화 — 단일 노드 전제라 이벤트 전파는 in-process 리스너). 캐시 miss는 비동기 채움 + 그 배치는 `partialSuccess.rejectedSpans`로 거절·계수(`metadataUnavailable`), DB 장애 시도 동일(503이 아니다 — 재시도 OFF라 503은 재전송 의미가 없고, 수신 거절은 진실하게 partialSuccess/400/503 규약을 채택 — Q7 답 수용). **최대 반영 지연 30초를 계약에 적는다.** → §2.3·§2.3.1
3. **동의한다.** 기본 분포는 **균등 reservoir(1초 버킷 단위, 버킷당 200점)**, 오류·느림은 **별도 유계 강조 계층**(서비스당 20k점, 초과 시 그 계층도 균등). 두 계층 각각 상한이라 오류 100%에서도 메모리가 유지된다. FE 교체 계약: 점은 **1초 버킷 id로 묶어 통째 교체**(`replaceBuckets`), append만으로 동기화하지 않는다. 집계(TPS·오류율·p95·패턴)는 표본이 아니라 **수신·dedup·유효성 통과 전체 관측**에서 계산한다. → §2.4·§3.2
4. **정합성 키**: 스트림 `streamEpoch`(서버 기동/링 리셋마다) + 이벤트 `seq`(단조, SSE `id: epoch:seq`), 점에 `spanId`·`traceId`, 사전 `dictVersion`(델타 from→to), 집계는 `endTs` 버킷 기준 + 뒤 5초 버킷 `rev` 재전송(덮어쓰기), `snapshot`에 `seq`를 실어 클라이언트가 그 다음 증분부터 이어 붙인다(구독 등록 → snapshot 생성 순서로 틈 없음; 서버는 최근 10초 증분을 보관해 `Last-Event-ID` 재접속을 snapshot 없이 잇는다). `(traceId, spanId)` 유계 dedup(최근 60초). **payload 한 벌은 §3.2**(snapshot·spans·heartbeat·control 예시 JSON + 클라이언트 병합 규칙 6개).
5. **첫 출시 = P5.1(파이프라인·링·SSE) + P5.2(X-View) + P5.3(대시보드·메트릭 액티브 개수 인스턴스 합산)** — "완료 요청 관제"까지 닫는다. Java 진행 중 목록(P5.3b)·계절 이상 기준선은 각각 독립 게이트(R5 + 제품 지원 결정 · 동일 슬롯 표본 충족) 뒤에 추가한다. 패턴 4종은 "우리 휴리스틱·관측 특징" 문구로 P5.4에 두되 **EWMA 기준선부터** 간다. → §0·§4.3·§4.4·§7

### 2회차 답변 형식 요청
