## 사용자가 본 문제 → 결정
1. "워크로그 쌓는 진입점이 하나였으면" → 연동 모드의 쓰기 창구는 **승인 앱 하나**. 워크포스 4화면은 넘김 버튼, 수정·삭제도 서버 경유 실행 시점 재판정.
2. "결재권자 동기화·표시" → 판정은 이미 org 서명 게시물로 동기화돼 있었고 **표시만** 없었다. 팀 탭·결재선 이름 추가(데이터는 W-8a 뒤).
3. "이슈별 정책을 패널에서 손보는 건 말이 안 됨" → **이슈 화면은 기록·보기·승인 요청·이력 네 가지만.** 정책 패널·결재선 선택 제거, 편집은 프로젝트 설정(단독)/워크포스 승인 설정 표(연동).
4. "작업 관리 하단 메뉴" → 이미 있던 워크포스 '승인 설정' 보기를 확장(결재선 열). **기록 규칙 7키는 넣었다가 뺐다**(아래 교훈).
5. "메뉴·역할 구분" → `isAdmin` 맥락, 관리자만 '관리' 묶음, '내 이력'·'승인 관리'·'기록' 1차 메뉴.
6. 이슈 화면 하단 잘림 → body margin 8px 가 iframe-resizer 측정에서 빠짐. [[forge-custom-ui-iframe-height]]

## 교훈
- **"상세 정책"이라는 말을 그대로 받아 범위를 넓히지 말 것.** 사용자가 "이슈별 상세 정책"이라 했을 때 기록 규칙(하루 상한 등)까지 팀장 표에 넣었다가 "팀장은 결재하는 사람인데 왜 시간이 나오지?"로 되돌렸다. 정책은 **누가 정하는 사람인가**로 먼저 갈라야 한다(근태 규칙 = 사이트 관리자, 작업별 통제 = 팀장). 구현 전에 "이 항목은 누가 만지나" 표 한 장이면 막혔다.
- **설계 전에 기준 브랜치를 확인.** master 가 현행이 아니었고(linked-issue-schedule 8커밋 미병합) 설계 에이전트가 찾아냈다. 하네스 Phase 0 에 `git log master..<branches>` 확인을 넣을 것.
- **"판정은 이미 동기화됨"은 코드 경로만 사실일 수 있다.** 워크포스가 org 문서의 팀 칸을 비워 보내고 있어서 화면을 만들어도 데이터가 없었다. 원천 데이터가 실제로 흐르는지 먼저 본다.
- **코덱스 검토가 잡은 것**: 화면 판정 캐시(5분)로 연동 전환 뒤 옛 판정으로 PUT/DELETE 가 나가는 경로, 이동 이슈가 옛 프로젝트 예외 목록에 남는 것, 쿼리 상한 테스트가 mock 으로 실제 비용을 가린 것(실측 635회 → 묶어서 16회). "N건 녹색"이 비용을 증명하지 않는다 — 실제 경로를 연결한 계측 테스트가 필요.
- **다른 이슈 id 로 우회**(R-U1)는 Jira 동작 실측에 기대지 않고 서버에서 소속·작성자를 대조해 닫았다. 플랫폼 보장이 불확실하면 앱이 한 번 더 확인하는 쪽이 싸다.
- 설계 열린 질문은 **기본안으로 진행하고 제품 결정만 4개로 추려 물었다** — 사용자가 한 번에 답할 수 있는 크기.
- 브라우저 확인은 로그인 세션이 있는 **Windows Chrome** 에서만([[chrome-use-windows-browser]] 메모리).
