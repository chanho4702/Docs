## 2. 통합하지 않기로 한 것 ★

이번 작업에서 배운 건 **"중복이니까 합친다"가 항상 옳지는 않다**는 쪽이다.

- **`StatusBadge` ↔ `SemanticBadge`** — 이름이 같아서 합칠 것처럼 보였지만 하는 일이 달랐다.
  전자는 *사용자가 고른 색*(`COLOR_OPTIONS`)을 칠하고, 후자는 *뜻이 고정된 상태*(success/warning/danger)를 그린다.
  → 합치지 않고 **이름과 위치만** 정리했다(`pages/resource/StatusBadge` → `components/lozenge/SemanticBadge`).
- **카드 3종(Card·WidgetCard·ChartCard)** — `ChartCard` 는 접기·인라인 제목편집·드래그 등
  커스텀 대시보드 전용 기능이 있다. 하나로 합치면 prop 이 비대해진다.
  → **겹치는 부분(전체화면 오버레이)만** 뽑아냈다.
- **`SectionMessage` 48곳** — Atlaskit 을 이미 일관되게 쓰고 있고,
  `appearance`(warning/error/information) 선택은 **도메인 판단**이라 일괄 규칙을 씌울 성질이 아니다.
- **프론트 quick-add 3벌** — 주입 인자가 6개라 통합 이득이 크지 않다(이건 다음 날 감사에서도 같은 결론).

> 판단 기준은 "코드가 닮았나"가 아니라 **"한쪽만 고쳤을 때 사용자가 다른 화면에서 다른 것을 보게 되나"** 였다.
> 전체화면 오버레이는 그렇고(→ 통합), `appearance` 선택은 아니다(→ 유지).

## 3. 색 토큰화에서 나온 것

### 3-1. 토큰은 문자열이라 산술이 안 된다

```js
background: color + '22'   // hex 였을 땐 알파 8자리로 동작
                           // 토큰은 `var(--ds-...)` 문자열 → 무효 값 → 배경이 사라진다
```

hex 를 토큰으로 바꾸는 순간 **색을 조작하던 코드가 조용히 죽는다.** 에러는 안 난다.

### 3-2. ECharts 만은 hex 를 박아 둔다

ECharts 는 canvas 라 `var(--ds-*)` 를 해석하지 못한다. `chartPalette.js` 는 Atlaskit
`color.chart.categorical.1~8` 의 **실제 값**을 복사해 라이트/다크 양쪽에 쓴다.
"미토큰화 0"을 목표로 삼되 **고칠 수 없는 것과 고치면 안 되는 것**(서드파티 오버라이드, 팔레트 정의 자체)은 명시적으로 남겼다.

### 3-3. `isDark ? A : B` 는 대부분 불필요했다

DOM 요소는 토큰이 CSS 변수라 테마가 알아서 바뀐다. 라이트/다크를 손으로 가르던 코드가
분석 리포트 표 4종에 있었는데 전부 지웠다. 손으로 갈라야 하는 건 canvas(ECharts)뿐이다.

### 3-4. "단일 출처"라고 쓴 주석이 거짓말이었다

가동률 밴드(>100/>=80/>=50) 판정에 *"단일 출처"* 주석이 붙어 있었지만 실제로는 **세 곳에 복사**돼 있었다.
→ `utilizationBand()` 로 뽑아 막대·숫자·팀별 표가 공유하게 했다.

> **주석은 검증되지 않는다.** 단일 출처라고 적혀 있으면 오히려 grep 해 볼 이유가 된다.

## 4. 곁에서 잡힌 실제 버그

### 4-1. ECharts 가 폭 0 에서 init 되면 영영 안 그려진다 ★

"이슈별 비용 우측 파이가 **간헐적으로** 빈 채로 남는" 증상.

```
패널이 flex-basis 0 → 40% 로 펼쳐지는 0.3s 트랜지션
  └ 그 사이 ECharts 가 폭 0 에서 init
      └ ResizeObserver 콜백이 인스턴스 준비 전에 오면 그냥 흘러간다
          └ 트랜지션이 끝나면 더 이상 크기 변화가 없다 → resize 가 다시는 호출되지 않는다
```

→ 패널 오픈 후 **두 시점에 resize 를 직접 보장**. 애니메이션과 지연 init 이 겹치는 자리는
"이벤트를 기다리는" 설계가 통하지 않는다. 이벤트가 이미 지나갔기 때문.

### 4-2. 다크모드 흰 장막

`Card` 의 전체화면 오버레이 배경이 `#fff` 하드코딩. 큰따옴표로 적혀 있어서 앞선 색 정리 스윕에서 빠졌다.
→ **일괄 치환은 자기 정규식이 놓친 것을 보고해 주지 않는다.** 결과 카운트("미토큰화 0")를 믿지 말고 눈으로 한 번 훑을 것.

### 4-3. CSS 고아 셀렉터

다중 셀렉터 다크 블록을 정리하다 `{` 없는 첫 줄이 남았다. 뒤따르는 `@media` 가 셀렉터에 붙어 무효화될 수 있었다.
→ CSS 는 **문법 오류가 있어도 빌드가 통과**한다. 대량 삭제 작업 뒤에는 파일을 다시 읽어야 한다.

## 5. 사용자 결정

**13px → 12px** (107건). 14 로 올리면 테이블 한 줄에 들어가던 글자가 넘친다.
스케일을 줄이는 방향은 기계적으로 정할 수 없고, 실제 화면이 견디는 쪽을 사용자가 골랐다.

## 6. 한 줄 정리

**공용화의 기준은 "코드가 닮았나"가 아니라 "한쪽만 고쳤을 때 화면이 갈리나"다.**
그리고 색을 토큰으로 바꾸면 **색을 조작하던 코드가 에러 없이 죽는다** — hex 는 값이었고 토큰은 문자열이다.
