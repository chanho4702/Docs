## B. 중점 확인 요청 1~8 답변

### 1. I1~I19 및 Phase — 🔴

전체가 일치하지는 않습니다. **I8은 일치하고, 현재 파일의 I9도 이미 “상세 탭 P1a / 인시던트 목록·메뉴·재생 P3”로 되어 있어 요청서의 우려는 해소되어 있습니다.** I12의 엔진 구분은 맞지만 tracked SQL P1a로 읽히는 부분은 WS-17 P3와 어긋나며, I10은 카운터와 그래프 Phase를 나눠야 합니다.

I15의 지연 카운터 P1a~P2는 부록 B와 어댑터 도착 순서에 맞습니다. I17의 Oracle 스키마·객체 통계 **소스가 미확정이라는 판단도 맞지만**, 허용목록에 딕셔너리 뷰가 전혀 없다는 설명은 틀립니다. `DBA_OBJECTS/CDB_OBJECTS`와 `DBA_TABLESPACE_USAGE_METRICS`는 이미 존재하며, 이들이 스키마 추적·인덱스 사용 통계까지 보증하는 것은 아닙니다.

> **수정:** “일반 추이·카운터, tracked SQL, 캐시 플랜, 독립 메뉴의 Phase를 각각 표시한다. Oracle 스키마·객체 통계는 전용 소스·권한·범위가 본문에 미확정이다.”

### 2. Oracle 데드락 소스 — 🔴

**`V$SYSSTAT`는 §4의 명시적 grant·허용 범위 안에 있습니다.** Oracle 공식 문서에도 `enqueue deadlocks` 통계가 존재합니다. 그러나 객체 호출 허용은 그 안의 특정 통계를 MovesEye 카운터·알람으로 채택했다는 계약과 같지 않습니다. [Oracle 19c 통계 정의](https://docs.oracle.com/en/database/oracle/oracle-database/19/refrn/statistics-descriptions-2.html)

현재 §7.1은 “인증된 카운터 소스가 있는 엔진·버전” 조건이고, §5.8의 정본 카운터 열거에는 Oracle이 없습니다. 부록 B의 “sysstat 선택”만으로 I10의 **건수 4종 제공 확정**을 뒷받침하기는 부족합니다.

> **이번 검수 범위의 권고:** I10에서 Oracle 제공 확정을 빼고 “소스 후보·채택 미확정”으로 낮춘다. 유지하려면 Q를 신설하고 §7.1·부록 B에 metric 식별·단위·리셋·scope·인증 조건을 추가한다. 이는 단순 재배열이 아니라 계약 보강이다.

### 3. OTel 필수 여부 — 🟢

**“J1을 사용할 때 OTel이 필수가 아니다”와 “O1 유예 시기는 R7 뒤 확정한다”는 양립합니다.** 전자는 기본 경로의 필수 구성요소, 후자는 보조 경로의 채택·시기에 관한 설명입니다. 다만 현재 문장은 망 조건과 R7 통과 조건을 벗어난 보편적인 도입 보증처럼 읽힐 수 있습니다.

> **수정:** “BE→DB 직접 접속과 필요한 DB 권한·설정이 갖춰진 J1 환경에서는 DB 모니터링을 위해 OTel Collector를 추가할 필요가 없다. O1 보조 경로의 지원 엔진·동등성·제공 시기는 R7 비교 결과와 Q11로 확정한다.”

## D. 종합 판정

**고객 문서·화면 문구의 기준표 승인 보류입니다.** A·B·C에 반복된 지적을 합치면 주요 🔴 잔존은 다음 **10건**입니다.

| # | 잔존 계약 문제 | 해제 조건 |
|---|---|---|
| R1 | I19의 설정 누락과 정책 미지원 혼용 | PG Q `MISSING`, PG P `UNSUPPORTED`로 통일 |
| R2 | I10의 Oracle 데드락 제공 확정 | §16에서 미확정으로 낮추거나 별도 채택·인증 계약 추가 |
| R3 | I16의 태그 귀속에 APM Feature 추가 제한 | APM 상관과 DBM 태그 기능의 권한 범위 분리 |
| R4 | §16.3의 관리형 DB 포괄 지원 약속 | 서비스별 인증 전 미확정으로 완화 |

| R7 | Redis 종결·MongoDB 순서·P5 후보·10일 견적 | Q31 신규 제안으로 명시하거나 삭제 |

| R9 | I7의 모든 카운터 15s 약속 | 부록 B의 개별 주기 예외 명시 |
| R10 | I12의 tracked SQL P1a 해석 | 일반 추이와 P3 tracked SQL 기능 분리 |

추가로 I5 범례, I11 리셋 구간 분리 표시, 전 응답 capability 등 **새 화면·API 동작은 삭제하거나 본문 계약으로 분리**해야 합니다. 인과관계처럼 읽히는 설명, 보존 자동 조정의 잘못된 부정, 빠진 인사이트도 위 권고대로 정리해야 기준표가 본문을 충실히 대표합니다.

작성자 주장은 다음처럼 바꾸면 정확합니다.

> **“기존 GA 확정 범위와 공수 합계는 변경하지 않았다. §16은 기존 계약의 고객 질문별 재배열을 기본으로 하되, 비범위 저장소 재개에 관한 신규 미결 제안 Q31을 포함한다. 별도 승인되지 않은 지원·기본값·일정·견적은 제품 계약으로 사용하지 않는다.”**

**I8·I9의 Phase 구분, I14의 프로시저 캐시 수명, I15의 membership scope, I3의 `observedShare`는 기존 반영 내용을 유지하고 있습니다. 이 부분을 다시 설계할 필요는 없습니다.**
