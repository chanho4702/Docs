2026-10-08 사용자 결정: 워크로그 시간은 결재선 "승인"이 아니라 **인증(certification)** 개념으로 간다.
- Jira 워크로그 = 본인 주장. 수정을 막을 수 없다(권한에 기간 조건 없음, REST·자동화 경로 존재).
- 인증된 시간의 **원본은 승인 앱 Forge SQL** 의 인증 레코드(워크로그 id·일자·초·지문·인증자·시각). Jira 가 바뀌면 지문 불일치 → 자동 미인증, 인증 레코드는 유지.
- **워크포스는 인증된 시간만** 원가·정산에 쓴다. 교환은 사용자×월 프로퍼티(32KB 한도, 월 단위 분할)에 합계 초 + 인증 워크로그 id·초 목록 + 서명. 현재 계약(상태+묶음 해시)에서 **인증된 초를 싣는 쪽으로 계약 변경 필요** → 워크포스 리포 수정 승인 필요.
- 결재선 타임시트 승인은 선택 기능으로 내려간다. 변경 이력은 "인증값 vs 현재값 차이" 설명 자료.
- 2026-10-08 추가 결정: (1) 인증 후 Jira 삭제 시 인증 시간 유지/0 처리는 **정책 옵션**. (2) 인증 단위(건별 vs 사용자×월)도 **정책 옵션** — 저장은 항상 건별 레코드, 월 모드는 일괄 인증 흐름+월 합계 게시(UI·흐름 차이). (3) **재인증은 팀장**이 한다.

**Why:** 워크포스 연계에서 "승인"은 "돈으로 쳐도 된다는 서명"일 뿐이라 승인 의례가 되기 쉽고, 수정 차단은 플랫폼상 불가능하다. 인증 레코드를 원본으로 두면 수정해도 인증된 시간은 안 바뀐다.
**How to apply:** 워크로그 관련 설계·보강(변경 이력 판단 화면 등)은 이 모델을 전제로 한다. 워크로그 프로퍼티 건별 쓰기는 기각(일괄 인증 시 수천 PUT). 관련: [[paid-license-gate]]
