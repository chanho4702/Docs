  🔴 **핵심 교훈 4개(전부 코덱스가 차단으로 잡음)**: ① **1콜 행 상한 < 보유 상한**이어야 쪼개 완주가 가능하다(같으면 "한 조각이 넘쳤다 = 이미 상한 초과") → history.get을 10만→**1만**으로 낮추고 기동 시 검증. ② **정책 창과 행 상한은 짝** — `200개 × 3,000초 ÷ 1분 = 1만 행`. 어긋나면 매 창 헛읽기+분할(창 3,600→3,000초). ③ 실행기의 **확정 전 창 버퍼**도 예산에 넣어야 한다 — `maxWindowRows`를 `IntSupplier`(남은 자리)로 주고, 이번 콜 상한도 `min(정책, 남은 자리)`로 낮추고, 전달한 페이지는 즉시 `set(i,null)`. ④ **분할은 기존 소비자를 깨뜨린다** — `ItemsService`는 "응답이 정확히 10만이면 잘림"으로 판정했고 `HostService`는 DESC로 최신 구간을 지켰다 → 레거시 `getHistoryByItemids`·`getRange`는 **1콜 그대로 두고** 분할은 새 API에만.
