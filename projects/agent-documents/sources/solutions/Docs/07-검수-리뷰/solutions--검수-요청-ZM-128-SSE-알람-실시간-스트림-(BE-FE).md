## 범위·의도

모니터링 제품인데 핵심 화면이 수동 새로고침이던 문제의 해소. 사용자별 폴링(벨 60초 × 접속자)을
서버 push로 뒤집는다. 새 장애의 화면 도달: 종전 "수동 새로고침/최대 1분+α" → **동기화 15초(ZM-127)
+ push 즉시 + 재조회(사본 DB 읽기)**.

### BE (`11bd25e`)
- `GET /event/stream` — SSE. 인증=accessToken 쿠키, 세션 대조=visitorId 쿼리/헤더
  (**APM Live 선례 그대로** — EventSource가 커스텀 헤더 불가·토큰 쿼리 금지·"없으면 통과" 함정 회피,
  판정은 공용 `VisitorSessionChecker`).
- `EventStreamHub` — 연결 레지스트리+하트비트(25초)+수명 30분. 🔴 **신호만 민다**(`events-changed`,
  시각뿐): 데이터를 실으면 허브가 권한 스코핑(ZM-125)을 복제하게 되고 그 복제본이 어긋나면 샌다.
  건수조차 안 싣는 이유도 같다(전역 건수도 가시 범위 밖 정보).
- 브로드캐스트 지점: 증분 사이클이 실제 변화(신규·해소)를 본 때 + 보정(5분) 무조건 + 조치 직후
  표적 재동기화. 접속 직후 첫 이벤트도 `events-changed`(재접속 공백 메움).
- 🔴 인스턴스 로컬 허브 — HA 시 Redis pub/sub 승격 대상(진단 문서 §2.6과 같은 유예, 주석 명시).

### FE (워크트리)
- `useEventStream` 훅 — EventSource 수명 관리, `events-changed` 수신 시 알람 계열 쿼리 무효화
  (벨·문제목록·이벤트현황·호스트그룹별 — 각 화면이 자기 권한으로 재조회), 2초 스로틀,
  재연결은 EventSource 내장.
- 알림 벨(전 화면 헤더 = 전역 구독 지점): `refetchInterval: isLive ? false : ONE_MINUTE` —
  **SSE 살아 있으면 폴링 정지, 끊기면 종전 60초 폴백**.
- `AlertService.eventStreamUrl()` — APM `liveStreamUrl`과 같은 규약(쿠키 인증·visitorId 쿼리).

## 불안한 지점 (여기를 봐 달라)

1. 신호 스톰: 브로드캐스트 조건(신규/해소 있는 사이클만)이 알람 폭주 상황에서 15초마다 전 접속자
   재조회를 유발 — 재조회가 사본 DB 읽기라 수용으로 판단(FE 2초 스로틀 별도).
2. 문제 목록·서버/네트워크 모니터링 화면 자체는 폴링을 새로 얻지 않았다 — 무효화는 마운트된
   화면의 활성 쿼리를 깨우므로 문제 목록은 열려 있으면 갱신된다. 서버/네트워크 모니터링(호스트 상태)은
   알람 축이 아니라 이번 무효화 대상 밖(범위 판단 — 반박 여지).
3. SSE 연결 수 = 접속 탭 수 — 서버 emitter 자원. 30분 수명+정리 3경로로 관리하지만 상한은 없다.
4. 벨 폴백 전환(isLive)과 useInfiniteQuery의 refetchInterval 재평가 타이밍.
5. 헤더 벨이 없는 화면(로그인 전 등)에서는 구독이 없다 — 의도된 동작(인증 전 스트림 무의미).
