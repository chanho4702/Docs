# MovesEye 기능별 상세 가이드

제품 전체를 **13개 기능 영역**으로 나눠, 영역마다 "무엇을 하는가 · 어떻게 쓰는가 · 내부에서 어떻게 동작하는가 · 무엇이 문제이고 어떻게 보완하는가"를 한 문서에 정리한 묶음이다. 2026-10-06 작업 디렉터리의 소스를 정적으로 대조해 작성했다.

- 화면 하나의 사용법만 빠르게 찾으려면 [화면별 가이드](../%ED%99%94%EB%A9%B4%EB%B3%84/solutions--MovesEye-%ED%99%94%EB%A9%B4%EB%B3%84-%EA%B0%80%EC%9D%B4%EB%93%9C.md)를 본다. 단, 화면별 가이드 대부분은 2026-08-11 기준이라 현재 메뉴·주소와 다른 곳이 많다. 차이는 각 문서 5절과 [종합 리포트](../../%EA%B0%9C%EC%9A%94/solutions--%EC%A0%84-%EC%A0%9C%ED%92%88-%EB%AC%B8%EC%A0%9C%EC%A0%90-%EB%B3%B4%EC%99%84%EC%A0%90-%EC%A2%85%ED%95%A9-%EB%A6%AC%ED%8F%AC%ED%8A%B8.md) 6절에 모았다.
- 전 영역의 문제점을 한 번에 보려면 [전 제품 문제점·보완점 종합 리포트](../../%EA%B0%9C%EC%9A%94/solutions--%EC%A0%84-%EC%A0%9C%ED%92%88-%EB%AC%B8%EC%A0%9C%EC%A0%90-%EB%B3%B4%EC%99%84%EC%A0%90-%EC%A2%85%ED%95%A9-%EB%A6%AC%ED%8F%AC%ED%8A%B8.md)를 먼저 읽는다.
- APM의 개념 설명과 10월 5~6일 보완 내역은 [APM 읽기 안내](../../%EA%B0%9C%EC%9A%94/solutions--MovesEye-%EC%B5%9C%EA%B7%BC-%EC%9E%91%EC%97%85%EA%B3%BC-APM-%EC%9D%BD%EA%B8%B0-%EC%95%88%EB%82%B4.md) 묶음에 있다.

## 읽을 때 알아 둘 표기

- **상태** — `현재`: 확인한 소스에 구현돼 있다(배포를 뜻하지 않는다). `부분`: 일부 조건에서만 구현·검증됐다. `계획`: 설계·제안 단계다. `보류`: 재개 결정이 필요하다.
- **중요도** — `높음`: 데이터가 틀리거나 유실됨, 권한 우회, 대규모에서 장애 가능. `중간`: 특정 조건의 오동작·운영 부담·검증 공백. `낮음`: 사용성·정리·문서.
- **증거 수준** — `코드 확인`: 이번에 해당 소스를 열어 확인한 사실. `기존 기록`: 과거 감사·검수·QA 문서의 내용. `추론`: 확인한 구조에서 예상되는 영향으로, 발생 빈도와 크기는 실측하지 않았다.
- **문제점 ID** — 영역 접두사 + 번호다. `HOME` `MON` `EVT` `AST` `MAP` `ZCF` `ZOP` `CLD` `APV` `APC` `AI` `SEC` `OPS`.
- 코드 위치는 `저장소/경로:행` 형태로 적었다. 행 번호는 기준 커밋(BE `e55948c`, FE `9dfcbe8`, AI `6eef23c`)의 것이다.

## 검증 범위

- 전 문서가 **정적 코드 대조**다. 서비스 기동, API 호출, 테스트 실행, 부하 시험, 실제 Zabbix·AWS·LLM 연동은 하지 않았다. 문서의 "영향" 서술은 코드 구조에서 미루어 본 것이다.
- 문서 안의 상대 링크와 코드 경로·행 번호는 스크립트로 실존을 확인했다(13개 문서, 링크 469개, 코드 참조 1,265개, 깨진 것 0).
- 중요도 "높음" 28건은 작성자와 별도로 핵심 근거 코드를 다시 열어 서술과 일치하는지 확인했다. 런타임 재현은 하지 않았다.
- BE·AI 저장소에 미커밋 변경이 일부 있어, 기준 커밋만으로 작업 디렉터리 전체를 재현할 수는 없다.
