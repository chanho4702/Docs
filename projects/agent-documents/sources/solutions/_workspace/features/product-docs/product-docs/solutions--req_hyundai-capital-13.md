## 3. 항목별 근거와 착수 지점

### 1. 인증 연동 — 🔴
- 현행: 자체 로그인(JWT HttpOnly 쿠키, 2026-07-16 보안 재설계) + Zabbix 계정 연동
- 🔴 **우리 OTP는 2차 인증이 아니다** — `OtpType`이 `VERIFY_EMAIL`·`RESET_PASSWORD` 둘뿐
- 착수 지점: `auth/AuthService.login` + `auth/security/JwtAuthFilter`

### 2. SW 인벤토리 — 🟡
| 요소 | 현행 |
|---|---|
| 인벤토리 수집 | 🟢 `AssetSyncService`가 `selectInventory=extend` 전 필드 → `asset.zabbix_data.inventory` |
| 필드 검색 | 🟡 **6축 고정** — name·host·group·`serialno_a`·tag·`poc_1_name` (`AssetRepository` 쿼리에 하드코딩) |
| SW 축 | 🔴 `software`·`software_app_a~e` 사용처 0건 |
| 커스텀 레포트 | 🔴 설정>리포트 관리는 **생성된 리포트의 목록·삭제·보관기간**만. 정의 빌더 없음 |

> 🔴 착수 전 확인: dev 실측에서 `inventory_mode=-1`(미사용) 호스트 33건. **필드 존재 ≠ 값 존재**

### 3. 서버 시간 — 🟢 (해석 주의)
- `SYSTEM_HW_UPTIME` 우선 → 0/부재 시 `SYSTEM_UPTIME` 폴백(실환경에서 hw.uptime이 전 호스트 0이라 만든 폴백)
- ⚠️ 요구가 **NTP 시각 동기화 확인**이면 `system.localtime` 축이 필요하고 **지금 없다**

### 4·5. 저사용 / 고사용 — 🟡
- 있는 것: `/hosts/{groupid}/resource-trend`, 그룹 리포트의 호스트별 CPU/메모리/디스크/트래픽 `avg·max·min`, TOP 호스트
- 없는 것: **판정 규칙**("임계 이하 N일 지속")과 그 목록 화면
- 클라우드(EC2) 낭비 진단 카드가 있으나 **AWS 전용**, Zabbix 호스트엔 미적용

### 6. 성능 추세 — 🟢
- 리소스 추이 화면 + 주·월 리포트 배치(`report_weekly`·`report_monthly`)가 스냅샷 적재
- ⚠️ "장기 용량 예측(회귀)"까지면 없음

### 7. 일일점검 — 🔴
- 리포트는 주·월만. 일일점검은 **체크리스트 + 이력 보관(+승인)** 성격이라 모니터링과 별개 도메인

### 8. Peak 이벤트 — 🟡
- 있는 것(2026-08-26 신설, FE `d2bd558`): 이벤트 현황 탭 — 일자별 발생 추이(심각도 스택)·반복 상위·해결 소요·미해결 경과
- 없는 것: 피크 시각 자동 식별, 피크 구간 ↔ 리소스 지표 상관 분석

### 9. 윈도우 패치 — 🔴
- 패치·KB·핫픽스·WSUS 코드 0건. Zabbix 기본 템플릿도 패치 목록을 주지 않는다
- **수집 방식부터 설계**(에이전트 스크립트 / 별도 수집원)

### 10. CPU/MEM 전체 추출 — 🟡
- 값·화면은 있으나 전체 일괄 추출 경로 없음. 현재 내보내기는 비용 업로드 템플릿(엑셀) 정도
- 리포트 상세가 이미 호스트별 요약을 가지므로 **CSV 내보내기만 붙이면 작은 작업**

### 11. 장기 미접속 — 🟡
- 있는 것: 에이전트 불통 판정(구성 현황·모니터링 커버리지), 마지막 수집 시각(`lastClock`)
- 없는 것: "N일 이상 데이터 없음" 판정과 목록
- ⚠️ 대상이 **서버**인지 **사용자 계정**인지에 따라 완전히 다른 작업

### 12. ITSM — 🔴
- 티켓 생성·상태 동기화 코드 0건
- 방향(단방향 생성 / 양방향 동기화)에 따라 난이도 차이 큼

### 13. ATOM — 🟡 (통로는 있음)
- 있는 것: Zabbix 미디어 타입 전체 관리(이메일·**스크립트**·SMS·**웹훅**) + 액션 조건/오퍼레이션 편집
- 🔴 **우리 제품 자체 푸시는 이메일뿐** — Slack/Teams 등은 전부 Zabbix 미디어 경유다. ATOM도 같은 경로가 자연스럽다
- 규격만 나오면 **13건 중 가장 빠르게 붙일 수 있는 축**

## 5. 🔴 착수 전 고객에게 확인할 것

판정이 뒤집힐 수 있는 것들이다. **이 답이 오기 전에 4~13번을 설계하지 말 것.**

1. **3번** — 업타임인가, **NTP 시각 동기화 확인**인가
2. **11번** — 대상이 서버인가 사용자 계정인가. "미접속" 판정 기준(며칠)
3. **4·5번** — 저/고사용 판정 임계와 지속 기간(예: CPU 10% 미만 7일)
4. **12번** — ITSM 제품명, 연동 방향(단방향 티켓 생성 / 양방향 상태 동기화)
5. **13번** — ATOM 정식 명칭과 인터페이스 규격(웹훅 URL·인증·페이로드)
6. **2번** — "SW 인벤토리"가 설치 소프트웨어 목록인가, 자산 대장의 SW 항목인가
7. **7번** — 일일점검 항목 정의, 결과 보관·승인 요건
8. **1번** — LDAP 서버 정보, MPASS 규격, "자빅스 로그인 화면 수정"이 **우리 화면**인지 **Zabbix 원본 UI**인지
9. **9번** — 대상 OS 범위(윈도우만인지), 패치 정보 출처(WSUS·SCCM·에이전트 스크립트)
