# APM 알람 — 정리 대상 Zabbix 아이템 정리 가이드

> 대상: MovesEye APM 알람을 쓰는 설치본의 운영자.
> 적용: APM 알람 규칙·SLO·서비스를 지운 뒤 Zabbix에 남는 알람용 아이템을 정리할 때.

## 왜 남는가

MovesEye는 APM 알람마다 Zabbix의 가상 호스트 **MovesEye APM**에 아이템(값을 받는 칸)과 트리거(알람 조건)를 만듭니다.
규칙이나 서비스를 지우면 MovesEye가 트리거는 자동으로 지우지만, **아이템은 지우지 않고 비활성화만** 합니다.
아이템의 태그는 바꾸지 않습니다.

Zabbix에서 아이템을 지우면 그 아이템의 **값 이력이 지워지고**, **그 아이템을 쓰는 트리거 객체도 함께 지워집니다.**
누군가 MovesEye 아이템을 이용해 직접 만든 트리거가 있다면 자동 삭제가 그 트리거까지 지워 버릴 수 있습니다. 그래서 MovesEye는
아이템을 비활성화만 하고, 실제 삭제는 아래 순서로 운영자가 확인한 뒤에 합니다.

## 정리 대상의 조건

아래 네 가지를 **모두** 만족하는 아이템이 정리 대상입니다.

| 조건 | 확인 방법 |
|---|---|
| 호스트가 `MovesEye APM` | 아이템 목록 필터 |
| 태그 `owner` = `moveseye-apm` | 아이템 목록 필터 |
| 상태가 비활성(Disabled) | 아이템 목록 필터 |
| MovesEye의 알람 규칙이 더 이상 쓰지 않음 | 아래 1-3 |

MovesEye는 쓰고 있는 아이템을 비활성화하지 않습니다. 다만 사람이 Zabbix에서 직접 비활성화한 아이템도 같은 모양이 되므로,
마지막 조건을 반드시 확인합니다.

비활성 아이템은 값을 받지 않으므로 그 아이템을 쓰는 트리거가 없다면 남겨 두어도 알람 동작에는 영향이 없고 목록만 길어집니다.
**그 아이템을 쓰는 트리거가 있다면** 그 트리거는 값을 받지 못하게 됩니다 — 1-2에서 확인합니다.

## 1. 정리 대상 찾기

### 1-1. 후보 목록

**Zabbix 화면**

1. **데이터 수집 → 아이템**(Data collection → Items)으로 갑니다.
2. 필터에서 **호스트**를 `MovesEye APM`으로 고릅니다.
3. **상태**를 `비활성`(Disabled)으로 고릅니다.
4. **태그**에 `owner` / `같음`(Equals) / `moveseye-apm`을 넣고 적용합니다.

**API**

```json
{
  "jsonrpc": "2.0", "method": "item.get", "id": 1,
  "params": {
    "output": ["itemid", "key_", "name", "status"],
    "host": "MovesEye APM",
    "filter": {"status": 1},
    "tags": [{"tag": "owner", "value": "moveseye-apm", "operator": 1}],
    "selectTags": "extend",
    "selectTriggers": ["triggerid", "description"]
  }
}
```

### 1-2. 그 아이템을 쓰는 트리거 확인

- 화면: 아이템 목록의 **트리거** 열(Triggers) 숫자가 0인지 봅니다. 숫자가 있으면 눌러서 어떤 트리거인지 확인합니다.
- API: 위 `item.get` 결과의 `selectTriggers`가 비어 있는지 봅니다.
- 트리거가 있으면 그 아이템은 **정리 대상이 아닙니다.** 누가 왜 만든 트리거인지 먼저 확인합니다.

### 1-3. MovesEye가 쓰지 않는지 확인

아이템 키는 `apm.<종류>[<서비스 또는 SLO 식별자>]` 모양입니다. MovesEye의 **APM 알람 규칙** 화면에서 그 서비스(또는 SLO)에
같은 종류의 규칙이 켜져 있으면 그 아이템은 다시 쓰일 수 있으므로 지우지 않습니다. 같은 규칙을 곧 다시 만들 계획일 때도 지우지 않습니다.

## 2. 지우기 직전 재확인 (반드시)

1-2 확인과 삭제 사이에 누군가 그 아이템으로 트리거를 만들면, 삭제가 그 트리거까지 지웁니다. 그래서:

- 정리하는 동안에는 `MovesEye APM` 호스트의 트리거를 만들거나 바꾸지 않도록 관련자에게 알립니다(정리 작업 시간을 정해 두는 것을 권장합니다).
- **삭제 바로 직전에** 지울 아이템만 다시 조회해 트리거가 0건인지 확인합니다.

```json
{
  "jsonrpc": "2.0", "method": "item.get", "id": 1,
  "params": {"output": ["itemid", "status"], "itemids": ["<아이템 id>"],
             "selectTriggers": ["triggerid"]}
}
```

- 결과의 `triggers`가 비어 있고 `status`가 여전히 `1`(비활성)일 때만 다음 단계로 갑니다. **하나라도 다르면 삭제를 멈춥니다.**

## 3. 지우기

- 화면: 재확인을 마친 아이템만 고르고 **삭제**를 누릅니다.
- API: `item.delete`에 재확인을 마친 아이템 id만 넣습니다.

```json
{"jsonrpc": "2.0", "method": "item.delete", "id": 1, "params": ["<아이템 id>"]}
```

## 주의

- 아이템 삭제는 되돌릴 수 없습니다. 지워지는 것은 두 가지입니다.
  - 그 아이템의 **값 이력**(지금까지 받은 측정값)
  - 그 아이템을 쓰는 **트리거 객체**(연쇄 삭제) — 2단계 재확인이 0건이면 해당 없음
- 아이템을 지운 뒤 MovesEye에서 같은 알람 규칙을 다시 만들면 새 아이템이 만들어지고, 이전 값 이력은 이어지지 않습니다.
  지우지 않고 두었다면 MovesEye가 그 아이템을 다시 켜서 이어 씁니다.
- 활성 상태의 MovesEye 아이템은 쓰이고 있는 아이템입니다. 지우지 않습니다.
- 호스트 `MovesEye APM`과 호스트 그룹 `MovesEye APM` 자체는 지우지 않습니다. 모든 APM 알람이 함께 쓰는 그릇입니다.

## 권장 주기

- 한 달에 한 번, 또는 서비스·규칙을 많이 정리한 직후에 1단계 목록을 확인합니다.
- 실수로 지운 규칙을 되살릴 여유를 두려면, 규칙·서비스를 지운 뒤 한 달 정도 지나서 정리하는 것을 권장합니다.
