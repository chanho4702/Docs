# 지리 맵

> **사이드바** 자산 관리 > 맵 > 지리 맵
> **경로** `/asset/geo-map` → 상세 `/:id` → 편집 `/:id/edit`

## 무엇을 하는 화면인가

지도 위에 사업장·데이터센터 단위로 장비를 배치해 **물리적 분포와 상태**를 보는 화면이다. 여러 지역에 인프라가 흩어져 있을 때 "어느 지역에 문제가 있는지"를 한눈에 파악한다.

## 화면 구성

### 클러스터 목록 (지도)

지도 위에 클러스터가 표시된다. 클러스터는 호스트를 묶는 위치 단위다(예: 본사, 대전 IDC).

### 클러스터 상세

| 영역 | 내용 |
|---|---|
| 가용성 | 클러스터 내 호스트 정상 비율 |
| 문제 | 활성 장애 수 |
| 위도 · 경도 | 좌표 |
| 호스트그룹 · 호스트 | 포함 대상 |

### 편집

클러스터를 만들고 호스트를 배치하며, **호스트 좌표를 직접 편집**할 수 있다.

## 좌표의 원천

🔴 **좌표는 데이터소스 인벤토리에 저장된다.** 제품이 별도 좌표를 복제해 갖고 있지 않다.

즉 지리 맵에서 좌표를 편집하면 **원천 시스템(Zabbix 인벤토리)에 기록된다.** 제품 안에서만 바뀌는 것이 아니므로, 다른 시스템이 같은 인벤토리 필드를 쓰고 있다면 영향을 검토한다.

## 권한 (ZM-157, 소스 반영·배포 전)

🔴 **호스트 좌표 편집은 관리자만 할 수 있다.** 좌표가 원천 시스템에 기록되기 때문이다.

- 일반 사용자도 지도와 클러스터를 볼 수 있다.
- 일반 사용자에게는 편집 화면의 핀 드래그, 지도 클릭으로 위치 지정, 위도·경도 입력이 비활성화된다.
- 좌표가 없는 호스트를 배치하려고 하면 "호스트 좌표는 관리자만 바꿀 수 있습니다(Zabbix 인벤토리에 저장됩니다)." 안내가 뜬다. 관리자에게 좌표 입력을 요청한다.

## 사용 흐름

1. 클러스터를 만든다.
2. 호스트를 클러스터에 배치한다.
3. 좌표가 없는 호스트는 편집으로 좌표를 넣는다.
4. 대표 지도라면 메인으로 지정한다.

## 주의할 점

### 호스트 후보가 0건일 때

**자산 동기화를 한 번도 실행하지 않은 것이다.** 동기화 전에는 자산과 호스트의 연결(`linked_hostid`)이 비어 있어 후보가 잡히지 않는다.

[자산 목록](solutions--%EC%9E%90%EC%82%B0-%EB%AA%A9%EB%A1%9D.md)에서 동기화를 실행한 뒤 다시 시도한다. **기능 고장으로 오인하기 가장 쉬운 지점이다.**

### 좌표 없는 호스트

클러스터에 속해 있어도 좌표가 없으면 지도에 표시되지 않는다. 화면 하단에 안내가 나온다.

> "N개 호스트는 인벤토리 좌표가 없어 지도에 표시되지 않습니다."

**클러스터에 배치했는데 좌표를 잃으면 지도에서 접근할 수 없게 된다.** 목록을 통해 찾아 좌표를 다시 넣어야 한다.

### 지도 표시

지도 타일은 외부 지도 서비스에서 가져온다. **폐쇄망에서는 지도 배경이 표시되지 않을 수 있다.**
