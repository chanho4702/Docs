# MCP 연결 가이드

> **이 문서로 답할 수 있는 질문** — Claude·Cursor·VS Code 같은 외부 AI 앱을 내 MovesEye 계정에 어떻게 연결하는가? 연결하면 무엇을 할 수 있고, 안 될 때는 무엇을 보는가? 관리자는 무엇을 켜고 설정하는가?
>
> - 1부 **사용자편**: 연결 절차, 권한, 연결 끊기, 문제 해결
> - 2부 **관리자편**(§10~§16): 기능 켜기, 프록시, 권한 부여, 삭제 작업 설정, 점검
>
> ⚠️ 이 문서는 2026-09-17 소스 기준이다. 삭제 작업 차단, 요청마다 권한 재확인 같은 일부 동작(ZM-157)은 아직 배포 전이다. 외부 앱의 메뉴 이름과 설정 방식은 **앱 버전에 따라 다를 수 있다.** 화면 문구는 개선 중이라 이 문서는 기능 기준으로 설명한다.

# 1부. 사용자편

## 1. MCP 연결이란

MCP(Model Context Protocol)는 외부 AI 앱이 다른 서비스의 기능을 "도구"로 불러 쓰는 표준이다. MovesEye에 연결하면 Claude Desktop·Claude Code·Cursor 같은 앱에서 이렇게 요청할 수 있다.

- "지금 열려 있는 심각도 높은 문제 보여 줘"
- "web-01 호스트의 CPU·메모리 추이 알려 줘"
- "자산 중 비용 정보가 빠진 것 목록 만들어 줘"
- (변경 권한이 있으면) "이 문제를 확인 처리하고 메모 남겨 줘"

**외부 AI 앱은 내 계정의 권한으로만 동작한다.** 내가 MovesEye 화면에서 못 하는 일은 외부 앱에서도 할 수 없다. 앱은 내 비밀번호를 받지 않는다. 연결할 때 MovesEye 로그인·동의 화면을 거치고, 이후에는 앱이 자동으로 갱신되는 접속 권한(토큰)을 쓴다.

화면 안에서 쓰는 **AI 어시스턴트**와는 다른 기능이다. AI 어시스턴트는 MovesEye 화면 안의 채팅이고, MCP 연결은 내가 쓰는 외부 AI 앱에서 MovesEye를 부르는 기능이다.

## 2. 준비물

| 확인할 것 | 어디서 | 없으면 |
|---|---|---|
| 설치본에서 MCP 연동이 켜져 있는가 | ⚙ 설정 › **연결된 앱** 화면에 커넥터 주소가 보이는가 | 관리자에게 MCP 연동을 켜 달라고 요청(2부 §10) |
| 내 계정의 MCP 권한 | 관리자가 사용자 관리에서 정한다 | 관리자에게 요청 |
| 커넥터 주소 | ⚙ 설정 › 연결된 앱 화면에서 복사 | — |
| 외부 AI 앱 | Claude Desktop·claude.ai·Claude Code·Cursor·VS Code 등 | — |
| 인터넷에서 접속 가능한 https 주소 | claude.ai·Claude Desktop 커넥터를 쓸 때만 필요 | §3.1 참고 |

MCP 권한은 세 단계다.

| 권한 | 화면 표시 | 외부 앱이 할 수 있는 일 |
|---|---|---|
| `NONE` | 사용 안 함 | 연결할 수 없다 |
| `READ` | 조회만 | 호스트·문제·자산 등을 읽기만 한다 |
| `READ_WRITE` | 조회+변경 | 읽기에 더해 호스트 등록, 문제 확인 처리 같은 변경을 한다 |

커넥터 주소는 보통 `https://<MovesEye 도메인>/mcp` 형태다. 설치본마다 다르니 반드시 연결된 앱 화면의 주소를 쓴다.

## 3. 앱별 연결 절차

아래 `https://<도메인>/mcp`는 연결된 앱 화면에서 복사한 주소로 바꾼다. 어느 앱이든 처음 연결할 때 브라우저가 열리고 MovesEye 로그인·동의 화면이 나온다(§4).

### 3.1 Claude Desktop / claude.ai

1. 설정에서 **커넥터** 메뉴를 연다.
2. **사용자 지정 커넥터 추가**를 누른다.
3. 이름(예: `MovesEye`)과 커넥터 주소를 넣는다.
4. 연결을 누르면 브라우저에서 MovesEye 동의 화면이 열린다.

⚠️ 이 방식은 **Anthropic 클라우드가 MovesEye 서버에 직접 접속**한다. 그래서 커넥터 주소가 **인터넷에서 접근 가능한 https 주소**여야 한다. 사내망에서만 열리는 주소를 넣으면 연결이 시작되지 않는다. 사내망 전용 설치본이면 내 PC에서 직접 접속하는 앱(Claude Code·Cursor·VS Code)을 쓴다.

### 3.2 Claude Code

터미널에서 서버를 등록한다.

```bash
claude mcp add --transport http moveseye https://<도메인>/mcp
```

Claude Code 안에서 `/mcp`를 입력하고 `moveseye`를 골라 인증을 진행한다. 브라우저에서 동의하면 연결이 끝난다.

### 3.3 Cursor

`~/.cursor/mcp.json`(모든 프로젝트) 또는 프로젝트의 `.cursor/mcp.json`에 추가한다.

```json
{
  "mcpServers": {
    "moveseye": {
      "url": "https://<도메인>/mcp"
    }
  }
}
```

Cursor 설정의 MCP 항목에서 `moveseye`를 켜고 로그인(인증)을 진행한다.

### 3.4 VS Code

작업 폴더의 `.vscode/mcp.json`에 추가한다.

```json
{
  "servers": {
    "moveseye": {
      "type": "http",
      "url": "https://<도메인>/mcp"
    }
  }
}
```

VS Code가 서버 시작과 인증을 안내하면 따라간다.

### 3.5 그 밖의 앱

"원격 MCP 서버", "Streamable HTTP", "OAuth 인증"을 지원하는 앱이면 같은 주소로 연결할 수 있다. 접속 키(API key)를 직접 넣는 방식만 지원하는 앱은 쓸 수 없다. MovesEye는 로그인·동의(OAuth) 방식만 제공한다.

## 4. 로그인·동의 화면

1. 앱이 연결을 시작하면 브라우저에 MovesEye가 열린다. 로그인하지 않았으면 로그인 화면이 먼저 나오고, 로그인 후 동의 화면으로 돌아온다.
2. 동의 화면에서 다음을 확인한다.
   - **클라이언트** — 연결을 요청한 앱 이름
   - **돌아갈 주소** — 동의 후 돌아갈 앱 주소의 호스트. 내가 쓰는 앱이 맞는지 본다
   - **요청 권한** — 조회만 또는 조회+변경
   - **내 계정**, **내 MCP 권한**
3. 내용이 맞으면 **허용**, 모르는 요청이면 **거부**를 누른다.

권한에 따라 화면이 달라진다.

| 상황 | 동의 화면 |
|---|---|
| 요청 권한이 내 MCP 권한 안에 있음 | 허용·거부 |
| 앱은 조회+변경을 요청했는데 내 권한은 조회만 | 요청 권한을 다 줄 수 없다는 안내와 함께 **읽기(조회)만 허용** 또는 거부 |
| 내 MCP 권한이 사용 안 함 | MCP 사용 권한이 없다는 안내. 관리자에게 요청 |
| 설치본에서 MCP 연동이 꺼짐 | MCP 연동이 꺼져 있다는 안내 |
| 동의 요청을 받은 지 10분이 지남 | 동의 요청 만료 안내. 앱에서 연결을 다시 시작 |

## 5. 연결 확인과 연결 끊기

⚙ 설정 › **연결된 앱**에서 내 계정에 연결된 앱을 본다. 앱 이름, 권한(조회만·조회+변경), 연결일, 마지막 사용, 만료가 표시된다.

- **연결 끊기**를 누르면 그 앱은 새 접속 권한을 받을 수 없다. 앱이 이미 받아 둔 접속 권한은 **최대 1시간**(설치본 기본값) 더 동작할 수 있다.
- 즉시 모든 외부 앱을 막아야 하면 관리자에게 내 MCP 권한을 "사용 안 함"으로 바꿔 달라고 요청한다. 이 변경은 다음 요청부터 바로 적용된다.
- 연결은 연결일로부터 **30일**(설치본 기본값)이 지나면 만료되어 목록에서 사라진다. 그때 앱에서 다시 연결한다.

| 항목 | 기본값 | 의미 |
|---|---|---|
| 접속 권한(access token) | 1시간 | 앱이 알아서 갱신한다 |
| 연결(refresh) | 연결일부터 30일 | 지나면 다시 연결 |
| 동의 대기 | 10분 | 지나면 연결을 다시 시작 |

🔴 **비밀번호를 바꿔도 연결된 앱은 끊기지 않는다.** 비밀번호 유출이나 PC 분실이 의심되면 비밀번호 변경과 함께 연결된 앱에서 모든 연결을 끊는다.

## 6. 쓸 수 있는 도구

외부 앱에는 MovesEye 도구 목록이 전달되고, 앱의 AI가 요청에 맞는 도구를 고른다. 대표 예시는 다음과 같다.

| 구분 | 필요한 MCP 권한 | 예시 |
|---|---|---|
| 조회 | 조회만 이상 | 호스트 목록·상세, 호스트 지표, 호스트 그룹 현황, 문제 목록·상세, 아이템·트리거·템플릿 조회, 자산·비용 조회, 모니터링 커버리지, 시스템 상태, 표 내보내기(Excel) |
| 변경 | 조회+변경 | 문제 확인 처리, 호스트 등록·수정·활성/비활성, 아이템·트리거 생성·수정·상태 변경, 템플릿 연결, 기기 분류 지정, 자산·비용 정보 수정, 자산 동기화 |
| 삭제 | **기본 차단** | 호스트·아이템·트리거 삭제, 자산 제외, 데이터까지 지우는 템플릿 연결 해제 |

- 외부 앱에는 MovesEye 화면의 **확인 카드가 없다.** 그래서 되돌릴 수 없는 삭제 작업은 기본으로 막혀 있다. 삭제는 MovesEye 화면이나 화면 안의 AI 어시스턴트(확인 카드 승인)에서 한다.
- 변경 작업을 실행하기 전에 외부 앱이 확인을 묻도록 설정해 두기를 권한다. 확인 방식은 앱마다 다르다.
- 설정·사용자 관리·라이선스 같은 관리 기능은 외부 앱에서 부를 수 없다.
- Zabbix 관리 도구(아이템·트리거·템플릿 등)는 MovesEye 화면에서도 관리자만 쓸 수 있는 기능이라, 외부 앱에서도 관리자 계정에서만 동작한다.
- 연결되지 않은 데이터소스의 도구는 목록에 보이더라도 실행하면 "데이터소스가 연결돼 있지 않다"는 오류가 난다.
- 도구 결과의 링크는 외부 앱 안에서 바로 열리지 않을 수 있다. MovesEye에 로그인한 브라우저에서 연다.

## 7. 권한 규칙 — 두 겹

외부 앱의 요청은 두 가지를 모두 통과해야 실행된다.

1. **MCP 권한** — 사용 안 함·조회만·조회+변경. 조회만이면 변경 요청은 거부된다.
2. **역할 권한** — 관리자가 역할 편집에서 켠 기능. 화면에서 못 하는 일은 외부 앱에서도 못 한다([관리자 가이드 §3-6](solutions--%EA%B4%80%EB%A6%AC%EC%9E%90-%EA%B0%80%EC%9D%B4%EB%93%9C.md)).

거부되면 외부 앱의 답변에 다음 취지의 안내가 나온다.

| 안내 취지 | 뜻 | 할 일 |
|---|---|---|
| 내 역할에서 이 기능이 허용되지 않았다 | 역할 권한 부족 | 관리자에게 역할 편집에서 해당 권한을 켜 달라고 요청 |
| MCP 연결 권한으로는 이 작업을 할 수 없다 | 조회만 권한이거나 MCP로 열지 않은 기능 | 변경이 필요하면 관리자에게 MCP 권한을 "조회+변경"으로 요청한 뒤 **다시 연결** |
| 쓰기 작업인데 현재 연결은 읽기 권한만 있다 | 연결할 때 조회만 허용됨 | 권한을 받은 뒤 연결을 끊고 다시 연결 |
| 되돌릴 수 없는 작업이라 MCP 연결로는 실행할 수 없다 | 삭제 작업 기본 차단 | MovesEye 화면에서 진행 |
| 한 번에 N건까지만 실행할 수 있다 | 관리자가 삭제를 허용했지만 건수 상한이 있음 | 대상을 나눠 한 건씩 요청 |
| 인증이 더 이상 받아들여지지 않는다 / 인증이 필요하다 | 계정 비활성화, 사용자 유형 변경, 연결 만료 등 | 앱에서 다시 연결(재인증) |

MCP 권한을 "조회만"에서 "조회+변경"으로 올려도 **이미 연결된 앱은 조회만 권한으로 남는다.** 연결을 끊고 다시 연결해야 변경 권한을 받는다.

## 8. 보안 안내

- 🔴 **MovesEye 데이터가 외부 AI 서비스로 전달된다.** 도구 결과(호스트 이름, IP, 알람 내용, 자산 정보 등)가 내가 쓰는 AI 앱과 그 앱의 AI 서비스 제공자에게 보내진다. 회사의 외부 AI 사용 정책을 먼저 확인한다.
- 동의 화면의 앱 이름과 돌아갈 주소가 내가 연결하려는 앱과 맞는지 확인한다. 내가 시작하지 않은 동의 요청은 거부한다.
- 필요한 만큼만 권한을 받는다. 조회만으로 충분하면 "읽기(조회)만 허용"을 고른다.
- 쓰지 않는 연결은 끊는다.
- 외부 앱이 문서·알람 내용에 들어 있는 지시를 따라 엉뚱한 작업을 시도할 수 있다. 변경 작업은 실행 전에 앱의 확인 단계에서 대상과 내용을 읽는다.

## 9. 문제 해결

| 증상 | 원인 | 조치 |
|---|---|---|
| 연결된 앱 화면에 커넥터 주소가 없다 | 설치본에서 MCP 연동이 꺼져 있음 | 관리자에게 요청(2부 §10) |
| 동의 화면에 "MCP 사용 권한이 없습니다" | 내 MCP 권한이 사용 안 함 | 관리자에게 조회만 또는 조회+변경 권한 요청 |
| 동의 화면에 "MCP 연동이 꺼져 있습니다" | 설치본에서 기능 꺼짐 | 관리자에게 문의 |
| "동의 요청이 만료되었습니다" | 동의 화면을 10분 넘게 두었음 | 앱에서 연결을 처음부터 다시 시작 |
| "잘못된 접근입니다" | 동의 화면 주소를 직접 열었거나 일부가 잘림 | 앱에서 연결을 다시 시작 |
| 동의 화면에 "읽기(조회)만 허용"만 있다 | 앱은 변경을 요청했지만 내 권한은 조회만 | 읽기만 허용하거나, 관리자에게 권한을 받은 뒤 다시 연결 |
| claude.ai·Claude Desktop에서 연결이 시작되지 않는다 | 사내망 주소나 http 주소를 넣음 | 인터넷에서 접근 가능한 https 주소 사용. 불가하면 Claude Code·Cursor·VS Code 사용 |

| 삭제를 요청했는데 거부된다 | 삭제 작업 기본 차단 | MovesEye 화면이나 AI 어시스턴트에서 진행 |
| 변경 권한을 받았는데도 변경이 거부된다 | 기존 연결이 조회만 권한으로 만들어짐 | 연결을 끊고 다시 연결 |
| 앱이 다시 인증하라고 한다 | 연결 만료(30일), 계정 비활성화, 사용자 유형 변경, MCP 권한 회수 | 앱에서 다시 연결. 권한 회수라면 관리자에게 문의 |
| 연결이 연결된 앱 목록에 없다 | 동의를 끝내지 않음, 만료됨, 관리자가 권한을 회수해 끊김, 다른 계정으로 동의함 | 로그인한 계정을 확인하고 다시 연결 |
| 연결을 끊었는데 앱이 잠시 계속 동작한다 | 이미 받은 접속 권한이 최대 1시간 유효 | 즉시 막아야 하면 관리자에게 MCP 권한 회수 요청 |
| 도구 실행 시 "데이터소스가 연결돼 있지 않다" | 그 도구가 쓰는 데이터소스가 설치본에 없음 | 관리자에게 데이터소스 연결 확인 요청 |
| 도구 결과의 링크가 열리지 않는다 | 외부 앱에는 MovesEye 로그인 정보가 없음 | MovesEye에 로그인한 브라우저에서 연다 |

# 2부. 관리자편

## 10. MCP 연동 켜기

MCP 연동은 **AI 서버(moveseye-ai)** 가 제공하며 **기본으로 꺼져 있다.** 켜면 모니터링 데이터가 사용자의 외부 AI 서비스로 나가기 때문에, 고객사가 정책을 확인한 뒤 명시적으로 켜도록 했다. 외부 AI 서비스에 닿지 않는 폐쇄망에서는 쓸 수 없다.

AI 서버 환경변수(값은 예시가 아니라 기본값이다. 비밀값은 문서에 적지 않는다):

| 환경변수 | 기본값 | 설명 |
|---|---|---|
| `AI_MCP_ENABLED` | `false` | `true`면 `/mcp`와 OAuth 엔드포인트가 켜지고, 연결된 앱 화면·사용자 관리의 MCP 권한 열이 나타난다 |
| `AI_MCP_DYNAMIC_REGISTRATION` | `true` | 외부 앱이 스스로 클라이언트 등록을 하도록 허용. `false`면 이미 등록된 클라이언트만 연결된다 |
| `AI_MCP_ACCESS_TTL` | `3600`(초) | 외부 앱 접속 토큰 수명. BE가 60~86400초 범위로 받는다 |
| `AI_MCP_REFRESH_TTL_DAYS` | `30` | 연결 수명(일). 연결일부터 계산되며 사용해도 연장되지 않는다 |
| `AI_MCP_ALLOW_DESTRUCTIVE` | `false` | 삭제 등급 도구의 MCP 노출·실행 허용(§13) |
| `AI_MCP_MAX_DESTRUCTIVE_TARGETS` | `1` | 삭제 허용 시 호출 한 번의 대상 수 상한 |
| `AI_PUBLIC_URL` | 비움 | AI 서버의 공개 URL. 비우면 프록시의 `X-Forwarded-Proto`·`X-Forwarded-Host`로 자동 계산. 프록시가 이 헤더를 넘기지 않는 환경만 지정 |
| `FE_PUBLIC_URL` | 비움 | FE가 다른 오리진일 때 동의 화면 주소 |
| `INTERNAL_API_TOKEN` | 비움 | BE와 **같은 값**. AI 서버가 BE 내부 API(토큰 발급 등)를 부를 때 쓴다 |

AI 서버는 BE와 같은 PostgreSQL(`DB_*`)과 Redis(`REDIS_HOST`·`REDIS_PORT`)를 쓴다. 연결 정보는 `ai_oauth_client`·`ai_oauth_grant` 테이블에, 동의 대기와 인가 코드(10분)는 Redis에 저장된다. 동의 대기 시간(10분)은 설정 파일의 `ai.mcp.code-ttl-seconds`(600)이며 환경변수로 노출되지 않는다.

`AI_MCP_DYNAMIC_REGISTRATION=false`로 두면 새 앱을 연결할 수 없다. 클라이언트를 미리 등록하는 관리 화면은 현재 없다.

## 11. https와 리버스 프록시

- **https가 필수다.** Claude Desktop·claude.ai 커넥터는 https 주소만 받는다. claude.ai·Claude Desktop 커넥터를 지원하려면 인터넷에서 접근 가능해야 한다.
- 고객에게는 도메인 하나만 보이게 구성한다. 아래 경로를 AI 서버(기본 포트 3100)로 보낸다.

| 경로 | 보낼 곳 | 용도 |
|---|---|---|
| `/mcp` | AI 서버 `/mcp` | MCP 요청(Streamable HTTP) — 버퍼링 끄기 |
| `/oauth/` | AI 서버 `/oauth/` | 클라이언트 등록·인가·토큰 |
| `/.well-known/` | AI 서버 `/.well-known/` | OAuth 메타데이터 |
| `/ai/` | AI 서버 `/ai/` | 동의 처리·연결 목록·AI 어시스턴트 — 버퍼링 끄기, 긴 타임아웃 |
| `/api/` | BE | 기존 |
| `/` | FE 정적 파일 | 동의 화면(`/oauth/consent`)은 FE 라우트다 |

nginx 예시(moveseye-ai `README.md`의 "설치형 배포" 절과 같다):

```nginx
location /ai/  { proxy_pass http://ai:3100/ai/;  proxy_set_header Host $host; proxy_set_header X-Forwarded-Proto $scheme; proxy_set_header X-Forwarded-Host $host; proxy_buffering off; proxy_read_timeout 600s; }
location /mcp  { proxy_pass http://ai:3100/mcp;  proxy_set_header Host $host; proxy_set_header X-Forwarded-Proto $scheme; proxy_set_header X-Forwarded-Host $host; proxy_buffering off; }
location /oauth/       { proxy_pass http://ai:3100/oauth/;       proxy_set_header Host $host; proxy_set_header X-Forwarded-Proto $scheme; proxy_set_header X-Forwarded-Host $host; }
location /.well-known/ { proxy_pass http://ai:3100/.well-known/; proxy_set_header Host $host; proxy_set_header X-Forwarded-Proto $scheme; proxy_set_header X-Forwarded-Host $host; }
```

🔴 **동의 화면 경로를 FE로 따로 보낸다.** AI 서버는 사용자를 FE의 `/oauth/consent`로 보내는데, 위 예시만 쓰면 이 주소도 `/oauth/` 규칙에 걸려 AI 서버로 가서 동의 화면이 열리지 않는다(소스 대조로 찾은 문제, 실환경 미확인). 더 긴 경로 규칙을 추가해 FE로 보낸다. nginx는 가장 긴 접두어 규칙을 고르므로 아래 규칙이 `/oauth/`보다 우선한다.

```nginx
location /oauth/consent { try_files $uri /index.html; }   # FE SPA 라우트(root는 FE 정적 파일 위치)
```

- 🔴 `X-Forwarded-Proto`·`X-Forwarded-Host`를 빠뜨리면 OAuth 메타데이터에 내부 주소(http, 내부 포트)가 박혀 외부 앱이 연결하지 못한다.
- FE 빌드의 AI 주소(`VITE_AI_URL`)는 같은 도메인으로 둔다. 연결된 앱 화면의 커넥터 주소는 이 값 뒤에 `/mcp`를 붙여 표시한다.

## 12. 사용자별 MCP 권한 부여

⚙ 설정 › 사용자 관리의 사용자 목록에서 **MCP 권한** 열로 사용자마다 사용 안 함·조회만·조회+변경을 고른다. MCP 연동이 꺼져 있으면 이 열이 보이지 않는다.

- 기본은 사용 안 함이다. 필요한 사람에게만 준다.
- 조회+변경을 주어도 실제 변경 범위는 그 사용자의 역할 권한을 넘지 않는다.
- 권한을 올린 사용자는 **기존 연결을 끊고 다시 연결**해야 변경 권한을 받는다.

## 13. 삭제 작업 설정

외부 앱에는 MovesEye의 확인 카드가 없다. 자동 승인하도록 설정된 앱은 사람의 확인 없이 도구를 실행할 수 있다. 그래서 되돌릴 수 없는 작업은 기본으로 막았다.

| 설정 | 동작 |
|---|---|
| `AI_MCP_ALLOW_DESTRUCTIVE=false`(기본) | 삭제 등급 도구가 외부 앱 목록에 나타나지 않고, 호출해도 거부된다 |
| `AI_MCP_ALLOW_DESTRUCTIVE=true` | 목록에 나타난다. 실행하려면 조회+변경 연결이어야 하고, 호출 한 번의 대상 수가 `AI_MCP_MAX_DESTRUCTIVE_TARGETS` 이하여야 한다 |

- 삭제 등급: 호스트 삭제, 아이템 삭제, 트리거 삭제, 자산 제외.
- 템플릿 연결 해제는 평소에는 변경 등급이다. 템플릿이 만든 아이템·트리거·이력까지 지우는 옵션을 쓰면 삭제 등급으로 판정한다. 이 경우 도구는 목록에 남고 그 요청만 거부된다.
- **권장: 기본값(`false`)을 유지한다.** 켜야 한다면 변경 승인을 받고, 상한은 1로 둔다.

## 14. 권한 회수와 반영 시점

**(ZM-157, 배포 전)** BE는 외부 앱의 요청마다 DB에서 계정을 다시 확인한다.

| 관리자 조치 | 반영 |
|---|---|
| MCP 권한을 사용 안 함으로 | 다음 요청부터 모든 요청 거부. 앱이 토큰을 갱신할 때 연결도 끊겨 목록에서 사라진다 |
| 조회+변경 → 조회만 | 다음 요청부터 변경만 거부 |
| 사용자 비활성화·삭제 | 다음 요청부터 인증 실패. 앱이 재인증을 요구한다 |
| 사용자 유형 변경(관리자↔일반) | 다음 요청부터 인증 실패. 다시 연결해야 한다 |
| 역할 권한 변경 | 다음 요청부터 반영 |
| 사용자의 비밀번호 변경 | **연결에 영향 없음** |

AI 서버는 토큰 검증 결과를 5분 캐시한다. 도구 실행 중 BE가 인증 실패를 돌려주면 그 캐시를 즉시 버리고, 다음 요청에서 재인증을 요구한다.

사용자가 연결된 앱에서 연결을 끊으면 새 토큰 발급은 즉시 막히지만, 이미 발급된 접속 토큰은 `AI_MCP_ACCESS_TTL`(기본 1시간)까지 유효하다. 즉시 차단이 필요하면 MCP 권한을 사용 안 함으로 바꾼다.

## 15. 외부 앱이 부를 수 있는 범위

BE는 외부 앱 토큰으로 들어온 요청을 경로 허용 목록으로 좁힌다. 허용 범위는 호스트·모니터링 지표·이벤트, Zabbix 관리, 자산·비용, 내 프로필, 기기 분류 조회, 시스템 상태다. 설정·사용자 관리·라이선스·인증 API는 부를 수 없다. 조회만 연결은 조회 요청만 통과한다.

## 16. 점검 포인트

- [ ] MCP 연동을 켜기 전에 외부 AI 서비스로 데이터가 나가는 것에 대한 사내 승인을 받았다.
- [ ] 공개 주소가 https이고, `https://<도메인>/.well-known/oauth-authorization-server`가 AI 서버의 JSON을 돌려준다. 그 안의 주소가 공개 도메인이다.
- [ ] `https://<도메인>/mcp`에 인증 없이 요청하면 401과 `WWW-Authenticate` 헤더가 온다.
- [ ] 연결된 앱 화면에 커넥터 주소가 보이고, 사용자 관리에 MCP 권한 열이 보인다.
- [ ] 테스트 계정(조회만)으로 연결해 조회가 되고 변경이 거부되는지 확인했다.
- [ ] `AI_MCP_ALLOW_DESTRUCTIVE`가 의도한 값이다.
- [ ] MCP 권한을 준 사용자 목록을 주기적으로 검토한다. 현재 MCP 권한 변경 이력(감사 로그)은 제품에 없다.
- [ ] AI 서버 로그에서 연결 승인(`mcp consent approved`)·연결 생성(`mcp grant created`)과 노출된 도구 수(`MCP tools exposed`)를 확인할 수 있다. 로그에 토큰 값이 남지 않는지 확인한다.

운영 절차와 배포 주의는 [로컬·검증 Runbook §11](../operations/solutions--%EC%9A%B4%EC%98%81%EC%9E%90-%EB%9F%B0%EB%B6%81.md), 설치 절차는 [설치·배포 가이드 §5-4](../operations/solutions--%EC%84%A4%EC%B9%98-%EB%B0%B0%ED%8F%AC-%EA%B0%80%EC%9D%B4%EB%93%9C.md)를 본다.
