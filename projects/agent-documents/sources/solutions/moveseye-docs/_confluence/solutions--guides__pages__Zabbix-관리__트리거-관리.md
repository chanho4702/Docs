# 트리거 관리

> **사이드바** Zabbix 관리 > 트리거 관리
> **경로** `/zabbix-management/trigger-lens`

> ⚠️ **여기서 한 변경은 실제 Zabbix에 반영되며, 알람 발생에 직접 영향을 준다.**

## 무엇을 하는 화면인가

이상 판정 규칙(트리거)을 전체 범위에서 탐색하고 관리하는 화면이다. 구조는 **아이템 관리**와 같지만 **다루는 대상이 알람 규칙**이라 영향이 더 즉각적이다.

## 화면 구성

### 필터

| 필터 | 값 |
|---|---|
| 호스트 그룹 / 호스트 / 템플릿 | 범위 |
| **심각도** | Severity |
| 상태 | 활성 / 비활성 |
| 검색 | 트리거 이름 |

### 보기 전환

**정의** / **전체** — 아이템 관리와 동일하다.

### 동작

- 트리거 생성 (대상 선택 후)
- 수정 / 삭제
- 상태 전환 (활성 ↔ 비활성)

## 사용 흐름

1. 범위를 좁힌다.
2. 대상 트리거를 찾는다.
3. **정의처를 확인한다** — 템플릿 상속인지 호스트 직접인지.
4. 변경한다.

## 주의할 점

### 상속된 트리거는 읽기 전용

🔴 아이템보다 제약이 강하다.

> "템플릿에서 상속된 트리거입니다(읽기 전용). 원본 템플릿에서 수정하세요."

아이템은 상속돼도 상태 전환이 가능하지만, **트리거는 상속되면 읽기 전용**이다.

### 대상은 expression이 결정한다

🔴 트리거는 대상 호스트를 따로 지정하지 않는다. **expression 안의 `/호스트/키`가 곧 대상**이다.

expression을 고치면 트리거가 **다른 호스트를 보게 될 수 있다.** 이름만 보고 판단하지 말고 expression을 확인한다.

### 심각도 변경의 파급

심각도는 단순한 라벨이 아니다. 알람 흐름 전체(목록 정렬, 집계, 외부 알림 정책)에 영향을 준다. **운영 시간대를 피해서** 바꾼다.

### 비활성화 = 감시 중단

트리거를 끄면 그 조건의 장애를 **더 이상 감지하지 않는다.** 노이즈가 심하다는 이유로 끄기 전에, 임계값 조정으로 해결되는지 먼저 검토한다. 끈 트리거는 잊히기 쉽다.

### 탐색 상한

아이템 관리와 동일하게 상한이 있다. 초과 시 필터를 좁힌다.
