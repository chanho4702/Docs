⚠️ 여기서 한 변경은 실제 Zabbix에 반영되며, 연결된 모든 호스트에 파급된다.

무엇을 하는 화면인가

여러 호스트에 재사용하는 수집 구성(아이템·트리거 묶음)을 관리하는 화면이다.

템플릿은 파급력이 가장 큰 대상이다. 호스트 하나를 고치면 그 호스트만 바뀌지만, 템플릿을 고치면 연결된 호스트 전부가 바뀐다.

사용 흐름

  1. 템플릿 목록에서 대상을 찾는다.
  2. 상세에서 아이템·트리거 구성을 확인한다.
  3. 연결된 호스트 수를 먼저 파악한다 — 이것이 변경 영향 범위다.
  4. 수정 후 실제 호스트 몇 대에서 값이 정상 수집되는지 확인한다.

주의할 점

수정 전 영향 범위 확인

🔴 템플릿의 아이템·트리거를 고치면 연결된 호스트 전부에 즉시 적용된다. 트리거 임계값을 잘못 바꾸면 수백 대에서 동시에 알람이 터질 수 있다.

운영 시간대를 피하고, 가능하면 소수 호스트로 먼저 검증한다.

연결 해제(unlink)

템플릿 연결을 끊으면 그 템플릿에서 상속받던 아이템·트리거가 사라진다. 수집이 중단된다. 해제 전에 해당 호스트가 다른 경로로 같은 항목을 수집하는지 확인한다.

연결 작업의 방향

템플릿과 호스트의 연결·해제는 호스트 쪽 API로 처리된다. 화면에서는 자연스럽게 보이지만, 문제가 생겼을 때 로그를 볼 때 알아 두면 도움이 된다.

상속 관계

호스트에서 직접 만든 아이템과 템플릿에서 상속된 아이템은 다르다. 상속된 것은 원본 템플릿에서 고쳐야 하며, 호스트 쪽에서는 이름·키 수정과 삭제가 막혀 있다(상태 변경은 가능).
