MovesEye 제품 소개서

이 문서는 제품을 처음 접하는 분을 위한 소개 자료다. 내부 기술 기준선은 제품 개요, 실제 사용법은 사용자 가이드를 본다.

기능 표기: [제공] 은 구현 완료, [개발 중] 은 진행 중, [예정] 은 설계·구조가 준비됐고 어댑터 구현이 남은 것이다. 실제 제공 범위는 계약과 도입 환경에 따라 달라진다.

1. MovesEye는 무엇인가

여러 모니터링 시스템에 흩어진 인프라 상태를 하나의 운영 화면으로 통합하는 종합 모니터링 제품입니다.

인프라가 커지면 모니터링 도구는 자연히 여러 개가 됩니다. 온프레미스 서버는 Zabbix, 쿠버네티스와 컨테이너는 Prometheus, 클라우드와 APM은 Datadog, 로그는 Elasticsearch — 각각은 그 영역에서 최선의 선택이었습니다.

문제는 그 다음입니다.

  • 장애가 나면 어느 콘솔을 봐야 할지부터 정해야 하고
  • 같은 서버가 도구마다 다른 이름으로 존재하고
  • 담당자별로 볼 수 있는 범위를 통제할 방법이 도구마다 다르고
  • 그 장비가 무엇이고 얼마짜리인지는 어느 도구도 모릅니다.

MovesEye는 이 도구들을 대체하지 않습니다. 수집은 각자 잘하는 도구에 맡기고, 그 위에 통합된 운영 화면 하나를 세웁니다.

2. 무엇이 다른가 — Grafana와의 차이

여러 소스를 한 화면에 붙이는 도구는 이미 있습니다. 접근 방식이 다릅니다.

Grafana 방식MovesEye 방식
통합 수준통합하지 않음. 패널마다 소스별 쿼리를 따로 작성도메인 개념으로 정규화. 소스가 달라도 "호스트·장애·메트릭"은 같은 개념
화면사용자가 직접 조립운영 화면이 이미 완성돼 있음
소스 교체대시보드를 다시 만들어야 함화면은 그대로. 뒤의 소스만 교체
필요 역량각 소스의 쿼리 언어(PromQL 등)를 알아야 함쿼리를 몰라도 사용 가능
자산·비용없음포함

Grafana는 범용 시각화 도구이고, MovesEye는 완성된 운영 제품입니다. 자유도가 필요하면 Grafana가 맞고, "우리 팀이 매일 보는 화면"이 필요하면 MovesEye가 맞습니다.

핵심은 이겁니다. MovesEye는 소스별 쿼리를 그대로 통과시키지 않고, 화면이 요구하는 능력(capability) 단위로 정규화한 계약을 둡니다. 그래서 Zabbix에서 오든 Prometheus에서 오든 운영자가 보는 화면은 동일합니다.

현재 실제 동작하는 어댑터는 Zabbix 하나입니다. 나머지 셋은 이를 위한 내부 구조가 완성돼 있고 어댑터 구현이 남았습니다(§6 로드맵). 도입 검토 시 이 점을 반드시 감안해 주십시오.

왜 지금 이 구조를 말하는가

"나중에 지원 예정"은 흔한 약속이지만, MovesEye는 이미 그 구조로 다시 지어졌습니다.

  • 비즈니스 로직과 수집 코드 사이에 소스 중립 계약(포트) 을 세웠습니다
  • 애플리케이션 코드가 Zabbix 구현을 직접 참조하면 빌드가 실패하도록 강제했습니다
  • Zabbix는 그 계약의 첫 번째 어댑터일 뿐입니다

즉 새 소스를 붙이는 일이 "화면을 다시 만드는 일"이 아니라 "어댑터 하나를 추가하는 일"입니다. 이 전환 작업(Phase 1)은 완료됐습니다.

5. 핵심 가치

5-1. 하나의 화면에서 장애를 찾는다

문제 목록에서 심각도·호스트·발생 시각으로 좁히고, 그룹 → 호스트 → 메트릭으로 내려갑니다. 인지 처리(acknowledge)로 누가 보고 있는지를 팀이 공유합니다.

소스가 늘어도 이 흐름은 바뀌지 않습니다. 장애가 Zabbix에서 왔든 Prometheus에서 왔든 운영자에게는 같은 목록의 한 줄입니다.

5-2. 대상을 관리한다, 보기만 하지 않는다

조회 전용 대시보드가 아닙니다. 화면에서 감시 대상 자체를 관리합니다 — 호스트 등록, 템플릿 연결, 아이템·트리거 정의. 여기서 한 변경은 실제 원천 시스템에 반영됩니다.

이 영역은 소스마다 개념이 달라 공통화되지 않습니다. 각 소스의 관리 기능은 해당 소스가 연결됐을 때만 활성화됩니다(Zabbix는 호스트·템플릿·아이템·트리거, Prometheus는 타깃·서비스 디스커버리·규칙 식으로).

5-3. 자산을 비용까지 관리한다 [개발 중]

모니터링 대상과 자산 대장이 분리되면 둘 다 낡습니다. MovesEye는 모니터링 중인 장비가 곧 자산입니다.

  • 수집된 호스트가 자동으로 자산으로 올라옵니다
  • 수집 대상이 아닌 것(비품·회선 등)도 직접 등록해 함께 관리합니다
  • 취득가·취득일을 넣으면 감가상각을 자동 계산합니다(정액법·정률법, 한국 세무 기준)
  • 엑셀 데이터는 CSV로 일괄 업로드합니다

어느 모니터링 도구에도 없는 영역입니다.

5-4. 위치와 구성을 눈으로 본다

기능설명
네트워크 맵구성도를 그리고 노드에 실제 호스트를 연결해 현재 상태가 반영된 구성도를 봅니다
지리 맵지도 위에 사업장·데이터센터 단위로 장비를 배치합니다

구성도가 낡는 이유는 그것이 "그림"이기 때문입니다. MovesEye의 맵은 실제 호스트에 연결돼 살아 있습니다.

5-5. 볼 수 있는 범위를 통제한다

두 축으로 통제합니다.

  • 기능 권한 — 어떤 메뉴·기능을 쓸 수 있는가
  • 데이터 범위 — 어떤 호스트 그룹의 데이터를 볼 수 있는가

부서별 담당 장비만 보여주거나 협력사에 특정 그룹만 여는 구성이 가능합니다. 권한은 화면 숨김이 아니라 서버에서 다시 검증하므로 우회할 수 없습니다.

도구마다 권한 체계가 제각각인 문제를, 통합 계층에서 한 번에 해결합니다.

능력 기반 메뉴 노출

소스마다 할 수 있는 일이 다릅니다. MovesEye는 각 소스가 선언한 능력(capability) 에 따라 화면을 조정합니다.

능력의미
METRICS시계열 메트릭 조회
INVENTORY감시 대상 목록·속성 조회
ALERTS장애·이벤트 조회
ALERT_ACK장애 인지 처리
LOGS로그 조회
ZABBIX_ADMINZabbix 전용 대상 관리

메트릭만 제공하는 소스를 붙이면 메트릭 화면만 켜집니다. 관리 메뉴는 그 능력을 가진 소스가 있을 때만 나타납니다.

수집기 분리에 대해

현재 수집 어댑터는 애플리케이션과 같은 프로세스에서 동작합니다. 다음 상황이 생기면 별도 수집 서버로 분리할 수 있도록 계약을 미리 호환 가능하게 설계해 두었습니다.

  • 고객사 망 구조상 수집기를 분산 배치해야 할 때
  • 수집 부하가 화면 응답성에 영향을 줄 때
  • 수집기를 다른 언어로 구현해야 할 때

9. 도입 요건

필수

  • 데이터소스 최소 1개 — 현재는 Zabbix (기존 운영 중인 것을 그대로 사용)
  • PostgreSQL — 제품 데이터
  • Redis — 세션·캐시
  • 애플리케이션 서버 (JDK 17)

선택

  • SMTP — 메일 발송
  • AWS 자격증명 — 클라우드 모니터링

기존 모니터링 도구가 있다면 추가로 필요한 것은 애플리케이션 서버와 DB뿐입니다. 수집 구조를 바꾸지 않으므로 기존 감시 체계에 영향을 주지 않습니다.

10. 도입 절차

단계내용담당
1요건 확인 — 사용 중인 모니터링 도구, 대상 규모, 필요 기능양측
2환경 준비 — 서버·DB·Redis, 소스 접근용 전용 계정고객
3설치·데이터소스 연동공급사
4초기 설정 — 자산 동기화, 장비 분류, 배치 주기공급사 + 고객
5권한 설계 — 역할·부서별 데이터 범위고객 주도
6사용자 교육공급사
7운영 전환고객

5단계(권한 설계)가 실질적으로 가장 중요합니다. 조직 구조를 어떻게 반영할지가 사용 경험을 좌우합니다. 처음부터 세밀하게 쪼개기보다 3~4개 역할로 시작해 필요할 때 나누기를 권합니다.

11. 자주 받는 질문

Q. 지금 당장 Prometheus를 붙일 수 있나요? 아니요. 현재 동작하는 어댑터는 Zabbix뿐입니다. 다중 소스를 위한 내부 구조(중립 계약, 소스 레지스트리, 능력 기반 게이팅)는 완성됐고 Prometheus 어댑터 구현이 다음 단계입니다. 도입 일정은 협의가 필요합니다.

Q. 기존 모니터링 도구를 바꿔야 하나요? 아니요. 기존 도구를 그대로 두고 API로 연동합니다. 수집 구조·에이전트·알림 규칙을 변경하지 않습니다.

Q. 여러 소스를 동시에 붙이면 같은 서버가 중복으로 보이나요? Phase 2 시점에는 소스별로 구분돼 보입니다. 같은 실물을 하나로 묶는 크로스 소스 식별은 그 다음 단계이며, 초기에는 수동 매핑으로 시작할 계획입니다. 이 부분은 솔직히 말씀드리는 것이 맞습니다 — 자동 식별은 어려운 문제입니다.

Q. Grafana를 이미 쓰고 있는데 왜 필요한가요? Grafana는 시각화 자유도가 필요할 때 강력합니다. MovesEye는 대시보드를 조립하는 도구가 아니라 운영 업무가 완성된 제품입니다. 권한 통제, 대상 관리, 자산·비용, 맵처럼 Grafana에 없는 영역이 필요하면 함께 쓰는 것도 가능합니다.

Q. 제품에서 설정을 바꾸면 원천 시스템에도 반영되나요? 네. 대상 관리 기능은 실제 원천 시스템에 기록됩니다. 별도 사본이 아닙니다.

Q. 몇 대까지 관리할 수 있나요? 대수 제한을 두지 않습니다. 실제 성능은 연결된 소스의 규모와 서버 사양에 따르므로 도입 전 규모를 공유해 주시면 검토해 드립니다.

Q. 폐쇄망에서 쓸 수 있나요? 제품 자체는 외부 통신 없이 동작합니다. 다만 지도 기능은 지도 타일 서버가, 클라우드·SaaS 소스(Datadog 등) 연동은 인터넷 연결이 필요합니다.

Q. 데이터는 어디에 저장되나요? 고객사 인프라에 설치되는 온프레미스 제품입니다. 데이터가 외부로 나가지 않습니다.

Q. 한국어를 지원하나요? 전 화면 한국어·영어를 지원하며 사용자별로 설정합니다.
