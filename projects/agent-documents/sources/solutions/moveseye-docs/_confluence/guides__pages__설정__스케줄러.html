무엇을 하는 화면인가

배치 작업의 실행 여부와 주기를 관리한다. 화면 안내대로 저장하면 재기동 없이 즉시 적용된다 — cron이 코드에 박혀 있지 않고 DB 설정을 따르기 때문이다.

화면 구성

열내용
작업배치 이름
사용 여부사용 / 중지
주기N분마다, 매일 HH:mm, 매주 요일 HH:mm, 매월 D일 HH:mm

옵션작업별 추가 설정
동작지금 실행 · 편집

등록된 배치

작업하는 일성격
asset_sync호스트 → 자산 동기화수집
event_sync이벤트·문제 동기화수집 (짧은 주기)
event_cleanup오래된 이벤트 정리정리
report_weekly주간 리포트 생성집계
report_monthly월간 리포트 생성집계
report_cleanup만료 리포트 삭제정리
user_sync사용자 동기화수집

주기 설계

  • event_sync는 짧게(1분 수준) 돌아야 장애를 빨리 잡는다. 대신 무겁다.
  • 리포트 집계는 오래 걸린다. 이벤트 동기화와 겹치는 시간대를 피한다.
  • 배치 스레드 풀 크기는 서버 설정(SCHEDULER_POOL_SIZE, 기본 4)이다. 등록 배치가 7개이므로 전부 겹치면 대기가 생긴다.

실행 이력 읽는 법

부분 실패는 성공으로 찍힌다

🔴 가장 중요한 함정이다. 40개 그룹 중 2개가 실패해도 결과는 "성공"이고, 실패는 요약 문자열에만 남는다.

ok=38 fail=2

성공 표시만 보고 전건 처리됐다고 판단하지 않는다. 요약을 읽는다.

전건 실패

실패로 기록되며 다음 실행은 취소되지 않는다. 원인을 고치면 다음 주기에 자연 복구된다.

주의할 점

수동 실행을 연타하지 않는다

"지금 실행"을 눌렀는데 반응이 없어 보여도 다시 누르지 않는다. 이전 실행이 아직 돌고 있을 수 있다.

파괴적 동기화 — user_sync

🔴 사용자 동기화는 Zabbix에 없는 로컬 계정을 제거할 수 있다. 그래서 서버 설정(SYNC_ENABLED)의 기본값이 꺼짐이다.

옵션의 'Zabbix 반영' / '가져오기만' 구분을 확인한다. 제품에서만 만든 계정이 있다면 켜기 전에 백업한다.

정리 배치는 라이선스와 무관하게 돈다

event_cleanup·report_cleanup은 라이선스가 만료돼도 계속 실행된다. 멈추면 만료된 설치본의 디스크가 무한정 차기 때문이다. 이 두 배치는 외부 수집 없이 자기 DB만 정리한다.

다음 실행이 '예정 없음'이면

배치가 비활성 상태이거나 주기가 설정되지 않은 것이다.
