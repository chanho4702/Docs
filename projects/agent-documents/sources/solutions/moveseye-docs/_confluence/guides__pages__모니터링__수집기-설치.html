수집기 설치 (APM 온보딩)

화면 모니터링 > 어플리케이션 모니터링 > 수집기 (관리자 전용) 이 문서와 화면의 관계 화면의 '설치 가이드' 탭은 서버(GET /apm/install-guide)가 만든 문구를 그대로 그린다. 이 문서는 그 문구의 문서판이다. 둘이 다르면 화면이 정본이다 — 화면은 설치본 설정(사내 미러 주소·큐 디렉터리)을 반영하지만 이 문서는 기본값만 적는다. 검증 조합 otelcol-contrib 0.159.0 · opentelemetry-javaagent 2.31.1 (2026-08-31 round-trip 실측). 다른 버전은 검증되지 않았다.

시작 전에

준비물

항목내용
MovesEye 권한관리자 계정. 라이선스에 APM 기능(PREMIUM) 포함
Collector를 둘 서버 1대Windows 10 1803 이상 / Windows Server, 또는 Linux amd64. 도커 불필요(단일 바이너리)
네트워크앱 서버 → Collector 4317(gRPC) · 4318(HTTP) 내부 통신. Collector → MovesEye 서버 주소로 아웃바운드 HTTPS. Collector 서버에서 내려받기 위한 GitHub 접근(폐쇄망은 사내 미러)
앱계측을 붙이고 재기동할 수 있어야 한다. Java는 코드 수정 없이 JVM 옵션 한 줄

두 가지 원칙

  • 🔴 게이트웨이 Collector는 사이트당 1대만 둔다. 두 대 이상이면 한 트레이스의 스팬이 갈라져, trace_id 일관 해싱(loadbalancing exporter 2계층) 없이는 tail 샘플링이 무의미해진다. 이중화가 필요하면 active-standby로 두고 전환 중 유실을 허용한다 — active-active는 지원 범위 밖이다. 여러 대가 같은 토큰으로 보내면 수집기별 지표가 서로 덮어쓴다.
  • ℹ️ 앱은 MovesEye가 아니라 Collector로 보낸다(LAN 내 4317/4318). MovesEye로 직접 보내는 구성은 지원하지 않는다 — 마스킹·샘플링·재시도 큐가 전부 Collector에 있다.

데이터가 오는 길

 [앱 서버들]                     [Collector 서버 1대]                     [MovesEye 서버]
 Java -javaagent ──gRPC 4317──▶ otelcol-contrib 0.159.0 ──HTTPS/json──▶ <MovesEye 주소>/apm/otlp/v1/metrics
 .NET/Node/Python  (또는 4318)    · 마스킹·허용목록·배치                    · Bearer 수신 토큰 검사
                                  · 디스크 큐(못 보낸 것 보관)             · 라이선스(APM) 검사
                                  · 자기 상태 지표도 함께 보냄             · 1분 표에 적재

1단계 — 토큰 발급과 설정 파일 받기 (MovesEye 화면)

수집기 > 토큰·설정 탭.

  1. 토큰 발급을 누르고 라벨(어느 수집기인지 구분할 이름, 예: 본사 수집기)을 적는다.
  2. '설정 파일(yaml)도 함께 받기'를 켠 채 발급한다. 켜 두면 토큰이 이미 채워진 완성본 yaml을 같은 응답으로 받는다.
  3. 발급 결과 창에서 토큰 원문을 복사하고 yaml을 내려받는다. 🔴 이 창을 닫으면 토큰 원문을 다시 볼 수 없다 — 서버는 해시만 저장하므로 복구 경로가 없다. 잃어버리면 새로 발급하고 옛 토큰을 회수하는 수밖에 없다.
  4. 창에 보이는 수신 주소(endpoint) 는 &lt;MovesEye 주소&gt;/apm/otlp 꼴이다. 뒤에 /v1/metrics를 붙이지 않는다 — exporter가 스스로 붙인다.

설정 파일 옵션 ('설정 파일 다시 만들기')

토큰을 발급한 뒤에도 설정 파일만 다시 만들 수 있다. 이때는 토큰 자리가 ${RECEIVE_TOKEN} 자리표시로 남으므로 발급 때 복사한 값을 손으로 넣어야 한다.

항목뜻기본
MovesEye 주소스킴 포함(예: https://moveseye.example.com). /apm/otlp는 서버가 붙이고, /v1/metrics를 붙여 오면 거절한다설치본 힌트
수집기 OS큐 디렉터리 기본값과 설치 명령이 갈린다Linux
느린 요청 임계(ms)이 시간을 넘는 트레이스는 샘플링에서 항상 남긴다(2단계)서버 기본값
정상 트레이스 표본(%)느리지도 실패하지도 않은 요청 중 남길 비율(2단계)서버 기본값
메모리 상한(MiB)Collector 프로세스가 쓸 최대 메모리서버 기본값
디스크 큐 경로아직 보내지 못한 데이터가 쌓이는 곳. 비우면 OS별 기본값 — Linux /var/lib/moveseye/otelcol-queue, Windows C:\ProgramData\moveseye\otelcol-queue설치본 설정
원문 SQL 보존🔴 켜면 리터럴 마스킹 프로세서가 빠져 쿼리 원문이 그대로 저장된다. 쿼리 값에 이름·연락처 같은 개인정보가 실려 올 수 있고, 누가 켰는지 감사 로그에 남는다. 문제를 재현하는 동안에만 켜고 끝나면 되돌린다마스킹(전역 기본값 따름)

설정 파일에는 토큰이 들어 있다. 파일 권한을 제한하고 형상관리(git)에 올리지 않는다.

2단계 — Collector 설치

아래는 화면 설치 가이드 탭의 Windows·Linux 6단계와 같은 명령이다. 다운로드 주소의 베이스(https://github.com/open-telemetry)는 설치본 설정으로 사내 미러로 바꿀 수 있으며, 그때는 화면에 보이는 주소를 쓴다. 미러는 베이스 뒤에 /&lt;저장소&gt;/releases/download/v&lt;버전&gt;/&lt;파일&gt; 경로 모양을 그대로 흉내 내면 된다.

Windows (관리자 권한 명령 프롬프트)

Windows 10 1803 이상이면 curl.exe·tar가 기본 포함되어 있다.

#단계명령
1Collector 내려받기curl.exe -L -o %TEMP%\otelcol-contrib.tar.gz https://github.com/open-telemetry/opentelemetry-collector-releases/releases/download/v0.159.0/otelcol-contrib_0.159.0_windows_amd64.tar.gz
2압축 해제mkdir "C:\Program Files\moveseye-collector" &amp; tar -xzf %TEMP%\otelcol-contrib.tar.gz -C "C:\Program Files\moveseye-collector"
3설정 파일 배치mkdir "C:\ProgramData\moveseye" &amp; copy config.yaml "C:\ProgramData\moveseye\config.yaml"
4큐 디렉터리 권한 제한mkdir "C:\ProgramData\moveseye\otelcol-queue" &amp; icacls "C:\ProgramData\moveseye\otelcol-queue" /inheritance:r /grant:r "SYSTEM:(OI)(CI)F" "Administrators:(OI)(CI)F"
5Windows 서비스 등록sc.exe create otelcol binPath= "\"C:\Program Files\moveseye-collector\otelcol-contrib.exe\" --config \"C:\ProgramData\moveseye\config.yaml\"" start= auto DisplayName= "MovesEye OTel Collector"
6서비스 시작sc.exe start otelcol
  • 3단계: 🔴 설정 화면에서 내려받은 config.yaml을 두고, 안의 ${RECEIVE_TOKEN} 자리에 발급 시 1회 표시된 토큰 원문을 넣는다(발급과 함께 받은 완성본이면 이미 채워져 있다).
  • 4단계: 디스크 큐에는 마스킹 후 텔레메트리가 남는다. 상속을 끊고 SYSTEM·관리자만 접근하게 둔다. 설정 파일(config.yaml)에도 같은 제한을 건다.
  • 5단계: 🔴 sc.exe는 binPath= 와 start= 의 등호 뒤에 공백이 있어야 한다(등호 앞에는 없다). 경로에 공백이 있어 안쪽 큰따옴표를 이스케이프한다. nssm 같은 별도 도구는 필요하지 않다.
  • 6단계: 실패하면 이벤트 뷰어 > Windows 로그 > 애플리케이션에서 otelcol 항목을 확인한다.

Linux (systemd)

#단계명령
1Collector 내려받기curl -L -o /tmp/otelcol-contrib.tar.gz https://github.com/open-telemetry/opentelemetry-collector-releases/releases/download/v0.159.0/otelcol-contrib_0.159.0_linux_amd64.tar.gz

5systemd 서비스 등록아래 유닛 파일
6서비스 시작sudo systemctl daemon-reload &amp;&amp; sudo systemctl enable --now otelcol &amp;&amp; systemctl status otelcol --no-pager
sudo tee /etc/systemd/system/otelcol.service > /dev/null <<'UNIT'
[Unit]
Description=MovesEye OTel Collector
After=network-online.target

[Service]
ExecStart=/usr/local/bin/otelcol-contrib --config /etc/moveseye/collector.yaml
Restart=always
RestartSec=5
User=otelcol
Group=otelcol
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target
UNIT
  • 3단계: 🔴 설정 화면에서 내려받은 config.yaml을 두고, 안의 ${RECEIVE_TOKEN} 자리에 발급 시 1회 표시된 토큰 원문을 넣는다. 토큰이 들어 있으므로 다른 사용자에게 읽기를 주지 않는다(640, root:otelcol).
  • 4단계: 디스크 큐에는 마스킹 후 텔레메트리가 남는다 — 700으로 둔다.
  • 5단계: Collector를 root로 돌리지 않기 위해 전용 계정 otelcol로 실행한다.

3단계 — 앱 계측

스택이 달라도 앞의 세 환경변수는 같다(서비스 식별의 정본). 앱 프로세스에 넣고, 꺾쇠 자리표시(&lt;...&gt;)는 실제 값으로 바꾼다 — 그럴듯한 예시값을 그대로 붙이면 아무 데이터도 안 온다.

공통 환경변수 3개

이름값왜 필요한가
OTEL_SERVICE_NAME&lt;서비스명&gt;🔴 이 값이 MovesEye의 서비스 이름이 된다. 인스턴스마다 같아야 하고, 환경이 다르면 이름이 아니라 아래 환경 속성으로 가른다
OTEL_EXPORTER_OTLP_ENDPOINThttp://&lt;collector-host&gt;:4317🔴 앱은 MovesEye가 아니라 Collector로 보낸다(gRPC 4317). MovesEye 주소를 여기 넣으면 인증이 없어 전부 버려진다
OTEL_RESOURCE_ATTRIBUTES`deployment.environment.name=<prod\stage\dev>,service.version=<버전>`환경과 버전. 버전이 있어야 배포 직후 수신 끊김 유예(10분)와 배포 전후 비교가 된다. 🔴 deployment.environment.name으로 적는다 — 구 이름 deployment.environment만 보내면 환경을 못 갈라 prod와 stage가 한 서비스로 합쳐진다

Java (Spring · Tomcat · WAS · Jira 등) — ✅ 실측

앱을 고칠 필요는 없다.

#단계명령·설명

Node.js — ⚠️ 실측 전

#단계명령·설명
1SDK 추가go get go.opentelemetry.io/otel go.opentelemetry.io/otel/sdk go.opentelemetry.io/otel/exporters/otlp/otlpmetric/otlpmetricgrpc go.opentelemetry.io/contrib/instrumentation/net/http/otelhttp
2초기화 코드 추가handler := otelhttp.NewHandler(mux, "http.server") — MeterProvider를 otlpmetricgrpc exporter로 만들고 http.server.request.duration 히스토그램을 내보내면 MovesEye 화면이 그대로 채워진다
3앱 재빌드·재기동⚠️ 수동 계측이라 어떤 지표가 오는지는 작성한 코드에 달려 있다

추가 환경변수: Node와 같다.

4단계 — 60초 검증

🔴 순서가 곧 진단이다. Collector가 떠 있나 → MovesEye가 받고 있나 → 화면에 보이나. 실패한 첫 단계가 곧 원인이다.

#확인방법판정

문제 해결

Collector 로그의 응답 코드

Permanent error와 함께 찍힌 코드가 원인이다. 401·403·413은 재시도 없이 즉시 버려진다. 반면 429·503은 백오프 재시도라 잠깐이면 저절로 복구된다.

코드뜻조치
401토큰이 틀렸거나 회수됐다설정 파일의 Authorization: Bearer … 값 확인. ${RECEIVE_TOKEN} 자리표시가 그대로 남아 있지 않은지 본다(그대로 배포하면 Collector는 기동에 성공한 채 인증에 실패하고 화면에는 '데이터가 안 온다'로만 보인다). 필요하면 재발급
403APM 기능 미보유 또는 라이선스 만료설정 > 라이선스에서 프리미엄 모듈 APM 포함 여부·만료일 확인. 아래 '라이선스 만료' 참조
413배치가 8MB를 넘었다실측 배치는 수십 KB라 보통 안 걸린다. 걸리면 설정의 send_batch_max_size를 줄인다
429 · 503일시 과부하·서버 장애Collector가 알아서 재시도한다(디스크 큐 보존, 최대 30분). MovesEye 서버 상태를 본다
415 · 400Content-Type 또는 JSON 형식 오류우리 템플릿(encoding: json)이 아닌 설정을 쓴 경우. 화면에서 만든 yaml로 되돌린다

라이선스 만료 — 데이터는 즉시 사라진다

🔴 라이선스가 만료되면 수신이 403이 되고, OTLP exporter는 403을 영구 실패로 보아 재시도 없이 즉시 폐기한다(실측). 만료된 순간부터 데이터가 사라지며 디스크 큐에도 남지 않는다. 나중에 갱신해도 그 사이 데이터는 돌아오지 않는다.

  • 만료 전에 갱신한다. 수집기 화면 상단에 "라이선스 만료까지 N일" 배너가 뜬다.
  • 만료가 예정돼 있고 갱신하지 않을 것이면 수집기를 중지하고 큐를 비운다: (1) 앱의 계측을 끄거나 그대로 두고 (2) Collector 서비스 중지 — Windows sc.exe stop otelcol, Linux sudo systemctl stop otelcol (3) 큐 디렉터리(C:\ProgramData\moveseye\otelcol-queue / /var/lib/moveseye/otelcol-queue) 안 파일 삭제 (4) 수집기 화면에서 토큰 회수. 배너의 '토큰 전체 회수' 버튼은 (4)를 한 번에 한다.
  • Collector를 계속 돌리면 앱은 계속 보내고 Collector는 계속 거부당하며 로그가 403으로 채워진다.

서비스가 목록에 안 보인다

  1. 4단계 검증을 1번부터 다시 한다.
  2. 서비스 이름이 unknown_service 로 왔다 — 앱에 OTEL_SERVICE_NAME이 없다. 이 이름은 등록이 거부되고 폐기 통계에 UNKNOWN_SERVICE로 잡힌다. 환경변수를 넣고 앱을 재기동한다.
  3. 등록 방식이 승인이면 등록·설정 탭의 승인 대기 목록에서 승인한다. 사전 등록만이면 먼저 서비스를 등록해야 받아 준다.
  4. prod와 stage가 한 서비스로 합쳐졌다 — deployment.environment.name이 아니라 구 이름 deployment.environment를 썼다. 속성 이름을 고치고 재기동한다.
  5. Collector 자기 지표(service.name=otelcol-contrib)는 서비스로 등록되지 않고 수집기 탭에 나타난다 — 정상이다.
  6. 상세 절차와 상태 뜻은 어플리케이션 모니터링 — 자주 묻는 것.

큐 디렉터리가 커진다

MovesEye로 보내지 못한 데이터가 쌓이는 곳이다(마스킹 후 데이터만 남는다). 커지고 있으면 Collector → MovesEye 구간이 막힌 것이다 — 4단계 2번(수신 확인)과 로그의 응답 코드를 본다. 원인을 고치면 저절로 비워진다(재시도 최대 30분). 정리가 필요하면 Collector를 중지한 뒤 디렉터리 안 파일을 지운다 — 켜진 채 지우지 않는다.

Windows 서비스가 등록되지 않는다

sc.exe create의 binPath=·start= 등호 뒤 공백을 확인한다. 경로에 공백(Program Files)이 있어 안쪽 큰따옴표를 \"로 이스케이프해야 한다. 표의 명령을 그대로 복사한다.

설정 파일을 손봤더니 Collector가 안 뜬다

otelcol-contrib validate --config &lt;파일&gt;로 문법을 먼저 검사한다. 화면에서 만든 yaml은 검증된 템플릿이므로 직접 편집하지 말고 옵션을 바꿔 다시 만드는 것이 안전하다. encoding: json은 서버 파서가 json 전용이라 바꾸면 415가 난다.

운영 중 알아 둘 것

  • 토큰 회수는 즉시다. 회수하는 순간 그 토큰으로 오는 수신이 전부 거부되고 그 사이 데이터는 재시도 없이 버려진다. 수집기 설정 파일을 새 토큰으로 교체한 뒤 회수한다.
  • 버전은 올리지 않는다. 0.159.0 / 2.31.1은 round-trip을 실측한 조합이다. 다른 버전은 검증되지 않았고, 특히 Collector는 릴리스에 별칭이 없어 풀버전 URL만 있다.
  • 원문 SQL 보존을 켜 둔 상태로 잊지 않는다. 등록·설정 탭에 마지막으로 바꾼 사람이 표시된다.
  • Collector 자체의 운영(업그레이드·모니터링 대행)은 MovesEye가 하지 않는다. 상태 탭의 큐 적체·전송 실패와 알람 규칙 '수집기 전송 실패'로 이상을 잡는 데까지다.
