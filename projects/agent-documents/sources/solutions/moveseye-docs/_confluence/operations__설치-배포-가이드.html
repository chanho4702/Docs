MovesEye 설치·배포 가이드

이 문서는 새 환경에 제품을 설치하는 절차다. 이미 설치된 환경의 기동·검증은 로컬·검증 Runbook, 설치 후 제품 설정은 관리자 가이드를 본다.

⚠️ 이 절차는 소스(Dockerfile·빌드 스크립트·설정 파일)에서 도출한 것이며, 실제 production 배포로 검증되지 않았다. Production Runbook이 current로 승격되기 전까지 운영 환경 적용은 담당자 검토를 거친다.

1. 시스템 구성

                    ┌─────────────────┐
   Browser ────────▶│  FE (정적 번들)   │  Nginx 등 웹서버
                    └────────┬────────┘
                             │ HTTP/HTTPS
                    ┌────────▼────────┐
                    │ Spring app      │  :3000
                    │ (moveseye-be)   │
                    └───┬───┬───┬──┬──┘
              ┌─────────┘   │   │  └──────────┐
    ┌─────────▼──┐  ┌───────▼─┐ │      ┌──────▼─────┐
    │ PostgreSQL │  │  Redis  │ │      │   SMTP     │
    └────────────┘  └─────────┘ │      └────────────┘
                    ┌───────────▼────┐  ┌────────────┐
                    │ Zabbix JSON-RPC│  │  AWS API   │
                    └────────────────┘  └────────────┘

FE는 정적 번들이다. 빌드 결과를 웹서버가 서빙하고, API 호출만 BE로 간다. BE는 단일 Spring Boot 프로세스다.

2. 사전 요구사항

2-1. 필수 구성요소

구성요소버전비고
JDK17빌드·실행 모두. 상위 버전 미검증
Node.js18 이상FE 빌드 시에만 필요
PostgreSQL13 이상 권장jsonb 사용
Redis6 이상세션·Zabbix 인증 캐시
ZabbixJSON-RPC 지원 버전필수 연동 대상

🔴 JDK 17을 명시적으로 지정한다. 시스템 전역 JAVA_HOME이 다른 버전(특히 JDK 8)을 가리키는 환경이 흔하다. 빌드가 알 수 없는 오류로 실패하면 가장 먼저 java -version을 확인한다.

2-2. 선택 구성요소

구성요소필요한 경우
SMTP 서버비밀번호 재설정·메일 발송
AWS 자격증명클라우드 인프라(EC2·VPC) 모니터링
Docker컨테이너 배포 시

2-3. 준비할 것

  • ☐ Zabbix 전용 API 계정 (사람과 공유하지 않는 계정)
  • ☐ 빈 PostgreSQL 데이터베이스와 접속 계정
  • ☐ 충분히 긴 무작위 JWT_SECRET
  • ☐ 서비스 도메인 또는 접속 URL (CORS·쿠키 설정에 필요)
  • ☐ 제품 라이선스 키

3. 데이터베이스 준비

빈 데이터베이스만 만들면 된다. 스키마를 수동으로 만들지 않는다 — Flyway가 기동 시 V1부터 최신까지 자동 적용한다(현재 최신 V20).

CREATE DATABASE moveseye;
CREATE USER moveseye_app WITH PASSWORD '<강한 비밀번호>';
GRANT ALL PRIVILEGES ON DATABASE moveseye TO moveseye_app;

Hibernate의 ddl-auto는 none이다. 애플리케이션은 스키마를 절대 자동 변경하지 않으며, 모든 스키마 변경은 Flyway 마이그레이션을 거친다. 이 정책을 끄지 않는다.

4. 환경변수 레퍼런스

.env 파일을 Spring이 자동으로 읽지 않는다. OS 환경변수 또는 컨테이너 환경변수로 프로세스에 주입해야 한다.

4-1. 필수

변수설명
DB_HOSTPostgreSQL 호스트
DB_PORTPostgreSQL 포트
DB_NAME데이터베이스명
DB_USERDB 계정
DB_PASSDB 비밀번호
JWT_SECRET토큰 서명 키. 기본값·예제값을 그대로 쓰지 않는다
ZABBIX_API_URLZabbix JSON-RPC 엔드포인트
ZABBIX_SADMIN_USERNAMEZabbix 전용 계정
ZABBIX_SADMIN_PASSWORDZabbix 전용 계정 비밀번호

4-2. 네트워크·보안

변수기본값설명
PORT3000BE 리스닝 포트
CORS_ALLOWED_ORIGINS—FE origin. 와일드카드로 낮추지 않는다
COOKIE_SECURE—HTTPS 환경에서 true. HTTP 로컬이면 false
COOKIE_SAME_SITE—크로스 도메인 배포 시 조정
BASE_PATH—리버스 프록시 하위 경로 배포 시
FE_PATH_WEB—메일 링크 등에 쓰이는 FE 주소
JWT_ACCESS_EXPIRATION_SECONDS—액세스 토큰 수명
JWT_REFRESH_EXPIRATION_SECONDS—리프레시 토큰 수명

4-3. 인프라

변수기본값설명
REDIS_HOSTlocalhost
REDIS_PORT6379
SCHEDULER_POOL_SIZE4배치 스레드 풀. 등록 배치는 7개
SPRINGDOC_ENABLED운영 false운영에서 Swagger를 켜지 않는다

4-4. 선택 기능

변수설명
MAIL_HOST / MAIL_PORT / MAIL_USER / MAIL_PASSSMTP. 기본 465(SMTPS)
MAIL_FROM_EMAIL / MAIL_FROM_NAME발신자 표기
AWS_ACCESS_KEY_ID / AWS_SECRET_ACCESS_KEY미설정 시 IAM 표준 자격증명 체인 사용
LENS_CAP아이템·트리거 렌즈 조회 상한
SYNC_ENABLED기본 false 유지 권장 — §7-2

4-5. 사용하지 않는 변수

VAULT_ADDR, VAULT_TOKEN은 설정 파일에 흔적이 남아 있으나 Vault 연동은 채택하지 않기로 결정됐고 관련 설정은 주석 처리돼 있다. 되살리지 않는다. 시크릿 정본은 OS 환경변수다.

5. 백엔드 설치

5-1. 방법 A — Docker (권장)

이미지에 멀티스테이지 빌드가 정의돼 있다.

cd moveseye-be-spring
docker build -t moveseye-be:latest .

docker run -d --name moveseye-be \
  -p 3000:3000 \
  -e DB_HOST=... -e DB_PORT=5432 -e DB_NAME=moveseye \
  -e DB_USER=... -e DB_PASS=... \
  -e JWT_SECRET=... \
  -e ZABBIX_API_URL=... \
  -e ZABBIX_SADMIN_USERNAME=... -e ZABBIX_SADMIN_PASSWORD=... \
  -e REDIS_HOST=... \
  -e CORS_ALLOWED_ORIGINS=https://moveseye.example.com \
  -e COOKIE_SECURE=true \
  moveseye-be:latest

컨테이너는 UTC로 고정 실행된다(-Duser.timezone=UTC). 날짜 처리가 UTC 전제이므로 이 설정을 바꾸지 않는다. 화면 표기 시각과 서버 시각이 다르게 보이면 이 때문이며, 정상이다.

5-2. 방법 B — JAR 직접 실행

cd moveseye-be-spring
./gradlew bootJar          # Windows: .\gradlew.bat bootJar
java -Duser.timezone=UTC -jar build/libs/*.jar

systemd 서비스로 등록할 때도 -Duser.timezone=UTC와 환경변수 주입을 빠뜨리지 않는다.

5-3. 기동 확인

  1. 로그에 Started 가 찍히고 3000 포트가 바인딩됐는가
  2. Flyway가 V1~V20을 적용하고 오류가 없는가
  3. Flyway 오류가 있으면 우회 기동하지 않는다 — 스키마 불일치 상태로 운영하면 이후 데이터가 깨진다

6. 프론트엔드 설치

cd moveseyee_fe
npm ci
npm run build        # 산출물: dist/

빌드 전 API 주소를 환경에 맞게 설정한다(VITE_API_URL). 환경별 빌드 스크립트도 있다: build:dev, build:qa.

dist/를 웹서버에 배치한다. SPA이므로 모든 경로를 index.html로 폴백시켜야 한다. 없으면 새로고침이나 URL 직접 입력 시 404가 난다.

server {
    listen 443 ssl;
    server_name moveseye.example.com;

    root /var/www/moveseye;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;   # SPA 폴백 (필수)
    }

    location /api/ {
        proxy_pass http://127.0.0.1:3000/;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

프록시를 쓰든 직접 호출하든 BE의 CORS_ALLOWED_ORIGINS에 실제 접속 origin이 들어가야 한다.

7. 설치 후 필수 조치

7-1. 초기 계정 비밀번호 변경

마이그레이션 V10이 초기 관리자 계정을 시드한다. 최초 로그인 직후 비밀번호를 변경한다.

7-2. 파괴적 동기화 차단 확인

SYNC_ENABLED가 false인지 확인한다. true이면 Zabbix에 없는 로컬 사용자가 삭제될 수 있다.

7-3. 문서 노출 차단

운영에서 SPRINGDOC_ENABLED가 꺼져 있는지 확인한다. /api와 /v3/api-docs가 응답하면 안 된다.

7-4. 제품 초기 설정

관리자 가이드 §2의 도입 순서를 따른다. 특히 자산 최초 동기화를 빠뜨리면 지리 맵이 빈 것처럼 보인다.

8. 업그레이드

  1. DB를 백업한다. Flyway 마이그레이션은 자동 롤백되지 않는다.
  2. 릴리스 노트에서 새로 추가된 마이그레이션과 환경변수를 확인한다.
  3. BE를 정지한다.
  4. 새 이미지/JAR로 교체하고 기동한다 — Flyway가 신규 마이그레이션만 적용한다.
  5. FE 번들을 교체한다. 브라우저 캐시 때문에 구 번들이 남을 수 있으므로 강제 새로고침으로 확인한다.
  6. 로그인 → 홈 → 호스트 그룹 → 호스트 상세 → 문제 목록 순으로 스모크 테스트한다.

🔴 BE와 FE 버전을 섞어 배포하지 않는다. API 계약이 바뀐 릴리스에서 한쪽만 올리면 화면이 빈 값을 그리거나 저장이 실패한다. 원인 파악이 어렵다.

롤백

코드 롤백과 DB 롤백은 별개로 판단한다. 이전 버전 JAR로 되돌려도 이미 적용된 마이그레이션은 남아 있다. 스키마 변경이 포함된 릴리스는 되돌리기보다 전진 수정(forward-fix) 을 우선 검토한다.
