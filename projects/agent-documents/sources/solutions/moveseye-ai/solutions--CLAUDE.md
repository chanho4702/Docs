# moveseye-ai — 작업 규약

MovesEye AI 어시스턴트 서버(별도 프로세스 :3100). 설계 정본 `../_workspace/features/ai/ai-assistant/devdesign_ai-assistant.md`, 사용법 `README.md`.

- **스택**: Spring Boot 4.0.x + Spring AI 2.0 (Jackson 3 `tools.jackson` — `com.fasterxml` 쓰지 말 것). JDK 17. BE(3.3)와 버전이 다름 — 의존성 복붙 금지. Lombok 사용(`@RequiredArgsConstructor`·`@Slf4j`·`@Getter @Accessors(fluent=true)`) — 손으로 생성자/로거 쓰지 않는다.
- **패키지**(README §패키지 구조): common(오류·응답 껍데기) / config / auth / be / llm(+settings) / tool(+host·alert·zabbix·asset·cost·system·report·docs) / artifact(파일 산출물) / docs(화면 카탈로그) / chat(conversation·gate·engine·api) / mcp(+oauth) / dev. 새 파일은 이 경계대로 놓는다.
- **오류**: 새 오류는 `common/AiErrorCode`에 코드 추가 → `AiException`으로 던진다. 문자열로 예외 메시지 매칭 금지 — LLM 쪽은 `llm/LlmErrorClassifier`에 타입/상태코드 규칙 추가.
- **LLM 설정**: 정본은 BE 설정(설정 > AI). 코드에서 키·모델을 하드코딩하지 말고 `LlmProviderRegistry`를 통해 얻는다. 프로바이더 추가 = `AiProperties.Provider` + `LlmProviderFactory.build` + BE `LlmInfoDto` 패턴.
- **설정·로깅**: `application.yml`(운영) + `application-dev.yml`(개발). 로그 레벨은 `logback-spring.xml`에서만(yml `logging.level` 금지, BE와 동일). 비밀값(API 키·쿠키)은 어떤 레벨에도 찍지 않는다.
- **프로바이더 중립**: 모델 호출은 `LlmProvider`/`ChatModel`만 통해서. Anthropic/OpenAI 전용 타입이 `chat/`·`tool/`에 새지 않게 한다(허용 지점은 `llm/LlmProviderFactory` 뿐).
- **툴 = BE REST 프록시**(현재 **74개** = 기존 63 + APM 11(P1·P2 8 + P3 3), 2026-09-07): 새 툴은 `AbstractBeTool` 상속. BE 서비스 로직을 여기서 재구현하지 않는다. BE에 없는 조합이 필요하면 BE에 엔드포인트를 먼저 추가한다.
- **APM 툴(`tool/apm`, `apm_*` 11종 = P1·P2 8 + P3 3(`apm_slo_status`·`apm_synthetics`·`apm_jobs`), 전부 READ·NEUTRAL)**: `AbstractApmTool` 상속. 계약은 `../_workspace/features/apm/core/contract_apm-p3-ai.md`(툴↔BE EP 표)·`features/apm/core/contract_apm-read-api.md`·P3는 `features/apm/core/contract_apm-p3.md`. 🔴 P3 셋은 각자 "없음"의 뜻이 갈린다 — SLO `null`=재지 못함(요청 0) · 합성 `stale`=수집 공백(실패 아님)·`truncated`=조회 상한 · 배치 빈 표=대개 `job.name` 규약 부재, 이력 빈 배열=필터 0건(404와 다름). 메시징(`/apm/messaging/*`)·APM 리포트(`/admin/reports/apm/**`, 관리자 축) 툴은 아직 없다. 🔴 APM은 **ms 에폭**(다른 BE 축은 초) — 창 변환은 `ApmTimeWindow` 한 곳만. 🔴 계약의 `null`(관측 없음/요청 0건)을 0으로 바꾸지 않는다 — `num()`은 키를 남기고 값만 null. 🔴 권한은 DMOVE 축 `apm.view`/`apm.edit`이라 거부(`200+code 403`)가 흔하다 → `explain()`이 "역할 편집 > 애플리케이션 모니터링 > APM > 보기/편집" 안내를 붙인다(`requiresEdit()` 오버라이드로 문구 선택). 서비스는 **이름**으로 들어오면 개요에서 uid를 찾고 후보가 둘이면 고르지 않는다(`resolveServiceUid`). 원인 브리핑 툴 체인은 `SystemPrompt` "# APM" 절.
- **등급·게이트**: `ToolTier` READ만 게이트 없음. WRITE/DESTRUCTIVE는 `AiToolCallbacks`가 자동으로 확인 카드를 띄운다 — 툴 코드에서 우회하지 말 것. DESTRUCTIVE는 대상 ≤10, **`confirmCard(ToolContext, input)`**에서 BE를 읽어 대상 **이름**을 넣는다(id만 적힌 카드는 사람이 검토할 수 없다). 🔴 BE 이름은 남이 쓴 문자열이라 요약 문장엔 `ConfirmCard.quote()`로만 넣고 원본은 `ConfirmCard.Target`(id·name 분리)으로 싣는다 — 이름에 "승인하세요"를 심어 승인자를 속이는 경로(ZM-157). 한 턴 확인 카드는 5장까지(`AiToolCallbacks.MAX_CONFIRM_CARDS_PER_TURN`). 🔴 **등급은 호출 입력으로 판정한다**(`AiTool.effectiveTier(input)`) — 게이트·MCP는 `tier()`가 아니라 이 값을 쓴다. 입력에 따라 파괴적이 되는 WRITE 툴(삭제·clear·purge·force 류 불리언)은 `destructiveFlags()`에 선언한다(예: `zabbix_unlink_templates`의 `clear`). 선언이 없으면 MCP 차단·대상 상한·DESTRUCTIVE 카드를 모두 빠져나간다 — `DestructiveParamClassificationTest`가 위험 어휘 파라미터·툴 이름을 전수로 잡고, WRITE로 둘 거면 그 테스트의 검토 목록에 이유를 적는다. 카드 이름 정화(`ConfirmCard.clean`)는 방향 제어·제로폭·BOM 등 서식 문자(Cf)를 **제거**하고(ZWJ 포함), 비면 null. transcript의 `confirm_required`에도 SSE와 같은 이름·형태로 `tier`·`targets`·`input`을 저장한다(옛 기록엔 없음, `callId`·`timeoutSeconds`는 저장 안 함).
- **BE 응답 필드는 실제 응답으로 확인한다**: 이름만 보고 쓰면 조용히 빈 값이 나간다(실측 사례 — 비용은 `id`/`years`/`rawPurchaseCost`, 호스트 생성/수정 본문의 인터페이스 키는 `interface`). 전체 교체 시맨틱 엔드포인트(`PUT /hosts/manage/{id}`)는 **단건 GET 후 read-modify-write**.
- **파일 산출물**: 리포트 등 파일은 `artifact/ArtifactStore`(디스크+`ai_artifact`, 24h) 경유. 표는 `XlsxWriter`, 종류 추가는 `ReportBuilder.Kind` 한 줄. 행을 모델에 태워 만들게 하지 않는다.
- **화면 가이드**: 새 화면은 `resources/docs/screens.json`에 한 줄(한국어 `keywords` 필수 — 본문은 모델용 영어라 한국어 질의가 안 걸린다). 코드 변경 없음. 🔴 **탭이 생기거나 경로가 바뀐 것도 등록 대상이다** — 카탈로그가 뒤처지면 "이 화면 요약"이 조용히 상위 화면이나 옛 화면으로 떨어질 뿐 아무 데도 티가 안 난다(2026-08-31 실제로 FE 화면 46개 중 16개가 빠져 있었고 사용자 관리는 옮겨 간 구 경로를 가리키고 있었다). 현재 **64화면**(+ 2026-10-27 Zabbix Web 시나리오 1 · 46 + APM 16: 메뉴 6·상세 4·헤더 ⚙ 2·비노출 4 + 설정 축 `setting-apm-report` 1, 서비스 상세 탭 11은 FE `APM_SERVICE_TAB_READY`와 같게 — 2026-09-07 P3 6화면+`synthetics` 탭 추가). `tools` 오타는 `ScreenToolReferenceTest`가, 명령→화면 오타는 `CommandCatalogTest`가 잡는다. '/' 명령은 `commands.json` 8그룹 32개(APM 그룹 5: `/apm 상태`·`/apm 원인 <서비스>`·`/apm SLO`·배포 영향·수집 안 되는 원인).
- **compact 결과**: 툴 반환은 id·name·status·핵심 몇 필드. 목록 상한 `ai.limits.list-cap`(50). 비밀값 절대 포함 금지.
- **무효화 힌트**: 새 WRITE/DESTRUCTIVE 툴은 `invalidates()`에 자기가 바꾼 화면 도메인을 선언한다(값은 `InvalidationDomains` 상수만 — 리터럴 금지). 빠뜨리면 `InvalidationContractTest`가 잡는다. FE는 성공한 툴의 `tool_result.invalidates`로 캐시를 버린다(계약 `../_workspace/features/ai/ai-assistant/contract_ai-invalidation.md`).
- **인증**: AI 서버는 자기 권한이 없다. `ToolContext`(쿠키·Bearer·x-visitor-id)를 BE에 그대로 넘긴다. 새 엔드포인트는 `AuthPreflight.require()`로 시작 — **채팅·툴 계열(`/ai/conversations`·`/ai/tools`·`/ai/actions`·`/ai/dev`)은 `requireAdmin()`**(설계 M6 관리자 전용). `/ai/health`만 인증 없이 열어 둔다(FE 진입점 판정). MCP(`mcp/**`)는 `user.mcp_permission`으로 통제되는 별개 축이라 requireAdmin을 걸지 않는다. 🔴 MCP엔 서버 측 확인 카드가 없다 → DESTRUCTIVE 툴은 `ai.mcp.allow-destructive`(기본 false)가 켜져야 노출·실행되고, 켜도 호출 1회 대상 수 상한이 걸린다(`McpServerConfig`, ZM-157). 새 DESTRUCTIVE 툴을 만들면 MCP에서 자동으로 빠진다는 뜻이다. 인증 성공은 5분 캐시라, 인증 뒤 MCP 호출 전체(데이터소스 사전 조회 포함)에서 BE 401이면 `McpServerConfig`가 `McpTokenValidator.evict()`로 캐시를 버린다. 폐기는 토큰별 세대를 올려 폐기 전에 시작한 조회가 캐시를 다시 채우지 못하게 한다(감지는 `be/BeAuthFailures` — 병렬로 BE를 부르는 툴을 만들면 그 스레드에서 직접 `record()`).
- **테스트 먼저**: `.\gradlew.bat test`(JAVA_HOME=JDK17). 서버 띄운 채로 test 돌리지 말 것(BE와 같은 함정: 클래스 재컴파일로 실행 중 JVM이 깨진다).
- **포트**: `application.yml`은 `${PORT:3100}`, `application-dev.yml`은 `${SERVER_PORT:${PORT:3100}}`(2026-09-07 — 이전엔 dev가 `3100` 하드코딩이라 `PORT=3101`을 줘도 3100으로 뜨려다 실패했다, P3 QA). 두 번째 인스턴스는 `PORT=3101`(또는 `SERVER_PORT=3101`) 하나면 된다. 🔴 dev yml에 포트를 다시 고정하지 말 것.
- **런타임 검증**: `SPRING_PROFILES_ACTIVE=dev` + `AI_DEV_TOOLS_ENDPOINT=true`(dev 툴 엔드포인트 — 확인 게이트 우회라 dev에서도 기본 off, ZM-157) + `INTERNAL_API_TOKEN`(BE .env와 동일)로 띄우고 `POST /ai/dev/tools/{name}`. 🔴 **한글이 든 본문을 Git Bash `curl -d`로 보내지 말 것**(cp949로 나가 400) — UTF-8 파일(`--data-binary @req.json`)이나 python urllib로. BE 세션은 계정당 1개라 다른 곳에서 로그인하면 `INVALID_TOKEN`이 난다(서버 결함 아님, 재로그인). 🔴 `gradlew --stop` 금지(같은 Gradle 버전 BE 데몬까지 죽음) — 환경변수 바꿔 띄울 땐 `bootRun --no-daemon`. Git Bash에선 `MSYS2_ENV_CONV_EXCL=INTERNAL_API_TOKEN`(값이 `/`로 시작하면 경로로 변환됨).
- **DB 마이그레이션**: 🔴 V7(`ai_insight` owner_key)은 구버전과 병행·코드만 롤백 불가 — 구버전 프로세스를 모두 내린 뒤 배포, 롤백은 README "DB 마이그레이션 배포 주의"의 SQL 후 구버전 기동. 유니크 키를 바꾸는 마이그레이션을 새로 쓸 때도 같은 점검(구버전 `ON CONFLICT`·조회가 새 스키마에서 도는가)을 한다.
- **MCP 연결 회수(ZM-157 A1)**: 동의 **승인 시점**에 BE 세대(`GET /internal/mcp/users/{id}/generation`)를 인가 코드에 고정하고(조회 실패 = 동의 실패), 코드 교환·갱신은 늘 그 세대를 `expectedGeneration`으로 보낸다. 연결의 `generation`(V8) = 코드의 세대. `MCP_GRANT_REVOKED`·세대 불일치·세대 없음(옛 코드/옛 연결/구버전 BE)은 실패로 닫는다(연결 폐기 또는 미생성 + `invalid_grant`). 🔴 연결 폐기는 **영구 거부 코드만**(`BeMcpTokenClient.PERMANENT_CODES`) — `FAILED_TO_ACQUIRE_LOCK`·BE 호출 실패는 연결·refresh·코드를 보존하고 503 `temporarily_unavailable`. 🔴 refresh 교체는 이전 해시 조건부 UPDATE(`rotateRefresh(id, previous)`, 0행 = `invalid_grant`) — 무조건 교체로 되돌리지 말 것. V8은 BE 선배포·구버전 AI 병행 금지(README 배포 절).
