# audit-trail — 워크로그·결재·인증 감사 이력

작성일: 2026-10-10. 근거: 사용자 요청(2026-10-10). 선행: `worklog-history`(구현됨), `worklog-certification-model`(백엔드 진행 중).

## 1. 사용자 요구 (원문 요지)

1. **워크포스와 연결된 워크로그**에 대해 "언제·누가·무엇을·어떻게 수정했는지" 이력이 남아야 한다.
2. "어떻게 수정됐는지"(수정 경로·방식)는 **검토가 필요** — 무엇을 알 수 있고 무엇을 알 수 없는지 먼저 정리한다.
3. **우리가 관리하는 워크로그의 감사**가 가능해야 한다(관리자가 기간·사람·프로젝트로 찾아보고 내보낼 수 있어야 함).
4. **누가·언제·무엇을 승인했는지** 이력도 확인할 수 있어야 한다(결재·인증 모두).

## 2. 현재 있는 것 (리더 확인, 2026-10-10)

- `worklog_history`(append-only): 변경 하나당 한 행. 언제(`changed_at`), 누가(`actor_account` — 앱 화면 쓰기는 호출자 확정, Jira 경로는 워크로그 `updateAuthor`, 삭제는 알 수 없음 NULL), 무엇을(일자·시간 이전→이후, 설명 지문+앞 40자 — 원문은 정책 `worklogHistoryKeepComment` 켤 때만, 공개 범위 지문), 경로(`source`: APP / JIRA / SWEEP). 감사 화면 `listWorklogHistory`(admin, 기간 ≤366일, 엑셀). 보관 12개월. 수집 범위 = 앱을 켠 프로젝트.
- `approval_event`: 요청별 REQUESTED/APPROVED/REJECTED/EXPIRED/CANCELLED + 감사 전용(CHANGED_AFTER_APPROVAL, CONSUMED, FIELD_APPLIED…). 행위자·대리인·시각·사유·내용 버전. 조회는 **요청 단위**(`getApprovalHistory`)뿐.
- 설정 변경 감사 `listSettingsAudit`(admin).
- 인증 모델(진행 중): `worklog_cert_batch`(인증자·대상·월·모드·PIN·정책·화면 지문), `worklog_cert_log`(재인증 전 판).

## 3. 빈 곳 (설계 대상)

- **조직 단위 결재 감사 조회가 없다.** "3월에 누가 무엇을 승인했나"를 기간·결재자·요청자·종류로 찾고 엑셀로 내보내는 화면·resolver 가 없다.
- **인증 감사 조회** — 인증 모델 테이블을 감사 화면에서 볼 경로.
- **워크로그 이력 범위 = "워크포스와 연결된 워크로그"** — 지금은 "앱 켠 프로젝트" 기준. 워크포스 연결 프로젝트(`rms.*` 검증 게시물/`movesRmsLink` 표식)와 범위를 맞춰야 하는지, 그 판정의 신뢰성(불변식 9 — 프로퍼티 불신, 서명 검증만).
- **"어떻게"의 한계** — Jira 이벤트는 화면/REST/자동화/모바일/다른 앱을 구분해 주지 않는다. 앱 화면(APP)과 그 밖(JIRA)만 확정 구분된다. 삭제 행위자는 알 수 없다. 이벤트 누락 시 스윕은 최종 상태만 보므로 중간 수정은 합쳐진다(횟수 과소). 설치 전 이력 없음. → 무엇을 더 얻을 수 있는지 조사(예: 감사 로그 REST `/rest/api/3/auditing/record` 는 워크로그를 다루는지, 이슈 changelog 의 `timespent`/`worklogId` 항목·author, 시간 추적 제공자 사용 시 기본 경로 차단 효과).
- **통합 감사 화면** — 워크로그 변경·결재 결정·인증을 한 타임라인(사람·워크로그·기간 축)으로 볼지, 탭으로 나눌지.
- 보관: 결재·인증 기록은 길게(결재 3년·인증 무기한), 워크로그 이력은 12개월 — 감사 요구 기간과 맞는지(정책값).

## 4. 완료 기준 (설계 단계)

- "어떻게 수정됐는지"에 대해 **알 수 있는 것 / 알 수 없는 것 / 추가로 얻을 방법(비용·권한·미검증)** 표.
- 결재·인증 감사 resolver 계약(admin 축, 기간 필수, 커서 페이징, 엑셀), 형제 resolver 범위(불변식 7).
- 워크포스 연결 워크로그 범위 판정 방식과 근거.
- 유휴 SQL 0 추가(AGENTS "유휴 비용") — 감사는 조회 시점 계산, 새 스케줄 없음.
- 용량·인덱스(감사 조회가 기간 범위 스캔이므로 `approval_event.occurred_at` 등 인덱스 필요 여부).
