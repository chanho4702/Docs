# 워크로그 승인 설정 운영 모드 분리

## 사용자 요구

- Approval 설정에서 Workforce 연동 모드와 일반 모드의 설정을 직관적으로 구분한다.
- Workforce 연동 모드에서는 Workforce에 연결된 이슈의 워크로그만 승인 대상이라는 점을 명확히 보여 준다.
- 현재 모드에서 승인 대상, 승인자 출처, Approval이 관리하는 정책을 혼동 없이 이해할 수 있어야 한다.
- 기존 저장값과 승인·잠금 동작은 유지하되, 실제 서버 판정이 위 범위와 다르면 함께 바로잡는다.

## 수용 기준

1. 화면 진입 즉시 현재 운영 모드와 승인 대상 범위를 확인할 수 있다.
2. 연동 모드는 Workforce 연결 이슈만 대상으로 표시하며 Workforce가 제공하는 정보와 Approval이 관리하는 정책을 구분한다.
3. 일반 모드는 Approval 단독 운영 범위와 승인자 선택 방식을 별도 문구로 설명한다.
4. 모드 전환 위치를 안내하되 이 화면에서 별도 상태값을 만들지 않는다.
5. 두 모드 모두 자동 승인 요청과 승인 기간 설정을 저장할 수 있다.
6. 연동 모드에서 미연결 이슈가 자동 승인 요청 대상이 되지 않는지 서버 구현과 테스트로 확인한다.
7. UI 테스트, 전체 테스트, UI 빌드, Forge lint, bundle check를 통과한다.

## 추가 요구 — 연동 모드 결재자 구성

- 연동 모드에서는 현재 사용자의 Workforce 팀장을 설정/결재자 안내에서 이름으로 확인할 수 있게 한다.
- 현재 사용자가 Workforce 팀장이라면 자기 워크로그의 승인자로 자기 자신을 선택하고 직접 승인할 수 있게 한다.
- 일반 사용자의 자기 승인은 계속 금지한다.
- 자동 요청은 기존 기본 팀장 흐름을 유지하되, 팀장 본인의 기록에는 본인을 유효한 기본 승인자로 사용할 수 있다.
- 자기 승인의 요청·결정도 기존 append-only 승인 이력과 감사 범위에 동일하게 남긴다.

## 제약

- 운영 모드의 단일 진실은 `workforceLinkEnabled`다.
- 기존 Atlaskit 기반 화면 문법과 공용 설정 컴포넌트를 재사용한다.
- 변경 커밋은 `#RFC-220 [TYPE] 이유 - YYYY-MM-DD` 형식을 사용한다.
