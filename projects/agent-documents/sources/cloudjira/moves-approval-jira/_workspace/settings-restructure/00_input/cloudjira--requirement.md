# 요구 — 설정 화면 재구성 (settings-restructure)

작성: 2026-10-12 (리더). 사용자 원문: "설정쪽 ui ux가 너무 복잡함. 상태 승인 쪽이랑 워크로그 쪽이랑 분리좀 해주고 어느정도는 탭으로좀 분리좀 해줘."

## 문제
- 설정 좌측 메뉴가 **평평한 11개 항목**(전역 정책·적용 프로젝트·타임시트·워크로그 통제·워크포스 연동·결재선·승인 그룹·승인자·설정 관리자·감사·데이터 관리). 이슈(상태) 승인 설정과 워크로그·타임시트 설정이 섞여 있다.
- "타임시트" 한 화면에 정책(384줄)·인증·제공자 안내·기간 마감·팀 명부 **다섯 섹션이 세로로 쌓여** 있다.
- "전역 정책" 폼에 일반 결재 옵션(기한·알림·서명·위임·독촉·PIN·접근)과 **이슈 승인 전용 옵션**(전환 승인 켬·필드 변경 적용 대체·상태 표시명)이 한 폼에 섞여 있다.

## 요구
1. 메뉴를 **묶음(그룹)** 으로 나눈다: 일반 / 이슈 승인 / 워크로그·타임시트 / 기록.
2. 이슈 승인 쪽(결재선·승인 그룹·승인자 + 이슈 승인 정책)과 워크로그 쪽(타임시트·워크로그 통제·워크포스 연동)을 **다른 묶음**에 둔다.
3. 큰 화면은 **탭**으로 나눈다: 타임시트(정책/인증/기간 마감/팀), 이슈 승인(정책/결재선/승인 그룹/승인자).
4. 전역 정책 폼에서 이슈 승인 전용 항목을 **이슈 승인 > 정책 탭**으로 옮긴다(저장은 부분 patch — `saveApprovalSettings` 가 이미 부분 갱신).
5. 옛 링크(`setting=flows|groups|approvers|worklogHistory`)는 **깨지지 않게** 새 위치로 정규화한다.

## 완료 기준
- 설정 엔트리(adminPage)와 업무함 사이드바(설정 하위 메뉴) **둘 다** 같은 묶음·항목을 보인다.
- 기존 기능·resolver 호출·쿼리키 변경 없음. 백엔드 변경 없음.
- 프론트 jest 전부 통과, `npm run build`(craco) 성공, `npm run merge`(locales) 성공.
- `PolicyFallback.test.jsx`·`InboxPage.test.jsx`·`AuditTrail.test.jsx` 등 기존 테스트는 새 구조에 맞게 갱신(동작 계약은 유지).

## 범위 밖
- 각 섹션 내부 폼의 UX 개선(필드 재배치·문구 개선)은 하지 않는다. 이동만 한다.
- 프로젝트 설정 엔트리(`projectSettings`)는 건드리지 않는다.
- 백엔드·manifest·스키마 변경 없음.
