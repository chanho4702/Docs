# 요구 — "사용할 기능" 선택 + 라벨 평문화 (feature-selection)

작성: 2026-10-12 (리더). 사용자 결정: **끔 = 신규 접수만 중지**(진행 중 결재·기록·잠금·복구는 유지). 코덱스 독립 검토 `codex-review.md` 의 최소안을 채택한다.
전제: 오늘 미커밋 작업(settings-restructure · operating-mode · settings-design) 위에서 작업한다.

## 사용자 문제
"설정이 어렵고 말도 어렵다. 단독이면 워크로그 승인·상태 변경 승인을 둘 다 또는 하나만 쓸 수 있고, 프로젝트를 골라 적용하고, 워크포스 연동하면 워크포스 팀장이 승인한다 — 복잡하지 않나?"
→ 원인: 제품의 선택(어떤 기능을 쓰나 / 어느 프로젝트에 / 결재자 원천)이 설정 어디에도 "선택"으로 보이지 않고, 라벨이 개발자 말이다.

## 요구
1. **정책 키 2개 신설**: `issueApprovalEnabled`(이슈 일반·상태 변경·필드 변경 승인의 **신규 요청** 접수), `timesheetApprovalEnabled`(타임시트 **신규 제출·재제출** 접수). **기본값 둘 다 true**(기존 설치가 갑자기 꺼지지 않게). 판정은 각각 Repository 의 단일 함수(운영 모드와 같은 방식 — 직접 `getValue` + `=== false` 금지).
2. **끔의 정의 = 신규 접수 중지**. 서버가 막는 경로는 설계서가 코드 전수로 확정하되, 최소한:
   - 이슈 승인 끔: 일반 승인 신규 요청(`ApprovalService.createForTarget` 경계), 전환 승인 요청·validator 는 **통과**(강제 없음) + 자동 전환 실행 중지(이미 POST 한 결과 대조는 계속), 필드 변경 승인 신규 요청. **별도 판정 코드·감사 action** 으로 비상 해제(`transitionApprovalEnabled`)와 구별.
   - 타임시트 끔: `submitTimesheet`(신규·재제출) + 공통 `createForTarget` 의 TIMESHEET 생성. `decide*`·`cancel`·읽기·팀 명부·기간 마감/재개·drift·게시·인증·통제·시간 추적 제공자 화면은 **그대로**.
   - 공통 결재 경로에 강한 차단을 넣지 않는다(`beforeDecide` 예외가 삼켜지는 구조 — codex §타임시트 끔 표 하단).
3. **비상 스위치 분리**: `transitionApprovalEnabled` 는 의미 그대로 두고 이슈 승인 > 정책 탭 맨 아래 "비상 해제" 섹션으로. 끌 때 확인 모달("승인 없이 상태 변경이 허용됩니다. 저장된 규칙은 유지되며 다시 켜면 즉시 강제됩니다"). 꺼져 있으면 이슈 승인 메뉴 항목에 경고 배지.
4. **설정 첫 화면 = "사용할 기능"**(설정 > 일반 맨 위, 기본 진입). 세 선택을 평문으로:
   - 이슈 승인 사용 — "일반 승인, 상태 변경 승인, 필드 변경 요청에 사용합니다. 적용 프로젝트는 아래에서 고릅니다."
   - 기간별 작업 시간 승인 사용 — "사람별 주·월 기록을 제출하고 승인받습니다. 여러 프로젝트의 시간이 포함됩니다."
   - 워크포스 연동 사용 — 기존 `workforceLinkEnabled` 토글을 **여기서도** 보여 준다(원천은 워크포스 연동 페이지와 같은 키, 같은 쿼리 캐시). 설명: "검증된 워크포스 팀장 정보를 우선 쓰고, 없으면 이 앱의 팀 명부를 씁니다. 점검 기준·인증 결과·통제도 함께 연동됩니다." + 현재 연결 상태 한 줄.
   - 각 항목 아래 "현재 상태" 요약(적용 프로젝트 수 / 팀 수 / 연동 상태)과 해당 설정으로 가는 링크.
5. **메뉴 접기 규칙**(운영 모드와 일관): 끈 기능의 묶음은 **이름과 "사용 안 함" 배지를 남기고 세부 항목만 접는다.** 결재선·승인 그룹·승인자는 **공용**이라 "일반" 묶음(또는 새 "결재 구성" 항목)으로 옮긴다. 통제 해제·기간 재개·감사·데이터는 항상 보인다. 기능 상태를 모르면 전부 보인다.
6. **업무함·일반 사용자**: 끈 기능의 신규 제출·요청 버튼은 숨기고 기존 요청·기록은 열린다. 비관리자 화면은 **관리자 전용 `getApprovalSettings` 를 부르지 않는다** — 기존 SELF 맥락 응답(예: `getTimesheetContext`, 업무함 부트스트랩 응답)에 기능 boolean 을 추가한다.
7. **라벨 평문화**: codex §라벨 15 의 대체 문구를 kr 에 반영, en 도 같은 뜻으로. 9번("제출·승인된 기간의 작업 로그 입력 잠금")은 도움말에 "승인된 기간은 항상 잠깁니다" 추가. 11·12·10번의 영향 설명은 확인 화면에 유지.
8. 감사: 기능 켬/끔은 `policy/update` 와 구별되는 action(예: `feature/toggle`)으로 기록.
