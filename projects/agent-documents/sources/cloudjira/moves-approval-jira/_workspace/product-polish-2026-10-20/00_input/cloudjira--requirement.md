## 완료 기준

### A. 상태 변경 승인
1. 관리자가 **기능 선택**에서 "상태 변경 승인"을 켤 수 있다(기본 꺼짐). 끄면 신규 요청만 막히고 validator 는 통과(강제 해제)한다.
2. 프로젝트 관리자가 **Jira 프로젝트 설정 > Moves Approval** 에서 규칙(이슈 유형 × 목적 상태 × 결재선)을 만들고, 같은 화면에서 워크플로 validator 부착 안내를 본다.
3. 규칙이 걸린 이슈에서만 이슈 우측 요약(issueContext)에 "상태 변경 승인" 칸이 따로 보이고, ••• 메뉴 "Request status change approval" 로 요청할 수 있다. 규칙이 없는 이슈에는 아무 것도 늘지 않는다(워크로그 화면 무변화).
4. 결재 → 최종 승인 시 요청자 권한으로 자동 전환(기존 TransitionExecutor). 자동 적용이 막히면 요청자가 직접 전환할 수 있고 validator 가 승인을 알아본다.
5. 업무함 종류 필터·결재·일괄 승인·상세·증명서·감사 이력에 "상태 변경 승인"이 워크로그 승인과 구분된 이름·배지로 나온다.
6. 기능 끔 상태에서 이슈 화면 로드가 SQL·Jira 호출을 늘리지 않는다(KVS 1회 이내).

### B. 모드 구분
1. 화면별 모드 규칙 표가 설계서에 있고 그대로 구현된다.
2. 단독 모드에서 워크포스·연동 문구가 보이는 곳이 0(워크포스 연동 설정 화면의 "켜기" 안내 제외).
3. 연동 모드에서 워크포스가 원장인 값(팀·팀장, 연동 이슈 작성 기간·사전 승인·결재선)은 승인 앱 화면에서 읽기 전용 + "워크포스에서 변경" 안내.
4. 모드를 모를 때(로딩·오류)의 처리가 한 규칙(전부 표시 + 경고 없음)으로 통일.

### C. 디자인·타이포
1. 타이포 규칙 1장(토큰 대응표)이 설계서에 있고 공용 컴포넌트로 강제된다.
2. 대상 파일의 하드코딩 `fontSize`·`fontWeight`·px 여백이 토큰으로 바뀐다(예외는 목록으로).
3. 화면 동작·testId·쿼리키 무변경. 기존 UI 테스트 통과.
