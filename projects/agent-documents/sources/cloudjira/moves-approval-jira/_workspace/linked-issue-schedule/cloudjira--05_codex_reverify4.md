1. **P1 — N2 추가 반례: 연속 재생으로 이미 적용한 제한이 사라질 수 있다.**
   - 근거: [설계 §5.3.1](C:/CloudJira/moves-approval-jira/_workspace/linked-issue-schedule/01_architect_design.md:326)은 `divergedBody` 하나에 Jira 문서를 넣고 저장본과 비교한다. 기존 [수신 코드](C:/CloudJira/moves-approval-jira/src/resolver/workforce/WorkforceInbound.js:85)는 최고 rev만 보존하며 충돌 제한을 누적하지 않는다.
   - 재현: 저장본 `rev=300, NOT_REQUIRED` → 재생 `rev=200, REQUIRED`로 제한 → 다음 갱신 때 `rev=100, NOT_REQUIRED`로 `divergedBody`를 교체하면 다시 허용된다. 모두 유효한 과거 서명 문서여도 가능하다.
   - 필요한 계약: **더 높은 rev를 정상 수신하기 전까지 기존 충돌 제한과 새 충돌 제한을 누적 병합**한다. 1시간 쓰기 생략도 이번 호출의 제한 판정을 생략해서는 안 된다. A48에 세 문서 연속 수신을 추가해야 한다.

2. **P1 — 감사 저장 실패가 새 제한의 집행을 우회한다.**
   - 근거: [설계 §5.3.3](C:/CloudJira/moves-approval-jira/_workspace/linked-issue-schedule/01_architect_design.md:344)은 감사 INSERT 실패 시 “그 호출의 판정은 기존 저장본으로”라고 명시한다.
   - 재현: 기존 저장본은 기간 제한 없음·사전 승인 불필요 → 팀장이 제한 문서 게시 → 쓰기나 제출에서 새 문서 검증 성공 → 감사 INSERT 실패 → 이전 허용값으로 작성·제출 진행.
   - 감사 선기록 순서는 유지하되, **검증된 변경을 저장하지 못한 쓰기·제출은 실패로 끝내야 한다.** 미리보기는 미해결 경고를 반환할 수 있다. 단순 재시도 테스트로는 명시된 허용 경로가 닫히지 않는다.

구현 시 확인: A46의 만료·역조회·상위자 판정, A47의 1,001건 이상 수렴, A49의 해제 후 재수신, A50의 최초 제출·검색 누락·숨김 보충 이슈 처리, W16′의 모든 생성 경로 서버 차단. 이 항목들은 착수를 막지 않는다.

P2: §4.2 첫 정의의 “후손 팀”과 §17.1 되돌리기의 “`ch`가 빠진다”를 최종 직속·명시적 `ch:'WORKFORCE'` 계약에 맞춰 정리한다.
