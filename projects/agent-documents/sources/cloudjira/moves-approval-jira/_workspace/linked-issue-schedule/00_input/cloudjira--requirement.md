# linked-issue-schedule — 연동 모드: 워크포스가 관리하는 작업의 이슈별 기간·사전승인 + 입력 화면 단일화 + 인원 구조 동기화

작성일: 2026-10-12. 근거: 사용자 결정(이 날 대화). 선행: worklog-control, schedule-window-fields(01_architect_design.md), worklog-policy-hierarchy, audit-retention-sync.

## 1. 사용자 결정 (확정)

1. **이슈별 설정은 워크포스에서.** 워크포스 "작업관리" 하위 탭 페이지를 새로 만들어, 워크포스가 관리하는 작업(연동 이슈)에 대해
   - (a) 작성 가능 기간: 시작일~종료일
   - (b) 사전 승인 필요 여부
   두 가지만 정한다. **워크포스 팀장 권한으로만** 편집. 작업 목록을 보며 여러 건을 한 번에 정할 수 있게.
2. **판정 원천은 승인 앱 하나.** 워크포스는 값을 서명(moves-link, 키는 이미 등록됨: ap-/wf- dev·stg)해 넘기고, 승인 앱은 서명 검증 후 자기 DB 에 저장해 생성·수정·삭제 판정에 쓴다(불변식 9). Jira 프로퍼티를 위조해도 무시.
3. **승인 앱의 "Jira 이슈 재정의" 계층 제거.** 사이트 기본 + Jira 프로젝트 예외 + (연동 이슈) 워크포스 이슈 설정으로 단순화. 이슈 정책 패널은 작업 로그 탭에서 이미 뺐다(2026-10-12). 서버 쪽 이슈 override 판정·저장 API 제거, 기존 데이터는 보존·비활성(코덱스 검토 `_workspace` 밖, 대화 요약: 작성 기한 대체 선행, WORKFORCE_ISSUE 연동 신호 유지, 과거 감사 증거 보존, 새 migration 으로 정리).
4. **연동 모드 입력 화면은 승인 앱 하나, 모양은 워크포스식.** 승인 앱 작업 로그 탭(연동 이슈)에 워크포스 패널과 같은 형태:
   - 상단 KPI 카드: 계획 작업량 · 투입 공수(MM/MD) · 내 몫 · 진행률 (계획·진행률·MM 환산 기준은 워크포스 DB 에만 → 워크포스가 서명해 보냄)
   - 입력: 날짜 · 시작 시간~종료 시간 · 코멘트 · 기록 (연속 입력 유지)
   - 최근 워크로그 목록
   워크포스 탭·마이워크·캘린더·기간 일괄 입력의 **연동 이슈 생성**은 승인 앱으로 넘긴다(수정·삭제는 이미 넘김). 미연동 이슈는 각자 그대로. 연동 확인 불가 시 직접 입력으로 자동 복귀 금지.
   현재는 반대로 승인 앱이 연동 이슈 생성 버튼을 숨기고 "워크포스 탭에서 기록"을 안내하며, 워크포스 생성 경로는 승인 앱의 기간 잠금·상한·사전승인 검사를 거치지 않는다(구멍).
5. **승인 구조는 워크포스 인원 구조를 따른다(연동 모드).** 팀·팀장·소속이 두 앱에서 동기화돼야 한다. 현재 승인 앱의 타임시트 결재선 routing source 에 WORKFORCE(워크포스 팀)/ROSTER(앱 팀 명부)가 있다 — 현황을 조사하고, 연동 모드에서 워크포스 구조가 원천이 되도록 빈 곳을 메운다(팀장 = 이슈 설정 편집 권한자 = 타임시트 결재자가 같은 판정에서 나와야 함).

## 2. 제약
- AGENTS.md(두 리포) 규칙, 불변식 1~10, 유휴 SQL 예산(새 스케줄 금지, idleSqlBudget 테스트), resolver 3단계 등록, 서버는 문구 생성 금지.
- 계약 파일 7개는 두 리포 바이트 동일. 계약 확장 시 vectors.json·지문 갱신.
- 워크포스 DB 증가는 최소(워크포스 쪽 저장이 필요하면 근거 명시).
- 미검증 플랫폼 사항은 실측 관문으로 분리.
