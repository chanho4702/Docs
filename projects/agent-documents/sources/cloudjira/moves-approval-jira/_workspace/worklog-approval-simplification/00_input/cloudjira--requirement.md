# 워크로그 승인 중심 단순화

2026-10-13 사용자 요청. 이전 linked-mode-ux의 승인 앱 단일 입력 및 사이트 관리자 전용 정책 결정은 이번 요구로 대체한다.

- 연동 시 정상 입력 창구는 Jira 이슈 패널 또는 Workforce 앱이다. 중복 입력 패널을 정리하며 두 진입점은 같은 검증·출처 증명·승인·잠금 계약을 따른다.
- 이미 작성한 워크로그별 승인 요청을 제공한다. 직접 요청하지 않은 정상 입력 건은 정책에 따라 자동으로 승인 요청으로 누적한다. 승인자는 일괄 승인할 수 있다.
- 승인월 진행 중 통계를 제공하고, 승인월 마감 후 통계는 승인된 워크로그만 포함한다. 건별 목록은 미승인분도 상태와 함께 표시한다.
- 연동 프로젝트 팀장은 연결된 이슈 워크로그의 정책을 설정한다. 단독 모드 정책도 지원한다. 승인월 이후 추가 입력·변경을 거부하고 승인 완료된 워크로그의 수정·삭제를 막는다. 사용자에게 사유를 포함한 소명·재승인 요청 경로를 제공한다.
- 정상 경로 입력 증명과 승인 여부를 구분한다. 승인/마감 잠금 판단은 Approval DB에서 수행한다. 재승인 요청 자체가 승인 잠금을 해제해서는 안 된다.
- 누가 언제 무엇을 승인/반려했는지와 반려 사유를 표시한다. Workforce 관리 이슈의 워크로그 생성·수정·삭제 이력을 필터링해 제공하고 Workforce에서도 볼 수 있게 한다.
- 이슈 패널은 입력, 목록·상태, 승인·반려·변경 이력, 승인 요청 중심으로 단순화한다.
- 연동 기본 승인자는 본인이 속한 팀장이다. 직접 요청할 때는 승인자를 선택할 수 있어야 하며 팀장 없는 경우도 지원한다.
- 상태 변경 승인 코드는 보존하되 기능에서 제외한다. 워크로그 승인만 사용자 흐름에 노출한다.

## 진행 및 검증

- 현재 작업 트리는 시작 시 깨끗함.
- Approval과 Workforce 코드를 확인하고 실제 서버 계약을 먼저 확정한다. Workforce는 `C:\CloudJira\moves-workforce`이며 쓰기 범위 밖 수정은 승인된 실행으로만 한다.
- 사용자 요청에 없는 배포·커밋·푸시는 하지 않는다.
- resolver 권한·소유자·조건부 결정·서명·신규 테이블 readiness·쿼리키·유휴 비용 불변식을 지킨다.
- 모든 에이전트가 작업을 마친 다음 리더가 필수 전체 테스트·check:bundle·UI 빌드·forge lint를 실행한다.
- shell 기본 실행은 sandbox 초기화 오류(helper_unknown_error)로 실패 중이며 require_escalated 실행은 가능했다.

## 설계 기본값 (사용자 비동기 질문 제출, 답변 전 적용)

- 자동 접수: 정상 경로 저장 직후 팀장에게 자동 요청. 팀장이 없으면 승인자 선택 필요 상태를 명시하며 무단 자기 승인은 하지 않는다.
- 마감: 기존 월별 승인 마감일을 재사용한다. 마감 후 소명·재승인 접수는 허용하되 기존 기록의 잠금은 유지한다.
- 자동 요청이 이미 생성된 경우에도 아직 결정되지 않은 요청의 승인자를 직접 선택할 수 있는 경로를 보장한다.

## 사용자 추가 지시: Approval UI·UX

사용자가 작업 중 "어프로벌 ui ux 신경 써야한다"고 강조했다. 화면 품질은 필수 완료 기준이다.

- 기존 Jira/Atlaskit 디자인 체계를 유지하고, 업무형 미니멀 화면으로 구성한다. 외부 폰트·장식·새 UI 라이브러리를 추가하지 않는다.
- 이슈 화면은 입력 → 목록·승인 상태 → 상세 이력 순서로 읽히게 한다. 입력기·같은 안내·같은 승인 동작을 중복 배치하지 않는다.
- 승인 대기·승인·반려·소명 중과 수정 불가 이유를 명시한다. 색상만으로 상태를 전달하지 않는다.
- 주 동작은 한눈에 보이도록 우선순위를 두고, 팀장 기본값과 승인자 변경은 같은 요청 흐름에 둔다.
- 승인자 목록은 다중 선택·일괄 승인과 건별 실패·부분 성공을 명확히 보여준다.
- 로딩·빈 목록·오류·저장 성공·자동 접수 지연·팀장 부재 상태에 다음 행동을 제공한다. 중복 제출을 방지한다.
- iframe 폭·하단 잘림·모달 높이·키보드 조작·접근 가능한 label을 확인한다.
- 상태 변경 승인·복잡한 인증·사전 승인 설정은 기본 사용자 흐름에서 제외한다.
- `frontend-design` 스킬과 저장소 `forge-frontend-dev`를 함께 적용한다. 서버의 실제 응답을 소비하고 화면에서 승인 권한을 추정하지 않는다.
