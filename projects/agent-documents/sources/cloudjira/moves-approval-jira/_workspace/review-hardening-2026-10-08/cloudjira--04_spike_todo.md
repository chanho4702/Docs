# 실제 환경에서 남은 확인

로컬 테스트로 확인할 수 없는 항목이다. 이번 작업에서 개발 사이트 배포·설치·자료 삭제는 하지 않는다.

| 항목 | 확인 방법 | 판정 기준 |
|---|---|---|
| v046~v048 Forge SQL 마이그레이션 | 개발 환경에서 마이그레이션 적용과 readiness 조회, PIN 동시 요청, 세션 CAS 수행 | 기존 마이그레이션 이름 불변, 새 컬럼·테이블 확인, 경합 시 한 소유자만 갱신 |
| 내보내기와 현재 Jira 권한 | 관리자가 일부 이슈 열람 권한만 가진 조건에서 승인 export/purge 호출, TIMESHEET 팀·참여 범위 변경 | 볼 수 없는 승인 원문과 삭제 허가 제외. 이력 Q73 마스킹 정책 별도 유지 |
| 대량 후보의 실행 예산 | 만료·이미 보낸 알림·정책 제외 행이 앞에 있는 대량 자료로 daily/5분 continuation 수행 | 처리 후 cursor 저장, 미완주 이어받기, 하위 SQL/Jira 지연 시 실제 실행 제한 초과 여부 측정 |
| 필드 결과 불명확 | PUT 응답을 타임아웃으로 만들고 현재 값을 원래 값으로 되돌린 뒤 다시 적용 요청 | UNKNOWN/기존 TIMEOUT에서 추가 PUT 없음. 실제 결과 해소는 별도 절차로 남음 |
| 부분 자식 삭제와 생산자 경쟁 | 자식 정리 중 실패·동시 변경·권한 변경을 주입하고 같은 허가로 재개 | 부모 세대와 현재 권한 보호. 조회 후 자식 변경을 완전히 fencing하지 못하는 경로 기록 |
| 워크로그 영구 장애 페이지 | 같은 원본 페이지를 25회 이상 실패시킨 뒤 정상화 | 원본 cursor/watermark 보존 및 복구. 실패 ID 영속 큐는 별도 설계 |
| 집계·내보내기 호출 비용 | 참여 요청·이력 규모별 SQL 수, Jira 권한 조회 수, 응답 시간 수집 | 권한 범위 유지, incomplete 하한 표시, 예산 내 처리량과 정체 여부 확인 |

재개한 키셋보다 앞에 새 후보가 생기면 현재 주기 완료 후 다음 원점 스캔에서 처리한다. 이 지연을 즉시 처리와 혼동하지 않는다.
