# workforce-approval-display — 요구서 (2026-10-14)

## 사용자 요구 (원문 요지)
"워크포스도 워크로그를 표시하는 곳(캘린더·마이워크·기타 집계 장소)에는 이 워크로그가 승인됐는지 안 됐는지 보여 줘야 한다.
그리고 한 달 단위로 끊어서, 이번 달은 승인 안 된 것과 같이 통계 내다가, 이번 달이 지나 다음 달이 되면 지난달은 승인된 것만 집계."

## 현황 (리더 확인)
- 판정 원천: 워크포스 `src/integration/approval/worklogApproval.js` `approvalOfWorklog` — 승인 앱이 게시한 사용자×월 문서(`movesApproval.cert.{YYYY-MM}`)의 entries 로 상태·`countableSeconds` 계산.
  현재 집계 규칙: `normalOrigin && (approved || (matched && !closed))` — **closed 는 `closeAt`(승인 앱 자동 마감 일수 또는 수동 마감)** 기준. 자동 마감 0(개발 사이트 현재값)이면 지난달 미승인분이 계속 집계됨 → 요구 위반.
- 적용 경로(서버): `applyWorklogApproval`(협업 캘린더·프로젝트 캘린더·협업 워크로그·리소스 워크로그), `withCertBadges`(마이워크·리소스 분석), `certifyCostRows`(원가).
- 배지(UI): `WorklogApprovalBadge` 는 MyIssueTable·ResourceAnalysisChart·WorklogHistoryList 에만. 캘린더(ProjectCalender·협업)·MyLogSummary·WorklogPage·MyWorklogPanel·ScheduleModal·팀 분석 등은 미확인/없음.
- CLAUDE.md 확정 결정: "워크포스 표시: 전부 표시 + 상태 배지, 원가·정산만 '승인분만'"(10-03), "승인월 진행 중 통계와 마감 후 승인분 통계를 구분. 건별 목록에는 미승인분도 상태와 함께 표시"(10-13).

## 요구
R1 **표시**: 워크포스에서 워크로그를 개별로 보여 주는 모든 화면(캘린더 셀·일정 블록·마이워크 표/요약/모달·워크로그 페이지·마이페이지 패널·프로젝트 상세 작업·리소스/팀 분석 상세·원가 근거 목록 등 — 설계가 전수 조사)에 승인 상태(승인됨·승인 대기·요청 전·반려·변경됨·마감)를 같은 컴포넌트로 표시. 미승인분도 숨기지 않는다. 연동 이슈가 아니거나 연동 모드가 아니면 표시하지 않음(기존 규칙).
R2 **월 경계 집계**: 집계(합계·차트·통계·원가·정산)의 포함 규칙을 "**작업 시작일이 속한 월(사이트 타임존, 승인 앱 `wr`/ctl 의 tz 또는 문서 tz)이 현재 월이면 미승인 포함, 지난 월이면 승인분만**"으로 바꾼다. 승인 앱 마감(`closeAt`)은 잠금(수정 차단)에만 쓰고 집계 포함 판정에서는 월 경계를 우선한다(마감이 월말보다 빨라도 이번 달은 미승인 포함인지, 늦어도 지난달은 승인분만인지 — 설계가 명시). 원가·정산은 기존 결정대로 항상 승인분만인지 확인해 유지.
R3 **집계 화면 안내**: 집계 화면에 "이번 달: 미승인 포함 / 지난달: 승인분만" 을 한 줄로 표시하고, 지난달 미승인 시간이 빠졌으면 "제외된 미승인 X시간" 을 보여 준다(사용자가 숫자가 왜 줄었는지 알 수 있게).
R4 **두 앱 일관성**: 승인 앱 쪽 "승인월 진행 중 통계 / 마감 후 승인분 통계"(내 타임시트·팀장 화면) 규칙이 같은 월 경계를 쓰는지 확인하고, 다르면 맞춘다(설계가 판단, 승인 앱 변경은 최소).

## 범위 밖

- 승인 앱의 마감·잠금 규칙 자체 변경.
