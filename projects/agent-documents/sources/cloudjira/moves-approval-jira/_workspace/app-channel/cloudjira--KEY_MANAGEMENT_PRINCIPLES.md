# 앱 간 통신 키·연결 관리 원칙 (내부)

| 항목 | 내용 |
|---|---|
| 대상 | 승인 앱(moves-approval-jira) ↔ 워크포스(moves-workforce) Web Trigger 채널의 서명 키, 공개키 목록, Web Trigger 주소, 연결 코드 |
| 작성일 | 2026-10-19 |
| 성격 | 내부 운영 원칙. 고객에게 배포하지 않는다(고객용 설명은 `ED25519_SELF_AUTH_CUSTOMER.md`) |
| 사고가 나면 | `KEY_INCIDENT_RUNBOOK.md` 를 연다 |
| 근거 코드 | `src/integration/channel/keyring.js`, `scripts/workforce-link/gen-key.mjs`, `src/resolver/channel/` |

---

## 1. 한 줄 원칙

**비밀은 앱마다 서명 키(seed) 하나뿐이고, 그 키는 생성한 사람의 터미널에서 Forge 암호화 환경 변수로 곧장 들어가 다른 어디에도 남지 않는다.** 나머지(공개키, 주소, 연결 코드)는 비밀이 아니지만 함부로 퍼뜨리지 않는다.

---

## 2. 관리 대상과 등급

| 자산 | 등급 | 보관 위치 | 접근 가능한 사람 | 유출 시 영향 |
|---|---|---|---|---|
| 서명 키 seed (`MOVES_LINK_SIGNING_KEY`) | **비밀** | 각 앱 Forge 환경 변수(`--encrypt`), 환경별 | 해당 Forge 앱의 기여자(배포 권한자) | **해당 계열 키를 쓰는 모든 고객 사이트**에서 사용자 사칭 요청 가능(조회 범위는 요청자 권한으로 제한, 승인·반려·삭제 불가) |
| 키 이름 (`MOVES_LINK_SIGNING_KID`) | 공개 | 각 앱 Forge 환경 변수 | 기여자 | 없음 |
| 신뢰 키 목록 (`MOVES_LINK_TRUSTED_KIDS`) | 공개 | 각 앱 Forge 환경 변수 | 기여자 | 없음. 잘못 설정하면 연동 중단 또는 개발 키 수용 |
| 공개키 목록 (`keyring.js`) | 공개 | 두 리포 소스(공유 파일, 원본은 승인 앱) | 리포 접근자 | 없음 |
| Web Trigger 주소 | 내부 | 각 고객 사이트 앱 저장소(KVS `link:channel`), 연결 코드 | 해당 사이트 관리자, 앱 | 데이터 노출 없음. 호출 폭주로 그 사이트의 설치 단위 호출 한도 소모 가능 |
| 연결 코드 (`MLNK1.…`) | 내부(30분) | 고객 관리자 화면, 관리자 간 전달 경로 | 두 앱 관리자 | 30분 안에 다른 사람이 먼저 붙여 넣으면 잘못된 연결 가능(같은 사이트 앱만 가능) |
| 외부 API용 OAuth 클라이언트 비밀 | **비밀** | 연동 담당자 시스템 | 연동 담당자 | 해당 OAuth 앱으로 토큰 발급 가능 |

> **주의:** Forge 의 `--encrypt` 는 `forge variables list` 출력에서 값을 숨길 뿐이고, 앱 실행 환경에는 원래 값으로 전달된다. 따라서 **배포 권한이 있는 사람은 코드를 바꿔 배포해 seed 를 읽을 수 있다.** 기여자 = 키 접근자로 취급한다.

## 3. 원칙

### 3.1 생성·등록

| # | 원칙 | 이유 |
|---|---|---|
| P1 | 키는 **키 관리자(사람)** 가 `node scripts/workforce-link/gen-key.mjs <kid>` 로 만든다. AI 에이전트(Claude·Codex), CI, 자동화 스크립트는 키를 만들거나 seed 를 다루지 않는다 | 에이전트·CI 출력은 로그·대화 기록에 남는다 |
| P2 | seed 는 출력 즉시 `forge variables set --encrypt -e <env> MOVES_LINK_SIGNING_KEY <seed>` 로 넣고 터미널을 지운다. **파일·커밋·채팅·메신저·이슈·문서·스크린샷·클립보드 관리자 금지** | 복사본이 하나라도 남으면 회수할 수 없다 |
| P3 | 화면 공유·녹화 중에는 생성하지 않는다. 관리되는 업무용 PC 에서만 생성한다 | |
| P4 | kid 이름은 `{ap|wf}-{prd|stg|dev}-{번호}`. **한 번 쓴 kid 는 재사용하지 않는다**(폐기 후에도) | 감사 기록의 kid 가 키를 유일하게 가리켜야 한다 |
| P5 | 환경마다 다른 키. prd seed 는 production 환경에만, dev·stg seed 를 production 에 넣지 않는다 | dev 키는 개발자 PC 를 거친다 |
| P6 | 공개키는 승인 앱의 `keyring.js` 에 넣고 워크포스로 **바이트 그대로** 복사한다(`SHARED_READY.md` 해시 갱신). 두 앱을 모두 배포한다 | 한쪽만 배포하면 그 방향 연동이 끊긴다 |
| P7 | 등록 후 설정 > 워크포스 연동(워크포스는 승인 앱 연동) 화면의 **공개키 지문**을 `gen-key` 출력의 `fingerprint` 와 대조하고 키 대장(5장)에 적는다 | 엉뚱한 키가 배포되는 것을 막는다 |

### 3.2 신뢰 범위

| # | 원칙 |
|---|---|
| P8 | production 에는 `MOVES_LINK_TRUSTED_KIDS` 를 **설정하지 않는다**(미설정 = 키링의 prd 키만 신뢰). 교체·사고 때만 일시적으로 설정하고 끝나면 지운다 |
| P9 | development·staging 에서는 그 환경의 kid 를 `MOVES_LINK_TRUSTED_KIDS` 에 명시한다. production kid 를 개발 환경에서 신뢰하게 두지 않는다 |
| P10 | 폐기한 키는 키링에서 바로 지우지 않고 `notAfter` 를 폐기 시각(epoch ms)으로 둔다. 그 시각 이후 서명은 거부된다. 키 대장에는 폐기 사유를 남기고, 다음 정기 배포에서 정리한다 |

### 3.3 접근자

| # | 원칙 |
|---|---|
| P11 | Forge 앱 기여자(Developer console 의 앱 기여자)는 최소 인원으로 둔다. 키 관리자 정·부 2명 + 배포 담당자 |
| P12 | 기여자의 Atlassian 계정은 2단계 인증 필수 |
| P13 | 퇴사·역할 변경 시 **당일** 기여자에서 제거하고, 그 사람이 prd seed 를 다룬 적이 있으면 정기 교체를 앞당긴다 |
| P14 | 분기마다 기여자 목록을 키 대장 옆에 기록하고 검토한다 |

### 3.4 코드·로그

| # | 원칙 |
|---|---|
| P15 | 환경 변수 값을 응답·프론트엔드·로그·감사·오류 메시지로 내보내지 않는다. 코드 리뷰 체크 항목으로 둔다 |
| P16 | 로그·감사에 seed, 연결 코드 원문, pin 원문을 남기지 않는다(현재 설계: pin 은 해시만, 1~8단계 거부는 원문 없이 한 줄) |
| P17 | 감사 이벤트에는 `kid`·`linkId`·`op`·actor 를 남긴다(설계 §2.6 M5). 사고 조사는 이 값으로 한다 |
| P18 | 커밋 전 비밀 탐지(gitleaks 등)를 두 리포에 둔다 — **적용 예정** |

### 3.5 주소·연결 코드

| # | 원칙 |
|---|---|
| P19 | Web Trigger 주소는 티켓·문서·채팅·스크린샷에 넣지 않는다. 지원 중 필요하면 마지막 6자만 쓴다 |
| P20 | 고객 지원 중 주소나 연결 코드를 받았으면 사용 후 대화에서 지우고, 노출 범위가 불분명하면 고객 관리자에게 주소 바꾸기를 안내한다(대응 매뉴얼 C) |
| P21 | 연결 코드는 관리자 사이 1:1 경로로만 전달하고 30분 안에 쓴다. 공개 채널·공유 문서 금지(고객 안내문에 포함) |

### 3.6 정기 교체

| # | 원칙 |
|---|---|
| P22 | prd 키는 **정기 교체**한다. 주기는 결정 필요(제안: 12개월, 그리고 P13 사유 발생 시) |
| P23 | 교체 순서는 항상 ① 새 공개키를 두 앱 키링에 추가·배포 → ② 서명 앱의 seed·kid 를 새 것으로 바꾸고 배포 → ③ 옛 kid 에 `notAfter` 설정·배포 → ④ 다음 정기 배포에서 옛 kid 제거. 중간에 두 키를 함께 신뢰하므로 끊기지 않는다 |
