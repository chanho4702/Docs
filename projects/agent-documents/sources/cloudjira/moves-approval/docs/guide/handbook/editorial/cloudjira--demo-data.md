# 데모 데이터와 캡처 장면 대응

가이드 캡처(`image-plan.md`, MA-01~22)를 찍기 위한 staging 데모 데이터입니다. 편집자용 문서이며 고객 본문에 넣지 않습니다.

## 넣는 방법

설정 화면의 데모 버튼은 없앴습니다. 워크포스처럼 외부 시더 + 임시 웹트리거로 넣습니다.

1. `scripts/demo-seed/config.local.json`(gitignore)에 관리자 이메일과 **범위 없는 일반 API 토큰**을 넣습니다.
2. `manifest.yml` 에 `demo-seed-trigger` 웹트리거와 `demoSeed` 함수를 잠시 붙이고 staging 에 배포합니다(동적 응답이라 major, RoA 일시 해제 → `install --upgrade`).
3. `forge variables set --encrypt -e staging DEMO_SEED_SECRET <config 의 demoSecret>` 후 `forge webtrigger create -f demo-seed-trigger ...` 로 URL 을 config 에 넣습니다.
4. `node scripts/demo-seed/seed.js check` → `node scripts/demo-seed/seed.js all` (특정 시나리오만: `all delegated legalReview`).
5. 끝나면 manifest 를 되돌려 다시 배포하고(RoA 복구) `DEMO_SEED_SECRET` 을 지웁니다. 다시 넣을 일이 생기면 2~3을 반복합니다.

시더가 켜 두는 정책: 위임·서명·독촉·앱 내 알림. Confluence @멘션 댓글은 끕니다(실제 사용자에게 메일이 간다). `cleanup --yes` 는 만든 페이지를 휴지통으로 보냅니다(결재 기록은 남음).

2026-10-22 staging(`MADEMO` 스페이스)에 15개 시나리오를 넣었습니다. 결재자는 사이트 사용자 6명입니다.

## 지우기

데모 문서는 스페이스째 지우면 됩니다. 결재 기록은 Confluence 에서 사라진 페이지의 기록으로 남으며, 설정 → 데이터 관리의 보관 기간 정리로 내보낸 뒤 지울 수 있습니다. 승인 그룹·결재선·위임은 각 설정 화면에서 지웁니다.
