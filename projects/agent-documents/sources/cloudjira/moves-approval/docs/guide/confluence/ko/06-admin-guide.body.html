대상: Confluence 관리자, Moves Approval 설정 관리자

누가 설정할 수 있나요

역할 범위
Confluence 관리자 모든 설정. 항상 접근할 수 있으며 별도 등록이 필요 없습니다. 또한 다른 사람의 요청을 회수할 수 있습니다.
설정 관리자 Confluence 관리자와 같은 범위로 앱 설정을 관리합니다. 다른 설정 관리자를 추가·제거할 수 있습니다.

설정 화면은 Confluence 설정 → Moves Approval에 있습니다. 승인 업무함의 설정 링크로도 열 수 있습니다. 화면을 열 때마다 서버에서 권한을 다시 확인하므로, 권한이 없는 사람이 주소를 알아도 설정을 읽거나 바꿀 수 없습니다.

설정 화면은 8개 탭으로 되어 있습니다: 전역 정책, 적용 스페이스, 결재선, 승인 그룹, 승인자, 설정 관리자, 변경 이력, 데이터 관리.

전역 정책

새 요청의 기본값과 알림·보안 규칙입니다. 저장 즉시 적용됩니다.

설정 기본값 설명
기본 마감일수 7일 요청 폼의 마감일 기본값. 0이면 마감 없이 시작합니다. 요청자는 요청마다 바꿀 수 있습니다.
마감 임박 기준(시간) 24시간 마감까지 이 시간 이하로 남으면 요청자와 지금 차례인 승인자에게 마감 임박 알림을 한 번 보냅니다. 마감 확인은 하루 한 번이므로, 24시간보다 짧게 정해도 알림은 마감 24시간 전부터 갈 수 있습니다(화면 문구: "하루 한 번 확인하므로 24시간보다 짧게 정해도 최대 하루 전에 알립니다").
반려 사유 필수 켬 반려할 때 사유를 반드시 입력하게 합니다.
앱 내 알림 사용 켬 승인 업무함의 알림에 알림을 만듭니다.
Confluence 알림으로도 보내기 켬 대상 페이지에 관련자를 @멘션하는 댓글을 남깁니다. 알림 동작 참고.
결정 옆에 서명·도장 표시 켬 승인 순서표에 등록 서명 또는 이름 자동 도장을 표시합니다.
승인·반려 확정에 서명 PIN 요구 끔 켜면 모든 승인자가 내 서명에서 PIN을 등록해야 결정할 수 있습니다.
독촉 알림 보내기 끔 처리되지 않은 요청을 지금 차례인 승인자에게만 다시 알립니다.
첫 독촉까지(일) / 독촉 반복 주기(일) 3일 / 3일 독촉 알림이 켜졌을 때의 간격입니다.
승인 요청 시 문서 맨 위에 결재란 자동 추가 켬 요청 폼의 문서 맨 위에 결재란 추가 체크박스 기본값입니다. 요청자는 건별로 끌 수 있으며, 페이지 결재에만 적용됩니다. 결재란 참고.
결재 위임 허용 끔 사용자가 내 위임에서 대리인을 지정할 수 있게 합니다. 끄면 등록된 위임도 효력이 없습니다.
요청 시 승인자의 페이지 접근 권한 확인 켬 승인자 중 한 명이라도 대상 페이지를 볼 수 없으면 요청을 거절합니다. 진행 중인 요청에는 영향이 없습니다.
등록된 사용자만 앱 사용 끔 켜면 승인자 명부, 설정 관리자, Confluence 관리자만 승인 업무함과 요청 화면을 열 수 있습니다. 전역 전용입니다.
상태 표시명 (언어별 기본) 승인 대기·승인 완료·반려됨·만료됨·회수됨의 표시 이름. 전역 전용입니다.

상태 표시명

전역 정책의 상태 흐름도에서 상태를 눌러 표시 이름을 바꿉니다.

  • 비워 두면 각 사용자 언어의 기본 이름이 보입니다. 조직에서 정한 이름은 번역되지 않고 모든 언어에서 그대로 보입니다.
  • 이름만 바뀌고 승인 흐름은 바뀌지 않습니다. 진행 중의 세부 상태(예: 법무 검토 중)는 결재선의 단계 이름으로 표현하세요.

접근 제한을 켜기 전에

  1. 승인자 탭에 요청자와 승인자를 모두 등록합니다.
  2. 설정 관리자 탭에 운영 담당자를 등록합니다.
  3. 등록된 일반 사용자 계정으로 업무함·요청 화면이 열리는지 시험합니다.
  4. 그다음 등록된 사용자만 앱 사용을 켭니다.

등록되지 않은 사용자는 "이 앱은 등록된 사용자만 사용할 수 있습니다"를 보게 됩니다.

적용 스페이스

승인을 쓸 스페이스를 고르고, 스페이스별로 정책을 다르게 줄 수 있습니다.

  • 처음 상태 — 아무 스페이스도 켜지 않았다면 모든 스페이스에서 승인을 쓸 수 있습니다.
  • 하나라도 켜면 켠 스페이스에서만 새 요청과 영역 매크로를 쓸 수 있고, 나머지는 모두 꺼집니다.
  • 스페이스를 끄면 진행 중인 요청은 자동으로 종료되지 않습니다. 저장할 때 남은 건수가 경고로 표시되며, 그 요청들은 승인 업무함에서 계속 결정할 수 있습니다(페이지의 영역 표시는 사라집니다).

스페이스별 정책

스페이스 행의 정책 편집에서 그 스페이스만 다르게 적용할 항목을 켭니다. 켠 항목만 덮어쓰고, 나머지는 전역 정책을 따릅니다("전역을 따름 · 현재 7일"처럼 표시). 등록된 사용자만 앱 사용과 상태 표시명은 사이트 전체에 하나여야 하므로 스페이스별로 바꿀 수 없습니다.

예) 법무 스페이스만 마감 3일 + PIN 필수, 나머지는 전역 기본값. 결재란 자동 추가도 스페이스별로 켜고 끌 수 있습니다.

결재선

자주 쓰는 승인 순서를 미리 정의합니다. 요청 폼의 결재선 사용 탭에 나타납니다.

  • 이름(필수, 255자 이하), 설명(요청자에게 보임), 기본 마감일수(1~365일, 비우면 전역 기본값)
  • 결재 단계 — 요청 폼과 같은 편집기로 단계, 승인자, 승인 그룹, 필요한 승인 수, 단계 이름을 정합니다.
  • 적용 스페이스 — 고른 스페이스의 요청 폼에서만 보입니다. 비우면 모든 스페이스에서 보입니다.
  • 사용 스위치를 끄면 새 요청에서만 숨겨집니다.
  • 결재선을 수정·삭제해도 이미 만들어진 요청에는 영향이 없습니다. 요청은 만들어질 때의 결재선을 복사해 가집니다.

승인자

설정 관리자

Confluence 관리자가 아니어도 모든 승인 설정을 바꿀 수 있는 사람입니다. 이름을 두 글자 이상 입력해 찾고, 설정 관리자 저장을 누릅니다. 이미 Confluence 관리자인 사람은 등록할 필요가 없습니다.

변경 이력

전역 정책, 적용 스페이스, 결재선, 승인 그룹, 승인자, 설정 관리자의 변경과 데이터 관리의 보관 기간 변경·내보내기·삭제가 시각·사용자·영역·동작·내용과 함께 기록됩니다(데이터 관리 작업은 영역 "보관 기간", 동작 "변경"·"내보내기"·"정리"로 남습니다). 사용자가 이력을 수정하거나 지울 수는 없으며, 1년이 지나면 자동으로 정리됩니다. 더 오래 보관해야 한다면 주기적으로 화면을 기록해 두세요.

요청 단위의 결정 기록은 각 요청의 감사 타임라인과 버전별 승인 이력에 있습니다. 이 기록도 사용자가 수정할 수 없으며, 데이터 관리의 보관 정책에 따라 관리자가 내보낸 뒤 삭제할 때만 지워집니다.

데이터 관리

앱이 쓰는 저장 공간과 끝난 결재 기록의 보관을 관리합니다. Confluence 관리자와 설정 관리자가 사용할 수 있습니다.

저장 공간

  • 이 앱이 쓰고 있는 용량을 1 GiB 한도 대비 막대로 보여 줍니다("{사용량} / {한도} 사용 (N%)"). 80% 이상이면 주의, 90% 이상이면 위험으로 표시됩니다.
  • 한도를 넘으면 새 결재를 저장할 수 없습니다. 주의가 보이면 아래 결재 기록 보관으로 정리를 계획하세요.
  • 데이터 종류(테이블)별 크기·행 수(추정)·비중을 표로 보여 주며, 열 머리를 눌러 정렬할 수 있습니다. 크기·행 수는 데이터베이스 통계 기반 추정치라 실제와 조금 다를 수 있습니다. 새로 고침으로 다시 읽습니다.

결재 기록 보관

끝난 결재(승인·반려·만료·회수)를 얼마나 둘지 정합니다. 진행 중인 결재는 대상이 아닙니다.

  1. 보관 기간을 고릅니다 — 무기한, 1년, 3년(기본), 5년, 10년. 기간이 지난 기록 건수와 가장 오래된 기록의 날짜가 표시됩니다.
  2. 엑셀로 내보내기를 누릅니다. 기간이 지난 기록 전부가 결재 요청, 결재선, 이력 3개 시트의 엑셀 파일로 내려받아집니다. 파일이 실제로 내려받아진 뒤에만 내보낸 것으로 기록되며, "마지막 내보내기: {날짜} · N건 ({사용자})"로 표시됩니다.
  3. 파일을 보관한 뒤 내보낸 N건 삭제를 누르고, "정말 삭제할까요? 되돌릴 수 없습니다."에서 삭제를 한 번 더 누릅니다.
  • 마지막으로 내보낸 범위만 삭제됩니다. 엑셀로 내보내기 전에는 삭제할 수 없습니다("보관 기간이 지난 기록을 먼저 엑셀로 내보내야 삭제할 수 있습니다.").
  • 마지막 내보내기 이후 새로 보관 기간을 넘긴 기록이 있으면 "마지막 내보내기 이후 N건이 새로 기간을 넘겼습니다. 다시 내보내야 함께 삭제할 수 있습니다."가 표시됩니다.
  • 삭제한 요청의 결재선, 감사 이력, 업무함 항목, 관련 알림도 함께 지워집니다. 되돌릴 수 없으므로 내보낸 파일을 사내 기록 보관 규정에 맞게 먼저 보관하세요.
  • 보관 기간 변경, 내보내기, 삭제는 모두 변경 이력에 남습니다.
  • 끝난 결재 기록은 보관 기간이 지나도 자동으로 지워지지 않습니다. 위의 내보내기 후 삭제로만 지워집니다.

결재란

결재란은 페이지에 결재 단계·결재자·도장을 종이 결재판처럼 보여 주는 매크로입니다(편집기에서의 매크로 이름: Moves 결재란). 페이지 결재에 쓰이며, 영역 승인에서는 영역 패널 아래에 같은 결재란이 붙습니다.

  • 자동 추가 — 정책 승인 요청 시 문서 맨 위에 결재란 자동 추가가 켜져 있으면(기본 켬) 요청할 때 문서 맨 위에 결재란이 들어갑니다. 이미 결재란이 있으면 넣지 않습니다.
    • 요청자의 권한으로 페이지를 수정하므로 페이지 버전이 하나 오르고, 페이지 이력에 요청자가 "Moves Approval" 메시지와 함께 남습니다. 결재는 그 오른 버전을 기준으로 걸립니다.
    • 요청자에게 편집 권한이 없거나 그 사이 다른 사람이 저장해 넣지 못하더라도 요청은 결재란 없이 그대로 진행됩니다.
    • 앱이 페이지 본문을 쓰는 경우는 이것 하나뿐이며, 앱 자체 권한으로는 쓰지 않습니다.
  • 운영 팁 — 결재가 자주 필요한 문서는 Confluence 템플릿에 Moves 결재란 매크로를 미리 넣어 두세요. 처음부터 원하는 자리에 결재란이 있고, 요청할 때 결재란 때문에 페이지 버전이 따로 오르지 않습니다. 결재 요청이 아직 없는 문서에서는 결재란에 "아직 결재 요청이 없습니다."와 승인 요청 버튼(요청 권한이 있는 사람에게)이 보입니다.
  • 정책 결정 옆에 서명·도장 표시를 끄면 결재란에도 도장 대신 글자가 표시됩니다.

만료와 정기 처리

  • 마감 경과 만료, 마감 임박 알림, 독촉 알림, 오래된 알림·설정 변경 이력 정리는 하루 한 번 백그라운드 작업이 처리합니다. 실행 시각은 Atlassian 플랫폼이 정합니다.
  • 그래서 마감이 지난 요청이 목록에서 만료됨으로 정리되기까지 최대 하루가 걸릴 수 있습니다. 그동안 업무함과 승인 상세에는 기한 초과, 페이지 제목 아래 항목에는 "⌛ 기한 초과"로 표시됩니다.
  • 다만 마감이 지난 요청은 그 즉시 화면에서 결정 버튼이 사라지고, 결정을 시도하면 서버가 거절하면서 그 자리에서 만료시키므로 마감 이후의 승인은 생기지 않습니다. 마감이 지난 문서에 새로 요청하면 이전 요청은 자동으로 만료됩니다.
  • 마감 임박 알림은 기준을 24시간보다 짧게 정해도 마감 24시간 전부터 갈 수 있습니다. 독촉은 일 단위라 영향이 없습니다.

운영 점검 체크리스트

  • [ ] 적용 스페이스가 의도대로 켜져 있다.
  • [ ] 승인자가 대상 스페이스·페이지를 볼 수 있다.
  • [ ] 마감일수·마감 임박 기준·독촉 주기가 사내 규정과 맞다.
  • [ ] 접근 제한을 켰다면 요청자·승인자·설정 관리자를 먼저 등록했다.
  • [ ] 대표 결재선과 승인 그룹을 만들고 시험 요청을 끝까지 진행해 봤다.
  • [ ] 서명·PIN·위임·Confluence 알림의 사용 여부와 운영 규칙을 정했다.
  • [ ] 결재란 자동 추가를 쓸지 정하고, 자주 결재하는 문서의 템플릿에 결재란을 넣어 두었다.
  • [ ] 결재 기록 보관 기간이 사내 규정과 맞고, 저장 공간 사용량을 정기적으로 확인한다.
  • [ ] 변경 이력과 엑셀 내보내기를 정기적으로 검토한다.
