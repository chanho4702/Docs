# 7.8 권한 관리

## 접근 권한

| 구분 | 필요 권한 |
|---|---|
| 화면 조회 | 「권한 관리」 읽기 |
| 권한 세트 추가·수정·삭제 | 「권한 관리」 쓰기 |
| 프로젝트 데이터 범위 변경 | 「권한 관리」 쓰기 |

- **이 화면의 쓰기 권한은 다른 모든 권한을 부여할 수 있는 권한입니다.** 최소 인원에게만 주세요.
- 기본 시스템 세트(Admin / Member)는 **페이지 권한을 수정할 수 없고**, 프로젝트 조회 범위만 바꿀 수 있습니다.
- Jira 관리자 권한 세트의 프로젝트 범위는 변경할 수 없습니다.
- 세트를 사용자·팀에 **배정**할 때는 배정자 자신의 권한을 넘는 세트를 줄 수 없습니다(Jira 관리자·「권한 관리」 쓰기 보유자는 제한 없음). 자기 승격을 막기 위한 규칙입니다.

---

**언제 쓰나** — 권한 세트를 만들고 각 기능의 **읽기/쓰기**와 **프로젝트 조회 범위**를 정할 때.

![그림 7-10 권한 세트 편집](../images/07-permission-set.png)
*그림 7-10. 권한 세트 편집 — ① 세트 목록(시스템 세트·프리셋·커스텀) ② 항목별 읽기/쓰기 체크(워크포스 영역·설정 영역) ③ 항목 설명 ④ 프로젝트 데이터 범위(전체/소속 프로젝트만/내 팀만)와 경고.*

## 권한 세트 만들기

1. **권한 추가** → 권한 이름을 입력합니다 (예: super admin).
2. 항목별로 **읽기 / 쓰기** 를 체크합니다. **최소 하나 이상** 선택해야 합니다.
3. **프로젝트 데이터 범위**를 지정합니다.

> **읽기(Read)** 는 화면 조회, **쓰기(Write)** 는 생성·수정·삭제 권한입니다. 각 항목 아래에 그 권한이 제어하는 페이지·탭·기능 설명이 표시됩니다.

## 권한 항목

화면에는 **17개 항목**이 두 묶음으로 표시됩니다. 이 매뉴얼의 「 」 표기는 이 항목명을 그대로 씁니다.

**워크포스**

| 항목 | 제어 대상 |
|---|---|
| 프로젝트 관리 | 프로젝트 목록·상세(인력·작업·캘린더), 작업 관리의 목록·트리·간트·맵, 작업 이력(쓰기) |
| 대시보드 | 프로젝트 상세의 대시보드 탭 |
| 칸반 보드 | 칸반 보드 조회·드래그·컬럼 편집 |
| 리포트 | 작업·인력·팀·진척 분석 리포트, 통합 대시보드(쓰기 = 재집계), 대시보드의 분석 위젯 |
| 비용 | 급여 관리·비용 탭·총 인건비·비용 위젯 (재무 민감정보, **기본 비공개**) |
| 자원관리 | 자원 관리(부하·스킬 적합도·배정) |
| 워크로그 추출 | Jira 전체 워크로그 검색·Excel. 조회 범위는 Jira 권한을 따름 |

**설정**

| 항목 | 제어 대상 |
|---|---|
| 일반 설정 | 근무시간·MM 기준·가동률 밴드·급여 정책 |
| 인력 관리 | 인력 등록·수정·삭제·엑셀 업로드 |
| 팀 관리 | 조직 계층·팀 소속·팀장 지정 |
| 역할 관리 / 등급 관리 / 스킬 관리 | 역할·등급·스킬 기준정보 |
| 프로젝트 상태 관리 | 프로젝트 상태(칸반 컬럼)·흐름 |
| 휴일 관리 | 공휴일 |
| 권한 관리 | 권한 세트와 데이터 범위 |
| 저장공간 관리 | 저장 공간 사용 현황 |

> 목록에 없는 legacy 간트 권한은 숨겨져 있으며, 간트·트리·맵은 모두 「프로젝트 관리」 권한을 사용합니다.

### 항목명과 내부 키 대조표

[관리자 매뉴얼](../../cloudjira--Moves_Workforce_%EA%B4%80%EB%A6%AC%EC%9E%90_%EB%A7%A4%EB%89%B4%EC%96%BC.md)·개발 문서·서버 오류 메시지는 내부 키를 씁니다. 대응은 다음과 같습니다.

| 항목명 | 내부 키 | 항목명 | 내부 키 |
|---|---|---|---|
| 프로젝트 관리 | `PROJECT` | 일반 설정 | `SETTINGS` |
| 대시보드 | `DASHBOARD` | 인력 관리 | `USER_MANAGEMENT` |
| 칸반 보드 | `KANBAN` | 팀 관리 | `TEAM_MANAGEMENT` |
| 리포트 | `REPORT` | 역할 관리 | `ROLE_MANAGEMENT` |
| 비용 | `PROJECT_COST` | 등급 관리 | `LEVEL_MANAGEMENT` |
| 자원관리 | `RESOURCE_MANAGEMENT` | 스킬 관리 | `SKILL_MANAGEMENT` |
| 워크로그 추출 | `WORKLOG_EXPORT` | 프로젝트 상태 관리 | `PROJECT_STATUS_MANAGEMENT` |
| | | 휴일 관리 | `PUBLIC_HOLIDAY_MANAGEMENT` |
| | | 권한 관리 | `PERMISSION_MANAGEMENT` |
| | | 저장공간 관리 | `STORAGE_MONITORING` |

프로젝트 데이터 범위: 전체 프로젝트 = `ALL`, 소속 프로젝트만 = `MEMBER_ONLY`, 내 팀만 = `TEAM_ONLY`.

## 기본 제공 세트와 프리셋

- **기본 시스템 세트**: Admin / Member — 페이지 권한은 수정할 수 없지만 **프로젝트 조회 범위는 설정할 수 있습니다.**
- **편집 가능한 프리셋**: PM / PMO / Team Lead / Team Member
- 앱 업그레이드로 새 항목(예: 워크로그 추출)이 생기면 **기존 세트에는 꺼진 채로** 추가됩니다. Admin 세트만 켜져 있으므로 필요한 세트에 직접 켜 주세요.

## 프로젝트 데이터 범위

| 값 | 의미 |
|---|---|
| **전체 프로젝트** | 모든 프로젝트 조회 |
| **소속 프로젝트만** | 본인이 인력으로 등록된 프로젝트만 |
| **내 팀만** | 내 팀과 하위 팀 인력이 투입된 프로젝트만 |

**주의사항**

- Jira 관리자 세트는 항상 전체를 조회하며 **이 설정을 변경할 수 없습니다.**
- **내 팀만** 선택 시 **팀 미지정 사용자는 아무 프로젝트도 볼 수 없게 된다**는 경고가 해당 인원 수와 함께 표시됩니다.
- **내 팀만은 프로젝트 범위만 제한합니다.** 같은 세트에 자원 관리·인력 관리 조회 권한을 함께 주면 **전사 인원 목록은 그대로 보입니다.**
- 워크로그 추출과 Jira 이슈 패널의 워크로그 기록은 이 범위와 무관합니다(Jira 권한 기준).

## 팀 권한 상속

개인 권한 세트를 지정하는 대신 **팀 권한 상속**을 선택하면 소속 팀(없으면 상위 팀)의 세트를 따릅니다.

- 선택 시 **"현재 상속받게 될 권한: {이름} ({팀})"** 이 미리 표시됩니다.
- 상속받을 권한이 없거나 팀에 소속되지 않았으면 **"이 사용자는 모든 권한을 잃게 됩니다"** 경고가 나옵니다.
- 팀에 권한 세트를 거는 방법은 [7.3 팀 관리](cloudjira--03-%ED%8C%80-%EA%B4%80%EB%A6%AC.md#팀-권한-상속)를 참고하세요.

## 알아두기

- 권한 검사는 화면 노출과 별개로 **서버에서도 수행**됩니다. 권한 없는 작업을 시도하면 "이 작업을 수행할 권한이 없습니다"가 표시됩니다.
- 권한별로 무엇이 되고 안 되는지는 [부록 B](../%EB%B6%80%EB%A1%9D/cloudjira--B-%EA%B6%8C%ED%95%9C%EB%B3%84-%EC%82%AC%EC%9A%A9-%EB%B2%94%EC%9C%84.md)를 참고하세요.
- 사용자가 자신의 현재 권한을 확인하려면 [마이페이지 > 내 권한](../cloudjira--03-%EB%A7%88%EC%9D%B4%ED%8E%98%EC%9D%B4%EC%A7%80.md#31-내-현황)을 보면 됩니다.
