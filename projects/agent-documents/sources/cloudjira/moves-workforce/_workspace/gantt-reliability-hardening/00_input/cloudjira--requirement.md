# 간트 안정화 1차 요구사항

## 목표

간트 편집 경로의 프로젝트-이슈 범위를 서버에서 확정하고, WBS에서 폴더로 옮길 때 발생할 수 있는 부분 성공을 제거한다. 또한 선행 coworker field 조회 실패를 사용자에게 오류로 보이게 한다.

## 범위

1. `updateGanttSchedule`과 `setGanttIssueFolder`는 대상 이슈가 전달된 `projectId`의 간트 이슈 집합에 속하는지 서버에서 검증한다.
2. WBS 하위 이슈를 폴더로 이동하는 UI 동작은 WBS 해제와 폴더 배정을 원자적으로 조율한다. 실패 시 성공으로 보이는 로컬 상태를 남기지 않는다.
3. coworker custom field 조회 실패는 간트 로딩을 무한 대기시키지 않고 기존 오류 UI로 전환한다.
4. 기존 resolver 응답과 일반 편집 동작의 호환성을 유지한다.
5. 간트 이슈 타입 아이콘이 URL 누락·이미지 로드 실패·그리드 재렌더링 상황에서도 빈 공간으로 사라지지 않도록, 이슈 타입명을 이용한 시각적 fallback을 제공한다.

## 디자인 보강

- 오류 상태에는 다시 시도 동작을 명확히 제공한다.
- 이슈 타입 아이콘은 16px 고정 영역을 유지하고, 원본 이미지가 없거나 실패하면 타입 이니셜 배지로 대체한다. 원래 아이콘이 정상 로드되면 기존 Jira 아이콘을 그대로 사용한다.
- 폴더와 이슈의 깊이는 배경색 농도만으로 구분하지 않는다. 좌측 트리에 depth별 들여쓰기, 부모-자식 연결 가이드, 폴더 라벨의 weight를 함께 적용해 명도 대비가 낮은 화면과 다크 모드에서도 구조를 읽을 수 있게 한다.

## 비범위

- 대용량 간트의 범위 로딩/가상화
- SVAR DOM 의존 렌더링 구조 변경
- 관계 링크 의미 및 UX 개편
