# 이슈 연결 Gantt — v2 요구사항 (Jira 네이티브 구조 전환 검토, 2026-07-01)

## 배경 / 문제

M3(관계 편집)를 **앱 커스텀필드**(`wbsParentField` string, `predecessorsField` object, 둘 다 `readOnly: true`)로 구현했으나:
- readOnly Forge 앱 필드는 표준 `PUT /issue` 로 write 불가 → `400 "Field does not support update 'customfield_10382'"`.
- 앱 전용 엔드포인트(`/app/field/{id}/value`, asApp)로 우회 수정했으나(2026-07-01), 사용자는 **여전히 "연결 안됨"** 보고.
- 근본적으로 관계 데이터를 **앱 사설 필드**에 담는 구조가 Jira 화면과 단절되고 write 제약도 크다.

→ **관계 모델을 Jira 네이티브 구조로 전환하는 방향을 검토**한다.

## 요구사항

### R1. 선후행(의존) 연결 — Jira 네이티브 이슈 링크 연동
- 막대 사이 화살표(선행→후행)가 실제로 생성/삭제/조회되어야 한다.
- 저장을 앱 커스텀필드가 아니라 **Jira 네이티브 이슈 링크**로 한다(예: "Blocks / is blocked by" 링크 타입). 표준 이슈 링크 API 사용.
- Jira 이슈 화면에서도 관계가 보이도록(네이티브라 자연 연동).

### R2. 이슈 구조 3단계 이상 계층
- 이슈 계층을 **3단계 이상** 연결 가능해야 한다.
- **이 계층은 선후행 관계가 아니다** — 별개의 "포함/구성" 관계다.

### R3. 계층 = 하위 이슈 개념 (네이티브 부모-자식) + 아코디언
- R2의 다단계 계층은 **"하위 이슈" 개념**과 같다 = Jira 네이티브 부모-자식(하위 이슈) 구조.
- **좌측 이슈 영역**에서 **아코디언 형태**로 포함 관계를 펼치면 하위에 연결된(하위) 이슈들을 볼 수 있어야 한다.

### R4. 미일정 이슈도 일정 편집 가능
- 시작일(customfield_10015)·듀데이트(duedate)가 **정해지지 않은 이슈**도 간트에서 **일정 편집(설정)** 이 가능해야 한다.
- 현재는 미일정 이슈가 SVAR unscheduled 별도 영역에 빠져 드래그 편집이 어려움 → 편집 진입 경로 필요.

## 검토 산출물 요구
- Jira 네이티브 이슈 링크 API(링크 타입 조회/생성/삭제, read fields=issuelinks) 조사.
- Jira 네이티브 계층(parent 필드, 하위 이슈, 3단계+ 가능성 — subtask/신규 issue hierarchy 제약 포함) 조사·실현 가능성.
- 커스텀필드 방식(현행) vs 네이티브 방식 비교표 + 마이그레이션/호환 영향.
- 경계면 계약(resolver 함수 shape) 갱신안.
- 좌측 아코디언 트리 + R4 미일정 편집 UX 설계.
- 사용자 판단이 필요한 결정(링크 타입 선택, 계층 깊이 제약 대응 등) 명시.
