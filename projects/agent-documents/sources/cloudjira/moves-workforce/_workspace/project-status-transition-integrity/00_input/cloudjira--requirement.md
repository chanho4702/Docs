# 프로젝트 상태 전이 정합성 보강

## 배경

RFC-192에서 프로젝트 상태 변경(`updateProject`, Kanban 이동, status link 변경)의 서버 상태 전이 검증은 완료했다. 그러나 상태 정의 자체를 추가·삭제·초기 상태로 변경할 때에는 전이 그래프의 유효성 및 동시 변경(CAS)이 충분히 보장되지 않는다.

## 목표

- 상태 추가, 삭제, 초기 상태 지정 경로가 유효한 상태 그래프를 유지하도록 한다.
- 삭제 또는 초기 상태 변경으로 기존 프로젝트가 유효하지 않은 상태를 참조하지 않도록 한다.
- 동시 편집에서 마지막 요청이 무조건 덮어쓰지 않도록 SQL compare-and-set 또는 같은 수준의 조건부 갱신을 적용한다.
- 기존 project/Kanban 상태 변경의 정책과 응답 계약을 깨지 않는다.
- Kanban 보드의 상태 이동, 컬럼 관리, 삭제된 상태 처리와 오류 안내를 점검하고, 상태 정합성을 깨거나 사용자에게 어색하게 보이는 동작을 같은 변경 범위에서 보정한다.

## 제외 범위

- 대규모 화면 기능 확장, 전면적인 Kanban UX 재설계, 권한 정책 변경은 제외한다.
- 기존 사용자 변경 파일(README 및 root locales)은 수정하지 않는다.
