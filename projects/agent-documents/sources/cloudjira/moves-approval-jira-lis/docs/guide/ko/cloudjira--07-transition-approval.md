# 상태 전환 승인

## 관리자가 설정할 것

1. 전역 설정에서 대상 프로젝트의 승인을 켜고 사용할 결재선을 만듭니다.
2. 프로젝트 설정 → **Moves Approval → 전환 승인 규칙**에서 이슈 유형·목적 상태·결재선을 지정합니다.
3. Jira 워크플로 편집에서 그 목적 상태로 들어가는 **각 전환**에 **Moves Approval — approval required** validator를 추가하고 워크플로를 게시합니다.
4. 승인 없는 전환의 거부와 승인 후 전환 성공을 일반 계정으로 시험합니다.

**규칙만 만들면 강제되지 않습니다. validator가 붙은 전환에서만 강제됩니다.** 동일한 목적 상태로 들어가는 다른 전환에도 붙여야 합니다. team-managed 프로젝트의 지원은 실환경 확인 전에는 보장하지 않습니다.

현재 validator는 전역 강제 꺼짐, 라이선스 비활성, 승인 테이블 초기화 미완료, 대상 이슈·목적 상태 없음, 일치 규칙 없음, 프로젝트 제외 상태에서 승인을 요구하지 않고 통과할 수 있습니다. 따라서 모든 상태 변경을 항상 차단한다고 안내하면 안 됩니다. 초기화 미완료와 실행 중 조회 오류는 다른 조건이며, 정상적인 보호 규칙의 미승인·대기·반려·이미 사용된 승인은 거부합니다. 설치·업그레이드·라이선스 변경 후에는 적용 경로를 일반 사용자로 다시 시험하세요.

## 요청자 흐름

이슈 **Moves Approval** 또는 **••• → Request approval → 상태 변경 승인**에서 목적 상태를 선택합니다. 결재선은 프로젝트 규칙이 정합니다. 메시지·마감·참조자를 확인하고 제출합니다.

신규 요청은 최종 승인 후 **원 요청자의 오프라인 권한으로 자동 전환**합니다. 관리자가 승인하거나 재시도를 눌러도 Jira 실행자는 원 요청자입니다. 기존 요청(`LEGACY_MANUAL`)은 자동 실행하지 않으므로 승인 후 Jira에서 수동 전환합니다.

승인 상태와 **Jira 적용 상태**는 별개입니다. `WAITING`은 승인 이후 배치 실행 대기, `APPLYING`은 실행 중, `APPLIED`는 성공 응답 또는 정확한 변경 이력·승인 소비 증거 확인입니다. `FAILED`는 적용 실패, `BLOCKED`는 권한·규칙·상태·필수 입력 등의 조건 미충족, `UNKNOWN`은 실행 결과 불명확입니다. 승인 완료 알림은 적용 완료 증명이 아닙니다. 상세에서 실제 적용 상태를 확인하세요.

서버가 허용한 경우에만 **자동 적용 재시도** 또는 **Jira 적용 결과 대조**를 제공합니다. `UNKNOWN`은 이미 적용되었을 수 있어 같은 요청을 재전송하지 않습니다. 대조는 요청자·출발/목적 상태·시각·단일 변경 이력·승인 소비 증거가 모두 맞아야 성공으로 판정하며 현재 목적 상태만으로 성공을 추정하지 않습니다. 한 번에 최대 500개/5페이지/15초를 확인하고 근거가 부족하면 관리자의 수동 확인이 필요합니다. 화면의 실행 중 자동 재조회는 약 1분까지만 수행하며 이후 새로고침으로 확인합니다.

자동 실행은 최종 승인 직후 또는 5분 배치에서 이루어집니다. 필수 전환 화면 입력은 추측하여 보내지 않습니다. 요청자 impersonation 동의·접근 제한, 실제 Jira 이력 actor 보존, REST validator 재진입, Forge SQL 마이그레이션 및 schedule 동작은 개발 사이트 실측 전이며 모든 워크플로 자동화를 보장하지 않습니다.

## 일시 해제

전역 정책에서 전환 승인 강제를 끄거나 적용 프로젝트를 제외하면 승인 강제가 해제됩니다. 이는 일반 승인 기록을 삭제하는 동작이 아닙니다. 해제 전 영향 범위를 확인하고 해제·복구 기록을 남기세요.
