# 데이터·보안·개인정보

이 페이지는 앱의 데이터 처리 설명입니다. 공급자의 개인정보 처리방침·이용약관·지원 정책은 Marketplace에 연결된 확정 문서를 확인하세요. 이 페이지가 법적 정책을 대신하지는 않습니다.

## 저장하는 데이터

| 데이터 | 내용과 목적 |
| --- | --- |
| 요청·결재선·결정·감사 | 대상 이슈 식별정보, 요청 메시지, 계정 ID, 단계·결정·사유·시간, 대리 처리자 |
| 타임시트 제출본 | 사용자·기간·시간대, 워크로그 ID·이슈·시작·시간과 지문, 제한선·변경 상태 |
| 전환·필드 승인 | 이전/목적 상태, 요청 필드의 이전/새 값, 적용 결과·실행자, 우회 변경 이력 |
| 워크로그 사전 승인 | 미등록 입력안의 작성자·이슈·날짜·시간·설명 원문, 결재선·정책 고정본, 등록 상태·연결된 Jira 워크로그 ID |
| 워크로그 변경 이력 | 생성·수정·삭제와 관측 기준 기록, 작성자·행위자, 시간·이슈, 설명 지문·미리보기 또는 원문 |
| 업무함·알림 | 관련 계정 ID, 역할, 알림 내용과 읽음 여부 |
| 서명·PIN·위임 | 서명 이미지, PIN의 솔트 처리된 PBKDF2 해시, 실패·잠금 상태, 대리인·유효 기간 |
| 설정·관리 기록 | 정책, 팀·팀장, 그룹·명부·결재선, 변경·내보내기·정리 이력 |

PIN 원문은 보관하지 않습니다. 이름·이메일·사진을 사용자 명부의 원본으로 보관하는 대신 Jira 계정 ID로 사용자를 식별하고 화면에서 Jira 정보를 조회합니다. 요청 대상의 표시 정보, 감사·내보내기에는 필요한 사용자·이슈 정보가 포함될 수 있습니다.

## 워크로그 설명

변경 이력은 기본 켜짐, 설명 원문 보관은 기본 꺼짐입니다. 원문 보관이 꺼져도 **앞 40자 미리보기와 지문을 저장**하므로 민감한 설명 일부가 남을 수 있습니다. 원문 보관을 켜면 이후 수집하는 변경에 적용되며 저장 공간이 늘어납니다.

워크로그 사전 승인 입력안은 결재와 승인된 내용의 등록을 위해 **설명 원문 전체를 저장**합니다. 변경 이력의 원문 보관 끔 설정은 승인 입력안에 적용되지 않습니다. 승인 입력안은 요청자와 해당 요청에 접근할 수 있는 결재자가 확인하므로 설명에 불필요한 개인정보를 넣지 마세요.

제한 공개 워크로그의 설명은 작성자에게만 보여 줍니다. 이력 조회·내보내기에서도 조회자의 Jira 이슈 권한을 확인합니다. 수집 이전의 모든 변경을 소급 복원하거나 누락 없는 실시간 감사를 보장하지 않습니다. 첫 관측의 기준 기록과 실제 변경 이벤트를 구분하세요.

## 저장과 Jira 쓰기

앱 데이터는 Forge SQL·KVS에 보관합니다. 현재 manifest에는 외부 도메인으로의 egress 권한이 선언되어 있지 않습니다. 이것만으로 데이터 위치·보안 인증·Runs on Atlassian 배지를 보장하지는 않습니다.

Jira에는 사용자가 입력한 워크로그, 승인 후 적용한 필드 값, 조건에 맞는 전환 @멘션 댓글, Workforce 연동 게시물을 씁니다. 워크로그·필드·댓글은 기본적으로 행위자의 권한으로 처리합니다. 관리자가 필드 변경 앱 대체 적용을 켜면 승인된 필드의 사용자 권한·화면 거절 뒤 앱 권한으로 적용을 시도하며, Jira 변경 이력에는 앱이 표시됩니다. 앱의 결재 기록에는 실제 승인자를 보존합니다. 사용자 컨텍스트가 없는 변경 수집·validator 판정·연동 게시 등은 제한된 앱 권한 경로를 사용합니다.

앱의 기록 삭제는 Jira 원본 워크로그·댓글·필드 값을 삭제하거나 되돌리지 않습니다. 댓글·프로퍼티는 Jira의 공개 범위에 영향을 받습니다.

## 보관·내보내기·삭제

| 항목 | 정책 |
| --- | --- |
| 종료된 승인 기록 | 기본 3년, 무기한·1·3·5·10년 선택. 기한만으로 자동 삭제하지 않으며 관리자 내보내기 확인 뒤 정리 |
| 진행 중 요청 | 종료 기록 정리 대상에서 제외 |
| 사전 승인 등록 대기·결과 불명 | 등록 중·결과 불명, 승인 후 등록 대기/재시도 가능 기록은 종료 기록 정리에서 제외 |
| 워크로그 변경 이력 | 기본 12개월, 0은 무기한. 내보내기 확정 뒤 관리자 정리 |
| 앱 내 알림 | 180일 보관 후 자동 정리 |
| 설정 변경 이력 | 1년 보관 후 자동 정리 |
| 서명·PIN·위임 | 사용자가 변경·삭제 가능 |

데이터 관리에서 사용량을 확인합니다. 내보낸 Excel·결재 증명서 PDF에는 이름·요청 메시지·반려 사유 등의 정보가 포함될 수 있으며 다운로드 이후의 보관·공유·폐기는 고객이 관리합니다. 삭제는 되돌릴 수 없으므로 파일을 확인한 뒤 진행하세요. 앱 제거 후 데이터 보관·복구 가능 기간은 Forge의 당시 정책과 공급자에게 확인하세요.

## 권한과 접근 통제

| 요청 scope | 사용 목적 |
| --- | --- |
| `storage:app` | 앱 설정과 승인·이력 데이터 저장 |
| `read:jira-work` | 이슈·프로젝트·워크로그·변경 기록 조회, 열람 권한 확인, 이벤트 수집 |
| `read:jira-user` | 사용자·그룹 검색과 구성원·이름 표시 |
| `write:jira-work` | 워크로그 입력·수정·삭제, 승인된 필드 적용, 댓글, 연동 게시 |
| `report:personal-data` | 개인정보를 보관하는 계정을 Atlassian에 보고하고 삭제·갱신 필요 여부 확인 |

서버에서 본인 여부·결재 차례·관리 권한·이슈 열람 권한을 확인합니다. 명부 등록·대리 지정이 이슈 권한을 늘리지 않습니다. 개인정보 관련 요청은 사이트 관리자와 공급자의 공식 지원 채널에 문의하세요. 개인 서명·PIN·위임은 본인이 삭제할 수 있지만 조직의 승인 감사 기록은 관리자 보관 정책으로 관리합니다.

## 계정 삭제와 비활성화

비활성화된 계정은 Jira 이름을 유지합니다. Atlassian 개인정보 보고 API가 `closed`로 확인한 계정은 서명 이미지·PIN·알림·위임·본인 소유의 업무함 기능 사본·팀 및 앱 명부 등록을 정리합니다. 요청자·대상자로 포함된 다른 사용자의 업무함 사본과 원본 참조(CC) 명부의 계정 ID는 보존합니다. 워크포스 검증 문서는 본인의 조직 문서만 삭제하며 다른 계정을 위한 문서는 유지합니다. 보고에서 `updated`가 반환되어도 서명된 워크포스 검증 문서는 삭제하지 않습니다. 표시 이름·아바타는 서버에 캐시하지 않고 다음 사용자 권한 조회에서 최신 정보를 가져옵니다. 보고는 기본 7일 주기이며 서버의 `Cycle-Period` 응답을 따르므로 계정 삭제와 앱 반영 사이에는 시간이 걸릴 수 있습니다.

결재 그룹·결재선은 탈퇴자의 구성원 등록만 제거하고 활성 상태를 유지합니다. 비어 있는 단계가 생긴 결재선에는 설정에서 **검토 필요** 경고를 표시하며, 관리자가 단계를 수정해 저장할 때까지 신규 요청에 사용할 수 없습니다.

감사 추적을 위해 **결재 요청·결재자·이벤트, 인증, 워크로그 변경 이력, 통제 이력, 설정 감사에 들어 있는 계정 ID를 보존**합니다. 감사 스냅샷과 사용자가 작성한 사유·설명 등 기록 전체를 계정별로 자동 삭제하거나 익명화하는 기능은 아닙니다. 삭제 계정의 구분 표식도 유지하며, 앱 화면에는 `탈퇴한 사용자 A`, `탈퇴한 사용자 B`처럼 같은 계정에 같은 표식을 표시합니다. 감사 내보내기에는 표시 이름 또는 이 표식과 원래 계정 ID가 함께 포함됩니다. 조직은 이 식별자 보관을 개인정보 처리방침과 보관 정책에 명시해야 합니다.

퇴사자 계정은 비활성화를 권장합니다. 삭제해야 한다면 먼저 이름과 계정 ID가 포함된 감사 기록을 내려받으세요. 앱 제거 직전에는 더 필요 없는 기능용 정보를 정리하며, 워크로그 공개 범위 복구에 필요한 통제 원장은 복구 전에 삭제하지 않습니다. 제거 훅의 시간 제한으로 정리를 모두 마치지 못할 수 있으므로 사전에 통제를 해제하고 내보낸 자료를 확인하세요.

## 자동 전환과 인증 데이터

자동 전환은 원 요청자의 offline asUser 권한으로 실행하며 asApp 전환 쓰기로 대체하지 않습니다. read:jira-work/write:jira-work에 impersonation을 허용하며 실제 동의·사용자 접근 제한·actor 기록은 개발 사이트 실측 전입니다. 적용 ledger에는 상태·원인·시도·시각·적용자·변경 이력 근거를 보관합니다. 승인과 적용은 별도 사실입니다.

사후 인증은 워크로그 원본의 시간·설명·공개 범위를 지문에 포함합니다. 저장하는 인증 snapshot은 worklogId/issueId/authorId/started/seconds/sourceUpdatedAt/fingerprint이며 설명·visibility 원문을 인증 ledger에 복제하지 않습니다. 승인 요청 당시 snapshot과 현재 원본 인증 상태를 구분하여 증명서에 표시합니다. 수정·삭제가 관찰되면 인증이 무효화되고 복원만으로 인증을 되살리지 않습니다. 워크로그 이력 수집을 꺼도 기존 인증 ledger가 있는 ID만 변경 feed에서 골라 상세를 재조회하며, 인증 요청·조회 전에는 다른 워크로그의 인증 ledger를 자동 생성하지 않습니다. 조회는 사용자의 Jira 권한으로 제한됩니다. 기존 이력 저장 정책과 인증 snapshot의 원문 미복제 정책은 서로 다릅니다. 보관 내보내기는 요청별 인증 snapshot과 전환 적용 ledger를 포함합니다.

## 워크로그 정책 계층 안내

워크로그 scope 정책은 sparse 값·수정자·리비전과 검증된 Workforce 캐시를 저장합니다. rms.policy는 공개 키 서명·대상·시각·rev를 검증한 뒤 판정에 쓰며 entity property 원문은 검증 전 신뢰하지 않습니다. runtime은 SQL 검증 캐시만 사용합니다. 서명 실패는 기존 검증본을 덮지 않습니다. Workforce 잠금이 유예를 넘겨 만료되면 관련 쓰기를 차단합니다. 이력 설명 보관은 기본 비활성이고 scope별 실제 정책을 따릅니다. historyRetentionMonths는 사이트 전용이며 0=무기한, 수동 내보내기 확인 후 삭제를 유지합니다. 진단은 지속적인 사용자 telemetry가 아니라 현재 응답·캐시 집계입니다.
