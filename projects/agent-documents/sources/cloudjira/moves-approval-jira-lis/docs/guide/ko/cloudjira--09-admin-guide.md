# 관리자 가이드

Jira 관리자는 Jira 앱 관리 또는 업무함의 설정을 사용합니다. 앱 설정 관리자는 업무함 경로에서 전역 설정을 관리합니다. 프로젝트 규칙은 해당 프로젝트 관리 권한이 필요합니다.

업무함 왼쪽 **설정**을 선택하면 하위 메뉴가 같은 사이드바에 펼쳐집니다. 원하는 설정을 선택하면 해당 화면을 불러옵니다. 업무함 경로에서는 선택한 설정이 URL에 보관되며, Jira 앱 관리의 독립 설정 화면에서는 현재 화면 안에서 메뉴를 선택합니다.

| 타임시트 | 월/주·시간대·제한선·팀/팀장·마감·워크로그 이력 수집 |

## 접근 제한·운영 점검

접근 제한을 켜면 Jira 관리자·설정 관리자·승인자 명부·활성 타임시트 팀 구성원 범위에서 앱을 사용합니다. 앱 사용 허용과 이슈 열람 권한은 별개입니다. 명부·팀 변경 뒤 일반 계정으로 확인하세요.

정기적으로 미처리 요청, 승인 후 변경, 필드 미적용, 마감 예외, 연동 지연과 저장 공간을 점검합니다. 데이터 삭제 전에는 반드시 내보내기 파일을 확인하고 조직의 보관 정책을 따르세요.

## 퇴사자 계정과 개인정보 보고

퇴사자는 계정을 삭제하기보다 **비활성화**하세요. 비활성 계정은 Jira가 제공하는 이름으로 표시합니다. 계정 삭제가 필요하면 **삭제 전에 감사 기록을 내려받고**, 이름과 계정 ID가 함께 들어 있는지 확인하세요. 삭제된 계정은 개인정보 보고에서 확인한 뒤 `탈퇴한 사용자 A`, `탈퇴한 사용자 B`처럼 표시하며, 같은 계정은 앱 전체에서 같은 표식을 사용합니다.

탈퇴 계정은 결재 그룹·결재선의 구성원에서만 제거하며 그룹과 결재선을 자동으로 비활성화하지 않습니다. 구성원이 모두 제거된 단계가 생기면 결재선 설정에 **검토 필요** 경고가 표시됩니다. 관리자가 단계를 수정해 저장할 때까지 해당 결재선은 신규 요청에서 선택할 수 없습니다. 기존 결재 요청과 다른 사용자의 업무함 기록은 보존합니다.

앱은 기존 일일 점검을 통해 개인정보 보관 계정을 기본 7일 주기로 Atlassian에 보고합니다. Atlassian이 다른 주기를 지정하면 그 주기를 따릅니다. 계정 삭제가 확인되면 서명 이미지·PIN·알림·위임·팀과 앱 명부 등록 등 기능용 정보를 정리하고 사용자 캐시를 비웁니다. **결재·인증·워크로그 변경·통제·설정 감사 기록의 계정 ID는 보존**하므로, 계정 삭제가 감사 기록 전체의 삭제를 뜻하지는 않습니다. 상세 보관 범위는 [개인정보 안내](cloudjira--11-data-security-privacy.md)를 확인하세요.

이 기능의 설치 업그레이드에는 개인정보 보고 권한 `report:personal-data`가 추가됩니다. 앱을 제거하기 전에는 통제로 숨긴 워크로그를 먼저 해제하고 필요한 감사 기록을 내려받으세요. 제거 직전 정리는 실행 시간에 제한이 있어 관리자 사전 확인을 대신하지 않습니다.

## 자동 전환·사후 인증 운영

신규 전환 승인은 요청자의 offline impersonation 권한으로 자동 적용됩니다. 적용 프로젝트·규칙·워크플로 validator·요청자 Jira 권한을 모두 확인하세요. 승인 상태와 적용 상태는 별도이며 UNKNOWN에는 재전송하지 않고 상세의 결과 대조와 수동 변경 이력 확인을 사용합니다. 기존 LEGACY_MANUAL 요청은 수동 전환합니다. 배포 시 impersonation scope 변경에 대한 설치 업그레이드와 동의 상태를 확인해야 합니다.

워크로그 사후 인증은 Jira 원본이 먼저 저장되는 모델입니다. 작성자는 행의 인증 화면에서 사용 가능한 결재선을 선택합니다. WORKLOG_CREATE 필수 정책은 선택적 고통제 모드이며 승인 후 본인 등록을 유지합니다. 인증은 기간 잠금이나 타임시트 승인과 별개입니다. 일반 계정으로 원본 변경 시 인증 무효화, 다른 작성자의 인증 요청 거부, 승인과 Jira 적용 결과 분리를 확인하세요. 현재 provider 실제 선택 여부를 앱이 자동 판정하지 않습니다.

## 워크로그 정책 계층 안내

사이트의 타임시트 정책에서 **사이트 워크로그 기본 정책**과 **정책 진단 카운터**를 사용합니다. 적용 프로젝트의 정책 모달에서 **프로젝트 워크로그 정책**, 이슈 작업 로그 탭에서 **이슈 워크로그 정책·상속**을 확인합니다. 프로젝트 관리자는 sparse override 전체와 현재 정수 리비전으로 저장합니다. POLICY_CONFLICT 시 최신 상태를 다시 조회하고 변경을 재검토하세요. legacy 문자열 리비전이면 마이그레이션 완료 전 저장하지 않습니다.

Workforce 정책은 이 화면에서 편집하지 않습니다. Workforce에서 발행한 서명 정책을 **Workforce 정책 새로 수신**으로 가져옵니다. 잠금·만료·서명 오류에는 수신 대상·공개 키·kid/trustedKids·시각·rev를 확인합니다. 보존 기간, 승인 단위, 시간대는 사이트에서만 설정합니다. 보존 0은 무기한이며 수동 export→purge 계약을 유지합니다. 프로젝트별 보존 override는 없습니다. diagnostics는 현재 응답 카운터이며 누적 통계가 아닙니다.


## 기간 재개방과 필드 앱 적용

정식 구독과 평가판은 만료 7일 전부터 업무함·작업 로그·이슈·설정 화면에서 경고합니다. 경고를 닫아도 다음 날 다시 표시합니다. Moves Approval이 시간 추적 제공자로 지정된 사이트는 만료 후 시간 입력이 멈출 수 있으므로 라이선스를 갱신하세요. 시간 입력을 되살려야 한다면 Jira 관리자가 **Jira 설정 > 이슈 > 시간 추적**에서 제공자를 **Jira 기본 제공자**로 되돌리고 이슈의 작업 로그 입력을 확인하세요.

기간 관리의 **새 입력 허용**은 마감 잠금만 풀며 기존 승인·인증은 유지합니다. **수정까지 허용**은 승인·인증·숨김 해제 건수를 미리 보여 주고 사유를 받은 뒤 실행합니다. 기존 결정과 인증 기록은 보존하고 재승인·재인증이 필요한 상태로 전환합니다. 작업이 나뉘면 이어하기로 완료하세요. 숨김 해제는 통제 작업 큐에서 처리하므로 기간 처리 완료 뒤에도 잠시 시간이 걸릴 수 있습니다.

필드 변경의 앱 대체 적용은 기본 꺼짐입니다. 켜면 사용자 PUT의 명확한 권한 또는 화면 거절 뒤 앱 권한으로 한 번 더 시도합니다. Jira 이력의 수정자는 앱이 되며 결재 승인자는 유지합니다. 앱에 편집 권한이 없거나 화면 제약이 해소되지 않으면 적용되지 않습니다. 결과 불명(UNKNOWN)은 중복 변경을 막기 위해 자동 재전송하지 않습니다.
