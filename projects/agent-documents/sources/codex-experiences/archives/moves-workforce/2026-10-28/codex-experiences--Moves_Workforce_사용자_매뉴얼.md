## 접근 권한

| 구분 | 필요 권한 |
|---|---|
| 이 목차 페이지 | **권한 불필요** |
| 각 화면의 권한 | 페이지마다 상단의 **접근 권한** 표를 확인하세요 |
| 권한 전체 요약 | [부록 B. 권한별 사용 범위](#부록-b-권한별-사용-범위-요약) |
| 내 현재 권한 확인 | [마이페이지 > 내 권한](#31-내-현황) (권한 불필요) |

**권한 표기 규칙**

권한 이름은 **[설정 > 권한 관리](#78-권한-관리) 화면에 표시되는 항목명**을 「 」 안에 그대로 씁니다.

| 표기 | 의미 |
|---|---|
| 「프로젝트 관리」 읽기 | 그 항목의 **읽기(Read)** 체크가 있어야 화면이 보입니다 |
| 「프로젝트 관리」 쓰기 | **쓰기(Write)** 체크가 있어야 추가·수정·삭제 버튼이 나타납니다 |
| A 또는 B | 둘 중 **하나만** 있어도 됩니다 |
| A + B | **둘 다** 있어야 합니다 |
| 권한 불필요 | 본인 데이터이거나 전역 공개 정보입니다 |
| Jira 권한 | 앱 권한과 **별개로** Jira 자체 권한이 필요합니다 |

> 권한이 없으면 대부분 **버튼·탭·메뉴가 아예 보이지 않습니다.** 서버에서도 같은 검사를 하므로 화면을 우회해도 거부됩니다.

## 이 문서를 읽는 법

각 페이지는 다음 순서로 구성됩니다.

1. **접근 권한** — 이 화면을 보고 편집하는 데 필요한 권한
2. **언제 쓰나** — 이 화면이 해결하는 문제
3. **화면 구성** — 어디에 무엇이 있는지 (그림 포함)
4. **절차** — 단계별 절차
5. **알아두기 / 주의** — 오해하기 쉬운 규칙
6. (필요 시) **문제 해결** — 증상과 원인

### 1.4 권한의 기본 개념

#### ① 읽기와 쓰기가 분리됩니다

기능 영역마다 **읽기(Read)** / **쓰기(Write)** 가 따로 있습니다. 읽기만 있으면 조회는 되지만 추가·수정·삭제 버튼이 **아예 보이지 않습니다.**

#### ② 화면에서 숨긴다고 끝이 아닙니다

권한 검사는 **서버에서도 수행**됩니다. 권한 없는 작업을 시도하면 "이 작업을 수행할 권한이 없습니다"가 표시됩니다.

#### ③ 프로젝트 조회 범위가 따로 있습니다

권한 세트마다 볼 수 있는 프로젝트 범위가 설정됩니다.


| 범위           | 보이는 프로젝트                                                                            |
| ------------ | ----------------------------------------------------------------------------------- |
| **전체 프로젝트**  | 모든 프로젝트                                                                             |
| **소속 프로젝트만** | 본인이 **인력으로 등록된** 프로젝트만                                                              |
| **내 팀만**     | 내 소속 팀·하위 팀, 내가 이끄는 팀·하위 팀의 인원이 참여했거나 담당 팀으로 지정된 프로젝트. **유효한 팀이 없으면 아무것도 보이지 않습니다** |


> Jira 관리자와 Admin 권한 세트는 이 설정과 무관하게 항상 전체 프로젝트를 봅니다.
> **참여 중인 프로젝트가 보이지 않는다면** 프로젝트 관리자에게 [인력 등록](#52-인력-관리)을 요청하세요.

권한 설정 방법은 [7.8 권한 관리](#78-권한-관리), 권한별로 무엇이 되는지는 [부록 B](#부록-b-권한별-사용-범위-요약)를 참고하세요.

#### ④ Jira 자체 권한도 따로 있습니다

앱은 Jira 호출을 **본인 계정으로** 실행합니다. 앱에서 쓰기 권한이 있어도 Jira에서 그 작업이 막혀 있으면 저장이 거부되고 사유가 안내됩니다.


| 하려는 일         | 필요한 Jira 권한                                              |
| ------------- | -------------------------------------------------------- |
| 이슈 조회         | Browse Projects                                          |
| 워크로그 작성·수정·삭제 | Work On Issues (남의 워크로그 수정·삭제는 Edit/Delete All Worklogs) |
| 일정 변경         | Edit Issues + Schedule Issues                            |
| 담당자 지정        | Assign Issues                                            |
| 선후행 연결        | Link Issues                                              |
| 계획 작업량(MD)    | Edit Issues + 프로젝트의 시간 추적 활성화                            |


> 설치·최초 접근에 필요한 Jira 계정 권한(누가 처음 관리자로 들어갈 수 있는지)은 [관리자 매뉴얼 2.0](codex-experiences--Moves_Workforce_%EA%B4%80%EB%A6%AC%EC%9E%90_%EB%A7%A4%EB%89%B4%EC%96%BC.md#20-시작하기-전에--필요한-jira-계정-권한)에 정리돼 있습니다.

## 2. My Work

### 접근 권한

| 구분 | 필요 권한 |
|---|---|
| 화면 조회 | **권한 불필요** — 사이드바에 항상 표시됩니다 |
| 워크로그 작성·수정·삭제 | **권한 불필요** (본인 데이터) + Jira의 Work On Issues 권한 |
| 다른 사람의 워크로그 | **수정·삭제 불가** — 작성자 본인만 가능(조회만) |

### 2.1 상단 요약 지표

| 카드 | 의미 | 예시 |
|---|---|---|
| 이번 달 누적 작업 시간 | 이번 달 기록한 시간 / 목표 시간 | 125h 3m / 164h |
| 이번 주 누적 작업 시간 | 이번 주 기록한 시간 / 목표 시간 | 26h 45m / 40h |
| 오늘 작업 시간 | 오늘 기록한 시간 / 목표 시간 | 6h 52m / 8h |
| 담당 및 협업 이슈 수 | 내가 담당자 또는 협업자로 연결된 이슈 수 | 11 |
| 참여 프로젝트 수 | 내가 속한 프로젝트 수 | 2 |

#### 목표 시간 계산

[설정 > 일반 설정](#71-일반-설정)의 **1Day 근무 시간**(기본 `8h`, `1MD = 8h`)을 하루 기준으로 삼고, [휴일 관리](#79-휴일-관리)에 등록된 **공휴일과 주말을 제외한 근무일 수**를 곱합니다.

```
오늘 목표 = 1일 근무 시간 (예: 8h)
주 목표   = 이번 주 근무일 수 × 1일 근무 시간 (예: 5일 × 8h = 40h)
월 목표   = 이번 달 근무일 수 × 1일 근무 시간
```

### 2.2 My 프로젝트

내가 참여 중인 프로젝트가 카드로 나열됩니다. 상단 검색창으로 빠르게 찾을 수 있고, 카드의 **상세로 이동**으로 프로젝트 상세를 엽니다.

각 카드에 표시되는 정보:

- 프로젝트 이름과 상태(예: `IN PROGRESS`)
- 시작일 / 종료일
- 내 **역할**(예: Data Engineer)과 **등급**(예: Mid-level)

> 역할·등급은 프로젝트 상세의 [인력 관리](#52-인력-관리) 탭에서 그 멤버에게 부여한 값이 그대로 표시됩니다. 값이 비어 있으면 프로젝트 관리자에게 지정을 요청하세요.

### 2.3 My 업무

내가 맡은 작업과 기록한 워크로그를 보는 영역입니다. 오른쪽 위 버튼으로 **캘린더 / 테이블** 뷰를 전환합니다.

#### 캘린더 뷰

- **월간 / 주간** 보기 전환, `<` `오늘` `>` 로 기간 이동. **월간은 한 칸에 많은 항목을 촘촘하게**, **주간은 시간·제목을 자세히** 보여주도록 밀도가 다릅니다.
- 오른쪽 위 **표시 모드** 토글로 달력에 무엇을 올릴지 고릅니다.

| 표시 모드 | 달력에 보이는 것 | 언제 쓰나 |
|---|---|---|
| **워크로그** (기본) | 그날 기록한 워크로그(이슈 키·시간), **일별 합계** | "내가 언제 얼마나 일했나" |
| **이슈** | 내가 담당·협업하는 이슈의 **시작일~기한 기간 막대**, 상태 색(할 일/진행 중/완료) | "이번 주 내 마감이 뭐지" |

- 공휴일은 날짜 칸에 **공휴일 라벨**로 표시되고, 개인 일정(연차 등)은 두 모드 모두에서 보입니다.
- 이슈 모드에서 시작일·기한이 둘 다 없는 이슈는 달력에 놓을 수 없어 **기간 미설정 N건** 버튼으로 따로 모아 보여줍니다. 일정은 [간트](#537-간트-보기)에서 지정합니다.

![그림 2-2 캘린더 워크로그 모드와 이슈 모드 비교](./Moves_Workforce_사용자_매뉴얼/images/02-mywork-calendar-modes.png)
*그림 2-2. 같은 주를 워크로그 모드(왼쪽)와 이슈 모드(오른쪽)로 본 모습. 이슈 모드의 ① 상태 색 막대 ② 기간 미설정 버튼.*

| 조작 | 결과 |
|---|---|
| 날짜 클릭 | 그 날짜로 워크로그(업무일지) 추가 창이 열립니다 |
| 이슈 클릭 | 해당 Jira 이슈로 이동 |
| 이벤트 클릭 | 이벤트 수정 |
| 워크로그를 다른 날짜로 **드래그** | 작업 일자가 변경됩니다(시작 시각·소요 시간은 유지) |
| 우측 위 **+ 일정 추가** | 워크로그 추가 창 열기 |

#### 테이블 뷰

이슈 단위로 작업 현황을 표로 봅니다.

| 컬럼 | 설명 |
|---|---|
| 이슈 키 | Jira 이슈 키 (예: SAMPLE-50) |
| 요약 | 이슈 제목 |
| 상태 | 할 일 / 진행 중 / 완료 |
| 담당자 | 이슈 담당자(Assignee) |
| 동료 | 함께 일하는 협업자 |
| 작업 시간 | 그 이슈에 누적된 작업 시간 (예: 11d, 2h 7m) |
| 기한 / 작업 일 | 이슈 기한 또는 워크로그 작업 일자 |
| 작업 | 부모 이슈는 **+ 추가**, 개별 워크로그는 **수정** |

- 이슈 왼쪽의 펼침(`>`) 아이콘을 누르면 그 이슈에 기록된 **개별 워크로그**가 날짜별로 펼쳐집니다.
- 부모 이슈 행의 **+ 추가**로 새 워크로그를, 개별 워크로그 행의 **수정**으로 기존 워크로그를 편집합니다. 수정 창 안의 **삭제** 버튼으로 지울 수 있습니다.

> **수정·삭제 권한:** 워크로그는 **작성자 본인만** 수정·삭제할 수 있습니다. 다른 사람이 쓴 워크로그는 버튼이 비활성화되어 조회만 됩니다.

> **동료(협업자)란?** Jira 이슈에 함께 저장되는 **협업자 목록**입니다. 담당자(1명)와 별개로 한 이슈를 함께 수행하는 사람을 여러 명 지정할 수 있고, 동료로 지정되면 그 사람의 My Work에도 "협업 이슈"로 집계됩니다. 자세한 내용은 [5.3 담당자·동료 관리](#532-담당자동료-관리)를 참고하세요.

### 2.4 업무일지(워크로그) 추가하기

`+ 추가`, `+ 일정 추가`, 또는 캘린더의 날짜를 클릭하면 **업무일지 추가** 창이 열립니다. 입력 방식은 두 가지 탭입니다.

![그림 2-3 업무일지 추가 창 — 시간 입력 탭](./Moves_Workforce_사용자_매뉴얼/images/02-worklog-modal-simple.png)
*그림 2-3. 시간 입력 탭 — ① 업무(이슈) 선택 ② 날짜 ③ 시작·종료 시간 ④ 자동 계산된 시간 ⑤ 업무 설명 편집기.*

#### 방법 1. 시간 입력(단건)

특정 날짜에 한 건을 기록합니다. **시작 시간과 종료 시간을 입력하면 소요 시간이 자동 계산**됩니다.

| 항목 | 필수 | 설명 |
|---|---|---|
| 프로젝트 정보 | | 대상 프로젝트 (자동 표시) |
| 업무 | 필수 | 워크로그를 기록할 이슈 선택 |
| Worklog 작성자 | | 작성자 (미지정 시 "할당되지 않음") |
| 담당자 / 동료 | | 선택한 이슈의 담당자·협업자 표시 |
| 날짜 | 필수 | 작업한 날짜 |
| 시작 시간 / 종료 시간 | 필수 | 작업한 시간대. 종료가 시작보다 늦어야 하며, 아래에 **계산된 시간**(예: 3시간 30분)이 표시됩니다 |
| 업무 설명 | | 마크다운 서식 편집기 |

> **예전에 기록한 워크로그를 수정할 때** 시작~종료로 표현할 수 없는 건(자정을 넘기는 등)은 **소요 시간** 입력란으로 바뀌며 "같은 날짜의 시간 범위로 표현할 수 없어 소요 시간으로 수정합니다"라고 안내됩니다. 형식은 Jira 표준(`6h 45m`)입니다.

> **업무 설명 편집기**는 제목·목록·인용·링크·코드 블록 등 마크다운 서식을 지원하며, 내용은 Jira 워크로그에 저장됩니다. 기존 워크로그에 **이미지·멘션**처럼 편집기가 다룰 수 없는 내용이 있으면 본문은 잠기고 "본문은 Jira에서 수정하세요"가 표시됩니다. 이때도 날짜·시간은 여기서 고칠 수 있고 본문은 그대로 보존됩니다.

#### 방법 2. 기간 입력(일괄)

날짜 범위에 대해 워크로그를 **한 번에 여러 건** 생성합니다.

| 항목 | 필수 | 설명 |
|---|---|---|
| 업무 | 필수 | 대상 이슈 |
| 시작일 / 종료일 | 필수 | 기록할 기간 |
| 하루 시작 시간 / 종료 시간 | 필수 | 매일 적용할 근무 시간대 (예: 09:00~17:00) |
| 주말 제외 | | 토·일 제외 |
| 공휴일 제외 | | [휴일 관리](#79-휴일-관리)에 등록된 휴일 제외 |
| 연차/휴가 제외 | | 연차·휴가일 제외 |
| 업무 설명 | | 상세 내용 |

- 입력값에 따라 하단에 **"워크로그 N개 생성 · 하루 8h · 총 40.0h"** 처럼 결과가 미리 표시됩니다.
- **일괄 생성이 중간에 실패하면 이미 만든 것까지 모두 취소(롤백)** 됩니다. 취소까지 실패한 경우에만 "일부 항목은 취소하지 못했습니다" 안내가 뜨므로 목록에서 확인하세요.

마지막에 **추가**로 저장, **닫기**로 취소합니다.

> Jira 이슈 화면을 이미 열어 두었다면 앱으로 오지 않고 그 자리의 **Moves Workforce 패널**에서 바로 기록할 수도 있습니다 — [10장](#10-jira-이슈-화면의-moves-workforce-패널).

### 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| 목표 시간이 예상과 다릅니다 | [일반 설정](#71-일반-설정)의 1Day 근무 시간과 [휴일 관리](#79-휴일-관리)의 공휴일 등록 상태를 확인하세요 |
| 워크로그 수정 버튼이 눌리지 않습니다 | 다른 사람이 작성한 워크로그입니다. 작성자 본인만 수정할 수 있습니다 |
| "Jira 워크로그 작성 권한이 없어 등록할 수 없습니다" | 그 Jira 프로젝트에서 Work On Issues 권한이 없습니다. Jira 프로젝트 관리자에게 요청하세요 |
| 이슈 모드로 바꿨는데 달력이 비어 있습니다 | 내 이슈에 시작일·기한이 없습니다. **기간 미설정 N건** 버튼에서 목록을 확인하고 간트에서 일정을 지정하세요 |
| My 프로젝트에 프로젝트가 안 보입니다 | 그 프로젝트의 [인력 관리](#52-인력-관리)에 본인이 등록돼 있어야 합니다 |
| 이슈 목록에 내 작업이 없습니다 | 담당자 또는 동료로 지정돼 있어야 합니다 |

## 3. 마이페이지

### 접근 권한

| 구분 | 필요 권한 |
|---|---|
| 화면 조회 | **권한 불필요** — 사이드바에 항상 표시됩니다 |
| 내 프로젝트·작업·워크로그·내 권한 | **권한 불필요** (본인 데이터) |
| 내 스킬 편집 | **권한 불필요** (본인 데이터) |
| **내 팀** 영역 | **팀장으로 등록**돼 있어야 합니다 (권한 항목이 아니라 *팀장 관계*로 열립니다) |
| 팀원 스킬 편집 | 팀장 관계 (또는 「자원관리」 쓰기) |

- **내 팀**은 권한 세트를 아무리 넓게 줘도 팀장이 아니면 나타나지 않습니다. 반대로 Member 세트여도 팀장이면 보입니다. 팀장 지정은 [7.3 팀 관리](#73-팀-관리)에서 합니다.
- 팀장은 이 화면에서 **팀원 스킬만** 편집할 수 있습니다. 직무·등급·급여·권한은 관리자 소관입니다.

---

**언제 쓰나** — 기간을 정해 **내 업무 성과를 정리**하거나, 팀장이라면 **팀원 업무 현황을 확인**할 때 씁니다.

기본 기간은 이번 달이며 이번 주·최근 3개월·직접 지정으로 바꿀 수 있습니다.

![그림 3-1 마이페이지 내 현황](./Moves_Workforce_사용자_매뉴얼/images/03-mypage-overview.png)
*그림 3-1. 마이페이지 — ① 기간 선택 ② 요약 KPI ③ 나에게 할당된 프로젝트(선택 시 아래가 그 범위로 좁혀짐) ④ 작업 목록 ⑤ 기여 차트 ⑥ 내 권한·내 스킬.*

### 3.1 내 현황

| 영역 | 내용 |
|---|---|
| **요약 KPI** | 처리율, 할당 작업, 진행/완료/남은 작업, 지연, 기간 투입(h/MD), 일평균 투입 |
| **나에게 할당된 프로젝트/작업** | 프로젝트를 선택하면 그 아래 작업·차트·워크로그가 모두 그 범위로 좁혀집니다. 작업은 내가 담당자 **또는 협업자**인 이슈입니다 |
| **기여 차트·워크로그** | 작업 상태 분포, 일별 투입 시간, 작업별 투입 TOP 8, 워크로그 목록과 작업별 합계, Excel 내보내기 |
| **내 권한·내 스킬** | 지금 적용 중인 권한 세트와 프로젝트 조회 범위를 확인하고, 본인의 보유 스킬을 직접 편집합니다 |

> **내 권한 영역이 유용한 순간:** "왜 이 화면이 안 보이지?" 싶을 때 여기서 내 권한 세트와 [조회 범위](#14-권한의-기본-개념)를 먼저 확인하면 관리자에게 정확히 요청할 수 있습니다. 권한 항목별 읽기/쓰기가 표로 보입니다.

> **내 스킬**에 등록한 값은 [자원 관리](#6-자원-관리)의 인력 검색과 [프로젝트 배정 적합도](#64-프로젝트-배정) 계산에 쓰입니다. 선택지는 [스킬 관리](#76-스킬-관리)에서 정의한 사전을 따릅니다.

### 3.2 내 팀 (팀장 전용)

팀장으로 등록된 사용자에게만 나타납니다. 자신이 이끄는 팀과 하위 팀을 선택해 다음을 확인합니다.

![그림 3-2 마이페이지 내 팀](./Moves_Workforce_사용자_매뉴얼/images/03-mypage-myteam.png)
*그림 3-2. 내 팀 — ① 팀 선택(이끄는 팀·하위 팀) ② 팀원별 가동률·투입·완수율 표(팀장 배지) ③ 이슈 상태 분포·참여 프로젝트 ④ 팀원 스킬 편집.*

- 팀원별·팀 소계의 **가동률**, 투입 공수, 완수율
- 이슈 상태 분포, 참여 프로젝트

**규칙**

- 같은 이슈에 여러 팀원이 참여해도 **팀 이슈 건수는 한 번만** 셉니다.
- 팀장은 이 화면에서 **팀원 스킬만** 편집할 수 있습니다. 직무·등급·급여·권한은 관리자 소관입니다.
- 팀장은 항상 자기 팀의 구성원이므로 팀원 목록 맨 앞에 **팀장** 배지와 함께 나옵니다.

> 팀장 지정은 [7.3 팀 관리](#73-팀-관리)에서 합니다. 이 영역이 보이지 않으면 팀장으로 등록돼 있는지 확인하세요.

## 4. 프로젝트 관리

### 접근 권한

| 구분 | 필요 권한 |
|---|---|
| 메뉴 노출 | **권한 불필요** — 사이드바에 항상 표시됩니다 |
| **프로젝트 목록** 탭 | 「프로젝트 관리」 읽기 (없으면 탭이 보이지 않습니다) |
| 프로젝트 추가·수정·삭제, 필요 스킬 편집 | 「프로젝트 관리」 쓰기 |
| **칸반 보드** 탭 | 「칸반 보드」 읽기 |
| 칸반 카드 드래그·컬럼 추가·삭제 | 「칸반 보드」 쓰기 |

- 두 탭은 **권한이 서로 다릅니다.** 「프로젝트 관리」만 있으면 목록만, 「칸반 보드」만 있으면 칸반만 보입니다.
- 보이는 프로젝트 **범위**는 권한 세트의 조회 범위(전체 / 소속 프로젝트만 / 내 팀만)를 따릅니다 — [1.4 참고](#14-권한의-기본-개념).

---

**언제 쓰나** — 프로젝트를 **만들고, 상태를 관리하고, 상세로 진입**하는 출발점입니다.

좌측 **프로젝트 관리** 메뉴로 진입하며 상단에 두 탭이 있습니다: **프로젝트 관리**(목록), **칸반 보드**. 선택한 탭은 주소에 남아 새로고침해도 유지됩니다.

### 4.1 프로젝트 목록

![그림 4-1 프로젝트 목록과 상세 드로어](./Moves_Workforce_사용자_매뉴얼/images/04-project-list-drawer.png)
*그림 4-1. 프로젝트 목록 — ① 이름 검색 ② + 프로젝트 추가 ③ 행 클릭으로 열린 상세 드로어(기간·참여 인력·요구 스킬·상세 페이지 열기).*

| 컬럼 | 설명 |
|---|---|
| 프로젝트 이름 | **이름을 클릭**하면 [프로젝트 상세](#5-프로젝트-상세)로 이동 |
| 프로젝트 상태 | 색 라벨. 예: To Do / IN PROGRESS / DONE ([7.7에서 정의](#77-프로젝트-상태-관리)) |
| 시작일 / 종료일 | 프로젝트 기간 |
| 프로젝트 비용 | 프로젝트 등록 시 입력한 예산값. 급여 정책으로 계산하는 **계획 인건비와는 별개** |
| 추가 작업 | 수정 / 삭제 |

- 상단 **프로젝트 이름** 입력 후 **검색**으로 필터링, 새로고침 아이콘으로 목록 갱신
- 우측 위 **+ 프로젝트 추가**로 새 프로젝트 등록
- **행의 빈 곳을 클릭**하면 오른쪽에 **상세 드로어**가 열립니다. 상세 페이지로 들어가지 않고 기간·참여 인력·요구 스킬을 훑어보고, **수정 / 삭제 / 상세 페이지 열기**로 이어갈 수 있습니다.

#### 프로젝트 추가 / 수정

![그림 4-2 프로젝트 추가 창](./Moves_Workforce_사용자_매뉴얼/images/04-project-modal.png)
*그림 4-2. 프로젝트 추가 창 — ① 기본 정보 ② 필요 스킬(직군 필터·검색·선택 목록) ③ 저장.*

| 항목 | 필수 | 설명 |
|---|---|---|
| 프로젝트 이름 | 필수 | |
| 프로젝트 상태 | 필수 | 프로젝트 상태 관리에서 정의한 값 중 선택 |
| 시작일 / 종료일 | 필수 | |
| 프로젝트 비용 | 필수 | 숫자(천 단위 콤마 자동). 비용 분석의 계획 인건비와는 별개 |
| **필요 스킬** | | 이 프로젝트에 필요한 스킬을 [스킬 사전](#76-스킬-관리)에서 고릅니다. 직군으로 좁히거나 이름으로 검색해 선택하며, 나중에 바꿀 수 있습니다 |

> 수정 모드에서는 **등록·수정 정보**(생성자/생성일시·수정자/수정일시)가 읽기 전용으로 함께 표시됩니다.

> **필요 스킬은 프로젝트 저장 시 함께 반영됩니다.** 기본 정보는 저장됐는데 스킬 저장이 끝나지 않으면 "다시 저장해 주세요" 안내가 뜨며 선택 내역은 유지됩니다. 여기서 정한 스킬이 [6.4 프로젝트 배정](#64-프로젝트-배정)의 **적합도** 계산 기준이 됩니다.

> **기간 입력을 빠뜨리지 마세요.** 프로젝트 시작일·종료일이 없으면 **인건비 환산(투입 개월수)과 진척률 계산이 모두 0**이 됩니다([5.2](#인건비가-0원으로-나올-때), [5.5](#554-진척률) 참고).

#### 프로젝트 삭제

프로젝트를 삭제하면 소속 인력·대시보드·간트·스킬 매핑 등 관련 데이터가 함께 삭제되며 되돌릴 수 없습니다. 확인 후 **삭제 진행** 창이 열려 단계별 진행 상태(이슈 연결 해제 → 간트 연결 정리 → 스킬 정리 → …)를 보여줍니다.

- **Jira 이슈 자체는 삭제되지 않습니다.** 이슈에 남아 있던 이 프로젝트와의 연결만 해제됩니다.
- 중간에 실패하면 진행 상태가 보존되어 **삭제 재시도**로 이어서 진행할 수 있습니다.
- "연결된 Jira 이슈에 접근할 수 없어 삭제를 완료할 수 없습니다"가 뜨면, 그 이슈를 볼 수 있는 관리자에게 재시도를 요청하세요. 삭제는 실행자의 Jira 권한으로 이슈를 정리하기 때문입니다.

### 4.2 칸반 보드

프로젝트를 **상태 컬럼별 카드**로 보여주며 드래그로 상태를 바꾸는 보드입니다.

![그림 4-3 칸반 보드](./Moves_Workforce_사용자_매뉴얼/images/04-kanban-board.png)
*그림 4-3. 칸반 보드 — ① 상태 컬럼 ② 프로젝트 카드(드래그 중) ③ 컬럼 하단 + 프로젝트 추가 ④ 우측 끝 컬럼 추가.*

- **컬럼 = 프로젝트 상태**([프로젝트 상태 관리](#77-프로젝트-상태-관리)에서 정의한 순서)
- **카드 = 프로젝트**(프로젝트명, 기간, 담당 아바타)

| 하고 싶은 일 | 조작 |
|---|---|
| 상태 변경 | 카드를 다른 컬럼으로 **드래그** (즉시 반영) |
| 프로젝트 수정 | 카드 클릭 → 추가/수정 모달 |
| 이름만 빠르게 변경 | 카드 제목 **인라인 편집** |
| 프로젝트 삭제 | 카드 메뉴 → 삭제 (목록과 같은 삭제 진행 창) |
| 상태 컬럼 추가 | 우측 끝 **+** 버튼 |
| 상태 이름 변경 | 컬럼 헤더 인라인 수정 |
| 상태 삭제 | 컬럼 메뉴 → 삭제 (최소 1개 필요, 이전 상태가 있어야 가능) |
| 그 상태로 프로젝트 신규 등록 | 각 컬럼 하단 **+ 프로젝트 추가** |
| 과거 프로젝트 더 보기 | 마지막(완료) 컬럼 하단 **더보기** |

> 쓰기 권한(「칸반 보드」 쓰기)이 없으면 드래그·추가·삭제·이름 변경이 비활성화되고 **조회만** 가능합니다.
> 상태 변경은 서버에서도 검증합니다. 거부되면 카드가 원래 컬럼으로 되돌아가고 사유가 표시됩니다.

### 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| 목록 탭 또는 칸반 탭이 없습니다 | 각각 「프로젝트 관리」 읽기, 「칸반 보드」 읽기 권한이 없습니다 |
| 내가 참여하는 프로젝트가 안 보입니다 | 조회 범위가 "소속 프로젝트만"인데 [인력 관리](#52-인력-관리)에 등록돼 있지 않습니다 |
| 칸반이 비어 있습니다 | 상태 컬럼이 하나도 없습니다. [7.7](#77-프로젝트-상태-관리)에서 상태를 먼저 만드세요 |
| 삭제가 중간에 멈췄습니다 | 삭제 진행 창의 **삭제 재시도**를 누르세요. Jira 이슈 접근 권한이 없어 멈춘 경우 권한 있는 관리자가 재시도해야 합니다 |

## 5.1 대시보드

### 접근 권한

| 구분 | 필요 권한 |
|---|---|
| 화면 조회 | 「대시보드」 읽기 |
| 위젯 추가·레이아웃 편집·삭제·커스텀 필터 편집 | 「대시보드」 쓰기 |
| **총 인건비** 카드, 급여 분포·비용 소진 위젯 | 「비용」 읽기 (없으면 **항목 자체가 표시되지 않음**) |
| 상태별 분포·계획 대비 실적·진척 추이·지연 이슈 등 분석 위젯 | 「리포트」 읽기 (없으면 위젯 자리에 "분석 리포트 열람 권한이 필요합니다" 안내) |

- 급여 정책이 **등급 기반**이면 「비용」이 있어도 총 인건비 카드와 급여 분포 위젯이 숨겨집니다([7.1](#71-일반-설정)).
- 대시보드 데이터는 프로젝트 단위라 **조회 범위 밖 프로젝트**에서는 열리지 않습니다.

![그림 5-2 프로젝트 대시보드 전체](./Moves_Workforce_사용자_매뉴얼/images/05-dashboard-overview.png)
*그림 5-2. 대시보드 — ① 요약 카드 6개 ② 위젯 그리드 ③ 편집 / 차트 추가 버튼. "전부 추가" 직후의 기본 배치로 캡처.*

### 상단 요약 카드

| 카드 | 의미 |
|---|---|
| 프로젝트 참여 인력 | [인력 관리](#52-인력-관리)에 등록된 인원 수 |
| 프로젝트 기간 | 시작일 ~ 종료일 |
| 총 인건비 | 「비용」 읽기 권한자에게만. 급여 정책이 [등급 기반](#계산-방식은-급여-정책이-결정합니다)이면 숨김 |
| 진척률 | 완성 진척(계획 공수 가중). [5.5.4 진척률](#554-진척률)과 같은 값 |
| 남은 기간 | 종료일까지 D-day. 기간이 없으면 "기간 미설정" |
| 지연 이슈 | 기한이 지났는데 완료되지 않은 이슈 수 |

> 이슈가 아주 많은 프로젝트는 "이슈가 많아 일부만 집계했습니다"가 함께 표시됩니다. 실제 값은 표시된 값보다 큽니다.

### 위젯 종류

**차트 추가**에서 고를 수 있는 데이터 유형입니다. 유형마다 어울리는 차트 종류가 정해져 있습니다.

| 데이터 유형 | 차트 | 무엇을 보여주나 |
|---|---|---|
| 역할 분포 / 등급 분포 / 팀 분포 | 도넛·바 | 참여 인력의 역할·등급·소속 팀 구성 비율 |
| 담당자 분포 | 도넛·바 | 이슈 담당자별 분포 |
| 작업 분포 | 도넛·바 | 이슈별 참여 인원 분포 |
| 급여 분포 | 바 | 인건비 구간별 인원 (「비용」 권한) |
| 워크로그 | 히트맵 · 멀티 라인 | 일자별 작업 시간 강도(히트맵은 **일일 용량** 대비 0h / 0~1h / 1~4h / 4~8h / 8h+ 단계) 또는 작업자별 일별 추이 |
| 상태별 분포 | 도넛 | 완료 / 진행 중 / 할 일. **건수 기준 ↔ 공수 기준** 전환 |
| 계획 대비 실적 | 바 | 계획 공수(MD) 합계 vs 실투입 공수 |
| 지연·임박 이슈 | 목록 | 기한 초과·임박 미완료 이슈를 위험한 순서로. 전체/지연/임박 필터, 클릭 시 Jira로 이동 |
| 이슈 규모 | 트리맵 | 어느 이슈가 작업량을 많이 차지하는지 면적으로 비교. **실투입 ↔ 계획** 전환 |
| 관계 토폴로지 | 관계망 | 이슈–하위 이슈–연결 이슈–워크포스 상위 관계를 그래프로. 원 크기 = 투입 시간, 색 = 소속 Jira 프로젝트. "관계 있는 이슈만" 토글 |
| 진척 추이 | S-curve | 계획 누적 vs 실적 누적 공수. [진척률 탭](#554-진척률)과 같은 데이터 |
| 비용 소진 | 번업 | 월별 누적 인건비 vs 예산선 (「비용」 권한). [비용 탭](#555-비용)과 같은 데이터 |
| 커스텀 필터 | 목록 | 담당자·상태·이슈 타입·우선순위·기한·계획 공수 조건을 직접 지정해 원하는 이슈만 모아 봄 |

각 위젯은 **차트/표 전환**, **펼치기**, **새로고침**, **계산식 안내(ⓘ)** 를 제공합니다. 조회가 무거운 위젯(토폴로지·진척 추이·비용 소진 등)에는 **무거움** 배지가 붙고, 이슈가 많은 프로젝트에서는 로딩이 오래 걸릴 수 있습니다.

![그림 5-3 차트 추가 창](./Moves_Workforce_사용자_매뉴얼/images/05-dashboard-add-chart.png)
*그림 5-3. 차트 추가 — ① 추천(템플릿) ② 직접 선택(데이터 유형 → 차트 타입) ③ 전부 추가(추가 예정 수·건너뛸 수 안내).*

### 대시보드 꾸미기

1. 우측 위 **편집**을 누릅니다.
2. 위젯을 **드래그해 재배치**하거나 모서리를 끌어 **크기를 조정**합니다.
3. **차트 추가**로 위젯을 늘립니다.
   - **추천(템플릿)**: 목적별 묶음 — 인력 분석(역할·등급) / 비용 분석(급여) / 업무 분석(작업·담당자) / **프로젝트 건강**(상태별 분포·지연 임박·계획 대비 실적) / **작업 규모**(이슈 규모·상태별 분포) / **일정·비용 심층**(진척 추이·비용 소진)
   - **직접 선택**: 데이터 유형을 고른 뒤 그에 맞는 차트 종류와 이름을 지정
   - **전부 추가**: 지금 권한으로 볼 수 있는 위젯을 **한 번에** 추가합니다. 이미 있는 위젯은 건너뛰며, 배치는 정해진 줄 순서로 채워집니다
4. **편집 완료**를 누르면 배치가 **프로젝트별로 저장**됩니다.

#### 커스텀 필터 위젯 쓰기

1. 커스텀 필터 위젯을 추가하면 처음엔 "조건이 설정되지 않아 전체 이슈를 표시합니다" 상태입니다.
2. 위젯의 **필터 편집**에서 담당자(**나** 선택 가능)·상태·이슈 타입·우선순위·기한(기한 초과 / 임박 / 기한 없음)·계획 공수(입력됨 / 미입력)를 조합합니다. 아래에 **현재 조건: N건** 미리보기가 갱신됩니다.
3. 저장하면 조건이 위젯과 함께 프로젝트에 저장되어 다른 사용자에게도 같은 목록이 보입니다.

### 알아두기

- 담당자 분포·지연 이슈 등 이슈 기반 위젯은 [작업 관리](#53-작업-관리)에 편입된 이슈만 대상으로 합니다.
- 역할·등급·팀 분포는 [인력 관리](#52-인력-관리)에서 각 멤버에게 부여한 값 기준입니다. 값이 비어 있는 인원은 분포에서 빠집니다.
- 「리포트」 권한이 없는 사용자가 대시보드를 열면 분석 위젯 자리에 권한 안내만 보이고 나머지 위젯은 정상 표시됩니다. 위젯이 잘못된 것이 아닙니다.
- 더 깊은 분석(담당자별 계획 대비 실적, 가동률, 지연 원인 이슈)은 [5.5 분석 및 리포트](#55-분석-및-리포트)를 사용하세요.

### 5.2.1 담당 팀

인력 목록 상단에서 **담당 팀 여러 개**와 **주 담당 팀 하나**를 지정할 수 있습니다.

> **담당 팀과 프로젝트 인력은 별개 축입니다.** 팀을 지정해도 인력이 자동으로 추가되지 않습니다. 인력으로 넣으려면 **팀 전체 추가** 또는 **팀원 골라 담기**를 실행해야 합니다.

- 팀 카드에는 `이미 투입된 인원 / 팀 직속 인원`이 표시됩니다.
- **팀 전체 추가**는 이미 투입된 인원을 건너뛰고 나머지만 등록합니다. 결과는 "N명 추가, M명 건너뜀"으로 안내됩니다. 이 프로젝트의 담당 팀이 아닌 팀은 추가할 수 없습니다.
- 담당 팀을 모두 해제하면 이 프로젝트의 팀 배정이 사라진다는 경고가 표시됩니다.

> 팀 구성 자체는 [7.3 팀 관리](#73-팀-관리)에서 합니다.

| 역할 | 예: DevOps Engineer, Data Engineer ([7.4에서 정의](#74-역할-관리)) |

| 추가 작업 | 삭제 |

#### 인력 추가하기

1. 우측 위 **+ 사용자 추가**를 누릅니다.
2. Jira 사용자를 **이름 또는 이메일로 검색**합니다.
3. 추가 후 **역할 / 등급 셀을 클릭**해 그 자리에서 지정합니다.

> 급여 수정은 「비용」 권한이 있는 사용자가 **급여 관리** 서브탭에서 수행합니다.

> **여기 등록해야 집계에 들어갑니다.** 이슈 담당자로만 지정된 사람은 인건비·가동률 집계에 포함되지 않습니다.

### 5.2.3 급여 관리

이 화면에서 정한 금액이 **비용 탭 · 대시보드 총 인건비 · 전사 대시보드 비용 축**의 원천이 됩니다.

![그림 5-5 급여 관리 서브탭](./Moves_Workforce_사용자_매뉴얼/images/05-salary-management.png)
*그림 5-5. 급여 관리(인원별 정책) — ① 인원별 투입 유형(프로젝트/연봉) ② 투입 급여·개인 연봉 ③ 계산된 인건비 ④ 정책 안내. 금액은 예시 데이터로 캡처.*

#### 금액이 저장되는 세 곳

| 구분 | 입력 화면 | 의미 |
|---|---|---|
| **개인 연봉** | [설정 > 인력 관리](#72-인력-관리) | 그 사람의 연봉. 프로젝트와 무관한 인사 정보 |
| **투입 급여** | 프로젝트 상세 > 인력 > **급여 관리** | **이 프로젝트에** 그 사람을 쓰는 데 잡는 금액 |
| **등급 급여 밴드** | [설정 > 등급 관리](#75-등급-관리) | 등급별 가격표(하한·상한·대표값). 개인이 아니라 직급에 값을 매김 |

세 곳이 나뉜 이유는 조직마다 인건비를 잡는 방식이 다르기 때문입니다. 사람별로 잡는 곳도 있고, 직급 테이블로 일괄 산정하는 곳도 있습니다.

#### 계산 방식은 급여 정책이 결정합니다

전역 설정([설정 > 일반 설정 > 급여 정책](#71-일반-설정))에서 조직 전체가 쓸 방식을 하나 고릅니다.

##### ① 인원별(기본값)

사람별 금액을 그대로 씁니다. 프로젝트 인력마다 **투입 유형**을 다시 고릅니다.

| 투입 유형 | 계산 | 언제 쓰나 |
|---|---|---|
| **프로젝트** (기본) | 투입 급여를 **그대로** 인정 | "이 프로젝트에 3,000만원어치 투입" 같은 계약 단위 |
| **연봉** | 연봉을 **투입 기간만큼 잘라서** 인정 | 정규 인력을 기간 비례로 배분할 때 |

> 두 금액(투입 급여·개인 연봉)이 모두 저장돼 있어도 **선택한 투입 유형에 해당하는 금액만** 계산에 씁니다.

##### ② 등급 기반

개인 금액을 **아예 읽지 않고** 그 사람의 등급 대표값으로 계산합니다. 개인 연봉을 노출하지 않으면서 원가를 산출하고 싶을 때 사용하며, 이 정책에서는 개인 금액 편집이 잠깁니다.

> 저장된 개인 금액을 **지우지는 않습니다.** 정책을 되돌리면 원래 숫자가 그대로 살아납니다.

#### 계산식

**연봉** 유형과 **등급 기반** 정책은 **같은 식**을 씁니다. 연봉을 어디서 가져오는지만 다릅니다.

```
투입 개월수 = 총 달력일수(종료일 포함) ÷ 30.4375
인건비      = (연봉 ÷ 12) × 투입 개월수
```

- 연봉 유형은 **개인 연봉**에서, 등급 기반은 **등급 대표값**에서 연봉을 가져옵니다.
- 프로젝트 유형은 환산 없이 투입 급여를 그대로 씁니다.
- **30.4375**는 365.25 ÷ 12로, 윤년까지 반영한 평균 월 길이입니다.

**근무일이 아니라 달력일을 쓰는 이유** — 공휴일과 연차에도 급여는 지급되기 때문입니다. 실제 지급 방식과 맞추기 위해 달력일 기준을 사용합니다.

| 프로젝트 기간 | 달력일 | 투입 개월수 |
|---|---|---|
| 1/1 ~ 12/31 | 365일 | 11.99 (≈ 12개월) |
| 15일간 | 15일 | 0.49 |
| 하루 (시작일 = 종료일) | 1일 | 0.03 |

#### 인건비가 0원으로 나올 때

[비용 화면](#555-비용)의 **미산정 인원** 지표로 확인할 수 있습니다.

| 정책 | 0원이 되는 조건 |
|---|---|
| 인원별 | 투입 유형이 **연봉**인데 **개인 연봉이 등록되지 않음** |
| 등급 기반 | 등급 미지정 / 등급에 밴드 미설정 / 대표값이 0 |
| 공통 | **프로젝트 기간이 설정되지 않음** → 투입 개월수 0 → 결과 0 |

> 프로젝트 유형의 0원은 미산정으로 세지 않습니다. "무상 투입"이라는 정상적인 배정일 수 있기 때문입니다.

#### 누가 볼 수 있나

급여 금액이 보이려면 **두 조건이 모두** 충족돼야 합니다.

1. 「비용」 **읽기 권한**이 있을 것
2. 급여 정책이 **인원별**일 것 (등급 기반에서는 개인 금액이 숨겨집니다)

권한이 없으면 금액이 **0원으로 표시되는 것이 아니라 항목 자체가 나타나지 않습니다.** 대시보드의 총 인건비 카드도 마찬가지입니다.

### 5.2.4 작업 배정

"이 사람에게 무엇을 맡길까"를 정하는 화면입니다. 좌우 패널은 접거나 폭을 조절할 수 있습니다.

- 프로젝트 인력 후보의 **스킬 적합도**와 **현재 부하**를 함께 보고 이슈 또는 프로젝트에 배정합니다.
- 배정할 이슈가 없으면 확인 후 **프로젝트 인력으로만 추가**할 수도 있습니다.

> 담당자·동료를 지정하는 세 가지 경로의 차이는 [5.3 담당자·동료 관리](#지정하는-세-가지-경로)를 참고하세요.
> 전사 범위로 사람을 찾아 배정하려면 [6.4 프로젝트 배정](#64-프로젝트-배정)을 사용합니다.

## 5.3 작업 관리

### 접근 권한

| 구분 | 필요 권한 |
|---|---|
| 목록·트리·간트·맵 조회 | 「프로젝트 관리」 읽기 |
| 작업 추가(편입)·프로젝트에서 제외 | 「프로젝트 관리」 쓰기 |
| 인라인 편집·일괄 적용(담당자·동료·일정·계획 작업량) | 「프로젝트 관리」 쓰기 **+ Jira 이슈 편집 권한** |
| 트리·간트 편집(일정·선후행·상위 지정·폴더) | 「프로젝트 관리」 쓰기 **+ Jira 권한**(아래) |
| 자동 편입(구독) 설정 | 「프로젝트 관리」 쓰기 |

**함께 필요한 Jira 권한**

| 작업 | Jira 권한 |
|---|---|
| 일정 변경 | 이슈 편집 · 일정 관리 |
| 담당자 지정 | 담당자 지정 |
| 선후행 연결 | 이슈 연결 |
| 계획 작업량(MD) | 이슈 편집 + 프로젝트의 **시간 추적 활성화** |

- 트리·간트·맵은 「프로젝트 관리」 읽기만 있으면 **조회 전용**으로 열립니다(간트 툴바에 "조회 전용" 배지). 맵은 원래 읽기 전용입니다.
- 권한이 없으면 보기 전환 버튼에서 해당 보기가 빠지고, 남는 보기가 하나뿐이면 전환 버튼 자체가 사라집니다.
- 앱 권한이 있어도 Jira 권한이 없으면 **저장 시점에 거부**되고 사유가 안내됩니다.

**언제 쓰나** — 프로젝트의 모든 작업(이슈)을 **찾고, 담당을 정하고, 구조와 일정을 잡을** 때.

같은 작업 묶음을 **목록 / 트리 / 간트 / 맵** 네 가지 방식으로 봅니다(우측 위 전환 버튼). 선택한 보기는 주소에 실려 새로고침·링크 공유 시 유지됩니다.

| 보기 | 무엇에 쓰나 | 잘하는 일 |
|---|---|---|
| **목록** (기본) | 작업을 찾고 추가·수정 | 검색·필터, 작업 추가/제외, 셀 인라인 편집, **여러 건 일괄 적용** |
| **트리** | 작업의 **구조**를 보고 정리 | 상위-하위·폴더 계층 정리(드래그), 한 작업의 모든 정보 확인 |
| **간트** | 작업의 **일정**을 보고 조정 | 기간 조정, 선후행 연결, 전체 일정 조망, 전체 화면 |
| **맵** | 구조를 **한 장의 그림**으로 | 프로젝트 → 폴더 → 작업 조직도, 선후행 점선, 카드 클릭 상세(읽기 전용) |

- 트리·간트·맵은 **같은 데이터**를 봅니다. 한쪽에서 바꾸면 다른 쪽에도 그대로 반영됩니다.

### 5.3.1 목록 보기

![그림 5-6 작업 관리 목록 보기](./Moves_Workforce_사용자_매뉴얼/images/05-work-list.png)
*그림 5-6. 목록 보기 — ① 필터(업무 검색·스페이스·담당자·상태·이슈 타입) ② 계층/평면 토글 ③ 체크박스 선택과 일괄 적용 / 프로젝트에서 제외 ④ 보기 전환(목록·트리·간트·맵) ⑤ + 작업 추가 ⑥ 자동 편입 요약.*

- 상단 필터: **업무 검색**, **스페이스**(Jira 프로젝트), **담당자**, **상태**, **이슈 타입**
- 우측 위 **+ 작업 추가**
- **계층 / 평면** 토글: 계층은 Jira 상위–하위 구조로 묶어 보여주고(행 왼쪽 화살표로 펼침/접기, **모두 펼치기 / 모두 접기**), 평면은 모든 이슈를 한 줄씩 나열합니다. 계층 보기에서는 **페이지 단위가 상위 이슈 기준**이라 하위 작업은 상위와 같은 페이지에 함께 나옵니다.

| 컬럼 | 설명 |
|---|---|
| 프로젝트 | 소속 Jira 프로젝트(스페이스) |
| 키 | 이슈 키와 이슈 타입 아이콘 |
| 업무 | 이슈 제목 |
| 상태 | 할 일 / 진행 중 / 완료 (색 라벨) |
| 담당자 | 이슈 담당자 |
| 동료 | 협업자(여러 명 지정 가능) |
| 시작일 | 작업 시작일 (셀에서 수정 가능) |
| 기한 | 작업 기한 (셀에서 수정 가능) |
| 계획 작업량 | 계획 공수. 단위 **MD = Man-Day(인일)** (예: 5.1 MD). Jira의 Original Estimate 기반 |
| 처리율 | 진행률 (예: 0% / 5% / 100%) |
| 추가 작업 | **삭제**(프로젝트 연결 해제) |

> **인라인 편집:** **담당자·동료·시작일·기한** 셀을 클릭하면 그 자리에서 수정됩니다. 변경은 해당 Jira 이슈에 즉시 반영됩니다.

> **"작업 추가"는 새 이슈를 만들지 않습니다.** **이미 존재하는 Jira 이슈를 검색해 이 프로젝트에 편입**하는 방식입니다. 목록의 **삭제**도 이슈 삭제가 아니라 **프로젝트 연결 해제**입니다.

#### 일괄 적용과 제외

행 왼쪽 체크박스로 여러 작업을 고르면 상단에 **N건 선택**과 두 버튼이 나타납니다.

![그림 5-7 선택 작업 일괄 적용 창](./Moves_Workforce_사용자_매뉴얼/images/05-work-bulk-apply.png)
*그림 5-7. 일괄 적용 창 — ① 대상 건수 ② 시작일·기한·계획 작업량(비워둔 항목은 변경하지 않음) ③ 적용 결과(성공/실패)와 실패 건만 재시도.*

| 버튼 | 동작 |
|---|---|
| **일괄 적용** | 선택한 작업의 **시작일 · 기한 · 계획 작업량(MD)** 을 한 번에 지정합니다. **비워둔 항목은 바꾸지 않으므로** 기한만 넣으면 시작일은 그대로 유지됩니다. 건별로 저장하며 결과가 "N건 성공 · M건 실패"로 집계되고, 실패 목록에서 **실패 건만 재시도**할 수 있습니다 |
| **프로젝트에서 제외** | 선택한 작업을 이 프로젝트에서 뺍니다. **Jira 이슈 자체는 삭제되지 않습니다** |

- 시작일이 기한보다 늦으면 적용 전에 막힙니다.
- 계획 작업량 저장이 실패하는 건은 대개 그 Jira 프로젝트에서 시간 추적이 꺼져 있는 경우입니다([문제 해결](#539-문제-해결)).

### 5.3.2 담당자·동료 관리

작업에 **누가 매달려 있는지**를 정하는 기능입니다. 여기서 지정한 값이 My Work·마이페이지·인력 분석·가동률 계산의 기준이 됩니다.

#### 담당자와 동료의 차이

| 구분 | 인원 | 성격 | 저장 위치 |
|---|---|---|---|
| **담당자**(Assignee) | **1명** | Jira 기본 기능. 이슈를 **책임지는** 사람 | Jira 이슈의 담당자 필드 |
| **동료**(협업자) | **여러 명** | 이 앱이 추가한 개념. 함께 **수행하는** 사람 | Jira 이슈에 앱이 저장하는 협업자 목록 |

한 이슈에 담당자는 한 명뿐이지만 실제로는 여러 명이 함께 일하는 경우가 많습니다. **동료**는 그 현실을 담기 위한 항목입니다. 담당자와 동료는 **별개 축**이라, 담당자를 바꿔도 동료 목록은 그대로 유지됩니다.

> 동료로 지정되면 그 사람의 **My Work에 "협업 이슈"로 집계**되고, 마이페이지·인력 분석의 작업량에도 반영됩니다. 즉 동료 지정은 단순 표시가 아니라 **집계에 실제로 들어갑니다.**

#### 지정하는 세 가지 경로

| 경로 | 위치 | 쓰임 |
|---|---|---|
| **표 인라인 편집** | 작업 관리 > 목록 | 이슈 하나씩 담당자·동료를 바로 수정 |
| **트리 보기** | 작업 관리 > 트리 | 상위/하위 구조를 보면서 동료 지정 |
| **작업 배정** | [인력 관리 > 작업 배정](#524-작업-배정) | **스킬 적합도와 현재 부하를 비교해** 배정. 여러 건을 한 번에 처리할 때 |

앞의 두 경로는 "이 이슈에 누구를 넣을까", **작업 배정**은 "이 사람에게 무엇을 맡길까" 관점입니다.

#### 등록일·등록자는 자동으로 기록됩니다

작업을 프로젝트에 편입할 때 **누가 언제 등록했는지**가 이슈에 함께 저장되며, [작업 이력](#556-작업-이력) 화면에서 확인할 수 있습니다. 자동 편입으로 들어온 이슈는 등록자가 **"구독"** 으로 표시됩니다.

- **최초 등록 시점만 유지됩니다.** 이미 등록일이 있는 이슈는 다시 편입해도 덮어써지지 않습니다.
- 직접 수정할 수 없는 읽기 전용 값입니다.

#### 지정 결과가 반영되는 곳

| 화면 | 반영 내용 |
|---|---|
| [My Work](#2-my-work) | 담당자·동료인 이슈가 내 작업으로 표시 |
| [마이페이지](#3-마이페이지) | 내 작업·처리율·남은 작업 집계 |
| 작업 관리(목록/트리/간트/맵) | 담당자 필터, 카드·행의 담당자 표시 |
| [분석 및 리포트 > 인력](#552-인력-분석) | 인력별 공수(MD)·가동률 산정 대상 |
| [자원 관리](#6-자원-관리) | 인력별 부하(작업량)·배정 현황 |
| [프로젝트 대시보드](#51-대시보드) | 담당자 분포·커스텀 필터 위젯 |
| [Jira 이슈 화면 패널](#10-jira-이슈-화면의-moves-workforce-패널) | "내 몫" 계산의 참여 인원 |

#### 주의사항

- **동료 지정 직후 목록 필터 결과가 잠깐 예전 상태로 보일 수 있습니다.** Jira 검색 색인 갱신에 시간이 걸리기 때문이며, 값 자체는 이미 저장돼 있습니다.
- **프로젝트 인력과 담당자는 별개입니다.** 이슈 담당자로 지정해도 프로젝트 인력 명단에 자동 추가되지 않습니다. 인건비·가동률 집계에 포함하려면 [인력 관리](#52-인력-관리)에서 별도로 추가해야 합니다.
- 담당자·동료 변경은 **해당 Jira 이슈에 즉시 반영**됩니다.

### 5.3.3 자동 편입(프로젝트 구독)

작업 추가 창의 **구독 설정** 탭에서 Jira **스페이스**(Jira 프로젝트)를 구독하면 조건에 맞는 이슈가 이 프로젝트로 자동 편입됩니다. 매번 손으로 "작업 추가"를 하지 않아도 됩니다.

![그림 5-8 구독 추가와 미리보기](./Moves_Workforce_사용자_매뉴얼/images/05-work-subscription.png)
*그림 5-8. 구독 설정 탭 — ① 소스(스페이스) 선택 ② 세부 조건(이슈 타입·하위 이슈 포함·추가 JQL·기본 계획 작업량) ③ 미리보기(편입 대상·건너뜀·이미 등록됨) ④ 기존 이슈도 가져오기 ⑤ 구독 중인 소스 목록(상태·마지막 동기화·수정·일시 중지·해제).*

#### 설정 절차

1. **소스**에서 스페이스를 고릅니다. **이미 다른 프로젝트가 구독 중인 스페이스는 선택할 수 없고** "○○ 구독중"으로 표시됩니다.
2. 필요하면 **세부 조건**을 펼쳐 지정합니다. 지정하지 않으면 스페이스 전체를 가져옵니다.

| 조건 | 설명 |
|---|---|
| 이슈 타입 | 고른 타입만 가져옵니다. 고르지 않으면 전체 |
| 선택한 이슈의 하위 이슈 포함 | 켜면 **선택한 타입에 해당하는 이슈와 그 이슈들의 하위 이슈**(하위 작업·자식 이슈)를 함께 가져옵니다. 스페이스 전체의 하위 작업이 아닙니다 |
| 추가 조건 (JQL) | 위 조건에 AND로 덧붙습니다(예: `labels = release`). `currentUser()`처럼 보는 사람에 따라 달라지는 함수와 `ORDER BY`는 쓸 수 없습니다 |
| 기본 계획 작업량 | 편입되는 이슈의 예상 시간이 **비어 있을 때만** 이 값(시간, 최대 100)을 채웁니다. 이미 값이 있으면 건드리지 않습니다 |

3. **미리보기**에서 **편입 대상 N건 · 건너뜀 M건(다른 프로젝트에 이미 등록) · 이미 등록됨 K건**을 확인합니다. 선택 타입/하위 이슈 건수가 나뉘어 표시되고 **JQL 보기**로 실제 조건을 볼 수 있습니다.
4. **기존 이슈도 가져오기**를 켜면 기존분을 백그라운드로 가져오고, 끄면 구독 이후 생성되는 이슈부터 가져옵니다.
5. **구독 추가**를 누릅니다.

#### 구독 목록 다루기

구독마다 **누적 N건 편입 · 마지막 동기화 시각 · 상태**가 표시됩니다.

| 상태 | 의미 |
|---|---|
| 정상 | 마지막 동기화 성공 |
| 일부 반영 | 대상이 많아 일부만 처리. 다음 동기화에서 이어집니다 |
| 소스에 접근할 권한이 없습니다 / 소스를 찾을 수 없습니다 | 스페이스 권한이 바뀌었거나 삭제됨 |
| 동기화 오류 | 그 밖의 오류 |

- **수정**: 이슈 타입·하위 이슈·JQL·기본 계획 작업량을 바꿉니다. **바뀐 조건은 다음 동기화부터** 적용되며 이미 편입된 이슈는 되돌아가지 않습니다. 진행 중인 "기존 이슈 가져오기"가 있으면 중단됩니다.
- **일시 중지**: 새 이슈를 가져오지 않습니다. 이미 편입된 이슈는 그대로 남습니다.
- **해제**: 구독을 끝냅니다. 역시 **이미 편입된 이슈는 남습니다.**

#### 운영 규칙

- 프로젝트당 구독은 **최대 10개**, 한 스페이스는 전체에서 **한 프로젝트만** 구독할 수 있습니다.
- 새 이슈는 생성 이벤트로 빠르게 처리하고, 이벤트 누락·이슈 이동·조건 변경은 **1시간마다** 정합성을 확인합니다. "방금 만든 이슈는 바로 안 보일 수 있어요" 안내가 이 때문입니다.
- 목록 보기 상단의 **자동 편입** 요약에서 구독 스페이스를 눌러 그 스페이스만 필터하거나 **지금 동기화**를 실행할 수 있습니다. 지금 동기화는 1시간을 기다리지 않고 바로 확인할 뿐, 생성 시 정한 "구독 이후 생성분만" 조건을 우회하지 않습니다.
- 이슈는 **프로젝트 하나에만** 속합니다. 다른 프로젝트가 이미 등록한 이슈는 구독으로 가져오지 않고 "건너뜀"으로 셉니다.

### 5.3.4 작업 추가 창

**+ 작업 추가**를 누르면 Jira 이슈를 검색해 편입하는 창이 열립니다.

- 검색어에 **이슈 요약(제목) 또는 이슈 키**(예: `SAMPLE-12`)를 입력합니다. 스페이스·상태 등으로 좁힐 수 있습니다.
- 결과 표의 **현재 소속** 컬럼에 그 이슈가 이미 어느 프로젝트에 있는지 표시됩니다 — "○○ 등록됨", "○○ 구독중", 또는 비어 있음.
- 체크해서 **추가**하면 이 프로젝트에 편입됩니다. 등록일·등록자가 자동 기록됩니다.

> **다른 프로젝트에 이미 등록된 이슈를 고르면** 확인 창이 뜹니다. **이슈는 프로젝트 하나에만 속할 수 있어**, 가져오면 원래 프로젝트에서 빠지고 **그동안 쌓인 공수·비용도 함께 옮겨갑니다.** "이 건은 빼고 N건만 등록"으로 그 이슈만 제외할 수도 있습니다.

### 5.3.5 트리·간트·맵 공통 사항

#### 권한

| 권한 | 가능한 일 |
|---|---|
| 「프로젝트 관리」 **읽기** | 트리·간트·맵 조회, 펼침/접기, 줌, 필터, 상세 확인 |
| 「프로젝트 관리」 **쓰기** | 일정·상위·선후행·폴더·담당자·동료·계획 작업량 편집(트리·간트) |

읽기 권한만 있으면 간트 툴바에 **"조회 전용"** 배지가 뜨고 드래그·연결·편집이 잠깁니다. 트리에서는 편집 버튼과 드래그가 나타나지 않습니다. 맵은 권한과 무관하게 항상 읽기 전용입니다.

> Jira 자체 권한도 함께 확인합니다. 앱에서 쓰기 권한이 있어도 Jira에서 **이슈 편집·일정 변경·담당자 지정·이슈 연결** 권한이 없으면 저장이 거부되고 사유가 안내됩니다.

#### 세 가지 계층 개념

| 개념 | 만드는 곳 | 저장 위치 | 특징 |
|---|---|---|---|
| **Jira 하위 이슈** | Jira | Jira 표준 | Jira가 정한 3단계(에픽>스토리>하위작업) 제약을 받습니다 |
| **상위 지정(WBS)** | 이 앱(트리·간트) | 앱이 이슈에 저장 | **단계 제한 없이 자유롭게 중첩**. Jira 상위가 있어도 이 지정이 **우선 적용**됩니다 |
| **폴더** | 이 앱(트리·간트) | 앱 내부 | Jira에 없는 앱 전용 묶음. 이슈가 아니므로 Jira에서는 보이지 않습니다 |

> **왜 상위 지정이 따로 있나요?** Jira는 3단계와 인접 단계만 허용해 4단계 이상 WBS를 만들 수 없습니다. 앱의 상위 지정은 이 제약을 벗어나기 위한 것입니다. 대신 **Jira 화면에는 이 계층이 나타나지 않습니다.**

#### 필터

담당자 · 상태 · **이슈 타입** · 스페이스(여러 스페이스가 섞여 있을 때만 표시) 필터를 세 보기가 공유합니다. 폴더는 필터로 직접 걸러지지 않고, **남은 작업을 기준으로 폴더의 기간·수행율이 다시 계산**됩니다.

### 5.3.6 트리 보기

화면은 좌우로 나뉩니다. **왼쪽은 계층 구조, 오른쪽은 선택한 항목의 상세**입니다. 카드 헤더의 접기 버튼과 경계선으로 폭을 조절할 수 있습니다.

![그림 5-9 트리 보기](./Moves_Workforce_사용자_매뉴얼/images/05-work-tree.png)
*그림 5-9. 트리 보기 — ① 검색·모두 펼치기/접기·폴더 추가 ② 계층 트리(폴더 → 상위 작업 → 하위 작업, 드래그 중) ③ 최상위로 이동 드롭 영역 ④ 상세 패널(속성·연관 관계·워크로그) ⑤ 상위 출처 배지.*

#### 왼쪽: 계층 구조

- **검색**: 작업 키·이름으로 걸러냅니다
- **모두 펼치기 / 모두 접기**
- **폴더 추가** (쓰기 권한)
- 폴더는 항상 같은 단계의 작업보다 위에 표시됩니다
- 항목을 클릭하면 오른쪽에 상세가 열립니다

#### 드래그로 구조 바꾸기 (쓰기 권한)

| 무엇을 | 어디에 놓으면 | 결과 |
|---|---|---|
| 작업 | 다른 작업 위 | 그 작업의 **하위로 지정**(상위 지정) |
| 작업 | 폴더 위 | 그 **폴더에 소속** |
| 작업 | 목록 아래 **"여기에 놓으면 최상위로 이동"** 영역 | **상위 지정 해제** |
| 폴더 | 다른 폴더 위 | 그 폴더의 **하위 폴더로 이동** |
| 폴더 | 최상위 영역 | **최상위 폴더로 이동** |
| 폴더 | 작업 위 | 아무 일도 일어나지 않습니다(작업은 폴더의 상위가 될 수 없습니다) |

- 자기 자신이나 자기 하위로는 옮길 수 없습니다(순환 방지).
- 상위가 지정된 작업을 폴더에 넣으면 **상위 지정이 먼저 해제**됩니다. 한 작업은 "다른 작업의 하위"이면서 동시에 "폴더 소속"일 수 없습니다.
- 같은 규칙이 간트의 행 드래그에도 그대로 적용됩니다.

#### 오른쪽: 선택한 작업의 상세

| 구역 | 내용 |
|---|---|
| 헤더 | 작업 이름, 상태, 이슈 키 |
| 처리율 | 진행률 막대 |
| 속성 | 담당자 / 시작일 / 기한 / 협업자 / 계획 작업량 / Jira 프로젝트 |
| 연관 관계 | 상위 작업 · 하위 이슈 · 선행/후행 작업 · 소속 폴더 · Jira 연결 |
| 쌓인 워크로그 | 이 작업에 기록된 워크로그 목록과 **합계 시간** |

속성의 **연필 아이콘**을 누르면 편집합니다(쓰기 권한). 계획 작업량은 그 자리에서 숫자를 입력하고 Enter로 저장하며, 일정·협업자·상위·폴더는 모달이 열립니다. 여기서 저장한 값은 간트·맵에도 즉시 반영됩니다.

#### 상위 작업의 출처 표시

상위는 **Jira가 정한 것**과 **이 앱에서 지정한 것** 두 가지가 있어, 지금 적용 중인 상위가 어디서 왔는지 배지로 구분합니다.

| 표시 | 의미 |
|---|---|
| **워크포스에서 지정** | 앱에서 지정한 상위가 적용 중 |
| **Jira에서 정의** | Jira 표준 상위가 적용 중 |
| *워크포스 지정으로 가려진 Jira 상위* | 앱 지정이 Jira 상위를 대신하는 중. 가려진 Jira 상위를 함께 표시하며, 상위 지정을 해제하면 Jira 상위로 돌아갑니다 |
| *현재 트리 화면에 없습니다* | 상위 작업이 필터에 걸렸거나 조회 범위 밖입니다 |
| *조회 범위에 없어 적용되지 않았습니다* | 앱에서 지정한 상위 작업이 이 프로젝트에 편입돼 있지 않아 계층이 그려지지 않았습니다 |

#### 선후행(선행 작업 / 후행 작업)

- **연결 추가** 버튼으로 상대 작업을 골라 연결하고, 각 항목의 **×** 로 해제합니다.
- 선후행은 **Jira 이슈 링크(Blocks)로 저장**됩니다. 그래서 간트에서 그렸는지 Jira에서 만들었는지는 **구분되지 않습니다.**
- 상대가 다른 프로젝트에 있거나 조회 범위 밖이면 **읽기 전용**으로 따로 표시됩니다(연결이 사라진 것이 아닙니다).
- 선후행이 아닌 Jira 링크(관련됨, 중복 등)는 아래 **Jira 연결**에 따로 모입니다.

### 5.3.7 간트 보기

왼쪽 표와 오른쪽 타임라인으로 구성됩니다. 경계선을 끌어 좌우 폭을, 컬럼 경계를 끌어 컬럼 폭을 조절할 수 있습니다. 툴바의 **전체 화면**으로 간트만 크게 띄울 수 있습니다.

![그림 5-10 간트 보기](./Moves_Workforce_사용자_매뉴얼/images/05-work-gantt.png)
*그림 5-10. 간트 보기 — ① 툴바(줌 일/주/월·폴더 추가·전체 화면·조회 전용 배지) ② 왼쪽 표 ③ 타임라인(파란 일반 작업·초록 요약 막대·보라 마일스톤·틸 폴더·회색 점선 미설정) ④ 선후행 연결선 ⑤ 오늘·프로젝트 시작/종료 기준선.*

#### 왼쪽 표의 컬럼

| 컬럼 | 내용 | 편집 |
|---|---|---|
| 이슈 | 이슈 타입 아이콘·키·이름 (펼침/접기 화살표 포함) | — |
| 상태 | 할 일 / 진행 중 / 완료 | — |
| 담당자 | 이슈 담당자 | 가능 셀 클릭 |
| 협업자 | 함께 수행하는 인원(여러 명) | 가능 셀 클릭 |
| 시작일 | 시작일. 미설정이면 **일정 설정** 버튼 | 필수 |
| 기간 | 시작~종료 일수 | — |
| 계획 작업량 | 계획 공수(MD) | 가능 셀 클릭 후 입력 |
| 처리율 | 진행률(%) | — |
| 상위 지정 | 상위 작업 선택 (쓰기 권한일 때만 컬럼 표시) | 필수 |

#### 타임라인

- 줌: **일 / 주 / 월**
- 세로 기준선: **오늘**, **프로젝트 시작**, **프로젝트 종료**

| 막대 | 의미 |
|---|---|
| 파란 막대 | 일반 작업 |
| 초록 막대 | **Jira 하위 이슈를 가진 상위 작업** — 하위 기간을 감싸는 요약 막대 |
| 보라 마름모 | 마일스톤(시작일 = 종료일) |
| 회색 점선 막대 | **일정이 없는 작업** — 프로젝트 시작일 위치에 임시 표시 |
| 틸(청록) 막대 | 폴더 — 깊이가 깊을수록 연해집니다 |

> **앱에서 상위 지정한 작업은 초록 요약 막대가 되지 않습니다.** 각자 자기 일정을 가진 **독립 작업**으로 남고, 왼쪽 표에서 펼침/접기만 생깁니다. 초록 요약 막대는 Jira 하위 이슈를 가진 경우에만 나타납니다.

#### 편집 조작 (쓰기 권한)

| 하고 싶은 일 | 조작 |
|---|---|
| 일정 변경 | 막대를 **드래그**(이동) 또는 **끝을 끌어** 기간 조정 |
| 일정 없는 작업에 일정 주기 | 회색 점선 막대를 드래그하거나, 시작일 컬럼의 **일정 설정** 버튼으로 날짜 입력 |
| 선후행 연결 | 한 막대의 **끝점**을 다른 막대로 드래그 |
| 선후행 해제 | 연결선을 선택해 삭제 |
| 계층 만들기 | 왼쪽 표에서 행을 **드래그**하거나 **상위 지정** 컬럼에서 선택 |
| 이슈를 폴더로 옮기기 | 행을 폴더 위로 드래그하거나 행 메뉴의 **폴더 이동**. 상위 지정된 이슈는 먼저 상위 지정이 해제됩니다 |
| 폴더 만들기·정리 | 툴바 **폴더 추가**, 행 메뉴에서 이름 변경/하위 폴더 추가/이동/삭제 |

- 진행률 막대는 드래그로 바꿀 수 없습니다. **처리율은 Jira가 시간 추적(기록 시간과 잔여 추정, 하위 이슈 포함)으로 계산한 값**이라 직접 입력하는 항목이 아닙니다.
- 순환이 생기는 연결(A→B→A), 자기 자신 연결, 다른 프로젝트 작업과의 연결은 거부되고 사유가 안내됩니다. 거부되면 화면도 원래대로 되돌아갑니다.

#### 폴더

- 폴더로 이슈를 묶어 **WBS(작업 분류)** 를 구성합니다. 중첩할 수 있고 **깊이에 따라 색 농도**가 달라집니다.
- 폴더 막대의 **기간·처리율·계획 작업량은 하위 항목에서 자동 집계**됩니다. 처리율은 계획 작업량(MD)으로 가중 평균합니다.
- 이슈가 없는 **빈 폴더도 이름만 표시**됩니다.
- **폴더를 삭제해도 이슈는 삭제되지 않습니다.** 내용물(이슈·하위 폴더)은 **상위 폴더로 옮겨지고**, 상위가 없으면 최상위로 올라갑니다. 다만 그 폴더가 끝점이던 선후행 연결은 함께 사라집니다.

#### 선후행 연결의 두 가지 저장 방식

- **이슈 ↔ 이슈** 연결은 Jira의 **이슈 링크(Blocks)** 로 저장되어 Jira 이슈 화면에서도 보입니다.
- **폴더가 포함된 연결**(폴더↔이슈, 폴더↔폴더)도 같은 방식으로 만들 수 있지만, 폴더는 Jira에 없는 앱 전용 개념이라 **앱 내부에만 저장**됩니다.

> **Jira 이슈 화면의 표기 방향:** 간트에서 만든 선후행은 Jira 이슈 화면에서 "blocks / is blocked by" 방향이 **간트와 반대로** 보일 수 있습니다. 간트 화면의 방향(왼쪽이 선행)이 기준이며, 일정 계산과 표시는 정상입니다.

> **성공 알림 묶음:** 드래그로 여러 항목을 연달아 편집하면 알림이 건건이 뜨지 않고 잠시 모아져 **"변경 N건이 저장되었습니다"** (일정 / 연결 / 상위 지정 / 폴더 소속 / 폴더 이동 분류) 한 건으로 표시됩니다. 오류 알림은 즉시 표시됩니다.

### 5.3.8 맵 보기

프로젝트를 정점으로 폴더와 작업을 **위에서 아래로 펼친 조직도**입니다. 보고 자료나 킥오프에서 "이 프로젝트가 어떤 덩어리로 이뤄져 있나"를 한 장으로 보여줄 때 씁니다. **읽기 전용**이라 여기서는 아무것도 바뀌지 않습니다.

![그림 5-11 맵 보기](./Moves_Workforce_사용자_매뉴얼/images/05-work-map.png)
*그림 5-11. 맵 보기 — ① 프로젝트 루트 카드(작업 N건·폴더 M개) ② 폴더 카드 ③ 작업 카드(담당자·상태·하위 N건) ④ 실선(하위)·점선 화살표(선후행) ⑤ 미니맵 ⑥ 카드 클릭으로 열린 작업 상세 드로어.*

| 요소 | 설명 |
|---|---|
| 프로젝트 루트 카드 | 맨 위. 작업 수·폴더 수 표시. 접거나 드로어를 열 수 없습니다 |
| 폴더 카드 / 작업 카드 | 이름·담당자·상태·하위 건수. **하위 펼치기/접기** 버튼으로 가지를 여닫습니다 |
| 실선 | 상위 → 하위(폴더 소속, 상위 지정, Jira 하위 이슈) |
| 점선 화살표 | 선후행(선행 → 후행). 양 끝이 지금 화면에 있을 때만 그려집니다 |
| 툴바 | 작업 키·이름 검색, **모두 펼침 / 모두 접기**, **미니맵 표시/숨김** |

- 처음 열면 프로젝트 루트와 **모든 폴더는 펼쳐지고**, 자식이 있는 작업만 접힌 상태입니다.
- 트리·간트와 같은 **담당자·상태·이슈 타입·스페이스 필터**를 공유합니다.
- 카드를 클릭하면 오른쪽에 **작업 상세** 드로어가 열려 처리율과 **워크로그 이력**(합계 시간 포함)을 보여줍니다. **커밋 이력** 탭은 Jira에 개발 도구(Bitbucket 등)가 연동돼 있고 조회 권한이 있을 때만 채워지며, 아니면 "연동된 저장소가 없습니다"로 표시됩니다.
- 구조를 바꾸려면 트리 보기, 일정을 바꾸려면 간트 보기로 전환하세요.

### 5.3.9 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| 트리·간트·맵 버튼이 안 보입니다 | 「프로젝트 관리」 읽기 권한이 없습니다 |
| 드래그·편집이 안 됩니다 | 「프로젝트 관리」 쓰기 권한이 없거나("조회 전용" 배지), Jira에서 그 이슈 편집 권한이 없습니다. 맵 보기는 원래 읽기 전용입니다 |
| 상위로 지정했는데 하위로 안 들어갑니다 | 상위로 지정한 작업이 **이 프로젝트에 편입돼 있지 않거나** 필터에 걸렸습니다. 트리 상세의 상위 항목에 사유가 표시됩니다 |
| 계획 작업량 저장이 실패합니다 | 그 Jira 프로젝트에서 **시간 추적(Time Tracking)이 꺼져** 있습니다. 팀 관리형 프로젝트는 프로젝트 설정 > 이슈 유형에서 해당 유형 필드에 '시간 추적'을 추가하고, 회사 관리형은 이슈 화면에 시간 추적 필드가 있는지 확인하세요 |
| 일괄 적용에서 일부만 실패했습니다 | 실패 목록의 사유(대개 Jira 권한·시간 추적)를 확인하고 **실패 건만 재시도**를 누르세요 |
| 폴더에 넣었더니 상위 지정이 풀렸습니다 | 정상 동작입니다. 상위 지정과 폴더 소속은 동시에 유지되지 않습니다 |
| 작업이 트리 최상위에 떠 있습니다 | 상위 작업이 필터로 걸러졌을 때 하위가 사라지지 않도록 최상위로 올려 보여줍니다. 필터를 해제하면 제자리로 돌아갑니다 |
| Jira에서 상위를 바꿨는데 반영되지 않습니다 | 앱에서 지정한 상위가 **우선 적용** 중입니다. 트리 상세에서 상위 지정을 해제하세요 |
| 간트에서 만든 계층이 Jira에 없습니다 | 앱의 상위 지정·폴더는 Jira에 없는 개념입니다(선후행 연결은 Jira에도 저장됩니다) |
| 구독했는데 이슈가 안 들어옵니다 | ① 구독 상태가 "권한 없음/소스 없음"인지 ② 이슈가 다른 프로젝트에 이미 등록돼 "건너뜀"인지 ③ "구독 이후 생성분만"으로 만들었는지 확인하고, **지금 동기화**를 눌러 보세요 |
| 작업 추가 창에서 이슈가 검색되지 않습니다 | Jira에서 그 이슈를 볼 권한(Browse Projects)이 있어야 합니다. 이슈 키로 정확히 검색해 보세요 |

### 5.5.1 작업 분석

![그림 5-13 작업 분석](./Moves_Workforce_사용자_매뉴얼/images/05-analysis-issue.png)
*그림 5-13. 작업 분석 — ① 상단 조망 차트(산정 정확도 · 담당자별 계획 대비 실적) ② 필터와 엑셀 내보내기 ③ 이슈 표(실투입 진행 바·초과율 배지·편차) ④ 이슈 클릭 시 상세 패널(누적 공수 S-curve·워크로그).*

#### 상단 조망 차트

| 차트 | 내용 |
|---|---|
| **산정 정확도** | 완료 이슈의 계획 대비 실제 비율 분포. **완료됐고 계획 작업량이 있는 이슈만** 계산하며, 계획이 없는 이슈와 미완료 이슈는 제외 수로 표시됩니다 |
| **담당자별 계획 대비 실적** | 담당자별 계획 MD 합 vs 실제 MD 합. 담당자 없는 이슈는 "미배정"으로 묶이고, **최대 15명**까지 표시됩니다. 인원이 많으면 아래 표에서 확인하세요 |

#### 이슈 표

이슈를 **계획 공수(MD)와 실투입 공수(MD)** 관점에서 비교합니다. 상단 필터(스페이스/담당자/상태/이슈 타입 등)로 범위를 좁히고 **엑셀 내보내기**로 현재 결과를 저장할 수 있습니다.

| 컬럼 | 의미 |
|---|---|
| 상태 / 담당자 / 작업 인원 | 누가 몇 명이 매달려 있는지 |
| 시작일 / 기한 | 일정 |
| 계획 작업량(MD) | 계획 공수(Original Estimate) |
| 예상 완료일 | 남은 공수 추세로 추정한 종료일 |
| 실투입(MD) | 누적 워크로그 + **진행 바**와 **초과율 배지**(100% 초과 시) |
| 편차 | **완료 이슈만** 표시. 계획 대비 실제(+ 초과, − 절감) |

**색으로 위험을 읽습니다**
�초록 = 계획 이내(≤100%) / �주황 = 초과(100~130%) / �빨강 = 심한 초과(130% 이상)

#### 활용

- **추정 정확도**: 계획보다 공수를 훨씬 많이/적게 쓴 이슈 → 견적 역량 점검
- **공수 초과**: 빨강 막대·큰 +편차 이슈는 비효율 또는 범위 누락(scope creep) 후보
- **완료 회고**: 편차 컬럼으로 끝난 이슈의 계획 정확도를 사후 검증
- **일정 리스크 예고**: 예상 완료일이 기한을 넘는 이슈를 미리 발견

#### 상세 차트 (이슈 클릭)

선택 이슈의 **누적 공수 S-curve**입니다.

- 파란 실선 = 실제 누적 투입 / 회색 점선 = 시작~기한 균등 분배한 이상적 계획선
- 오늘·기한·예측 종료일 마커와 **편차 막대**(실제−계획)
- 실선이 점선보다 가파르면 계획보다 빨리 소진(초과 위험), 완만하면 지연 신호. 아래 워크로그 원본으로 "언제 누가 얼마나" 투입했는지 추적

### 5.5.2 인력 분석

![그림 5-14 인력 분석](./Moves_Workforce_사용자_매뉴얼/images/05-analysis-resource.png)
*그림 5-14. 인력 분석 — ① 퀵 필터와 기준값(1MD·1MM) ② 상단 조망 차트(인원별 가동률 · 팀별 투입) ③ 인별/팀별 전환 ④ 멤버 표(실효 가용 MD·가동률 바) ⑤ 멤버 클릭 시 일/주/월 상세.*

#### 상단 조망 차트

| 차트 | 내용 |
|---|---|
| **인원별 가동률** | 가동률 상위 인력(**최대 20명**)을 막대로. 100% 기준선과 색 밴드로 과부하 여부를 바로 읽습니다 |
| **팀별 투입** | 선택 기간의 팀별 투입 공수 합계 |

#### 멤버 표

프로젝트 멤버별 투입 공수(MD/MM)와 **가동률**을 기간 기준으로 분석합니다.

- **퀵 필터**: 오늘 / 이번 주 / 이번 달 / 지난 주 / 지난 달, 또는 날짜 직접 선택
- 상단 기준값: `1MD = N h · 1MM = M 근무일(= M×N h) · MM = MD ÷ M`

| 컬럼 | 의미 |
|---|---|
| 총 MM | 투입 공수를 인월로 환산(`총MD ÷ 1MM 근무일`) — 절대 투입량 |
| 실효 가용 MD | 기간 근무일에서 **연차·공휴일을 뺀** 실제 출근 가능 일수(가동률 분모). 차감이 있으면 주황색으로 내역 표시 |
| 총 MD / 총 시간 / 이슈 수 | 실제 투입 공수·시간과 관여한 이슈 수 |
| 가동률 | `총 MD ÷ 실효 가용 MD`. 진행 바 + % |

**가동률 색상**
회색 <50%(저활용) / �초록 50~80% / �파랑 80~100%(적정) / �빨강 >100%(과부하)

#### 활용

- **부하 균형**: 빨강(과부하)·회색(저활용)을 비교해 업무 재분배 판단
- **공정한 비교**: 연차를 분모에서 빼므로 휴가자가 "일 안 한 사람"으로 과소평가되지 않음
- **투입량 정산**: 총 MM으로 인월 기준 정산 근거 확보
- **집중도**: 이슈 수 대비 MD로 소수 이슈에 깊게/다수 이슈에 얕게 붙어 있는지 확인

#### 상세 차트 (멤버 클릭)

**일별 / 주별 / 월별** 탭 전환. MD 막대 + 시간(h) 라인, 월별 탭에는 **1MM 기준선**(주황 점선)을 그려 풀가동 대비 위치를 표시합니다. 하단 워크로그 원본 테이블(이슈 타입 아이콘 포함)로 개인 투입 내역을 그대로 확인합니다.

> **가동률 = 실제 일한 양(MD) ÷ 일할 수 있었던 양(근무일 − 연차·공휴일)**. 1.0 = 100%(풀가동). 이 프로젝트 기준 가동률이라, 여러 프로젝트를 합산하는 전사 종합 가동률과는 분모가 달라 의미가 다릅니다.

인력 분석은 **인별 / 팀별** 보기를 전환할 수 있습니다. 팀별 가동률은 팀원 비율의 단순 평균이 아니라 `팀 합계 MD ÷ 팀 합계 가용 MD`이며, 하위 팀 포함 필터와 팀 미지정 필터를 제공합니다.

### 5.5.3 팀 분석

프로젝트에 지정한 [담당 팀](#521-담당-팀)과 선택 기간의 워크로그 실제 기여 팀을 나란히 봅니다.

| 구분 | 의미 |
|---|---|
| **담당·기여** | 계획과 실행이 일치 |
| **담당이지만 기여 없음** | 책임 팀으로 지정됐지만 선택 기간에 워크로그 기여가 없음 |
| **미담당 기여** | 담당 팀이 아닌 조직이 실제 작업에 참여 |

- 비용 권한이 있으면 **프로젝트 전체 기간 기준** 팀별 비용도 표시합니다(위 기간 필터와 무관하다는 안내가 함께 표시됩니다).
- 팀 분석은 **현재 소속 기준**입니다. 과거에 다른 팀이었던 인원의 실적도 지금 소속된 팀에 집계됩니다.

### 5.5.4 진척률

![그림 5-15 진척률](./Moves_Workforce_사용자_매뉴얼/images/05-analysis-progress.png)
*그림 5-15. 진척률 — ① 종합 헤더(완성/일정 진척률·차이·지연 배지·예상 완료일) ② 진척 비교 막대 ③ S-curve ④ 상태별 분포(건수/공수) ⑤ 지연·위험 이슈 표 ⑥ "이 화면 읽는 법" 접이식 가이드.*

프로젝트의 **현재 시점 진척 스냅샷**입니다. 이 화면은 **성격이 다른 세 가지를 한 숫자로 합치지 않습니다.** ("공수를 80% 썼으니 80% 끝났다" → 틀린 판단)

| 층 | 질문 | 계산 |
|---|---|---|
| **완성 진척**(핵심) | 얼마나 **끝났나** | Σ(이슈 진행률 × 계획공수) ÷ Σ(계획공수). 완료=100%, 진행 중=실투입/계획(최대 100%), 할 일=0% |
| **공수 진척** | 얼마나 **일했나** | 실투입 워크로그 누적. 완성도가 아닌 효율·리스크 신호 |
| **일정 진척** | 시간이 얼마나 **흘렀나** | 경과 근무일 ÷ 전체 근무일(휴일·주말 제외) |

#### 핵심 판단 규칙

- **① 완성 vs 일정 (주 신호)**: 완성이 일정보다 임계치(기본 5%p, [7.1에서 조정](#71-일반-설정)) 이상 낮으면 **지연**
- **② 공수 vs 완성 (보조)**: 공수를 많이 썼는데 완성이 낮으면 **비효율·리스크**

> 상단 종합 헤더의 **차이(완성률 − 일정률)** 가 이 화면의 단일 핵심 신호입니다. **음수면 지연, 양수면 선행.**

#### 영역별로 읽는 법

| 영역 | 무엇을 보여주나 | 어떻게 읽나 |
|---|---|---|
| **종합 헤더** | 완성/일정 진척률, 차이(%p), 지연 배지(정상/주의/지연), 확정 지연·예측 지연, 예상 완료일 | 일정대로인지 바로 판단합니다. 종료 예정일 초과 여부 선제 파악 |
| **진척 비교 막대** | 일정·완성·공수를 같은 0~100% 축에 병치 + 계획/실적 기성/실투입(MD) | 완성 막대가 일정보다 짧으면 지연, 공수 막대만 길면 비효율. **실적 기성 < 실투입**이면 쓴 공수만큼 못 끝낸 것 |
| **진척 추이(S-curve)** | 계획 누적(점선) vs 실적 누적(실선) + 오늘·종료 예정·예상 완료 마커 | 실선이 점선 아래로 처지면 진행이 느림. **곡선 모양으로 막판 몰림 예측** |
| **상태별 분포** | 완료/진행 중/할 일을 **개수** 또는 **공수(MD)** 기준으로 | 공수 기준 권장. 대기 비중이 큰데 일정이 임박하면 범위 리스크 |
| **지연·위험 이슈** | 기한 초과 미완료·공수 편차 큰 이슈 테이블(이슈 타입 아이콘 포함) | **당장 손봐야 할 이슈를 우선순위로 식별** |

#### 지연 지표 두 가지

- **확정 지연** = 이미 완료된 이슈의 (실적일 − 기한) 평균 → **회고**
- **예측 지연** = 남은 공수 추세로 본 예상 종료일 − 종료 예정일 → **예보**

> 예측 지연은 **낙관 근사치**입니다. 이슈별 예상 종료일의 최댓값 기준이라 병렬 작업 한계를 무시 — 실제보다 빠르게 잡힐 수 있어 보수적으로 해석하세요.

#### 대표 사용 시나리오

- **주간 스탠드업**: 종합 헤더의 차이(%p)·지연 배지로 30초 상태 보고
- **일정 위험 조기 경보**: S-curve 실선이 점선 아래로 벌어지기 시작하면 인력 보강/범위 조정 판단
- **비효율 감지**: 공수율은 높은데 완성률이 낮은 구간 → 추정 오류·재작업·블로커 조사

#### 제약

- 진척률은 현재 시점 전체 스냅샷이라 **기간 필터가 없습니다**(기준 기간은 프로젝트 시작~종료, 일정은 시작~오늘).
- **계획 작업량(Original Estimate)이 입력된 이슈가 없으면 계산할 수 없습니다.** [일괄 적용](#일괄-적용과-제외)이나 [구독의 기본 계획 작업량](#533-자동-편입프로젝트-구독)으로 채울 수 있습니다.
- 상단의 접이식 **"이 화면 읽는 법"** 가이드에서 각 지표의 정의·계산식을 확인할 수 있습니다.
- 같은 데이터를 [대시보드의 진척률 카드·진척 추이 위젯](#51-대시보드)에서도 볼 수 있습니다.

### 접근 권한

| 구분 | 필요 권한 |

- Jira 편집 권한이 없는 작업은 저장할 때 그 작업만 **실패**로 표시되고, 나머지 작업은 그대로 저장됩니다.

**언제 쓰나** — 프로젝트의 설계서·회의록·산출물 같은 **Confluence 문서를 작업(Jira 이슈)이나 프로젝트에 연결**해 두고, 문서가 없는 작업이나 오래 손대지 않은 문서를 한눈에 찾을 때.

### Jira와 Confluence의 역할

Moves Workforce의 모든 화면은 **Jira 안에** 있습니다. Confluence는 이 탭에서 문서를 찾아 연결하는 **문서 출처로만** 쓰입니다.

| 제품 | 필수 여부 | 역할 |
|---|---|---|
| **Jira** | 필수 | 앱 설치 위치. 메뉴·화면 전부가 Jira에 있습니다 |
| **Confluence** | 선택 | **앱 화면이 없습니다.** 이 탭이 Confluence 페이지를 검색하고 제목·스페이스·최종 수정일을 읽어 옵니다 |

- Confluence에서 앱을 찾을 필요는 없습니다. 문서 연결은 언제나 **Jira → 앱 → Moves Workforce → 프로젝트 관리 → 프로젝트 → 문서 관리 탭**에서 합니다.
- 앱은 Confluence의 **검색 기능만** 사용하고, Confluence에 아무것도 쓰지 않습니다. 연결 정보는 Jira 쪽(작업의 속성, 프로젝트 문서는 앱 저장소)에 저장됩니다.
- 검색과 표시는 **본인 계정의 Confluence 권한**으로 이뤄집니다. 동료가 연결한 문서라도 본인에게 볼 권한이 없으면 「끊김」으로 보입니다.

#### Confluence가 연결되지 않은 경우

사이트에 Confluence가 없거나 앱이 Confluence에 추가되지 않았으면 탭 위에 **「Confluence에 연결되지 않았습니다」** 안내가 뜹니다.

- 이미 연결된 문서 목록은 **마지막으로 저장된 정보로** 계속 보입니다.
- 새 문서 연결과 문서 상태 확인(최종 수정일·끊김)은 할 수 없습니다.
- 나머지 Moves Workforce 기능은 Confluence와 무관하게 모두 동작합니다.

이 사이트에서 Confluence를 쓰고 있다면 Jira 관리자에게 **Moves Workforce 앱을 Confluence에도 추가**해 달라고 요청하세요. 이미 추가돼 있다면 본인 계정에 Confluence 접근 권한이 있는지 확인하세요.

*그림 5-17. 문서 관리 탭(문서 보기) — ① 문서 / 작업 보기 전환 ② 요약 카드 5개 ③ 필터 ④ 문서 목록 ⑤ 문서 연결 버튼.*

### 화면 구성

탭 위쪽의 **문서 / 작업** 전환으로 두 가지 보기를 오갑니다. 두 보기 모두 **문서 연결** 버튼이 있습니다(「프로젝트 관리」 쓰기 권한자만).

#### 요약 카드

문서 보기 맨 위에 작은 카드 5개가 한 줄로 표시됩니다. 카드를 누르면 해당 조건으로 목록이 걸러집니다.

| 카드 | 뜻 | 누르면 |
|---|---|---|
| **연결 문서 수** | 이 프로젝트에 연결된 문서 수 | 문서 필터 해제 |
| **문서 없는 작업** | 연결된 문서가 하나도 없는 작업 수 | 작업 보기로 바뀌고 「문서 없는 작업만」이 켜짐 |
| **오래된 문서** | 기준 일수(기본 90일) 넘게 수정되지 않은 문서 | 상태 = 오래됨 |
| **끊긴 링크** | 삭제됐거나 본인이 볼 권한이 없는 문서 | 상태 = 끊김 |
| **누락된 필수 분류** | 필수로 지정한 분류인데 프로젝트에 그 분류의 문서가 하나도 없음 | (분류 이름만 표시) |

- 경고 카드(오래된 문서·끊긴 링크·누락된 필수 분류)는 0이면 흐리게, 1 이상이면 경고 색으로 표시됩니다.
- Confluence에 연결되지 않아 확인할 수 없는 값은 0이 아니라 **확인 불가**로 표시됩니다.

#### 문서 보기

연결된 **문서 한 건이 한 줄**입니다.

| 열 | 내용 |
|---|---|
| 제목 | 누르면 Confluence 페이지가 새 창으로 열립니다 |
| 스페이스 | 스페이스 아이콘과 이름 |
| 분류 | 연결할 때 고른 분류. 없으면 「미분류」 |
| 연결 작업 | 이 문서가 연결된 작업. 작업 없이 연결한 문서는 **프로젝트 문서** 배지 |
| 최종 수정일 | Confluence에서 마지막으로 수정된 날짜 |
| 상태 | **정상** / **오래됨** / **끊김** / **확인 불가** |
| 동작 | **분류 변경**, **연결 해제** (쓰기 권한자만) |

필터: 검색어(제목·스페이스·작업 키·요약), 작업(여러 개 고르면 하나라도 연결된 문서), 분류, 상태.

#### 작업 보기

프로젝트의 **작업 한 건이 한 줄**입니다.

| 열 | 내용 |
|---|---|
| 키 | 이슈 유형 아이콘과 이슈 키 |
| 요약 / 상태 | Jira 이슈 요약과 상태 |
| 문서 | 연결된 문서 제목 링크 3개까지, 나머지는 「외 N건」. 문서 수로 정렬됩니다 |
| 동작 | **문서 연결** — 이 작업을 대상으로 연결 창을 엽니다 |

필터: 검색어(키·요약·문서 제목), **문서 없는 작업만**.

### 절차

#### 문서 연결하기

![그림 5-18 문서 연결 창](./Moves_Workforce_사용자_매뉴얼/images/05-documents-link-modal.png)
*그림 5-18. 문서 연결 창 — ① 스페이스 선택 ② 검색어·본문 포함 ③ 검색 결과(선택한 문서는 체크 유지) ④ 작업 선택 ⑤ 분류.*

1. **문서 연결**을 누릅니다.
2. **① 문서** — 문서를 찾아 고릅니다.
   - 제목을 입력하거나 Confluence **페이지 주소를 붙여 넣어** 찾습니다. **본문 포함**을 켜면 본문 내용까지 검색합니다.
   - **스페이스**를 고르면 검색어 없이도 그 스페이스의 문서가 최근 수정 순으로 나옵니다(25건씩 **더 보기**).
   - 여러 문서를 한 번에 고를 수 있습니다(최대 30건). **이 목록 모두 선택 / 해제**는 지금까지 불러온 결과 전체가 대상입니다.
3. **② 작업** — 문서를 연결할 작업을 고릅니다(여러 개 가능).
   - **작업을 고르지 않으면** 특정 작업이 아니라 **이 프로젝트의 문서**(프로젝트 문서)로 연결됩니다. 프로젝트 전체에 해당하는 계획서·회의록에 쓰세요.
4. **③ 분류** — 분류를 고릅니다(선택). 분류 목록은 [일반 설정](#문서-설정)에서 정합니다.
5. 저장하면 **작업별 성공·실패 결과**가 표시됩니다.

#### 분류 바꾸기 · 연결 해제하기

문서 보기의 **동작** 열에서 **분류 변경** 또는 **연결 해제**를 누릅니다. 문서가 여러 작업에 연결돼 있으면 **적용할 작업을 고른 뒤** 저장하고, 결과는 작업별로 표시됩니다.

연결 해제는 연결만 끊습니다. **Confluence 페이지는 지워지지 않습니다.**

### 알아두기

- **한 작업에 연결할 수 있는 문서는 30건까지**입니다. 넘으면 그 작업은 실패로 표시됩니다.
- 같은 문서를 같은 작업에 다시 연결하면 새로 추가되지 않고 **분류만 갱신**됩니다.
- 목록의 제목·스페이스는 연결 당시 값을 저장해 두고, 화면을 열 때 Confluence에서 최신 정보로 다시 확인합니다. Confluence에서 제목을 바꾸면 다음에 열 때 반영됩니다.
- 작업이 아주 많은 프로젝트는 앞쪽 일부 작업만 불러오며, 이때 「작업이 많아 일부만 표시합니다」 안내가 뜹니다. 연결 문서가 500건을 넘으면 그 이후 문서는 최신 정보를 확인하지 않고 「확인 불가」로 표시됩니다.
- 작업을 [프로젝트에서 제외](#일괄-적용과-제외)해도 그 작업에 연결된 문서 정보는 Jira 작업에 남습니다. 다시 편입하면 그대로 보입니다.

### 문제 해결

| 증상 | 원인 | 조치 |
|---|---|---|
| 「Confluence에 연결되지 않았습니다」가 뜬다 | 사이트에 Confluence가 없거나, 앱이 Confluence에 추가되지 않았거나, 본인에게 Confluence 권한이 없음 | Jira 관리자에게 앱을 Confluence에 추가해 달라고 요청하거나 본인의 Confluence 접근 권한을 확인 |
| **문서 연결** 버튼이 없다 | 「프로젝트 관리」 쓰기 권한 없음 | 권한 관리자에게 요청 |
| 일부 작업만 실패한다 | 그 작업의 Jira 편집 권한이 없거나 한 작업에 30건이 넘음 | 결과 창의 실패 사유를 확인 |
| 동료에게는 보이는 문서가 나에게는 「끊김」이다 | 본인이 그 Confluence 페이지를 볼 권한이 없음 | Confluence 스페이스 관리자에게 권한 요청 |
| 찾는 문서가 검색되지 않는다 | 본인이 볼 수 없는 페이지이거나 검색어가 제목과 다름 | **본문 포함**을 켜거나 페이지 주소를 붙여 넣어 검색 |

## 6. 자원 관리

### 접근 권한

| 구분 | 필요 권한 |
|---|---|
| 메뉴·화면 진입 | 「자원관리」 읽기 (없으면 **사이드바에 메뉴가 없습니다**) |
| 인력 현황 · 조직 현황 | 「자원관리」 읽기 |
| 팀 분석 | 「자원관리」 읽기 (+ 공수·진척·리스크 축은 「리포트」 읽기, 인건비는 「비용」 읽기) |
| 프로젝트 배정 — 조회 | 「자원관리」 읽기 |
| 프로젝트 배정 — 실행 | 「프로젝트 관리」 쓰기 또는 「자원관리」 쓰기 **+ Jira 담당자 지정 권한** |
| 인력 보유 스킬 편집 | 「자원관리」 쓰기 (또는 자기 팀원에 한해 팀장) |

**보이는 인원 범위는 권한이 아니라 별도 판정을 따릅니다**

| 사용자 | 인력·조직 현황 | 팀 분석 |
|---|---|---|
| 관리자·PMO·PM (프로젝트 범위 "전체") | 전사 인원 | 전 팀 |
| 팀장 | 자신이 이끄는 팀 인원 | 자신이 이끄는 팀과 하위 팀 |

> **프로젝트 조회 범위와 인원 조회 범위는 다릅니다.** 권한 세트를 "내 팀만"으로 두어도 **프로젝트 범위만** 제한되며, 자원 관리 읽기를 함께 주면 전사 인원 목록은 그대로 보입니다.

## 6.1 인력 현황

### 접근 권한

| 구분 | 필요 권한 |
|---|---|
| 화면 조회 | 「자원관리」 읽기 |
| 인력 상세 드로어 | 「자원관리」 읽기 |
| 보유 스킬 편집 | 「자원관리」 쓰기 (자기 팀원에 한해 **팀장**도 가능) |

- 보이는 인원은 관리자·PMO·PM이면 전사, **팀장이면 자신이 이끄는 팀 인원**입니다.
- 스킬 선택지는 [7.6 스킬 관리](#76-스킬-관리)에서 「스킬 관리」 권한으로 정의합니다.

---

**언제 쓰나** — **개인 단위로** 누가 바쁘고 누가 여유인지, 어떤 스킬을 가졌는지 확인할 때.

![그림 6-2 인력 현황](./Moves_Workforce_사용자_매뉴얼/images/06-resource-people.png)
*그림 6-2. 인력 현황 — ① 요약 카드(총 인원·여유·적정·과부하)와 마지막 집계 ② 필터(스킬·직무·등급·팀·직군·투입가능만) ③ 인력 표(가동률 밴드·완수율·작업량) ④ 행 클릭으로 열린 인력 상세 드로어.*

### 상단 요약

**총 인원 · 여유 · 적정 · 과부하** 카드와 **마지막 집계** 시각이 표시됩니다.

> 가동률은 **배치 집계** 값입니다. 방금 등록한 인원이나 방금 쌓인 워크로그는 다음 집계 전까지 반영되지 않습니다. "집계 데이터가 오래되었습니다" 안내가 뜨면 그 시점 기준으로 해석하세요.

### 목록 컬럼

| 컬럼 | 의미 |
|---|---|
| 인력 | 이름·아바타 |
| 팀 / 직무 / 등급 | 소속과 직무 정보 |
| 가동률 | 배치 집계 기준. 밴드(여유/적정/과부하 주의/과부하/실적없음)로 색 구분 |
| 완수율 | `소비시간 ÷ (소비 + 남은 작업량)`. **완료 이슈는 최근 6개월분만** 집계 |
| 작업량 | 처리 / 남은 / 할당. 진행도 % = 처리 ÷ 할당 |
| 할당 이슈 | 담당·협업으로 연결된 이슈 수 |
| 참여 프로젝트 | 참여 중(미종료) 프로젝트 수 |
| 보유 스킬 | 등록된 스킬 태그 |

**필터**: 스킬 · 직무 · 등급 · 팀 · 직군 · **투입가능만**

> 가동률 밴드의 경계값(과소 / 과부하 / 심한 과부하)은 [7.1 일반 설정](#71-일반-설정)에서 조정합니다.

### 인력 상세 드로어

행을 클릭하면 오른쪽에 상세가 열립니다.

| 구역 | 내용 |
|---|---|
| **부하** | 진행중 이슈 수, 남은 작업량(시간) |
| **진행 중 작업** | 이슈별 상태·프로젝트·마감·참여 형태(담당/협업)·**내 몫** |
| **경험** | 프로젝트 참여 이력(역할·기간·상태) |

> **"내 몫"은 근사치입니다.** 여러 명이 참여한 이슈는 남은 작업량을 **참여 인원으로 균등 분할**한 1인 기대 몫으로 계산합니다. 실제 분담 비율과 다를 수 있습니다.

### 스킬 편집

드로어의 **스킬 편집**으로 보유 스킬을 지정합니다(쓰기 권한 필요).

- 선택지는 [7.6 스킬 관리](#76-스킬-관리)에서 정의한 사전을 따릅니다.
- 여기 등록한 값이 [6.4 프로젝트 배정](#64-프로젝트-배정)의 **적합도** 계산에 쓰입니다.
- 본인 스킬은 [마이페이지](#3-마이페이지)에서도 직접 편집할 수 있고, 팀장은 마이페이지의 **내 팀**에서 팀원 스킬을 편집할 수 있습니다.

### 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| 가동률이 "데이터 없음"입니다 | 아직 집계 전이거나 해당 기간 워크로그 실적이 없습니다 |
| 일부 인원만 보입니다 | 팀장 권한이면 자신이 이끄는 팀 인원만 보입니다 |
| 스킬 필터에 원하는 스킬이 없습니다 | [7.6 스킬 관리](#76-스킬-관리)에서 사전에 먼저 등록해야 합니다 |
| 완수율이 낮게 나옵니다 | 완료 이슈를 **최근 6개월분만** 집계합니다. 오래된 완료 이슈는 분자에서 빠집니다 |

## 6.2 조직 현황

### 접근 권한

| 구분 | 필요 권한 |
|---|---|
| 화면 조회 | 「자원관리」 읽기 |
| 조직 계층·팀장·팀원 **편집** | 이 화면에서는 불가 — [7.3 팀 관리](#73-팀-관리)에서 「팀 관리」 쓰기로 수행 |

- 이 화면은 **조회 전용**입니다. 팀 생성·이동·팀원 배치는 설정 화면에서 합니다.
- 보이는 팀·인원 범위는 관리자면 전사, 팀장이면 자신이 이끄는 팀과 하위 팀입니다.

---

**언제 쓰나** — **조직도 관점**에서 팀 구성과 팀별 인원·가동률을 볼 때.

![그림 6-3 조직 현황](./Moves_Workforce_사용자_매뉴얼/images/06-resource-org.png)
*그림 6-3. 조직 현황 — ① 팀 트리(팀장·직속/누적 인원) ② 직속 인원만 보기 토글 ③ 선택 팀의 팀원 목록(팀장 배지·가동률·보유 스킬).*

### 화면 구성

**왼쪽 — 팀 트리**

- 전사 → 팀 → 하위 팀 계층
- 팀별 **팀장**, **인원 수** 표시 — `직속 N명 / 누적 M명`
- **직속 인원만 보기** 토글로 하위 팀 인원 포함 여부를 전환

**오른쪽 — 팀원 목록**

| 컬럼 | 내용 |
|---|---|
| 팀원 | 이름·아바타. 팀장은 맨 앞에 **팀장** 배지와 함께 |
| 팀 | 소속 팀 |
| 직무 / 등급 | 직무 정보 |
| 가동률 | 배치 집계 기준 |
| 보유 스킬 | 등록된 스킬 태그 |

### 알아두기

- 아직 집계되지 않은 인원이 있으면 **"N명은 아직 집계 전이라 합계에서 제외되었습니다"** 가 표시됩니다. 팀 합계를 읽을 때 이 안내를 함께 확인하세요.
- 표시할 팀원이 없으면 빈 상태 안내가 나옵니다. 팀에 사람을 배치하려면 [7.3 팀 관리](#73-팀-관리)의 **팀원 배치**를 사용합니다.
- 조직 계층 자체(상위 팀·팀장·팀 권한)는 이 화면이 아니라 [7.3 팀 관리](#73-팀-관리)에서 편집합니다.
- 팀장은 항상 그 팀의 소속 인원으로 세어집니다([7.3 규칙](#팀장-규칙)).

### 이 화면과 팀 분석의 차이

| | 조직 현황 | [팀 분석](#63-팀-분석) |
|---|---|---|
| 보는 단위 | **사람** (팀에 속한 개인 목록) | **팀** (팀 간 비교·롤업) |
| 쓰는 때 | "이 팀에 누가 있지?" | "어느 팀이 과부하지?" |

## 6.3 팀 분석

### 접근 권한

| 구분 | 필요 권한 |
|---|---|
| 탭 진입 | 「리포트」 읽기 또는 「자원관리」 읽기 또는 「팀 관리」 읽기 |
| 가동률·인원 축 | 위 진입 권한만으로 표시 |
| 공수·진척·리스크 축 | 「리포트」 읽기 |
| 인건비 | 「비용」 읽기 (+ 급여 정책 스냅샷 정합성) |

- 「리포트」가 없어도 **탭 전체가 막히지는 않습니다.** 가동률·인원 축만 보이고 나머지 축은 안내와 함께 숨겨집니다.
- 보이는 팀 범위는 서버가 판정합니다 — 전사 조직 조회 권한과 "전체 프로젝트" 범위를 가지면 전 팀, 팀장은 자신이 이끄는 팀과 하위 팀입니다.

---

**언제 쓰나** — 여러 팀·프로젝트를 가로질러 **팀 단위 자원 지표**를 비교할 때.

![그림 6-4 팀 분석](./Moves_Workforce_사용자_매뉴얼/images/06-resource-team-analytics.png)
*그림 6-4. 팀 분석 — ① 팀·프로젝트 필터 ② KPI ③ 프로젝트별 팀 투입 ④ 가동률 분포·팀 간 비교 ⑤ 가동률-규모 산점도 ⑥ 계층 롤업.*

### 제공 위젯

| 위젯 | 내용 |
|---|---|
| KPI | 팀 단위 핵심 지표 요약 |
| 프로젝트별 팀 투입 | 어느 팀이 어느 프로젝트에 얼마나 투입됐는지 |
| 가동률 분포 | 팀별 가동률 밴드 분포 |
| 팀 간 비교 | 팀을 나란히 두고 지표 비교 |
| 인력 구성 | 직무·등급 구성 |
| 가동률-규모 산점도 | 팀 규모 대비 가동률 위치 |
| 계층 롤업 | 하위 팀을 합산한 상위 팀 지표 |

**필터**: 팀 · 프로젝트

### 보이는 범위는 서버가 판정합니다

| 사용자 | 범위 |
|---|---|
| 전사 조직 조회 신호 + "전체 프로젝트" 범위 | 전 팀 |
| 팀장 | 자신이 이끄는 팀과 하위 팀 |

### 권한에 따른 축 제한

- 「리포트」 권한이 없으면 **탭 전체를 막지 않고 가동률·인원 축만** 제공합니다. 공수·진척·리스크 축은 안내와 함께 숨겨집니다.
- **인건비**는 「비용」 권한과 급여 정책 스냅샷 정합성이 **모두** 충족돼야 표시됩니다.

### 알아두기

- 인원이 **500명을 초과**하면 팀 필터와 팀별 보기를 사용할 수 없습니다.
- 팀 분석은 **현재 소속 기준**입니다. 과거에 다른 팀이었던 인원의 실적도 **지금 소속된 팀**에 집계됩니다(소급하지 않습니다).
- 미래 기간은 가동률 계산에서 제외됩니다.
- "N개 프로젝트는 아직 집계 전이라 제외되었습니다"가 뜨면 다음 배치 이후 포함됩니다.

### 세 개의 팀 화면 구분

| 화면 | 답하는 질문 | 범위 |
|---|---|---|
| [마이페이지 → 내 팀](#32-내-팀-팀장-전용) | 내가 이끄는 조직의 업무 현황은? | 본인이 팀장인 팀과 하위 팀 |
| [프로젝트 상세 → 팀 분석](#553-팀-분석) | 이 프로젝트의 담당 조직과 실제 기여가 일치하는가? | 현재 프로젝트 |
| **자원 관리 → 팀 분석** (이 화면) | 여러 팀·프로젝트의 자원 지표와 계층 롤업은? | 허용된 전 팀 또는 리딩 팀 |

## 6.4 프로젝트 배정

### 접근 권한

| 구분 | 필요 권한 |
|---|---|
| 화면 조회(프로젝트 카드·작업 현황) | 「프로젝트 관리」 읽기 또는 「자원관리」 읽기 |
| **전사 인력 후보 목록** | 「자원관리」 읽기 |
| 배정 실행·팀 전체 배정 | 「프로젝트 관리」 쓰기 또는 「자원관리」 쓰기 **+ Jira 담당자 지정 권한** |
| 프로젝트 필요 스킬 편집 | 「프로젝트 관리」 쓰기 |
| 인력 보유 스킬 편집 | 「자원관리」 쓰기 |

- **조회 전용 자원 관리자(읽기만)는 배정을 실행할 수 없습니다.** 쓰기 권한이 필요합니다.
- 배정 대상 후보는 [7.2 인력 관리](#72-인력-관리)에 등록된 인원으로 한정됩니다.
- 보이는 프로젝트는 조회 범위(소속 프로젝트만 / 내 팀만)로 필터됩니다.

---

**언제 쓰나** — "이 프로젝트에 누구를 넣을까"를 전사 인력 풀에서 고를 때.

![그림 6-5 프로젝트 배정](./Moves_Workforce_사용자_매뉴얼/images/06-resource-assignment.png)
*그림 6-5. 프로젝트 배정 — ① 배정 대상 프로젝트 카드(D-day·미배정/임박/지연) ② 작업 현황(배정 인원) ③ 전사 인력 후보(적합도·신호·배정 버튼) ④ 패널 접기 버튼 ⑤ 팀 전체 배정.*

### 화면 구성

| 영역 | 내용 |
|---|---|
| **배정 대상 프로젝트** (좌) | 프로젝트 카드 — D-day, 미배정·임박·지연 작업 수. 검색·상태 필터, **종료·일정오버 포함** 토글 |
| **작업 현황** (중) | 선택 프로젝트의 열린 작업과 **배정 인원 N명** |
| **전사 인력** (우) | 후보 목록 — 직무/등급 · 스킬 · **적합도** · 신호 · 배정 버튼 |

세 패널은 카드 헤더의 접기 버튼과 경계선 드래그로 폭을 조절할 수 있습니다. 프로젝트 카드에는 `D-7`, `D-DAY`, `D+3 지연` 같은 일정 배지와 종료·일정 오버 표시가 붙습니다.

### 배정하는 법

1. 왼쪽에서 프로젝트를 선택합니다. (선택 전에는 "프로젝트를 선택하면 적합도가 표시됩니다")
2. 오른쪽 전사 인력 목록에서 **적합도**와 **신호**(부하 상태)를 확인합니다.
3. **배정**을 눌러 맡길 작업을 고르거나, 배정할 작업이 없으면 **프로젝트 인력으로만** 배정합니다.
4. 팀 단위로 넣으려면 팀을 선택한 뒤 **팀 전체 배정**을 사용합니다.

> **적합도**는 프로젝트 **필요 스킬** 대비 후보의 보유 스킬 일치도입니다. 필요 스킬은 [프로젝트 추가/수정 창](#프로젝트-추가--수정)의 필요 스킬 영역 또는 이 화면의 **요구 스킬 편집**으로, 보유 스킬은 [6.1 인력 현황](#스킬-편집)에서 지정합니다. 둘 중 하나가 비어 있으면 적합도가 의미를 갖지 못합니다.

> 백오피스에 등록되지 않은 Jira 사용자는 배정할 수 없습니다 — 먼저 [7.2 인력 관리](#72-인력-관리)에서 등록하세요.

### 팀 전체 배정 규칙

- **이미 배정된 인원은 대상에서 제외**됩니다. 실행 전 "{팀} {N}명을 [{프로젝트}]에 배정합니다"로 확인합니다.
- 되돌리려면 배정 명단에서 **한 명씩 취소**해야 합니다(일괄 취소 없음).
- 배정 취소 시 **이미 할당된 작업의 담당은 해제되지 않습니다** — 해당 건수가 안내됩니다.

### 배정 관계도

프로젝트–팀–담당자 3레이어 관계를 그래프로 보여줍니다.

![그림 6-6 배정 관계도](./Moves_Workforce_사용자_매뉴얼/images/06-resource-allocation-graph.png)
*그림 6-6. 배정 관계도 — ① 프로젝트 노드 ② 팀 노드 ③ 담당자 노드(여러 프로젝트에 선이 이어진 중복 배정 강조) ④ 진행 상태·프로젝트 필터, 종료 프로젝트 포함 토글.*

> **링크 기준은 "프로젝트 인력 배정 명단"이지 워크로그 투입이 아닙니다.** 배정만 되고 아직 착수하지 않은 인원도 표시됩니다. 실제 기여도는 [5.5 팀 분석](#553-팀-분석)이나 [5.5 인력 분석](#552-인력-분석)에서 확인하세요.

- 배정 인원이 많으면 상위 N개 프로젝트만 표시되며 **전체 표시**로 펼칠 수 있습니다.
- 진행 상태·프로젝트 필터, **종료 프로젝트 포함** 토글을 제공합니다.
- 노드를 클릭하면 해당 인력의 상세 드로어가 열립니다.
- 같은 관계도를 [통합 대시보드 > 자원 서브탭](#83-비교-서브탭)의 **전사 배정 관계도**에서도 볼 수 있습니다.

### 프로젝트 상세의 작업 배정과 어떻게 다른가

| | 이 화면 (6.4) | [5.2 작업 배정](#524-작업-배정) |
|---|---|---|
| 후보 범위 | **전사 인력** | 이미 등록된 **프로젝트 인력** |
| 출발점 | 여러 프로젝트를 비교하며 사람 고르기 | 이 프로젝트 안에서 작업 나누기 |
| 팀 단위 처리 | **팀 전체 배정** 지원 | 담당 팀에서 팀 전체 추가 |

### 도입 시 권장 순서

```
7.1 일반 설정 (근무시간·급여 정책)
   ↓
7.4 역할 · 7.5 등급 · 7.6 스킬 (기준정보)
   ↓
7.8 권한 → 7.2 인력 → 7.3 팀
   ↓
7.7 프로젝트 상태 → 7.9 휴일
```

**왜 이 순서인가**

- 인력을 등록하려면 **역할·등급·권한**이 먼저 있어야 선택할 수 있습니다.
- 팀에 **권한 세트**를 걸려면 권한이 먼저 정의돼 있어야 합니다.
- 팀장은 **등록된 인원** 중에서만 지정할 수 있고, 지정하면 그 팀 소속으로 옮겨지므로 인력을 먼저 등록하고 팀을 만드는 편이 편합니다.
- 프로젝트를 만들기 전에 **프로젝트 상태**가 있어야 하고, 근무일 계산이 맞으려면 **휴일**이 등록돼 있어야 합니다.

| 설정 | 영향받는 곳 |

| 급여 정책 | 프로젝트 급여 관리, 비용 탭, 대시보드 총 인건비·비용 소진, 통합 대시보드 비용 축 |
| 가동률 밴드 | 인력 현황 색상, 전사 대시보드 신호등 |
| 진척도 임계값 | 진척률의 정상/주의/지연 판정 |
| 공휴일 | 목표 시간, 가동률 분모, 진척률 근무일, 워크로그 일괄 입력, 캘린더 공휴일 라벨 |
| 역할·등급·스킬 | 프로젝트 인력 선택지, 적합도 계산 |
| 권한·팀 | 모든 화면의 노출 범위 |

## 7.1 일반 설정

### 접근 권한

| 구분 | 필요 권한 |
|---|---|
| 화면 조회 | 「일반 설정」 읽기 |
| 설정 변경·전체 초기화 | 「일반 설정」 쓰기 |
| 급여 정책 변경 | 「일반 설정」 쓰기 |

- 여기서 정한 값(근무시간·가동률 밴드 등)은 **모든 사용자의 화면 계산에 쓰이므로**, 조회 권한 없이도 값 자체는 각 화면에 반영됩니다. 권한은 **이 설정 화면의 접근과 변경**을 제어합니다.
- 급여 정책을 바꾸면 전사 인건비 표시가 달라집니다. 영향 범위는 아래 본문을 확인하세요.

---

**언제 쓰나** — 전사 공통 기준값을 정할 때. **여기 값이 바뀌면 거의 모든 화면의 숫자가 함께 바뀝니다.**

![그림 7-2 일반 설정](./Moves_Workforce_사용자_매뉴얼/images/07-general-settings.png)
*그림 7-2. 일반 설정 — ① 화폐 단위·1Day 근무 시간·1MM 기준 일수 ② 월별 기준(일괄/개별) ③ 진척도 임계값·가동률 기준 3단계 ④ 급여 정책 카드(밴드 미설정 등급 수 경고) ⑤ 전체 초기화.*

### 설정 항목

| 항목 | 설명 | 기본값 |
|---|---|---|
| 화폐 단위 | 시스템 전역 통화 | — |
| **1Day 근무 시간** | `1MD = N시간`. 0.5 단위, 0.5~24h. 모든 MD/MM/목표시간 계산의 기준 | 8h |
| **1MM 기준 일수** | `1MM`이 며칠에 해당하는지 | — |
| 월별 기준 설정 | 모든 월에 같은 기준을 쓰거나(**일괄 적용**), 월마다 다르게(**개별 설정**) 지정 | 일괄 |
| 진척도 임계값 | 완성률과 일정률 차이를 "정상"으로 볼 허용 범위(%p). 0~100 | 5%p |
| 가동률 기준 — 과소 | 이 값 **미만**은 '과소' | 0.7 |
| 가동률 기준 — 과부하 | 이 값 **이상**은 '과부하' | 1.1 |
| 가동률 기준 — 심한 과부하 | 이 값 **이상**이면 신호등 적색(위험) | 1.3 |
| **급여 정책** | **인원별** 또는 **등급 기반** | 인원별 |
| 문서 — 분류 | 문서를 연결할 때 고르는 분류 목록. 분류마다 **필수** 지정 가능 | 기획·설계·회의록·산출물·기타 (필수 없음) |
| 문서 — 오래된 문서 기준 | 이 일수 넘게 수정되지 않은 문서를 「오래됨」으로 표시. 1~3650일 | 90일 |

하단의 **전체 초기화(기본값으로)** 로 되돌릴 수 있습니다. 값은 서버에서도 범위를 검증하므로 허용 범위 밖 값은 저장되지 않습니다.

### 각 값이 영향을 주는 곳

| 설정 | 영향 |
|---|---|
| 1Day 근무 시간 | [My Work 목표 시간](#목표-시간-계산), 계획 작업량(MD) 환산, 인력 분석의 MD/MM, 진척률, [워크로그 추출](#9-워크로그-추출)의 총 MD, [Jira 이슈 패널](#10-jira-이슈-화면의-moves-workforce-패널) KPI |
| 1MM 기준 일수 / 월별 기준 | 인력 분석의 `MM = MD ÷ 1MM 근무일`, 월별 1MM 기준선, 이슈 패널의 MM 환산 |
| 진척도 임계값 | [진척률](#554-진척률)의 정상/주의/지연 배지 판정 |
| 가동률 기준(band) | [인력 현황](#61-인력-현황) 밴드 색상, 전사 대시보드의 가동률 분포 차트와 종합 개요 신호등(자원 축) |
| 문서 분류 / 오래된 문서 기준 | [문서 관리](#56-문서-관리) 탭의 분류 선택지, 「누락된 필수 분류」·「오래된 문서」 카드와 상태 표시 |
| 급여 정책 | [프로젝트 급여 관리](#523-급여-관리), 비용 탭, 대시보드 총 인건비·비용 소진 위젯 |

> 가동률 1.0 = 100%(기준 가동)입니다.

### 문서 설정

화면 아래 **문서** 카드에서 [문서 관리](#56-문서-관리) 탭의 분류와 오래된 문서 기준을 정합니다. 「일반 설정」 쓰기 권한이 없으면 읽기 전용으로 표시됩니다.

- **분류 추가·삭제·필수 지정**: 필수로 지정한 분류의 문서가 프로젝트에 하나도 없으면 문서 관리 탭의 「누락된 필수 분류」 카드에 그 분류 이름이 표시됩니다.
- 분류를 삭제해도 이미 그 분류로 연결된 문서의 분류 값은 남습니다.
- **오래된 문서 기준**: Confluence 최종 수정일로부터 이 일수가 지나면 「오래됨」입니다.

### 급여 정책을 바꿀 때 일어나는 일

변경 전 확인 창에서 영향 범위를 안내합니다.

| 방향 | 즉시 일어나는 일 |
|---|---|
| → **등급 기반** | 개인 연봉이 화면·응답에서 **즉시 숨겨지고**, 인건비가 등급 대표값 기준으로 재계산됩니다. **저장된 값은 삭제되지 않으며** 언제든 되돌릴 수 있습니다 |
| → **인원별** | 개인 연봉이 다시 표시되고 인건비가 개인 연봉·투입 급여 기준으로 돌아갑니다. 등급 기반으로 운영하는 동안 등록된 인원은 연봉이 비어 있을 수 있습니다 |

**반영 시점**

- 프로젝트 비용 분석: 최대 **10분**
- 전사 대시보드: **다음 집계** 후. 그 전까지 비용 서브탭은 "급여 정책이 변경되어 이전 집계 결과의 인건비는 표시하지 않습니다"로 가려집니다

**주의**

- **급여 밴드가 없는 등급**의 인원은 인건비가 0으로 계산됩니다. 전환 전 "등급 N개에 급여 밴드가 없습니다" 경고가 표시되며, [7.5 등급 관리](#75-등급-관리)에서 채울 수 있습니다.
- 프로젝트에 직접 입력한 **프로젝트 비용(예산)** 값은 이 전환으로 바뀌지 않습니다.

## 7.2 인력 관리

### 접근 권한

| 구분 | 필요 권한 |
|---|---|
| 화면 조회 | 「인력 관리」 읽기 |
| 인력 추가·수정·삭제 | 「인력 관리」 쓰기 |
| 엑셀 일괄 업로드 | 「인력 관리」 쓰기 |
| Excel 다운로드 | 「인력 관리」 읽기 |
| 연봉 입력·표시 | 「인력 관리」 쓰기 **+** 급여 정책이 **인원별** |
| 권한 세트 지정 | 「인력 관리」 쓰기. 단, **자기 권한을 넘는 세트는 줄 수 없습니다**(Jira 관리자·「권한 관리」 쓰기 보유자는 제한 없음) |

- 역할·등급·팀·권한 **선택지**는 이 화면에서 함께 조회됩니다(「인력 관리」 읽기로 열립니다). 값 자체를 만들려면 각 기준정보 화면의 권한이 필요합니다.
- 급여 정책이 등급 기반이면 연봉 칸이 사라집니다([7.1](#71-일반-설정)).

---

**언제 쓰나** — 워크포스 사용자(인력)를 등록·수정할 때. **여기 등록된 사람만** 팀 배치·프로젝트 인력·팀장 지정의 대상이 됩니다.

![그림 7-3 인력 관리](./Moves_Workforce_사용자_매뉴얼/images/07-users.png)
*그림 7-3. 인력 관리 — ① 권한/역할/등급/팀별 인원 통계 카드 ② 필터와 Excel 다운로드 ③ 인력 추가·일괄 업로드 ④ 인력 표(팀장 배지·권한·연봉).*

### 화면 구성

- 상단에 **권한 / 역할 / 등급 / 팀별 인원 통계** 카드
- 필터: 사용자 검색 · 역할 · 등급 · 권한 · 팀
- **Excel 다운로드**: 설정한 필터 조건 그대로 내려받습니다

| 컬럼 | 설명 |
|---|---|
| 사용자 | 이름·아바타. 소속 팀의 팀장이면 **팀장** 배지 |
| 직무 역할 | [7.4](#74-역할-관리)에서 정의한 값 |
| 직무 등급 | [7.5](#75-등급-관리)에서 정의한 값 |
| 팀 | 소속 팀 |
| 권한 | 권한 세트 또는 **팀 권한 상속** |
| 연봉 | **급여 정책이 인원별일 때만** 입력·표시 (단위: 만원) |
| 등록일 / 작업 | 등록 시각, 수정·삭제 |

### 인력 한 명 추가하기

1. **인력 추가**를 누릅니다.
2. **Jira 사용자**를 이름 또는 이메일로 검색해 선택합니다.
3. 직무 역할·등급·권한을 지정합니다.
   - **권한을 선택하지 않으면 Member 권한으로 자동 등록**됩니다.
   - 팀 권한을 따르게 하려면 **팀 권한 상속**을 선택합니다([7.8 참고](#팀-권한-상속)).
4. 정책이 인원별이면 연봉을 입력할 수 있습니다.

### 팀장의 팀 이동 제한

수정 창에서 **팀**을 바꿀 수 있지만, 그 사람이 **어떤 팀의 팀장이면 그 팀 밖으로 옮길 수 없습니다.** "팀장은 이끄는 팀 밖으로 옮길 수 없습니다. 팀장 지정을 먼저 해제하세요"가 표시됩니다. [7.3 팀 관리](#73-팀-관리)에서 팀장을 바꾼 뒤 이동하세요.

### 여러 명 한 번에 등록하기 (일괄 업로드)

![그림 7-4 엑셀 일괄 업로드](./Moves_Workforce_사용자_매뉴얼/images/07-users-bulk-upload.png)
*그림 7-4. 일괄 업로드 — ① 템플릿 다운로드 ② 파일 드롭 영역 ③ 진행률 ④ 결과 요약(전체/등록/중복/미존재/실패) ⑤ 실패 목록 버튼.*

1. **일괄 업로드** → **템플릿 다운로드**로 양식을 받습니다.
2. 양식을 채워 xlsx로 저장합니다. **최대 5MB, xlsx만 가능**합니다.
3. 파일을 드래그하거나 **파일 선택**으로 올립니다.
4. 처리는 백그라운드로 진행되며 진행률이 표시됩니다.
5. 결과가 **전체 / 등록 / 중복 / 미존재 / 실패**로 요약됩니다.
6. 실패 건이 있으면 **일괄 업로드 실패 목록** 버튼으로 사유를 확인합니다.

| 결과 항목 | 의미 |
|---|---|
| 등록 | 정상 등록됨 |
| 중복 | 이미 워크포스에 있는 사용자 |
| **미존재** | **Jira에 없는 계정** — Jira 사용자로 먼저 초대돼 있어야 등록됩니다 |
| 실패 | 그 밖의 오류(실패 목록에서 사유 확인) |

### 알아두기

- 급여 정책이 등급 기반이면 **"개인 연봉은 입력·표시되지 않습니다"** 안내가 표시됩니다([7.1](#71-일반-설정)).
- 사용자를 삭제하면 복구할 수 없습니다. 삭제 전 확인 창이 표시됩니다. 삭제된 사람이 팀장이던 팀은 **팀장이 비워집니다.**
- 여기서 등록한 연봉은 프로젝트 인건비 계산 중 **연봉 투입 유형**에서 사용됩니다([5.2 급여 관리](#523-급여-관리)).

### 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| 업로드 결과가 전부 "미존재"입니다 | 대상자들이 Jira 사용자로 초대돼 있지 않습니다 |
| 연봉 칸이 보이지 않습니다 | 급여 정책이 등급 기반입니다 |
| 권한 세트를 고를 수 없습니다 | 내 권한보다 넓은 세트는 배정할 수 없습니다. 「권한 관리」 쓰기 보유자에게 요청하세요 |
| 팀을 바꾸려는데 거부됩니다 | 그 사람이 팀장입니다. [7.3](#73-팀-관리)에서 팀장을 먼저 해제하세요 |
| 팀장으로 지정하려는데 목록에 없습니다 | 그 사람을 먼저 여기서 인력으로 등록해야 합니다 |
| 프로젝트 배정 화면에서 "백오피스에 등록되지 않은 사용자"라고 나옵니다 | 같은 이유입니다. 인력으로 먼저 등록하세요 |

## 7.3 팀 관리

### 접근 권한

| 구분 | 필요 권한 |
|---|---|
| 화면 조회 | 「팀 관리」 읽기 |
| 팀 추가·수정·삭제 | 「팀 관리」 쓰기 |
| 계층 이동(드래그) | 「팀 관리」 쓰기 |
| 팀원 배치·소속 해제 | 「팀 관리」 쓰기 |
| 팀 권한 세트 지정 | 「팀 관리」 쓰기. **자기 권한을 넘는 세트는 걸 수 없습니다** |

- 팀 **목록**은 「인력 관리」 읽기로도 조회됩니다(인력 관리 화면의 팀 컬럼·필터에 필요). 편집은 「팀 관리」 쓰기만 가능합니다.
- 팀장 후보는 [7.2 인력 관리](#72-인력-관리)에 등록된 인원으로 한정됩니다.
- 여기서 지정한 팀 권한 세트는 [7.8 권한 관리](#78-권한-관리)에서 만든 세트 중에서 고릅니다.

---

**언제 쓰나** — 조직 계층과 팀 소속을 구성할 때. 좌측 **팀 트리**, 우측 **선택 팀 상세** 구성입니다.

![그림 7-5 팀 관리](./Moves_Workforce_사용자_매뉴얼/images/07-teams.png)
*그림 7-5. 팀 관리 — ① 팀 트리(검색·모두 펼치기/접기·팀 미지정 N명) ② 팀 추가 ③ 선택 팀 상세(팀장·권한 세트 상속 문장) ④ 팀원 목록(팀장 맨 앞)·팀원 배치·소속 해제.*

### 팀 만들기

1. **팀 추가**를 누릅니다.
2. 입력 항목:

| 항목 | 설명 |
|---|---|
| 팀명 | 중복 불가 |
| 상위 팀 | 비우면 **최상위 팀**으로 생성 |
| 팀장 | **서비스에 등록된 인원**([7.2](#72-인력-관리)) 중에서만 지정 가능. **지정하면 소속이 이 팀으로 변경됩니다** |
| 팀 권한 세트 | **개인 권한이 지정되지 않은 팀원에게만** 적용 |
| 설명 | |

> 팀장으로 지정된 사람은 [마이페이지 > 내 팀](#32-내-팀-팀장-전용)에서 팀원 현황을 볼 수 있게 되고, [자원 관리](#6-자원-관리)의 조회 범위도 자신의 팀으로 열립니다.

### 팀장 규칙

| 규칙 | 화면에서 일어나는 일 |
|---|---|
| **팀장은 반드시 그 팀 소속** | 다른 팀 사람을 팀장으로 지정하면 저장과 함께 **소속이 이 팀으로 옮겨집니다.** 지정 폼에 "팀장으로 지정하면 소속이 이 팀으로 변경됩니다" 안내가 표시됩니다 |
| **한 사람은 한 팀만 이끕니다** | 이미 다른 팀의 팀장인 사람은 지정할 수 없습니다(겸임 불가). 먼저 그 팀의 팀장을 바꾸세요 |
| **팀장은 팀 밖으로 옮길 수 없습니다** | 팀원 배치·소속 해제·[7.2 인력 수정](#72-인력-관리)에서 팀장을 다른 팀으로 옮기려 하면 "팀장은 이끄는 팀 밖으로 옮길 수 없습니다. 팀장 지정을 먼저 해제하세요"로 거부됩니다 |
| 팀장 해제·교체 | 이전 팀장의 소속은 그대로 둡니다(자동으로 빠지지 않습니다) |
| 팀장이 **인력 삭제**되면 | 그 팀의 팀장이 비워집니다 |

팀장은 팀원 목록 **맨 앞**에 **팀장** 배지와 함께 표시되고, [인력 관리](#72-인력-관리)·[프로젝트 인력 목록](#52-인력-관리)에서도 같은 배지가 붙습니다.

### 계층 바꾸기

- 팀을 끌어 다른 팀 위에 놓으면 **상위 팀이 바뀝니다.**
- **"여기에 놓으면 최상위 팀이 됩니다"** 영역에 놓으면 최상위로 이동합니다.
- **모두 펼치기 / 모두 접기**, **팀 검색**을 제공합니다.

**차단되는 이동**

| 상황 | 안내 |
|---|---|
| 하위 팀 밑으로 이동 | "하위 팀 밑으로는 옮길 수 없습니다" (순환 방지) |
| 계층 깊이 한도 초과 | "계층 깊이 한도를 초과합니다" — 하위 팀까지 함께 이동하기 때문입니다 |
| 목록이 오래됨 | "지금은 팀을 옮길 수 없습니다. 목록을 새로고침한 뒤 다시 시도하세요" |

### 팀원 배치

- **팀원 배치** 버튼으로 여러 명을 한 번에 넣습니다. **한 번에 최대 500명.**
- **사용자는 하나의 팀에만 속합니다.** 다른 팀 소속자를 선택하면 **이 팀으로 이동**합니다. 단, 다른 팀의 **팀장**은 데려올 수 없습니다.
- **소속 해제 (N)** 으로 선택 인원을 팀 미지정 상태로 만듭니다. 팀장은 해제할 수 없습니다.
- 좌측 트리 하단에서 **팀 미지정 N명**을 확인할 수 있습니다.

### 팀 권한 상속

팀에 권한 세트를 지정하면, **개인 권한이 "팀 권한 상속"인 팀원**이 그 권한을 따릅니다. 상세 화면에 현재 상태가 문장으로 표시됩니다.

| 표시 | 의미 |
|---|---|
| 이 팀의 권한 세트: {이름} | 이 팀이 직접 권한을 가짐 |
| 상위 팀 '{팀}'의 권한 세트({이름})를 상속합니다 | 상위에서 물려받는 중 |
| **이 팀과 상위 팀 어디에도 권한 세트가 없습니다** | 이 팀에 배치되고 개인 권한이 '팀 권한 상속'인 사용자는 **모든 권한을 잃습니다** |

> 팀장을 새로 지정하면 그 사람도 이 팀으로 옮겨져 팀 세트를 상속받을 수 있으므로, 팀 권한 세트는 **지정자 자신의 권한을 넘지 않는 범위**에서만 걸 수 있습니다.

### 팀 삭제

- 하위 팀은 **상위 팀으로 이동**하고, 팀원은 **팀 미지정** 상태가 됩니다.
- 삭제 전 미리보기로 알려주는 것:
  - **권한을 잃는 인원 수** (팀 권한을 상속받던 사람)
  - **상속이 바뀌는 인원 수** (하위 팀 소속자)
- 프로젝트 배정 정리 결과도 함께 안내됩니다.

### 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| "순환 참조가 감지된 팀이 있습니다" 경고 | 상위 팀 설정이 서로를 가리키고 있습니다. 해당 팀의 상위 팀을 다시 지정하세요 |
| "상위 팀 연결이 유효하지 않아 최상위로 표시 중" | 상위 팀이 삭제됐거나 조회되지 않습니다. 상위 팀을 다시 지정하세요 |
| "팀 수가 조회 한도를 초과해 일부만 표시됩니다" | 관리자에게 문의하세요 |
| 팀장 후보 목록이 비어 있습니다 | [7.2 인력 관리](#72-인력-관리)에서 인원을 먼저 등록해야 합니다 |
| 팀장으로 지정했더니 그 사람 소속이 바뀌었습니다 | 정상입니다. 팀장은 그 팀의 구성원이어야 합니다 |
| "팀장은 이끄는 팀 밖으로 옮길 수 없습니다" | 그 팀에서 팀장을 먼저 바꾸거나 비운 뒤 이동하세요 |
| 배치하려는 인원이 "이 팀 범위 밖"이라고 나옵니다 | 목록을 새로고침한 뒤 다시 시도하세요 |

## 7.5 등급 관리

### 접근 권한

| 구분 | 필요 권한 |
|---|---|
| 화면 조회 | 「등급 관리」 읽기 |
| 등급 추가·수정·삭제·빠른 추가 | 「등급 관리」 쓰기 |
| 급여 밴드(하한·상한·대표값) 입력 | 「등급 관리」 쓰기 |
| 급여 밴드 **금액 열람** | 「비용」 읽기 또는 「등급 관리」 권한. 없으면 금액이 응답에서 제외됩니다 |

- 등급 **목록**은 「인력 관리」 읽기 또는 「일반 설정」 읽기로도 조회됩니다(인력 화면의 선택지, 급여 정책 카드의 "밴드 미설정 등급 수" 계산에 필요).
- 급여 밴드는 급여 정책이 **등급 기반**일 때 인건비 계산에 쓰입니다([7.1](#71-일반-설정)).

---

**언제 쓰나** — 인력 **등급(Level)** 을 정의하고, 등급 기반 급여 정책을 쓴다면 **급여 밴드**를 채울 때.

![그림 7-7 등급 관리](./Moves_Workforce_사용자_매뉴얼/images/07-levels.png)
*그림 7-7. 등급 관리 — ① 등급 표(급여 범위·대표값) ② 등급 추가 창(하한·상한·대표값·중앙값 계산) ③ 빠른 추가 프리셋 ④ 정책이 인원별일 때의 "급여 밴드는 사용되지 않습니다" 안내.*

### 목록 컬럼

| 컬럼 | 설명 |
|---|---|
| 등급 / 설명 | 등급명과 설명 (예: Senior / 10년차 이상) |
| 급여 범위 | 하한 ~ 상한 |
| 대표값 | **인건비 계산에 실제로 쓰이는 값** |

### 등록 방법 두 가지

| 방법 | 설명 |
|---|---|
| **등급 추가** | 이름·설명·급여 밴드를 입력해 하나씩 등록 |
| **빠른 추가** | 직급 체계 프리셋에서 골라 한 번에 등록 |

**프리셋 종류**: 일반(Junior/Senior) · 등급제(G1~G5) · 한국식 직급 · Band 체계

### 급여 밴드 입력 규칙

급여 정책이 **등급 기반**일 때 사용됩니다.

| 항목 | 규칙 |
|---|---|
| 하한 / 상한 | 0 이상. **하한이 상한보다 크면 저장 거부** |
| **대표값** | **계산에 쓰이는 값.** 비워 두면 **중앙값**(`(하한 + 상한) ÷ 2`)이 자동 입력됩니다 |

- **중앙값 계산** 버튼으로 대표값을 채울 수 있습니다.
- 대표값이 하한~상한 범위를 벗어나도 **저장은 허용**됩니다(관리자 판단 존중). "대표값이 급여 범위를 벗어났습니다. 그대로 저장할 수 있습니다" 경고만 표시됩니다.

> 급여 정책이 '인원별'이면 **"급여 밴드는 사용되지 않습니다"** 안내와 함께 [설정으로 이동하는 링크](#71-일반-설정)가 표시됩니다.

### 밴드를 비워 두면 생기는 일

등급 기반 정책에서 **밴드(대표값)가 없는 등급**의 인원은 **인건비가 0으로 계산**됩니다.

- [7.1 일반 설정](#71-일반-설정)에서 정책을 전환할 때 "등급 N개에 급여 밴드가 없습니다" 경고가 표시됩니다.
- 비용 화면의 [**미산정 인원**](#인건비가-0원으로-나올-때) 지표로도 확인할 수 있습니다.

## 7.7 프로젝트 상태 관리

### 접근 권한

| 구분 | 필요 권한 |
|---|---|
| 화면 조회 | 「프로젝트 상태 관리」 읽기 |
| 상태 추가·수정·삭제 | 「프로젝트 상태 관리」 쓰기 |
| 상태 연결(흐름) 편집 | 「프로젝트 상태 관리」 쓰기 |
| 칸반 화면에서 컬럼 추가·이름 변경·삭제 | 「칸반 보드」 쓰기 |

- 같은 상태를 두 곳에서 만질 수 있습니다. **설정 화면은 「프로젝트 상태 관리」**, **칸반 화면은 「칸반 보드」** 권한을 씁니다.

---

**언제 쓰나** — 프로젝트의 **상태(칸반 컬럼)** 와 **상태 전이 흐름**을 정의할 때.

기본 시드 상태는 `To Do` → `IN PROGRESS` → `DONE` 입니다.

![그림 7-9 프로젝트 상태 관리와 상태 흐름 편집](./Moves_Workforce_사용자_매뉴얼/images/07-project-status.png)
*그림 7-9. 프로젝트 상태 관리 — ① 상태 표(이름·색) ② 상태 추가 ③ 상태 연결 편집(노드와 화살표로 흐름 정의, 연결되지 않은 상태 표시).*

### 상태 추가·수정

1. **상태 추가**를 누릅니다.
2. **상태 이름**(예: 진행중)과 **색상**을 지정합니다.
3. 행에서 수정·삭제할 수 있습니다.

> 여기서 정의한 상태가 [프로젝트 목록](#41-프로젝트-목록)의 상태 선택지와 [칸반 보드](#42-칸반-보드)의 **컬럼**이 됩니다. 칸반 화면에서도 컬럼 추가·이름 변경·삭제를 할 수 있습니다. 상태 색은 목록·칸반·My Work 카드의 상태 라벨에 그대로 쓰입니다.

### 상태 흐름 편집

**상태 연결 편집**을 누르면 상태 간 이동 흐름을 시각적으로 정의합니다.

**규칙**

- 각 상태는 **다음 상태 하나, 이전 상태 하나**만 가질 수 있습니다(1:1 연결).
- **순환 연결은 허용되지 않습니다.**
- 연결되지 않은 상태는 "연결되지 않은 상태입니다"로 표시됩니다.
- 칸반에서 카드를 옮기거나 프로젝트 상태를 바꿀 때 **서버가 이 흐름과 상태 존재 여부를 검증**합니다. 거부되면 원래 상태로 되돌아가고 사유가 표시됩니다.

### 삭제 제약

| 제약 | 이유 |
|---|---|
| 최소 1개의 상태가 필요합니다 | 상태가 하나도 없으면 프로젝트를 만들 수 없고 칸반이 비어 보입니다 |
| 이전 상태가 없으면 삭제할 수 없습니다 | 삭제 시 그 상태의 프로젝트를 옮길 곳이 필요합니다 |

> 삭제하면 그 상태에 있던 **프로젝트는 이전 상태로 변경**됩니다(프로젝트가 삭제되지 않습니다).

- 워크로그 추출과 Jira 이슈 패널의 워크로그 기록은 이 범위와 무관합니다(Jira 권한 기준).

### 팀 권한 상속

개인 권한 세트를 지정하는 대신 **팀 권한 상속**을 선택하면 소속 팀(없으면 상위 팀)의 세트를 따릅니다.

- 선택 시 **"현재 상속받게 될 권한: {이름} ({팀})"** 이 미리 표시됩니다.
- 상속받을 권한이 없거나 팀에 소속되지 않았으면 **"이 사용자는 모든 권한을 잃게 됩니다"** 경고가 나옵니다.
- 팀에 권한 세트를 거는 방법은 [7.3 팀 관리](#팀-권한-상속)를 참고하세요.

### 알아두기

- 권한 검사는 화면 노출과 별개로 **서버에서도 수행**됩니다. 권한 없는 작업을 시도하면 "이 작업을 수행할 권한이 없습니다"가 표시됩니다.
- 권한별로 무엇이 되고 안 되는지는 [부록 B](#부록-b-권한별-사용-범위-요약)를 참고하세요.
- 사용자가 자신의 현재 권한을 확인하려면 [마이페이지 > 내 권한](#31-내-현황)을 보면 됩니다.

## 8. 통합 대시보드 (전사)

### 접근 권한

| 구분 | 필요 권한 |
|---|---|
| 메뉴·화면 진입 | 「리포트」 읽기 (없으면 **사이드바에 메뉴가 없고**, 주소로 들어가도 권한 안내 화면이 뜹니다) |
| 종합 개요 · 일정 · 범위 · 자원 서브탭 | 「리포트」 읽기 |
| **비용** 서브탭 | 「리포트」 읽기 **+** 「비용」 읽기 |
| **지금 재집계** 실행 | 「리포트」 쓰기 |

- 표시되는 프로젝트는 권한 세트의 **조회 범위**(전체 / 소속 프로젝트만 / 내 팀만)로 필터됩니다. 범위가 좁으면 전사 대시보드라도 일부 프로젝트만 비교됩니다.
- 가동률 밴드(과소/과부하/심한 과부하) 경계값은 [7.1 일반 설정](#71-일반-설정)을 따릅니다.

---

**언제 쓰나** — 프로젝트 하나가 아니라 **여러 프로젝트를 한 화면에서 비교**할 때. 경영 보고, 포트폴리오 점검, 위험 프로젝트 선별에 씁니다.

![그림 8-1 통합 대시보드 상단](./Moves_Workforce_사용자_매뉴얼/images/08-portfolio-overview.png)
*그림 8-1. 통합 대시보드 — ① 기준 시각과 지금 재집계 ② 프로젝트 필터 바(인원·투입 MM·인건비 요약) ③ 종합 개요 T/S/R 신호등 표 ④ 비교 서브탭(일정·범위·자원·비용).*

### 8.1 화면 공통

| 요소 | 설명 |
|---|---|
| **기준 시각** | 마지막 집계 시각. 이 화면은 **실시간이 아니라 배치 집계 결과**입니다 |
| **지금 재집계** | 즉시 집계를 실행합니다. 백그라운드로 **수 초~수십 초** 걸리며 완료되면 화면이 자동 갱신됩니다. 일부 프로젝트 집계가 실패하면 "직전 값 표시" 안내가 붙습니다 |
| **프로젝트 필터 바** | 비교할 프로젝트를 선택(전체 선택/해제)하면 **아래 모든 위젯이 함께 반응**합니다. 선택 프로젝트의 인원·투입 MM·인건비 합계가 요약됩니다 |

> **숫자가 방금 한 작업과 다르다면** 기준 시각을 먼저 확인하세요. 워크로그를 막 입력했다면 재집계 전까지 반영되지 않습니다.

### 8.2 종합 개요(T/S/R 신호)

각 프로젝트의 **일정(Time) / 범위(Scope) / 자원(Resource)** 상태를 **신호등(정상 / 주의 / 위험)** 으로 요약합니다. **신호등 ↔ 수치표** 보기를 전환할 수 있고, 행을 클릭하면 프로젝트 상세로 드릴다운합니다.

| 축 | 판정 기준 |
|---|---|
| **일정 (Time)** | 완성 진척 − 일정 진척 (음수로 벌어질수록 위험) |
| **범위 (Scope)** | 대기(할 일) 이슈 비중 |
| **자원 (Resource)** | 프로젝트 평균 가동률 밴드 — 과소 0.7 미만 / 과부하 1.1 이상 / 심한 과부하 1.3 이상 ([7.1 설정값](#71-일반-설정)) |

**읽는 법**

- 세 축이 모두 초록이면 정상 운영 중입니다.
- **일정 적색 + 자원 과부하**는 투입을 늘려도 일정을 따라가지 못하는 상태 — 범위 조정이나 증원을 검토합니다.
- **일정 적색 + 자원 과소**는 투입 부족 신호입니다.
- **범위 적색**은 착수도 못한 일이 많다는 뜻이라, 일정이 아직 초록이어도 후반에 몰릴 위험이 큽니다.

### 8.3 비교 서브탭

| 서브탭 | 위젯 |
|---|---|
| **일정 (Time)** | 프로젝트 일정(간트·경과율) · 공수 추이 비교(월/주·누적) · 리스크 TOP 프로젝트 |
| **범위 (Scope)** | 이슈 상태 분포(완료/진행/대기) · 완성률 vs 일정률 · 계획 대비 실적 공수 · 문제 이슈 한눈에(버블 TOP 50) · **토폴로지**(8.4) · 이슈 완료율 vs 진척률 · 지연 이슈가 몰린 담당자 |
| **자원 (Resource)** | 롤/레벨 분포 비교 · 인력 가동률(전사 종합 / 프로젝트별) · 작업 분포(투입 인력 대비 공수) · 인력 집중도 · 가동률과 투입 공수(산점도) · 전사 배정 관계도 |
| **비용 (Cost)** | 전사 비용 요약 · 계획 대비 실집행 · 비용 초과 위험 순위 · 소진율 vs 진척률 · 전사 월별 소진 추이 · 역할/레벨별 비용 · 완료 시 예상 비용 · MD 단가 비교 |

- 각 위젯에는 **계산식/해석 안내(ⓘ)** 가 있어 지표의 의미를 그 자리에서 확인할 수 있습니다.
- 일부 위젯은 **상단 프로젝트 필터와 무관**하게 전사 기준으로 그립니다(전사 가동률 분포, 지연 이슈가 몰린 담당자, 전사 배정 관계도). 위젯의 안내 문구에 명시돼 있습니다.
- 비용 서브탭은 「비용」 권한이 없으면 "인건비 조회 권한이 없어 비용 정보를 표시하지 않습니다"로 가려집니다. 급여 정책을 바꾼 뒤에는 **재집계 전까지** 이전 집계의 인건비를 표시하지 않습니다.
- 팀 축 비교는 이 화면이 아니라 [6.3 자원 관리 > 팀 분석](#63-팀-분석)에서 제공합니다.

### 8.4 토폴로지

범위 서브탭 상단의 **Workforce(RMS) 프로젝트 · 상태 · 이슈 토폴로지**는 `Workforce 허브 → 앱 프로젝트 → (Jira 스페이스) → 작업 상태 → 이슈` 경로를 관계망으로 그립니다.

![그림 8-2 토폴로지 위젯](./Moves_Workforce_사용자_매뉴얼/images/08-portfolio-topology.png)
*그림 8-2. 토폴로지 — ① 계층 필터(프로젝트/스페이스/상태)와 작업 상태 필터 ② Workforce 허브 ③ 프로젝트 노드(크기 = 투입 MD) ④ 상태 노드를 눌러 펼친 이슈 노드 ⑤ 스페이스 이슈 패널.*

| 조작 | 결과 |
|---|---|
| **계층** 필터 | 프로젝트까지 / 스페이스까지 / 상태까지 중 어디까지 펼칠지 |
| **작업 상태** 필터 | 할 일 / 진행 중 / 완료 중 보고 싶은 상태만 |
| 상태 노드 클릭 | 그 상태의 이슈가 그래프에 펼쳐집니다(여러 노드 동시 가능). 다시 누르면 접힘 |
| **전체 이슈 펼치기 / 모두 접기** | 한 번에 펼치거나 접기 |
| 프로젝트 노드 클릭 | 프로젝트 상세로 이동 |
| 스페이스 노드 클릭 | 오른쪽에 **스페이스 이슈** 패널(최대 300건, 실적·계획 포함) |
| 이슈 노드 클릭 | Jira에서 엽니다 |

- 프로젝트 노드 크기는 투입 공수(MD), 스페이스 노드 크기는 이슈 수, 이슈 노드 크기는 실제 투입 공수입니다.
- 프로젝트가 많으면 **위험도 상위만** 먼저 표시하고 **전체 표시**로 펼칠 수 있습니다.
- "스페이스 계층은 다음 집계 후 표시됩니다"가 뜨면 아직 스페이스 정보가 집계되지 않은 것입니다. 재집계 후 다시 열어 보세요.

### 8.5 가동률 두 종류의 차이

| 지표 | 분모 | 특징 |
|---|---|---|
| **가동률(종합)** | 한 사람이 참여한 **모든 프로젝트 기간을 겹치지 않게 합산** | 이중 계상 방지. **프로젝트 필터와 무관**하게 고정 |
| **프로젝트별 가동률** | 그 프로젝트 기간의 실효 가용 MD | [5.5 인력 분석](#552-인력-분석)과 같은 기준 |

> 두 숫자가 다르다고 오류가 아닙니다. **분모가 다른 서로 다른 지표**입니다.

### 8.6 프로젝트 상세 화면과의 관계

| 질문 | 이 화면 (8장) | 프로젝트 상세 (5장) |
|---|---|---|
| 어느 프로젝트가 위험한가? | **종합 개요 신호등**으로 선별 | — |
| 왜 위험한가? | 비교 서브탭·토폴로지로 축을 좁힘 | [5.5 진척률](#554-진척률)에서 원인 이슈까지 추적 |
| 누구를 조정할까? | 자원 서브탭에서 부하 비교 | [5.2 인력 관리](#52-인력-관리) · [6.4 프로젝트 배정](#64-프로젝트-배정) |

**권장 흐름**: 통합 대시보드에서 **위험 프로젝트를 고르고** → 프로젝트 상세 진척률에서 **원인을 찾고** → 자원 관리에서 **사람을 조정**합니다.

### 문제 해결

| 증상 | 원인과 해결 |
|---|---|

| 프로젝트가 일부만 보입니다 | 권한 세트의 조회 범위가 "소속 프로젝트만" 또는 "내 팀만"입니다 |
| 비용 서브탭이 가려져 있습니다 | 「비용」 읽기 권한이 없거나, 급여 정책 변경 후 아직 재집계하지 않았습니다 |
| 숫자가 오래됐습니다 | 배치 집계 결과입니다. 기준 시각을 확인하고 **지금 재집계**를 실행하세요(「리포트」 쓰기 필요) |

| 인건비가 0인 프로젝트가 있습니다 | 급여 미등록·기간 미설정 등입니다 — [5.2 인건비가 0원으로 나올 때](#인건비가-0원으로-나올-때) |

## 9. 워크로그 추출

### 접근 권한

| 구분 | 필요 권한 |
|---|---|
| 메뉴·화면 진입 | 「워크로그 추출」 읽기 (없으면 **사이드바에 메뉴가 없습니다**) |
| 검색·Excel 다운로드 | 「워크로그 추출」 읽기 |
| **조회되는 범위** | 앱 권한이 아니라 **본인의 Jira 권한**을 따릅니다. Jira에서 볼 수 있는 이슈의 워크로그만 나옵니다 |

- 이 화면은 앱 서버를 거치지 않고 **내 계정으로 Jira에 직접 질의**합니다. 그래서 앱의 프로젝트 조회 범위(소속 프로젝트만 등)와 무관하고, Jira에서 못 보는 이슈는 여기서도 안 보입니다.
- 기존 설치 환경에서는 이 권한이 **Admin 세트에만** 켜져 있습니다. 다른 세트에 열려면 [7.8 권한 관리](#78-권한-관리)에서 「워크로그 추출」 읽기를 추가하세요.

---

**언제 쓰나** — 앱 프로젝트에 편입됐는지와 무관하게 **Jira 전체**의 워크로그를 기간·프로젝트·작성자 기준으로 뽑아 정산·보고용 엑셀을 만들 때.

![그림 9-1 워크로그 추출 화면](./Moves_Workforce_사용자_매뉴얼/images/09-worklog-export.png)
*그림 9-1. 워크로그 추출 — ① 검색 조건(프로젝트·작성자·기간·추가 JQL) ② 진행 표시(이슈 검색 → 워크로그 수집, 취소) ③ 결과 요약 카드 ④ 미리보기 표 ⑤ Excel 다운로드.*

### 9.1 검색 조건

| 조건 | 필수 | 설명 |
|---|---|---|
| 프로젝트 | | Jira 프로젝트(스페이스). 여러 개 선택 가능. 선택하지 않으면 **접근 가능한 모든 프로젝트** |
| 작성자 | | 워크로그 작성자. 선택하지 않으면 전체 |
| 기간 | 필수 | 워크로그 **작업 시작일** 기준 시작일~종료일. 종료일은 시작일 이후여야 합니다 |
| 추가 JQL | | 위 조건과 AND로 결합됩니다 (예: `issuetype = Bug`) |

**조건 초기화**로 모두 비웁니다. 기간이 1년을 넘으면 "결과가 많으면 시간이 오래 걸릴 수 있습니다" 경고가 뜹니다.

### 9.2 검색과 수집

1. **검색**을 누르면 두 단계로 진행됩니다.
   - "이슈를 검색하는 중… (N건 확인)" — 조건에 맞는 이슈를 찾습니다.
   - "워크로그를 가져오는 중… (done/total)" — 이슈별 워크로그를 여러 건 동시에 가져옵니다.
2. 중간에 **취소**하면 "지금까지 수집한 결과만 표시합니다"로 멈춥니다. 부분 결과도 다운로드할 수 있습니다.
3. 끝나면 "워크로그 N건을 수집했습니다" 알림과 함께 결과가 표시됩니다.

**상한과 경고**

| 안내 | 의미 |
|---|---|
| 결과가 상한(5,000건)에 도달해 일부 이슈만 수집했습니다 | 이슈 수 상한입니다. 기간이나 프로젝트를 좁혀 다시 검색하세요 |
| N개 이슈의 워크로그를 가져오지 못했습니다 | 일부 실패. 나머지 결과만 표시합니다 |
| Jira 요청 한도에 걸렸습니다 | 잠시 후 다시 시도하세요 |
| JQL이 올바르지 않습니다 | 추가 JQL 문법을 확인하세요 |

### 9.3 결과 확인

**요약 카드**: 이슈 수 · 워크로그 건수 · 총 시간 · 총 MD(1MD 기준 시간은 [일반 설정](#71-일반-설정)의 1Day 근무 시간) · 추출 조건(기간·프로젝트·작성자 수·추가 JQL·추출 시각)

**미리보기 표** (상위 500건만 표시, 파일에는 전체 포함)

| 컬럼 | 설명 |
|---|---|
| 이슈키 / 요약 / 프로젝트키 | 워크로그가 달린 이슈 |
| 작성자 / 작성자 accountId | 작성자 표시명과 Jira 계정 ID |
| 시작일시 / 시작일 | 워크로그의 작업 시작 시각과 날짜 |
| 소요시간(초) / 소요시간(시간) | 기록된 시간 |
| 코멘트 | 워크로그 본문(서식 제거한 텍스트) |
| 워크로그ID | Jira 워크로그 ID |

컬럼 헤더로 정렬할 수 있고, 표의 정렬은 파일에 영향을 주지 않습니다.

### 9.4 Excel 다운로드

**Excel 다운로드**를 누르면 `.xlsx` 파일이 내려받아집니다.

| 시트 | 내용 |
|---|---|
| 워크로그 | 수집한 워크로그 **전체**(미리보기 상한과 무관) — 위 컬럼 그대로 |
| 요약 | 추출 조건과 합계(이슈 수·건수·총 시간·총 MD) |

파일명에는 기간이 들어갑니다. 파일 생성에 실패하면 "Excel 파일을 만들지 못했습니다"가 표시되니 다시 시도하세요.

### 알아두기

- **프로젝트 상세의 인력 분석·비용 화면과 값이 다를 수 있습니다.** 그 화면들은 앱 프로젝트에 편입된 이슈와 등록된 인력만 집계하지만, 여기는 Jira 전체가 대상입니다.
- 다른 사람의 워크로그 **코멘트**도 내려받습니다. 파일을 공유할 때 내용을 확인하세요.
- 특정 프로젝트의 인력별 투입만 필요하다면 [5.5 인력 분석](#552-인력-분석)의 엑셀 내보내기가 더 빠릅니다.

### 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| 사이드바에 메뉴가 없습니다 | 「워크로그 추출」 읽기 권한이 없습니다. 기존 설치에서는 Admin만 기본으로 켜져 있습니다 |
| 특정 프로젝트가 결과에 없습니다 | Jira에서 그 프로젝트를 볼 권한(Browse Projects)이 없습니다 |
| 상한 경고가 계속 뜹니다 | 기간을 나누거나 프로젝트를 지정해 여러 번 추출하세요 |
| 검색이 매우 느립니다 | 이슈가 많은 조건입니다. 기간·프로젝트를 좁히거나, 진행 중 취소해 부분 결과를 먼저 받으세요 |

## 10. Jira 이슈 화면의 Moves Workforce 패널

### 접근 권한

| 구분 | 필요 권한 |
|---|---|
| 패널 표시 | **앱 권한 불필요** — 그 이슈가 **앱 프로젝트에 편입**돼 있고, Jira에서 이슈를 볼 수 있으면 표시됩니다 |
| 워크로그 기록 | Jira의 **Work On Issues** 권한 + 그 Jira 프로젝트의 **시간 추적 활성화** |
| 워크로그 수정·삭제 | **본인이 쓴 것만** (Jira의 Edit/Delete Own Worklogs) |
| 프로젝트명·"Workforce에서 열기" 링크 | 「프로젝트 관리」 읽기 **+** 그 프로젝트가 내 조회 범위 안일 때. 범위 밖이면 링크만 숨겨지고 공수·기록은 그대로 됩니다 |
| 라이선스 | 앱 라이선스가 명시적으로 비활성이면 패널이 안내만 표시합니다 |

---

**언제 쓰나** — Jira에서 이슈를 보다가 **앱을 열지 않고** 그 자리에서 계획 공수 대비 투입을 확인하고 워크로그를 남길 때.

패널은 이슈가 **앱 프로젝트에 편입된 경우에만** 나타납니다. 편입은 [5.3 작업 추가](#534-작업-추가-창) 또는 [자동 편입](#533-자동-편입프로젝트-구독)으로 합니다. 앱 업그레이드 전에 편입된 이슈는 백그라운드 정리 후 순차적으로 표시됩니다.

### 10.1 표시 위치

![그림 10-1 Jira 이슈 화면의 두 패널](./Moves_Workforce_사용자_매뉴얼/images/10-issue-panel-both.png)
*그림 10-1. Jira 이슈 화면 — ① 오른쪽 컨텍스트 패널(요약: 프로젝트명·KPI·+ 워크로그 기록·Workforce에서 열기) ② 활동 탭 "Moves Workforce"(전체: KPI·기록 폼·최근 워크로그).*

| 위치 | 이름 | 내용 |
|---|---|---|
| 이슈 오른쪽 **컨텍스트 패널** | Moves Workforce | 요약 — 프로젝트명, KPI 4개(간략), **+ 워크로그 기록**, **Workforce에서 열기** |
| 이슈 하단 **활동 탭** | Moves Workforce | 전체 — KPI 4개, 워크로그 기록 폼, **최근 워크로그** 목록(내 것 수정·삭제) |

컨텍스트 패널의 **+ 워크로그 기록**을 누르면 활동 탭으로 이동해 기록합니다("목록·수정은 활동 탭에서").

### 10.2 KPI 읽기

| 지표 | 의미 |
|---|---|
| 계획 작업량 | 이슈의 Original Estimate를 MD/MM로 환산 |
| 투입 공수 | 누적 워크로그 |
| **내 몫** | 투입 공수 중 **내가 기록한** 부분. 최근 워크로그 N건만 읽어 계산하므로 **근사치**입니다 |
| 진행률 | Jira 시간 추적 기준 진행 정도 |

단위는 MM/MD이며 안내(ⓘ)에 `1MM = N일(H h) · MD = 시간 ÷ 1Day 근무 시간 · MM = MD ÷ N (이번 달 기준)` 이 표시됩니다. 기준값은 [7.1 일반 설정](#71-일반-설정)과 [7.9 휴일 관리](#79-휴일-관리)의 이번 달 근무일입니다.

### 10.3 워크로그 기록하기

![그림 10-2 활동 탭의 워크로그 기록 폼과 최근 워크로그](./Moves_Workforce_사용자_매뉴얼/images/10-issue-panel-activity.png)
*그림 10-2. 활동 탭 — ① KPI ② 기록 폼(날짜·시작·종료·소요 시간·코멘트) ③ 최근 워크로그(내 것에 수정·삭제 버튼).*

1. 활동 탭의 **워크로그 기록** 폼에서 날짜, 시작 시간, 종료 시간을 입력합니다. 소요 시간이 자동 계산되며 직접 고칠 수도 있습니다.
2. 코멘트를 적고 **기록**을 누릅니다. **되돌리기**로 입력을 초기화합니다.
3. 아래 **최근 워크로그**에 바로 반영되고 KPI가 갱신됩니다. 앱의 [My Work](#2-my-work)에서도 같은 워크로그가 보입니다.

**최근 워크로그** 목록에서 내가 쓴 항목(**나** 표시)은 **수정 / 삭제**할 수 있습니다. 다른 사람 것은 조회만 됩니다. 목록은 최근 N건만 보여주며 "최근 N건만 표시 — 내 몫은 근사치입니다" 안내가 붙습니다.

### 10.4 패널이 안내만 보여줄 때

| 안내 | 의미와 조치 |
|---|---|
| 연결된 프로젝트가 없습니다 | 이 이슈가 앱 프로젝트에 편입되지 않았습니다. 작업 관리에서 추가하면 표시됩니다 |
| 시간 추적이 꺼져 있습니다 | 그 Jira 프로젝트에서 시간 추적이 비활성이라 워크로그를 기록할 수 없습니다. Jira 관리자에게 요청하세요 |
| Jira 워크로그 기록 권한이 없습니다 | Work On Issues 권한이 없습니다 |
| Moves Workforce 라이선스가 활성 상태가 아닙니다 | 관리자에게 라이선스 상태를 확인하세요 |
| 이슈 정보를 불러오지 못했습니다 | 일시 오류. 새로고침하세요 |
| 워크로그 목록을 불러오지 못했습니다. 내 몫은 알 수 없습니다 | KPI 중 내 몫만 계산 불가. 기록은 가능합니다 |

### 알아두기

- 패널에서 기록한 워크로그는 Jira 워크로그 그 자체입니다. 앱의 워크로그와 별도 저장소가 아닙니다.
- 프로젝트명과 **Workforce에서 열기** 링크는 내 조회 범위 안의 프로젝트일 때만 보입니다. 범위 밖이면 링크가 숨겨질 뿐 공수 확인과 기록은 됩니다. 이슈 자체는 Jira가 이미 보여주고 있기 때문입니다.
- 이슈를 프로젝트에서 **제외**하거나 프로젝트를 **삭제**하면 그 이슈의 패널도 사라집니다.

| 가동률 | 실제 일한 양(MD) ÷ 일할 수 있었던 양(근무일 − 연차·공휴일). 1.0 = 100% |
| 실효 가용 MD | 기간 근무일에서 연차·공휴일을 뺀 실제 출근 가능 일수. 가동률의 분모 |
| 완성 진척 | 계획공수 가중 진행률. "얼마나 끝났나" |
| 일정 진척 | 경과 근무일 ÷ 전체 근무일. "시간이 얼마나 흘렀나" |
| 공수 진척 | 워크로그 누적 공수 소진. "얼마나 일했나" |
| 처리율 | 작업의 진행 정도(%). Jira 시간 추적(기록 시간·잔여 추정) 기반 |
| 계획 작업량 | Jira Original Estimate 기반 계획 공수(MD) |
| 내 몫 | 여러 명이 참여한 이슈에서 한 사람에게 귀속되는 부분. 화면에 따라 **내가 기록한 워크로그**(이슈 패널) 또는 **남은 작업량의 균등 분할**(인력 현황)로 계산되는 근사치 |
| 확정 지연 | 완료된 이슈의 (실적일 − 기한) 평균. 회고 지표 |
| 예측 지연 | 남은 공수 추세로 본 예상 종료일 − 종료 예정일. 예보 지표(낙관 근사치) |

### 프로젝트 조회 범위

| 범위 | 보이는 프로젝트 |
|---|---|
| **전체 프로젝트** | 모든 프로젝트 |
| **소속 프로젝트만** | 본인이 인력으로 등록된 프로젝트만 |
| **내 팀만** | 내 소속 팀·하위 팀과 내가 이끄는 팀·하위 팀 기준의 프로젝트. **유효한 팀이 없으면 비어 있음** |

Jira 관리자와 Admin 세트는 이 설정과 무관하게 항상 전체를 조회합니다.

> **내 팀만**은 **프로젝트 범위만** 제한합니다. 자원 관리·인력 관리 조회 권한이 함께 있으면 전사 인원 목록은 그대로 보입니다.

> **워크로그 추출과 Jira 이슈 패널은 이 범위와 무관**합니다. 둘 다 본인의 Jira 권한으로 동작합니다.

### 화면이 안 보일 때 확인 순서

1. **[마이페이지 > 내 권한](#31-내-현황)** 에서 내 권한 세트와 프로젝트 조회 범위를 확인합니다.
2. 위 표에서 그 기능에 필요한 권한을 확인합니다.
3. 관리자에게 **필요한 권한 항목명과 읽기/쓰기 여부**를 명시해 요청합니다.
4. 프로젝트가 안 보이는 경우라면, 권한이 아니라 **[프로젝트 인력 등록](#52-인력-관리)** 이 빠진 것일 수 있습니다.
5. 그래도 안 되면 Jira 자체 권한(Browse Projects 등)을 확인합니다 — [1.4 ④](#④-jira-자체-권한도-따로-있습니다).
