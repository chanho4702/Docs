## 1. 목적·범위

Moves Workforce의 모든 산출물에서 **동일한 의미로 사용하는 용어**를 한 곳에 정의한다. 다른 문서는 용어를 재정의하지 않고 이 문서를 참조한다. 정의가 흩어져 어긋나는 것을 방지하는 단일 소스(SSOT)다.

## 2. 용어 정의

### 2.1 제품·도메인

| 용어 | 정의 |
|------|------|
| **Moves Workforce / Moves RMS** | Atlassian Jira Cloud용 Forge 앱. 프로젝트의 인력·팀·워크로그·공수·진척·인건비를 관리·분석하는 RMS. |
| **RMS** | Resource Management System. 인력·공수 관점에서 프로젝트 상태를 보여주는 시스템. |
| **Forge** | Atlassian이 제공하는 클라우드 앱 실행 플랫폼. 앱 코드가 Atlassian 인프라 안에서 실행된다(외부 서버 없음). |
| **글로벌 페이지 (Global Page)** | 이 앱의 유일한 Jira UI 진입점(`jira:globalPage`, 앱명 "Moves Workforce"). 내부는 SPA 라우팅으로 화면 전환. |
| **워크로그 (Worklog)** | Jira 이슈에 기록된 작업 시간. **모든 공수 계산의 원천 데이터**이며 Jira가 원본(앱에 별도 미러링하지 않음). |
| **이슈 (Issue)** | Jira의 작업 단위(스토리·태스크·버그 등). 진척·완성률 계산의 기본 단위. |
| **인력 / 리소스 (Resource)** | Workforce에 등록되어 프로젝트에 배정될 수 있는 사람. 프로젝트 참여 명단은 `projectusers`에 저장한다. |
| **팀 (Team)** | 현재 조직 소속을 나타내는 계층형 단위. 상위 팀·팀장·권한 세트를 가질 수 있으며 사용자는 한 팀에 소속된다. |
| **담당 팀 (Project Team)** | 프로젝트의 계획·책임 주체로 지정한 팀(`project_team`). 프로젝트 인력 명단과 별개이며 팀 지정만으로 인원이 자동 추가되지는 않는다. |
| **팀장 (Team Lead)** | `team.leaderAccountId` 관계로 판정되는 사용자. 권한 세트와 별도인 관계 기반 권한으로 자신이 이끄는 팀과 하위 팀의 허용된 정보에 접근한다. |
| **자원관리 (Resource Management)** | `/resource`에서 인력 현황·조직 현황·팀 분석·프로젝트 배정을 다루는 기능 영역. `RESOURCE_MANAGEMENT` 권한으로 제어한다. |
| **프로젝트 구독 (Project Subscription)** | RMS 프로젝트가 Jira 소스를 구독해 조건에 맞는 이슈를 `moves_RMS_projectId`로 자동 편입하는 규칙. SPACE는 Jira 프로젝트 전체, BOARD는 보드의 저장 필터+sub-query를 기본 범위로 삼는다. |
| **백필 (Backfill)** | 구독 생성 시 기존 이슈까지 스캔해 편입하는 처리. 선택하지 않으면 구독 시점 이후 생성된 이슈만 대상이다. |
| **리컨실 (Reconcile)** | 이벤트 유실·보드 조건 후행 충족·이슈 이동을 복구하기 위해 시간별로 구독 소스를 재검사하는 정합성 스윕. |

### 2.2 공수 지표

| 용어 | 정의 |
|------|------|
| **MD (Man-Day)** | 워크로그를 일 단위로 환산한 투입량. **근무일 1일 = 1MD.** |
| **1MM (Man-Month)** | 그 달의 **실제 근무일 수(평일 − 공휴일)**. 관리자 입력값이 아니라 캘린더·휴일 데이터로 자동 계산. |
| **MM (절대 공수)** | "얼마나 일했나"를 나타내는 절대량. `totalMD ÷ 그 달 1MM 근무일`. |
| **가동률 (Utilization, %)** | "가용 시간 대비 얼마나 채웠나"를 나타내는 상대 지표. `totalMD ÷ effectiveMD(가용 근무일)`. MM과 **분리**해서 산출. |
| **effectiveMD (가용 근무일)** | 연차 등을 뺀 실제 투입 가능한 근무일. 가동률의 분모. |
| **base MD (기준 공수)** | 어떤 기간의 근무 가치 합. 주말=0, 공휴일=workRatio, 평일=1을 더해서 구함. |
| **workRatio** | 공휴일의 근무 비율. 0=휴무, 0.5=반휴, 1=정상 근무. |
| **hourRate** | 1일 = N시간 환산 계수(시간↔MD 변환용). settings 항목. |

### 2.3 진척도 (3층)

| 용어 | 정의 |
|------|------|
| **진척도 3층** | 공수·완성·일정을 **한 숫자로 합치지 않고** 세 층으로 분리해 보는 방식. |
| **층1 · 공수 (소진율)** | 얼마나 일했나. 계획 누적(선형) vs 실제 누적(워크로그 일별 합). EVM의 AC. |
| **층2 · 완성 (진척)** | 얼마나 끝났나. `Σ(이슈 진행률 × 계획MD) ÷ Σ(계획MD)`. EVM의 EV. |
| **층3 · 일정 (달력)** | 시간이 얼마나 흘렀나. `경과 근무일 ÷ 전체 근무일`. EVM의 PV. |
| **이슈 진행률** | 완료=100%(캡), 진행 중=`min(실투입MD÷계획MD, 100%)`, 할 일=0%. 진행 중은 공수 기반 **근사치**. |
| **EVM** | Earned Value Management. 공수/완성/일정을 AC/EV/PV로 보는 프로젝트 관리 기법. |
| **확정 지연** | 완료 이슈의 실제 완료일 − 마감일(>0만 집계). |
| **예측 지연** | 미완료 이슈의 남은 공수 기준 예상 종료일 vs 프로젝트 종료일(낙관적 근사). |

### 2.4 포트폴리오·신호등

| 용어 | 정의 |
|------|------|
| **포트폴리오 대시보드 (전사, `/dashboard`)** | 전 프로젝트를 가로질러 비교하는 통합 대시보드. "배치 스냅샷 + 프론트 재집계" 구조. |
| **스냅샷** | 일일 배치(`portfolio-snapshot`) 또는 수동 재집계가 적재하는 프로젝트별 집계 데이터. 수동 재집계 완료는 `lastAggregatedAt` 변경으로 식별한다. |
| **전사 가동률** | 인원별 기간 **합집합** 분모로 계산한 전사 지표(포트폴리오에서 유일한 배치 산출값). |
| **T / S / R 신호등** | 프로젝트 요약 3축. T=완성률−일정률(Time), S=잔여 작업 비중(Scope), R=가동률(Resource). |
| **계획 인건비** | `Σ effectiveSalary`. 현재 급여 정책으로 계산한 인원별 유효 인건비의 합. "예산(BAC)"이 **아님**. |
| **급여 정책 (Salary Policy)** | 전사 인건비 산정 원천. 개인 금액을 쓰는 `INDIVIDUAL`과 등급 대표값을 쓰는 `LEVEL_BAND` 중 하나를 적용한다. |
| **급여 밴드 (Salary Band)** | 등급별 급여 하한·상한·대표값. `LEVEL_BAND` 정책에서는 대표값을 사용하며, 대표값이 비어 있고 하한·상한이 모두 있으면 중앙값을 사용한다. |
| **유효 인건비 (Effective Salary)** | 비용 계산에 실제 사용되는 인원별 금액. `INDIVIDUAL`에서는 인력별 `salaryType`(`PROJECT` 기본 / `ANNUAL`)이 선택한 금액만 사용하고, `LEVEL_BAND`에서는 등급 대표값을 월할한다. |
| **미산정 인원 (Unpriced Member)** | `ANNUAL` 연봉이 없거나 `LEVEL_BAND`의 등급·대표값(또는 중앙값)을 결정할 수 없어 유효 인건비가 0인 인원. 화면에 누락 인원 수로 경고한다. |

### 2.5 기술·운영

| 용어 | 정의 |
|------|------|
| **resolver** | 프론트의 `invoke('함수명')` 호출을 처리하는 백엔드 함수. |
| **responseWrapper** | 모든 resolver 응답을 `{success, ...}` 형태로 통일하는 공통 래퍼. |
| **guardedDefine** | resolver를 권한 가드 + 응답 표준화와 함께 등록하는 표준 등록 방식. |
| **Forge SQL** | Forge의 관계형 DB(실체는 TiDB). 프로덕션 설치당 **1 GiB 한도**. FK·CASCADE·트랜잭션 미지원. |
| **Forge KVS** | Forge의 키-값 저장소. 값 하나 **240 KiB 제한**. 설정성 데이터·캐시용. |
| **asUser / asApp** | Jira API 호출 권한. 기본 asUser(사용자 권한), 배치·앱필드 write만 asApp. |
| **권한 세트** | 사용자에게 부여되는 권한 묶음. Admin/Member 시스템 세트, PM/PMO/Team Lead/Team Member 프리셋, 커스텀 세트가 있으며 사용자당 1개다. |
| **리소스 카탈로그 (권한 키)** | 권한 경계 단위. 각각 read/write 보유 여부로 접근 제어. |
| **projectScope** | 권한 세트의 프로젝트 데이터 범위. `ALL`(전체), `MEMBER_ONLY`(본인 참여), `TEAM_ONLY`(내 소속/리딩 팀과 각 하위 팀의 인원 참여 + 담당 팀 프로젝트) 중 하나다. TEAM_ONLY에 유효 팀이 없으면 빈 범위다. |
| **커스텀 필드** | 앱이 Jira에 등록하는 필드(projectId, coworkers, wbsParent, predecessors 등). 대부분 readOnly. |
