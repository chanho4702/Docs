# Moves Workforce 제품 개요 (PMS / RMS)

기준일: 2026-09-30

## 1. 제품 정의

Moves Workforce는 Jira Cloud에 설치하는 프로젝트·인력 관리 앱입니다. Jira 이슈와 워크로그를 원천 데이터로 삼아 프로젝트의 일정·진척·비용(PMS)과 인력의 투입·가동률·배정(RMS)을 한 앱에서 관리합니다.

한 줄 정의: **Jira의 업무 기록을 인력·공수·진척·비용의 판단 근거로 바꿔 주는 앱.**

## 2. 대상 사용자

1차 대상은 **Jira Cloud로 프로젝트를 수행하면서 투입 공수(MM)와 인건비를 집계·보고해야 하는 조직의 PM과 PMO**입니다. SI, IT 서비스, 에이전시처럼 사람의 투입량이 곧 원가인 조직이 해당합니다.

| 사용자 | 앱에서 하는 일 |
|---|---|
| PM (1차) | 프로젝트 일정·진척·비용 관리, 인력 편성과 작업 배정 |
| PMO·경영진 (1차) | 전사 프로젝트 비교, 위험 프로젝트 선별 |
| 팀장 | 팀원 부하 확인, 팀 단위 투입 분석 |
| 실무자 | 워크로그 기록, 내 작업·일정 확인 |
| 관리자 | 인력·조직·권한·근무 기준 설정 |

## 3. 해결하는 문제

| 지금 벌어지는 일 | Moves Workforce가 하는 일 |
|---|---|
| 이슈는 Jira에, 인력 배치는 엑셀에, 비용은 별도 시트에 있어 보고 때마다 손으로 모은다 | Jira 이슈·워크로그에 인력·팀·급여를 연결해 한곳에서 집계한다 |
| 프로젝트 하나의 작업이 여러 Jira 스페이스에 흩어져 있다 | 여러 스페이스의 이슈를 한 프로젝트로 묶고, 구독으로 자동 편입한다 |
| 투입 공수(MM)를 월말에 수기로 계산한다 | 워크로그를 근무 기준과 공휴일에 맞춰 MD·MM으로 자동 환산한다 |
| 진척률이 담당자의 감이거나 소진 공수를 그대로 옮긴 숫자다 | 완성·공수·일정을 따로 계산하고 그 차이로 지연을 판정한다 |
| 누가 바쁘고 누가 여유인지 모른 채 사람을 배정한다 | 연차·공휴일을 반영한 가동률과 스킬 적합도로 후보를 제시한다 |
| 인건비가 프로젝트 실적과 연결되지 않고, 급여 정보는 노출 위험이 있다 | 급여 정책으로 인건비를 자동 계산하고, 비용 정보는 별도 권한으로 통제한다 |

## 4. 대표 사용 시나리오

프로젝트 하나를 착수부터 보고까지 운영하는 흐름입니다.

| 단계 | 누가 | 무엇을 |
|---|---|---|
| 1. 기준 설정 (최초 1회) | 관리자 | 1일 근무 시간·공휴일을 정하고, 인력·팀·권한·급여 정책을 등록 |
| 2. 프로젝트 생성 | PM | 프로젝트를 만들고 기간·예산·필요 스킬을 입력 |
| 3. 작업 연결 | PM | 관련 Jira 스페이스를 구독. 조건에 맞는 이슈가 자동으로 프로젝트에 편입 |
| 4. 인력 편성 | PM·팀장 | 스킬 적합도와 현재 부하를 보고 사람을 배정. 인건비가 자동 계산됨 |
| 5. 계획 수립 | PM | 작업을 WBS로 묶고, 일정·선후행·계획 작업량을 입력 |
| 6. 실행 | 실무자 | 매일 작업한 시간을 워크로그로 기록 |
| 7. 주간 점검 | PM | 진척률로 지연 여부 확인 → 작업 분석으로 원인 이슈 확인 → 인력 분석으로 과부하 인원 조정 |
| 8. 전사 보고 | PMO·경영진 | 통합 대시보드의 신호(정상/주의/위험)로 위험 프로젝트를 고르고 상세로 내려가 확인 |
| 9. 월말 정산 | PM·PMO | 인원별 MM, 프로젝트 인건비, 워크로그 추출 자료로 정산·보고 |

핵심은 **6번(워크로그 기록) 하나만 꾸준히 하면 7~9번의 숫자가 자동으로 나온다**는 점입니다.

## 5. 핵심 기능

### PMS — 프로젝트 관리

| No | 핵심 기능 | 설명 |
|---|---|---|
| 1 | 멀티 스페이스 프로젝트 | 앱 프로젝트 하나에 여러 Jira 스페이스의 이슈를 연결해 하나의 작업 집합으로 관리. 기존 이슈를 편입하는 방식이며, 이슈는 프로젝트 하나에만 소속 |
| 2 | 자동 편입(구독) | Jira 스페이스를 구독하면 조건(이슈 타입·하위 이슈·JQL)에 맞는 이슈가 자동 등록. 새 이슈는 생성 즉시, 누락분은 1시간마다 보완 |
| 3 | 자유 계층 WBS·폴더 | Jira의 3단계 계층 제한을 넘어 단계 제한 없이 상위–하위를 지정하고, 앱 전용 폴더로 작업을 묶음 |
| 4 | 일정·선후행 관리 | 작업 시작일·기한을 Jira 이슈와 양방향으로 관리. 선후행은 Jira 이슈 링크로 저장되어 Jira에서도 보임 |
| 5 | 계획 작업량 관리 | Jira 예상 시간을 계획 공수(MD)로 사용. 여러 작업의 일정·계획 작업량을 일괄 입력 |
| 6 | 진척률 산정·지연 판정 | 완성·공수·일정을 따로 계산. 완성이 일정보다 뒤처지면 지연으로 판정하고 예상 완료일을 예측 |
| 7 | 계획 대비 실적 분석 | 이슈별·담당자별 계획 공수와 실투입을 비교해 초과율, 편차, 산정 정확도를 산출 |
| 8 | 프로젝트 비용 분석 | 급여 기준으로 프로젝트 인건비를 자동 계산. 예산 대비, 소진 추이, 이슈별·인력별 비용 제공 |
| 9 | 프로젝트 대시보드 | 상태 분포, 계획 대비 실적, 진척 추이, 비용 소진, 지연 이슈 등을 프로젝트별로 골라 구성 |
| 10 | 프로젝트 상태·칸반 | 조직이 정의한 상태 흐름대로 프로젝트 상태를 관리 |
| 11 | 전사 통합 대시보드 | 전 프로젝트를 일정·범위·자원 신호(정상/주의/위험)로 요약하고 일정·범위·자원·비용으로 비교 |

### RMS — 인력·자원 관리

| No | 핵심 기능 | 설명 |
|---|---|---|
| 1 | 워크로그 기록 | Jira 워크로그를 그대로 사용. 단건·기간 일괄 기록을 지원하고 Jira 이슈 화면에서도 바로 기록 |
| 2 | 담당자 + 동료 | Jira 담당자(1명)와 별도로 함께 수행하는 동료를 여러 명 지정. 동료도 작업량·부하 집계에 포함 |
| 3 | 공수 환산(MD/MM) | 워크로그 시간을 인일(MD)·인월(MM)로 환산. 1일 근무 시간과 공휴일 기준으로 자동 계산 |
| 4 | 가동률 | 실투입 ÷ 실효 가용일. 연차·공휴일을 가용일에서 빼고 여유/적정/과부하로 분류 |
| 5 | 급여 정책·인건비 산출 | 인원별(투입 급여 또는 연봉 월할) 또는 등급 기반(등급 대표값) 중 선택. 등급 기반은 개인 연봉을 노출하지 않고 원가 산출 |
| 6 | 스킬 적합도 기반 배정 | 프로젝트 필요 스킬 대비 보유 스킬로 적합도를 계산하고, 적합도와 부하 순으로 후보를 제시해 배정 |
| 7 | 프로젝트 인력 편성 | 프로젝트별 참여 인력과 역할·등급, 담당 팀을 관리. 인건비·가동률 집계의 기준 |
| 8 | 인력 현황 | 전사 인력의 가동률, 완수율, 남은 작업량, 참여 프로젝트, 보유 스킬을 조회 |
| 9 | 조직(팀) 관리 | 계층형 팀과 팀장을 관리. 팀장은 자기 팀과 하위 팀의 업무 현황을 조회 |
| 10 | 팀 분석 | 팀 단위 투입·가동률·진척을 하위 팀까지 합산해 비교. 담당 팀과 실제 기여 팀을 대조 |
| 11 | 개인 업무 현황 | 본인의 작업 시간, 목표 대비 실적, 처리율, 참여 프로젝트를 기간별로 확인 |
| 12 | 워크로그 추출 | Jira 전체 워크로그를 기간·스페이스·작성자 조건으로 추출해 엑셀 생성 |

### 공통

| No | 핵심 기능 | 설명 |
|---|---|---|
| 1 | 권한 관리 | 기능 영역별 읽기/쓰기를 권한 세트로 묶어 사용자 또는 팀에 배정. 프로젝트 조회 범위(전체 / 소속 프로젝트만 / 내 팀만) 지정 |
| 2 | 비용 정보 통제 | 급여·인건비는 별도 권한으로 분리. 권한이 없으면 금액 항목 자체가 제공되지 않음 |
| 3 | 조직 기준 설정 | 1일 근무 시간, 공휴일, 진척·가동률 판정 기준, 급여 정책, 역할·등급·스킬을 조직에 맞게 정의 |

## 8. 제품 제약사항

| 구분 | 제약 |
|---|---|
| 지원 환경 | Jira Cloud 전용. Server / Data Center는 미지원 |
| 데이터 전제 | 투입 공수·가동률은 워크로그 기록이 있어야 의미가 있음. 진척률은 이슈에 계획 작업량(예상 시간)이 입력돼야 계산됨 |
| Jira 설정 | 계획 작업량과 워크로그 기록은 Jira 프로젝트의 시간 추적이 켜져 있어야 함 |
| Jira 권한 | 앱은 사용자 본인의 Jira 권한으로 동작. Jira에서 볼 수 없는 이슈는 앱에서도 다룰 수 없음 |
| 프로젝트 구조 | 이슈는 앱 프로젝트 하나에만 소속. 한 스페이스는 한 프로젝트만 구독 가능. 프로젝트당 구독 최대 10개 |
| 계층 | 앱에서 만든 상위 지정(WBS)과 폴더는 Jira 화면에 나타나지 않음 |
| 진척률 | 진행 중 이슈의 진행률은 투입 공수 비율로 추정한 근사치. 예상 완료일도 낙관적 추정 |
| 비용 | 인건비는 급여 기준의 계획 값이며 회계 실적이 아님. 인건비 외 직접비는 다루지 않음 |
| 전사 집계 | 통합 대시보드와 전사 가동률은 하루 1회 집계(수동 재집계 가능). 실시간이 아님 |
| 조직 이력 | 팀 분석은 현재 소속 기준. 과거 소속을 소급하지 않음 |
| 미제공 | 워크로그 승인·마감, 휴가 신청·승인 절차, 청구·인보이스 |
| 용량 | 앱 저장공간 한도 1GiB(설치당). 워크로그 추출은 1회 이슈 5,000건까지. 팀 분석은 인원 500명까지 |
