# 자원관리 재편 v2 — 사용자와 직접 확정한 설계 (2026-07-23)

**v1(셀렉터형 ProjectAssignmentTab)은 사용자가 거부했다.** "프로젝트 선택을 해서 나오는 메뉴는 안 됨" — 드롭다운 뒤에 숨은 빈 화면 금지. 진입하자마자 좌우 양쪽에 정보가 보여야 한다. v1 구현물(ProjectAssignmentTab.jsx)은 폐기 대상.

## 사용자와 문답으로 확정한 사항 (변경 금지)

### 프로젝트 배정 탭 = 좌우 2분할, 진입 즉시 양쪽 표시
- **좌측 = 프로젝트 카드 목록** (배정 관점, 세로 나열)
  - 카드 내용: 이름·상태·기간 + **미배정 작업 수 + 마감임박·지연 작업 수 + 요구 스킬 칩(읽기 전용)**
  - (투입 인원 수·남은 작업량은 사용자가 선택하지 않음 — 넣지 말 것)
  - 클릭 = 선택 → 우측이 그 프로젝트 기준으로 전환
- **우측 = 전사 인원 테이블, 항상 표시**
  - 기본(선택 전): 가동률·부하·스킬
  - 프로젝트 선택 시: **적합도 점수·괴리 신호 컬럼이 활성화**되고 재정렬
- **배정 실행 = 인원 행의 [배정] 버튼 → 작업 선택 모달**
  - 모달: 선택된 프로젝트의 작업 목록에서 작업 선택 → 담당/협업 지정
  - 기존 배정 확인 모달·write 경로(assignWorkItem)·캐시 패치 재사용

### 탭 관계: 2탭 유지, 역할 분리
- 인력 현황 = 사람 탐색·360도 드로어·스킬 편집 중심
- 프로젝트 배정 = 배정 의사결정 중심 (우측 테이블은 배정 관점 컬럼만 컴팩트하게)

### 부가 기능 재배치 (사용자 지정)
- **관계도(AllocationGraph) → 인력 현황 탭으로 이동** (배정 탭에서 제거)
- **요구 스킬 편집 → 프로젝트 관리(등록/수정)로 이동** — 프로젝트 등록·수정 폼에서 요구 스킬을 정의. 배정 탭의 카드에서는 읽기 전용 칩만.

## 설계 과제 (architect가 풀 것)

1. **좌측 카드 지표의 데이터 소스** — 활성 프로젝트 전체에 대해 미배정/마감임박/지연 수를 어떻게 산출할지. 프로젝트당 board 전량 호출은 금지(비용). 후보: 경량 배치 resolver(JQL count / approximate-count), lazy hydrate(인력 현황 부하 배치 패턴), 상한·동시성. 실측 근거로 판정하라.
2. **우측 전사 인원 + 적합도 조인** — 전사 목록은 기존 people 배치(buildPeopleContext/overview 패턴) 재사용. 선택 시 board(멤버 candidates) + pool(비멤버 candidates) 조합으로 적합도·신호를 accountId 조인하는 경로 설계. 서버 신호 재계산 금지 원칙(규칙 이원화 방지) 유지.
3. **작업 선택 모달** — board.queue 재사용. 모달 내 작업 필터(미배정 우선) 여부.
4. **프로젝트 등록/수정 폼에 요구 스킬 편집 통합** — 기존 등록 모달(/project ProjectPage 쪽) 위치 확인, RequiredSkillEditor/setProjectSkills 재사용 경로, 권한.
5. **관계도의 인력 현황 탭 배치** — 어디에 어떻게(하단 접이식 등).
6. v1 산출물 처리 — ProjectAssignmentTab 폐기, 재사용 가능한 부분(권한 OR grant 3건은 유효) 명시.

## 유지되는 결정 (v1에서 유효)
- 백엔드 권한 OR grant 3건 (getActiveProjects/board=+RESOURCE_MANAGEMENT read, assign=+RESOURCE_MANAGEMENT write) — 이미 구현·테스트 315 통과
- 배정 게이트 = canWrite('PROJECT') || canWrite('RESOURCE_MANAGEMENT')
- match/allocation 기존 3탭 구조는 제거 (단 AllocationGraph는 인력 현황으로 이동)
- AssignmentPage(프로젝트 상세) 회귀 금지
- invalidate 금지 원칙 (스킬 저장 경로만 예외)
