# 관리자 초기 설정과 운영 점검

[가이드 홈](codex-experiences--index.md) · [English](../en/codex-experiences--admin-setup.md)

> 검토 초안: 지정된 staging 환경의 실제 화면·배포 버전 확인 전입니다.

관리자는 사용자가 앱을 열고, 업무를 기록하고, 올바른 범위의 결과를 볼 수 있도록 준비합니다. 설치 작업은 조직의 앱 설치 담당자가 수행하고, 이후 고객 관리자가 화면에서 조직 설정을 관리합니다.

## 시작 전 확인

- 대상 Jira 사이트에 Moves Workforce가 설치돼 있고 활성 라이선스를 사용할 수 있는지 확인합니다.
- 최초 설정 담당자가 Jira 관리 권한으로 앱에 접근할 수 있는지 확인합니다.
- 운영 담당자와 일반 사용자가 Jira 계정 및 필요한 프로젝트 접근 권한을 갖고 있는지 확인합니다.
- 개발·테스트·운영 사이트를 구분하고, 지금 설정을 바꾸는 사이트가 의도한 대상인지 확인합니다.

## 최초 운영 준비를 실제로 진행하는 순서

처음에는 설치·설정을 담당할 관리자, 실제 Jira 사용자 한 명, 접근 가능한 Jira 이슈 한 개로 준비합니다. 문서 기능을 사용할 때만 같은 사이트의 Confluence 페이지를 추가로 준비합니다. 아래 수치는 설명용 예시이며 조직의 운영 기준으로 바꾸세요.

| 순서와 메뉴 | 수행할 일 | 다음 단계로 넘어가기 전 확인 |
|---|---|---|
| 1. Jira Apps → Moves Workforce → 설정 | 설치 사이트와 관리자 접근을 확인합니다. 운영할 관리자의 권한을 준비합니다. | 예정한 사이트에서 설정을 열 수 있습니다. |
| 2. 설정 → 일반 설정 | 조직 통화와 1일 근무 시간(예: 8시간)을 확인·설정합니다. 휴일 기준도 준비합니다. | 화면의 통화·시간 기준이 조직 기준과 일치합니다. MM은 별도의 임의 입력값으로 가정하지 말고 [계산 기준](codex-experiences--analytics.md)을 확인합니다. |
| 3. 설정의 역할·레벨·스킬·프로젝트 상태 | 사람과 프로젝트에서 사용할 선택지를 준비합니다. | 사용자·프로젝트 입력창에서 필요한 선택지가 나옵니다. |
| 4. 설정의 사용자·팀 | 실제 Jira 계정을 앱 사용자로 등록한 뒤 팀을 만들고 구성원·리더를 지정합니다. | 해당 사용자와 팀 관계가 목록에 보입니다. 리더도 먼저 사용자로 등록합니다. |
| 5. 권한 설정 | 일반 사용자·리더의 필요한 읽기·쓰기 권한과 조회 범위를 정합니다. | 해당 계정으로 허용한 화면이 열리고 범위 밖 데이터는 노출되지 않는지 확인합니다. 인력 등록과 비용 접근 권한을 구분합니다. |
| 6. 급여·비용 기준 | 비용 기능을 운영할 때만 급여 정책과 사용할 레벨 또는 개인 금액을 준비합니다. | 비용 권한이 있는 사용자로 기준을 확인합니다. 워크로그 시작을 위해 불필요한 금액을 임의 등록하지 않습니다. |
| 7. 프로젝트 관리 | [예시 프로젝트](codex-experiences--projects.md)를 만들고 [구성원](codex-experiences--project-people.md)과 [Jira 작업](codex-experiences--project-work.md)을 각각 연결합니다. | 프로젝트 상세의 인력과 작업 목록에 대상이 각각 보입니다. |
| 8. 나의 작업 | [빠른 시작](codex-experiences--quick-start.md)의 단일 워크로그를 실제 업무 날짜로 등록합니다. | 앱과 Jira에서 같은 이슈·날짜·시간의 기록을 확인합니다. |
| 9. 문서 관리(선택) | [문서 연결](codex-experiences--documents.md)의 프로젝트·작업 예시를 진행합니다. | 연결 대상이 맞고 Confluence 원본이 열립니다. |

운영 공개 전에는 관리자 계정 확인에 더해 일반 사용자·팀 리더가 본인 계정으로 접근을 확인하게 합니다. 일반 사용자에게 비용 권한이 없다면 비용·개인 금액을 볼 수 없는지 확인하고, 팀 리더는 허용된 팀 범위인지 확인합니다. 오류가 나면 화면 경로·이슈 키·실행 시각·오류 문구를 기록해 권한 설정 또는 Jira 접근 문제부터 해결합니다. 이 체크리스트는 확인 절차이며 해당 사이트의 실제 검증 완료를 의미하지 않습니다.

## 설정 순서

| 순서 | 설정 | 완료 확인 |
|---|---|---|
| 1 | 운영 담당자 등록과 관리 권한 배정 | 담당자가 Settings에 접근 가능 |
| 2 | 통화·1일 근무시간·MM 기준·휴일 | 조직의 계산 기준과 일치 |
| 3 | 역할·등급·스킬·프로젝트 상태 | 사용자 등록과 프로젝트 생성의 선택지 준비 |
| 4 | 사용자·팀·리더 | 사용자 등록 후 팀 구성원·리더가 올바름 |
| 5 | 읽기·쓰기·조회 범위 | 일반 사용자·리더·관리자의 실제 접근을 확인함 |
| 6 | 급여 정책·금액(비용 기능 운영 시) | 사용할 인원별 또는 레벨 기반 비용 기준이 준비됨 |
| 7 | 예시 프로젝트·인력·이슈 연결 | 각 대상이 따로 등록됐는지 확인 |
| 8 | 예시 워크로그와 분석 확인 | 같은 기간·대상으로 값 비교 |

팀장을 지정하려면 사용자가 먼저 인력으로 등록돼 있어야 합니다. 등급 기반 비용을 쓸 때는 실제 사용 등급의 금액 기준을 먼저 준비하세요.

## 사용자 역할별 점검

1. 일반 사용자 계정에서 My Work와 본인 프로젝트를 확인합니다.
2. 팀장 계정에서 내 팀과 허용된 인력만 보이는지 확인합니다.
3. 비용 권한이 없는 계정에서 개인 금액과 비용 화면의 접근을 확인합니다.
4. 관리 계정에서 설정 변경이 가능한지 확인합니다.

관리자 화면만 확인하면 일반 사용자의 권한 문제를 놓칠 수 있습니다. 사용자에게 다른 계정의 비밀번호를 요청하지 말고 본인 계정에서 확인하도록 안내합니다.

## 정기 운영 점검

- 통합 대시보드·자원 현황의 마지막 집계와 실패 안내
- 구독 상태와 이슈 편입 결과
- 새해 휴일과 근무 기준
- 팀 변경에 따른 팀장·권한 상속·프로젝트 배정
- 업그레이드 후 새 권한 항목과 신규 기능의 제공 여부

장애 문의에는 사이트, 발생 시각, 화면 경로, 이슈 키, 수행 동작, 오류 문구를 포함합니다. 민감한 급여·개인정보는 필요한 범위만 공유합니다.

개발용 배포·DB 마이그레이션·복구 명령은 고객이 임의로 실행하지 않고 제품 운영 담당자에게 요청합니다. [FAQ](codex-experiences--faq.md)에서 사용자 문제의 점검 순서를 확인할 수 있습니다.
