# 5.3 작업 관리

## 접근 권한

| 구분 | 필요 권한 |
|---|---|
| 목록·트리·간트·맵 조회 | 「프로젝트 관리」 읽기 |
| 작업 추가(편입)·프로젝트에서 제외 | 「프로젝트 관리」 쓰기 |
| 인라인 편집·일괄 적용(담당자·동료·일정·계획 작업량) | 「프로젝트 관리」 쓰기 **+ Jira 이슈 편집 권한** |
| 트리·간트 편집(일정·선후행·상위 지정·폴더) | 「프로젝트 관리」 쓰기 **+ Jira 권한**(아래) |
| 자동 편입(구독) 설정 | 「프로젝트 관리」 쓰기 |

**함께 필요한 Jira 권한**

| 작업 | Jira 권한 |
|---|---|
| 일정 변경 | 이슈 편집 · 일정 관리 |
| 담당자 지정 | 담당자 지정 |
| 선후행 연결 | 이슈 연결 |
| 계획 작업량(MD) | 이슈 편집 + 프로젝트의 **시간 추적 활성화** |

- 트리·간트·맵은 「프로젝트 관리」 읽기만 있으면 **조회 전용**으로 열립니다(간트 툴바에 "조회 전용" 배지). 맵은 원래 읽기 전용입니다.
- 권한이 없으면 보기 전환 버튼에서 해당 보기가 빠지고, 남는 보기가 하나뿐이면 전환 버튼 자체가 사라집니다.
- 앱 권한이 있어도 Jira 권한이 없으면 **저장 시점에 거부**되고 사유가 안내됩니다.

---

**언제 쓰나** — 프로젝트의 모든 작업(이슈)을 **찾고, 담당을 정하고, 구조와 일정을 잡을** 때.

같은 작업 묶음을 **목록 / 트리 / 간트 / 맵** 네 가지 방식으로 봅니다(우측 위 전환 버튼). 선택한 보기는 주소에 실려 새로고침·링크 공유 시 유지됩니다.

| 보기 | 무엇에 쓰나 | 잘하는 일 |
|---|---|---|
| **목록** (기본) | 작업을 찾고 추가·수정 | 검색·필터, 작업 추가/제외, 셀 인라인 편집, **여러 건 일괄 적용** |
| **트리** | 작업의 **구조**를 보고 정리 | 상위-하위·폴더 계층 정리(드래그), 한 작업의 모든 정보 확인 |
| **간트** | 작업의 **일정**을 보고 조정 | 기간 조정, 선후행 연결, 전체 일정 조망, 전체 화면 |
| **맵** | 구조를 **한 장의 그림**으로 | 프로젝트 → 폴더 → 작업 조직도, 선후행 점선, 카드 클릭 상세(읽기 전용) |

- 트리·간트·맵은 **같은 데이터**를 봅니다. 한쪽에서 바꾸면 다른 쪽에도 그대로 반영됩니다.
- 트리·간트·맵은 **담당자·상태·이슈 타입·스페이스 필터를 공유**합니다. 보기를 바꿔도 "이 담당자 작업만" 보던 상태가 유지됩니다. (목록 보기는 검색 조건 체계가 달라 따로 동작합니다.)

## 5.3.1 목록 보기

![그림 5-6 작업 관리 목록 보기](../images/05-work-list.png)
*그림 5-6. 목록 보기 — ① 필터(업무 검색·스페이스·담당자·상태·이슈 타입) ② 계층/평면 토글 ③ 체크박스 선택과 일괄 적용 / 프로젝트에서 제외 ④ 보기 전환(목록·트리·간트·맵) ⑤ + 작업 추가 ⑥ 자동 편입 요약.*

- 상단 필터: **업무 검색**, **스페이스**(Jira 프로젝트), **담당자**, **상태**, **이슈 타입**
- 우측 위 **+ 작업 추가**
- **계층 / 평면** 토글: 계층은 Jira 상위–하위 구조로 묶어 보여주고(행 왼쪽 화살표로 펼침/접기, **모두 펼치기 / 모두 접기**), 평면은 모든 이슈를 한 줄씩 나열합니다. 계층 보기에서는 **페이지 단위가 상위 이슈 기준**이라 하위 작업은 상위와 같은 페이지에 함께 나옵니다.

| 컬럼 | 설명 |
|---|---|
| 프로젝트 | 소속 Jira 프로젝트(스페이스) |
| 키 | 이슈 키와 이슈 타입 아이콘 |
| 업무 | 이슈 제목 |
| 상태 | 할 일 / 진행 중 / 완료 (색 라벨) |
| 담당자 | 이슈 담당자 |
| 동료 | 협업자(여러 명 지정 가능) |
| 시작일 | 작업 시작일 (셀에서 수정 가능) |
| 기한 | 작업 기한 (셀에서 수정 가능) |
| 계획 작업량 | 계획 공수. 단위 **MD = Man-Day(인일)** (예: 5.1 MD). Jira의 Original Estimate 기반 |
| 처리율 | 진행률 (예: 0% / 5% / 100%) |
| 추가 작업 | **삭제**(프로젝트 연결 해제) |

> **인라인 편집:** **담당자·동료·시작일·기한** 셀을 클릭하면 그 자리에서 수정됩니다. 변경은 해당 Jira 이슈에 즉시 반영됩니다.

> **"작업 추가"는 새 이슈를 만들지 않습니다.** **이미 존재하는 Jira 이슈를 검색해 이 프로젝트에 편입**하는 방식입니다. 목록의 **삭제**도 이슈 삭제가 아니라 **프로젝트 연결 해제**입니다.

### 일괄 적용과 제외

행 왼쪽 체크박스로 여러 작업을 고르면 상단에 **N건 선택**과 두 버튼이 나타납니다.

![그림 5-7 선택 작업 일괄 적용 창](../images/05-work-bulk-apply.png)
*그림 5-7. 일괄 적용 창 — ① 대상 건수 ② 시작일·기한·계획 작업량(비워둔 항목은 변경하지 않음) ③ 적용 결과(성공/실패)와 실패 건만 재시도.*

| 버튼 | 동작 |
|---|---|
| **일괄 적용** | 선택한 작업의 **시작일 · 기한 · 계획 작업량(MD)** 을 한 번에 지정합니다. **비워둔 항목은 바꾸지 않으므로** 기한만 넣으면 시작일은 그대로 유지됩니다. 건별로 저장하며 결과가 "N건 성공 · M건 실패"로 집계되고, 실패 목록에서 **실패 건만 재시도**할 수 있습니다 |
| **프로젝트에서 제외** | 선택한 작업을 이 프로젝트에서 뺍니다. **Jira 이슈 자체는 삭제되지 않습니다** |

- 시작일이 기한보다 늦으면 적용 전에 막힙니다.
- 계획 작업량 저장이 실패하는 건은 대개 그 Jira 프로젝트에서 시간 추적이 꺼져 있는 경우입니다([문제 해결](#539-문제-해결)).

## 5.3.2 담당자·동료 관리

작업에 **누가 매달려 있는지**를 정하는 기능입니다. 여기서 지정한 값이 My Work·마이페이지·인력 분석·가동률 계산의 기준이 됩니다.

### 담당자와 동료의 차이

| 구분 | 인원 | 성격 | 저장 위치 |
|---|---|---|---|
| **담당자**(Assignee) | **1명** | Jira 기본 기능. 이슈를 **책임지는** 사람 | Jira 이슈의 담당자 필드 |
| **동료**(협업자) | **여러 명** | 이 앱이 추가한 개념. 함께 **수행하는** 사람 | Jira 이슈에 앱이 저장하는 협업자 목록 |

한 이슈에 담당자는 한 명뿐이지만 실제로는 여러 명이 함께 일하는 경우가 많습니다. **동료**는 그 현실을 담기 위한 항목입니다. 담당자와 동료는 **별개 축**이라, 담당자를 바꿔도 동료 목록은 그대로 유지됩니다.

> 동료로 지정되면 그 사람의 **My Work에 "협업 이슈"로 집계**되고, 마이페이지·인력 분석의 작업량에도 반영됩니다. 즉 동료 지정은 단순 표시가 아니라 **집계에 실제로 들어갑니다.**

### 지정하는 세 가지 경로

| 경로 | 위치 | 쓰임 |
|---|---|---|
| **표 인라인 편집** | 작업 관리 > 목록 | 이슈 하나씩 담당자·동료를 바로 수정 |
| **트리 보기** | 작업 관리 > 트리 | 상위/하위 구조를 보면서 동료 지정 |
| **작업 배정** | [인력 관리 > 작업 배정](codex-experiences--02-%EC%9D%B8%EB%A0%A5-%EA%B4%80%EB%A6%AC.md#524-작업-배정) | **스킬 적합도와 현재 부하를 비교해** 배정. 여러 건을 한 번에 처리할 때 |

앞의 두 경로는 "이 이슈에 누구를 넣을까", **작업 배정**은 "이 사람에게 무엇을 맡길까" 관점입니다.

### 등록일·등록자는 자동으로 기록됩니다

작업을 프로젝트에 편입할 때 **누가 언제 등록했는지**가 이슈에 함께 저장되며, [작업 이력](codex-experiences--05-%EB%B6%84%EC%84%9D-%EB%B0%8F-%EB%A6%AC%ED%8F%AC%ED%8A%B8.md#556-작업-이력) 화면에서 확인할 수 있습니다. 자동 편입으로 들어온 이슈는 등록자가 **"구독"** 으로 표시됩니다.

- **최초 등록 시점만 유지됩니다.** 이미 등록일이 있는 이슈는 다시 편입해도 덮어써지지 않습니다.
- 직접 수정할 수 없는 읽기 전용 값입니다.

### 주의사항

- **동료 지정 직후 목록 필터 결과가 잠깐 예전 상태로 보일 수 있습니다.** Jira 검색 색인 갱신에 시간이 걸리기 때문이며, 값 자체는 이미 저장돼 있습니다.
- **프로젝트 인력과 담당자는 별개입니다.** 이슈 담당자로 지정해도 프로젝트 인력 명단에 자동 추가되지 않습니다. 인건비·가동률 집계에 포함하려면 [인력 관리](codex-experiences--02-%EC%9D%B8%EB%A0%A5-%EA%B4%80%EB%A6%AC.md)에서 별도로 추가해야 합니다.
- 담당자·동료 변경은 **해당 Jira 이슈에 즉시 반영**됩니다.

## 5.3.3 자동 편입(프로젝트 구독)

작업 추가 창의 **구독 설정** 탭에서 Jira **스페이스**(Jira 프로젝트)를 구독하면 조건에 맞는 이슈가 이 프로젝트로 자동 편입됩니다. 매번 손으로 "작업 추가"를 하지 않아도 됩니다.

![그림 5-8 구독 추가와 미리보기](../images/05-work-subscription.png)
*그림 5-8. 구독 설정 탭 — ① 소스(스페이스) 선택 ② 세부 조건(이슈 타입·하위 이슈 포함·추가 JQL·기본 계획 작업량) ③ 미리보기(편입 대상·건너뜀·이미 등록됨) ④ 기존 이슈도 가져오기 ⑤ 구독 중인 소스 목록(상태·마지막 동기화·수정·일시 중지·해제).*

### 설정 절차

1. **소스**에서 스페이스를 고릅니다. **이미 다른 프로젝트가 구독 중인 스페이스는 선택할 수 없고** "○○ 구독중"으로 표시됩니다.
2. 필요하면 **세부 조건**을 펼쳐 지정합니다. 지정하지 않으면 스페이스 전체를 가져옵니다.

| 조건 | 설명 |
|---|---|
| 이슈 타입 | 고른 타입만 가져옵니다. 고르지 않으면 전체 |
| 선택한 이슈의 하위 이슈 포함 | 켜면 **선택한 타입에 해당하는 이슈와 그 이슈들의 하위 이슈**(하위 작업·자식 이슈)를 함께 가져옵니다. 스페이스 전체의 하위 작업이 아닙니다 |
| 추가 조건 (JQL) | 위 조건에 AND로 덧붙습니다(예: `labels = release`). `currentUser()`처럼 보는 사람에 따라 달라지는 함수와 `ORDER BY`는 쓸 수 없습니다 |
| 기본 계획 작업량 | 편입되는 이슈의 예상 시간이 **비어 있을 때만** 이 값(시간, 최대 100)을 채웁니다. 이미 값이 있으면 건드리지 않습니다 |

3. **미리보기**에서 **편입 대상 N건 · 건너뜀 M건(다른 프로젝트에 이미 등록) · 이미 등록됨 K건**을 확인합니다. 선택 타입/하위 이슈 건수가 나뉘어 표시되고 **JQL 보기**로 실제 조건을 볼 수 있습니다.
4. **기존 이슈도 가져오기**를 켜면 기존분을 백그라운드로 가져오고, 끄면 구독 이후 생성되는 이슈부터 가져옵니다.
5. **구독 추가**를 누릅니다.

### 구독 목록 다루기

구독마다 **누적 N건 편입 · 마지막 동기화 시각 · 상태**가 표시됩니다.

| 상태 | 의미 |
|---|---|
| 정상 | 마지막 동기화 성공 |
| 일부 반영 | 대상이 많아 일부만 처리. 다음 동기화에서 이어집니다 |
| 소스에 접근할 권한이 없습니다 / 소스를 찾을 수 없습니다 | 스페이스 권한이 바뀌었거나 삭제됨 |
| 동기화 오류 | 그 밖의 오류 |

- **수정**: 이슈 타입·하위 이슈·JQL·기본 계획 작업량을 바꿉니다. **바뀐 조건은 다음 동기화부터** 적용되며 이미 편입된 이슈는 되돌아가지 않습니다. 진행 중인 "기존 이슈 가져오기"가 있으면 중단됩니다.
- **일시 중지**: 새 이슈를 가져오지 않습니다. 이미 편입된 이슈는 그대로 남습니다.
- **해제**: 구독을 끝냅니다. 역시 **이미 편입된 이슈는 남습니다.**

### 운영 규칙

- 프로젝트당 구독은 **최대 10개**, 한 스페이스는 전체에서 **한 프로젝트만** 구독할 수 있습니다.
- 새 이슈는 생성 이벤트로 빠르게 처리하고, 이벤트 누락·이슈 이동·조건 변경은 **1시간마다** 정합성을 확인합니다. "방금 만든 이슈는 바로 안 보일 수 있어요" 안내가 이 때문입니다.
- 목록 보기 상단의 **자동 편입** 요약에서 구독 스페이스를 눌러 그 스페이스만 필터하거나 **지금 동기화**를 실행할 수 있습니다. 지금 동기화는 1시간을 기다리지 않고 바로 확인할 뿐, 생성 시 정한 "구독 이후 생성분만" 조건을 우회하지 않습니다.
- 이슈는 **프로젝트 하나에만** 속합니다. 다른 프로젝트가 이미 등록한 이슈는 구독으로 가져오지 않고 "건너뜀"으로 셉니다.

## 5.3.4 작업 추가 창

**+ 작업 추가**를 누르면 Jira 이슈를 검색해 편입하는 창이 열립니다.

- 검색어에 **이슈 요약(제목) 또는 이슈 키**(예: `SAMPLE-12`)를 입력합니다. 스페이스·상태 등으로 좁힐 수 있습니다.
- 결과 표의 **현재 소속** 컬럼에 그 이슈가 이미 어느 프로젝트에 있는지 표시됩니다 — "○○ 등록됨", "○○ 구독중", 또는 비어 있음.
- 체크해서 **추가**하면 이 프로젝트에 편입됩니다. 등록일·등록자가 자동 기록됩니다.

> **다른 프로젝트에 이미 등록된 이슈를 고르면** 확인 창이 뜹니다. **이슈는 프로젝트 하나에만 속할 수 있어**, 가져오면 원래 프로젝트에서 빠지고 **그동안 쌓인 공수·비용도 함께 옮겨갑니다.** "이 건은 빼고 N건만 등록"으로 그 이슈만 제외할 수도 있습니다.

## 5.3.5 트리·간트·맵 공통 사항

### 권한

| 권한 | 가능한 일 |
|---|---|
| 「프로젝트 관리」 **읽기** | 트리·간트·맵 조회, 펼침/접기, 줌, 필터, 상세 확인 |
| 「프로젝트 관리」 **쓰기** | 일정·상위·선후행·폴더·담당자·동료·계획 작업량 편집(트리·간트) |

읽기 권한만 있으면 간트 툴바에 **"조회 전용"** 배지가 뜨고 드래그·연결·편집이 잠깁니다. 트리에서는 편집 버튼과 드래그가 나타나지 않습니다. 맵은 권한과 무관하게 항상 읽기 전용입니다.

> Jira 자체 권한도 함께 확인합니다. 앱에서 쓰기 권한이 있어도 Jira에서 **이슈 편집·일정 변경·담당자 지정·이슈 연결** 권한이 없으면 저장이 거부되고 사유가 안내됩니다.

### 세 가지 계층 개념

| 개념 | 만드는 곳 | 저장 위치 | 특징 |
|---|---|---|---|
| **Jira 하위 이슈** | Jira | Jira 표준 | Jira가 정한 3단계(에픽>스토리>하위작업) 제약을 받습니다 |
| **상위 지정(WBS)** | 이 앱(트리·간트) | 앱이 이슈에 저장 | **단계 제한 없이 자유롭게 중첩**. Jira 상위가 있어도 이 지정이 **우선 적용**됩니다 |
| **폴더** | 이 앱(트리·간트) | 앱 내부 | Jira에 없는 앱 전용 묶음. 이슈가 아니므로 Jira에서는 보이지 않습니다 |

> **왜 상위 지정이 따로 있나요?** Jira는 3단계와 인접 단계만 허용해 4단계 이상 WBS를 만들 수 없습니다. 앱의 상위 지정은 이 제약을 벗어나기 위한 것입니다. 대신 **Jira 화면에는 이 계층이 나타나지 않습니다.**

### 필터

담당자 · 상태 · **이슈 타입** · 스페이스(여러 스페이스가 섞여 있을 때만 표시) 필터를 세 보기가 공유합니다. 폴더는 필터로 직접 걸러지지 않고, **남은 작업을 기준으로 폴더의 기간·수행율이 다시 계산**됩니다.

## 5.3.6 트리 보기

화면은 좌우로 나뉩니다. **왼쪽은 계층 구조, 오른쪽은 선택한 항목의 상세**입니다. 카드 헤더의 접기 버튼과 경계선으로 폭을 조절할 수 있습니다.

![그림 5-9 트리 보기](../images/05-work-tree.png)
*그림 5-9. 트리 보기 — ① 검색·모두 펼치기/접기·폴더 추가 ② 계층 트리(폴더 → 상위 작업 → 하위 작업, 드래그 중) ③ 최상위로 이동 드롭 영역 ④ 상세 패널(속성·연관 관계·워크로그) ⑤ 상위 출처 배지.*

### 왼쪽: 계층 구조

- **검색**: 작업 키·이름으로 걸러냅니다
- **모두 펼치기 / 모두 접기**
- **폴더 추가** (쓰기 권한)
- 폴더는 항상 같은 단계의 작업보다 위에 표시됩니다
- 항목을 클릭하면 오른쪽에 상세가 열립니다

### 드래그로 구조 바꾸기 (쓰기 권한)

| 무엇을 | 어디에 놓으면 | 결과 |
|---|---|---|
| 작업 | 다른 작업 위 | 그 작업의 **하위로 지정**(상위 지정) |
| 작업 | 폴더 위 | 그 **폴더에 소속** |
| 작업 | 목록 아래 **"여기에 놓으면 최상위로 이동"** 영역 | **상위 지정 해제** |
| 폴더 | 다른 폴더 위 | 그 폴더의 **하위 폴더로 이동** |
| 폴더 | 최상위 영역 | **최상위 폴더로 이동** |
| 폴더 | 작업 위 | 아무 일도 일어나지 않습니다(작업은 폴더의 상위가 될 수 없습니다) |

- 자기 자신이나 자기 하위로는 옮길 수 없습니다(순환 방지).
- 상위가 지정된 작업을 폴더에 넣으면 **상위 지정이 먼저 해제**됩니다. 한 작업은 "다른 작업의 하위"이면서 동시에 "폴더 소속"일 수 없습니다.
- 같은 규칙이 간트의 행 드래그에도 그대로 적용됩니다.

### 오른쪽: 선택한 작업의 상세

| 구역 | 내용 |
|---|---|
| 헤더 | 작업 이름, 상태, 이슈 키 |
| 처리율 | 진행률 막대 |
| 속성 | 담당자 / 시작일 / 기한 / 협업자 / 계획 작업량 / Jira 프로젝트 |
| 연관 관계 | 상위 작업 · 하위 이슈 · 선행/후행 작업 · 소속 폴더 · Jira 연결 |
| 쌓인 워크로그 | 이 작업에 기록된 워크로그 목록과 **합계 시간** |

속성의 **연필 아이콘**을 누르면 편집합니다(쓰기 권한). 계획 작업량은 그 자리에서 숫자를 입력하고 Enter로 저장하며, 일정·협업자·상위·폴더는 모달이 열립니다. 여기서 저장한 값은 간트·맵에도 즉시 반영됩니다.

### 상위 작업의 출처 표시

상위는 **Jira가 정한 것**과 **이 앱에서 지정한 것** 두 가지가 있어, 지금 적용 중인 상위가 어디서 왔는지 배지로 구분합니다.

| 표시 | 의미 |
|---|---|
| **워크포스에서 지정** | 앱에서 지정한 상위가 적용 중 |
| **Jira에서 정의** | Jira 표준 상위가 적용 중 |
| *워크포스 지정으로 가려진 Jira 상위* | 앱 지정이 Jira 상위를 대신하는 중. 가려진 Jira 상위를 함께 표시하며, 상위 지정을 해제하면 Jira 상위로 돌아갑니다 |
| *현재 트리 화면에 없습니다* | 상위 작업이 필터에 걸렸거나 조회 범위 밖입니다 |
| *조회 범위에 없어 적용되지 않았습니다* | 앱에서 지정한 상위 작업이 이 프로젝트에 편입돼 있지 않아 계층이 그려지지 않았습니다 |

### 선후행(선행 작업 / 후행 작업)

- **연결 추가** 버튼으로 상대 작업을 골라 연결하고, 각 항목의 **×** 로 해제합니다.
- 선후행은 **Jira 이슈 링크(Blocks)로 저장**됩니다. 그래서 간트에서 그렸는지 Jira에서 만들었는지는 **구분되지 않습니다.**
- 상대가 다른 프로젝트에 있거나 조회 범위 밖이면 **읽기 전용**으로 따로 표시됩니다(연결이 사라진 것이 아닙니다).
- 선후행이 아닌 Jira 링크(관련됨, 중복 등)는 아래 **Jira 연결**에 따로 모입니다.

## 5.3.7 간트 보기

왼쪽 표와 오른쪽 타임라인으로 구성됩니다. 경계선을 끌어 좌우 폭을, 컬럼 경계를 끌어 컬럼 폭을 조절할 수 있습니다. 툴바의 **전체 화면**으로 간트만 크게 띄울 수 있습니다.

![그림 5-10 간트 보기](../images/05-work-gantt.png)
*그림 5-10. 간트 보기 — ① 툴바(줌 일/주/월·폴더 추가·전체 화면·조회 전용 배지) ② 왼쪽 표 ③ 타임라인(파란 일반 작업·초록 요약 막대·보라 마일스톤·틸 폴더·회색 점선 미설정) ④ 선후행 연결선 ⑤ 오늘·프로젝트 시작/종료 기준선.*

### 왼쪽 표의 컬럼

| 컬럼 | 내용 | 편집 |
|---|---|---|
| 이슈 | 이슈 타입 아이콘·키·이름 (펼침/접기 화살표 포함) | — |
| 상태 | 할 일 / 진행 중 / 완료 | — |
| 담당자 | 이슈 담당자 | 가능 셀 클릭 |
| 협업자 | 함께 수행하는 인원(여러 명) | 가능 셀 클릭 |
| 시작일 | 시작일. 미설정이면 **일정 설정** 버튼 | 필수 |
| 기간 | 시작~종료 일수 | — |
| 계획 작업량 | 계획 공수(MD) | 가능 셀 클릭 후 입력 |
| 처리율 | 진행률(%) | — |
| 상위 지정 | 상위 작업 선택 (쓰기 권한일 때만 컬럼 표시) | 필수 |

### 타임라인

- 줌: **일 / 주 / 월**
- 세로 기준선: **오늘**, **프로젝트 시작**, **프로젝트 종료**

| 막대 | 의미 |
|---|---|
| 파란 막대 | 일반 작업 |
| 초록 막대 | **Jira 하위 이슈를 가진 상위 작업** — 하위 기간을 감싸는 요약 막대 |
| 보라 마름모 | 마일스톤(시작일 = 종료일) |
| 회색 점선 막대 | **일정이 없는 작업** — 프로젝트 시작일 위치에 임시 표시 |
| 틸(청록) 막대 | 폴더 — 깊이가 깊을수록 연해집니다 |

> **앱에서 상위 지정한 작업은 초록 요약 막대가 되지 않습니다.** 각자 자기 일정을 가진 **독립 작업**으로 남고, 왼쪽 표에서 펼침/접기만 생깁니다. 초록 요약 막대는 Jira 하위 이슈를 가진 경우에만 나타납니다.

### 편집 조작 (쓰기 권한)

| 하고 싶은 일 | 조작 |
|---|---|
| 일정 변경 | 막대를 **드래그**(이동) 또는 **끝을 끌어** 기간 조정 |
| 일정 없는 작업에 일정 주기 | 회색 점선 막대를 드래그하거나, 시작일 컬럼의 **일정 설정** 버튼으로 날짜 입력 |
| 선후행 연결 | 한 막대의 **끝점**을 다른 막대로 드래그 |
| 선후행 해제 | 연결선을 선택해 삭제 |
| 계층 만들기 | 왼쪽 표에서 행을 **드래그**하거나 **상위 지정** 컬럼에서 선택 |
| 이슈를 폴더로 옮기기 | 행을 폴더 위로 드래그하거나 행 메뉴의 **폴더 이동**. 상위 지정된 이슈는 먼저 상위 지정이 해제됩니다 |
| 폴더 만들기·정리 | 툴바 **폴더 추가**, 행 메뉴에서 이름 변경/하위 폴더 추가/이동/삭제 |

- 진행률 막대는 드래그로 바꿀 수 없습니다. **처리율은 Jira가 시간 추적(기록 시간과 잔여 추정, 하위 이슈 포함)으로 계산한 값**이라 직접 입력하는 항목이 아닙니다.
- 순환이 생기는 연결(A→B→A), 자기 자신 연결, 다른 프로젝트 작업과의 연결은 거부되고 사유가 안내됩니다. 거부되면 화면도 원래대로 되돌아갑니다.

### 폴더

- 폴더로 이슈를 묶어 **WBS(작업 분류)** 를 구성합니다. 중첩할 수 있고 **깊이에 따라 색 농도**가 달라집니다.
- 폴더 막대의 **기간·처리율·계획 작업량은 하위 항목에서 자동 집계**됩니다. 처리율은 계획 작업량(MD)으로 가중 평균합니다.
- 이슈가 없는 **빈 폴더도 이름만 표시**됩니다.
- **폴더를 삭제해도 이슈는 삭제되지 않습니다.** 내용물(이슈·하위 폴더)은 **상위 폴더로 옮겨지고**, 상위가 없으면 최상위로 올라갑니다. 다만 그 폴더가 끝점이던 선후행 연결은 함께 사라집니다.

### 선후행 연결의 두 가지 저장 방식

- **이슈 ↔ 이슈** 연결은 Jira의 **이슈 링크(Blocks)** 로 저장되어 Jira 이슈 화면에서도 보입니다.
- **폴더가 포함된 연결**(폴더↔이슈, 폴더↔폴더)도 같은 방식으로 만들 수 있지만, 폴더는 Jira에 없는 앱 전용 개념이라 **앱 내부에만 저장**됩니다.

> **Jira 이슈 화면의 표기 방향:** 간트에서 만든 선후행은 Jira 이슈 화면에서 "blocks / is blocked by" 방향이 **간트와 반대로** 보일 수 있습니다. 간트 화면의 방향(왼쪽이 선행)이 기준이며, 일정 계산과 표시는 정상입니다.

> **성공 알림 묶음:** 드래그로 여러 항목을 연달아 편집하면 알림이 건건이 뜨지 않고 잠시 모아져 **"변경 N건이 저장되었습니다"** (일정 / 연결 / 상위 지정 / 폴더 소속 / 폴더 이동 분류) 한 건으로 표시됩니다. 오류 알림은 즉시 표시됩니다.

## 5.3.8 맵 보기

프로젝트를 정점으로 폴더와 작업을 **위에서 아래로 펼친 조직도**입니다. 보고 자료나 킥오프에서 "이 프로젝트가 어떤 덩어리로 이뤄져 있나"를 한 장으로 보여줄 때 씁니다. **읽기 전용**이라 여기서는 아무것도 바뀌지 않습니다.

![그림 5-11 맵 보기](../images/05-work-map.png)
*그림 5-11. 맵 보기 — ① 프로젝트 루트 카드(작업 N건·폴더 M개) ② 폴더 카드 ③ 작업 카드(담당자·상태·하위 N건) ④ 실선(하위)·점선 화살표(선후행) ⑤ 미니맵 ⑥ 카드 클릭으로 열린 작업 상세 드로어.*

| 요소 | 설명 |
|---|---|
| 프로젝트 루트 카드 | 맨 위. 작업 수·폴더 수 표시. 접거나 드로어를 열 수 없습니다 |
| 폴더 카드 / 작업 카드 | 이름·담당자·상태·하위 건수. **하위 펼치기/접기** 버튼으로 가지를 여닫습니다 |
| 실선 | 상위 → 하위(폴더 소속, 상위 지정, Jira 하위 이슈) |
| 점선 화살표 | 선후행(선행 → 후행). 양 끝이 지금 화면에 있을 때만 그려집니다 |
| 툴바 | 작업 키·이름 검색, **모두 펼침 / 모두 접기**, **미니맵 표시/숨김** |

- 처음 열면 프로젝트 루트와 **모든 폴더는 펼쳐지고**, 자식이 있는 작업만 접힌 상태입니다.
- 트리·간트와 같은 **담당자·상태·이슈 타입·스페이스 필터**를 공유합니다.
- 카드를 클릭하면 오른쪽에 **작업 상세** 드로어가 열려 처리율과 **워크로그 이력**(합계 시간 포함)을 보여줍니다. **커밋 이력** 탭은 Jira에 개발 도구(Bitbucket 등)가 연동돼 있고 조회 권한이 있을 때만 채워지며, 아니면 "연동된 저장소가 없습니다"로 표시됩니다.
- 구조를 바꾸려면 트리 보기, 일정을 바꾸려면 간트 보기로 전환하세요.

## 5.3.9 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| 트리·간트·맵 버튼이 안 보입니다 | 「프로젝트 관리」 읽기 권한이 없습니다 |
| 드래그·편집이 안 됩니다 | 「프로젝트 관리」 쓰기 권한이 없거나("조회 전용" 배지), Jira에서 그 이슈 편집 권한이 없습니다. 맵 보기는 원래 읽기 전용입니다 |
| 상위로 지정했는데 하위로 안 들어갑니다 | 상위로 지정한 작업이 **이 프로젝트에 편입돼 있지 않거나** 필터에 걸렸습니다. 트리 상세의 상위 항목에 사유가 표시됩니다 |
| 계획 작업량 저장이 실패합니다 | 그 Jira 프로젝트에서 **시간 추적(Time Tracking)이 꺼져** 있습니다. 팀 관리형 프로젝트는 프로젝트 설정 > 이슈 유형에서 해당 유형 필드에 '시간 추적'을 추가하고, 회사 관리형은 이슈 화면에 시간 추적 필드가 있는지 확인하세요 |
| 일괄 적용에서 일부만 실패했습니다 | 실패 목록의 사유(대개 Jira 권한·시간 추적)를 확인하고 **실패 건만 재시도**를 누르세요 |
| 폴더에 넣었더니 상위 지정이 풀렸습니다 | 정상 동작입니다. 상위 지정과 폴더 소속은 동시에 유지되지 않습니다 |
| 작업이 트리 최상위에 떠 있습니다 | 상위 작업이 필터로 걸러졌을 때 하위가 사라지지 않도록 최상위로 올려 보여줍니다. 필터를 해제하면 제자리로 돌아갑니다 |
| Jira에서 상위를 바꿨는데 반영되지 않습니다 | 앱에서 지정한 상위가 **우선 적용** 중입니다. 트리 상세에서 상위 지정을 해제하세요 |
| 간트에서 만든 계층이 Jira에 없습니다 | 앱의 상위 지정·폴더는 Jira에 없는 개념입니다(선후행 연결은 Jira에도 저장됩니다) |
| 구독했는데 이슈가 안 들어옵니다 | ① 구독 상태가 "권한 없음/소스 없음"인지 ② 이슈가 다른 프로젝트에 이미 등록돼 "건너뜀"인지 ③ "구독 이후 생성분만"으로 만들었는지 확인하고, **지금 동기화**를 눌러 보세요 |
| 작업 추가 창에서 이슈가 검색되지 않습니다 | Jira에서 그 이슈를 볼 권한(Browse Projects)이 있어야 합니다. 이슈 키로 정확히 검색해 보세요 |
