## 로컬 확인

app root에서 다음을 실행합니다. 네트워크 호출이나 Confluence 변경은 하지 않습니다.

```powershell
node Moves_Workforce_사용자_매뉴얼/confluence/build-guide.cjs
```

생성 위치는 `_workspace/bilingual-guide-preview/`입니다. `index.html`에서 전체 목차, 언어별 페이지와 상호 링크를 확인할 수 있습니다. `page-map.json`에는 실제 게시 전 확인할 페이지 구조와 원본 연결을 기록합니다. `storage/`에는 Confluence 저장 형식의 검토용 본문을 생성합니다.

이 빌드는 게시 도구가 아닙니다. 실제 이미지는 존재 여부·JPEG 형식·대체 텍스트를 검증하고, 미리보기에는 원본 파일을 복사합니다. Confluence 저장 형식은 첨부 참조로 변환하며 `page-map.json`의 `attachments`에 페이지별 업로드 대상 원본을 기록합니다. 첨부 참조 생성은 실제 업로드 완료를 의미하지 않습니다. 이미지 없이 게시한 본문은 `browser-html/`에서 준비했으며 로컬 초안 배너·캡처 요청·이미지와 캡션을 제외하고 실제 페이지 ID로 링크를 연결했습니다.

미리보기 검증은 로컬 HTML에서 수행했습니다. 실제 Jira 화면이나 Confluence 편집기의 표시 검증을 의미하지 않습니다. 앱 실행 코드는 변경하지 않았으며, 문서 빌드·링크 검사·브라우저 표시 확인을 수행했습니다.

## staging 확인 순서

1. 사용자 계정으로 앱 접속, My Work와 워크로그 작성·수정 권한을 확인합니다.
2. 프로젝트 담당자로 목록·인력·작업·캘린더·대시보드·분석을 확인합니다.
3. 팀장으로 내 팀과 자원 범위를 확인합니다.
4. 관리자로 인력·팀·권한·일반 설정과 기준정보를 확인합니다.
5. 문서 관리·구독·간트·맵·이슈 패널의 제공 여부를 기록합니다.
6. 각 언어의 실제 메뉴·버튼과 초안 표현을 맞춥니다.
7. 본문 예시의 계산과 실제 표시를 비교하고, 필요한 캡처를 연결합니다.

읽기와 창 열기만으로 확인 가능한 항목을 먼저 점검합니다. 워크로그 생성·팀 이동·권한 변경·프로젝트 삭제 같은 변경 동작을 검증하려면 지정된 데모 대상과 허용된 변경 범위를 먼저 확인합니다.

## 게시 전 대조

기존 `_workspace/user-manual/pages.json`에는 한국어 사용자 가이드 폴더 `171573307`과 일부 페이지 ID가 있습니다. 이 값은 과거 로컬 매핑이며 현재 서버 상태를 증명하지 않습니다. 읽기 연결이 생기면 MW 공간과 홈, 기존 한국어·영어 영역을 먼저 조회합니다.

- 이미 존재하는 문서와 목적·제목·내용이 겹치는지 확인합니다.
- 사용자·관리자 영역 아래에 언어별 대응 페이지를 배치합니다.
- 기존 페이지를 변경할 경우 현재 내용을 읽고 페이지 ID·버전을 기준으로 갱신합니다.
- 한·영 링크와 첨부 이미지를 실제 Confluence 페이지에 연결합니다.
- 대표 페이지에서 표·문단·권한·그림 표시를 검증한 뒤 나머지를 반영합니다.
- 게시 후 페이지 수, 부모 관계, 언어 이동, 누락 이미지와 깨진 링크를 확인합니다.

기존 단일 언어 발행기는 형제 제품 문서 링크를 일반 텍스트로 바꾸고 누락 이미지도 첨부 참조로 변환합니다. 이 편집본에 그대로 실행하지 않습니다. 새 페이지 매핑과 이미지 검증을 거친 본문을 사용합니다.
