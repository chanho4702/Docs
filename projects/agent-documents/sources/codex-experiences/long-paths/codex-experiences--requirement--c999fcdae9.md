# RFC-213~215 수정 및 커밋

사용자가 프로젝트 수정 필드 누락(RFC-213), 상태값 간헐 오류(RFC-214), 칸반보드 로드 오류(RFC-215)를 지정하고 작업 후 커밋을 요청했다. 각 RFC의 코드·테스트를 수정하고 독립 검수·전체 필수 검증 후 RFC별로 커밋한다. 푸시·배포·DB 변경은 하지 않는다.

- RFC-213: 상세 응답 캐시 shape를 기존 `{success,rows}`로 유지하고 수정창의 observer에서 단일 row를 선택한다. 수정창 최초 열기에서는 fresh 조회 완료를 기다린 뒤 한 번 초기화하며 사용자 입력은 후속 재조회로 덮지 않는다. 실패·재시도·닫고 다시 열기·상세/맵 소비를 검증한다.
- RFC-214: 목록 행은 목록·상태·번역 변경에 따라 함께 계산한다. 상태 응답 지연/이름 수정 및 페이지 크기 변경을 확인한다.
- RFC-215: 기본 보드 재조회와 과거 페이지 로드를 일관되게 관리한다. 로드한 과거 카드가 재조회로 사라지지 않으며 페이지·hasMore·실패 재시도·경합도 검증한다. 기본 보드 cache shape와 기존 낙관 mutation 계약을 유지한다.
- 칸반 동일 컬럼 순서 영속화는 별도 정책 결정이 필요하므로 이번 수정 범위 밖이다.

백엔드 API·인가·DB·스키마는 변경하지 않는다. 프론트 캐시를 기존 서버 응답 계약에 맞추는 수정이므로 별도 backend 구현 단계는 생략한다. root가 설계·RFC-213/214와 전체 검증·커밋을 담당하고 frontend 담당자가 독립적인 RFC-215를 구현한다. 통합 verifier는 실제 코드 계약을 별도로 확인한다.
