# 기능 정리 (사용자 관점)

> 대상: Confluence 9.2 어댑터 (C10은 이식 전). 마지막 갱신: 2026-08-18 (배치 8·8.5까지 반영).
> 로드맵(서명·CC·위임·잠금 등)은 `docs/backlog.md` 참조.

## 1. 결재 단위

| 단위 | 방법 | 특징 |
|------|------|------|
| 페이지 전체 | 페이지를 열면 자동으로 상태 pill 표시, 상단 액션 `승인 요청` | 페이지당 열린 요청 1개 |
| **게시글(영역)** | 본문에 `approval-region` 매크로로 게시글을 감싸기 | **한 페이지에 여러 개** — 영역마다 독립 결재 |

영역 key는 **적지 않아도 된다.** 페이지의 첫 영역은 `default`를 쓰고, 두 번째부터는 Confluence가
매크로에 부여하는 식별자로 자동 구분한다(기존 문서의 승인 이력은 그대로 이어진다).
직접 `key`를 적으면 그 값이 우선하며, 같은 key를 두 곳에 쓰면 중복 경고가 뜬다(두 영역이 같은 결재를 공유).

**승인 UI는 관리자가 적용한 스페이스에서만 나타난다.** 적용하지 않은 스페이스에서는 상태 pill,
승인 요청 버튼, 영역 매크로의 승인 틀이 전혀 렌더링되지 않고 매크로 본문만 보인다(§7).

## 2. 결재선

- **직접 지정**: 사용자·그룹을 검색해 순서대로 추가 (↑↓로 순서 변경). 순서가 곧 단계.
- **그룹 단계**: 요청 시점의 활성 구성원으로 확정(스냅샷). 통과 조건(1인/전원)은 관리자의 그룹 설정.
- **승인 Flow**: 관리자가 만든 결재선 템플릿 선택. 미리보기 제공.
- 같은 사람이 여러 단계에 있으면 앞 단계에만 남는다.
- 앞 단계가 끝나기 전 뒤 단계 승인자는 결정 불가(409). 반려 1건으로 즉시 REJECTED.
- **요청 메모** — 상신 시 결재자에게 전달할 메시지(≤500자, 선택). 상세 모달·업무함·이메일에 표시.

## 3. 상태와 화면

- 상태: `PENDING / APPROVED / REJECTED / EXPIRED / CANCELLED(회수)`. 라벨은 관리자 설정으로 변경 가능.
- **페이지/영역 헤더의 상태 pill** — 아이콘+라벨(+진행 단계). 클릭하면 상세 모달:
  단계별 결정 현황, 감사 타임라인, 버전별 승인 이력, (내 차례면) 승인/반려 버튼.
  **반려 사유는 모달 안 인라인 스텝**에서 입력(브라우저 prompt 없음) — "반려 사유 필수" 설정 연동.
- **승인 업무함** (`/plugins/servlet/approval-inbox`): Confluence 페이지처럼 렌더링.
  접이식 앱 사이드바(좌측 풀-하이트) — 내 차례 / 진행 중 / 내 요청 / **참조** / 처리한 건 + 알림 + 내 서명.
  (전역 설정 진입은 상단 헤더의 **승인** 아이콘 → popover에서, §7)
  스페이스에서 진입하면 `← 스페이스` 복귀 링크.
  **상태 칩 레일**(클릭하면 필터 적용, 회수·마감 임박·기한 지남 칩은 해당 건이 있을 때만 — 건수는
  현재 탭 모집단 기준) + **구체 필터**(상태 다중·제목 검색·**스페이스**·요청자·Flow·요청일
  프리셋/기간·마감·내 차례) — 필터 상태는 URL(`?f_*`)에 유지되어 새로고침·공유에도 보존.
  목록·필터·건수는 **서버 페이징**(50건 단위 "더 보기", 총건수 표시) — 데이터가 커져도 첫 화면이 가볍다.
  '내 요청' 탭의 진행 중 행은 **행에서 바로 회수** 가능(인라인 확인 폼).
- 요청 상신 중 다른 사용자가 먼저 요청/영역 수정 시(409): 자동 새로고침 대신 **안내 문구 + 새로고침
  버튼** — 작성 중이던 결재선·메모가 보존된다.
- **알림**: 인앱(업무함 피드) + 이메일(설정 시). 요청 생성/승인/반려/만료/마감 임박(DUE_SOON).
- **Excel 다운로드** — 현재 탭과 필터 조건 그대로 CSV로 내려받는다(한 번에 10,000건까지).
- **전역 헤더 `승인`** — 어느 화면에서든 내 차례 건수 배지와 popover(내 차례·마감 임박·읽지 않은 알림·
  업무함·내 서명·(권한자) 승인 설정). 요약은 세션에 짧게 캐시되고 결재하면 즉시 갱신된다.

## 4. 편집과 재승인 — 버전 기록 모델

- **승인 완료는 영구 기록** — 이후 편집·마감으로 무효화되지 않는다.
- 페이지가 승인 버전보다 새로워지면 pill이 `v{n} 승인 · v{m} 미승인`(stale)으로 표시된다.
- 상세 모달에서 **승인 버전과의 차이 보기(diff)**, **버전별 승인 이력**(최근 5건),
  **`같은 결재선으로 재승인 요청`** 원클릭 제공(이력은 최근 20건, 항목을 펼치면 그 버전의 감사 타임라인). 그룹 단계는 재요청 시점 구성원으로 재확장,
  사용 불가 그룹(삭제/비활성)이면 결재선 재구성 안내.
- 진행 중(PENDING) 요청은 편집 시 만료된다(승인이 낡은 버전을 대상으로 남지 않도록).
  영역 결재는 **그 영역 본문이 실제로 바뀐 경우에만** 만료/stale (본문 해시 비교) — 같은 페이지의
  다른 게시글 편집에는 반응하지 않는다. 상신 중 다른 사용자가 영역을 고치면 409로 알려준다.
- 마감일(expiresAt) 경과 시 PENDING만 만료. 마감 임박 알림 제공.

## 5. 회수/취소

- 진행 중(PENDING) 요청을 **요청자 본인 또는 관리자**가 회수(CANCELLED) — 상세 모달의 인라인
  확인 스텝(사유 입력 선택). 미결정 승인자·요청자에게 알림.
- 회수 이력은 감사 타임라인에 영구 보존 (물리 삭제 없음).
- 매크로가 삭제된 영역의 진행 중 결재는 페이지 저장 시 자동 회수(사유 REGION_REMOVED).

## 6. 화면 테마

- **다크 모드는 Confluence 설정을 그대로 따른다.** 앱에 별도 토글이 없으므로 본문과 항상 같은 모드로 보인다.
  사용자가 외관을 명시적으로 고르면 그 값(`html[data-color-mode]`)을, '자동'이면 OS 설정을 따른다.
- 색은 전부 `--dmove-*` 토큰으로만 쓴다(정의는 `css/approval.css`의 `:root` 한 곳).
  화면 어딘가에 리터럴 색을 쓰면 그 부분만 라이트로 남아 다크에서 깨지므로, 회귀 테스트로 막아 둔다.

## 7. 표시 언어

- **Confluence 사용자 언어 설정을 따른다.** 한국어면 한국어, 그 밖의 언어는 전부 영어다.
- 번역은 두 벌뿐이다 — `approval.properties`(영어, 기본)와 `approval_ko.properties`(한국어).
- 적용 범위: **화면 전체** — 페이지 패널·영역 매크로·상세/요청 모달, 승인 업무함, 승인 설정, 사이드바,
  브라우저가 만드는 문구, REST 오류 메시지, 이메일 본문, 헤더·사이드바 메뉴 이름.
- 상태 표시명(승인 대기 등)은 관리자가 정하면 그 값을 그대로 쓴다(조직 용어라 번역하지 않는다).
  정한 적이 없을 때의 기본값만 사용자 언어를 따른다.
- 운영자용 로그와 내부 예외는 번역하지 않는다.

## 8. 시각 표기

- 모든 결정·이벤트는 초 단위로 기록되며, 전 화면에서 접속자 로컬 시간
  `YYYY-MM-DD HH:MM:SS (UTC±h[:mm])`으로 표시된다 (업무함 표는 열 머리에 오프셋 1회 표기).

## 9. 전자서명과 참조

- **전자서명**(관리자 설정, 기본 꺼짐): ① 이름 기반 자동 도장 ② 등록 서명(그리기·이미지 업로드,
  PNG/JPEG 50KB 이하) ③ 승인/반려 확정 시 **서명 PIN** 검증(4~12자, 5회 실패 15분 잠금).
  PIN은 Confluence 비밀번호와 별개이며 원문을 저장하지 않는다. 등록·변경은 업무함 **내 서명** 화면.
- **참조(CC)**: 요청 시 사용자·그룹을 참조자로 지정. 결재 권한은 없고 **열람과 알림만** 받는다
  (요청 생성 시와 최종 결정 시). 업무함 **참조** 탭에서 모아 본다.

## 9-1. 결재 위임과 독촉

- **결재 위임**(관리자 설정, 기본 꺼짐): 자리를 비우는 동안 대신 결재할 사람을 지정한다.
  등록은 업무함 **내 위임** 화면 — 대상자, 시작일·종료일(둘 다 선택), 메모.
  기간을 비우면 해제할 때까지 유효하다. 자신에게는 위임할 수 없고, **위임할 수 있는 것은 내 결재뿐**이다.
  해제는 맡긴 사람과 받은 사람 모두 할 수 있다.
- 대리인은 위임받은 건을 **자기 업무함에서 그대로 보고**(내 차례·배지 집계 포함), 페이지 배너에서
  `대리 결재 — OOO` 표시와 함께 승인·반려한다.
- **결재는 원래 결재자의 이름으로 기록된다.** 실제로 누른 사람은 이벤트에 함께 저장되어
  결재 이력에 `(대신 결재: OOO)`으로 표시된다. 결재선의 자리는 위임으로 바뀌지 않는다.
- **도장·서명은 실제로 누른 사람(대리인)의 것이 찍힌다.** 서명은 "누가 동의했는가"가 아니라
  "누가 그 자리에서 확인했는가"의 산출물이기 때문이다. 도장은 테두리가 점선으로 구분되고
  옆에 `대리` 표시가 붙으며, 도장에 마우스를 올리면 `대리인 (대리 결재 — 원 결재자)`가 보인다.
- 관리자가 위임을 끄면 **등록된 위임이 있어도 그 즉시** 대리 결재가 막힌다(REST에서 403).
- **독촉 알림**(관리자 설정, 기본 꺼짐): 차례가 온 지 `첫 독촉까지(일)`이 지나면 `반복 주기(일)`마다
  한 번씩 알림을 다시 보낸다. 받는 사람은 **지금 차례인 결재자뿐**이다 —
  Confluence에는 조직 계층이 없어 상급자로 올릴 대상이 정해지지 않는다.
- 독촉은 만료 sweep job에 얹혀 돈다. 회차 번호가 알림 키에 들어가므로 sweep이 몇 분마다 돌아도
  주기당 한 번만 나간다.

## 9-2. 일괄 승인

- **일괄 승인**(관리자 설정, 기본 꺼짐): 업무함 **내 차례** 탭에서 여러 건을 골라 한 번에 승인한다.
  머리글의 체크박스로 지금 보이는 건을 모두 고를 수 있고, 한 번에 **최대 50건**이다.
- **반려는 일괄로 하지 않는다.** 반려 사유는 건마다 다르고, 같은 문장을 여러 건에 붙이면
  기록으로서 뜻이 없어진다.
- 서명 PIN이 켜져 있으면 **묶음 전체에 한 번만** 묻는다.
- 일부만 실패하는 것은 정상이다(그 사이 남이 처리했거나 영역 본문이 바뀐 경우). 첫 실패에서
  멈추지 않고 끝까지 처리한 뒤 **어느 건이 왜 안 됐는지**를 목록으로 보여 준다.
- 대리 중인 건도 함께 고를 수 있다 — 결재는 한 건씩 누를 때와 똑같이 원 결재자 이름으로 남는다.

## 10. 관리 (Confluence 관리자 · 설정 관리자)

진입: 전역 헤더의 **승인** 아이콘 → popover의 `승인 설정`, 또는 사이드바의 `승인 설정`
(설정을 다룰 수 있는 사용자에게만 보인다). 한 화면에 여섯 탭이다.

| 탭 | 내용 |
|----|------|
| 전역 정책 | 기본 마감일, 만료 sweep 주기, 마감 임박 기준, 반려 사유 필수, 전자서명·PIN, **결재 위임**, **독촉 알림**(첫 독촉일·반복 주기), **일괄 승인**, 알림/이메일/drain/**알림 보존 기간**, **상태 표시명**(pill 미리보기·설명·기본값 복원이 붙은 행 목록) |
| **적용 스페이스** | 승인 기능을 쓸 스페이스 선택. 고르지 않은 스페이스에서는 승인 UI가 전혀 뜨지 않고 REST도 새 요청을 거절한다 |
| 승인 Flow | 결재선 템플릿. **왼쪽 인원 목록**(검색 없이도 가나다순으로 바로 표시, 사용자/그룹 전환)에서 골라 **오른쪽에 순서대로 쌓고 ↑↓로 조정**. 기본 마감일 설정 |
| 승인 그룹 | 결재선에 올릴 그룹 등록. **두 종류** — ① Confluence 그룹 가져오기(구성원 변경이 자동 반영) ② **사용자 직접 선택**(고른 명단을 그대로 유지). 그룹별 전원 승인(requireAll) |
| 관리자 | **설정 관리자** — Confluence 관리자가 아니어도 이 화면 전체를 다룰 수 있는 사용자. 인원 목록에서 바로 추가 |
| **변경 이력** | 전역 설정을 누가 언제 바꿨는지. 관리자 목록·적용 스페이스·전역 정책 변경이 남는다(수정 불가) |

- 적용 스페이스 목록은 50개씩 서버 페이징된다. 목록을 통째로 들고 있지 않으므로 '보이는 것 선택'은
  현재 페이지에만 적용되고, 선택 상태 자체는 페이지를 넘겨도 유지된다.
- 아직 적용 스페이스를 정하지 않은 설치는 **모든 스페이스에서 사용 가능**(기존 동작 유지).
  스페이스를 빼면서 그 스페이스에 진행 중 결재가 있으면 건수를 경고하고 확인을 받는다.
- 설정 관리자는 Confluence 관리자와 **동일 지위**다(서로 추가·삭제 가능). 다만 타인 요청 회수 등
  결재 개입은 Confluence 관리자에게만 남는다. 관리자·적용 스페이스 변경은 서버 로그에 기록된다.
- 그룹은 **등록된 그룹만** 결재선 검색에 노출. 직접 선택 그룹은 Confluence 그룹과 이름이 겹치면 저장을 거부한다
  (결재선의 `group:이름` 참조가 어느 쪽을 가리키는지 항상 명확해야 하므로). 어느 종류든 비활성 사용자는 결재선에서 빠진다.
- Flow·그룹·설정 관리자의 생성과 편집은 **모달**에서 한다. 탭 본문은 등록된 목록만 보여준다.

## 11. REST 요약

`/rest/approval/1.0/approvals` — 생성(steps·flowId·fromRequestId·requestMessage·regionHash),
조회, 승인/반려/회수(/cancel), 업무함(/mine, /mine/requested, /mine/cc), CSV(/mine/export 등),
알림, 헤더 요약(/header-summary), 서명·PIN, 위임(/delegations/mine, /delegations, /delegations/{id}/disable),
사람 찾기(/users/lookup — 로그인 사용자, 2자 이상 검색만), 일괄 승인(/bulk-approve),
전역 설정(/administration, /administration/spaces), Flow/그룹 관리.
**상태를 바꾸는 요청(POST·PUT·PATCH·DELETE)은 `X-Atlassian-Token: no-check` 헤더가 없으면 403** (CSRF 방어).
`/mine`·`/mine/requested`는 **서버 페이징·필터**: `limit`(≤200)/`offset`/`status`/`q`/`spaceKey`/
`requesterKey`/`flowId`/`createdFrom·To`(ISO)/`due`/`myTurn=1|0`/`myDecided`/`viewStatus` →
`{items, total, statusCounts, facets, badges}`. `fromRequestId`는 steps·flowId·approverKeys·
approverGroups가 모두 없을 때만 이전 결재선을 복원(그 외에는 계보 연결만).
상세는 README 참조. 서버가 페이지 권한(EDIT/VIEW)과 본인 여부를 재검증한다.
