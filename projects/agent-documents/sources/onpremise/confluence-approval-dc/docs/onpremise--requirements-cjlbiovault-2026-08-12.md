# 고객 요구사항 정리 — CJLBioVault (항공수출팀 정서희 님 피드백, 2026-08-12)

## 배경

- 대상 공간(CJLBioVault)은 **전면 HTML 매크로로 페이지를 구성**하며, 페이지 전체가 아니라
  **페이지 내 개별 게시글 단위**의 결재가 필요하다.
- 참고: 함께 회람된 답변(트라이얼 add-on 기준)은 **서드파티 앱**에 대한 것으로, 본 앱(DMOVE
  Approvals)의 지원 범위와 다르다. 아래는 본 앱 기준의 채점과 반영 계획이다.

## 요구 × 지원 현황 × 반영 계획

| # | 요구 | 본 앱 현황 (2026-08-12) | 반영 |
|---|------|------------------------|------|
| 1 | 한 페이지에 게시글 단위 독립 결재 2개 이상 | **지원** — `approval-region` 매크로. key가 다른 매크로마다 독립 결재(CONTENT_REGION), 영역 헤더에 상태 pill·요청 버튼 | ✅ **완료 (배치 6)** — 영역 본문 해시로 "그 게시글이 실제로 바뀐 경우"만 만료/재승인 판정. 상신 중 타인 편집은 409 안내 |
| 2 | 결재 상신 시 메시지/사유 입력 | (구) 미지원 | ✅ **완료 (배치 6)** — 요청 메모(≤500자), 상세 모달·업무함·이메일 표시 |
| 3 | 재결재 + 이력 누적 | **지원** — 버전 기록 모델, stale 표시, 원클릭 재승인, 버전별 승인 이력, diff 링크 | ✅ 완료 (배치 5) |
| 4 | 처리 일시 YYYY-MM-DD HH:MM:SS + Local Time(±UTC) | (구) 화면별 불일치 | ✅ **완료 (배치 6)** — 전 화면 로컬 표시 `YYYY-MM-DD HH:MM:SS (UTC±h[:mm])` |
| 5 | 결재 회수/취소 + 관리자 삭제 + 이력 보존, 매크로 삭제 시 잔존 문제 | (구) 미지원 | ✅ **완료 (배치 6)** — CANCELLED 회수(요청자/관리자, 사유 선택), 이력 영구 보존, 매크로 삭제 영역 자동 회수(REGION_REMOVED) |

## 결정 사항 (2026-08-12)

- 취소는 별도 상태(`CANCELLED`)로 신설 — 업무함에서 만료와 구분. 삭제가 아니라 회수이며 이력은
  이벤트로 남는다 (물리 삭제는 제공하지 않음 — 감사 추적 보존).
- 영역 단위 정밀화(요구 1 갭)를 배치 6에 포함.
- 데모/설명이 더 필요하면 고객 공간(CJLBioVault)을 보며 확인하기로 (정서희 님 제안).

## 미해소/후속 후보

- 요구 1의 "HTML 매크로 구조 유지" — approval-region 매크로가 게시글(HTML 매크로) **주변을 감싸는**
  방식이므로, 기존 페이지에 도입하려면 각 게시글을 매크로로 감싸는 편집 1회가 필요하다.
  대량 페이지 일괄 적용이 필요하면 별도 마이그레이션 논의.
- 물리 삭제(감사 이력까지 제거)는 요구되면 관리자 전용으로 별도 검토.
