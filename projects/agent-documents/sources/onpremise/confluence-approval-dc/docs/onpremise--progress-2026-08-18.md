## 2. 사용자 요구 반영

**① 적용 스페이스에서만 UI를 그린다** — 기존 구현은 `canRequest`만 막아 배너·pill이 그대로 나왔다.
패널은 빈 문자열, 매크로는 본문만 렌더. 스페이스를 끌 때 진행 중 건수를 409로 알리고
인라인 확인을 받는다(브라우저 `confirm` 미사용 관례 유지).

**② 전역 설정을 한 화면 5탭으로** — `전역 정책 / 적용 스페이스 / 승인 Flow / 승인 그룹 / 관리자`.
별도 `/approval-space-settings` 화면은 폐지(서블릿·descriptor 제거). 업무함 사이드바에서 설정을 빼고
진입은 헤더 `승인` popover 하나로 모았다.

**③ 위임 관리자 = Confluence 관리자 동급** (사용자 결정). REST의 설정 계열 권한 13곳을
`isAdministrator()` → `canAdminister()`로 교체. 단 **타인 요청 회수 등 결재 개입은 관리자 전용 유지**.
권한 확산 경로(관리자가 관리자를 추가)가 생기므로 관리자·적용 스페이스 변경을 서버 로그에 남긴다.

## 3. 운영 위험 조치 — CSRF

REST가 파라미터를 **query로 받는 POST**여서, 방어가 없으면 외부 페이지의
`<form method="POST" action="...?keys=...">` 하나로 로그인된 관리자의 설정을 바꾸거나 결재를 위조할 수 있었다.
`ApprovalXsrfFilter`(`/rest/approval/*`)로 상태 변경 메서드에 `X-Atlassian-Token` 헤더를 강제한다.
앱의 모든 클라이언트가 이미 이 헤더를 보내고 있어 무중단으로 켤 수 있었다.

전체 평가와 남은 위험은 `docs/operational-risk-2026-08-18.md`.

## 4-1. 화면 확인 후 반영한 피드백 (같은 날)

- **사이드바 '승인 설정'이 화면마다 나타났다 사라져 어색** — 설정→내 서명으로 넘어가면 돌아갈 길이
  사라졌다. 설정 권한자에게는 업무함에서도 같은 자리에 상시 표시하도록 되돌렸다(위임 관리자 포함).
- **Flow 단계 편집이 쉼표 텍스트 입력** — 요청 모달에 이미 있던 패턴을 가져와 **인라인 2단 피커**로
  교체했다. 왼쪽 인원 목록(사용자/그룹 전환·검색·페이징), 오른쪽 선택 단계 목록(순번·↑↓·빼기).
  hidden `#steps`에 서버 계약 형식(`user:key;group:name`)만 직렬화해 REST 계약은 그대로 뒀다.
- **인원 목록이 기본으로 안 뜨는 게 가장 불편** — `/users/page`가 검색어 2자 미만이면 빈 배열을
  주던 것을, 검색어가 없으면 **디렉터리 전체를 이름순으로 페이징**하도록 바꿨다. UserAccessor에
  페이징 질의가 없어 정렬하려면 전체를 읽어야 하므로 60초 로컬 캐시 + 3,000명 상한을 뒀다.
  관리자 탭도 같은 이유로 기본 목록을 띄운다.

## 4-2. 2차 피드백 — 모달화와 직접 선택 그룹

- **생성·편집을 모두 모달로** — Flow·승인 그룹·설정 관리자 세 탭 모두 "목록 + 만들기 버튼 → 모달" 구조로
  바꿨다. 탭 본문에서 좌우 2단(폼+목록)이 사라져 목록이 화면을 다 쓴다.
  부수 효과로 `ApprovalSettingsServlet`의 text block이 상수 풀 64KB 한계를 넘어
  `String.join("", ...)` 3조각으로 분할했다 (배치 8e의 InboxServlet과 같은 처방).
- **승인 그룹에 '사용자 직접 선택' 종류 추가** — 기존에는 Confluence 그룹만 등록할 수 있었다.
  `ApprovalGroupEntity`에 `groupType`(CONFLUENCE/CUSTOM)과 `memberKeys`를 더하고,
  `UserAccessorGroupDirectory`가 CUSTOM이면 저장된 명단을, 아니면 Confluence 그룹을 펼치도록 했다.
  - 이 필드가 생기기 전 행은 값이 비어 있어 **CONFLUENCE로 해석**된다(기존 데이터 무영향).
  - 이름 충돌은 저장 시 거부한다 — 결재선의 `group:이름`이 어느 쪽을 가리키는지 모호해지면 안 된다.
  - 종류 변경은 편집 중 잠근다(같은 이유).
  - 비활성 사용자 제외 규칙은 Confluence 그룹과 동일하게 적용된다.

## 4-3. 다크 모드 (Confluence 설정 연동)

실측: Confluence 9.2는 `<html data-theme="dark:dark light:light" data-color-mode-auto>`를 찍고
`confluence.dark.theme.text.colors` 플래그가 켜져 있다. 따라서 앱 토글을 만들지 않고 그 속성을 따른다.

- `approval.css`의 리터럴 색 **170곳(고유 43종)을 전부 토큰화**. 이 파일에는 토큰 정의가 없어
  `var()`가 무효였고 그래서 리터럴을 쓰고 있었다(배치 8c·8d 사고의 근원).
- 토큰은 `:root`에 `--dmove-` 접두로 정의한다. 컴포넌트마다 정의하면 새 컴포넌트에서 빠뜨리고,
  접두어가 없으면 Confluence 전역을 오염시킨다.
- 업무함·설정 서블릿과 NavMarkup의 색 정의를 걷어내고 같은 토큰을 참조하게 했다 — **정의는 한 곳**.
- `--dmove-on-accent` 신설: 다크에서 accent가 밝아지므로 그 위 글자를 흰색으로 고정하면 대비가 무너진다.
- `DarkModeTokenTest` 4건으로 리터럴 재유입을 막는다(토큰 정의 줄 밖에 색이 있으면 실패).

## 4-4. i18n (2026-08-19)

Confluence 사용자 언어가 한국어면 한국어, 그 밖에는 전부 영어. 번역은 두 벌뿐이다.

- `ApprovalI18n` — `{{i18n:key}}` 자리표시자를 한 번에 치환한다. 문구마다 `__TOKEN__`을 만들면
  서블릿 템플릿에서만 수백 개가 된다. 마크업은 문구와 사용자 데이터를 함께 조립하므로,
  사용자가 우연히 적은 글자가 자리표시자로 읽히지 않도록 `i18n:` 접두까지 요구한다.
- ResourceBundle을 직접 쓴다(렌더 단위 테스트가 Confluence 컨텍스트 없이 돌기 때문).
  **기본 폴백은 서버 로캘로 떨어지므로 껐다** — 한국어 서버에서 영어 사용자가 한국어를 보는 경로다.
- 적용: ApprovalMarkup 91 + 패널·매크로 10 + 업무함 145 + 설정 174 + 사이드바 15. 키 392개.
  같은 문구는 키를 재사용한다(업무함 18건, 설정 19건, 사이드바 9건).
- 렌더 지점(서블릿 doGet, 패널·매크로 반환)에서 한 번에 localize한다.

**치환 사고 하나**: 짧은 라벨("진행 중")이 긴 문장("승인 **진행 중** 페이지가 수정되어…") 한가운데를
잘라먹었다. 긴 문구부터 치환하도록 정렬하고, 긴 문장을 매핑에 먼저 등록해야 한다.

회귀 방지 — `ServletLocalizationTest` 3건: 영어 화면에 한국어 잔존 0(주석 제외), 화면이 쓰는 키가
두 언어 모두에 존재, 번역 후 자리표시자 잔존 0. `ApprovalI18nTest` 7건.

## 4-5. i18n 마무리 + 로그인 화면 노출 버그 (2026-08-19)

**로그인 페이지에 승인 헤더가 박히는 버그** (사용자 제보): `web-item`에 조건이 없어 익명 화면에도
나왔다. `LoggedInCondition`을 만들어 헤더 진입점과 스페이스 사이드바 링크에 걸었다.
실측 확인 — 로그인 페이지 HTML에서 `dmove-approval*` 0건(이전에는 헤더 항목이 있었다).

i18n 나머지 (키 총 491개)
- REST 오류 44문구. `msg()`가 `"키:상세"` 형태도 받는다 — 도메인·헬퍼가 대상 이름을 실어 보내면
  앞부분만 번역하고 상세는 붙인다. 키로 잡히지 않으면 원문을 그대로 통과시켜 안전하다.
- 사용자에게 노출되는 예외(GroupApproverResolver, ApprovalPinService)는 번역 키를 던지고
  REST 경계에서 문구로 바꾼다.
- 이메일: 판정이 "영어일 때만 영어"라 일본어·독일어 사용자에게 한국어 메일이 나갔다. 정책대로 뒤집었다.
- approval.js 49문구: 정적 파일이라 치환이 불가능하므로 `WebResourceDataProvider`로 문구를 실어 보내고
  JS가 `t(key)`로 꺼내 쓴다.
- 상태 라벨 기본값도 사용자 언어를 따른다(관리자가 정한 값이 있으면 그 값 우선).

**번역되면 깨지는 로직 2곳**을 함께 고쳤다 — 문구로 분기하던 코드다.
- 서버 409 응답을 `error.body.indexOf('영역이 변경')`으로 판별하던 것 → 서버가 `REGION_CHANGED:` 코드를
  앞에 붙이고 JS는 코드로 분기.
- 아바타 이니셜에서 `/^그룹:\s*/`로 접두를 떼던 정규식 → 번역된 접두 기준으로 제거.

회귀 방지: `ApprovalJsI18nTest` 4건 — JS가 부르는 키 ⊆ 서버가 싣는 키 ⊆ 번역 파일, 그리고 그 역도.
셋 중 하나만 어긋나도 화면에 키가 드러나므로 양방향으로 막았다.

## 5. 교훈

- **파이프라인 밖에서 만들어진 코드는 결함 밀도가 높다.** 8/15 뭉치는 스펙·QA 산출물이 없었고,
  치명 1건(CSV) + 높음 3건이 나왔다. 하네스를 우회하면 그만큼 QA를 나중에 몰아서 치르게 된다.
- **"버튼만 숨기기"는 기능 차단이 아니다.** 스페이스 정책이 `canRequest`에만 걸려 있어 요구와 어긋났다.
  차단은 렌더 진입점에서 끊어야 한다.
- **자동 식별자 도입은 기존 데이터의 키를 바꾼다.** macro-id 자동 key는 좋은 개선이지만,
  첫 영역에 `default` 폴백을 두지 않으면 기존 문서의 승인 이력이 통째로 끊겼다.
