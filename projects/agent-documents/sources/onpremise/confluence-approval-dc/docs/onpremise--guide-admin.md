## 1. 설치와 호환 버전

### 1.1 지원 매트릭스

| 산출물 | 지원 Confluence | 지원 Java 런타임 |
|---|---|---|
| Confluence 9 어댑터 | 9.2.x | Java 17 또는 21 |

- 앱은 Data Center 호환으로 선언되어 있습니다.
- **현재 제공되는 산출물은 Confluence 9.2 계열 하나입니다.** Confluence 10 계열 지원은
  준비 중이며, 아직 제공하지 않습니다.
- Confluence를 10.x로 올릴 계획이 있으시면 **업그레이드 전에 문의해 주십시오.**
  9.2용 산출물은 10.x에서 동작하지 않습니다.

### 1.2 설치 절차

1. Confluence 관리자로 로그인합니다.
2. **일반 설정 → 앱 관리(Universal Plugin Manager)** 에서 대상 Confluence 버전에 맞는 앱 파일을 업로드합니다.
3. 앱이 활성화되면 아무 페이지나 열어 상단 헤더에 **승인** 메뉴가 나타나는지 확인합니다.
4. 편집 권한이 있는 페이지에서 상단 액션에 **승인 요청** 버튼이 보이는지 확인합니다.

> 설치 직후에는 **적용 스페이스**를 아직 정하지 않은 상태이므로 모든 스페이스에서 승인을 쓸 수 있습니다.
> 특정 스페이스에서만 쓰려면 [4장](#4-적용-스페이스-탭)을 참고해 적용 스페이스를 지정하십시오.

### 1.3 업그레이드

- 같은 계열의 새 버전 파일을 앱 관리에서 업로드하면 기존 승인 데이터와 페이지에 삽입된
  `approval-region` 매크로는 그대로 유지됩니다.
- Confluence 자체를 10.x로 올리는 경우에는 이 앱이 동작하지 않습니다. 10 계열 산출물이
  준비되기 전까지는 Confluence 업그레이드를 보류하시거나 먼저 문의해 주십시오.

## 2. 설정 화면에 들어가는 방법

승인 설정 화면은 **Confluence 관리자** 또는 **설정 관리자**([7장](#7-관리자-탭))만 열 수 있습니다.
권한이 없는 사용자가 주소로 직접 접근하면 접근 거부(403)로 응답합니다.

들어가는 경로는 두 가지입니다.

| 경로 | 방법 |
|---|---|
| 전역 헤더 | 어느 화면에서든 상단 헤더의 **승인**을 누르면 열리는 작은 창에서 **승인 설정**을 선택합니다. 이 항목은 설정 권한이 있는 사용자에게만 보입니다. |
| 승인 업무함 | **승인 업무함** 화면 왼쪽 사이드바의 **알림과 설정** 묶음에 있는 **승인 설정**을 선택합니다. |

설정 화면은 한 페이지 안에서 여섯 개의 탭으로 나뉘며, 화면에 표시되는 순서는 다음과 같습니다.

**전역 정책 · 적용 스페이스 · 승인 Flow · 승인 그룹 · 관리자 · 변경 이력**

## 3. 전역 정책 탭

요청을 만들 때 적용되는 기본값과 만료·서명·위임·독촉·알림 동작을 정합니다.
이 탭의 모든 항목은 맨 아래 **승인 설정 저장** 버튼 하나로 함께 저장됩니다.

### 3.1 승인 정책

| 설정 항목 | 기본값 | 설명 |
|---|---|---|
| 기본 마감일(일) | **0 (마감일 없음)** | 요청을 만들 때 자동으로 붙는 마감일입니다. 0이면 마감일을 두지 않습니다. 요청에 승인 Flow를 적용했고 그 Flow에 기본 마감일이 있으면 **Flow의 값이 우선**하고, Flow에 값이 없을 때 이 전역 값이 적용됩니다. |
| 만료 sweep 주기(분) | **10** | 진행 중인 요청의 마감 경과 여부를 서버가 확인하는 주기입니다. 마감 임박 여부도 이 주기로 함께 점검합니다. 값을 크게 잡으면 만료 처리와 마감 임박 알림이 그만큼 늦게 반영됩니다. |
| 마감 임박 기준(시간) | **24** | 마감까지 남은 시간이 이 값 이하가 되면 "마감 임박"으로 표시하고, 마감 임박 알림을 보냅니다. |
| 반려 사유 필수 | **꺼짐** | 켜면 반려할 때 사유를 반드시 적어야 합니다. |

### 3.2 전자서명

| 설정 항목 | 기본값 | 설명 |
|---|---|---|
| 전자서명 사용 | **꺼짐** | 켜면 승인 결정 옆에 도장/서명이 표시되고, 사용자가 **내 서명** 화면에서 서명과 PIN을 등록할 수 있습니다. |
| 승인/반려 시 서명 PIN 검증 | **꺼짐** | 켜면 승인·반려를 확정할 때 서명 PIN을 입력해야 합니다. **전자서명 사용이 켜져 있을 때만 선택할 수 있으며**, 꺼져 있으면 이 항목은 비활성 상태로 표시됩니다. |

자세한 운영 지침은 [9장](#9-전자서명을-켤-때-알아야-할-것)을 참고하십시오.

### 3.3 결재 위임

결재자가 자리를 비우는 동안 **자기 결재를 대신 처리할 사람**을 지정할 수 있게 하는 설정입니다.

| 설정 항목 | 기본값 | 설명 |
|---|---|---|
| 결재자가 위임을 등록할 수 있음 | **꺼짐** | 켜면 사용자가 승인 업무함의 **내 위임** 화면에서 대리인·기간·메모를 등록할 수 있고, 대리인이 그 결재를 대신 승인·반려할 수 있습니다. |

**켜면 무엇이 달라지나**

- 사용자는 **내 위임** 화면에서 대리인을 등록합니다. 시작일·종료일은 둘 다 선택이며, 비워 두면 해제할 때까지 유효합니다.
  **자기 자신에게는 위임할 수 없고, 맡길 수 있는 것은 본인의 결재뿐**입니다(남의 결재를 대신 맡겨 줄 수 없습니다).
  등록된 위임은 **맡긴 사람과 받은 사람 어느 쪽에서도** 해제할 수 있습니다.
- 대리인의 **승인 업무함**에 위임받은 건이 자기 결재와 함께 나타나고, 전역 헤더의 건수 배지에도 함께 잡힙니다.
- 대리인이 그 페이지를 열면 상태 표시 옆에 **대리 결재 — (원래 결재자 이름)** 이 붙고 승인·반려 버튼이 나타납니다.
- **결재는 원래 결재자의 이름으로 기록됩니다.** 결재선의 자리는 위임으로 바뀌지 않으며,
  실제로 누른 사람은 그 요청의 **감사 타임라인에 "(대신 결재: OOO)"** 으로 함께 남습니다.
  전자서명을 켜 두었다면 결정 옆의 도장·서명도 원래 결재자의 것이 표시됩니다.
- 서명 PIN 검증을 켜 두었다면, 대리 결재에는 **버튼을 누르는 대리인 본인의 PIN**이 필요합니다.

**끄면 어떻게 되나**

- **등록된 위임이 남아 있어도 그 즉시 대리 결재가 막힙니다.** 서버가 요청 단계에서 거절하므로,
  화면을 열어 둔 사용자가 이어서 누르더라도 결재되지 않습니다. 대리인의 업무함에서도 위임받은 건이 사라지고,
  **내 위임** 화면에는 "이 사이트는 결재 위임이 꺼져 있습니다. 관리자에게 문의하세요."라고 표시됩니다.
- 등록된 위임 자체가 지워지지는 않으므로, 다시 켜면 유효 기간 안의 위임이 그대로 되살아납니다.

> 대리 결재는 **페이지 전체 결재**에 적용됩니다. 승인 매크로로 지정한 **영역 결재는 결재자 본인만** 승인·반려할 수 있습니다
> (대리인의 업무함에는 보이지만 페이지에서 승인 버튼이 나타나지 않습니다).

### 3.4 독촉 알림

차례가 온 지 오래된 결재자에게 알림을 **다시** 보내는 설정입니다.

| 설정 항목 | 기본값 | 설명 |
|---|---|---|
| 독촉 알림 보내기 | **꺼짐** | 켜면 아래 두 값에 따라 독촉 알림을 보냅니다. 꺼져 있으면 아래 두 칸은 비활성 상태로 표시됩니다. |
| 첫 독촉까지(일) | **3** | 그 건이 마지막으로 진행된 뒤(요청 생성 또는 앞 단계 승인) 이 날수가 지나도록 결정이 없으면 **첫 독촉**을 보냅니다. |
| 반복 주기(일) | **3** | 첫 독촉 이후에도 결정이 없으면 이 주기마다 한 번씩 다시 보냅니다. |

- **받는 사람은 지금 차례인 결재자뿐입니다.** 요청자나 참조자, 상급자에게는 가지 않습니다.
  **상급자 상신(에스컬레이션) 기능은 없습니다.** Confluence에는 조직 계층 정보가 없어 "상급자"를 정할 근거가 없기 때문입니다.
  조직 계층에 따른 상신이 필요하다면 결재선 자체에 상위 결재자를 한 단계 더 넣는 방식으로 설계하십시오.
- 위임을 받은 대리인에게는 독촉이 따로 가지 않습니다. 독촉은 결재선에 있는 **원래 결재자**에게 발송됩니다.
- 알림 목록과 메일 제목에는 **결재 독촉**으로 표시됩니다.
- 독촉 점검은 **만료 sweep 주기**([3.1](#31-승인-정책))에 얹혀 함께 돕니다. 다만 회차마다 한 번만 나가도록 되어 있어,
  sweep 주기를 짧게 잡아도 **주기당 한 번**을 넘겨 발송되지 않습니다. 반대로 sweep 주기를 아주 길게 잡으면
  독촉 시점도 그만큼 늦게 감지됩니다.
- **알림 사용**([3.5](#35-알림))이 꺼져 있으면 독촉 알림도 만들어지지 않습니다. 이메일로도 받게 하려면
  **email 알림 사용**까지 켜져 있어야 하고, 수신자에게 이메일 주소가 있어야 합니다.
  즉 화면 안 알림은 `알림 사용` + `독촉 알림 보내기`, 이메일은 여기에 `email 알림 사용`이 더해져야 나갑니다.

### 3.5 알림

| 설정 항목 | 기본값 | 설명 |
|---|---|---|
| 알림 사용 | **켜짐** | 전체 알림의 주 스위치입니다. 끄면 화면 안 알림과 email 알림이 **모두** 만들어지지 않습니다. |
| email 알림 사용 | **꺼짐** | 켜면 알림을 이메일로도 보냅니다. **Confluence 메일 서버가 설정되어 있어야 합니다.** |
| 마감 임박 알림 사용 | **켜짐** | 마감 임박 시점의 알림입니다. '알림 사용'이 켜져 있을 때만 동작합니다. |
| 알림 발송 주기(분) | **1** | 대기 중인 알림을 실제로 내보내는 주기입니다. |
| 알림 최대 재시도 | **5** | 발송에 실패한 알림을 다시 시도하는 최대 횟수입니다. |

> **email 알림을 켜고 저장했는데 메일 서버가 설정되어 있지 않으면**, 저장 직후 화면에
> "email 알림은 켜졌지만 Confluence 메일 서버가 설정되어 있지 않습니다."라는 경고가 표시됩니다.
> 설정은 저장되지만 메일은 나가지 않으므로, Confluence의 메일 서버를 먼저 구성하십시오.

### 3.6 상태 표시명

승인 상태 다섯 가지의 표시 이름을 조직에서 쓰는 용어로 바꿀 수 있습니다.
각 줄에는 실제 화면과 같은 모양의 미리보기, 상태 설명, **기본값** 되돌리기 버튼이 함께 있습니다.

| 상태 | 기본 표시명(한국어) | 의미 |
|---|---|---|
| PENDING | 승인 대기 | 결재를 기다리는 중 |
| APPROVED | 승인 완료 | 모든 단계가 승인함 |
| REJECTED | 반려 | 한 명이라도 반려함 |
| EXPIRED | 만료 | 마감이 지나 끝남 |
| CANCELLED | 회수 | 요청자가 거둬들임 |

- 여기서 정한 이름은 상태 표시, 승인 업무함, 알림에 그대로 쓰입니다.
- 이름을 바꿔도 **결재 흐름 자체는 달라지지 않습니다.**
- 관리자가 이름을 한 번도 정하지 않았을 때만 위 기본값이 사용자 언어에 맞춰 표시됩니다.
  한 번이라도 값을 정하면, 사용자의 언어와 무관하게 정한 값이 그대로 표시됩니다(조직 용어는 번역하지 않습니다).

### 3.7 저장 후 나타나는 메시지

| 메시지 | 뜻과 대응 |
|---|---|
| 승인 설정을 저장했습니다. | 정상 저장되었고 주기 설정도 즉시 반영되었습니다. |
| 설정은 저장됐지만 만료 주기는 서버 재기동 후 적용됩니다. | 값은 저장되었으나 주기 작업을 다시 등록하지 못한 경우입니다. 새 주기를 확실히 적용하려면 **Confluence를 재기동**하십시오. |
| email 알림은 켜졌지만 Confluence 메일 서버가 설정되어 있지 않습니다. | Confluence 메일 서버를 구성하십시오. |
| 입력값을 확인해 주세요. | 숫자 항목이 비었거나 허용 범위를 벗어났습니다. |

## 4. 적용 스페이스 탭

### 4.1 무엇을 정하는 탭인가

**승인 기능을 사용할 스페이스를 고르는 곳입니다.**
여기서 고른 스페이스에서만 페이지 상단의 승인 영역과 승인 매크로가 나타납니다.
고르지 않은 스페이스에서는

- 페이지 상단의 상태 표시와 **승인 요청** 버튼이 보이지 않고,
- 본문에 넣은 승인 매크로도 승인 틀 없이 본문만 보이며,
- 새 승인 요청 생성이 서버에서 거절됩니다("이 스페이스에는 승인 기능이 적용되어 있지 않습니다").

### 4.2 아직 정하지 않은 상태(설치 직후)

적용 스페이스를 한 번도 저장하지 않은 설치에서는 **모든 스페이스에서 승인을 쓸 수 있습니다.**
이 상태에서는 탭 위쪽에 "아직 적용 스페이스를 정하지 않아 **모든 스페이스**에서 승인을 쓸 수 있습니다"라는
안내가 표시됩니다. 여기서 한 번 저장하면 그때부터는 **선택한 스페이스에서만** 쓰게 됩니다.

### 4.3 목록 다루기

- 목록은 **50개씩 나누어** 표시되며, **이전/다음** 버튼으로 넘깁니다.
- 이름이나 키로 걸러 찾을 수 있습니다. 스페이스가 아주 많으면 일부만 검색되며,
  "스페이스가 많아 일부만 찾아봤습니다"라는 안내가 나옵니다. 검색어를 더 입력해 좁히십시오.
- **보이는 것 선택 / 보이는 것 해제**는 이름 그대로 **지금 화면에 보이는 페이지에만** 적용됩니다.
  전체 목록을 한 번에 선택하는 기능이 아닙니다.
- 선택 상태 자체는 페이지를 넘기거나 검색어를 바꿔도 유지되며, **적용 스페이스 저장**을 눌러야 반영됩니다.

### 4.4 스페이스를 뺄 때 (중요)

진행 중인 승인이 있는 스페이스를 적용에서 빼려고 하면 저장이 곧바로 되지 않고 **확인 절차**가 나타납니다.

1. 화면에 "진행 중인 승인 N건이 있는 스페이스를 적용에서 제외합니다 (스페이스명 N건 …)"라는 경고가
   건수와 함께 표시됩니다.
2. **돌아가기**를 누르면 저장이 취소됩니다.
3. **그래도 적용 해제**를 누르면 저장이 진행됩니다.

적용에서 뺀 뒤에도 **진행 중이던 결재가 사라지지는 않습니다.** 다만 해당 페이지에서는 승인 영역이 보이지 않으므로,
**결재는 승인 업무함에서만 처리할 수 있습니다.** 해당 스페이스에서 새 요청을 만드는 것은 막힙니다.
다시 적용에 포함시키면 페이지에서도 원래대로 보입니다.

## 5. 승인 Flow 탭

반복해서 쓰는 결재선을 템플릿으로 등록하는 곳입니다. 사용자는 승인 요청을 만들 때
**승인 Flow 사용** 탭에서 여기 등록한 Flow를 골라 쓸 수 있습니다.

### 5.1 Flow 만들기

**새 Flow 만들기**를 누르면 모달이 열립니다.

| 입력 | 설명 |
|---|---|
| Flow 이름 | 요청 화면의 선택 목록에 표시되는 이름입니다. |
| 승인 단계 | 왼쪽 인원 목록에서 결재자를 고르면 오른쪽에 순서대로 쌓입니다. **사용자 / 그룹**을 전환해 고를 수 있고, 검색 없이도 목록이 바로 표시됩니다. |
| 기본 마감일(일) | 이 Flow로 만든 요청의 마감일입니다. 0이면 마감일 없음이며, 이때는 전역 기본 마감일이 적용됩니다. |

### 5.2 순서의 의미

- **위에서 아래가 곧 승인 순서입니다.** 1단계가 승인해야 2단계 차례가 되고, 그 전에는 뒤 단계 결재자가 결정할 수 없습니다.
- 순서는 각 항목의 **↑ ↓** 버튼으로 바꾸고, **×** 로 뺍니다.
- 그룹을 넣으면 그 그룹 전체가 **한 단계**로 묶입니다. 그 단계의 통과 조건(한 명 승인 / 전원 승인)은
  Flow가 아니라 [승인 그룹](#6-승인-그룹-탭) 설정을 따릅니다.
- 반려는 한 건만 있어도 그 즉시 요청 전체가 반려로 끝납니다.

### 5.3 목록에서 할 수 있는 일

등록된 Flow 카드에는 단계 수, 마감일, 결재선이 요약되어 있고 다음 버튼이 있습니다.

- **편집** — 이름·결재선·마감일을 고칩니다.
- **비활성화 / 활성화** — 비활성화하면 요청 화면의 Flow 선택 목록에 나오지 않습니다. 잠시 쓰지 않을 때 사용하십시오.
- **삭제** — 목록에서 지웁니다. **확인 창 없이 즉시 실행되며 되돌릴 수 없습니다.**

> 이미 만들어진 요청의 결재선은 요청 시점에 확정되므로, Flow를 고치거나 지워도 **진행 중인 결재는 그대로 진행됩니다.**
> 다만 결재선에 있던 그룹을 더 이상 쓸 수 없게 되면, 나중에 그 결재선으로 재승인을 요청할 때
> "결재선을 다시 구성해 주세요"라는 안내가 나옵니다.

## 6. 승인 그룹 탭

**여기 등록한 그룹만 결재선에 올릴 수 있습니다.** Confluence에 그룹이 있어도 등록하지 않으면
요청 화면의 그룹 검색 결과에 나오지 않습니다.

### 6.1 두 가지 그룹 종류

| 종류 | 만드는 법 | 구성원 변경 반영 |
|---|---|---|
| **Confluence 그룹 가져오기** | Confluence의 기존 그룹을 검색해 등록합니다. | **자동으로 반영됩니다.** Confluence에서 구성원이 바뀌면 그 뒤에 만들어지는 요청의 결재선에 그대로 따라옵니다. |
| **사용자 직접 선택** | 그룹 이름을 새로 짓고, 사용자 목록에서 구성원을 직접 고릅니다. | **반영되지 않습니다.** 여기서 고른 명단이 그대로 유지되며, Confluence 그룹의 구성원이 바뀌어도 영향받지 않습니다. |

- 그룹 종류는 **만들 때 정하며, 편집 중에는 바꿀 수 없습니다.** 종류를 바꾸면 결재선이 가리키는 대상이
  달라지기 때문입니다. 종류를 바꾸려면 새로 만들어야 합니다.
- 직접 선택 그룹의 이름도 편집 중에는 바꿀 수 없습니다.

### 6.2 이름 충돌 규칙

결재선은 그룹을 **이름으로** 가리킵니다. 따라서 어느 쪽을 가리키는지 모호해지지 않도록,
**Confluence 그룹과 같은 이름의 직접 선택 그룹은 만들 수 없습니다.** 저장하려고 하면
"같은 이름의 Confluence 그룹이 있습니다. 다른 이름을 쓰세요"라는 메시지와 함께 거부됩니다.
반대로 이미 직접 선택 그룹으로 쓰고 있는 이름을 Confluence 그룹으로 등록하려는 경우도 거부됩니다.

### 6.3 통과 조건 — 전원 승인 / 1명 승인

- **구성원 전원이 승인해야 통과**를 체크하면 그 그룹 단계는 구성원 **전원**의 승인이 있어야 다음 단계로 넘어갑니다.
- 체크하지 않으면(기본) 구성원 **한 명**이 승인하면 통과합니다.
- 카드에는 각각 `전원 승인` / `1명 승인` 배지로 표시됩니다.

### 6.4 그 밖의 항목과 동작

| 항목 | 설명 |
|---|---|
| 표시 이름 | 결재선과 목록에 보일 이름입니다. 비워 두면 그룹 이름이 그대로 쓰입니다. |
| 결재선에서 사용 | 기본으로 켜져 있습니다. 끄면 결재선 검색에 나오지 않습니다(`미사용` 배지). |
| 구성원 보기 | 지금 이 그룹의 활성 구성원을 펼쳐 확인합니다. |
| 등록 해제 | 승인 그룹 목록에서 뺍니다. **확인 창 없이 즉시 실행됩니다.** Confluence 그룹 자체가 삭제되지는 않습니다. |

- 그룹 단계의 승인자는 **요청을 만드는 시점의 활성 구성원**으로 확정됩니다(스냅샷).
  요청 후에 구성원이 바뀌어도 진행 중인 결재의 승인자 명단은 달라지지 않습니다.
- 어느 종류든 **비활성 사용자는 결재선에서 제외**됩니다. 활성 구성원이 하나도 없으면
  "활성 구성원이 없습니다. 이 그룹은 결재선에 올려도 승인자가 만들어지지 않습니다"라고 알려 줍니다.

## 7. 관리자 탭

### 7.1 설정 관리자란

**설정 관리자**는 Confluence 관리자가 아니어도 이 승인 설정 화면의 모든 설정을 다룰 수 있는 사용자입니다.

- 전역 정책, 적용 스페이스, 승인 Flow, 승인 그룹, 변경 이력까지 **Confluence 관리자와 같은 범위**를 다룹니다.
- **설정 관리자끼리 서로 추가·삭제할 수 있습니다.** 즉, 한 명을 추가하면 그 사람이 다른 설정 관리자를
  뺄 수도 있습니다. 이 점을 이해한 상태에서만 추가하십시오.
- Confluence 관리자는 이 목록과 무관하게 **언제나** 설정 화면을 쓸 수 있습니다. 따라서 목록이 비어도
  설정 화면에 못 들어가는 상황은 생기지 않습니다.
- 다만 **결재 자체에 개입하는 권한**(예: 다른 사람이 올린 요청의 회수)은 Confluence 관리자에게만 있습니다.

### 7.2 추가와 삭제

- **설정 관리자 추가**를 누르면 사용자 목록이 열립니다. 이름이나 계정으로 검색해 **추가**를 누르면 즉시 반영됩니다.
- 카드의 **삭제**를 누르면 **확인 창 없이 즉시** 목록에서 빠집니다.
- 설정 관리자 목록의 변경은 **변경 이력**에 남고, 서버 로그에도 기록됩니다.

## 8. 변경 이력 탭

전역 설정을 **누가, 언제, 무엇을** 바꿨는지 확인하는 탭입니다. 기록은 나중에 수정되지 않습니다.

| 열 | 내용 |
|---|---|
| 시각 | 변경 시각(접속자 시간대 기준으로 표시) |
| 변경한 사람 | 설정을 바꾼 사용자 |
| 대상 | `전역 정책` / `적용 스페이스` / `설정 관리자` 중 하나 |
| 변경 내용 | 실제로 달라진 항목만 요약해서 표시 |

기록되는 항목은 다음과 같습니다.

- **전역 정책** — 기본 마감일, 만료 sweep 주기, 마감 임박 기준, 반려 사유 필수, 알림, email 알림,
  마감 임박 알림, 알림 발송 주기, 알림 최대 재시도, 전자서명, 서명 PIN 필수, 상태 표시명.
  **결재 위임과 독촉 알림 설정의 변경은 이 목록에 포함되지 않습니다.**
- **적용 스페이스** — 추가·제외된 스페이스
- **설정 관리자** — 추가·삭제된 사용자

이 화면은 **최근 100건**을 보여 줍니다. **새로 고침** 버튼으로 다시 불러올 수 있습니다.

## 9. 전자서명을 켤 때 알아야 할 것

전자서명은 **기본적으로 꺼져 있습니다.** 켜면 세 단계로 동작합니다.

| 단계 | 무엇인가 | 관리자가 알아야 할 점 |
|---|---|---|
| ① 자동 도장 | 서명을 등록하지 않은 사용자에게는 이름을 딴 도장이 자동으로 표시됩니다. | 별도 준비가 필요 없습니다. 전자서명을 켜는 순간부터 적용됩니다. |
| ② 등록 서명 | 사용자가 직접 그리거나 이미지를 올려 자기 서명을 등록합니다. | 이미지는 **PNG 또는 JPEG, 50KB 이하**만 등록됩니다. 등록한 사용자에게는 자동 도장 대신 등록 서명이 표시됩니다. |
| ③ 서명 PIN | 승인·반려를 확정할 때 PIN을 입력하게 합니다. | **전자서명을 켠 뒤에만** 선택할 수 있습니다. |

운영상 반드시 확인할 점은 다음과 같습니다.

- **서명·PIN 등록은 사용자 본인이 합니다.** 승인 업무함의 **내 서명** 화면에서 등록·변경합니다.
  관리자가 대신 등록해 줄 수 없습니다.
- **서명 PIN 검증을 켜면, PIN을 등록하지 않은 사용자는 승인·반려를 할 수 없습니다.**
  해당 사용자에게는 "관리자가 PIN 검증을 켰습니다. PIN을 등록해야 승인/반려할 수 있습니다"라는 안내가 표시됩니다.
  결재가 멈추지 않도록, **켜기 전에 결재자들에게 PIN 등록을 먼저 안내**하십시오.
- PIN은 **4~12자**이며 **Confluence 로그인 비밀번호와는 별개**입니다. 다르게 정하도록 안내하십시오.
  원문은 저장되지 않으므로 관리자도 사용자의 PIN을 확인하거나 알려 줄 수 없습니다.
- PIN을 **5회 틀리면 15분간 잠깁니다.** 잠금은 시간이 지나면 자동으로 풀립니다.
- 도장·서명은 **승인 결정 옆에** 표시됩니다.
- 전자서명을 나중에 끄면 서명·PIN 관련 화면과 표시는 더 이상 사용되지 않습니다.
  **내 서명** 화면에는 "관리자가 전자 서명 기능을 켜면 사용할 수 있습니다"라고 안내됩니다.

## 10. 알림과 이메일

- 알림은 **화면 안 알림(승인 업무함의 알림 목록)** 과 **이메일** 두 갈래로 나갑니다.
- 알림이 생기는 시점: 요청 생성, 승인, 반려, 만료, 마감 임박, 회수, 결재 독촉.
  요청에 참조자를 지정하면 참조자는 **요청 생성 시점과 최종 결정 시점**에 알림을 받습니다.
  **결재 독촉**은 지금 차례인 결재자에게만 갑니다([3.4](#34-독촉-알림) 참고).
- **email 알림은 기본적으로 꺼져 있습니다.** 켜려면 다음 두 가지가 모두 필요합니다.
  1. Confluence에 **메일 서버가 설정**되어 있을 것
  2. 전역 정책에서 **알림 사용**과 **email 알림 사용**이 모두 켜져 있을 것
- 수신자에게 이메일 주소가 없으면 그 사람에게는 메일이 나가지 않습니다(화면 안 알림은 그대로 표시됩니다).
- **알림 사용**을 끄면 화면 안 알림과 이메일이 **모두** 만들어지지 않습니다. 마감 임박 알림과 결재 독촉도
  함께 멈춥니다. 특정 종류만 끄고 싶다면 주 스위치가 아니라 개별 항목(예: 마감 임박 알림, 독촉 알림)을 끄십시오.
- 알림은 즉시 발송되는 것이 아니라 **알림 발송 주기(기본 1분)** 마다 모아서 나갑니다.
  실패하면 **알림 최대 재시도(기본 5회)** 까지 다시 시도합니다.

## 11. 표시 언어와 화면 테마

### 표시 언어

- 앱 화면은 **Confluence 사용자 언어 설정을 따릅니다.** 사용자의 언어가 **한국어면 한국어**,
  그 밖의 언어는 **모두 영어**로 표시됩니다. 언어를 앱에서 따로 고르는 설정은 없습니다.
- 적용 범위는 화면 전체입니다 — 페이지의 승인 표시, 승인 매크로, 요청·상세 창, 승인 업무함,
  승인 설정, 사이드바, 오류 메시지, 이메일 본문까지 같은 규칙을 따릅니다.
- 예외는 **상태 표시명**입니다. 관리자가 정한 이름은 조직 용어이므로 번역하지 않고 그대로 표시됩니다
  ([3.6](#36-상태-표시명) 참고).

### 다크 모드

- 앱에는 별도의 테마 토글이 **없습니다.** **Confluence의 외관(테마) 설정을 그대로 따릅니다.**
- 사용자가 라이트/다크를 명시적으로 골랐으면 그 값을, '자동'이면 운영체제 설정을 따릅니다.
  따라서 앱 화면은 항상 Confluence 본문과 같은 모드로 보입니다.

## 12. 보안

- **설정 화면 접근**: Confluence 관리자 또는 설정 관리자만 열 수 있습니다. 주소로 직접 접근해도 권한이 없으면 거부됩니다.
- **화면 노출과 별개로 서버에서 권한을 다시 검증합니다.**
  - 요청 생성: 로그인 사용자 + 대상 페이지 **편집 권한**
  - 조회·승인·반려: 로그인 사용자 + 대상 페이지 **보기 권한**
  - 다른 사람 명의로 결재하려는 호출은 거부됩니다. **결재 위임이 켜져 있고 지금 유효한 위임이 있는 경우에만**
    그 결재자를 대신할 수 있으며, 이때도 결정은 원래 결재자의 이름으로 기록되고 실제로 누른 사람이 감사 이력에 함께 남습니다.
  - 적용되지 않은 스페이스에서의 새 요청 생성은 거부됩니다.
- **CSRF 방어**: 상태를 바꾸는 모든 요청(`POST`, `PUT`, `PATCH`, `DELETE`)에는
  **`X-Atlassian-Token: no-check` 헤더가 반드시 있어야 하며**, 없으면 403으로 거부됩니다.
  앱 화면에서 하는 조작에는 이 헤더가 자동으로 붙으므로 사용자가 신경 쓸 일은 없습니다.
  **외부 스크립트나 연동 도구로 승인 REST를 직접 호출한다면 이 헤더를 반드시 넣으십시오.**
  조회(`GET`)에는 필요하지 않습니다.
- 관리자 목록과 적용 스페이스의 변경은 **변경 이력**과 **서버 로그**에 남습니다.
- 서명 PIN은 원문을 저장하지 않으므로 관리자도 복구·조회할 수 없습니다.

## 13. 운영 주의사항

### 13.1 되돌릴 수 없는 동작

| 동작 | 결과 |
|---|---|
| 요청 회수 | 진행 중인 요청이 종료되고 **지금까지 받은 승인이 무효**가 됩니다. 되돌릴 수 없습니다. |
| 반려 | 반려 즉시 요청 전체가 종료됩니다. 단 한 건의 반려로 끝납니다. |
| 승인 Flow 삭제 | 확인 창 없이 즉시 삭제됩니다. |
| 승인 그룹 등록 해제 | 확인 창 없이 즉시 해제됩니다(Confluence 그룹 자체는 남습니다). |
| 설정 관리자 삭제 | 확인 창 없이 즉시 제외됩니다. |
| 위임 해제 | 해제한 위임은 다시 켤 수 없습니다. 계속 쓰려면 새로 등록해야 합니다(맡긴 사람·받은 사람 모두 해제할 수 있습니다). |
| 변경 이력 | 기록은 수정하거나 지울 수 없습니다. |

또한 진행 중(승인 대기) 요청은 **대상 문서가 편집되면 만료**되어 그때까지 받은 승인이 초기화됩니다.
승인 매크로로 지정한 영역의 결재는 **그 영역의 본문이 실제로 바뀐 경우에만** 만료됩니다.
매크로를 지운 채 페이지를 저장하면 그 영역의 진행 중 결재는 자동으로 회수됩니다.
반대로 **이미 완료된 승인 기록은 이후 편집으로 사라지지 않습니다.** 문서가 승인 버전보다 새로워지면
"승인 버전 / 미승인 버전"이 함께 표시됩니다.

### 13.2 서버 재기동이 필요한 경우

- 대부분의 설정(정책, 알림 스위치, 상태 표시명, 적용 스페이스, Flow, 그룹, 설정 관리자)은
  **저장 즉시 적용**됩니다.
- **주기 관련 설정(만료 sweep 주기, 알림 발송 주기)** 은 저장할 때 주기 작업을 다시 등록합니다.
  다시 등록하지 못한 경우 화면에 "설정은 저장됐지만 만료 주기는 서버 재기동 후 적용됩니다"라고 표시되며,
  이때는 **Confluence를 재기동**해야 새 주기가 확실히 적용됩니다.

### 13.3 대량 데이터에서의 제한

| 화면·기능 | 제한 |
|---|---|
| Excel(CSV) 다운로드 | **한 번에 10,000건까지**입니다. 초과하면 "필터를 더 적용해 주세요"라는 메시지가 나옵니다. |
| 승인 업무함 목록 | 50건 단위로 나누어 불러옵니다(더 보기). 총건수는 함께 표시됩니다. |
| 적용 스페이스 목록 | 50개 단위 페이지입니다. '보이는 것 선택'은 현재 페이지에만 적용됩니다. |
| 사용자·그룹·스페이스 검색 | 대상이 많으면 일부만 검색되며 "일부만 찾아봤습니다"라고 안내합니다. 검색어를 더 입력해 좁히십시오. |
| 변경 이력 | 화면에는 최근 100건만 표시됩니다. |

## 14. 문제 해결

| 증상 | 확인할 것 |
|---|---|
| 페이지에 승인 표시와 **승인 요청** 버튼이 보이지 않는다 | ① 그 스페이스가 **적용 스페이스**에 포함되어 있는지 ② 앱이 활성화되어 있는지 ③ 사용자가 그 페이지의 편집 권한을 갖고 있는지 |
| 승인 매크로가 본문만 보이고 승인 틀이 없다 | 해당 스페이스가 적용 스페이스에서 빠져 있습니다. |
| 승인 설정 화면이 열리지 않는다(접근 거부) | Confluence 관리자이거나 **설정 관리자** 목록에 있어야 합니다. |
| 결재선 검색에 그룹이 나오지 않는다 | **승인 그룹** 탭에 등록되어 있어야 하고, '결재선에서 사용'이 켜져 있어야 합니다. |
| 그룹을 결재선에 넣었는데 승인자가 만들어지지 않는다 | 그 그룹에 **활성 구성원**이 있는지 확인하십시오. 비활성 사용자는 제외됩니다. |
| 직접 선택 그룹이 저장되지 않는다 | 같은 이름의 Confluence 그룹이 있으면 저장할 수 없습니다. 다른 이름을 쓰십시오. |
| 이메일이 오지 않는다 | ① Confluence 메일 서버 설정 ② '알림 사용' ③ 'email 알림 사용' ④ 수신자에게 이메일 주소가 있는지 |
| 마감이 지났는데 만료되지 않는다 | **만료 sweep 주기**만큼 기다려야 반영됩니다. 주기를 방금 바꿨다면 재기동 안내 메시지가 나왔는지 확인하십시오. |
| 마감 임박 알림이 오지 않는다 | '알림 사용'과 '마감 임박 알림 사용'이 모두 켜져 있어야 하고, 요청에 **마감일이 있어야** 합니다(기본 마감일이 0이면 마감일이 없습니다). |
| 승인자가 "아직 차례가 아닙니다"라는 안내를 본다 | 순차 승인이므로 앞 단계가 끝나야 결정할 수 있습니다. 정상 동작입니다. |
| 사용자가 **내 위임** 화면에서 "결재 위임이 꺼져 있습니다"를 본다 | 전역 정책의 **결재자가 위임을 등록할 수 있음**이 꺼져 있습니다. 켜면 바로 쓸 수 있습니다. |
| 위임을 등록했는데 대리인이 승인하지 못한다 | ① 위임이 `지금 유효` 상태인지(시작일·종료일 확인) ② 그 결재자의 차례가 맞는지 ③ **결재 위임**이 켜져 있는지 ④ 승인 매크로로 지정한 **영역 결재는 대리 결재가 되지 않습니다**(결재자 본인이 처리해야 합니다) |
| 독촉 알림이 오지 않는다 | ① **알림 사용** ② **독촉 알림 보내기** ③ **첫 독촉까지(일)** 가 지났는지 ④ 그 사람이 **지금 차례**인지(차례가 아닌 결재자와 요청자·참조자에게는 가지 않습니다) ⑤ 만료 sweep 주기가 지나야 감지됩니다 |
| 결재가 늦어질 때 상급자에게 알리고 싶다 | 상급자 상신 기능은 없습니다(Confluence에 조직 계층 정보가 없어 대상을 정할 수 없습니다). 결재선에 상위 결재자를 한 단계 더 넣는 방식으로 설계하십시오. |
| 사용자가 승인·반려를 못 하고 PIN을 요구받는다 | **서명 PIN 검증**이 켜져 있습니다. 사용자가 업무함의 **내 서명**에서 PIN을 등록해야 합니다. |
| PIN이 잠겼다 | 5회 실패 시 15분간 잠깁니다. 시간이 지나면 자동으로 풀립니다. |
| 외부 스크립트에서 승인 REST 호출이 403이 된다 | 상태를 바꾸는 요청에 **`X-Atlassian-Token: no-check`** 헤더를 넣으십시오. |
| CSV 다운로드가 거부된다 | 대상이 10,000건을 넘었습니다. 필터를 더 걸어 범위를 좁히십시오. |
| 요청을 만드는 중 "이미 진행 중인 요청" 안내가 나온다 | 같은 대상에는 열린 요청이 하나만 있을 수 있습니다. 끝난 뒤에 새로 만드십시오. |
| 설치 후 앱이 동작하지 않는다 | Confluence 버전과 산출물이 맞는지 확인하고, Confluence 애플리케이션 로그에서 `kr.dmove.confluence.approval`을 검색해 오류를 확인하십시오. |
