사용자가 요청했으나 **의도적으로 후순위로 미뤘다** (2026-08-19 판단).

- 도메인 상태 머신에 핵심 불변식이 묶여 있다: 열린 요청 대상당 1개(`dedupeKey`), 단계 전이,
  legacy minimum, 승인자 행 변경분 반영. 여기를 재설계하면 배치 1~8이 전부 회귀 위험에 들어간다.
- 실사용 검증이 아직 얕다. 2026-08-19 첫 화면 검증에서 버그 4건이 나왔다.
- C10 미이식 상태에서 도메인을 바꾸면 이식 대상이 더 커진다.

**착수 전 조건**: `docs/approval-workflow-design.md`를 먼저 쓰고, 기존 데이터 마이그레이션 경로와
"상태를 지운 뒤 그 상태에 머물던 요청"의 처리 규칙을 확정할 것.

## 배치 8 (구 배치 7 — 사용자 요청 2026-08-12)

### 서명 (전자 도장) — **전체가 옵션. `signatureEnabled` 꺼짐(기본)이면 현행 화면과 동일.**
1. **자동 도장(1단계)** — 저장물 없이 이름 기반 CSS/SVG 도장을 결재 이력·상세 모달에 렌더링. DB 부담 0.
2. **등록 서명(2단계)** — 사용자 프로필에서 1회 등록(그리기/업로드, ≤50KB 검증), AO BLOB 사용자당
   1행. 결재 표시는 참조만. 1,000명 기준 ~30MB로 부담 미미.
3. **서명 비밀번호(PIN)** — 승인/반려 시 PIN 검증(관리자 설정으로 on/off).
   - **Confluence 로그인 비밀번호 재입력은 금지** — 피싱 안티패턴 + SSO/LDAP 조직은 검증 불가.
   - 별도 PIN을 솔트+해시(PBKDF2)로 저장, 원문 미보관. 결정 REST에 pin 파라미터, 서버 검증,
     실패 횟수 제한 검토.
- 결정마다 그리기 방식은 **비채택** (UX 마찰 + 결정 수 비례 저장 누적: 연 10만 건 × 30KB ≈ 3GB/년).

### CC (참조)
- 요청 모달에 참조자(사용자/그룹) 지정. 결재 권한 없음, 열람·알림만.
- 알림: 요청 생성 시 + 최종 결정(승인/반려/만료/회수) 시.
- 업무함 "참조" 필터/그룹. 저장 모델(승인자 테이블 role 구분 vs 별도 테이블)과
  domain 포함 여부(알림 resolver가 스냅샷만 보므로)는 설계에서 결정.
