평가 대상: 배치 8d/8e + 8.5(스페이스 정책·헤더 진입점·CSV·사용자 피커)까지 반영한 `main` 작업 트리.
방법: 코드 실측(전 diff 정독) + 단위 테스트 124건 + 배포 게이트(jar 임베드) 검증.
등급 기준 — **치명**: 데이터 손실·보안 침해·핵심 기능 불능 / **높음**: 운영 중 장애·오작동이 실사용에서 재현 /
**중간**: 규모가 커지면 문제 / **낮음**: 체감 품질.

## 2. 남은 위험과 개선 방안

### ✅ P1. 위임 관리자의 권한 확산 — 조치 완료 (2026-08-19)
설계 결정(2026-08-18)에 따라 위임 관리자는 Confluence 관리자와 **동일 지위**다. 따라서
위임 관리자가 또 다른 위임 관리자를 추가할 수 있고, 한 번 등록되면 Confluence 관리자 권한 없이도
전역 정책·Flow·그룹을 바꾼다. 결재 위조는 불가(요청 회수 등 결재 개입은 `isAdministrator` 유지).

- **개선 1 — 완료**: `APR_AUDIT` 테이블에 설정 변경을 append-only로 남긴다(관리자 목록·적용 스페이스·
  전역 정책). 설정 화면의 **변경 이력** 탭에서 언제·누가·무엇을 바꿨는지 본다.
  기록 실패가 설정 저장을 되돌리지는 않는다 — 저장은 이미 끝났고, 이력이 빠졌다고 사용자의 저장을
  실패로 돌리는 편이 더 나쁘다(그 경우 서버 로그에 남긴다).
- **개선 2(선택)**: "관리자 탭은 Confluence 관리자만" 옵션을 두어 확산을 차단할 수 있게 한다.

### ✅ P2. CSV 내보내기의 메모리 — 조치 완료 (2026-08-19)
최대 10,000행을 `StringBuilder`에 전부 쌓고, 페이지 객체도 전량 맵에 유지한 뒤 한 번에 응답한다.
동시 요청이 겹치면 힙 압박이 된다.
- **완료**: `StreamingOutput`으로 행 단위 전송. 1만 행을 문자열로 쌓지 않는다.

### ✅ P3. 전체 스페이스 일괄 로드 — 조치 완료 (2026-08-19)
`/administration/spaces`가 `spaceManager.getAllSpaces()`로 전량을 내려준다. 스페이스가 수천 개인
인스턴스에서 설정 화면 진입이 무거워진다(현재 필터링은 클라이언트에서 수행).
- **완료**: `ListBuilder.getRange`로 서버 페이징(50개씩). `SpacesQuery`에 이름 검색이 없어 검색 시에는
  상한(2,000)까지 훑고, 끊겼으면 화면에 알린다. 선택 상태는 키 집합으로만 유지하므로 페이지를 넘겨도
  유지된다. 목록을 다 들고 있지 않으므로 '전체 선택'은 '보이는 것 선택'으로 의미를 좁혔다.

### P4. 적용 해제 시 영향 집계 비용 — 중간
`pendingCountsOutside`가 진행 중 요청마다 `pageManager.getPage`를 호출한다. 저장 시 1회뿐이고
`STATUS` 인덱스를 타지만, 진행 중 요청이 수천 건이면 저장 버튼 응답이 느려진다.
- **개선**: 요청 행에 spaceKey를 비정규화 저장하면 페이지 조회 없이 집계 가능(배치 7의 spaceKey 파생과 통합).

### P5. C10 어댑터 미이식 — 높음(호환)
`approval-confluence10`은 배치 1~8이 전혀 반영되지 않았다. Confluence 10 고객이 생기면 즉시 문제가 된다.
- **개선**: 이식 전용 배치를 별도로 편성(도메인은 공유하므로 어댑터 레이어만 대상).

### ✅ P6. i18n — 조치 완료 (2026-08-19)
UI 문구가 한국어로 하드코딩돼 있다(이메일만 en 분기). 해외 사용자는 쓸 수 없다.
- **완료**: 화면 전체 + REST 오류 + 이메일 + 브라우저 생성 문구. 한국어/영어 두 벌(키 500여 개).

### P7. 헤더 배지의 신선도 — 낮음
세션 캐시 2분 때문에 **다른 사용자**가 만든 요청은 최대 2분 늦게 배지에 반영된다.
내 행동은 즉시 무효화되므로 체감 문제는 작다. 성능과의 맞교환으로 수용.

### ✅ P8. XSRF 필터의 적용 범위 — 조치 완료 (2026-08-19)
실기동으로 확정했다. `X-Atlassian-Token` 없는 `POST /rest/approval/1.0/approvals/delegations`는 **403**,
헤더를 붙이면 정상 처리된다. `url-pattern`이 `/rest/approval/*` 전체를 덮는 것이 확인됐다.

### P5-1. 문서가 C10 지원을 표방한다 — 확인 필요
`compatibility.md`의 지원 매트릭스는 `approval-confluence10`을 "Confluence 10.2.x 지원"으로 적고 있으나,
실제 C10 어댑터는 **소스 7개**뿐이다(C9는 57개). 서블릿·설정·알림·서명·위임·i18n·XSRF가 전부 없다.
지금 배포 대상 고객은 Confluence 9라 문제가 되지 않지만(2026-08-19 확인), **Marketplace 등록이나
"C10 지원" 표기를 하기 전에는 반드시 P5를 먼저 해소해야 한다.** 그대로 두면 사실과 다른 표기가 된다.

## 3. 검증 방법

```powershell
# 단위 테스트 (c9 124건 + domain 54건)
.\scripts\build.ps1 -Target confluence9   # 단, 인스턴스가 떠 있으면 clean 금지 — mvn -pl approval-confluence9 -am test 로 우회

# 배포 전 게이트 (철칙 3조)
unzip -l approval-confluence9\target\approval-confluence9-1.0.0.jar | grep -c "approval/domain/.*class"   # 0이면 배포 금지
```

라이브 실측 항목:
1. 헤더 없는 POST → 403, 화면을 통한 POST → 정상 (P8)
2. 미적용 스페이스 페이지에 배너·매크로가 **전혀** 없음 (R7)
3. 적용 스페이스를 끌 때 진행 중 건수 경고가 뜨고, 확인해야 저장됨 (R8)
4. 설정 5탭 전환, 업무함 사이드바에 설정 없음, 헤더 popover로 설정 진입 (배치 C)
5. Excel 다운로드 → 행이 여러 줄로 분리됨 (R1)
