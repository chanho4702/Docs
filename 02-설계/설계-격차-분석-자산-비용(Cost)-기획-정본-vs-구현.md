## G-1 ✅ "왜 늘었는가"에 답하지 못한다 — 전기 대비 축이 통째로 빠졌다 **(해소)**

### 격차

기획의 대시보드 지표 15개 중 **4개가 전기 대비 축**이다.

| 기획 지표 | 산정 | 우리 구현 |
|---|---|---|
| `Change rate` | (현재 − 이전) / 이전 × 100 | **없음** |
| `Increase impact` | `Σ max(0, cost − previousCost)` | **없음** |
| `Increase impact Top N` | 위 기준 상위 5개 | **없음** |
| `Cost movement` | previous / total / forecast 3단 비교 | **없음** |

우리 대시보드 KPI 5개(총 취득원가·기간 총비용·12개월 예상·연간 유지비·미입력) 중 **0개**,
위젯 5개 중 **0개**가 이 축이다.

### 🔴 아이러니 — 요약 화면이 상세 화면보다 못 본다

```ts
// M1 HW 탭 KPI — 변화율이 있다
export type TCostHwKpi = { hwTotal; changeRate: number | null; forecast; expiryExposure; incompleteCount };

// M2 대시보드 KPI — 없다
export type TCostDashboardKpi = { totalPurchaseCost; periodTotalCost; periodDepreciation;
                                  periodRecurring; forecast12mTotal; annualRecurringCost; ... };
```

대시보드는 HW 탭의 **상위 요약**이어야 하는데, HW 탭이 보여주는 변화율을 대시보드가 못 보여준다.

### 데이터는 이미 다 있다

- BE `Env`가 `prevStart`/`prevEnd`를 **이미 계산**하고 응답 `period`에 실어 보낸다.
- 아이템별 `costChangeRate`가 **이미 있다**(계약 §1, `CostHwItemDto`).
- 즉 **집계 함수 하나만 추가**하면 되는 격차다. 비용 대비 이득이 가장 크다.

### 예산을 뺀 결정과는 무관하다

2026-08-04에 예산을 뺀 건 옳았다 — 감가상각은 통제 가능한 지출이 아니다.
그러나 **예산은 "목표 대비", 변화율은 "과거 대비"**로 서로 다른 축이다.
지출 축으로 재정의했다면 *"지난달보다 얼마 늘었나"* 는 오히려 그 축의 한복판이다.

### 레퍼런스 대조

AWS Cost Explorer·Cloudability·Flexera·ServiceNow CCM은 **기간 비교를 1급 기능**으로 둔다.
비용 관리 제품에서 "이번 달 총액"만 보여주는 화면은 사실상 없다.

### 권고

| | 추가 |
|---|---|
| KPI | `전기 대비 변화` (금액 + %) |
| 위젯 | `비용 증가 기여 Top 5` — `max(0, 현재 − 이전)` 내림차순 |
| 검토 후보 | 사유 태그에 `비용 급증`(예: 변화율 > 10%) 추가 |

⚠️ 단, **§2.7 소급 재계산 정책** 때문에 "이전 기간"도 *지금 파라미터로 다시 계산한 값*이다.
파라미터를 바꾸면 과거 수치도 함께 변한다 — 화면에 이미 있는 기준일 고지로 커버되지만,
변화율은 그 영향이 더 직접적이라 문구를 보강해야 한다.

## G-2 ✅ 과거 추이가 없다 — "추적"인데 시계열이 미래만 있다 **(해소)**

우리 유일한 시계열은 `monthlyForecast`(**다음 달부터 12개월**, 미래)다. **과거 추이 차트가 없다.**

- 기획: `Cost movement` = previous / total / forecast **3단**
- 레퍼런스: Cost Explorer의 본체가 시계열이고, Cloudability·Flexera도 동일

🔴 **감가상각은 확정 스케줄이라 과거가 "예측"이 아니라 사실이다** — 오히려 그리기 쉽다.
`DepreciationSchedule`이 이미 월별 배열을 들고 있어서 계산 자체는 신규 로직이 거의 없다.

⚠️ 한계는 명시할 것: 유지보수·리스 금액의 **변경 이력이 없어서**, 과거 월의 현금성 비용은
"당시 값"이 아니라 "지금 값을 소급 적용한 값"이 된다(§2.7). 이걸 안 적으면 거짓말이 된다.

## G-3 ✅ 검토 후보에서 다음 행동으로 못 간다 (드릴다운 부재) **(해소)**

기획 전반의 핵심어가 **"근거 중심 탐색"**이고, 화면마다 상호작용에 반복해 나온다:
*"Asset을 클릭하면 Asset Detail로 이동한다" · "연결된 Host를 클릭하면 Host Detail로 이동한다"*

| 화면 | 자산명 |
|---|---|
| M1 HW 테이블 | ✅ `<Link to={.../hw/${record.id}}>` (`CostHwTable.tsx:160`) |
| **M2 대시보드 검토 후보** | 🔴 **`<Text>` — 클릭 불가** |

또한 대시보드 검토 후보 테이블에 **연결 Host 컬럼이 없다**(기획 HW 테이블 컬럼에는 있다).

**결과: "확인이 필요한 자산 40건"을 보여주고 끝난다.** 화면 목적의 절반이 무력화된다.
ServiceNow HAM·AssetExplorer의 핵심도 자산에서 계약·호스트·티켓으로 잇는 것이다.

### 권고
FE만 고치면 된다(가장 싼 수정). 자산명을 `Link`로, `linkedHostName` 컬럼 추가.

## G-4 🟡 대시보드가 HW 탭과 역할이 겹친다 (클라우드 배제의 부작용)

기획의 대시보드는 **"HW냐 Cloud냐, 어디를 먼저 볼지 정하는 라우팅 화면"**이다
— `Total / HW / Cloud` 3 KPI + `Platform allocation` 도넛 + 각 화면 진입 링크.

Cloud를 뺐으므로(사용자 결정) 그 역할이 사라졌고, 남은 건 **HW 탭 지표의 재배열**이다.

| 중복 | M1 | M2 |
|---|---|---|
| 소유자별 비용 도넛 | ✅ | ✅ (동일) |
| 만료 구간 | ✅ | ✅ (정의만 다름 — G-5) |
| 미입력 건수 | ✅ | ✅ |

→ **대시보드의 차별점을 G-1·G-2·G-3(전기 대비 · 추이 · 행동 가능한 큐)으로 잡아야 역할이 선다.**
그러지 않으면 탭 2개가 같은 것을 두 번 보여주는 구조로 남는다.

## G-5 🟢 "만료 임박"의 정의가 앱 안에 두 개다

| | 정의 |
|---|---|
| M1 `expiryWindow` | 누적 + **경과 포함** |
| M2 `expiryStatus` | 경과 분리 + **예정만** |

탭을 옮기면 "90일 이내" 숫자가 달라진다. M2 쪽이 옳은 개선이지만 **사용자에겐 불일치로 보인다.**

✅ 완화됨: M1 툴팁이 *"누적 구간입니다(60일 이내는 30일 이내를 포함). 이미 만료된 자산도 포함됩니다."*
라고 명시하고 있다. 그래도 **M1을 M2 정의로 통일하는 게 최종 방향**이다.

## G-6 ✅ "운영 연결 정보 부족" 검토 축이 없다 (기능요구 #7) **(해소)**

기획 기능요구 #7: *"소유자 미지정 자산, 연결 Host 없는 HW 자산, 식별 정보가 부족한 Cloud 비용 항목이 표시된다."*

우리 검토 후보 사유 4종(`missing_cost` · `depreciated_but_recurring` · `expired` · `expiring_soon`)에
**연결 누락 축이 없다.** dev 데이터에도 소유자 미지정이 실재하는데(소유자 도넛의 `미지정`),
검토 대상으로는 잡히지 않는다.

ServiceNow HAM 계열이 공통으로 두는 기능이다(unassigned / orphaned assets).
**비용 데이터가 정확해도 주인이 없으면 아무도 조치하지 않는다** — 그래서 별도 축인 것이다.

### 권고
사유 태그 `owner_missing` / `host_unlinked` 추가. M1 우선순위 점수에 이미 `link`(소유자·연결 호스트) 요소가
있으므로(`priority_basis.link`) **판정 로직은 이미 존재한다.**

## G-7 ✅ 우선순위(costPriority)가 대시보드에서 사라졌다 **(해소)**

- 기획 대시보드 **필터**: 기간 · 플랫폼 · 소유자 · 계정 · 리전 · **우선순위**
- 기획 review queue **정렬**: 예산 위험, 최적화 후보, 만료 임박, 증가율, **우선순위 점수**

M1엔 이미 구현돼 있다 — `COST_PRIORITY_OPTIONS`, `item.priority.{level,score}`, 필터.
**M2 대시보드는 필터에도 없고 정렬에도 안 쓴다**(태그 수 → 연간 유지비).

→ **이미 만들어 둔 것을 안 쓰는 격차**라 보완 비용이 거의 없다.

## G-8 ✅ 조회 결과 내보내기가 없다 (기능요구 #3) **(해소)**

기획 공통 요구 #3: *"현재 조회 조건에 맞는 비용 목록이 CSV로 다운로드된다."*

현재 있는 건 **일괄 업로드 템플릿**뿐이고, 조회 결과 내보내기는 없다.
FE에 `exportData`/`exportSheetsToXlsx` 유틸이 이미 있다(exceljs 전환 완료).

이건 Cloudability·Flexera의 핵심인 **showback/chargeback**의 최소 형태다 —
소유자별 비용을 각 팀에 돌리려면 내보내기가 출발점이다.

## G-9 🟢 수명주기가 폐기에서 끊긴다

ServiceNow HAM·ManageEngine AssetExplorer의 수명주기는
**요청 → 구매 → 배치 → 운영 → 회수 → 폐기/매각**까지다. 잔존가치 회수와 처분 비용이 TCO의 일부다.

우리는 **"교체 검토" 태그까지**다. 그 다음 상태 전이도, 처분 비용도 없다.
기획 데이터 요구에 `residualCostAmount`(잔존가액)가 있으나 우리는 **상각 하한으로만** 쓴다.

M2 범위 밖으로 봐도 되지만, 로드맵에 없으면 "자산 비용 관리"가 반쪽으로 남는다.

## G-10 🟢 `forecast`가 기획과 다른 뜻이다 (용어 충돌 예방)

| | 정의 |
|---|---|
| 기획 `Forecast` | **선택 기간 종료 시** 예상 비용(월말 착지) → 예산 초과 판단용 |
| 우리 `forecast12mTotal` | **다음 달부터 12개월** 합계 |

HW 감가상각은 월할 확정값이라 "월말 착지 예상"이 무의미하다 → **HW에 한해 우리 정의가 더 맞다.**
다만 **Cloud가 들어오면 기획 정의가 반드시 필요해진다**(사용량 기반이라 월말 착지가 실제 예측이다).

→ 지금 용어를 갈라 둘 것: `12개월 예상`(우리) vs `기간말 예상`(기획). 같은 이름 두 뜻이 되면 늦다.

## ✅ 기획보다 나은 점 (유지할 것)

| | |
|---|---|
| **감가상각 계산 엔진** | 기획은 `depreciationCostAmount`를 단순 입력 필드로 뒀다. 우리는 정액·정률 스케줄 엔진을 만들었다 — 취득가·내용연수만 있으면 자동 산출된다 |
| **취득원가를 기간 비용에서 분리** | 기획은 `purchaseCostAmount`를 비용 필드로 나열한다. 월 비용에 취득가를 더하면 **이중계상**이다. 우리가 맞다 |
| **비현금(상각) / 현금성(유지보수·리스) 분리** | 기획엔 없는 구분. "실제로 나가는 돈"을 따로 보여준다 |
| **만료 경과/예정 분리** | 기획 `Expiry window`는 경과 포함 누적이다 |
